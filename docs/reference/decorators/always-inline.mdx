`@always_inline` 装饰器强制函数在调用点内联展开。编译器会将函数体直接插入到调用位置，而不是生成函数调用指令。

## 语法

```mojo
@always_inline
def function_name(...):
    ...
```

## 用法

```mojo
@always_inline
def add(a: Int, b: Int) -> Int:
    return a + b

def main():
    var result = add(1, 2)  # 编译器直接展开为 1 + 2
```

## 优点

- **消除调用开销**：没有函数调用的栈操作开销
- **启用进一步优化**：内联后的代码可以进行更多优化
- **编译时求值**：内联函数更容易在编译时求值

## 缺点

- **代码膨胀**：频繁内联会增加二进制大小
- **编译时间增加**：更多代码需要编译

## 适用场景

### 小型工具函数

```mojo
@always_inline
def min(a: Int, b: Int) -> Int:
    return a if a < b else b

@always_inline
def max(a: Int, b: Int) -> Int:
    return a if a > b else b
```

### 性能关键路径

```mojo
@always_inline
def fast_abs(x: Int) -> Int:
    return x if x >= 0 else -x
```

### SIMD 操作

```mojo
@always_inline
def simd_add[T: DType, N: Int](a: SIMD[T, N], b: SIMD[T, N]) -> SIMD[T, N]:
    return a + b
```

## 与 `@no_inline` 对比

| 装饰器         | 行为               |
|----------------|--------------------|
| `@always_inline` | 强制内联         |
| `@no_inline`     | 禁止内联         |
| 无装饰器         | 编译器决定       |

## 注意事项

- 递归函数不能使用 `@always_inline`
- 过度使用可能导致代码膨胀
- 编译器可能会忽略某些情况下的内联请求
