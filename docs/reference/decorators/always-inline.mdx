你可以在任何函数上添加 `@always_inline` 装饰器，让 Mojo 编译器将函数体（复制后）直接"内联"到调用函数的函数体中。

这消除了函数调用跳转到代码中新位置可能产生的性能开销。通常，编译器会在能够提升性能的地方自动执行此操作，但此装饰器会强制其执行。缺点是它会在每个调用点复制函数，从而增加二进制大小。

例如：

```mojo
@always_inline
def add(a: Int, b: Int) -> Int:
    return a + b

print(add(1, 2))
```

因为 `add()` 被装饰以 `@always_inline`，Mojo 编译此程序时不会将 `add()` 函数添加到调用栈，而是直接在 `print()` 调用点执行加法运算，就像它是这样编写的一样：

```mojo
print(1 + 2)
```

## `@always_inline("nodebug")`

你还可以使用带有 `"nodebug"` 参数的装饰器，它具有相同的内联效果，但没有调试信息。这意味着你在调试时无法步入该函数。

此装饰器旨在用于库中的低级函数，这些函数可能包装原语函数、MLIR 操作或内联汇编。将这些函数标记为 "nodebug" 可以防止用户在调试时意外步入低级非 Mojo 代码。

## `@always_inline("builtin")`

`"builtin"` 参数类似于 `"nodebug"`，但更为严格。此装饰器的 `"builtin"` 版本应仅用于包装编译器具有特殊编译时处理的单个 MLIR 操作的函数。它允许编译器在参数上下文中使用该函数时将其内联。

:::caution

使用此版本的装饰器需要对 Mojo 编译器的内部机制有所了解。不建议在标准库之外使用。请改用标准的 `@always_inline` 装饰器或 `"nodebug"` 版本。

:::

此版本的装饰器会执行 `"nodebug"` 的所有操作，外加另外两种行为：

- 它会检查函数体，验证其未使用 `@always_inline("builtin")` 无法处理的任何内容。这会检查是否存在控制流、对非 `@always_inline("builtin")` 函数的调用、不支持的 MLIR 操作的使用等。

- 当函数在参数上下文中使用时，它会无条件内联。

有关更多详细信息和背景，请参阅
[`@always_inline("builtin")` 提案](https://github.com/modular/modular/blob/main/mojo/proposals/always_inline_builtin.md)。
