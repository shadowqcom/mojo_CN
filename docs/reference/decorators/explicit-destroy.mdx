显式销毁阻止 ASAP 销毁在值最后一次使用时将其销毁。要启用显式销毁，请让类型遵循一个不可满足的 `Deinitable` 约束：

```mojo
struct Example(Deinitable where False):
    def cleanup(deinit self):
        pass
```

这会禁用通过 `__deinit__()` 方法进行的自动销毁，并要求通过命名的析构方法进行显式清理。使用此模式时，你必须调用一个命名的析构方法来消费该值。如果不调用，编译器会发出错误。

当清理必须被刻意执行、可能失败并需要错误处理，或者你的类型提供多种有效方式来结束一个值的生命周期（例如保存到文件并关闭文件描述符，或者不保存直接退出）时，请使用显式销毁。

## 隐式销毁与显式销毁

Mojo 支持两种销毁模型。大多数类型依赖编译器管理的生命周期分析，而一些类型则选择显式控制以获得更强的清理保证。

_隐式销毁_（默认）：当值不再有进一步使用时，编译器会自动调用 `__deinit__()`。清理由 Mojo 的生命周期分析触发，无需手动干预。你可以在你的类型中重写 `__deinit__()`，但编译器不会验证清理是否被有意执行。

_显式销毁_：你有意调用命名的析构方法（例如 `cleanup()` 或 `save_and_close()`）。该遵循会禁用自动销毁，并由编译器强制执行显式消费。如果值离开作用域前未调用析构方法，将导致编译时错误。

大多数类型使用隐式销毁。当清理可能失败、需要错误处理，或者从对值生命周期结束方式的刻意控制中受益时，显式销毁增加了一层安全性。

## 基本用法

要启用显式、编译器强制执行的销毁，请使用 `Deinitable where False` 标记类型。

提供使用 `deinit self` 参数约定的命名析构方法：

```mojo
struct FileBuffer(Deinitable where False):
    var path: String
    var data: String

    def __init__(out self, path: String):
        self.path = path
        self.data = ""

    def write(mut self, content: String):
        self.data += content

    def save_and_close(deinit self) raises:
        write_to_disk(self.path, self.data)
```

使用 `Deinitable where False` 声明类型要求你在作用域结束前添加对类型特定析构方法的刻意调用，或者将该值移出作用域以便稍后消费：

```mojo
def write_log(path: String, message: String) raises:
    var buffer = FileBuffer(path)
    buffer.write(message)
    buffer^.save_and_close()  # Required before `buffer` leaves scope
```

如果省略此调用，编译器会发出错误。

## 自定义错误信息

为了改善显式销毁的编译器诊断，请在 `where` 约束中包含自定义错误信息：

```mojo
struct CustomFileHandle(
    Deinitable where(False, "Must call save_and_close() or discard()")
):
    # ... other implementation details ...

    def save_and_close(deinit self) raises:
        write_to_disk(self.path, self.data) # Store data, then end
        self.close_descriptor()

    def discard(deinit self):
        pass  # Abandon without writing
```
