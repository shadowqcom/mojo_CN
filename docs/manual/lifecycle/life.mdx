Mojo 中值的生命在变量被初始化时开始，持续直到值最后一次使用，此时 Mojo 销毁它。本页描述 Mojo 如何创建、复制和移动每个值。（下一页描述[值如何被销毁](/docs/manual/lifecycle/death)。）

Mojo 将所有数据类型——包括标准库中的基本类型，如 [`Bool`](/docs/std/builtin/bool/Bool/)、[`Int`](/docs/std/builtin/simd/#int) 和 [`String`](/docs/std/collections/string/string/String/)——都定义为[结构体](/docs/manual/structs/)。这意味着任何数据片段的创建和销毁都遵循相同的生命周期规则，你可以定义以完全相同方式工作的自定义数据类型。

Mojo 结构体不会获得任何默认的生命周期方法，如构造函数、复制构造函数或移动构造函数。这意味着你可以定义一个没有构造函数的结构体，但你不能实例化它，它仅作为静态方法的某种命名空间有用。例如：

```mojo
struct NoInstances:
    var state: Int

    @staticmethod
    def print_hello():
        print("Hello world!")
```

没有构造函数，它无法被实例化，因此没有生命周期。`state` 字段也是无用的，因为它不能被初始化（Mojo 结构体不支持默认字段值——你必须在构造函数中初始化它们）。

所以你唯一能做的就是调用静态方法：

```mojo
NoInstances.print_hello()
```

```output
Hello world!
```

## 构造函数

要创建一个 Mojo 类型的实例，它需要 `__init__()` 构造函数方法。构造函数的主要职责是初始化所有字段。例如：

```mojo
struct MyPet:
    var name: String
    var age: Int

    def __init__(out self, name: String, age: Int):
        self.name = name
        self.age = age
```

现在我们可以创建一个实例：

```mojo
var mine = MyPet("Loki", 4)
```

你也可以读取和销毁 `MyPet` 的实例，但目前无法复制或移动它。

我们认为这是一个良好的默认起点，因为没有内置的生命周期事件，也没有意外行为。你——类型作者——必须通过实现复制和移动构造函数来明确决定类型是否可以复制或移动，以及如何复制或移动。

上面展示的模式是一种为结构体每个字段接受一个参数并直接从参数初始化字段的构造函数。它被称为 *按字段构造函数*（field-wise initializer）。这是一种足够常见的模式，因此 Mojo 提供了 [`@fieldwise_init`](/docs/reference/decorators/fieldwise-init/) 装饰器来合成按字段构造函数。所以你可以像这样重写前面的示例：

```mojo
@fieldwise_init
struct MyPet:
    var name: String
    var age: Int
```

:::note
Mojo 不需要析构函数来销毁实例。在某些情况下，你可能需要定义自定义析构函数来释放资源（例如，如果结构体使用 [`alloc()`](/docs/std/memory/alloc/alloc/) 动态分配内存）。
:::

### 重载构造函数

与任何其他函数/方法一样，你可以[重载](/docs/manual/functions/#overloaded-functions) `__init__()` 以使用不同的参数初始化对象。例如，你可能希望有一个设置一些默认值且不带参数的默认构造函数，然后是接受更多参数的附加构造函数。

请注意，为了修改任何字段，每个构造函数必须使用 [`out` 约定](/docs/manual/values/ownership#argument-conventions)声明 `self` 参数。如果你想从另一个构造函数中调用一个构造函数，你只需像从外部那样调用该构造函数（你不需要传递 `self`）。

例如，以下是如何从一个重载的构造函数委托工作：

```mojo
struct MyPet:
    var name: String
    var age: Int

    def __init__(out self):
        self.name = ""
        self.age = 0

    def __init__(out self, name: String):
        self = MyPet()
        self.name = name
```

### 字段初始化

请注意，在前面的示例中，在每个构造函数结束时，所有字段都必须被初始化。这是构造函数中唯一的要求。

实际上，`__init__()` 构造函数足够智能，可以在构造函数完成之前将 `self` 对象视为完全初始化，只要所有字段都已初始化。例如，此构造函数可以在所有字段初始化后立即传递 `self`：

```mojo
def use(arg: MyPet):
    pass

struct MyPet:
    var name: String
    var age: Int

    def __init__(out self, name: String, age: Int, cond: Bool):
        self.name = name
        if cond:
            self.age = age
            use(self)  # Safe to use immediately!

        self.age = age
        use(self)  # Safe to use immediately!
```

### 构造函数与隐式转换

Mojo 支持从一种类型到另一种类型的隐式转换。当以下情况之一发生时，可能会发生隐式转换：

- 你将一种类型的值赋给具有不同类型的变量。
- 你将一种类型的值传递给需要不同类型的函数。
- 你从指定了不同返回类型的函数中返回一种类型的值。

例如，[`Optional[T]`](/docs/std/collections/optional/Optional/) 类型建模了一个可能存在也可能不存在的值。你可以将类型 `T` 的值隐式转换为 `Optional[T]`，也可以将 `None` 的值隐式转换为空的 `Optional[T]`：

```mojo
var opt_greeting: Optional[String] = None  # implicitly converts to an empty Optional
opt_greeting = String("Salve!")  # implicitly converts the String into an Optional
```

通常，类型应仅在转换满足以下条件时才支持隐式转换：

- 安全
- 零成本或低成本
- 语义上无歧义

隐式转换的存在是为了减少不必要的样板代码，而不是为了削弱类型安全。

#### 启用隐式转换

仅当目标类型定义了满足以下条件的构造函数时，Mojo 才支持隐式转换：

- 具有 [`@implicit`](/docs/reference/decorators/implicit/) 装饰器。
- 具有源类型的单个必需的非关键字参数。

例如：

```mojo
var a = Source()
var b: Target = a
```

如果 `Target` 定义了像这样的匹配构造函数，Mojo 会将 `a` 中的 `Source` 值隐式转换为 `Target` 值：

```mojo
struct Target:

    @implicit
    def __init__(out self, s: Source):
        pass
```

通过隐式转换，上面的赋值本质上等同于使用构造函数：

```mojo
var b = Target(a)
```

用于隐式转换的构造函数可以接受可选参数，因此以下构造函数也将支持从 `Source` 到 `Target` 的隐式转换：

```mojo
struct Target:

    @implicit
    def __init__(out self, s: Source, reverse: Bool = False): ...
```

如果 Mojo 无法明确地将转换匹配到构造函数，隐式转换可能会失败。例如，如果目标类型有两个接受不同类型的重载构造函数，并且这些类型中的每一个都支持从源类型的隐式转换，则编译器有两条同等有效的路径来转换值：

```mojo
struct A:
    @implicit
    def __init__(out self, s: Source): ...

struct B:
    @implicit
    def __init__(out self, s: Source): ...

struct OverloadedTarget:
    @implicit
    def __init__(out self, a: A): ...
    @implicit
    def __init__(out self, b: B): ...

var t = OverloadedTarget(Source()) # Error: ambiguous call to '__init__': each
                                   # candidate requires 1 implicit conversion
```

在这种情况下，你可以通过显式转换为其中一种中间类型来修复此问题。例如：

```mojo
var t = OverloadedTarget(A(Source())) # OK
```

Mojo 对一个变量最多应用一次隐式转换。例如：

```mojo
var t: OverloadedTarget = Source() # Error: can't implicitly convert Source
                                   # to Target
```

这会失败，因为没有从 `Source` 到 `OverloadedTarget` 的直接转换。

对于具有单个字段的结构体，你可以使用 `@fieldwise_init("implicit")` 装饰器生成一个隐式构造函数。

```mojo
@fieldwise_init("implicit")
struct Counter:
    var count: Int

def main():
    var c: Counter = 5  # implicitly converts from Int
```

## 复制构造函数

在 Mojo 中，你可以 *显式地* 或 *隐式地* 复制值：

```mojo
# Explicit copy
var s = "Test string"
var s2 = s.copy()

# Implicit copy
var i = 15
var i2 = i
```

要使结构体显式可复制，你需要：

- 添加 `Copyable` trait。
- （可选）如果需要，定义自定义复制构造函数，写为 `def __init__(out self, *, copy: Self)`。

通过添加 `Copyable` trait，Mojo 可以为你生成默认的复制构造函数，除非你自己编写了一个。此默认方法将所复制值的每个字段复制到新值中。`Copyable` trait 还定义了一个默认的 `copy()` 方法，它提供了复制值的另一种方式，而不是直接调用复制构造函数：

```mojo
@fieldwise_init
struct MyPet(Copyable):
    var name: String
    var age: Int
```

现在这段代码可以用于创建副本：

```mojo
var mine = MyPet("Loki", 4)
var yours = mine.copy()
```

:::note
从技术上讲，你 *可以* 创建一个具有复制构造函数但 *不* 添加 `Copyable` trait 的结构体，但不推荐这样做。Mojo 将能够复制该值，但你无法将此结构体与任何需要 `Copyable` trait 的参数化容器或函数一起使用。
:::

生成的复制构造函数只是将现有值中的每个字段复制到新值中。例如，如果你手动为 `MyPet` 编写复制构造函数，它看起来会是这样的：

```mojo
def __init__(out self, *, copy: Self):
    self.name = copy.name
    self.age = copy.age
```

此默认复制构造函数在大多数情况下都有效，但在少数情况下你需要定义自定义复制构造函数：

- 结构体的一个或多个字段不是 `Copyable`。
- 结构体包含非拥有类型（如 [`Pointer`](/docs/std/memory/pointer/Pointer/)），并且你想要进行数据的深度复制。
- 结构体持有其他需要管理的资源（如文件描述符或网络套接字）。

### 自定义复制构造函数

与其他语言相比，Mojo 的复制行为的不同之处在于，复制构造函数被设计为按[值语义](/docs/manual/values/value-semantics/)对类型中的所有字段执行深度复制。也就是说，它复制堆分配的值，而不仅仅是复制指针。

然而，Mojo 编译器并不强制执行此操作，因此实现具有值语义的复制构造函数是类型作者的责任。

例如，这里有一个新的 `HeapArray` 类型，具有执行深度复制的自定义复制构造函数：

```mojo
from std.memory import alloc, dealloc, ThinAllocation

struct HeapArray(Copyable, Writable):
    var data: ThinAllocation[Int]
    var size: Int
    var cap: Int

    def __init__(out self, size: Int, val: Int):
        self.size = size
        self.cap = size * 2
        self.data = alloc[Int]({count = self.cap}).into_thin()
        var ptr = self.data.unsafe_ptr()
        for i in range(self.size):
            ptr.unsafe_offset(i).unsafe_write(val)

    def __init__(out self, *, copy: Self):
        # Deep-copy the existing value
        self.size = copy.size
        self.cap = copy.cap
        self.data = alloc[Int]({count = self.cap}).into_thin()
        var ptr = self.data.unsafe_ptr()
        for i in range(self.size):
            var copy_ptr = copy.data.unsafe_ptr()
            ptr.unsafe_offset(i).unsafe_write(copy_ptr[unsafe_offset=i])
        # The lifetime of `copy` continues unchanged

    def __deinit__(deinit self):
        # We must free the heap-allocated data, but
        # Mojo knows how to destroy the other fields
        var ptr = self.data.unsafe_ptr()
        for i in range(self.size):
            ptr.unsafe_offset(i).unsafe_deinit_pointee()
        dealloc(
            self.data^.unsafe_with_layout({count = self.cap})
        )

    def append(mut self, val: Int):
        # Update the array for demo purposes
        if self.size < self.cap:
            var ptr = self.data.unsafe_ptr()
            ptr.unsafe_offset(self.size).unsafe_write(val)
            self.size += 1
        else:
            print("Out of bounds")

    def write_to(self, mut writer: Some[Writer]):
        writer.write("[")
        var ptr = self.data.unsafe_ptr()
        for i in range(self.size):
            writer.write(ptr[unsafe_offset=i])
            if i < self.size - 1:
                writer.write(", ")
        writer.write("]")
```

请注意，复制构造函数并不复制 `UnsafePointer` 值（这样做会使复制的值引用与原始值相同的 `data` 内存地址，这是一个浅复制）。相反，初始化一个新的 `UnsafePointer` 来分配一个新的内存块，然后复制所有堆分配的值（这是一个深度复制）。

当复制 `HeapArray` 的实例时，每个副本在堆上都有自己的值集合，因此对一个数组的更改不会影响另一个，如下所示：

```mojo
    var a = HeapArray(2, 1)
    var b = a.copy()  # Calls the copy method
    print(a)  # Prints [1, 1]
    print(b)  # Prints [1, 1]

    b.append(2)  # Changes the copied data
    print(b)   # Prints [1, 1, 2]
    print(a)   # Prints [1, 1] (the original did not change)
```

从复制构造函数中还有两点值得注意：

- `copy` 参数的类型是 `Self`（大写 "S"）。`Self` 是当前类型名的别名（在此示例中为 `HeapArray`）。在引用当前结构体名称时使用此别名是避免出现任何错误的最佳实践。

- `copy` 参数是不可变的，因为默认的[参数约定](/docs/manual/values/ownership#argument-conventions)是不可变引用。这是一件好事，因为此函数不应修改它所复制的值的内容。

:::note
在 `HeapArray` 中，使用 `__deinit__()` 在 `HeapArray` 生命周期结束时释放堆分配的数据。Mojo 会在各自的生命周期结束时自动销毁所有其他字段。
:::

如果你的类型不使用任何指针来处理堆分配的数据，那么编写构造函数和复制构造函数就是你不应该编写的样板代码。对于大多数不显式管理内存的结构体，你可以将 `Copyable` trait 添加到结构体定义中，Mojo 将合成复制构造函数。

:::note
当值被传递给将参数作为 [`var`](/docs/manual/values/ownership/#transfer-arguments-var-and-) 接收的函数，*并且* 给定值的生命周期在此时 *不* 结束时，Mojo 也会调用复制构造函数。如果值的生命周期确实在此时结束（通常用转移信号 `^` 表示），那么 Mojo 会改为调用移动构造函数。
:::

### 非拥有类型

在 Mojo 中，默认的期望是复制一个值会产生一个独立的值——一个深度复制。

但有时，结构体 *避免* 复制数据会更高效。[`Span`](/docs/std/collections/span/Span/) 和 [`StringSpan`](/docs/std/collections/string/string_span/StringSpan/) 是 *非拥有类型*（non-owning types）的示例，它们持有指向不属于自己的底层数据的指针。

当你复制非拥有类型时，它通常复制 *指针*，使原始值和副本都指向相同的数据。

`StringSpan` 表示对连续字符串数据的非拥有视图。在操作字符串时使用 `StringSpan` 可能非常高效，因为它不复制字符串数据。例如，当使用切片操作提取字符串的一部分时，你会得到一个引用原始字符串数据的 `StringSpan`。实际的 `StringSpan` 不需要复制任何字符串数据：它只持有一个指向子字符串开头的指针和子字符串的长度。

通过编写自定义构造函数，Mojo 使构建像 `StringSpan` 这样的非拥有类型变得容易。由于 Mojo 类型通常拥有其数据，因此你应清楚地记录任何非拥有类型，或任何返回非拥有视图的方法。

### 隐式可复制类型

要使类型 *隐式可复制*，请添加 [`ImplicitlyCopyable`](/docs/std/traits/copyable/ImplicitlyCopyable/) trait：

```mojo
@fieldwise_init
struct MyPair(ImplicitlyCopyable):
    var first: Int
    var second: Int

def main():
    var pair = MyPair(3, 4)
    var copy = pair
    print(pair.first, copy.second)
```

`ImplicitlyCopyable` trait 细化了 `Copyable`，因此将 `ImplicitlyCopyable` 添加到你的类型会给你 `Copyable` 的复制构造函数和一个 `copy()` 方法。它还为你提供自动的 `Movable` 一致性。

此 trait 不定义任何自己的方法：它作为信号告诉编译器可以根据需要插入复制构造函数的调用。例如，在前面的示例中，编译器可能会生成等效于以下内容的代码：

```mojo
var pair = MyPair(3, 4)
var copy = pair.copy()
```

只有当复制类型成本低廉且没有副作用时，类型才应该是隐式可复制的。不必要的复制可能是对内存和性能的巨大消耗，因此请谨慎使用此 trait。

特别是，任何动态分配内存或管理其他资源的类型可能都不应该是隐式可复制的。

## 移动构造函数

虽然复制值提供了与 Mojo 的[值语义](/docs/manual/values/value-semantics/)相匹配的可预测行为，但复制某些数据类型可能会对性能产生重大影响。

Mojo 使用移动构造函数将值的所有权从一个变量转移到另一个变量，*而无需* 复制其字段。一个可复制但没有移动构造函数的值仍然可以通过复制然后丢弃原始值来转移。因此，在这种情况下，移动构造函数作为一种优化。

要使类型 *可移动*：

- 添加 `Movable` trait *或* 遵循 `Copyable`。
- （可选）实现自定义移动构造函数。

以下是 `MyPet` 结构体的一个可移动（也可复制）版本：

```mojo
@fieldwise_init
struct MyPet(Copyable):
    var name: String
    var age: Int
```

以下是一个展示如何为 `MyPet` 调用移动构造函数的示例：

```mojo
def moves():
    var a = MyPet("Bobo", 2)

    print(a.name) # Prints "bobo"

    var b = a^ # the lifetime of `a` ends here

    print(b.name) # prints "bobo"
    # print(a.name)  # ERROR: use of uninitialized value 'a'
```

如果你包含 `Movable` trait 但没有定义移动构造函数，Mojo 会为你生成一个默认的移动构造函数。此移动构造函数只是将每个字段移动到新实例。

如果你自己编写，`MyPet` 的生成移动构造函数会是这样的：

```mojo
def __init__(out self, *, deinit move: Self):  # move initializer
    self.name = move.name^
    self.age = move.age
```

移动构造函数使用 `deinit` [参数约定](/docs/manual/values/ownership/#argument-conventions)接收其 `move` 参数，该约定授予对值的独占所有权并在函数结束时将其标记为已销毁。（有关 `deinit` 约定的更多信息，请参阅[析构和移动期间的字段生命周期](/docs/manual/lifecycle/death/#field-lifetimes-during-destruct-and-move)。）

移动构造函数使用转移信号（`^`）指示 `name` 值的所有权从 `move` 转移到 `self`。对于像 `Int` 这样的简单寄存器可传递类型，省略转移信号。简单类型总是可移动的。由于它们不能定义自定义移动构造函数或析构函数，因此移动不需要特殊逻辑。

在移动构造函数方法结束时，Mojo 立即使原始变量失效，防止对其的任何访问。因为参数被声明为 `deinit`，它 *不* 调用析构函数，因为那会销毁已转移到新实例的资源。使原始变量失效对于避免堆分配数据上的内存错误（如释放后使用和双重释放错误）很重要。

:::note
移动构造函数 *不需要* 转移值的所有权。Mojo 可以复制值并使原始实例失效。你可以在关于[所有权转移](/docs/manual/values/ownership#transfer-arguments-var-and-)的部分了解更多信息。

如果复制一个类型很昂贵，使用移动构造函数移动它要高效得多。例如，如果一个类型有堆分配的数据，复制构造函数通常需要分配新的存储来对数据进行深度复制。

对于没有堆分配字段的结构体，你从移动构造函数中得不到真正的好处。在栈上复制简单数据类型（如整数、浮点数和布尔值）非常便宜。然而，如果你允许你的类型被复制，那么通常没有理由禁止移动。
:::

### 自定义移动构造函数

实际上，结构体很少需要自定义移动构造函数。如果一个类型有指向自身或其某个字段的指针，则该类型可能需要自定义实现，因为结构体在移动时其在内存中的位置会改变。

移动构造函数执行消耗性移动：当原始变量的生命周期结束时，它将值的所有权从一个变量[转移](/docs/manual/values/ownership#transfer-arguments-var-and-)到另一个变量（也称为"破坏性移动"）。

移动构造函数的一个关键特征是它将传入值作为 `deinit` 参数接收，这意味着此方法获得了对该值的唯一所有权。此外，由于这是一个 Mojo 仅在执行移动（在所有权转移期间）时调用的 dunder 方法，Mojo 保证 `move` 参数是对原始值的可变引用，*而不是副本*（与其他可能将参数声明为 `var` 的方法不同，但如果在没有 [`^` 转移信号](/docs/manual/values/ownership/#transfer-arguments-var-and-)的情况下调用方法，则可能接收到副本）。也就是说，Mojo *仅* 在原始变量的生命周期确实在转移点结束时才调用此移动构造函数。

## 仅可移动和不可移动类型

为了防止类型被隐式复制，你可以通过使其 `Movable` 但不是 `Copyable` 来使其成为"仅可移动"。你可以将仅可移动类型传递给其他变量，并使用任何参数约定（如 `mut` 或 `var`）传递给函数。唯一需要注意的是，在将仅可移动类型赋值给新变量或作为 `var` 参数传递时，你必须使用 `^` 转移信号来结束其生命周期。[`OwnedPointer`](/docs/std/memory/owned_pointer/OwnedPointer/) 是仅可移动类型的一个示例：因为它提供了对存储值的清晰单一所有权，所以你可以移动 `OwnedPointer`，但不能复制它。

在某些（罕见的）情况下，你可能不希望类型可复制 *或* 可移动。[`Atomic`](/docs/std/atomic/atomic/Atomic/) 类型是一个既不可复制也不可移动的类型的示例。
