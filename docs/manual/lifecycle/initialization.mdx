Mojo 为结构体跟踪两种初始化：_字段初始化_（fieldwise）和 _逻辑初始化_（logical）。

字段初始化意味着结构体的存储中每个字段都持有有效值。逻辑初始化意味着实例作为一个整体处于有效的、可用的状态。

理解这两种初始化形式之间的区别对于正确使用结构体至关重要。

## 基础

通过调用 `__init__()` 构造函数来创建结构体实例：

```mojo
struct Person:
    var name: String
    var age: Int

    def __init__(out self, name: String, age: Int):
        self.name = name
        self.age = age

def main():
    var me = Person("Alice", 30)
```

调用 `Person("Alice", 30)` 是直接调用构造函数的语法糖：

```mojo
var me: Person
me = Person.__init__("Alice", 30) # Identical
```

在构造 Person 时，编译器首先为实例 `me` 分配栈空间，然后由 `__init__()` 初始化该空间。

## 字段初始化与逻辑初始化

通过直接为字段赋值来初始化结构体可能会填充数据，但不会使实例变为可用：

```mojo
struct Person(Writable):
    var age: Int
    var height: Int

    ...

def main():
    var me: Person
    me.age = 25
    me.height = 6
    print(me)  # Error
    # error: 'me' used with all fields manually initialized
    # but without calling an '__init__' method
```

在这个示例中，所有字段都包含有效值，但实例仍不被视为已初始化。

Mojo 跟踪两种不同的初始化状态：

- 字段初始化意味着每个字段都包含有效数据，并且实例的存储已被填充。
- 逻辑初始化意味着实例作为一个整体是有效的，并且其 `__init__()` 方法已经运行。

仅靠字段初始化是不够的。编译器要求实例在使用前完成逻辑初始化：

```mojo
var me = Person(25, 6)  # Now OK: __init__() ran
print(me)
```

调用 `__init__()` 使实例 _逻辑上_ 被初始化。这个过程不仅仅是赋值数据。它确保任何所需的初始化逻辑都已运行，并且实例可以安全使用。

## `__init__()` 内部

在 `__init__()` 内部，传入的 `self` 实例被视为逻辑上已初始化，但其字段仍未初始化：

```mojo
def __init__(out self, name: String, age: Int):
    # At this point:
    # - Logically initialized (self is valid as an instance)
    # - Fieldwise uninitialized (fields have no values yet)

    self.name = name
    self.age = age

    # Now both logically and fieldwise initialized
```

这种区分是有意为之的。进入 `__init__()` 确立了实例本身，但填充其字段是你的责任。

你必须在 `__init__()` 中初始化 _每一个字段_：

```mojo
def __init__(out self, name: String, age: Int):
    self.name = name
    # Error: field 'age' not initialized in __init__
```

`__init__()` 的签名不必与结构体的字段一一对应。你可以使用参数、常量或外部值来初始化这些字段：

```mojo
# Parameters can be used to initialize fields
self._store = List[T](capacity=Count)

# Constants can be used to initialize fields
self.string = ""

# External values can be used to initialize fields
from std.math import pi
self.default_angle = pi / 2.0
self.uuid = MyUUIDImplementation.uuid()
```

在所有字段初始化完成之前，你不能调用方法：

```mojo
def __init__(out self, name: String):
    self.greet()      # Error: self not fully initialized
    self.name = name
    self.greet()      # OK: all fields initialized
```

字段初始化仅限于 `__init__()` 方法。普通函数不能 _初始化_ `out` 参数的各个字段，但 `__init__()` 方法可以。

## 从字段中移动

将值从字段中移出会 _析构该字段_：

```mojo
struct Person(Writable):
    var name: String
    var age: Int

    def __init__(out self, name: String, age: Int):
        self.name = name
        self.age = age

def main():
    var me = Person("Connor", 25)
    var name_owner = me.name^  # Move value from me.name.
    print(me)     # Error: use of uninitialized value 'me'
```

移动之后，实例仍然 _逻辑上已初始化_，但它只是部分 _字段初始化_。Mojo 不允许使用具有未初始化字段的实例。

要使实例再次可用，你必须重新初始化被移动的字段：

```mojo
var me = Person("Connor", 25)
var name_owner = me.name^
me.name = "John"      # Reinitialize field
print(me)             # OK
use_value(name_owner) # Now, use name_owner
```

任何被移动的字段都需要一个新值才能再次使用该实例。即使 _所有_ 字段都被移动，实例本身仍然保持逻辑上已初始化。

## Mojo 的默认析构函数

`__deinit__()` 是 Mojo 的默认 _析构函数_（deinitializer）。在其运行期间，实例保持逻辑上已初始化，当方法完成时它变为逻辑上已析构：

```mojo
@fieldwise_init
struct Contact:
    var name: String
    var email: String

    def __deinit__(deinit self):
        # `self` is initialized
        print("destroying contact")
        # `self` remains initialized until this method completes

def main():
    var me = Contact("Alice", "alice@example.com")
    # Last use of `me` (and end of scope)
    # Prints "destroying contact" along with a warning
    # since the instance was never used after assignment.
```

## 析构函数与移动字段

析构函数是唯一可以安全地从实例字段中移出值，而无需在其下一次使用前重新初始化该字段的地方。

这个特殊规则与代码所在位置无关。它关乎的是保证：

```mojo
def __deinit__(deinit self):
    var name = self.name^  # OK: can take ownership of fields
```

编译器知道像 `__deinit__()` 这样的析构函数是实例的最终使用。因此，它允许你从字段中移出值而无需重新初始化它们。

这确保了只有当编译器能保证实例处于其生命周期末尾时，字段才会从结构体实例中被移出。

与实例一样，结构体字段在 `__deinit__()` 方法内使用 ASAP 销毁。例如：

```mojo
struct S:
   var a: String
   var b: String

   def __deinit__(deinit self):
       # Mojo calls a.__deinit__() here.
       use(b)
       # Mojo calls b.__deinit__() here.
```

## `deinit` 约定

析构函数的秘密武器是 `deinit` 约定。因此，`deinit self` 在命名的析构函数和 `__deinit__()` 中都有效：

```mojo
struct Parent:
    def consume(deinit self):
        # `consume` is a named deinitializer
        # Can move values out of fields here too
```

当你在方法中使用 `deinit self` 约定时，编译器会识别该方法为析构函数，并允许你移动字段而无需重新初始化它：

```mojo
struct Parent:
    def consume(deinit self):
        """valid deinitializer"""
        var name = self.name^
        print("Name:", name) # Prints name
```

任何使用 `deinit self` 作为第一个参数的结构体方法在技术上都是析构函数。除非类型遵循 `Deinitable where False`，否则它不会参与显式销毁。

## 显式和隐式析构函数

`__deinit__()` 方法是隐式销毁类型的核心。它是 Mojo 的默认析构函数，与 `Deinitable` 协同工作，后者是所有结构体默认遵循的 trait。当编译器检测到 `Deinitable` 结构体值的最终使用时，会自动调用 `__deinit__()`。

顾名思义，显式销毁要求你调用析构函数。显式销毁的类型必须定义至少一个自定义析构函数，例如上一节中所示的 `consume()` 方法。编译器确保显式销毁值的最终使用将是对其自定义析构函数之一的调用。

### 将 `deinit` 与其他参数一起使用

`deinit` 约定不限于 `self`。你可以编写销毁其他实例的方法和函数：

```mojo
struct Pair:
    def destroy_other(self, deinit other: Self):
        # Can take from fields of `other` here
```

与 `deinit self` 一样，此示例中的 `deinit` 约定告诉编译器 `other` 被标记为销毁。

使用 `deinit` 意味着 `other` 在方法结束时被逻辑上已析构。因此，从 `other` 中移出值是安全的，因为实例的生命周期保证会完成。

## 普通方法与移动字段

在普通方法中，你不能在不重新初始化字段的情况下从结构体的字段中移出值：

```mojo
@fieldwise_init
struct MyStruct:
    var name: String

    def move_field(mut self, var new_name: String):
        var name = self.name^ # Error
        # error: 'self.name' is uninitialized at the implicit return
        #        from this function
        print("Name:", name)

def main():
    var instance = MyStruct("Ken")
    instance.move_field("Scott")
    print("Name:", instance.name) # Prints: "Name: Scott"
```

要安全地移动，请在作用域结束之前重新初始化实例的字段。以下更新通过重新初始化该字段修复了 bug：

```mojo
def move_field(mut self, var new_name: String):
    var name = self.name^
    print("Name:", name)  # Prints name
    self.name = new_name^ # reinitialize the name field
```

## 销毁实例

除非你通过遵循 `Deinitable where False` 来选择[显式销毁](/docs/manual/lifecycle/death/#explicitly-destroyed-types)，否则 Mojo 使用隐式销毁。

```mojo
def example():
    var x = SomeType()
    use(x) # last use in scope
    # x destroyed here, immediately after last use

    more_code()  # x is already gone
```

采用 ASAP 销毁（默认的隐式方式）时，Mojo 在实例的最后一次使用后立即销毁它们，而不是在作用域结束时。这甚至可能发生在表达式中间。

这与许多具有编译器管理生命周期的语言不同，那些语言在作用域结束时销毁。Mojo 的 ASAP 销毁支持更好的尾调用优化，但它也意味着析构函数可能比你预期的更早运行。

Mojo 还支持 _显式销毁类型_，这要求你显式调用析构函数方法。有关更多信息，请参阅[显式销毁类型](/docs/manual/lifecycle/death/#explicitly-destroyed-types)。

Mojo 跟踪你代码中值的生存期。它知道你何时使用转移运算符（`^`）移出值，或者你何时调用显式销毁它的 `deinit` 方法。如果编译器发现一个尚未以其他方式清理的活值，它会使用隐式析构函数（`__deinit__(deinit self...)`）来销毁它。

如果某个类型因为没有隐式析构函数而需要显式销毁，编译器会发出错误。

虽然编译器会检查在实例超出作用域之前是否调用了析构函数，但由你选择 _何时_ 发生。关键区别是：

- 析构不会在最后一次使用时自动发生。
- 显式析构函数不命名为 `__deinit__()`。

## 对象初始化总结

在 Mojo 中创建、使用和销毁实例遵循一套基于初始化状态的一致规则。

通过调用 `__init__()` 创建实例。你必须在构造函数中初始化每个字段，特别是如果你计划在方法作用域内使用该实例。除非结构体的所有字段都已初始化，否则你不能在该结构体上调用方法。

在使用实例之前，你必须 _逻辑上_ 初始化它，这意味着调用构造函数。你还必须在访问字段之前初始化它们。部分初始化的实例不能在许多上下文中使用，包括方法调用和返回值。

对于隐式销毁的结构体，编译器在实例的最后一次使用之后插入析构函数调用。对于显式销毁的值，你必须在实例超出作用域之前调用析构函数。析构由编译器检查，但由你选择何时发生。该值在作用域中的最终使用必须是该显式析构函数调用。

字段操作也受到限制。字段初始化必须在 `__init__()` 构造函数内部进行。只有当编译器能证明实例不会被再次使用，或者该字段会在普通方法结束前被重新初始化时，你才能从字段中移出值。

逻辑初始化和字段初始化之间的这种划分使 Mojo 能够对实例生存期进行细粒度控制，同时确保初始化、使用和析构保持安全和显式。
