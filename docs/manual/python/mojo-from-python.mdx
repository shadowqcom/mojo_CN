如果你有一个现有的 Python 项目，希望利用 Mojo 的高性能计算能力，你不需要用 Mojo 重写整个项目。相反，你可以只用 Mojo 编写性能关键部分的代码，然后从 Python 调用它。

:::experiment Beta 功能

从 Python 调用 Mojo 代码仍处于早期开发阶段。你应该预期 API 和使用体验会有大量变化。同样，本文档仍在完善中。请参阅下方的[已知限制](#known-limitations)。

:::

## 在 Python 中导入 Mojo 模块

为了说明从 Python 调用 Mojo 是什么样的，我们将从一个简单的示例开始，然后深入了解它的工作原理以及目前可以实现的功能。

考虑一个具有以下结构的项目：

```text
project
├── 🐍 main.py
└── 🔥 mojo_module.mojo
```

主入口是一个名为 `main.py` 的 Python 程序，Mojo 代码包含要从 Python 调用的函数。

例如，假设我们想要一个 Mojo 函数来接受一个 Python 值作为参数：

```mojo title="mojo_module.mojo"
def factorial(py_obj: PythonObject) raises -> Python
    var n = Int(py=py_obj)
    return math.factorial(n)
```

我们想从 Python 这样调用它：

```python title="main.py"
import mojo_module

print(mojo_module.factorial(5))
```

然而，在我们能从 Python 调用 Mojo 函数之前，我们必须声明它，以便 Python 知道它的存在。

因为 Python 正在尝试加载 `mojo_module`，它会查找一个名为 `PyInit_mojo_module()` 的函数。（如果我们的文件名为 `foo.mojo`，Python 查找的函数就是 `PyInit_foo()`。）在 `PyInit_mojo_module()` 中，我们必须使用 [`PythonModuleBuilder`](/docs/std/python/bindings/PythonModuleBuilder/) 声明所有可从 Python 调用的 Mojo 函数和类型。

所以完整的 Mojo 代码如下：

```mojo title="mojo_module.mojo"
from std.python import PythonObject
from std.python.bindings import PythonModuleBuilder
from std import math
from std.os import abort

@export
def PyInit_mojo_module() abi("C") -> PythonObject:
    try:
        var m = PythonModuleBuilder("mojo_module")
        m.def_function[factorial]("factorial", docstring="Compute n!")
        return m.finalize()
    except e:
        abort(String("error creating Python Mojo module:", e))

def factorial(py_obj: PythonObject) raises -> PythonObject:
    # Raises an exception if `py_obj` is not convertible to a Mojo `Int`.
    var n = Int(py=py_obj)

    return math.factorial(n)
```

在 Python 端，我们将包含 `mojo_module.mojo` 的目录添加到 Python 路径中，然后使用普通的 `import` 语句加载我们的 Mojo 代码：

```python title="main.py"
import mojo.importer
import mojo_module

print(mojo_module.factorial(5))
```

就是这样！试试看：

```sh
python main.py
```

```output
120
```

### 工作原理

Python 支持一种称为 [Python 扩展模块](https://docs.python.org/3/extending/extending.html)的标准机制，使编译型语言（如 Mojo、C、C++ 或 Rust）能够以直观的方式从 Python 调用。具体来说，Python 扩展模块就是一个定义了合适的 `PyInit_*()` 函数的动态库。

Mojo 内置了定义 Python 扩展模块的功能。关键在于我们导入的 `mojo.importer` 模块。

如果我们查看 Python 导入 Mojo 代码后的文件系统，会注意到有一个新的 `__mojocache__` 目录，其中包含一个动态库（`.so`）文件：

```text
project
├── main.py
├── mojo_module.mojo
└── __mojocache__
    └── mojo_module.hash-ABC123.so
```

加载 `mojo.importer` 会加载我们的 Python Mojo [导入钩子（import hook）](https://docs.python.org/3/reference/import.html#import-hooks)，它在后台查找与导入模块名匹配的 `.mojo` 文件，如果找到，则使用 [`mojo build --emit shared-lib`](/docs/cli/build/#--emit-file_type) 编译它以生成动态库。生成的文件存储在 `__mojocache__` 中，只有在过期时（通常是当 Mojo 源文件发生变化时）才会重新构建。

:::note 清除缓存的构建产物
`__mojocache__` 目录应仅包含派生产物。删除 `__mojocache__` 目录的内容始终是安全的。需要的产物会在下次导入 Mojo 模块时自动重建。
:::

### 导出函数的 `abi`

[`@export`](/docs/reference/decorators/export/) 函数必须通过显式的 [`abi`](/docs/reference/function-declarations#abi-c) effect 声明它使用的调用约定。在 Python 扩展模块中，你唯一需要导出的函数是 `PyInit_<module>` 入口点，它必须使用 `abi("C")`：

```mojo
@export
def PyInit_mojo_module() abi("C") -> PythonObject:
    ...
```

这是因为 CPython 运行时直接跨 C 边界定位并调用 `PyInit_<module>`，因此它必须暴露 C 调用约定。`abi("C")` 函数不能标记为 `raises`，这就是为什么上面的示例在函数体内捕获任何错误并调用 `abort` 而不是传播它的原因。

你通过模块构建器注册的函数、方法和初始化器（`def_function`、`def_method`、`def_py_init` 等）根本不需要 `@export`；你通过引用传递它们，Mojo 会生成 CPython 实际调用的 C 包装器。该包装器使用 Mojo 调用约定调用你的函数，并将任何抛出的错误转换为 Python 异常，因此像上面的 `factorial` 这样的已注册函数可以自由地标记为 `raises`。

现在我们已经了解了 Mojo 从 Python 调用的基本原理，接下来深入了解可用功能以及如何利用它们用 Mojo 加速你的 Python 代码。

## 绑定功能

### 绑定 Mojo 类型

你可以使用 [`PythonModuleBuilder`](/docs/std/python/bindings/PythonModuleBuilder/) 绑定任何 Mojo 类型以供 Python 使用。例如：

```mojo
@fieldwise_init
struct Person(Movable, Writable):
    var name: String
    var age: Int

@export
def PyInit_person_module() abi("C") -> PythonObject:
    try:
        var mb = PythonModuleBuilder("person_module")
        var person_type = mb.add_type[Person]("Person")
    except e:
        abort("error creating Mojo module")
```

当你调用 [`add_type()`](/docs/std/python/bindings/PythonModuleBuilder/#add_type) 时，它返回一个 [`PythonTypeBuilder`](/docs/std/python/bindings/PythonTypeBuilder/)，然后你可以用它来绑定类型构造函数（参见下方[绑定 Python 初始化器](#constructing-mojo-objects-in-python)）和方法。

任何使用 `PythonTypeBuilder` 绑定的 Mojo 类型都会在全局注册生成的 Python 'type' 对象，从而启用两个功能：

- 使用 `PythonObject(alloc=Person(..))` 构造包装 Mojo 值的 Python 对象，以供 Python 端使用。

- 使用 `python_obj.downcast_value_ptr[Person]()` 进行向下转型。

:::note

Mojo 类型必须实现 [`Writable`](/docs/std/format/Writable/) 才能被绑定供 Python 使用。特定绑定功能还需要额外的特征：自定义初始化器（`def_py_init`）需要 `Movable`，默认初始化器（`def_init_defaultable`）需要 `Defaultable` 和 `Movable`。

:::

然而，仅仅将 Mojo 类型绑定到 Python `type` 对象本身并不太有用。接下来，我们将告诉 Python 如何与我们的 Mojo 类型交互——首先是如何从 Python 中构造我们的 Mojo 类型的实例。

### 在 Python 中构造 Mojo 对象

Mojo 类型可以通过将 Mojo 初始化器函数声明为 Python 兼容的对象初始化器，在将类型添加到模块时使用 [`def_py_init()`](/docs/std/python/bindings/PythonTypeBuilder/#def_py_init) 从 Python 进行构造。例如：

```mojo
@export
def PyInit_person_module() abi("C") -> PythonObject:
    try:
        var mb = PythonModuleBuilder("person_module")
        # highlight-start
        _ = mb.add_type[Person]("Person").def_py_init[Person.py_init]()
        # highlight-end
        return mb.finalize()
    except e:
        abort(String("error creating Python Mojo module:", e))

@fieldwise_init
struct Person(Movable, Writable):
    var name: String
    var age: Int

    # highlight-start
    @staticmethod
    def py_init(
        out self: Person, args: PythonObject, kwargs: PythonObject
    ) raises:
        # Validate argument count
        if len(args) != 2:
            raise Error("Person() takes exactly 2 arguments")

        # Convert Python arguments to Mojo types
        var name = String(args[0])
        var age = Int(args[1])

        self = Self(name, age)
    # highlight-end
```

有了这个 Mojo 绑定，你可以在 Python 中创建 `Person` 实例：

```python
person = person_module.Person("Sarah", 32)
print(person)
```

```output
Person(name=Sarah, age=32)
```

对于支持默认构造的类型，你可以使用更简单的 [`def_init_defaultable()`](/docs/std/python/bindings/PythonTypeBuilder/#def_init_defaultable) 方法：

```mojo
var counter_type = m.add_type[Counter]("Counter")
counter_type.def_init_defaultable[Counter]()
```

这使得 Python 代码可以创建不带参数的实例：

```python
counter = counter_module.Counter()  # Creates Counter()
```

:::note "构造函数"与"初始化器"

在 Python 中，对象构造发生在 `__new__()` 和 `__init__()` 两个方法中，因此 `__init__()` 方法严格来说只是属性初始化器。然而，在 Mojo struct 中没有 `__new__()` 方法，因此我们倾向于始终将 `__init__()` 称为初始化器。

:::

### 将 Mojo 对象返回给 Python

从 Python 调用的 Mojo 函数不仅需要能够接受 [`PythonObject`](/docs/std/python/python_object/PythonObject/) 值作为参数，还需要能够返回新值。有时，它们甚至需要能够将 Mojo 原生值返回给 Python。这可以通过使用 `PythonObject(alloc=<value>)` 构造函数来实现。

示例如下：

```mojo
def create_person() -> PythonObject:
    var person = Person("Sarah", 32)
    return PythonObject(alloc=person^)
```

:::caution

如果提供的 Mojo 对象类型之前没有通过 [`PythonModuleBuilder.add_type()`](/docs/std/python/bindings/PythonModuleBuilder/#add_type) 注册，`PythonObject(alloc=...)` 将抛出异常。

:::

### `PythonObject` 转换为 Mojo 值

在任何处理 [`PythonObject`](/docs/std/python/python_object/PythonObject/) 的 Mojo 代码中，尤其是从 Python 调用的 Mojo 函数中，通常需要期望特定类型的参数。

将 `PythonObject` 转换为原生 Mojo 值有两种方式：

- **转换**：将 Python 对象转换为具有相同逻辑值的新构造的 Mojo 值。
  这由 [`ConvertibleFromPython`][ConvertibleFromPython] 特征处理。

- **向下转型**：将持有原生 Mojo 值的 Python 对象向下转型为指向该内部值的指针。
  这由 [`PythonObject.downcast_value_ptr()`][downcast_value_ptr] 处理。

#### `PythonObject` 转换

许多 Mojo 类型支持通过 [`ConvertibleFromPython`][ConvertibleFromPython] 特征直接从等效的 Python 类型转换：

```mojo
# Given a person, clone them and give them a different name.
def create_person(
    name_obj: PythonObject,
    age_obj: PythonObject
) raises -> PythonObject:
    # These conversions will raise an exception if they fail
    var name = String(name_obj)
    var age = Int(age_obj)

    return PythonObject(alloc=Person(name, age))
```

可以从 Python 这样调用：

```python
person = mojo_module.create_person("John Smith")
```

传递无效参数将导致运行时参数错误：

```python
person = mojo_module.create_person(42)
```

#### `PythonObject` 向下转型

从 `PythonObject` 值向下转型到内部 Mojo 值：

```mojo
def print_age(person_obj: PythonObject) raises:
    # Raises if `obj` does not contain an instance of the Mojo `Person` type.
    var person = person_obj.downcast_value_ptr[Person]()

    print("Person is", person[].age, "years old")
```

通过向下转型也支持不安全修改。用户需要确保此可变指针不会与 Mojo 中指向同一对象的其他指针产生别名：

```mojo
def birthday(person_obj: PythonObject):
    var person = person_obj.downcast_value_ptr[Person]()

    person[].age += 1
```

完全不检查的向下转型——不进行类型检查——可以使用：

```mojo
def get_person(person_obj: PythonObject):
    var person = person_obj.unchecked_downcast_value_ptr[Person]()
```

不检查的向下转型可用于在优化紧凑内循环时消除开销，当你已经通过基准测试确认类型检查的向下转型是显著瓶颈时。

### 方法

在绑定 Mojo 对象供 Python 使用时，你也可以使用 [`PythonTypeBuilder.def_method()`](/docs/std/python/bindings/PythonTypeBuilder/#def_method) 将选定的方法暴露给 Python。

目前，暴露给 Python 的 Mojo 方法与普通 Mojo 方法相比需要做一些修改：它们必须是 `@staticmethod`，接受 `py_self: PythonObject` 或 `self_ptr: Pointer[Self]`：

```mojo
from std.python import PythonObject
from std.python.bindings import PythonModuleBuilder
from std.os import abort

@export
def PyInit_mojo_module() abi("C") -> PythonObject:
    try:
        var mb = PythonModuleBuilder("mojo_module")
        # highlight-start
        _ = mb.add_type[Person]("Person")
            .def_method[Person.get_name]("get_name")
            .def_method[Person.set_age]("set_age")
        # highlight-end
        return mb.finalize()
    except e:
        abort("error creating Mojo module")

struct Person(Writable):
    var name: String
    var age: Int

    # highlight-start
    @staticmethod
    def get_name(py_self: PythonObject) raises -> PythonObject:
        var self_ptr = py_self.downcast_value_ptr[Self]()
        return self_ptr[].name

    @staticmethod
    def set_age(
        self_ptr: Pointer[mut=True, Self],
        new_age: PythonObject,
    ) raises:
        self_ptr[].age = Int(new_age)
    # highlight-end

    def write_to(self, mut writer: Some[Writer]):
        t"Person({self.name}, {self.age})".write_to(writer)
```

接受 `py_self: PythonObject` 可以访问 Mojo 对象实例存储在其中的完整 `PythonObject` 分配。不过，在方法仅需访问对象字段的常见情况下，接受 `self_ptr: Pointer[Self]` 可以减少样板代码。

从 Python 调用的 Mojo 方法目前需要使用非标准的 self 类型，这是因为 Python Mojo 绑定的未来版本将解除的限制。

### 静态方法

Python Mojo 绑定支持暴露 Python `@staticmethods`，使用 [`PythonTypeBuilder.def_staticmethod()`](/docs/std/python/bindings/PythonTypeBuilder/#def_staticmethod) 绑定。使用 `def_staticmethod()` 声明的函数可以在 Python 中作为类型上的静态方法调用，无需对象实例。

```mojo
from std.python import PythonObject
from std.python.bindings import PythonModuleBuilder
from std.os import abort

@export
def PyInit_mojo_module() abi("C") -> PythonObject:
    try:
        var mb = PythonModuleBuilder("mojo_module")
        # highlight-start
        mb.add_type[Person]("Person")
            .def_staticmethod[Person.is_valid_age]("is_valid_age")
        # highlight-end
        return mb.finalize()
    except e:
        abort("error creating Mojo module")

struct Person(Writable):
    var name: String
    var age: Int

    # highlight-start
    @staticmethod
    def is_valid_age(age_obj: PythonObject) raises -> PythonObject:
        var age = Int(age_obj)
        return 0 <= age <= 130
    # highlight-end

    def write_to(self, mut writer: Some[Writer]):
        t"Person({self.name}, {self.age})".write_to(writer)
```

调用绑定为静态方法的 Mojo 函数就像在类型对象上直接调用典型的 Python 静态方法：

```python title="main.py"
from mojo_module import Person

print(Person.is_valid_age(45)) # Prints 'True'
print(Person.is_valid_age(-1)) # Prints 'False'
```

### 关键字参数

[Mojo 中的关键字参数](/docs/manual/functions/#keyword-arguments)有两种形式：

1. 仅关键字参数：`def foo(*, x: Int)`
   目前在 Python Mojo 绑定中不支持。
2. [可变关键字参数](/docs/manual/functions/#variadic-keyword-arguments)：
   `def foo(var **kwargs: Int)` 在 Python Mojo 绑定中使用非语法糖形式时受支持：`def foo(kwargs: StringDict)`。（`**kwargs` 语法限制将在未来移除。）

你可以使用 [`StringDict[PythonObject]`](/docs/std/collections/dict/StringDict/) 作为最后一个参数来定义接受可变关键字参数的 Mojo 函数。一个简单的示例如下：

```python
import mojo_module

result = mojo_module.sum_kwargs_ints(a=10, b=20, c=30)  # returns 60
```

```mojo
from std.collections import StringDict

def sum_kwargs_ints(kwargs: StringDict[PythonObject]) raises -> PythonObject:
    var total = 0
    for entry in kwargs.items():
        total += Int(entry.value)
    return PythonObject(total)
```

关键字参数也支持在普通位置参数之后使用。此外，获取特定关键字参数是通过对 `StringDict` 进行字典查找：

```mojo
from std.collections import StringDict

def duration_in_seconds(
    hours_obj: PythonObject,
    minutes_obj: PythonObject,
    kwargs: StringDict[PythonObject]
) raises -> PythonObject:
    var hours = Int(hours_obj)
    var minutes = Int(minutes_obj)

    var seconds = Int(kwargs["seconds"])

    return hours * 3600 + minutes * 60 + seconds
```

在此示例中，如果对 `duration_in_seconds()` 的调用缺少必需的 `"seconds"` 命名参数，将发生运行时异常：

```python title="main.py"
from mojo_module import duration_in_seconds

# Pass hours and minutes, missing "seconds"
duration_in_seconds(4, 5) # ERROR: KeyError
```

关键字参数在绑定顶层函数、方法和静态方法时均受支持。

### 可变参数

Python 和 Mojo 的可变参数通常使用以下语法编写：

```mojo
def foo(*args: Int):
    ...
```

然而，此语法在 Python/Mojo 绑定中尚不支持，因为使用 [`def_function()`](/docs/std/python/bindings/PythonModuleBuilder/#def_function) 绑定的函数仅支持固定参数数量的函数。

作为替代方案，你可以使用较低级别的 [`def_py_function()`](/docs/std/python/bindings/PythonModuleBuilder/#def_py_function) 接口将接受可变数量参数的 Mojo 函数暴露给 Python，该接口将验证提供的参数数量留给用户：

```mojo
@export
def PyInit_mojo_module() abi("C") -> PythonObject:
    try:
        var b = PythonModuleBuilder("mojo_module")
        b.def_py_function[count_args]("count_args")
        b.def_py_function[sum_args]("sum_args")
        b.def_py_function[lookup]("lookup")

def count_args(py_self: PythonObject, args_tuple: PythonObject) raises:
    return len(args_tuple)

def sum_args(py_self: PythonObject, args_tuple: PythonObject) raises:
    var total = args_tuple[0]
    for i in range(1, len(args_tuple)):
        total += args_tuple[i]
    return total

def lookup(py_self: PythonObject, args_tuple: PythonObject) raises:
    if len(args_tuple) != 2 and len(args_tuple) != 3:
        raise Error("lookup() expects 2 or 3 arguments")

    var collection = args_tuple[0]
    var key = args_tuple[1]

    try:
        return collection[key]
    except e:
        if len(args) == 3:
            return args_tuple[2]
        else:
            raise e
```

## 将 Python 移植到 Mojo 的策略

### 在 Mojo 中编写 Python 风格的代码

在这种绑定方法中，我们拥抱 Python 的灵活性，避免尝试将 `PythonObject` 参数转换为 Mojo 类型系统中严格约束的强类型空间，而是倾向于直接编写代码，如果出错就在运行时抛出异常。

`PythonObject` 的灵活性启用了一种独特的编程风格，其中 Python 代码可以以相对较少的更改"移植"到 Mojo。

```python
def foo(x, y, z):
    x[y] = int(z)
    x = y + z
```

经验法则：任何 Python 内置函数都应该可以在 Mojo 中使用 `Python.<builtin>()` 访问。

```mojo
def foo(x: PythonObject, y: PythonObject, z: PythonObject) -> PythonObject:
    x[y] = Python.int(z)
    x = y + z
```

## 构建 Mojo 扩展模块

你可以通过以下方式创建和分发用于 Python 的 Mojo 模块：

- 作为源文件，使用 Python Mojo 导入器钩子按需编译。

  这种方法的优点是易于上手，保持项目结构简单，同时确保导入的 Mojo 代码在编辑后始终是最新的。

- 作为预构建的 Python 扩展模块 `.so` 动态库，使用以下命令编译：

  ```bash
  mojo build mojo_module.mojo --emit shared-lib -o mojo_module.so
  ```

  这种方法的优点是可以手动指定任何其他必要的构建选项（优化或调试标志、导入路径等），为高级用户提供了从 Mojo 导入钩子抽象中的"逃生通道"。

## 已知限制

虽然我们对 Python 到 Mojo 互操作有着远大的目标——我们的目标是让 Mojo 成为扩展 Python 的最佳方式——但此功能仍处于早期活跃开发阶段，有一些需要注意的限制。这些限制将随着时间的推移逐步解除。

- **接受超过 6 个参数的函数。** 目前 `PyTypeBuilder.add_function()` 和相关的函数绑定仅支持最多接受 6 个 `PythonObject` 参数的 Mojo 函数：
  `def(PythonObject, PythonObject, PythonObject, PythonObject, PythonObject, PythonObject)`。

- **关键字参数语法。**
  目前，从 Python 调用的 Mojo 函数仅在使用尾随的 `kwargs: StringDict[PythonObject]` 参数时才接受关键字参数。原生 `**kwargs` 语法的支持将在未来添加。

- **Mojo 包依赖。**
  依赖于 Mojo 标准库以外的包的 Mojo 代码（例如[不断增长的 Modular Community](https://github.com/modular/modular-community) 包频道中的包），目前仅在手动构建 Mojo 扩展模块时受支持，因为 Mojo 导入钩子目前不支持指定 Mojo 包依赖的导入路径。

- **属性。**
  计算属性的 getter 和 setter 目前不支持。

- **预期类型转换。**
  少数 Mojo 标准库类型可以通过实现 [`ConvertibleFromPython`][ConvertibleFromPython] 特征直接从等效的 Python 内置对象类型构造。然而，许多 Mojo 标准库类型尚未实现此特征，因此如果需要可能需要手动转换逻辑。
