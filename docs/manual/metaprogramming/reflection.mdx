反射帮助你编写能在编译时自省自身结构并报告类型信息的代码。这使得构建诸如结构验证、自动比较、序列化、更安全的断言以及更丰富的错误消息等功能成为可能，而无需为特定类型实现硬编码细节。

:::caution
Mojo 反射是近期引入的，目前尚不完整。部分反射能力受限、不稳定，或尚未通过语言接口完全暴露。本页面描述了该功能的方向，以及目前可用的部分。

所有示例均反映本页面发布时语言的状态。随着反射支持的成熟，它们可能会发生变化。
:::

## 为什么要使用反射？

反射是 Mojo 强大的编译时特性之一。它让你能够自省类型、访问字段，并生成能够适配某个 struct 形状的代码。

例如，定义一个 struct，使其符合 `Equatable`，`==` 运算符就会自动可用：

```mojo
@fieldwise_init
struct Sensor(Equatable, Hashable, Writable):
    var id: Int
    var label: String
    var reading: Float64
```

这段代码不使用任何运算符重载，也没有样板代码。

Mojo 在编译时自省该 struct，检查每个字段是否支持相等性比较，并生成比较代码。这就是反射所做的事情。

反射没有运行时开销。编译器在前期完成工作，生成的代码与手写代码一样高效。

:::note
在这个示例中，`Sensor` 还符合 `Hashable` 和 `Writable`。通过符合这些 trait，其实例可用作 `Dict` 的键或 `Set` 的元素，并且能整洁地打印输出，无需额外代码。
:::

## 自省类型

使用 `reflect[T]` 别名在编译时自省类型。它内置于 Mojo，会被解析为 `Reflected[T]`——一个带有用于查询类型的静态方法的句柄类型。

以下代码使用 `reflect[T]` 自省类型的结构：

```mojo
def show_type[T: AnyType]():
    comptime type_name = reflect[T].name()
    comptime field_count = reflect[T].field_count()
    comptime field_names = reflect[T].field_names()
    comptime field_types = reflect[T].field_types()

    print("struct", type_name)

    comptime for idx in range(field_count):
        comptime field_name = field_names[idx]
        comptime field_type = reflect[field_types[idx]].name()
        var intro = "├──" if idx < (field_count - 1) else "└──"
        print(intro, " var ", field_name, ": ", field_type, sep="")
```

创建一些类型来测试它：

```mojo
@fieldwise_init
struct MyStruct:
    var x: String
    var y: Optional[Int]

comptime DefaultItemCount = 10

struct ParameterizedStruct[
    T: Copyable, item_count: Int = DefaultItemCount
](Copyable):
    var list: List[Self.T]
    def __init__(out self):
        self.list = List[Self.T](capacity=Self.item_count)

def main():
    show_type[MyStruct](); print()
    show_type[Optional[Float64]](); print()
    show_type[Dict[Int, String]](); print()
    show_type[ParameterizedStruct[String, item_count=5]]()
```

运行时，这段代码会打印每个 struct 的名称、字段及其类型。对字段的 `comptime for` 循环在编译时解析。在运行时，只有结果性的 `print()` 调用会执行：

```text
struct test.MyStruct
├── var x: String
└── var y: std.collections.optional.Optional[Int]

struct std.collections.optional.Optional[SIMD[DType.float64, 1]]
└── var _value: std.utils.variant.Variant[<unprintable>, {}]

struct std.collections.dict.Dict[Int, String, std.hashlib\
    ._ahash.AHasher[[0, 0, 0, 0] : SIMD[DType.uint64, 4]]]
├── var _table: std.collections._swisstable\
    .SwissTable[Int, String, std.hashlib._ahash\
    .AHasher[[0, 0, 0, 0] : SIMD[DType.uint64, 4]]]
└── var _order: List[SIMD[DType.int32, 1]]

struct test.ParameterizedStruct[String, 5]
└── var list: List[String]
```

输出使用的是由编译器解析出的名称。类型会以应用参数后的完全限定形式呈现。如果你只需要基础类型名，可使用 `base_name()`：

```mojo
print(reflect[List[Int]].base_name())          # List
print(reflect[Dict[String, Int]].base_name())  # Dict
```

:::note
当你需要某个字段时，可以直接通过名称访问它，而不是遍历：

```mojo
comptime host_handle = reflect[Config].field["host"]
var default_host: host_handle.T = "localhost"

print(default_host)  # localhost
```

基于名称的查找需要一个具体的类型。如果 `T` 是参数化的，请改用基于索引的迭代。
:::

## 检测两个值之间在字段级别的差异

比较两个值并列出哪些字段不同。这可用于测试断言、审计日志、变更跟踪或调试。

```mojo
def diff_fields[T: AnyType](a: T, b: T) -> List[String]:
    comptime names = reflect[T].field_names()
    comptime types = reflect[T].field_types()
    var diffs = List[String]()

    comptime for idx in range(reflect[T].field_count()):
        comptime if conforms_to(types[idx], Equatable):
            ref a_val = reflect[T].field_ref[idx](a)
            ref b_val = reflect[T].field_ref[idx](b)
            if a_val != b_val:
                diffs.append(String(comptime (names[idx])))

    return diffs^
```

例如，考虑一个配置类型：

```mojo
@fieldwise_init
struct Config(Equatable):
    var host: String
    var port: Int
    var verbose: Bool
    var timeout: Float64
```

`diff_fields()` 比较两个 `Config` 值并返回存在差异的字段名：

```mojo
def main():
    var old = Config("localhost", 8080, False, 30.0)
    var new = Config("localhost", 9090, True, 30.0)

    var changes = diff_fields(old, new)
    for name in changes:
        print("changed:", name)
    # changed: port
    # changed: verbose
```

## 写一次，到处复用：配合 trait 使用

在带有 provided method 的 trait 中使用反射尤为强大。该方法会对任何符合该 trait 要求的 struct 运行。

`MakeCopyable` 会将一个实例中每个可拷贝的字段复制到另一个实例：

```mojo
trait MakeCopyable:
    def copy_to(self, mut other: Self):
        comptime field_count = reflect[Self].field_count()
        comptime field_types = reflect[Self].field_types()

        comptime Usable = Copyable & Deinitable
        comptime for idx in range(field_count):
            comptime field_type = field_types[idx]
            comptime if conforms_to(field_type, Usable):
                reflect[Self].field_ref[idx](other) = reflect[Self].field_ref[
                    idx
                ](self).copy()
```

符合该 trait 的 struct 无需自行编写实现即可获得 `copy_to()`。作为 trait 方法，`copy_to()` 可直接访问 `Self`，你无需再传入类型参数。

```mojo
@fieldwise_init
struct MultiType(MakeCopyable, Writable):
    var w: String
    var x: Int
    var y: Bool
    var z: Float64

    def write_to[W: Writer](self, mut writer: W):
        writer.write(String(t"[{self.w}, {self.x}, {self.y}, {self.z}]"))


def main():
    var original = MultiType("Hello", 1, True, 2.5)
    var target = MultiType("", 0, False, 0.0)

    original.copy_to(target)
    print(target)  # [Hello, 1, True, 2.5]
```

你只需定义一次行为，每个符合该 trait 的 struct 都会将其作为 provided method 获得。

## 布局、源位置与类型工具

这些工具暴露更低层级的细节，例如布局、生命周期和源信息。

### 字段布局与字节偏移

当你需要用于零拷贝序列化、C 互操作或对齐的字段布局时，可使用 `field_offset()`：

```mojo
struct Packet:
    var flags: UInt8
    var id: UInt32
    var payload: UInt64

def show_layout[T: AnyType]():
    var names = materialize[reflect[T].field_names()]()
    comptime for i in range(reflect[T].field_count()):
        comptime off = reflect[T].field_offset[index=i]()
        print(names[i], "at byte", off)

def main():
    show_layout[Packet]()
    # flags at byte 0
    # id at byte 4     (alignment padding: 3 bytes)
    # payload at byte 8
```

`field_offset` 接受 `name=` 或 `index=`，并会考虑对齐填充。`flags`（1 字节）和 `id`（第 4 字节）之间的间隙表明编译器插入了 3 字节的填充，以让 `id` 对齐到 4 字节边界。

### 类型与来源

有两个函数可提供对表达式类型与生命周期信息的编译时访问：

**`type_of(x)`** 返回表达式的类型，可用于参数位置：

```mojo
def make_default[T: Defaultable]() -> T:
    return T()

def main():
    var x = 42
    var y = make_default[type_of(x)]()
    print(y)  # 0
```

**`origin_of(x)`** 捕获某个引用的来源（origin，即生命周期与可变性）。

在 Mojo 中，每个引用都有一个 _origin_，用于追踪它从哪个值读取，以及它能否修改该值。`origin_of(x)` 在编译时捕获这一信息，使你能够将其传递到函数签名中。

它出现在那种返回的引用必须与某个输入的生命周期绑定的签名中：

```mojo
from std.os import abort

def first_ref[
    T: Copyable
](ref list: List[T]) -> ref[list[0]] T:
    if not list:
        abort("empty list")
    return list[0]

def main():
    var l = [1, 2, 3]
    ref x = first_ref(l)
    print(x)  # 1
    x += 10   # modifies the original list through the reference
    print(l)  # [11, 2, 3]

    l = []
    first_ref(l)  # aborts with "empty list"
```

返回的引用与 `list` 共享其 origin，因此编译器知道只要 `list` 有效它就有效。两者都无需 import 即可使用。

### 源位置

**`call_location()`** 返回调用者的源位置，而非 `call_location()` 调用本身所在的位置。在构建断言或校验器时，错误消息若指向调用点会更有用：

```mojo
from std.reflection import call_location

@always_inline
def require(
    cond: Bool, msg: String = "requirement failed"
) raises:
    if not cond:
        raise Error(call_location().prefix(msg))

def main() raises:
    var x = 5
    require(x > 10, "x must be > 10")
    # Error: At /path/to/file.mojo:10:5: x must be > 10
```

外层函数必须是 `@always_inline` 才能捕获调用者的位置。如果没有这一装饰器，位置会指向 `require()` 内部。`call_location()` 接受一个可选的 `inline_count` 参数。默认值（1）捕获直接调用者。更高的值会跳过更多层级的内联调用。

**`source_location()`** 返回 `source_location()` 被调用处的位置。这对调试而言不太有用，因为它报告的是该调用所在的位置，而不是调用者的位置：

```mojo
from std.reflection import source_location

def log(msg: String):
    var loc = source_location()
    print(
        "[", loc.file_name(), ":", loc.line(), "] ",
        msg, sep=""
    )

def main():
    log("starting up")
    # [/path/to/file.mojo:4:15] starting up
```

### 函数名

在编译时检索函数的源名或链接器符号。这可用于日志、跟踪或分发：

```mojo
from std.reflection import get_function_name, get_linkage_name

def process_data():
    pass

def main():
    print(get_function_name[process_data]())  # process_data
    print(get_linkage_name[process_data]())   # mangled symbol
```

- **`get_function_name[func]()`** 返回源代码中书写的名称。
- **`get_linkage_name[func]()`** 返回 mangled 后的符号名。

两者都把函数作为参数值传入。
