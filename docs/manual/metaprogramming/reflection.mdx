反射帮助您编写在编译时检查其自身结构并报告有关类型信息的代码。这使得构建结构验证、自动比较、序列化、更安全的断言和更丰富的错误消息等功能成为可能，而无需为特定类型实现硬编码细节。

:::caution
Mojo 反射是新引入的，目前不完整。某些反射功能有限、不稳定，或尚未通过语言接口完全暴露。本页面描述了该功能的方向以及今天可用的部分。

所有示例都反映此页面发布时的语言状态。随着反射支持的成熟，它们可能会发生变化。
:::

## 为什么要反射？

反射是 Mojo 的强大编译时功能之一。它让您能够检查类型、访问字段，并生成适应结构形状的代码。

例如，定义一个结构体，使其符合 `Equatable`，`==` 运算符自动工作：

```mojo
@fieldwise_init
struct Sensor(Equatable, Hashable, Writable):
    var id: Int
    var label: String
    var reading: Float64
```

此代码不使用运算符重载或样板代码。

Mojo 在编译时检查结构体，验证每个字段支持相等性，并生成比较代码。这就是反射所做的。

反射没有运行时成本。编译器提前完成工作，并生成与手动编写的代码一样高效的代码。

:::note
在这个示例中，`Sensor` 也符合 `Hashable` 和 `Writable`。通过符合，实例可用作 `Dict` 键或 `Set` 元素，并且可以干净地打印，而无需额外代码。
:::

## 检查类型

使用 `reflect[T]` 别名在编译时检查类型。内置于 Mojo 中，它解析为 `Reflected[T]`——一个具有用于查询类型的静态方法的句柄类型。

此代码使用 `reflect[T]` 检查类型的结构：

```mojo
def show_type[T: AnyType]():
    comptime type_name = reflect[T].name()
    comptime field_count = reflect[T].field_count()
    comptime field_names = reflect[T].field_names()
    comptime field_types = reflect[T].field_types()

    print("struct", type_name)

    comptime for idx in range(field_count):
        comptime field_name = field_names[idx]
        comptime field_type = reflect[field_types[idx]].name()
        var intro = "├──" if idx < (field_count - 1) else "└──"
        print(intro, " var ", field_name, ": ", field_type, sep="")
```

创建一些类型来测试：

```mojo
@fieldwise_init
struct MyStruct:
    var x: String
    var y: Optional[Int]

comptime DefaultItemCount = 10

struct ParameterizedStruct[
    T: Copyable, item_count: Int = DefaultItemCount
](Copyable):
    var list: List[Self.T]
    def __init__(out self):
        self.list = List[Self.T](capacity=Self.item_count)

def main():
    show_type[MyStruct](); print()
    show_type[Optional[Float64]](); print()
    show_type[Dict[Int, String]](); print()
    show_type[ParameterizedStruct[String, item_count=5]]()
```

运行时，此代码打印每个结构体的名称和字段及其类型。对字段的 `comptime for` 循环在编译时解析。在运行时，只有生成的 `print()` 调用执行：

```text
struct test.MyStruct
├── var x: String
└── var y: std.collections.optional.Optional[Int]

struct std.collections.optional.Optional[SIMD[DType.float64, 1]]
└── var _value: std.utils.variant.Variant[<unprintable>, {}]

struct std.collections.dict.Dict[Int, String, std.hashlib\
    ._ahash.AHasher[[0, 0, 0, 0] : SIMD[DType.uint64, 4]]]
├── var _table: std.collections._swisstable\
    .SwissTable[Int, String, std.hashlib._ahash\
    .AHasher[[0, 0, 0, 0] : SIMD[DType.uint64, 4]]]
└── var _order: List[SIMD[DType.int32, 1]]

struct test.ParameterizedStruct[String, 5]
└── var list: List[String]
```

输出使用编译器解析的名称。类型完全带有应用的参数出现。如果您只需要基本类型名称，使用 `base_name()`：

```mojo
print(reflect[List[Int]].base_name())          # List
print(reflect[Dict[String, Int]].base_name())  # Dict
```

:::note
当您需要一个字段时，通过名称访问它而不是迭代：

```mojo
comptime host_handle = reflect[Config].field_type["host"]
var default_host: host_handle.T = "localhost"

print(default_host)  # localhost
```

基于名称的查找需要具体类型。如果 `T` 是泛型的，请使用基于索引的迭代代替。
:::

## 检测两个值之间的字段级别更改

比较两个值并列出哪些字段不同。这用于测试断言、审计日志、更改跟踪或调试。

```mojo
def diff_fields[T: AnyType](a: T, b: T) -> List[String]:
    comptime names = reflect[T].field_names()
    comptime types = reflect[T].field_types()
    var diffs = List[String]()

    comptime for idx in range(reflect[T].field_count()):
        comptime if conforms_to(types[idx], Equatable):
            ref a_val = reflect[T].field_ref[idx](a)
            ref b_val = reflect[T].field_ref[idx](b)
            if a_val != b_val:
                diffs.append(String(names[idx]))

    return diffs^
```

例如，考虑一个配置类型：

```mojo
@fieldwise_init
struct Config(Equatable):
    var host: String
    var port: Int
    var verbose: Bool
    var timeout: Float64
```

`diff_fields()` 比较两个 `Config` 值并返回不同的字段名称：

```mojo
def main():
    var old = Config("localhost", 8080, False, 30.0)
    var new = Config("localhost", 9090, True, 30.0)

    var changes = diff_fields(old, new)
    for name in changes:
        print("changed:", name)
    # changed: port
    # changed: verbose
```

## 使用特性编写一次，到处重用

在提供方法的特性中使用反射非常强大。该方法针对符合特性约束的任何结构体运行。

`MakeCopyable` 从一个实例复制每个可复制的字段：

```mojo
trait MakeCopyable:
    def copy_to(self, mut other: Self):
        comptime field_count = reflect[Self].field_count()
        comptime field_types = reflect[Self].field_types()

        comptime Usable = Copyable & ImplicitlyDestructible
        comptime for idx in range(field_count):
            comptime field_type = field_types[idx]
            comptime if conforms_to(field_type, Usable):
                reflect[Self].field_ref[idx](other) = reflect[Self].field_ref[
                    idx
                ](self).copy()
```

符合的结构体接收 `copy_to()` 而无需编写实现。作为特性方法，`copy_to()` 直接访问 `Self`。您不需要类型参数。

```mojo
@fieldwise_init
struct MultiType(MakeCopyable, Writable):
    var w: String
    var x: Int
    var y: Bool
    var z: Float64

    def write_to[W: Writer](self, mut writer: W):
        writer.write(String(t"[{self.w}, {self.x}, {self.y}, {self.z}]"))


def main():
    var original = MultiType("Hello", 1, True, 2.5)
    var target = MultiType("", 0, False, 0.0)

    original.copy_to(target)
    print(target)  # [Hello, 1, True, 2.5]
```

您定义一次行为。每个符合的结构体将其作为提供的方法接收。

## 布局、源位置和类型工具

这些工具暴露低级细节，如布局、生命周期和源信息。

### 字段布局和字节偏移

当您需要用于零复制序列化、C 互操作或对齐的字段布局时，使用 `field_offset()`：

```mojo
struct Packet:
    var flags: UInt8
    var id: UInt32
    var payload: UInt64

def show_layout[T: AnyType]():
    comptime names = reflect[T].field_names()
    comptime for i in range(reflect[T].field_count()):
        comptime off = reflect[T].field_offset[index=i]()
        print(names[i], "at byte", off)

def main():
    show_layout[Packet]()
    # flags 在字节 0
    # id 在字节 4     （对齐填充：3 字节）
    # payload 在字节 8
```

`field_offset` 接受 `name=` 或 `index=` 并考虑对齐填充。`flags`（1 字节）和 `id`（字节 4）之间的间隙显示编译器插入 3 字节填充，以便 `id` 与 4 字节边界对齐。

### 类型和来源

两个函数提供来自表达式的类型和生命周期的编译时访问：

**`type_of(x)`** 返回表达式的类型，用于参数位置：

```mojo
def make_default[T: AnyType & Defaultable]() -> T:
    return T()

def main():
    var x = 42
    var y = make_default[type_of(x)]()
    print(y)  # 0
```

**`origin_of(x)`** 捕获引用的来源（生命周期和可变性）。

在 Mojo 中，每个引用都有一个_来源_，它跟踪它从哪个值借用以及它是否可以修改该值。`origin_of(x)` 在编译时捕获此信息，以便您可以将其传递到函数签名中。

它出现在返回引用必须绑定到输入生命周期的签名中：

```mojo
from std.os import abort

def first_ref[
    T: Copyable
](ref list: List[T]) -> ref [origin_of(list)] T:
    if not list:
        abort("empty list")
    return list[0]

def main():
    var l = [1, 2, 3]
    ref x = first_ref(l)
    print(x)  # 1
    x += 10   # 通过引用修改原始列表
    print(l)  # [11, 2, 3]

    l = []
    first_ref(l)  # 带有 "empty list" 中止
```

返回的引用与 `list` 共享其来源，因此编译器知道只要 `list` 存在，它就是有效的。两者都可以在不导入的情况下使用。

### 源位置

**`call_location()`** 返回调用者的源位置，而不是 `call_location()` 调用本身的位置。在构建断言或验证器时，错误消息在指向调用点时更有用：

```mojo
from std.reflection import call_location

@always_inline
def require(
    cond: Bool, msg: String = "requirement failed"
) raises:
    if not cond:
        raise Error(call_location().prefix(msg))

def main() raises:
    var x = 5
    require(x > 10, "x must be > 10")
    # 错误：在 /path/to/file.mojo:10:5: x must be > 10
```

封闭函数必须是 `@always_inline` 以捕获调用者的位置。没有此装饰器，位置将指向 `require()` 内部。`call_location()` 接受可选的 `inline_count` 参数。默认值（1）捕获直接调用者。更高的值跳过额外的内联调用级别。

**`source_location()`** 返回 `source_location()` 被调用的位置。这对于调试不太有用，因为它报告调用的位置，而不是调用者的位置：

```mojo
from std.reflection import source_location

def log(msg: String):
    var loc = source_location()
    print(
        "[", loc.file_name(), ":", loc.line(), "] ",
        msg, sep=""
    )

def main():
    log("starting up")
    # [/path/to/file.mojo:4:15] starting up
```

### 函数名称

在编译时检索函数的源名称或链接器符号。这用于日志记录、跟踪或调度：

```mojo
from std.reflection import get_function_name, get_linkage_name

def process_data():
    pass

def main():
    print(get_function_name[process_data]())  # process_data
    print(get_linkage_name[process_data]())   # 混淆符号
```

- **`get_function_name[func]()`** 返回源代码中写入的名称。
- **`get_linkage_name[func]()`** 返回混淆的符号名称。

两者都将函数作为参数值。
