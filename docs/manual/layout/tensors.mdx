[`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/)
提供了对存储在线性数组中的多维数据的视图。`LayoutTensor` 将多维数据的逻辑组织与其在内存中的实际排列方式进行抽象。你可以生成相同数据的新张量"视图"，而无需复制底层数据。
这为编写高性能计算算法提供了关键模式，例如：

- 从现有张量中提取分块（子张量）。这在 GPU 上尤其有价值，允许线程块将一个分块加载到共享内存中，以实现更快的访问和更高效的缓存。
- 向量化张量——将它们重组为多元素向量，以实现更高效的内存加载和存储。
- 将张量划分为线程本地片段（fragment），以便在线程块间分配工作。

`LayoutTensor` 对于编写 GPU 内核尤其有价值，它的许多 API 是 GPU 专用的。不过，`LayoutTensor` 也可用于基于 CPU 的算法。

`LayoutTensor` 由三个主要属性组成：

- 一个[布局（layout）](/docs/manual/layout/layouts/)，定义元素在内存中的排列方式。
- 一个 `DType`，定义张量中存储的数据类型。
- 一个指向存储数据的内存的指针。

由于 `LayoutTensor` 是一个视图，基于现有张量创建新张量不需要复制底层数据。因此你可以轻松创建一个新视图，表示一个分块（子张量），或以不同顺序访问元素。这些视图都访问相同的数据，因此在某个视图中更改存储的数据会改变所有视图看到的数据。

张量中的每个元素可以是单个（标量）值或 SIMD 向量值。对于向量化布局，你可以指定一个*元素布局（element layout）*来确定向量元素在内存中的排列方式。更多信息请参见[向量化张量](#vectorizing-tensors)。

## 访问张量元素

对于具有简单行主序或列主序布局的张量，你可以像访问多维数组一样通过下标访问布局张量的元素：

```mojo
element = tensor2d[x, y]
tensor2d[x, y] = z
```

传递给下标运算符的索引数量必须与张量所需的坐标数量匹配。对于简单布局，这与布局的*秩（rank）*相同：二维张量为 2，三维张量为 3，以此类推。如果索引数量不正确，你可能会看到一个晦涩的运行时错误。

```mojo
# 对二维张量进行索引需要两个索引
el1 = tensor2d[x, y]  # 正确
el2 = tensor2d[x]  # 运行时错误
```

对于更复杂的"嵌套"布局（如分块布局），索引数量**不**匹配张量的秩。详情请参见[张量索引和嵌套布局](#tensor-indexing-and-nested-layouts)。

`__getitem__()` 方法返回一个 SIMD 向量元素，编译器无法静态确定向量的大小（即张量元素布局的大小）。这可能在编译时导致类型检查错误，因为某些 API 只接受标量值（宽度为 1 的 SIMD 向量）。例如，考虑以下代码：

```mojo
i: Int = SIMD[DType.int32, width](15)
```

如果 `width` 为 1，向量可以隐式转换为 `Int`，但如果 `width` 为任何其他值，向量则不能隐式转换。如果 `width` 在编译时未知，这会产生错误。

如果你的张量存储标量值，你可以通过显式取向量中的第一个元素来解决这个问题：

```mojo
var element = tensor[row, col][0]  # element 保证是标量值
```

你也可以使用 `load()` 和 `store()` 方法访问元素，这些方法允许你显式指定向量宽度：

```mojo
var elements: SIMD[DType.float32, 4]
var elements = tensor.load[4](row, col)
elements = elements * 2
tensor.store(row, col, elements)
```

### 张量索引和嵌套布局

张量的布局可能具有嵌套模式（或子布局），如[布局简介](/docs/manual/layout/layouts/#modes)中所述。这些布局的一个或多个维度被划分为子布局。例如，图 2 展示了一个具有嵌套布局的张量：

<figure>

![](../images/layout/tensors/layout-tensor-indexing-nested.png#light)
![](../images/layout/tensors/layout-tensor-indexing-nested-dark.png#dark)

<figcaption><b>图 2.</b> 具有嵌套布局的张量</figcaption>

</figure>

图 2 展示了一个具有分块主序嵌套布局的张量。它不是在每个轴上使用单个坐标进行寻址，而是每个轴使用一对坐标。例如，坐标 `((1, 0), (0, 1))` 映射到偏移量 6。

你不能将嵌套坐标传递给下标运算符 `[]`，但可以传递坐标的扁平化版本。例如：

```mojo
# 获取 ((1, 0), (0, 1)) 处的值
element = nested_tensor[1, 0, 0, 1][0]
```

传递给下标运算符的索引数量必须与张量的*扁平化秩（flattened rank）*匹配。

目前你不能对具有嵌套布局的张量使用 `load()` 和 `store()` 方法。不过，这些方法通常用于已经被[*分块化*](#tiling-tensors)的张量，分块化后会产生具有简单布局的张量。

## 创建 LayoutTensor

根据张量数据所在的位置，有几种创建 `LayoutTensor` 的方式：

- 在 CPU 上。
- 在 GPU 全局内存中。
- 在 GPU 共享内存或本地内存中。

除了从头创建张量的方法外，`LayoutTensor` 还提供了多种方法来生成现有张量的新视图。

:::note[无边界检查]

`LayoutTensor` 构造函数不会进行任何边界检查来验证分配的内存是否足够容纳布局中指定的所有元素。用户需要确保分配了足够的空间。

:::

### 在 CPU 上创建 `LayoutTensor`

虽然 `LayoutTensor` 通常在 GPU 上使用，但你也可以用它来创建用于 CPU 的张量。

要在 CPU 上创建 `LayoutTensor`，你需要一个 `Layout` 和一块用于存储张量数据的内存。为 `LayoutTensor` 分配内存的一种常见方式是使用
[`InlineArray`](/docs/std/collections/inline_array/InlineArray/)：

```mojo
comptime rows = 8
comptime columns = 16
comptime layout = Layout.row_major(rows, columns)
var storage = InlineArray[Float32, rows * columns](uninitialized=True)
var tensor = LayoutTensor[DType.float32, layout](storage).fill(0)
```

`InlineArray` 是一个静态大小的栈分配数组，因此它是为大多数类型的 `LayoutTensor` 分配存储的一种快速高效的方式。不过，以这种方式分配的内存大小存在依赖于目标平台的限制。

你也可以使用 `UnsafePointer` 创建 `LayoutTensor`。对于非常大的张量，这可能更可取。

```mojo
comptime rows = 1024
comptime columns = 1024
comptime buf_size = rows * columns
comptime layout = Layout.row_major(rows, columns)
var ptr = alloc[Float32](buf_size)
memset(ptr, 0, buf_size)
var tensor = LayoutTensor[DType.float32, layout](ptr)
```

注意此示例使用 [`memset()`](/docs/std/memory/memory/memset/) 而不是 `LayoutTensor` 的 `fill()` 方法。`fill()` 方法执行张量的逐元素初始化，因此对于大型张量可能较慢。

### 在 GPU 上创建 `LayoutTensor`

在为 GPU 使用创建 `LayoutTensor` 时，你需要考虑张量数据将存储在哪个内存空间：

- GPU 全局内存只能从主机端（CPU）分配，作为 `DeviceBuffer`。
- GPU 共享内存或本地内存可以在 GPU 上静态分配。

#### 在全局内存中创建 `LayoutTensor`

你必须从主机端分配全局内存，通过分配一个
[`DeviceBuffer`](/docs/std/gpu/host/device_context/DeviceBuffer/)。你可以在调用 GPU 内核之前在主机端使用此内存构造 `LayoutTensor`，也可以在内核内部构造 LayoutTensor：

- 在 CPU 上，你可以使用 `DeviceBuffer` 作为存储来构造 `LayoutTensor`。虽然你可以在 CPU 上创建此张量并将其传入内核函数，但你不能在 CPU 上直接修改其值，因为内存位于 GPU 上。
- 在 GPU 上：当 `DeviceBuffer` 被传递给
  `enqueue_function()` 时，内核接收一个对应的
  `UnsafePointer` 来替代 `DeviceBuffer`。然后内核可以使用该指针创建 `LayoutTensor`。

在这两种情况下，如果你想从 CPU 初始化张量的数据，可以在调用内核之前对缓冲区调用
[`enqueue_copy()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_copy)
或
[`enqueue_memset()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_memset)。
以下示例展示了从 CPU 初始化 `LayoutTensor` 并将其传递给 GPU 内核。

```mojo
def initialize_tensor_from_cpu_example() raises:
    comptime dtype = DType.float32
    comptime rows = 32
    comptime cols = 8
    comptime block_size = 8
    comptime row_blocks = rows // block_size
    comptime col_blocks = cols // block_size
    comptime input_layout = Layout.row_major(rows, cols)
    comptime size: Int = rows * cols


    def kernel(tensor: LayoutTensor[dtype, input_layout, MutAnyOrigin]):
        if global_idx.y < UInt(tensor.shape[0]()) and global_idx.x < UInt(
            tensor.shape[1]()
        ):
            tensor[global_idx.y, global_idx.x] = (
                tensor[global_idx.y, global_idx.x] + 1
            )


    try:
        var ctx = DeviceContext()
        var host_buf = ctx.enqueue_create_host_buffer[dtype](size)
        var dev_buf = ctx.enqueue_create_buffer[dtype](size)
        ctx.synchronize()

        var expected_values = List[Scalar[dtype]](length=size, fill=0)

        for i in range(size):
            host_buf[i] = Scalar[dtype](i)
            expected_values[i] = Scalar[dtype](i + 1)
        ctx.enqueue_copy(dev_buf, host_buf)
        var tensor = LayoutTensor[dtype, input_layout](dev_buf)

        ctx.enqueue_function[kernel](
            tensor,
            grid_dim=(col_blocks, row_blocks),
            block_dim=(block_size, block_size),
        )
        ctx.enqueue_copy(host_buf, dev_buf)
        ctx.synchronize()

        for i in range(rows * cols):
            if host_buf[i] != expected_values[i]:
                raise Error(
                    String("Error at position {} expected {} got {}").format(
                        i, expected_values[i], host_buf[i]
                    )
                )
    except error:
        print(error)
```

#### 在共享内存或本地内存中创建 `LayoutTensor`

要在 GPU 的共享内存或本地内存中创建张量，使用 `LayoutTensor.stack_allocation()` 静态方法来创建在相应内存空间中有后备内存的张量。

共享内存和本地内存都是非常有限的资源，因此一种常见模式是将较大张量的一个小分块复制到共享内存或本地内存中，以减少内存访问时间。

```mojo
comptime tile_layout = Layout.row_major(16, 16)

var shared_tile = LayoutTensor[
    dtype,
    tile_layout,
    MutAnyOrigin,
    address_space=AddressSpace.SHARED,
].stack_allocation()
```

对于共享内存，线程块中的所有线程看到相同的分配。对于本地内存，每个线程获得单独的分配。

没有办法显式分配*寄存器*内存。不过，编译器可以将某些本地内存分配提升为寄存器。要启用此优化，请保持张量大小较小，并且对张量的所有索引都是静态的——例如使用 `comptime for` 循环。

:::note

`stack_allocation()` 这个名称具有误导性。它是一个*静态*分配，意味着分配在编译时处理。这种分配类似于 C/C++ 的栈分配，其生命周期在分配它的函数返回时结束。此 API 可能在不久的将来发生变化。

:::

## 张量分块

使用布局张量的一种基本模式是将张量划分为更小的分块（tile），以实现更好的数据局部性和缓存效率。在 GPU 内核中，你可能希望选择一个与线程块大小对应的分块。例如，给定一个 16x16 线程的二维线程块，你可以使用 16x16 的分块（每个线程处理分块中的一个元素）或 64x16 的分块（每个线程处理张量中的 4 个元素）。

分块通常是一维或二维的。对于逐元素计算（给定张量元素的输出值仅取决于一个输入值），一维分块易于推理。对于涉及相邻元素的计算，二维分块有助于保持数据局部性。例如，矩阵乘法或二维卷积操作通常使用二维分块。

`LayoutTensor` 提供了 `tile()` 方法用于提取单个分块。你也可以使用 `LayoutTensorIter` 类型遍历分块。

当对不是分块大小整数倍的张量进行分块时，你可以将张量创建为*掩码张量*（将可选参数 `masked` 设置为 True）。对掩码张量进行分块时，分块操作将在张量边缘返回部分分块。这些分块将小于请求的分块大小。你可以使用 `tensor.dim(axis)` 方法在运行时查询分块维度。

### 提取分块

[`LayoutTensor.tile()`](/docs/layout/layout_tensor/LayoutTensor/#tile)
方法在给定坐标处提取给定大小的分块：

```mojo
comptime rows = 2
comptime columns = 4
comptime tile_size = 32
comptime tile_layout = Layout.row_major(tile_size, tile_size)
comptime tiler_layout = Layout.row_major(rows, columns)
comptime tiled_layout = blocked_product(tile_layout, tiler_layout)
var storage = InlineArray[Float32, tiled_layout.size()](uninitialized=True)
for i in range(comptime (tiled_layout.size())):
    storage[i] = Float32(i)
var tensor = LayoutTensor[DType.float32, tiled_layout](storage)
var tile = tensor.tile[tile_size, tile_size](0, 1)
```

此代码创建了一个 64x128 的张量，使用 32x32 的分块，并提取第 0 行、第 1 列的分块，如图 3 所示。

<figure>

![](../images/layout/tensors/layout-tensor-tile.png#light)
![](../images/layout/tensors/layout-tensor-tile-dark.png#dark)

<figcaption><b>图 3.</b> 从张量中提取分块</figcaption>

</figure>

注意坐标是以*分块*为单位指定的。

提取的分块的布局取决于父张量的布局。例如，如果父张量具有列主序布局，则提取的分块也具有列主序布局。

如果你从具有分块布局的张量中提取分块，提取的分块必须与父张量的分块边界匹配。例如，如果父张量由 8x8 行主序分块组成，8x8 的分块大小会产生一个具有 8x8 行主序布局的提取分块。

:::note

尝试提取不是父分块大小整数倍的分块通常会导致错误。

:::

如果你需要知道分块的类型（例如用于声明变量），你可以使用 `TileType` 类型别名，并传入相同的分块大小参数。

```mojo
var my_tile: tensor.TileType[tile_size, tile_size]
for i in range (rows):
    for j in range(columns):
        my_tile = tensor.tile[tile_size, tile_size](i, j)
        # ... 对分块进行操作 ...
```

### 分块迭代器

[`LayoutTensorIter`](/docs/layout/layout_tensor/LayoutTensorIter/)
结构体提供了一种遍历内存块的方式，为每个位置生成一个布局张量。使用 `LayoutTensorIter` 有两种方式：

- 从内存缓冲区开始，你可以生成一系列分块。
- 给定一个现有的布局张量，你可以沿给定轴提取一组分块。

#### 对内存缓冲区进行分块

当你从内存缓冲区开始时，`LayoutTensorIter` 每次遍历一个分块的内存。这本质上将内存视为分块的扁平数组。

```mojo
comptime buf_size = 128
var storage = InlineArray[Int16, buf_size](uninitialized=True)
for i in range(buf_size):
    storage[i] = Int16(i)
comptime tile_layout = Layout.row_major(4, 4)
var iter = LayoutTensorIter[
    DType.int16,
    tile_layout,
    MutAnyOrigin
](storage.unsafe_ptr(), buf_size)

for i in range(ceildiv(buf_size, comptime (tile_layout.size()))):
    var tile = iter[]
    # ... 对分块进行操作
    iter += 1
```

迭代器构造函数接受构造 `LayoutTensor` 所需的所有参数——一个 `DType`、布局和一个来源（origin）——以及一个指针和内存缓冲区大小作为参数。

注意迭代器不像标准迭代器那样工作，你不能像使用集合那样直接在 `for` 语句中使用它。相反，你可以使用解引用运算符（`iter[]`）或 `get()` 方法来检索表示当前位置分块的 `LayoutTensor`。

你可以通过递增来推进迭代器，如上所示。迭代器还支持 `next()` 和 `next_unsafe()` 方法，它们返回按指定偏移量（默认为 1）递增的迭代器副本。这意味着你也可以使用如下模式：

```mojo
for i in range(num_tiles):
    current_tile = iter.next(i)[]
    …
```

`LayoutTensorIter` 还有一个可选的布尔参数 `circular`。使用 `circular=True` 创建的 `LayoutTensorIter` 将内存缓冲区视为循环的；当到达缓冲区末尾时，它会从头重新开始。

### 对 `LayoutTensor` 进行分块

要遍历现有张量，调用
[`tiled_iterator()`](/docs/layout/layout_tensor/LayoutTensor/#tiled_iterator)
方法，它会产生一个 `LayoutTensorIter`：

```mojo
# 给定一个大小为 rows x cols 的张量
comptime num_row_tiles = ceildiv(rows, tile_size)
comptime num_col_tiles = ceildiv(cols, tile_size)

for i in range(num_row_tiles):
    var iter = tensor.tiled_iterator[tile_size, tile_size, axis=1](i, 0)

    for _ in range(num_col_tiles):
        var tile = iter[]
        # ... 对分块进行操作
        iter += 1
```

## 向量化张量

在处理张量时，一次访问多个值通常是高效的。例如，让单个 GPU 线程计算多个输出值（"线程粗化"）通常可以提高性能。同样，在将数据从一个内存空间复制到另一个内存空间时，让每个线程复制一个 SIMD 向量大小的值而不是单个值通常更有帮助。许多 GPU 具有向量化复制指令，可以使复制更高效。

要选择最佳向量大小，你需要了解当前 GPU 对你正在使用的数据类型支持的向量操作。（例如，如果你正在处理 4 字节的值，而 GPU 支持 16 字节的复制操作，你可以使用 4 的向量宽度。）`LayoutTensor` 的复制操作支持最大 16 字节的复制大小。

[`vectorize()`](/docs/layout/layout_tensor/LayoutTensor/#vectorize)
方法创建张量的一个新视图，其中张量的每个元素是一个值的向量。

```mojo
var vectorized_tensor = tensor.vectorize[1, 4]()
```

向量化张量是原始张量的视图，指向相同的数据。底层标量值的数量保持不变，但张量布局和元素布局发生了变化，如图 4 所示。

## 跨线程划分张量

在 GPU 上处理张量时，有时需要将张量的元素分配给线程块中的各个线程。
[`distribute()`](/docs/layout/layout_tensor/LayoutTensor/#distribute)
方法接受一个线程布局和一个线程 ID，并返回张量的一个线程特定*片段（fragment）*。

线程布局被平铺在张量上。第 *N* 个线程接收由每个分块中的第 *N* 个值组成的片段。例如，图 5 展示了给定一个 4x4 行主序张量和一个 2x2 列主序线程布局时，`distribute()` 如何形成片段：

<figure>

![](../images/layout/tensors/distribute-layout.png#light)
![](../images/layout/tensors/distribute-layout-dark.png#dark)

<figcaption><b>图 5.</b> 将张量划分为片段</figcaption>

</figure>

在图 5 中，数据布局中的数字表示存储中的偏移量（如通常一样）。线程布局中的数字表示线程 ID。

图 5 中的示例使用了较小的线程布局用于说明目的。在实践中，通常最佳做法是使用与 GPU 的 warp 大小相同的线程布局，以便将工作分配给所有可用线程。例如，以下代码在一个完整 warp 的线程上对张量进行向量化和划分：

```mojo
comptime thread_layout = Layout.row_major(WARP_SIZE // simd_size, simd_size)
var fragment = tile.vectorize[1, simd_size]().distribute[thread_layout](lane_id())
```

给定 16x16 的分块大小、32 的 warp 大小和 4 的 `simd_size`，此代码产生一个 16x4 的 1x4 向量张量。线程布局是一个 8x4 的行主序布局。

## 复制张量

`layout-tensor` 包提供了大量用于复制张量的工具。其中许多专门用于在各种 GPU 内存空间之间复制。所有布局张量复制方法都遵循布局——因此你可以通过将张量复制到具有不同布局的张量来变换张量。

`LayoutTensor` 本身提供了两种复制张量数据的方法：

- [`copy_from()`](/docs/layout/layout_tensor/LayoutTensor/#copy_from)
  将数据从源张量复制到当前张量，两者可能在不同的内存空间中。
- [`copy_from_async()`](/docs/layout/layout_tensor/LayoutTensor/#copy_from_async)
  是一种优化的复制机制，用于从 GPU 全局内存异步复制到共享内存。

这两种方法都复制整个源张量。要将复制工作分配给多个线程，你需要使用 `distribute()` 创建线程本地张量片段，如[跨线程划分张量](#partitioning-a-tensor-across-threads)中所述。

以下代码示例演示了使用两种复制方法在共享内存之间复制数据。

```mojo
def copy_from_async_example():
    comptime dtype = DType.float32
    comptime rows = 128
    comptime cols = 128
    comptime block_size = 16
    comptime num_row_blocks = rows // block_size
    comptime num_col_blocks = cols // block_size
    comptime input_layout = Layout.row_major(rows, cols)
    comptime simd_width = 4

    def kernel(tensor: LayoutTensor[dtype, input_layout, MutAnyOrigin]):
        # 从输入张量中提取一个分块
        var global_tile = tensor.tile[block_size, block_size](
            Int(block_idx.y), Int(block_idx.x)
        )
        comptime tile_layout = Layout.row_major(block_size, block_size)
        var shared_tile = LayoutTensor[
            dtype,
            tile_layout,
            MutAnyOrigin,
            address_space=AddressSpace.SHARED,
        ].stack_allocation()

        # 创建用于复制的线程布局
        comptime thread_layout = Layout.row_major(
            WARP_SIZE // simd_width, simd_width
        )
        var global_fragment = global_tile.vectorize[
            1, simd_width
        ]().distribute[thread_layout](lane_id())
        var shared_fragment = shared_tile.vectorize[
            1, simd_width
        ]().distribute[thread_layout](lane_id())

        shared_fragment.copy_from_async(global_fragment)
        comptime if is_nvidia_gpu():
            async_copy_wait_all()
        barrier()

        # 向共享分块中放入一些数据，以便在主机端验证
        if global_idx.y < rows and global_idx.x < cols:
            shared_tile[thread_idx.y, thread_idx.x] = (
                shared_tile[thread_idx.y, thread_idx.x] + 1
            )
        barrier()
        global_fragment.copy_from(shared_fragment)

    try:
        var ctx = DeviceContext()
        var host_buf = ctx.enqueue_create_host_buffer[dtype](rows * cols)
        var dev_buf = ctx.enqueue_create_buffer[dtype](rows * cols)
        for i in range(rows * cols):
            host_buf[i] = Float32(i)
        var tensor = LayoutTensor[dtype, input_layout](dev_buf)

        ctx.enqueue_copy(dev_buf, host_buf)
        ctx.enqueue_function[kernel](
            tensor,
            grid_dim=(num_row_blocks, num_col_blocks),
            block_dim=(block_size, block_size),
        )
        ctx.enqueue_copy(host_buf, dev_buf)
        ctx.synchronize()
        for i in range(rows * cols):
            if host_buf[i] != Float32(i + 1):
                raise Error(
                    String("Unexpected value ", host_buf[i], " at position ", i)
                )
    except error:
        print(error)
```

### 线程感知复制函数

[`layout_tensor` 包](/docs/layout/layout_tensor/)还包含许多用于不同场景的专用复制函数，例如从共享内存复制到本地内存。这些函数都是*线程感知*的：你不需要传入张量片段，而是传入一个线程布局，函数使用它来划分工作。

与 `copy_from()` 和 `copy_from_async()` 方法一样，在复制之前使用 `vectorize()` 方法可以利用向量化复制操作。

许多线程感知复制函数对复制的张量形状和线程布局有非常具体的要求，这取决于所使用的特定 GPU 和数据类型。

## 总结

在本文档中，我们探讨了 `LayoutTensor` 的基本概念和实际用法。`LayoutTensor` 的核心提供了一种处理多维数据的强大抽象。通过组合布局（定义内存组织）、数据类型和内存指针，`LayoutTensor` 实现了灵活高效的数据操作，而无需不必要地复制底层数据。

我们介绍了几种构成使用 `LayoutTensor` 基础的基本张量操作，包括创建张量、访问张量元素以及在张量之间复制数据。

我们还介绍了优化数据访问的关键模式：

- 分块张量以实现数据局部性。逐块访问张量可以提高缓存效率。在 GPU 上，分块可以让线程块中的线程高速访问张量的子集。
- 向量化张量以实现更高效的数据加载和存储。
- 将张量划分或分配为线程本地片段进行处理。

这些模式为在 Mojo 中编写高效内核提供了构建块，同时保持代码整洁可读。

要查看 `LayoutTensor` 实际使用的示例，请参阅 MAX 指南，[使用 Mojo 优化 GPU 自定义操作](https://docs.modular.com/max/develop/custom-ops-matmul/)。
