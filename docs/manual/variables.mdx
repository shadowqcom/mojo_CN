变量是一个保存值或对象的名称。Mojo 中的所有变量默认都是可变的——它们的值可以改变。如果你想定义一个在运行时不能改变的常量值，请参阅 [`comptime` 关键字](/docs/manual/metaprogramming/comptime-evaluation/#comptime-values)，或者将该值作为不可变函数实参传递。

在 Mojo 中声明变量时，你会分配一个逻辑存储位置，并将一个名称绑定到该存储位置。

```mojo
var greeting: String = "Hello World"
```

`var` 声明做了三件事：

- 它声明一个与特定类型关联的逻辑存储位置。在本例中，它保存 `String` 实例。
- 它将名称 `greeting` 绑定到这个逻辑存储位置。
- 它使用 "Hello World" 用新创建的 `String` 值*初始化*该存储空间。新值由该变量*拥有*。除非你转移其所有权，否则没有其他变量可以拥有这个值。

## 变量声明

要声明变量，请使用 `var` 加上一个名称。你可以给它一个值、一个类型标注，或两者都给。你标注得越多，代码就越明确，也越容易阅读和维护：

```mojo
var a = 5  # Mojo infers that a is type Int
var b: Float64 = 3.14  # Explicit declaration of Float64 type
var c: String  # The name is created but uninitialized
```

变量的类型永远不会改变。其存储空间在创建时就被强类型化，并且只能保存该类型的值：

```mojo
var count = 8 # count is type Int
count = "Nine?" # Error: can't implicitly convert 'StringLiteral' to 'Int'
```

变量作用于声明它的代码块。其值在最后一次使用时被销毁。你可以从一个变量转移出一个值，使其不再存活于该变量或该作用域中。名称，也就是变量本身，在作用域结束时被销毁。

- 变量是保存值的名称。
- 值是存在于内存中的数据。

## 变量作用域

Mojo 中的变量使用*词法作用域*（lexical scoping）。变量的定义由它在源代码中出现的位置决定，而不是由它在运行时执行的时间决定。具体的作用域级别取决于变量是如何声明的。

变量具有**块级**作用域。嵌套代码可以读取和修改在外部作用域中定义的变量。外部作用域不能读取在内部作用域中定义的变量。

例如，这里所示的 `if` 代码块创建了一个内部作用域，其中外部变量可以被读写，但任何新变量都不会超出 `if` 代码块的作用域而存在：

```mojo
def lexical_scopes():
    var num = 1
    var dig = 1
    if num == 1:
        print("num:", num)  # Reads the outer-scope "num"
        var num = 2         # Creates new inner-scope "num"
        print("num:", num)  # Reads the inner-scope "num"
        dig = 2             # Updates the outer-scope "dig"
    print("num:", num)      # Reads the outer-scope "num"
    print("dig:", dig)      # Reads the outer-scope "dig"
```

```output
num: 1
num: 2
num: 1
dig: 2
```

注意，`if` 内部的 `var` 语句创建了一个与外部变量同名的**新**变量。这阻止了内部 if 语句访问外部的 `num` 变量。这被称为"变量遮蔽"（variable shadowing），即内部作用域的变量隐藏或"遮蔽"了外部作用域中的变量。

内部 `num` 的生命周期恰好在 `if` 代码块结束时结束，因为那是定义该变量的作用域。

## 复制和移动值

对新创建值或字面量的赋值语句会建立所有权：

```mojo
var owning_variable = "Owned value"
```

对现有变量值的赋值会将该值或该值的副本的所有权转移给新变量：

```mojo
var source = String("Hello")
var copied = source   # A copy
var moved = source^   # A transfer
```

以这种方式赋值时，右侧变量必须是 `Copyable` 或 `Movable`。赋值之后，新变量拥有一个值，无论是复制的还是转移的。转移会让 `source` 处于未初始化状态，在为它赋新值之前你不能再次使用它。

赋值语句右侧的值必须能够转移到新变量。下面是一个不奏效的例子：

```mojo
var first: List[Int] = [1, 2, 3]
var second = first  # error: 'List[Int]' is not implicitly copyable because
                    # it doesn't conform to 'ImplicitlyCopyable'
```

第一个赋值没有问题：表达式 `[1, 2, 3]` 创建了一个没有所有者的新 `List` 值，所以 `first` 成为它的所有者而没有任何歧义。第二个赋值报错，因为 `first` 不是隐式可复制的，并且该值也未被转移。

每种结果都取决于参与赋值的值所对应的类型特性。

- `Copyable` 类型可以被显式复制，方法是调用其复制初始化器或 `copy()` 方法。

  ```mojo
  var second = first.copy()
  ```

  复制后 `first` 保持不变。`second` 被赋予它自己独有的、由它拥有的列表副本。

- `ImplicitlyCopyable` 类型可以在没有显式信号的情况下被复制：

  ```mojo
  var one_value = 15
  var another_value = one_value  # implicit copy
  ```

  隐式可复制类型通常是像 `Int`、`Float64` 和 `Bool` 这样可以简单复制的简单值类型。

- 值的所有权可以通过在要转移的值后面附加*转移符号*（`^`）从一个变量显式转移到另一个变量：

  ```mojo
  var second = first^
  ```

  这会将值移动到 `second`，并使 `first` 处于未初始化状态。

  这种所有权转移可能会将值从一个内存位置移动到另一个内存位置。这要求该值是 `Movable` 的。

## 引用绑定

某些 API 会返回由其他地方所拥有值的[_引用_](/docs/manual/values/lifetimes/#working-with-references)。引用可以避免复制值。例如，当你从集合中检索一个值时，集合返回的是一个引用，而不是副本：

```mojo
var animals: List[String] = ["Cats", "Dogs", "Zebras"]
print(animals[2])  # Prints "Zebras", does not copy the value.
```

如果你将一个引用赋值给一个*变量*，它会创建一个副本（如果该值是隐式可复制的）或产生一个错误（如果不是）：

```mojo
var items: List[Int] = [99, 77, 33, 12]
var item = items[1]  # item is a copy of items[1]
item += 1  # increments item
print(items[1])  # prints 77
```

要命名一个引用，请使用 `ref` 关键字创建一个引用绑定：

```mojo
ref item_ref = items[1]  # item_ref is a reference to item[1]
item_ref += 1  # increments items[1]
print(items[1])  # prints 78
```

名称 `item_ref` 绑定到 `items[1]`。对 `item_ref` 的所有读和写都作用于它所引用的项。

引用绑定不能被重新赋值：

```mojo
ref item_ref = items[2]  # error: invalid redefinition of item_ref
```

关于引用的更多信息，请参阅[使用引用](/docs/manual/values/lifetimes/#working-with-references)。
