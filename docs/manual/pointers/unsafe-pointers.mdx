[`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 类型是标准库中可用的几种指针类型之一，用于间接引用内存中的位置。

你可以使用 `UnsafePointer` 来动态分配和释放内存，或者指向由其他代码分配的内存。你可以使用这些指针来编写与低级接口交互的代码、与其他编程语言交互，或构建类数组数据结构。但顾名思义，它们本质上是不安全的。例如，使用不安全指针时，你需要负责确保内存被正确分配和释放。

通常，你应该尽可能优先使用安全指针类型，将 `UnsafePointer` 保留给其他指针类型无法胜任的用例。有关标准库指针类型的比较，请参阅[指针简介](/docs/manual/pointers/)。

## 不安全指针基础

`UnsafePointer` 是一种持有内存地址的类型。你可以在该内存中存储和检索值。`UnsafePointer` 类型是_泛型_的——它可以指向任何类型的值，值类型以参数的形式指定。指针所指向的值有时被称为_被指物_（pointee）。

```mojo
# 分配内存以存储一个值
var ptr = alloc[Int](1)
# 初始化已分配的内存
ptr.init_pointee_copy(100)
```

## 指针的生命周期

在任何给定时间，指针可以处于几种状态之一。`UnsafePointer` 是不可空的。它可以是_未初始化的_、_悬空的_，或指向某个内存位置：

- 未初始化。就像任何变量一样，`UnsafePointer` 类型的变量可以被声明但未初始化。

  ```mojo
  var ptr: UnsafePointer[Int, MutExternalOrigin]
  ```

- 指向已分配但未初始化的内存。`alloc()` 函数返回一个指向新分配内存块的指针，该内存块有足够空间存储指定数量的被指物类型的元素。

  ```mojo
  ptr = alloc[Int](1)
  ```

  尝试解引用指向未初始化内存的指针会导致未定义行为。

- 指向已初始化的内存。你可以通过将现有值移动或复制到内存中来初始化已分配但未初始化的指针。或者你可以通过使用 `to` 关键字参数调用构造函数来获取指向现有值的指针。

  ```mojo
  ptr.init_pointee_copy(value)
  # 或
  ptr.init_pointee_move(value^)
  # 或
  ptr = UnsafePointer(to=value)
  ```

  值初始化后，你可以使用解引用语法来读取或修改它：

  ```mojo
  var oldValue = ptr[]
  ptr[] = newValue
  ```

- 悬空。当你释放指针分配的内存时，你会得到一个_悬空指针_。地址仍然指向其之前的位置，但内存已不再分配给该指针。尝试解引用该指针或调用任何会访问该内存位置的方法会导致未定义行为。

  ```mojo
  ptr.free()
  ```

### 分配内存

使用 `alloc()` 函数来分配内存。此函数返回一个指向所请求内存的新指针。你可以分配一个或多个被指物类型值的空间。分配失败会陷阱终止程序。`alloc()` 函数总是返回一个有效的、非空的指针：

```mojo
var ptr = alloc[Int](10) # 分配空间存储 10 个 Int 值
```

分配的空间是_未初始化的_——就像一个已声明但未初始化的变量。

### 初始化被指物

要初始化已分配的内存，`UnsafePointer` 提供了
[`init_pointee_copy()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_copy)
和
[`init_pointee_move()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_move)
方法。例如：

```mojo
ptr.init_pointee_copy(my_value)
```

要将值移动到指针的内存位置，请使用 `init_pointee_move()`：

```mojo
str_ptr.init_pointee_move(my_string^)
```

注意，要移动值，你通常需要添加转移符号（`^`），除非该值是[平凡类型](/docs/manual/traits#register-passable)（如 `Int`）或新构造的"拥有"值：

```mojo
str_ptr.init_pointee_move("Owned string")
```

或者，你可以通过使用 `to` 关键字参数调用 `UnsafePointer` 构造函数来获取指向现有值的指针。这对于获取栈上值的指针很有用，例如。

```mojo
var counter: Int = 5
var ptr = UnsafePointer(to=counter)
```

注意，当调用 `UnsafePointer(to=value)` 时，你不需要分配内存，因为你指向的是一个现有值。

### 解引用指针

使用 `[]` 解引用运算符来访问指针存储的值（"被指物"）。

```mojo
# 从被指物读取
print(ptr[])
# 修改被指物
ptr[] = 0
```

```output
5
```

如果你已为多个值分配了空间，你可以使用下标语法来访问这些值，就像它们是数组一样，例如 `ptr[3]`。空下标 `[]` 与 `[0]` 含义相同。

:::caution

解引用运算符假设被解引用的内存已初始化。解引用未初始化的内存会导致未定义行为。

:::

你不能安全地对未初始化的内存使用解引用运算符，即使是为了_初始化_被指物。这是因为对解引用的指针赋值会调用现有被指物上的生命周期方法（如析构函数、移动构造函数或复制构造函数）。

```mojo
var str_ptr = alloc[String](1)
# str_ptr[] = "Testing" # 未定义行为！
str_ptr.init_pointee_move("Testing")
str_ptr[] += " pointers" # 现在可以正常工作
```

### 销毁或移除值

[`take_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#take_pointee) 方法将一个被指物从 `ptr` 指向的内存位置移出。这是一个消费性移动。它在目标值上调用 `__init__(take=)`。它使该内存位置变为未初始化状态。

[`destroy_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#destroy_pointee) 方法在被指物上调用析构函数，并使 `ptr` 指向的内存位置变为未初始化状态。

`take_pointee()` 和 `destroy_pointee()` 都要求指针非空，且内存位置包含被指物类型的有效、已初始化的值；否则该函数会导致未定义行为。

调用 [`init_pointee_move_from(self, src)`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_move_from) 将 `src` 指向的值移动到 `self` 指向的内存位置。此操作后，该值的所有权从 `src` 转移到 `self`，`src` 处的内存变为未初始化状态：不要从中读取数据，也不要对其调用析构函数。要使内存再次有效，请使用 `init_pointee_*()` 操作之一用新值初始化它。

:::note
Mojo 假设目标内存是未初始化的。它不会在写入 `src` 的值之前销毁现有内容。
:::

### 释放内存

对指针调用 [`free()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#free) 会释放该指针分配的内存。它不会对存储在内存中的任何值调用析构函数——你需要显式地执行此操作（例如，使用 [`destroy_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#destroy_pointee) 或[销毁或移除值](#destroying-or-removing-values)中描述的其他函数之一）。

释放指针而不释放关联的内存可能导致内存泄漏——你的程序会不断占用越来越多的内存，因为并非所有分配的内存都被释放了。

另一方面，如果你有多个指针副本访问同一块内存，你需要确保只对其中一个调用 `free()`。两次释放同一块内存也是一个错误。

释放指针的内存后，你会得到一个悬空指针——其地址仍然指向已释放的内存。任何访问该内存的尝试，如解引用指针，都会导致未定义行为。

## 存储多个值

如[分配内存](#allocating-memory)中所述，你可以使用 `UnsafePointer` 为多个值分配内存。内存作为单个连续块分配。指针支持算术运算：给指针加上一个整数会返回一个新指针，该指针从原始指针偏移指定数量的值：

```mojo
var third_ptr = first_ptr + 2
```

指针还支持减法，以及原地加法和减法：

```mojo
# 将指针前进一个元素：
ptr += 1
```

例如，以下示例分配内存来存储 6 个 `Float64` 值，并将它们全部初始化为零。

```mojo
var float_ptr = alloc[Float64](6)
for offset in range(6):
    (float_ptr+offset).init_pointee_copy(0.0)
```

值初始化后，你可以使用下标语法访问它们：

```mojo
float_ptr[2] = 3.0
for offset in range(6):
    print(float_ptr[offset], end=", ")
```

```output
0.0, 0.0, 3.0, 0.0, 0.0, 0.0,
```

## `UnsafePointer` 与来源

`UnsafePointer` 结构体有一个 `origin` 参数，用于跟踪其指向的内存的来源。

对于使用 `to` 关键字参数初始化的指针，来源设置为被指物的来源。例如，在以下代码中，`s_ptr.origin` 与 `s` 的来源相同：

```mojo
s = "Testing"
s_ptr = UnsafePointer(to=s)
```

当使用 `alloc()` 函数分配内存时，返回的指针的 `origin` 值为 `MutExternalOrigin`。此值表示一个可变的且不_别名_现有值的来源。例如，它不指向为任何其他变量分配的内存。这意味着编译器不会不必要地延长不相关值的生命周期。此内存不被 Mojo 的生命周期检查器跟踪，你需要负责释放它。

如果你在结构体的实现中使用指针，只要指针不暴露在结构体之外，你通常不需要关心来源。例如，如果你实现一个静态数组类型，在其构造函数中分配内存，在其析构函数中释放内存，并且不将指针暴露在结构体之外，那么默认来源就可以了。

但如果结构体暴露了指向该内存的指针，你需要适当地设置来源。例如，`List` 类型有一个 `unsafe_ptr()` 方法，返回指向底层存储的 `UnsafePointer`。在这种情况下，返回的指针应该共享列表的来源，因为列表是存储的逻辑所有者。

该方法类似于以下代码：

```mojo
def unsafe_ptr(
    ref self,
) -> UnsafePointer[T, origin_of(self)]:

    return self.data.unsafe_origin_cast[origin_of(self)]()
```

这返回原始指针的副本，其来源设置为匹配 `self` 值的来源和可变性。

这样的方法是不安全的，但设置正确的来源使其更安全，因为编译器知道指针引用的是列表拥有的数据。

## 使用可空性

`UnsafePointer` 是不可空类型。要模拟空指针，请将其包装在 `Optional` 中：

```mojo
  var ptr = Optional[UnsafePointer[Int, MutExternalOrigin]]()
```

这创建了一个值为 `None` 的 `Optional`，等同于空指针。`Optional[UnsafePointer]` 与原始指针具有相同的内存布局，因此你可以将其作为 `NULL` 跨 FFI 边界传递。

要检查可选指针是否为空，请使用 `Optional` 方法：

```mojo
if ptr:
    # ptr 不是 None — 可以安全解包
    var p = ptr.value()
```

当你需要一个非空的哨兵值用于延迟初始化时，请改用 `unsafe_dangling()`：

```mojo
  var ptr = UnsafePointer[Int, MutExternalOrigin].unsafe_dangling()
```

有关可选指针在数据结构中的实际示例，请参阅[自引用结构体](/docs/manual/structs/reference/)。

## 使用外部指针

在与其他编程语言交换数据时，你可能需要从外部指针构造 `UnsafePointer`。Mojo 限制从任意地址创建 `UnsafePointer` 实例，以避免用户意外创建相互_别名_的指针（即两个指向同一位置的指针）。但是，有特定的方法可以从 Python 或 C/C++ 指针获取 `UnsafePointer`。

在处理由其他地方分配的内存时，你需要了解谁负责释放该内存。释放在其他地方分配的内存可能导致未定义行为。

在使用某些外部函数时，你可能需要提供一个没有特定类型的指针（类型擦除指针，或 C/C++ 中的"void 指针"）。这等同于 Mojo 的 `OpaquePointer`。

你还需要了解存储在内存中的数据格式，包括数据类型和字节顺序。更多信息请参阅[转换数据：位转换和字节顺序](#converting-data-bitcasting-and-byte-order)。

### 从原始内存地址创建 Mojo 指针

你可以使用 `unsafe_from_address` 初始化器从原始内存地址创建 `UnsafePointer`。

```mojo
def write_to_address(mmio_address: Int, value: Int32):
    var ptr = UnsafePointer[Int32, MutExternalOrigin](
      unsafe_from_address=mmio_address
    )

     # 写入原始内存地址可能需要易失性加载/存储，因为
     # 操作可能有编译器不可见的副作用。
     # 你可以使用 `volatile` 参数来指定这一点。
    ptr.store[volatile = True](value)
```

这是不安全的，因为调用者必须确保地址在写入之前是有效的，并且在读取之前内存已初始化。调用者还必须确保指针的来源和可变性对该地址有效，否则可能导致未定义行为。

### 从 Python 指针创建 Mojo 指针

`PythonObject` 类型定义了一个
[`unsafe_get_as_pointer()`](/docs/std/python/python_object/PythonObject/#unsafe_get_as_pointer)
方法，用于从 Python 地址构造 `UnsafePointer`。

例如，以下代码创建一个 NumPy 数组，然后使用 Mojo 指针访问数据：

```mojo
from std.python import Python

def share_array() raises:
    np = Python.import_module("numpy")
    arr = np.array(Python.list(1, 2, 3, 4, 5, 6, 7, 8, 9))
    ptr = arr.ctypes.data.unsafe_get_as_pointer[DType.int64]()
    for i in range(9):
        print(ptr[i], end=", ")
    print()

def main() raises:
    share_array()
```

```output
1, 2, 3, 4, 5, 6, 7, 8, 9,
```

此示例使用 NumPy 的
[`ndarray.ctype`](https://numpy.org/doc/stable/reference/generated/numpy.ndarray.ctypes.html#numpy.ndarray.ctypes)
属性来访问底层存储的原始指针（`ndarray.ctype.data`）。`unsafe_get_as_pointer()` 方法构造一个指向该地址的 `UnsafePointer`。

### 使用 C/C++ 指针

如果你使用
[`external_call`](/docs/std/ffi/external_call/)
函数调用返回指针的 C/C++ 函数，你可以将返回类型指定为 `UnsafePointer`，Mojo 会为你处理类型转换。

值得注意的是，跨 FFI 边界工作时，`origin` 参数通常应设置为 `(Mut/Immut)ExternalOrigin`，因为指针指向的是 mojo 程序外部的内存。

```mojo
from std.ffi import external_call

def get_foreign_pointer() -> UnsafePointer[Int, MutExternalOrigin]:
    var ptr = external_call[
        "my_c_function", # 外部函数名
        UnsafePointer[Int, MutExternalOrigin] # 返回类型
    ]()
    return ptr
```

### 不透明指针

`OpaquePointer` 类型是一种没有特定类型的指针。在其他语言中，这通常被称为类型擦除指针或 void 指针。不透明指针通常在与非 Mojo 代码交互时使用，例如接受 void 指针的 C 库函数。

`OpaquePointer` 实际上是 `UnsafePointer[NoneType]` 的类型别名，因此它具有与任何其他 `UnsafePointer` 相同的 API。

你不能解引用不透明指针，但可以使用 `bitcast()` 方法将其转换为特定类型。类似地，你可以通过位转换到 `NoneType` 从现有指针创建不透明指针。例如：

```mojo
var str = "Hello, world!"
var str_ptr = UnsafePointer(to=str)
var opaque_ptr = str_ptr.bitcast[NoneType]()
# ... 调用某个接受 void 指针的外部函数
```

## 转换数据：位转换和字节顺序

位转换指针会返回一个具有相同内存位置但新数据类型的指针。如果你需要从单个内存区域访问不同类型的数据，这会很有用。这种情况可能发生在读取二进制文件（如图像文件）或从网络接收数据时。

以下示例处理一种由数据块组成的格式，其中每个数据块包含可变数量的 32 位整数。每个数据块以一个 8 位整数开头，标识该数据块中的值数量。

```mojo
def read_chunks(
  var ptr: UnsafePointer[mut=False, UInt8],
) -> List[List[UInt32]]:
    chunks = List[List[UInt32]]()
    # 数据块大小为 0 表示数据结束
    chunk_size = Int(ptr[])
    while (chunk_size > 0):
        # 跳过 1 字节的 chunk_size 并获取指向数据块中第一个
        # UInt32 的指针
        ui32_ptr = (ptr + 1).bitcast[UInt32]()
        chunk = List[UInt32](capacity=chunk_size)
        for i in range(chunk_size):
            chunk.append(ui32_ptr[i])
        chunks.append(chunk)
        # 将指针移动到当前数据块之后的下一个字节
        ptr += (1 + 4 * chunk_size)
        # 读取下一个数据块的大小
        chunk_size = Int(ptr[])
    return chunks
```

在处理从文件或网络读入的数据时，你可能还需要处理字节顺序。大多数系统使用小端字节顺序（也称为最低有效字节，或 LSB），其中多字节值中的最低有效字节排在前面。例如，数字 1001 可以用十六进制表示为 0x03E9，其中 E9 是最低有效字节。表示为 16 位小端整数时，两个字节的顺序为 E9 03。表示为 32 位整数时，它表示为 E9 03 00 00。

大端或最高有效字节（MSB）顺序则相反：在 32 位情况下，为 00 00 03 E9。MSB 顺序常用于文件格式和网络数据传输。你可以使用 [`byte_swap()`](/docs/std/bit/bit/byte_swap/) 函数来交换 SIMD 值的字节顺序，从大端到小端或反之。例如，如果上面的方法读取的是大端数据，你只需更改一行：

```mojo
chunk.append(byte_swap(ui32_ptr[i]))
```

## 使用 SIMD 向量

`UnsafePointer` 类型包含
[`load()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#load) 和
[`store()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#store) 方法，用于执行标量值的对齐加载和存储。它还支持跨步加载/存储和聚集/分散的方法。

跨步加载使用偏移量（"步幅"）在连续内存地址之间将值从内存加载到 SIMD 向量中。这对于从表格数据中提取行或列，或从结构化数据中提取单个值很有用。例如，考虑 RGB 图像的数据，其中每个像素由三个 8 位值组成，分别表示红色、绿色和蓝色。如果你只想访问红色值，可以使用跨步加载或存储。

以下函数使用
[`strided_load()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#strided_load)
和
[`strided_store()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#strided_store)
方法来反转图像中的红色像素值，每次处理 8 个值。（注意，此函数仅处理像素数可被八整除的图像。）

```mojo
def invert_red_channel(ptr: UnsafePointer[mut=True, UInt8], pixel_count: Int):
    # 每次加载或存储的值数量
    comptime simd_width = 8
    # 每像素字节数，也是步幅大小
    bpp = 3
    for i in range(0, pixel_count * bpp, simd_width * bpp):
        red_values = (ptr + i).strided_load[width=simd_width](bpp)
        # 反转值并将其存储回原始位置
        (ptr + i).strided_store[width=simd_width](~red_values, bpp)
```

[`gather()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#gather) 和
[`scatter()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#scatter) 方法
让你可以加载或存储存储在任意位置的一组值。你通过传入一个相对于当前指针的_偏移量_ SIMD 向量来实现这一点。

例如，使用 `gather()` 时，向量中的第 <var>n</var> 个值从（指针地址）+ <var>offset[n]</var> 加载。

## 安全性

不安全指针之所以不安全，有以下几个原因：

- 内存管理由用户负责。你需要手动分配和释放内存，和/或了解其他 API 何时在为你分配或释放内存。

- `UnsafePointer` 值是不可空的，但不保证指向_已初始化_的内存。你需要负责确保在解引用之前内存已初始化。

- `UnsafePointer` 确实有 `origin` 参数，以便 Mojo 可以跟踪其指向的数据的来源，但它也提供了不安全的 API。例如，当你进行指针算术运算时，编译器不会做任何边界检查。
