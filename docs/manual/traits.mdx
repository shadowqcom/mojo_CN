特征（trait）定义了类型与使用该类型的代码之间的契约。这些契约描述了行为，比如类型必须提供的方法，以及相关的（*关联*）类型和常量。当一个类型遵循某个特征时，编译器会验证它满足了每一项要求，从而让代码可以*依赖*该特征的接口。

特征是 Mojo 实现多态的途径。它们让你能够编写适用于多种类型的代码，而无需依赖契约之外的实现细节。对于参数化类型和函数来说，特征尤为重要——它们让你能够编写适用于多种具体类型的代码。通过将参数化类型约束到一个或多个特征，你可以为编译器提供推理类型所需的信息，并验证代码是安全且正确的。

想象一下，你正在编写与多个品牌的传感器协同工作的代码。每个传感器都有自己的实现。它们都知道如何产生一个读数，即一个运行时值，比如偏转角。它们还会报告一个标准误差范围，这是该设备特有的编译时常量。

每个传感器还声明了一个测量*类型*，它决定了读数如何被解释。有些传感器测量角度，有些测量距离或压力。你的代码不应该关心某个特定传感器是如何工作的，或者它如何表示其测量值。例如，角度测量可能使用度、弧度或梯度。它只需要知道每个传感器都提供了它所依赖的操作和信息。

特征将这些要求表达为单个契约。你不需要为每种传感器类型编写一个函数，而是针对特征编写一个函数，任何遵循该特征的类型都可以使用它。Mojo 会验证每个必需的方法、关联类型和编译时值都存在，这样你的代码就可以使用它们，而无需运行时开销或能力检查。

特征是 Mojo 代码复用的基础。你根据特征的要求编写代码，而不是枚举具体类型。这使你的代码保持灵活，同时保持编译时正确性。

## 定义特征

特征让编译器能够推理一个类型的形状和能力：它的方法、关联类型和编译时值。使用 `trait` 关键字声明特征，后跟一个名称和一组要求：

```mojo
trait DeflectionSensing:
    def fetch_reading(self) -> Float64:
        ...
```

三个点将 `fetch_reading()` 标记为必需方法。`DeflectionSensing` 并不说明类型如何产生一个值，只说明遵循该特征的类型必须能够产生一个值。

### 领域特定行为

特征可以基于它所知道的关于遵循类型的信息提供默认实现。默认实现可以调用其他必需方法，但不能调用不属于特征契约的方法。

默认方法非常适合那些可以用特征要求来表达的领域特定行为。例如，`within_tolerance()` 验证传感器的当前读数：

```mojo
trait DeflectionSensing:
    def fetch_reading(self) -> Float64:
        ...

    comptime absolute_tolerance: Float64 = 0.05  # This is made up for this example

    def within_tolerance(self) -> Bool:
        return abs(self.fetch_reading()) <= Self.absolute_tolerance
```

遵循类型会继承默认实现，并可以覆盖它们。

Mojo 不提供从覆盖实现中调用默认实现的方法。

### 细化其他特征

特征可以细化另一个特征，这意味着它继承了被细化特征的所有要求，同时添加了新的要求。例如，`CalibratableDeflectionSensing` 做了 `DeflectionSensing` 所做的一切，但还要求一个 `calibrate()` 方法：

```mojo
trait CalibratableDeflectionSensing(DeflectionSensing):
    def calibrate(mut self):
        ...

struct EddyCurrentSensor(CalibratableDeflectionSensing):
    def fetch_reading(self) -> Float64:
        # its implementation

    def calibrate(mut self):
        # its implementation
```

遵循的 `EddyCurrentSensor` 必须实现 `calibrate()`，同时满足 `DeflectionSensing` 的每一项要求。它继承了 `within_tolerance()` 的默认实现，该实现调用了 `fetch_reading()` 并使用 `absolute_tolerance` 常量。

## 特征契约

特征契约由方法和三种编译时成员组成：关联类型、必需编译时值和共享编译时常量。

方法可以是必需的或提供的。必需方法必须由每个遵循类型实现。提供方法包含一个默认实现，遵循类型可以覆盖它。

编译时成员要么要求每个遵循类型提供自己的值，要么定义一个由所有遵循类型共享的值。

- *必需方法* 在其方法体中使用 `...` 省略号。每个遵循类型都必须实现它们。

  ```mojo
  trait Loggable:
      def log(self, message: String):
          ...
  ```

- *提供方法* 在特征中实现。遵循类型可以覆盖它们。即使是默认的空操作实现也是有效的提供方法。

  ```mojo
  trait Pausable:
      def pause(self):
          pass
  ```

- *关联类型* 要求遵循类型声明一个从属类型。它们最常用于集合中，参数化集合在其中声明一个元素类型。

  ```mojo
  trait Container:
      associatedtype Element: Movable
  ```

- *必需编译时值* 必须由每个遵循类型定义。它们通常用于在不同实现间变化的值。

  ```mojo
  trait Pausable:
      comptime max_pause_seconds: Float64
  ```

- *共享编译时常量* 由特征定义，并被每个遵循类型共享。

  ```mojo
  trait DeflectionSensing:
      comptime absolute_tolerance: Float64 = 0.05
  ```

不声明任何这些元素的特征称为*标记特征*（marker trait）。它不要求任何方法、关联类型或编译时值。相反，它将遵循类型标记为具有特定属性或能力。

## 遵循特征

结构体通过在结构体名称后的括号中列出特征并实现其必需方法来遵循该特征：

```mojo
@fieldwise_init
struct CapacitiveSensor(Copyable, DeflectionSensing):
    def fetch_reading(self) -> Float64:
        # Not a very good sensor, but a simple example.
        return Float64(21.5)
```

如果一个结构体声称遵循 `DeflectionSensing` 但没有实现 `fetch_reading()`，它将无法编译。在编译时，Mojo 会验证 `CapacitiveSensor` 满足 `DeflectionSensing` 的每一项要求，包括其方法和 comptime 元素。

特征不使用鸭子类型（duck typing）。实现了 `fetch_reading()` 但没有声明 `DeflectionSensing` 的结构体不是遵循类型。

### 必需的 comptime 成员

使用 `comptime name = value` 在遵循类型上直接定义必需的 comptime 值。例如，如果 `Pausable` 要求一个 `max_pause_seconds` 值，你可以这样声明它：

```mojo
@fieldwise_init
struct Timer(Copyable, Pausable):
    comptime max_pause_seconds: Float64 = 30.0

    def pause(self):
        print("Paused")
```

## 用特征参数化函数和类型

使用 `DeflectionSensing` 特征，你可以为特定传感器构建类型，例如 `CapacitiveSensor` 或 `EddyCurrentSensor`。

通过遵循该特征，每个类型实现了所有必需的方法和 comptime 成员。这个共享契约让你能够编写一个适用于它们中任何一个的函数：

```mojo
def averaged_poll[
    SensorType: DeflectionSensing, //  # infer-only
](sensor: SensorType, samples: Int) -> Float64:
    var total: Float64 = 0.0
    for _ in range(samples):
        total += sensor.fetch_reading()
    return total / Float64(samples)
```

由于每个传感器都遵循 `DeflectionSensing`，编译器知道 `fetch_reading()` 是可用的：

```mojo
var sensor = CapacitiveSensor()
var average_reading = averaged_poll(sensor, 10)
print("Average reading:", average_reading)  # Fixed to 21.5 for the example
```

调用处不使用方括号，因为编译器会从参数推断 `SensorType`。

当你不需要命名类型时，使用 `Some[]` 简写形式：

```mojo
def averaged_poll_2(sensor: Some[DeflectionSensing], samples: Int) -> Float64:
    var total: Float64 = 0.0
    for _ in range(samples):
        total += sensor.fetch_reading()
    return total / Float64(samples)
```

当你需要再次引用该类型时，使用命名形式，例如要求两个参数是*相同*的遵循类型：

```mojo
def compare_readings[
    SensorType: DeflectionSensing
](a: SensorType, b: SensorType) -> Float64:
    return a.fetch_reading() - b.fetch_reading()
```

## 组合特征

一个参数可以要求多个特征。使用与号（`&`）来组合它们。传递给该参数的任何类型都必须遵循组合中的每个特征。

例如，你可以定义一个 `Loggable` 特征，并要求一个传感器同时遵循 `DeflectionSensing` 和 `Loggable`：

```mojo
trait Loggable:
    def log(self, message: String):
        ...

def poll_and_log[T: DeflectionSensing & Loggable](sensor: T):
    print(sensor.fetch_reading())
    sensor.log("Polling sensor")
```

细化和组合解决不同的问题。当一个特征自然地扩展另一个特征，且这种关系应该始终成立时，使用细化。当一个函数或类型需要多个独立的能力时，使用组合。

### 复用特征组合

如果你在多个地方复用相同的组合，可以使用 `comptime` 声明为它命名：

```mojo
comptime SensorLike = DeflectionSensing & Loggable

struct SmartSensor(Copyable, SensorLike):
    def fetch_reading(self) -> Float64:
        return 18.2

    def log(self, message: String):
        print("reading logged")
```

`SensorLike` 不是一个新特征。它是 `DeflectionSensing & Loggable` 的简写。任何同时遵循这两个特征的类型都自动满足 `SensorLike`；无需额外声明任何内容。

## 默认实现

特征可以提供一个可用的实现，而不仅仅是要求一个：

```mojo
trait DefaultLoggable:
    def log(self, message: String):
        print("reading logged")

@fieldwise_init
struct BasicSensor(Copyable, DefaultLoggable):
    pass
```

`BasicSensor` 在没有实现 `log()` 的情况下遵循了该特征。它继承了特征的实现，但任何遵循类型都可以通过提供自己的 `log()` 来覆盖它。

默认实现可能会冲突。如果一个类型遵循两个都提供相同方法的特征，Mojo 不会在它们之间做选择：

```mojo
trait PowerCycle:
    def restart(self):
        print("Restarting via power cycle")

trait Rebootable:
    def restart(self):
        print("Restarting via soft reboot")

struct Gateway(PowerCycle, Rebootable):
    pass
    # Error: conflicting default implementations for restart().
```

通过在 `Gateway` 上实现 `restart()` 来解决冲突。你的实现会覆盖两个默认实现。

## 注意事项

**你不能向现有类型添加特征。** 遵循性是在类型定义时声明的。你不能事后让 `Float64`、`Int` 或任何你不拥有的类型遵循一个新特征。

**遵循是显式的。** 一个恰好实现了 `fetch_reading()` 的结构体不会遵循 `DeflectionSensing`，除非它声明了该特征。Mojo 检查的是声明的遵循性，而不仅仅是匹配方法名。

**特征是全有或全无的。** 遵循类型必须满足每一项要求，要么直接实现，要么继承默认实现。没有部分遵循。
