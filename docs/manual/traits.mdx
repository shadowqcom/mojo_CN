*特征（trait）* 是一个类型必须实现的一组要求。你可以把它看作是一种契约：一个*遵循*（conforms to）特征的类型保证它实现了该特征的所有功能。

特征类似于 Java 的*接口*、C++ 的*概念*、Swift 的*协议*和 Rust 的*特征*。如果你熟悉这些特性中的任何一个，Mojo 的特征解决的是同样的基本问题。

你可能已经在示例代码中见过一些特征，比如 `Copyable` 和 `Movable`。本节将描述特征的工作原理、如何使用现有特征，以及如何定义自己的特征。

## 背景

在 Python 这样的动态类型语言中，你不需要显式声明两个类是相似的。这最好通过示例来说明：

```python title="🐍 Python"
class Duck:
    def quack(self):
        print("Quack.")

class StealthCow:
    def quack(self):
        print("Moo!")

def make_it_quack(maybe_a_duck):
    try:
        maybe_a_duck.quack()
    except:
        print("Not a duck.")

make_it_quack(Duck())
make_it_quack(StealthCow())
```

`Duck` 和 `StealthCow` 类没有任何关联，但它们都定义了 `quack()` 方法，所以它们在 `make_it_quack()` 函数中的工作方式相同。这是因为 Python 使用动态分发——它在运行时识别要调用的方法。所以 `make_it_quack()` 不关心你传递给它的是什么类型，只关心它们实现了 `quack()` 方法这一事实。

在静态类型环境中，这种方法行不通：Mojo 函数要求你指定每个参数的类型。如果你想在 Mojo 中编写这个示例*而不使用*特征，你需要为每种输入类型编写一个函数重载。

```mojo title="🔥 Mojo"
@fieldwise_init
struct Duck(Copyable):
    def quack(self):
        print("Quack")

@fieldwise_init
struct StealthCow(Copyable):
    def quack(self):
        print("Moo!")

def make_it_quack(definitely_a_duck: Duck):
    definitely_a_duck.quack()

def make_it_quack(not_a_duck: StealthCow):
    not_a_duck.quack()

make_it_quack(Duck())
make_it_quack(StealthCow())
```

```output
Quack
Moo!
```

只有两种类型时这还不算太糟。但是你想要支持的类型越多，这种方法就越不实用。

你可能会注意到 Mojo 版本的 `make_it_quack()` 没有包含 `try/except` 语句。我们不需要它，因为 Mojo 的静态类型检查确保你只能将 `Duck` 或 `StealthCow` 的实例传递给 `make_it_quack()` 函数。

## 使用特征

特征通过让你定义一组类型可以实现的共享*行为*来解决这个问题。然后你可以编写依赖于特征而不是单个类型的函数。作为一个例子，让我们使用特征更新 `make_it_quack()` 示例。这将涉及三个步骤：

1. 定义一个新的 `Quackable` 特征。
2. 将特征添加到 `Duck` 和 `StealthCow` 结构体中。
3. 更新 `make_it_quack()` 函数以依赖于该特征。

### 定义特征

第一步是定义一个需要 `quack()` 方法的特征：

```mojo
trait Quackable:
    def quack(self):
        ...
```

特征看起来很像结构体，只是它由 `trait` 关键字引入。注意 `quack()` 方法签名后面跟着三个点（`...`）。这表示它没有在特征内实现。在这个例子中，`quack` 是一个*必需方法*，必须由任何遵循该特征的结构体实现。

特征可以提供默认实现，这样遵循的结构体就不需要自己实现该方法。你可以提供完整的实现或使用 `pass` 关键字。使用 `pass` 会创建一个什么都不做的空操作方法。在你的遵循结构体中，你可以选择覆盖这个默认实现：

```mojo
trait Quackable:
    def quack(self):
        pass
```

更多信息请参阅[默认方法实现](#default-method-implementations)。

特征还可以包含 `comptime` 成员——必须由遵循结构体定义的编译时常量值。`comptime` 成员对于编写描述泛型类型的特征很有用。更多信息请参阅[泛型的 `comptime` 成员](#comptime-members-for-generics)。

### 将特征添加到结构体

接下来，我们需要一些遵循 `Quackable` 特征的结构体。由于上面的 `Duck` 和 `StealthCow` 结构体已经实现了 `quack()` 方法，我们需要做的就是将 `Quackable` 特征添加到它遵循的特征列表中（在结构体名称后的括号内）。

（如果你熟悉 Python，这看起来就像 Python 的继承语法。）

```mojo
@fieldwise_init
struct Duck(Copyable, Quackable):
    def quack(self):
        print("Quack")

@fieldwise_init
struct StealthCow(Copyable, Quackable):
    def quack(self):
        print("Moo!")
```

结构体需要实现特征中声明的任何方法。编译器强制执行遵循性：如果一个结构体说它遵循某个特征，它必须实现该特征要求的所有内容，否则代码将无法编译。

### 使用特征作为类型约束

最后，你可以定义一个接受 `Quackable` 的函数，如下所示：

```mojo
def make_it_quack[DuckType: Quackable](maybe_a_duck: DuckType):
    maybe_a_duck.quack()
```

或使用简写形式：

```mojo
def make_it_quack2(maybe_a_duck: Some[Quackable]):
    maybe_a_duck.quack()
```

如果你之前没有接触过 Mojo [参数](/docs/manual/parameters/)，这个语法可能看起来有点陌生。第一个签名的意思是 `maybe_a_duck` 是 `DuckType` 类型的参数，其中 `DuckType` 是一个必须遵循 `Quackable` 特征的类型。`Quackable` 被称为 `DuckType` 的*类型约束*（type bound）。

`Some[Quackable]` 形式表达了同样的想法：`maybe_a_duck` 的类型是某个遵循 `Quackable` 特征的具体类型。

两种形式的工作方式相同，只是第一种形式显式命名了类型值。这可能很有用，例如，如果你想接受两个相同类型的值：

```mojo
def take_two_quackers[DuckType: Quackable](quacker1: DuckType, quacker2: DuckType):
    pass
```

### 整合在一起

使用该函数很简单：

```mojo
make_it_quack(Duck())
make_it_quack(StealthCow())
```

```output
Quack
Moo!
```

注意调用 `make_it_quack()` 时不需要方括号：编译器会推断参数的类型，并确保该类型具有所需的特征。

特征的一个限制是你不能向现有类型添加特征。例如，如果你定义了一个新的 `Numeric` 特征，你不能将它添加到标准库的 `Float64` 和 `Int` 类型中。但是，标准库已经包含了很多特征，我们将来会添加更多。

### 特征可以要求静态方法

除了常规实例方法外，特征还可以指定必需的静态方法。

```mojo
trait HasStaticMethod:
    @staticmethod
    def do_stuff(): ...

def fun_with_traits[type: HasStaticMethod]():
    type.do_stuff()
```

## 默认方法实现

通常，遵循给定特征的部分或全部结构体可以为给定的必需方法使用相同的实现。在这种情况下，特征可以包含*默认实现*。遵循的结构体仍然可以定义自己的方法版本，覆盖默认实现。但如果结构体没有定义自己的版本，它会自动继承默认实现。

为特征定义默认实现看起来与为结构体编写方法相同：

```mojo
trait DefaultQuackable:
    def quack(self):
        print("Quack")


@fieldwise_init
struct DefaultDuck(Copyable, DefaultQuackable):
    pass
```

在查看标准库特征的 API 文档时，你会看到*必须*实现的方法列为*必需方法*，有默认实现的方法列为*提供方法*。

[`Equatable`](/docs/std/builtin/comparable/Equatable/) 特征是默认实现用例的一个好例子。该特征包含两个方法：`__eq__()`（对应 `==` 运算符）和 `__ne__()`（对应 `!=` 运算符）。每个遵循 `Equatable` 的类型都需要自己定义 `__eq__()` 方法，但该特征为 `__ne__()` 提供了默认实现。给定一个 `__eq__()` 方法，大多数类型的 `__ne__()` 定义都很简单：

```mojo
def __ne__(self, other: Self) -> Bool:
    return not self.__eq__(other)
```

## 特征组合

你可以使用 `&` 符号组合特征。这让你可以定义简单组合其他特征的新特征。你可以在任何使用单个特征的地方使用特征组合：

```mojo
trait Flyable:
    def fly(self): ...

def quack_and_go[type: Quackable & Flyable](quacker: type):
    quacker.quack()
    quacker.fly()

@fieldwise_init
struct FlyingDuck(Copyable, Quackable, Flyable):
    def quack(self):
        print("Quack")

    def fly(self):
        print("Whoosh!")
```

你也可以使用 `comptime` 关键字为特征组合创建简写名称：

```mojo
comptime DuckLike = Quackable & Flyable

struct ToyDuck(DuckLike):
    # ... 实现省略
```

你还可以使用[细化](#trait-refinement)来组合特征，通过定义一个新的空特征，如下所示：

```mojo
trait DuckTrait(Quackable, Flyable):
    pass
```

但是，这不如使用特征组合灵活，不推荐使用。区别在于使用 `trait` 关键字定义了一个新的命名特征。对于一个结构体要遵循这个特征，你需要在其签名中*显式*包含它。另一方面，`DuckLike` `comptime` 值表示两个独立特征 `Quackable` 和 `Flyable` 的组合，任何遵循这两个特征的事物都遵循 `DuckLike`。例如，考虑上面显示的 `FlyingDuck` 类型：

```mojo
struct FlyingDuck(Copyable, Quackable, Flyable):
    # ... 等等
```

因为 `FlyingDuck` 同时遵循 `Quackable` 和 `Flyable`，它也遵循 `DuckLike` 特征组合。但它*不*遵循 `DuckTrait`，因为它的特征列表中没有包含 `DuckTrait`。

## 特征细化

特征可以*细化*（refine）其他特征。一个细化另一个特征的特征包含原始特征声明的所有要求。例如：

```mojo
trait Animal:
    def make_sound(self):
        ...

# Bird 细化了 Animal
trait Bird(Animal):
    def fly(self):
        ...
```

由于 `Bird` 细化了 `Animal`，遵循 `Bird` 特征的结构体必须实现 `make_sound()` 和 `fly()` **两个**方法。而且由于每个 `Bird` 都遵循 `Animal`，遵循 `Bird` 的结构体可以传递给任何需要 `Animal` 的函数。

你可以通过在括号中列出多个特征来定义一个细化多个特征的特征。这可以是逗号分隔的特征列表或特征组合。例如，你可能定义一个 NamedAnimal 特征，它结合了 Animal 特征和一个新的 Named 特征的要求：

```mojo
trait Named:
    def get_name(self) -> String:
        ...

trait NamedAnimal(Animal, Named):
    def emit_name_and_sound(self):
        ...
```

当你创建一个添加额外要求的新特征时，细化很有用。如果你只是想表达两个或多个特征的并集，请使用简单的特征组合：

```mojo
comptime NamedAnimal = Animal & Named
```

## 特征与生命周期方法

特征可以指定必需的[生命周期方法](/docs/manual/lifecycle/#lifecycles-and-lifetimes)，包括构造函数、拷贝构造函数和移动构造函数。

例如，以下代码创建了一个 `MassProducible` 特征。一个 `MassProducible` 类型有一个默认（无参数）构造函数并且可以被移动。它使用两个内置特征：[`Defaultable`](/docs/std/builtin/value/Defaultable/)，它要求一个默认（无参数）构造函数，以及 [`Movable`](/docs/std/builtin/value/Movable/)，它要求该类型有一个[移动构造函数](/docs/manual/lifecycle/life#move-constructor)。

`factory[]()` 函数返回一个新构造的 `MassProducible` 类型实例。以下示例在注释中显示了 `Defaultable` 和 `Movable` 特征的定义以供参考：

```mojo
# trait Defaultable
#     def __init__(out self): ...

# trait Movable
#     def __init__(out self, *, deinit take: Self): ...

comptime MassProducible = Defaultable & Movable

def factory[type: MassProducible]() -> type:
    return type()

struct Thing(MassProducible):
    var id: Int

    def __init__(out self):
        self.id = 0

    def __init__(out self, *, deinit take: Self):
        self.id = take.id

var thing = factory[Thing]()
```

### 寄存器可传递类型与 RegisterPassable 特征

"寄存器可传递"告诉 Mojo 一个类型应该在机器寄存器（如 CPU 寄存器）中传递。这意味着该类型总是按值传递。对于整数或浮点数等数据类型，这比将值存储在栈内存中效率更高。

Mojo 支持两种形式的寄存器可传递类型。

标准的*寄存器可传递类型*具有以下能力和限制：

- 它们有正常的生命周期，可以实现或覆盖生命周期方法。
- 每个字段必须是寄存器可传递的或平凡寄存器可传递的。
- 该类型必须是 [`Movable`](/docs/manual/lifecycle/life/#move-constructor)。
- 它们的 self 指针既不稳定也不可预测。它们可以随时在内存中移动，因此不适合依赖指针标识的类型。
- 当用作参数或结果时，它们可以通过外部函数接口（FFI）直接暴露给 C 和 C++，不需要通过指针传递。
- 它们不能覆盖默认的移动构造函数。这保证了移动总是无副作用的。

你可以通过让类型遵循 `RegisterPassable` 特征来创建自定义的寄存器可传递类型。

平凡寄存器类型通常是数据类型。它们包括：

- *算术类型*。这包括 `Int`、`Int32`、`Bool`、`Float64` 等类型。
- *指针*。地址值是平凡的，而不是被指向的数据。
- *其他平凡类型的数组*。`SIMD` 是一个很好的例子。

这些类型由 Mojo 的标准库提供。

*平凡寄存器可传递类型*具有以下能力和限制：

- 它们不使用生命周期方法。
- 每个字段必须是平凡寄存器可传递的。
- 该类型必须是 [`Copyable`](/docs/manual/lifecycle/life/#copy-constructor)。
- 它们使用特殊的平凡（空操作）析构函数。它们是*平凡可移动的*（通过 `Copyable`，它细化了 `Movable`）、*平凡可复制的*和*平凡可析构的*。

### `Sized` 特征

[`Sized`](/docs/std/builtin/len/Sized/) 特征标识具有可测量长度的类型，如字符串和数组。

具体来说，`Sized` 要求类型实现 `__len__()` 方法。这个特征被内置的 [`len()`](/docs/std/builtin/len/len/) 函数使用。例如，如果你正在编写一个自定义列表类型，你可以实现这个特征，使你的类型与 `len()` 一起工作：

```mojo
struct MyList(Copyable, Sized):
    var size: Int
    # ...

    def __init__(out self):
        self.size = 0

    def __len__(self) -> Int:
        return self.size

print(len(MyList()))
```

```output
0
```

### `Intable` 和 `IntableRaising` 特征

[`Intable`](/docs/std/builtin/int/Intable/) 特征标识一个可以转换为 `Int` 的类型。[`IntableRaising`](/docs/std/builtin/int/IntableRaising/) 特征描述一个可以转换为 `Int` 的类型，但转换可能会引发错误。

这两个特征都要求类型实现 `__int__()` 方法。例如：

```mojo
@fieldwise_init
struct IntLike(Intable):
    var i: Int

    def __int__(self) -> Int:
        return self.i

value = IntLike(42)
print(Int(value) == 42)
```

```output
True
```

### `Writable` 特征

任何遵循 [`Writable`](/docs/std/format/Writable/) 的类型都会获得一个默认实现，该实现使用反射格式化其字段。添加该特征，你就可以打印你的类型：

```mojo
struct SomeType(Writable):
```

[`print()`](/docs/std/io/io/print/) 要求其参数遵循 `Writable`。这使用基于流的写入，避免了不必要的 `String` 分配。

覆盖 `write_to()` 以控制输出格式。编写一系列组成表示的 `Writable` 值：

```mojo
@fieldwise_init
struct Point(Writable):
    var x: Float64
    var y: Float64

    # 覆盖 Writable 遵循性的默认实现
    def write_to(self, mut writer: Some[Writer]):
        writer.write(t"Point({self.x}, {self.y})")

...

var p = Point(1.5, 2.7)
print(p)  # Point(1.5, 2.7)
```

`Writer` 特征只接受有效的 UTF-8 文本。你不能写入任意字节。这保证了像 `String` 这样的类型可以实现 `Writer` 而不会有损坏的风险。

`Writable` 提供了 [`write_repr_to()`](/docs/std/format/Writable/#write_repr_to)，它产生一个特定于调试的值的字符串表示。

`write_repr_to()` 有一个基于反射的默认实现。只有当你的类型需要自定义调试表示时才覆盖它：

```mojo
# 另一个方法。覆盖 Writable 遵循性的默认实现
def write_repr_to(self, mut writer: Some[Writer]):
    writer.write(t"{self.x} : {self.y}")

print(repr(p))  # 1.5 : 2.7
```

### 生命周期管理特征

Mojo 提供了两个核心特征来管理值生命周期：

- [`AnyType`](/docs/std/builtin/anytype/AnyType/)：所有类型扩展的基础特征。仅遵循 `AnyType` 的类型可能需要显式销毁。

- [`ImplicitlyDestructible`](/docs/std/builtin/anytype/ImplicitlyDestructible/)：当生命周期结束时可以通过调用 `__del__()` 自动销毁的类型。

有关值销毁、使用 `@explicit_destroy` 装饰器的显式销毁以及何时使用每种方法的详细信息，请参阅[值的消亡](/docs/manual/lifecycle/death)。

## 带特征的泛型结构体

在定义泛型容器时也可以使用特征。泛型容器是一个可以保存不同数据类型的容器（例如，数组或哈希表）。在 Python 这样的动态语言中，很容易向容器添加不同类型的项。但在静态类型环境中，编译器需要能够在编译时识别类型。例如，如果容器需要复制一个值，编译器需要验证该类型可以被复制。

[`List`](/docs/std/collections/list/) 类型是泛型容器的一个例子。单个 `List` 只能保存单一类型的数据。列表元素必须遵循 `Copyable` 特征：

```mojo
struct List[T: Copyable]:
```

例如，你可以像这样创建一个整数值列表：

```mojo
var list: List[Int]
list = [1, 2, 3, 4]
for i in range(len(list)):
    print(list[i], end=" ")
```

```output
1 2 3 4
```

你可以使用特征来定义存储在容器中的元素的要求。例如，`List` 要求元素可以被移动和复制。要在 `List` 中存储结构体，该结构体需要遵循 `Copyable` 特征，这需要一个[拷贝构造函数](/docs/manual/lifecycle/life/#copy-constructor)和一个[移动构造函数](/docs/manual/lifecycle/life/#move-constructor)。

构建泛型容器是一个高级主题。有关介绍，请参阅[参数化结构体](/docs/manual/parameters/#parameterized-structs)部分。

### 泛型的 `comptime` 成员

除了方法之外，特征还可以包含 `comptime` 成员，这些成员必须由任何遵循的结构体定义。例如：

```mojo
trait Repeater:
    comptime count: Int
```

实现结构体必须为 `comptime` 成员定义一个具体的常量值，可以使用任何编译时参数值。例如，它可以使用字面量常量或编译时表达式，包括使用结构体参数的表达式。

```mojo
struct Doublespeak(Repeater):
    comptime count: Int = 2

struct Multispeak[verbosity: Int](Repeater):
    comptime count: Int = Self.verbosity * 2 + 1
```

`Doublespeak` 结构体有一个 `count` 的常量值，但 `Multispeak` 结构体让用户使用参数设置该值：

```mojo
repeater = Multispeak[12]()
```

注意字段名为 `count`，而 `Multispeak` 参数名为 `verbosity`。参数和 `comptime` 成员在同一个命名空间中，所以参数不能与 `comptime` 成员同名。

`comptime` 成员对于为泛型类型编写特征最有用。例如，假设你想编写一个描述存储遵循 `Copyable` 特征的元素的泛型栈数据结构的特征。

通过将元素类型作为特征上的 `comptime` 成员添加，你可以在特征上指定泛型方法：

```mojo
trait Stacklike:
    comptime EltType: Copyable

    def push(mut self, var item: Self.EltType):
        ...

    def pop(mut self) -> Self.EltType:
        ...
```

以下结构体使用 `List` 作为底层存储来实现 `Stacklike` 特征：

```mojo
struct MyStack[type: Copyable & ImplicitlyDestructible](Stacklike):
    """一个使用 List 构建的简单栈。"""
    comptime EltType = Self.type
    comptime list_type = List[Self.EltType]

    var list: Self.list_type

    def __init__(out self):
        self.list = Self.list_type()

    def push(mut self, var item: Self.EltType):
        self.list.append(item^)

    def pop(mut self) -> Self.EltType:
        return self.list.pop()

    def dump[
        WritableEltType: Writable & Copyable & ImplicitlyDestructible
    ](self: MyStack[WritableEltType]):
        print("[", end="")
        for item in self.list:
            print(item, end=", ")
        print("]")
```

`MyStack` 类型添加了一个 `dump()` 方法，用于打印栈的内容。因为遵循 `Copyable` 的结构体不一定是可打印的，`MyStack` 使用条件遵循来定义一个 `dump()` 方法，只要元素类型是[可写的](/docs/std/format/Writable/)就可以工作。

以下代码通过定义一个泛型方法 `add_to_stack()` 来练习这个新特征，该方法向任何 `Stacklike` 类型添加一个项。

```mojo
def add_to_stack[S: Stacklike](mut stack: S, var item: S.EltType):
    stack.push(item^)

def main():
    s = MyStack[Int]()
    add_to_stack(s, 12)
    add_to_stack(s, 33)
    s.dump()             # [12, 33, ]
    print(s.pop())       # 33
```
