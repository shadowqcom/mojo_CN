许多编程语言都提供了编写参数化或多态代码的系统，这些系统让你只需编写一次代码，就能在编译时生成高效、专门的代码。

Mojo 的编译时参数系统让你定义可重用的代码。参数（parameter）是结构体或函数的编译时输入。参数出现在结构体或函数名之后的方括号中。参数可以接受普通值，如 `Int` 或 `String`：

```mojo
def multiplier[factor: Int](x: Int) -> Int:
    return x * factor


def main():
    comptime times_ten = multiplier[10]
    var x10 = times_ten(3)
```

参数在编译时既可接受类型也可接受值。当参数接受类型时，结果是类型参数化代码；当参数接受值时，结果是值参数化代码。

```mojo no-test
struct MyList[T: AnyType]:
    # ... 类型参数化

struct FixedBuffer[size: Int]:
    # ... 值参数化
```

Mojo 的参数类似于 C++ 模板参数或 Rust 泛型参数。

在 Mojo 中，"parameter"（参数）始终指编译时值，"argument"（参数）始终指运行时值。

在大多数其他语言中，parameter 是声明的一部分，而 argument 是你在调用点传递的值。Mojo 改变了 "parameter" 的含义，使其专门指编译时值。

Mojo 在语法上让这种区别清晰可见：使用 `[]` 表示参数（parameter），使用 `()` 表示参数（argument）。

除了对结构体和函数进行参数化外，你还可以定义参数化的 `comptime` 值。

## 参数化函数

要定义*参数化函数*，在参数列表之前用方括号添加参数。每个参数的格式与参数完全相同：参数名，后跟冒号和类型。在以下示例中，函数有一个参数 `count`，类型为 `Int`。

```mojo
def repeat[count: Int](msg: String):
    comptime for i in range(count):
        print(msg)
```

这里展示的
[`comptime`](/docs/manual/metaprogramming/comptime-evaluation/#comptime-for)
关键字使 `for` 循环在编译时完全展开。`comptime for` 要求循环边界在编译时已知。由于 `count` 是参数，`range(count)` 可以在编译时计算。

调用参数化函数时，你为参数提供值，就像函数参数一样：

```mojo
repeat[3]("Hello")
```

```output
Hello
Hello
Hello
```

编译器在编译期间解析参数值，并为每个唯一的参数值创建一个 `repeat[]()` 函数的具体版本。在解析参数值并展开循环之后，`repeat[3]()` 函数大致等价于：

```mojo no-test
def repeat_3(msg: String):
    print(msg)
    print(msg)
    print(msg)
```

:::note

这并不代表编译器实际生成的代码。当参数被解析时，Mojo 代码已经被转换为 [MLIR](https://mlir.llvm.org/) 中的中间表示。

:::

如果编译器无法将所有参数值解析为常量值，编译失败。

### 参数上的重载

函数和方法可以在其参数签名上重载。关于重载解析的信息，请参阅
[重载函数](/docs/manual/functions/#overloaded-functions)。

## 参数一览

函数或结构体的参数出现在函数或结构体名之后的方括号中。参数总是需要类型注解。

当你查看函数或结构体签名时，可能会在参数列表中看到一些特殊字符，例如 `/` 和 `*`。下面是一个示例：

```mojo
def my_sort[
    # infer-only parameters
    dtype: DType,
    width: SIMDLength,
    //,
    # positional-only parameter
    values: SIMD[dtype, width],
    /,
    # positional-or-keyword parameter
    compare: def(Scalar[dtype], Scalar[dtype]) thin -> Int,
    *,
    # keyword-only parameter
    reverse: Bool = False,
]() -> SIMD[dtype, width]:
```

这里，`compare` 是函数类型的参数。由于比较器是一个非捕获的函数值，函数类型显式使用了 `thin`。

下面是参数列表中特殊字符的快速概述：

- 双斜杠（`//`）：在双斜杠之前声明的参数是
  [推断型参数（infer-only parameters）](#infer-only-parameters)。
- 斜杠（`/`）：在斜杠之前声明的参数是仅位置参数（positional-only
  parameter）。仅位置参数和仅关键字参数遵循与
  [仅位置参数和仅关键字参数](/docs/manual/functions#positional-only-and-keyword-only-arguments)
  相同的规则。
- 以星号为前缀的参数名，例如 `*Types`，标识一个
  [可变参数（variadic parameter）](#variadic-parameters)（上面的示例中未展示）。
  可变参数之后的任何参数都是仅关键字参数。
- 星号（`*`）：在没有可变参数的参数列表中，单独的星号表示后面的参数是仅关键字参数。
- 等号（`=`）为
  [可选参数（optional parameter）](#optional-parameters-and-keyword-parameters)
  引入一个默认值。

## 参数化声明

参数化让函数可以跨多种类型工作，让容器可以存储多种类型的值。例如，
[`List`](/docs/std/collections/list/List/) 接受一个类型参数，所以
`List[Int]` 存储整数，`List[String]` 存储字符串。

在 Mojo 中，参数化使用编译时元素。在类型上参数化的函数是类型参数化的。在值上参数化的函数是值参数化的。两者都使用 `[]`。

下面这个函数同时使用了类型参数和值参数：

```mojo
def repeat[
    MsgType: Writable, // infer-only
    count: Int
](msg: MsgType):
    comptime for _ in range(count):
        print(msg)

def main():
    repeat[2](42)  # prints 42 on two lines
```

`MsgType` 是类型参数化的。它接受任何 `Writable` 类型。`count` 是值参数化的。它接受一个编译时整数。它们一起让你编写一个跨类型工作、并针对不同重复次数进行特化的函数。

`MsgType` 使用 `//` 将其标记为
[推断型参数](#infer-only-parameters)。编译器从 `msg` 推断类型，因此你只需显式传递 `count`。

关于参数化声明的更多信息，包括 trait 一致性、条件一致性和值参数化，请参阅
[参数化声明](/docs/manual/generics/)。

## 参数化结构体

你也可以为结构体添加参数。你可以使用参数化结构体来构建参数化集合。例如，一个参数化数组类型可能包含如下代码：

```mojo
from std.memory.alloc import alloc, dealloc, ThinAllocation, Layout

struct ParameterizedArray[T: Copyable & Deinitable](
    Writable where conforms_to(T, Writable)
):
    var _data: ThinAllocation[Self.T]
    var _size: Int

    def __init__(out self, var *elements: Self.T):
        self._size = len(elements)
        self._data = alloc[Self.T]({count = self._size}).into_thin()
        var ptr = self._data.unsafe_ptr()
        for i in range(self._size):
            ptr.unsafe_offset(i).unsafe_write(elements[i].copy())

    def __init__(out self, *, count: Int, value: Self.T):
        self._size = count
        self._data = alloc[Self.T]({count = count}).into_thin()
        var ptr = self._data.unsafe_ptr()
        for i in range(self._size):
            ptr.unsafe_offset(i).unsafe_write(copy=value)

    def __deinit__(deinit self):
        var ptr = self._data.unsafe_ptr()
        for i in range(self._size):
            ptr.unsafe_offset(i).unsafe_deinit_pointee()
        dealloc(self._data^.unsafe_with_layout({count = self._size}))

    def __getitem__(self, i: Int) raises -> ref[self] Self.T:
        if i < self._size:
            return self._data.unsafe_ptr().unsafe_origin_cast[
                origin_of(self)
            ]()[unsafe_offset=i]
        else:
            raise Error("Out of bounds")

    def write_to(
        self, mut writer: Some[Writer]
    ) where conforms_to(Self.T, Writable):
        writer.write("[")
        var ptr = self._data.unsafe_ptr()
        for i in range(self._size):
            writer.write(ptr[unsafe_offset=i])
            if i < self._size - 1:
                writer.write(", ")
        writer.write("]")
```

该结构体有一个参数 `T`，它是你想在数组中存储的数据类型的占位符，有时称为*类型参数*。`T` 遵循
[`Copyable`](/docs/std/builtin/value/Copyable/) trait，因此也遵循
[`Movable`](/docs/std/builtin/value/Movable/) trait。

与参数化函数一样，使用参数化结构体时需要传入参数值。在这种情况下，当你创建一个 `ParameterizedArray` 的实例时，你需要指定要存储的类型，例如
`Int` 或 `Float64`。（这有点令人困惑，因为在这种情况下你传入的*参数值*是一个*类型*。这是可以的：Mojo 类型是一个有效的编译时值。）

你会看到 `Self.T` 在整个结构体中使用，通常你会在那里看到类型名。例如，作为初始化器中 `elements` 的形式类型，以及 `__getitem__()` 方法的返回类型。

下面是使用 `ParameterizedArray` 的示例：

```mojo
var array = ParameterizedArray(1, 2, 3)
print(array)
```

```output
[1, 2, 3]
```

参数化结构体可以使用 `Self` 类型来表示结构体的一个具体实例（即其所有参数都被指定）。例如，你可以为 `ParameterizedArray` 添加一个静态工厂方法，签名如下：

```mojo no-test
struct ParameterizedArray[ElementType: Copyable & Deinitable]:
    ...

    @staticmethod
    def splat(count: Int, value: Self.T) -> Self:
        # Create a new array with count instances of the given value
        return Self(count=count, value=value)
```

这里，`Self` 等价于写 `ParameterizedArray[Self.ElementType]`。也就是说，你可以这样调用 `splat()` 方法：

```mojo
var float_array = ParameterizedArray[Float64].splat(8, 0)
```

该方法返回一个 `ParameterizedArray[Float64]` 的实例。

### 引用结构体参数

如前一节所示，你使用点语法引用结构体参数，就像引用结构体方法或字段一样（例如 `Self.T`）。

这种结构体参数访问在任何地方都有效，不仅限于结构体的方法内部。你可以将参数作为类型本身的属性访问：

```mojo
def on_type():
    print(SIMD[DType.float32, 2].length)  # prints 2
```

或作为类型的*实例*的属性：

```mojo
def on_instance():
    var x = SIMD[DType.int32, 2](4, 8)
    print(x.dtype)  # prints int32
```

### `comptime` 成员

你也可以将 `comptime` 值定义为 `struct` 或 `trait` 声明的成员：

```mojo
struct Circle[radius: Float64]:
    comptime pi = 3.14159265359
    comptime circumference = 2 * Self.pi * Self.radius
```

这些 `comptime` 成员有多种用途：

- 特定于该类型的常量值。
- 基于结构体参数计算得出的常量值。
- 基于结构体参数的关联类型（associated type）。

参数和 `comptime` 成员的区别在于：参数值由用户指定，而 `comptime` 成员要么表示常量值，要么表示从输入参数派生的值。

必需值（required value）是一个没有初始化器的 `comptime` 成员。遵循类型必须为其提供一个值。当 trait 需要一个在不同遵循类型之间变化的编译时常量时，这非常有用。例如，一个 `Measurable` trait 可能需要一个 `unit` 字符串和一个 `always_positive` 布尔值来验证测量值。

常见的 trait 提供值包括常量（如种子）以及用于细化的 trait 组合。

引用 `comptime` 成员与引用结构体参数一样。你可以使用点语法引用成员（例如
`Self.IteratorType`）。

#### `comptime` 成员作为枚举

一些 Mojo 类型使用 `comptime` 成员来表达枚举。例如，以下代码定义了一个 `Sentiment` 类型，它为不同的情感值定义了 `comptime` 常量：

```mojo
@fieldwise_init
struct Sentiment(Equatable, ImplicitlyCopyable):
    var _value: Int

    comptime NEGATIVE = Sentiment(0)
    comptime NEUTRAL = Sentiment(1)
    comptime POSITIVE = Sentiment(2)

    def __eq__(self, other: Self) -> Bool:
        return self._value == other._value

    def __ne__(self, other: Self) -> Bool:
        return not (self == other)


def is_happy(s: Sentiment):
    if s == Sentiment.POSITIVE:
        print("Yes. 😀")
    else:
        print("No. ☹️")
```

此模式提供了一个类型安全的枚举。

[`DType`](/docs/std/builtin/dtype/DType/) 结构体使用类似这样的 `comptime` 成员实现了一个简单的枚举。这允许客户端在参数表达式或运行时表达式中使用诸如 `DType.float32` 之类的值。

#### `comptime` 成员作为关联类型

关联类型是 `comptime` 成员的一种常见用途。例如，一个 `List[T]` 结构体持有类型为 `T` 的值。该列表的 `__iter__()` 方法返回一个返回类型为 `T` 值的列表迭代器。`List` 使用 `comptime` 成员 `IteratorType` 来定义返回迭代器的类型。

下面的代码片段展示了 `List` 部分代码的简化版本，显示 `List` 及其关联的 `IteratorType`：

```mojo no-test
@fieldwise_init
struct _ListIter[
    mut: Bool,
    //,
    T: Copyable,
    origin: Origin[mut],
](ImplicitlyCopyable, Iterable, Iterator):

    comptime Element = Self.T  # Required by the Iterator trait

    var index: Int
    var src: Pointer[List[Self.Element], Self.origin]

    # ... implementation omitted

struct List[T: Copyable](
    Boolable, Copyable, Defaultable, Iterable, Sized
):
    comptime IteratorType[
        iterable_mut: Bool, //, iterable_origin: Origin[iterable_mut]
    ]: Iterator = _ListIter[Self.T, iterable_origin]

    # ... code omitted

    def __iter__(ref self) -> Self.IteratorType[origin_of(self)]:
        return {0, Pointer(to=self)}

    # ... code omitted
```

`IteratorType` 成员在 origin 上参数化，因此它可以表示可变和不可变两种迭代器。

### 结构体方法

结构体的方法可以接受自己的参数。例如，`SIMD.slice()` 方法接受一个 `size` 参数：

```mojo
var m = SIMD[DType.int32, 4](1, 3, 5, 7)
var n = m.slice[2]()
print(n)  # prints [1, 3]
```

结构体的生命周期方法（`__init__()` 和 `__deinit__()`）是此规则的例外——它们不能接受参数。

### 案例研究：SIMD 类型

作为参数化类型的真实示例，让我们看看 Mojo 标准库中的
[`SIMD`](/docs/std/builtin/simd/SIMD/) 类型。

[单指令多数据流（SIMD）](https://en.wikipedia.org/wiki/Single_instruction,_multiple_data)
是一种内置于许多现代 CPU、GPU 和定制加速器中的并行处理技术。SIMD 允许你同时对多个数据执行单个操作。例如，如果你想对数组中每个元素取平方根，可以使用 SIMD 来并行化这项工作。

处理器在硬件中使用低级向量寄存器实现 SIMD，这些寄存器持有多个标量数据类型的实例。要使用这些处理器上的 SIMD 指令，数据必须被塑形为正确的 SIMD 宽度（数据类型）和长度（向量大小）。处理器可能支持 512 位或更长的 SIMD 向量，并支持从 8 位整数到 64 位浮点数的多种数据类型，因此预定义所有可能的 SIMD 变体并不实际。

Mojo 的 [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型（定义为一个结构体）通过其方法暴露了通用的 SIMD 操作，并将 SIMD 数据类型和长度值作为参数接受。这允许你直接将数据映射到任何硬件上的 SIMD 向量。

下面是 Mojo `SIMD` 类型定义的一个精简（非功能性）版本：

```mojo no-test
struct SIMD[dtype: DType, length: Int]:
    var value: … # Some low-level MLIR stuff here

    # Create a new SIMD from a number of scalars
    def __init__(out self, *elems: SIMD[Self.dtype, 1]):  ...

    # Fill a SIMD with a duplicated scalar value.
    @staticmethod
    def splat(x: SIMD[Self.dtype, 1]) -> SIMD[Self.dtype, Self.length]: ...

    # Cast the elements of the SIMD to a different elt type.
    def cast[target: DType](self) -> SIMD[target, Self.length]: ...

    # Many standard operators are supported.
    def __add__(self, rhs: Self) -> Self: ...
```

因此，你可以像这样创建和使用 SIMD 向量：

```mojo
var vector = SIMD[DType.int16, 4](1, 2, 3, 4)
vector = vector * vector
for i in range(4):
    print(vector[i], end=" ")
```

```output
1 4 9 16
```

如你所见，将像 `*` 这样的简单算术运算符应用于一对 `SIMD` 向量时，会在每个向量的对应元素上进行操作。

用参数定义每个 SIMD 变体非常适合代码重用，因为 `SIMD` 类型可以静态地表达所有不同的向量变体，而不需要语言预定义每个变体。

由于 `SIMD` 是一个参数化类型，其函数中的 `self` 参数携带这些参数——完整类型名是 `SIMD[dtype, length]`。虽然把它显式写出来是有效的（如 `splat()` 的返回类型所示），但这可能很冗长，因此我们建议使用 `Self` 类型（来自
[PEP673](https://peps.python.org/pep-0673/)），正如 `__add__()` 示例所做的那样。

## 使用参数化类型和函数

你可以通过向方括号中的参数传递值来使用参数化类型和函数。例如，对于上面的 `SIMD` 类型，`dtype`
指定数据类型，`length` 指定 SIMD 向量中元素的数量（必须是 2 的幂）：

```mojo
# Make a vector of 4 floats.
var small_vec = SIMD[DType.float32, 4](1.0, 2.0, 3.0, 4.0)

# Make a big vector containing 1.0 in float16 format.
var big_vec = SIMD[DType.float16, 32](1.0)

# Do some math and convert the elements to float32.
var bigger_vec = (big_vec + big_vec).cast[DType.float32]()
```

注意 `cast()` 方法也需要一个参数来指定你想要从转换得到的目标类型（上面的方法定义期望一个 `target` 参数值）。因此，正如 `SIMD` 结构体是一个参数化类型定义一样，`cast()` 方法是一个参数化方法定义。在编译时，编译器创建一个 `cast()` 方法的具体版本，其中 `target` 参数绑定到 `DType.float32`。

上面的代码展示了对具体类型的使用（即所有参数都绑定到已知值）。但参数的主要威力来自于定义参数化算法和类型（使用参数值的代码）的能力。例如，下面演示如何使用 `Scalar` 定义一个与数据类型无关的参数化算法：

```mojo
from std.math import sqrt


def rsqrt[dt: DType](x: Scalar[dt]) -> Scalar[dt]:
    return 1 / sqrt(x)

def main():
    var v = Scalar[DType.float16](42)
    print(rsqrt(v))
```

```output
0.154296875
```

当你使用方括号编写类型表达式时，例如 `List[Int]`，你必须绑定（指定值）该类型的所有参数。此规则有两个例外：

- 你可以显式地不绑定一个或多个参数，以创建一个
  [部分绑定或未绑定类型](#partially-bound-and-unbound-types)。

- 如果 Mojo 可以从上下文推断它们，你可以省略参数。

### 参数推断

Mojo 编译器通常可以*推断*参数值，因此你不必总是显式指定。例如，在前一节中，我们是这样调用参数化 `rsqrt()` 函数的：

```mojo
var v = Scalar[DType.float16](42)
print(rsqrt(v))
```

编译器根据传入的 `v` 值的类型推断 `dt` 参数，就好像你显式写了 `rsqrt[DType.float16](v)` 一样。图 1 展示了参数推断工作原理的心智模型。

参数推断可能看起来有点令人困惑：它看起来像是编译器在从运行时参数值推断编译时参数值。但实际上它是在从参数静态已知的*类型*推断参数。

:::note 推断失败

如果参数推断失败，编译器会报告错误，通常是 "failed
to infer parameter 'param_name'"。遗憾的是，编译器有时也会错误地报告此错误，例如当实际错误是类型不匹配时。在这些情况下，显式指定缺失的参数通常能让 Mojo 报告正确的错误。

:::

Mojo 还可以根据传给初始化器或静态方法的参数推断结构体参数的值。

例如，考虑以下结构体：

```mojo
struct One[Type: Writable & Copyable & Deinitable]:
    var value: Self.Type

    def __init__(out self, value: Self.Type):
        self.value = value.copy()


def use_one():
    var s1 = One(123)  # equivalent to One[Int](123)
    var s2 = One("Hello")  # equivalent to One[String]("Hello")
```

注意，你可以在不指定 `Type` 参数的情况下创建 `One` 的实例——Mojo 可以从 `value` 参数推断它。

你也可以从传给初始化器或静态方法的参数化类型推断参数：

```mojo
struct Two[Type: Writable & Copyable & Deinitable]:
    var val1: Self.Type
    var val2: Self.Type

    def __init__(out self, one: One[Self.Type], another: One[Self.Type]):
        self.val1 = one.value.copy()
        self.val2 = another.value.copy()
        print(String(self.val1), String(self.val2))

    @staticmethod
    def fire(thing1: One[Self.Type], thing2: One[Self.Type]):
        print("🔥", String(thing1.value), String(thing2.value))


def use_two() raises:
    var s3 = Two(One("infer"), One("me"))  # prints: infer me
    Two.fire(One(1), One(2))  # prints: 🔥 1 2
    # Two.fire(One("mixed"), One(0)) 
    # Error: parameter inferred to two different values
```

`Two` 接受一个 `Type` 参数，其初始化器接受类型为 `One[Type]` 的值。在构造 `Two` 的实例时，你不需要指定 `Type` 参数，因为它可以从参数推断出来。

类似地，静态 `fire()` 方法接受类型为 `One[Type]` 的值，因此 Mojo 可以在编译时推断出 `Type` 值。注意，传递两个不同类型的 `One` 实例是行不通的。

:::note

如果你熟悉 C++，你可能会认出这类似于类模板参数推导（Class Template
Argument Deduction，CTAD）。

:::

## 参数声明

当你在结构体或函数上声明参数时，你有许多与参数相同的选项——你可以定义带默认值的可选参数；仅关键字参数；以及可变参数。

此外，你可以定义*推断型参数（infer-only parameters）*，它提供了一种灵活的方式来定义参数化类型之间的依赖关系。

### 可选参数和关键字参数

就像你可以在函数签名中指定
[可选参数](/docs/manual/functions#optional-arguments)一样，你也可以通过给参数一个默认值来定义一个可选*参数*。

你也可以通过关键字传递参数，就像你可以使用
[关键字参数](/docs/manual/functions/#keyword-arguments)一样。对于一个有多个可选参数的函数或结构体，使用关键字让你可以只传递你想要指定的参数，无论它们在函数签名中的位置如何。

例如，下面是一个有两个参数的函数，每个参数都有默认值：

```mojo
def speak[a: Int = 3, msg: String = "woof"]():
    print(msg, a)


def use_defaults():
    speak()  # prints 'woof 3'
    speak[5]()  # prints 'woof 5'
    speak[7, "meow"]()  # prints 'meow 7'
    speak[msg="baaa"]()  # prints 'baaa 3'
```

回想一下，当调用一个参数化函数时，Mojo 可以
[推断参数值](#parameter-inference)。也就是说，它可以根据附加到参数上的参数来确定其参数值。如果参数化函数也定义了默认参数值，那么推断的参数值优先。

例如，在下面的代码中，我们更新参数化的 `speak[]()` 函数以接受一个具有参数化类型的参数。虽然该函数有一个为 `a` 定义的默认参数值，但 Mojo 使用从 `bar` 参数推断的 `a` 参数值（按所写的那样，默认的 `a` 值永远用不到，但这只是为了演示）：

```mojo
@fieldwise_init
struct Bar[v: Int]:
    pass


def speak[a: Int = 3, msg: String = "woof"](bar: Bar[a]):
    print(msg, a)


def use_inferred():
    speak(Bar[9]())  # prints 'woof 9'
```

如上所述，你也可以在结构体中使用可选参数和关键字参数：

```mojo
struct KwParamStruct[greeting: String = "Hello", name: String = "🔥mojo🔥"]:
    def __init__(out self):
        print(Self.greeting, Self.name)


def use_kw_params():
    var a = KwParamStruct[]()  # prints 'Hello 🔥mojo🔥'
    var b = KwParamStruct[name="World"]()  # prints 'Hello World'
    var c = KwParamStruct[greeting="Hola"]()  # prints 'Hola 🔥mojo🔥'
```

:::note

Mojo 支持仅位置参数和仅关键字参数，遵循与
[仅位置参数和仅关键字参数](/docs/manual/functions#positional-only-and-keyword-only-arguments)
相同的规则。

:::

### 可变参数

Mojo 也支持可变参数，类似于
[可变参数](/docs/manual/functions/#variadic-arguments)：

```mojo
struct MyTensor[*dimensions: Int]:
    pass
```

可变参数目前有一些可变参数所没有的限制：

- 可变参数必须是同质的——即所有值必须是相同的类型。

- 参数类型必须是寄存器可传递的（register-passable）。

可变关键字参数（例如 `**kwparams`）尚不支持。

### 推断型参数

有时你需要声明参数依赖于其他参数的函数。由于签名是从左到右处理的，一个参数只能*依赖*参数列表中较早出现的参数。例如：

```mojo no-test
def dependent_type[dtype: DType, value: Scalar[dtype]]():
    print("Value: ", value)
    print("Value is floating-point: ", dtype.is_floating_point())

dependent_type[DType.float64, Float64(2.2)]()
```

```output
Value:  2.2000000000000002
Value is floating-point:  True
```

你不能交换 `dtype` 和 `value` 参数的位置，因为 `value` 依赖于 `dtype`。然而，由于 `dtype` 是一个必需参数，你不能把它从参数列表中省略，让 Mojo 从 `value` 推断它：

```mojo no-test
dependent_type[Float64(2.2)]() # Error!
```

推断型参数是一类特殊的参数，它们**总是**要么从上下文推断，要么通过关键字指定。推断型参数放在参数列表的**开头**，用 `//` 符号与其他参数分隔：

```mojo no-test
def example[T: Copyable, //, list: List[T]]()
```

将 `dtype` 转换为推断型参数解决了这个问题：

```mojo
def dependent_type[dtype: DType, //, value: Scalar[dtype]]():
    print("Value: ", value)
    print("Value is floating-point: ", dtype.is_floating_point())
```

```mojo
dependent_type[Float64(2.2)]()
```

```output
Value:  2.2000000000000002
Value is floating-point:  True
```

由于推断型参数是在参数列表的开头声明的，其他参数可以依赖它们，并且编译器总是尝试从绑定的参数或参数中推断推断型值。

有时通过关键字指定一个推断型参数会很有用。例如，
[`Span`](/docs/std/collections/span/Span/) 类型在
[origin](/docs/manual/values/lifetimes/) 上参数化：

```mojo no-test
struct Span[mut: Bool, //, T: Copyable, origin: Origin[mut]]:
    # ... implementation omitted
```

这里，`mut` 参数是推断型的。该值通常在你创建 `Span` 实例时被推断。通过关键字绑定 `mut` 参数让你可以定义一个需要可变 origin 的 `Span`。

```mojo
def mutate_span(span: Span[mut=True, Byte, _]):
    for i in range(0, len(span), 2):
        if i + 1 < len(span):
            span.swap_elements(i, i + 1)
```

如果编译器无法推断出一个推断型参数的值，并且也未通过关键字指定它，则编译失败。

## 参数表达式就是 Mojo 代码

参数表达式是指出现在期望参数位置的任何代码表达式（例如 `a+b`）。参数表达式支持运算符和函数调用，就像运行时代码一样，并且所有参数类型都使用与运行时程序相同的类型系统（例如 `Int` 和 `DType`）。

由于参数表达式使用与运行时 Mojo 代码相同的语法和类型，你可以使用许多
["依赖类型"（dependent type）](https://en.wikipedia.org/wiki/Dependent_type) 特性。例如，你可能想定义一个辅助函数来拼接两个 SIMD 向量：

```mojo
def concat[
    dtype: DType, ls_size: Int, rh_size: Int, //
](lhs: SIMD[dtype, ls_size], rhs: SIMD[dtype, rh_size]) -> SIMD[
    dtype, ls_size + rh_size
]:
    var result = SIMD[dtype, ls_size + rh_size]()

    comptime for i in range(ls_size):
        result[i] = lhs[i]

    comptime for j in range(rh_size):
        result[ls_size + j] = rhs[j]
    return result
```

注意结果长度是输入向量长度之和，一个简单的 `+` 运算就表达了这一点。

### 强大的编译时编程

虽然简单表达式很有用，但有时你想编写带控制流的命令式编译时逻辑。你甚至可以做编译时递归。例如，下面是一个 "树形归约（tree reduction）" 算法示例，它递归地把一个向量的所有元素求和为一个标量：

```mojo
def slice[
    dtype: DType, size: Int, //
](x: SIMD[dtype, size], offset: Int) -> SIMD[dtype, size // 2]:
    comptime new_size = size // 2
    var result = SIMD[dtype, new_size]()
    for i in range(new_size):
        result[i] = Scalar[dtype](x[i + offset])
    return result


def reduce_add(x: SIMD) -> Int:
    comptime if x.length == 1:
        return Int(x[0])
    elif x.length == 2:
        return Int(x[0]) + Int(x[1])

    # Extract the top/bottom halves, add them, sum the elements.
    comptime half_size = x.length // 2
    var lhs = slice(x, 0)
    var rhs = slice(x, half_size)
    return reduce_add(lhs + rhs)


def main():
    var x = SIMD[DType.int, 4](1, 2, 3, 4)
    print(x)
    print("Elements sum:", reduce_add(x))
```

```output
[1, 2, 3, 4]
Elements sum: 10
```

这使用了
[`comptime if`](/docs/manual/metaprogramming/comptime-evaluation/#comptime-if)
语句，它是一个在编译时运行的 `if` 语句。它要求其条件是一个有效的参数表达式，并确保只有 `if` 语句的活动分支被编译进程序。这与前面展示的 `comptime for` 循环的用法类似。

## 参数化的 `comptime` 值

*参数化的 `comptime` 值*是一个接受参数列表并返回编译时常量值的编译时表达式：

```mojo
comptime AddOne[a: Int] : Int = a + 1

comptime nine = AddOne[8]
```

正如前一个示例所示，参数化的 `comptime` 值有点像*仅编译时函数*。常规的函数或方法也可以在编译时被调用：

```mojo
def add_one(a: Int) -> Int:
    return a + 1

comptime ten = add_one(9)
```

函数和参数化的 `comptime` 值之间的一个主要区别是：`comptime` 表达式的值可以是一个类型，而函数不能作为一个值返回类型。

```mojo no-test
# Does not work—-dynamic type values not permitted
def int_type() -> AnyType:
    return Int

# Works
comptime IntType = Int
```

由于 `comptime` 值可以是一个类型，你可以使用参数化的 `comptime` 值来表达新类型：

```mojo
comptime TwoOfAKind[dt: DType] = SIMD[dt, 2]
var twoFloats = TwoOfAKind[DType.float32](1.0, 2.0)

comptime StringKeyDict[ValueType: Copyable & Deinitable] = Dict[
    String, ValueType
]
var b: StringKeyDict[UInt8] = {"answer": 42}
```

参数化的 `comptime` 声明支持与参数化结构体或函数相同的特性：推断型参数、仅关键字和可选参数、
[自动参数化](#automatic-parameterization)，等等。

```mojo
comptime Floats[size: Int, half_width: Bool = False] = SIMD[
    (DType.float16 if half_width else DType.float32), size
]
var floats = Floats[2](6.0, 8.0)
var half_floats = Floats[2, True](10.0, 12.0)
```

## 部分绑定和未绑定类型

一个参数化类型如果其参数都被指定，就被称为*完全绑定（fully bound）*。也就是说，它的所有参数都绑定到值。如前所述，你只能实例化一个完全绑定类型（有时称为*具体类型（concrete type）*）。

然而，在某些上下文中，参数化类型可以是*未绑定（unbound）*或*部分绑定（partially bound）*的。例如，你可以使用 `comptime` 为部分绑定类型创建类型别名，以创建一个需要较少参数的新类型：

```mojo
comptime StringKeyDict = Dict[String, _]
var b: StringKeyDict[UInt8] = {"answer": 42}
```

这里，`StringKeyDict` 是一个接受 `String` 键的 `Dict` 的类型别名。参数列表中的下划线 `_` 表示第二个参数
`V`（即值类型）未绑定。你在使用 `StringKeyDict` 时再指定 `V` 参数。

当作为 `comptime` 值使用时，未绑定参数上的任何默认值都会被保留，直到形成一个具体类型（例如，通过调用结构体的初始化器）：

```mojo
@fieldwise_init
struct HasDefault[x: Int, y: Int = 0]:
    pass


comptime UseDefault = HasDefault[10]
```

```mojo
var instance1 = UseDefault()  # instance of HasDefault[10, 0]
```

在定义参数化 API 时，你可以使用部分绑定和未绑定类型以更少的样板代码表达类型约束，这一特性称为
[自动参数化](#automatic-parameterization)：

```mojo no-test
# standard declaration--explicit parameter declarations
def take_simd[dtype: DType, size: Int](value: SIMD[dtype, size]): pass

# automatically parameterized declaration
def take_floats(value: SIMD[_, _]): pass
```

你可以通过几种方式指定部分绑定或未绑定类型：

- 使用下划线（`_`）代替参数值，显式不绑定一个或多个参数：

  ```mojo
  comptime StringKeyDict = Dict[String, _]

  def take_floats(floats: SIMD[DType.float32, _]): pass
  ```

  当像这样编写类型表达式时，你必须绑定或显式不绑定每个参数，除非 Mojo 可以从上下文推断该参数。例如，这会产生一个错误：

  ```mojo
  comptime Bad = Dict[String]  # error: 'Dict' failed to infer parameter 'V'
  ```

- 使用省略号（`...`）在参数列表末尾显式不绑定任意数量的参数：

  ```mojo
  comptime PartiallyBound = SomeComplicatedType[String, ...]
  comptime Unbound = SomeComplicatedType[...]

  def take_simd(v: SIMD[...]): pass
  ```

  使用省略号会不绑定列表中所有剩余的参数，包括关键字参数。

- 使用不带方括号的裸标识符来指定一个未绑定类型：

  ```mojo
  comptime SomeAlias = SomeComplicatedType

  def take_simd2(v: SIMD): pass
  ```

  就风格而言，`SIMD[...]` 或 `SIMD[_, _]` 通常比裸 `SIMD` 更可取。前两者更明确，并为读者提供一个视觉提示，表明他们正在看一个参数化类型。

### 部分绑定类型与参数化的 `comptime` 值

你可能会注意到本节中的 `comptime` 示例看起来类似于
[参数化的 `comptime` 值](#parameterized-comptime-values) 一节中的示例。例如，你可以用两种语法中的任意一种定义 `StringKeyDict` 别名：

```mojo no-test
# partially-bound type
comptime StringKeyDict = Dict[String, _]
# parameterized comptime value
comptime StringKeyDict[V] = Dict[String, V]
```

对于简单的类型别名，你可以使用部分绑定类型或参数化的 `comptime` 值。对于更复杂的别名，参数化的 `comptime` 值为你提供了更多的灵活性。

## 自动参数化

编写高度参数化的 API 通常会产生冗长、重复的签名。例如，要定义一个接受任何类型 `SIMD` 值的函数，你可以这样写：

```mojo no-test
def take_simd[dtype: DType, size: Int, //](vec: SIMD[dtype, size]):
    pass
```

这个签名表示一个函数接受任何 `SIMD` 值，并推断其 `dtype` 和 `size` 参数。但要做一件相当简单的事情，这代码量有点多。

为了更容易地编写此类签名，Mojo 支持 "自动" 参数化。你不需要在参数类型中显式命名每个参数，而是指定一个
[部分绑定或未绑定类型](#partially-bound-and-unbound-types)：

```mojo
def take_simd(vec: SIMD[...]):
    print(vec.dtype)
    print(vec.length)
```

```mojo
var v = SIMD[DType.float64, 4](1.0, 2.0, 3.0, 4.0)
take_simd(v)
```

```output
float64
4
```

在上面的示例中，`take_simd()` 函数是自动参数化的。`vec` 参数接受一个类型为 `SIMD[...]` 的值——一个未绑定的参数化类型。Mojo 把 `vec` 上的未绑定参数视为函数上的推断型参数。这大致等价于以下代码：

```mojo no-test
def take_simd[t: DType, s: Int, //](vec: SIMD[t, s]):
    print(t)
    print(s)
```

当你调用 `take_simd()` 时，你必须传入一个 `SIMD` 类型的具体实例——即所有参数都被指定的实例，例如
`SIMD[DType.float64, 4]`。Mojo 编译器从输入参数*推断*参数值。

你也可以在部分绑定类型上使用自动参数化：

```mojo no-test
def take_floats(floats: SIMD[DType.float32, _]): pass
```

手动参数化的签名与自动参数化的签名之间有两个重要区别：

- 对于手动参数化的函数，你可以按名称访问参数（例如前一示例中的 `t` 和 `s`），而这在自动参数化的函数中不是一个选项。

  不过，你始终可以使用点语法访问类型的参数和 `comptime` 成员——正如在自动参数化示例中那样，使用 `vec.dtype` 和 `vec.length` 访问参数上的参数。

- 对于手动参数化的函数，你可以直接传递参数值；这在自动参数化的函数中不是一个选项。未绑定参数总是被推断出来的。

除了在函数的参数列表中使用自动参数化外，你还可以在函数、结构体和参数化的 `comptime` 值的参数列表中使用它。

### 自动参数化的示例

本节展示更多使用自动参数化的示例。

#### 参数的自动参数化

你也可以在函数、结构体或参数化的 `comptime` 值的参数列表中利用自动参数化。例如：

```mojo no-test
def simd_param[value: SIMD[...]]():
    pass

# Equivalent to:
def simd_param[dtype: DType, size: Int, //, value: SIMD[dtype, size]]():
    pass
```

下面是使用参数化的 `comptime` 值的另一个示例：

```mojo
comptime SomeComptime[s: SIMD[...]] = SomeStruct[s]

# Equivalent to:
comptime SomeComptime2[dtype: DType, size: Int, //, S: SIMD[dtype, size]] = SomeStruct[S]
```

#### 自动参数化和类型表达式

如前面的示例所示，你可以使用点语法（`arg.param`）访问参数或参数值的参数。你也可以在签名内部使用此语法。

例如，如果你希望函数接受两个具有相同类型和大小的 SIMD 向量，可以这样编写代码：

```mojo
def interleave(v1: SIMD[...], v2: type_of(v1)) -> SIMD[v1.dtype, v1.length * 2]:
    var result = SIMD[v1.dtype, v1.length * 2]()

    comptime for i in range(v1.length):
        result[i * 2] = v1[i]
        result[i * 2 + 1] = v2[i]
    return result
```

```mojo
var a = SIMD[DType.int16, 4](1, 2, 3, 4)
var b = SIMD[DType.int16, 4](0, 0, 0, 0)
var c = interleave(a, b)
print(c)
```

```output
[1, 0, 2, 0, 3, 0, 4, 0]
```

如示例所示，如果你只是想匹配一个参数的类型，你可以使用魔术表达式 `type_of(x)`。在这种情况下，它比写等价的 `SIMD[v1.dtype, v1.length]` 更方便、更紧凑。

#### 使用部分绑定类型的自动参数化

Mojo 也支持使用
[部分绑定参数化类型](#partially-bound-and-unbound-types)（即只有部分参数被指定的类型）的自动参数化。

例如，假设你有一个带三个参数的 `Fudge` 结构体：

```mojo
@fieldwise_init
struct Fudge[sugar: Int, cream: Int, chocolate: Int = 7](Writable):
    pass
```

你可以编写一个只接受一个绑定参数（即*部分绑定*）的 `Fudge` 参数的函数：

```mojo
def eat(f: Fudge[5, ...]):
    print("Ate", f)
```

`eat()` 函数接受一个 `Fudge` 结构体，其中第一个参数（`sugar`）绑定到值 5。第二个和第三个参数 `cream` 和 `chocolate` 未绑定。

未绑定的 `cream` 和 `chocolate` 参数成为 `eat` 函数上的隐式参数。在实践中，这大致等价于写：

```mojo no-test
def eat[cr: Int, ch: Int, //](f: Fudge[5, cr, ch]):
    print("Ate", String(f))
```

在两种情况下，你都可以通过传入一个绑定了 `cream` 和 `chocolate` 参数的实例来调用该函数：

```mojo
eat(Fudge[5, 5, 7]())  # Ate Fudge (5,5,7)
eat(Fudge[5, 8, 9]())  # Ate Fudge (5,8,9)
```

如果你试图传入一个 `sugar` 值不是 5 的参数，编译会失败，因为它与参数类型不匹配：

```mojo no-test
eat(Fudge[12, 5, 7]())
# This fails because `eat()` expects `Fudge[5, 5, 7]`, but this value is
# `Fudge[12, 5, 7]`.
```

你也可以显式不绑定单个参数。这给了你在指定未绑定参数时更多的自由。

例如，你可能想让用户指定 `sugar` 和 `chocolate` 的值，而让 `cream` 保持常量。为此，把每个未绑定的参数值替换为单个下划线（`_`）：

```mojo
def devour(f: Fudge[_, 6, _]):
    print("Devoured", String(f))
```

同样，未绑定的参数（`sugar` 和 `chocolate`）作为函数上的隐式参数被添加。

你也可以通过关键字不绑定参数，或混合位置参数和关键字参数，因此下面的函数大致等价于前一个函数：第一个参数 `sugar` 用下划线字符显式不绑定。`chocolate` 参数使用关键字语法 `chocolate=_` 不绑定。而 `cream` 显式绑定到值 6：

```mojo no-test
def devour(f: Fudge[_, chocolate=_, cream=6]):
    print("Devoured", String(f))
```

`devour()` 函数的两个版本都适用于以下调用：

```mojo
devour(Fudge[3, 6, 9]())
devour(Fudge[4, 6, 8]())
```

```output
Devoured Fudge (3,6,9)
Devoured Fudge (4,6,8)
```

## 用 `rebind()` 断言参数化类型相等

Mojo 不像 C++ 那样在解析器中执行函数实例化，其后果之一是 Mojo 并不总能判断某些参数化类型是否相等，从而报告无效转换错误。这通常发生在静态分派模式中。例如，以下代码无法编译：

```mojo no-test
def take_simd8(x: SIMD[DType.float32, 8]):
    pass


def parameterized_simd[nelts: Int](x: SIMD[DType.float32, nelts]):
    comptime if nelts == 8:
        take_simd8(x)
```

解析器会报告：

```plaintext
error: invalid call to 'take_simd8': argument #0 cannot be converted from
'SIMD[f32, nelts]' to 'SIMD[f32, 8]'
        take_simd8(x)
        ~~~~~~~~~~^~~
```

这是因为解析器在不实例化的情况下对函数进行完整的类型检查，而 `x` 的类型仍然是 `SIMD[f32, nelts]`，而不是 `SIMD[f32, 8]`，尽管有静态条件。补救办法是使用
[`rebind()`](/docs/std/builtin/rebind/rebind/) 内置函数手动断言 `x` 的类型，它插入一个编译时断言：输入类型和结果类型在 elaboration 之后解析为同一类型：

```mojo
def take_simd8(x: SIMD[DType.float32, 8]):
    pass


def parameterized_simd[nelts: Int](x: SIMD[DType.float32, nelts]):
    comptime if nelts == 8:
        take_simd8(rebind[SIMD[DType.float32, 8]](x))
```

编译器仍然会检查类型是否匹配，但会在稍后的 elaboration 期间进行。如果类型不匹配，编译失败。关于何时使用 `rebind()` 有相当简单的规则：

- **应当**在你确信两个参数化类型在 elaboration 之后会完全相同时使用 `rebind()`。
- **不应当**使用 `rebind()` 在任意数据类型之间进行转换。

`rebind()` 返回一个指向被重绑定值的引用。如果你需要转移被重绑定的值或将其赋给一个变量，请使用
[`rebind_var()`](/docs/std/builtin/rebind/rebind_var/) 函数。
