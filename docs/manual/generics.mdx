参数化类型让你只需编写一次代码，即可在多种类型上使用而无需重复逻辑。你不需要为每种情况单独实现或进行类型检查。Mojo 会为你使用的每种类型生成专用版本。

大多数语言只对类型进行参数化。Mojo 还支持值参数。它的参数系统使用相同的 `[]` 语法接受类型和编译时值。

Mojo 在语法上区分编译时参数和运行时参数。参数放在方括号 `[]` 中，在编译时解析。参数放在圆括号 `()` 中，在运行时解析。

你在每个定义和调用点都能看到这种区别，因此你始终知道编译器特化了什么、运行时传递了什么。

```mojo
# T is a type parameter, threshold is a value parameter.
# Both are compile-time. values is a runtime argument.
def count_above[
    T: Comparable & ImplicitlyCopyable & Deinitable, threshold: T
](values: List[T]) -> Int:
    var count = 0
    for v in values:
        if v > threshold:
            count += 1
    return count
```

许多参数化声明使用 trait 来约束哪些类型可以与代码一起工作。trait 定义了类型必须做什么，参数化代码声明它需要哪些 trait。编译器会强制执行这些要求，并在调用点为每个具体类型生成专用代码。

## 类型参数

类型参数让你编写可跨多种类型工作的代码。你只需定义一次行为，编译器就会在调用点为每个具体类型对其进行特化。

### 类型约束

*约束*（constraint）定义了类型必须做什么。你将它们表示为 trait 或 trait 组合。你必须始终约束或显式指定参数名的类型。如果没有一组固定的必要功能，编译器就无法保证哪些操作是有效的。

- 最宽松的约束是 [`AnyType`](/docs/std/builtin/anytype/AnyType/)。它对类型不施加任何行为要求。

- [`Deinitable`](/docs/std/builtin/anytype/Deinitable/) 是具有生命周期的类型的常见基线。存储或拥有值的参数化代码通常需要它。

约束使你的代码健全：你使用的每个操作都保证存在于满足约束的任何类型中。

### 命名约定

Mojo 遵循 Rust 和 C++ 等语言中使用的命名约定。类型参数名使用 PascalCase，可以是简短的（`T`、`E`）也可以是描述性的（`ErrorType`、`Element`）。按照约定，`T`、`U`、`V` 表示通用类型；`K`/`V` 用于键值对；`E` 表示错误；`H` 表示哈希器。值参数名使用 lower_snake_case，应当具有描述性（如 `capacity`、`hasher`、`tile_x`）。

### 基础示例：比较两个列表

考虑比较两个列表以测试它们是否按相同顺序包含相同的值。

你可以为每种元素类型编写单独的实现。或者，你也可以编写一个参数化函数，适用于任何其元素支持所需操作的列表。

下面这个具体版本只适用于整数：

```mojo
def all_equal_int(ref lhs: List[Int], ref rhs: List[Int]) -> Bool:
    if len(lhs) != len(rhs): return False

    for left, right in zip(lhs, rhs):
        if left != right:
            return False
    return True
```

参数化版本不关心元素类型。它只要求算法所使用的能力：元素必须支持相等比较、可复制，并且可隐式销毁（这样 `zip()` 产出的元组才能在每次迭代结束时被清理）：

```mojo
def all_equal[
    T: Equatable & Copyable & Deinitable
](ref lhs: List[T], ref rhs: List[T]) -> Bool:
    if len(lhs) != len(rhs): return False

    for left, right in zip(lhs, rhs):
        if left != right:
            return False
    return True
```

两个实现遵循相同的逻辑：检查长度，在第一次不匹配时返回 `False`，如果没有发现差异则返回 `True`。

类型参数 `T` 在函数参数之前的方括号中声明。它表示两个列表的元素类型。当你调用 `all_equal()` 时，编译器会从调用点推断 `T`：

```mojo
print("Int (Expect True):\t",
    all_equal([1, 2, 3], [1, 2, 3])) # True
print("Int (Expect False):\t",
    all_equal([1, 2, 3], [4, 5, 6])) # False
print("String (Expect True):\t",
    all_equal(["hello", "world"], ["hello", "world"])) # True
print("String (Expect False):\t",
    all_equal(["hello", "world"], ["goodbye", "world"])) # False
```

编译器为你使用的每种类型生成一个具体的、特定类型的 `all_equal()` 版本：在这个例子中，一个用于 `Int`，一个用于 `String`。

:::note
在类型论中，参数化的 `all_equal()` 函数是*多态的*（polymorphic）。生成的特定类型版本是*单态的*（monomorphic）。
:::

### 选择约束

保持要求最小化：

```mojo
T: Equatable & Copyable & Deinitable
```

和号（`&`）用于组合 trait。请使用你的代码所需的最少约束。这能让你的函数适用于更多类型。如果你从 `all_equal()` 中移除 `Equatable`，代码将无法编译，因为编译器无法保证 `!=` 对所有 `T` 都存在。删除 `Deinitable` 失败的原因更隐蔽：`zip()` 以元组的形式产出每一对值，而循环只有在 `T` 可隐式销毁时才能销毁那个临时元组。

:::note
类型通过实现 `__ne__()` 来支持 `!=`。
:::

当你的代码使用了约束未覆盖的操作时，编译器会报告错误：类型*未充分指定*。通过添加提供缺失行为的 trait 来修复此问题。在实践中，参数化错误意味着你的约束未包含代码所使用的行为。

添加约束会限制你接受的类型，但会扩展你的代码能做的事情。每个 trait 都会添加有保证的操作，这让编译器能够检查正确性并推理生命周期和效果。

### 参数化类型

在 `all_equal()` 示例中，两个参数使用了相同的元素类型：

```mojo
lhs: List[T], rhs: List[T]
```

对两个参数都使用 `T` 可确保你的循环进行同类比较，并防止类型不匹配。你也可以直接使用参数化类型，而无需将其嵌入到容器中：

```mojo
def my_parameterized_fn[T: AnyType](value: T):
```

这个函数接受任何类型，因为它的唯一限制是 `AnyType`，即所有类型都遵循的 trait 层次结构根。使用 `AnyType` 意味着该值没有保证的析构器或生命周期管理。除了[反射](/docs/manual/metaprogramming/reflection/)之外，这个函数无法对 `value` 做任何有意义的事情。

#### 打印未充分指定的参数化值

`AnyType` 的一个常见问题是，编译器无法打印未指定类型的值。由于它无法确定 `T` 是否遵循 `Writable`，因此无法生成打印它所需的代码：

```mojo
def function[Ts: AnyType](*args: Ts):
    for arg in args:
        print(arg) # Will error.
        # The compiler can't verify `Writable` conformance


def main():
    function(1, 2, 3)
```

可以通过测试参数化类型参数是否遵循 `Writable` 并将其向下转型以暴露 `Writable` trait 来解决此问题：

```mojo
def represent[T: AnyType](v: T) -> String:
    comptime if conforms_to(T, Writable):
        return String(v)
    else:
        return String(t"{reflect[T].name()}")

def function[Ts: AnyType](*args: Ts):
    for arg in args:
        print(represent(arg))

@fieldwise_init
struct SomeStruct:
    var x: Int

def main():
    function(1, 2, 3) # prints each integer
    function(SomeStruct(2), SomeStruct(3)) # each "(module-name).SomeStruct"
```

`Writable` 项的打印效果与显式转换为 `String` 相同。非 `Writable` 项使用其类型名，前面加上模块名（即不带扩展名的文件名）作为前缀。

请参阅本页关于[安全向下转型](#downcasting-safely)的更多内容。

## 参数化类型

参数化声明不限于函数。你可以定义使用编译时参数来定义其字段和方法的参数化类型。

参数化类型让你可以打包一种可重用的形状：存储字段加上支持的操作。你无需编写 `PairInt`、`PairString` 等，只需编写一个 `Pair[T]`，让编译器为你使用的每个具体 `T` 生成专用版本。

```mojo
comptime ComparableValue = Equatable & ImplicitlyCopyable & Deinitable

@fieldwise_init
struct Pair[T: ComparableValue](ComparableValue):
    var left: Self.T
    var right: Self.T

    def __eq__(self, other: Pair[Self.T]) -> Bool:
        return self.left == other.left and self.right == other.right
```

与参数化函数一样，参数化类型使用占位符参数，但参数化类型在其存储和方法中都会使用这些参数。这里，`Pair` 存储两个相同元素类型的值，并通过比较其字段来实现相等。

`Pair` 需要比较值，因此 `T` 必须是可相等的。它还需要在常见操作中复制和清理值，因此它对 `T` 应用了 trait 组合：

```mojo
comptime ComparableValue = Equatable & ImplicitlyCopyable & Deinitable
```

`Pair` 的定义在两个地方应用了这个遵循：

```mojo
struct Pair[T: ComparableValue](ComparableValue):
```

- **方括号** —— 对调用者的要求：任何与 `Pair` 一起使用的值必须具有类型 `T`，且 `T` 必须是 `ComparableValue`。
- **圆括号** —— 来自 `Pair` 自身的承诺："我是一个 `ComparableValue`。"

这使得 `Pair[T]` 可在任何需要 `ComparableValue` 的地方使用，并确保所有 `T` 值都遵循。

## 混合类型参数和值参数

参数化类型也可以接受非类型参数。添加定义行为所需的任何内容：

```mojo
struct ExampleStruct:
    def example[
        T: Writable & Copyable,   # type parameter
        count: Int,               # value parameter
    ](
        self,
        data: String,             # argument
        init_value: T             # parameterized argument
    ) -> String:
```

按照约定，Mojo 对编译时值参数使用 lower_snake_case。这在视觉上将它们与类型参数区分开来。

## 使用 `Some` 简化遵循语法

你可以用简洁的 `Some[Trait(s)]` 和 `SomeTypeList[Trait(s)]` 语法来替代显式的类型参数和遵循。这些形式既支持单个 trait，也支持 trait 组合，并让你在使用类型的地方表达遵循，而不是在一个地方声明参数又在另一个地方使用它。

例如：

```mojo
def my_parameterized_fn[T: Trait(s)](value: T):
```

可以变为：

```mojo
def my_parameterized_fn(value: Some[Trait(s)]):
```

你可以在任何曾经使用类型参数的地方、在任何参数约定下，将 `Some` 与任何 trait 或 trait 组合一起使用。如果编译器无法推断出具体类型，它会报错并要求你改用显式的类型参数。

### 参数

`Some` 将 trait 要求直接放在参数上，从而消除了显式的类型参数：

```mojo
# Before
def foo[T: Intable, //](x: T) -> Int:
    return x.__int__()

# After
def foo(x: Some[Intable]) -> Int:
    return x.__int__()
```

### 函数类型

`Some` 也适用于函数类型，将闭包参数的遵循移到参数上：

```mojo
# Before
def sync_parallelize[
    FuncType: def(Int) -> None,
](func: FuncType):
    ...

# After
def sync_parallelize(func: Some[def(Int) -> None]):
    ...
```

### 可变参数

使用 `*SomeTypeList` 来让可变参数包遵循，而不是使用单个类型参数：

```mojo
# Before
def show[*Ts: Writable](*pack: *Ts):
    ...

# After
def show(*pack: *SomeTypeList[Writable]):
    ...
```

### 运算符重载

运算符重载是 `Some` 的天然适用场景，使运算符生效的 trait 直接位于声明上：

```mojo
# Before
def __getitem__[I: Indexer, //](self, idx: I) -> ref[self.x] Self.T:
    ...

# After
def __getitem__(self, idx: Some[Indexer]) -> ref[self.x] Self.T:
    ...
```

### `Some` 不适用的情况

`Some` 并非在所有情况下都能替代类型参数。编译器无法为结构体字段推断出具体类型，并会报告错误，指出类型不具体，要求你使用 `[]` 来绑定缺失的参数：

```mojo
@fieldwise_init
struct Struct(Writable):
    # Error: a `Some` struct field has no concrete type to infer
    var x: Some[Copyable & Deinitable & Writable]

def main():
    var s = Struct(1)
    print(s)
```

将遵循移回参数化类型的参数上以修复此问题：

```mojo
@fieldwise_init
struct Struct[T: Copyable & Deinitable & Writable](Writable):
    var x: Self.T

def main():
    var s = Struct(1)
    print(s)  # Struct[Int](x=1)
```

## 使用条件可用性

有时遵循比你需要的更宽泛。例如，参数化类型在结构体中可能被约束为 `AnyType`，但你希望在某个方法中将其作为 `Writable` 使用。添加一个 `where` 子句来要求 `Writable`，使编译器在允许具体实例调用该方法之前证明遵循：

```mojo
def process(self, value: Self.T) where conforms_to(Self.T, Writable):
    print(value)
```

调用 `conforms_to(T, Trait)` 来测试 `T` 是否满足某个 trait。用 `and` 或 `or` 组合多个检查以表达更复杂的条件。

条件不限于 trait 检查。它们也可以约束编译时事实，例如数据长度是 2 的幂或容量为正。任何具有已知值的编译时表达式都可以出现在 `where` 子句中。

编译器会拒绝不满足约束的调用。例如，用非 `Writable` 类型 `T` 构建的类型无法调用 `process()`：

```mojo
self.process(non_writable)   # Compile-time error, constraint violation
```

`where` 子句让编译器能够在构造类型、解析遵循、编译方法和函数，或实例化编译时声明之前证明条件。

除了遵循之外，where 子句还可以对其参数测试谓词：某个 `DType` 是否为浮点或数值（`dtype.is_floating_point()`、`dtype.is_numeric()`），或某个整数参数是否为 2 的幂。

它不能做的是将目标事实（如 `is_64bit()` 或 `is_nvidia_gpu()`）或任意编译时函数作为约束进行求值。编译器无法将这些作为证明携带。对于这些情况，请改用 `comptime if`，它会直接对其条件求值。

## 参数化值

值让代码基于编译时常量而非类型进行参数化。你在 `[]` 中与类型参数一起声明它们，但它们绑定到值。

### 何时使用参数化值

当某个值影响结构或行为且在编译时已知时，使用参数化值。常见场景：

- *固定大小：* 缓冲区长度、数组维度、矩阵形状
- *阈值和限制：* 容量上限、重试次数、精度级别
- *功能选择：* 算法变体、调试标志、模式开关
- *数值配置：* SIMD 宽度、步长、展开因子

编译器为每个不同的值特化代码。它可以移除死分支（`comptime if`）、展开循环（`comptime for`）、替换内联常量，并进行积极优化而无需运行时成本。

### 基础示例

以下函数创建一个用默认值初始化的固定大小列表：

```mojo
comptime MyCollectionElement = ImplicitlyCopyable & Deinitable

def make_filled[T: MyCollectionElement, size: Int](
    splat_value: T
) -> List[T]:
    var result = List[T](capacity=size)
    for _ in range(size):
        result.append(splat_value)
    return result^
```

`size` 参数在编译时解析。每个具有不同值的调用点都会获得自己的专用版本：

```mojo
var three_zeros = make_filled[Int, 3](0)
var five_hellos = make_filled[String, 5]("hello")
print(three_zeros)  # [0, 0, 0]
print(five_hellos)  # [hello, hello, hello, hello, hello]
```

### 值参数与运行时参数

将编译时已知的值放在 `[]` 中。将只在运行时已知的值放在 `()` 中。

问问自己：调用者在编写代码时是否知道这个值？如果是，使用参数。如果它依赖于输入、文件或运行时状态，使用参数。

```mojo
# size is compile-time: the compiler specializes
def fixed[size: Int]():
    var buf = Array[Int, size](fill=0)

# size is runtime: no specialization
def dynamic(size: Int):
    var buf = List[Int](capacity=size)
```

## 参数化类型与显式销毁

显式销毁的类型并不总是适用于参数化代码。问题不在于参数化，而在于生命周期管理。显式销毁让你可以控制拆卸：你可以定义接受参数、遵循不同路径或引发错误的析构器。

复制或移动值的参数化代码无法看到或遵守该逻辑。一旦值被复制或传输，你就失去了如何（或是否）清理它的控制，代码将无法编译。

注意这些情况：

- 管理生命周期的参数化代码
- 复制或传输值的参数化代码

这些最常出现在复制值或获取所有权并决定何时销毁的容器、集合和迭代器中。

安全的情况是不影响生命周期的参数化操作，如比较和谓词。

如果你的参数化代码需要拥有、复制或控制值何时消亡，请避免显式销毁的类型。添加一个 `Deinitable` 约束以保持正常工作。

## 条件 trait 遵循

:::caution
某些功能在推出期间可能不稳定或不可用。对 `RegisterPassable` 和 `TrivialRegisterPassable` 使用时要小心。
:::

*条件 trait 遵循*在允许类型采用 trait 之前使用检查。当条件满足时，类型就遵循。它必须满足 trait 的要求，并获得该 trait 提供的任何默认实现。当条件不满足时，Mojo 跳过遵循。

### 示例：派生遵循

在以下声明中，当其参数 `T` 也是 `Writable` 时，Mojo 让 `Wrapper` 遵循 `Writable`：

```mojo
comptime BaseTraits = Copyable & Deinitable & Writable
@fieldwise_init
struct Wrapper[T: BaseTraits](
    Writable where conforms_to(T, Writable)
):
    var value: Self.T
```

遵循 `Writable` 时，`Wrapper` 不需要实现任何方法。该 trait 提供了 `write_to()` 的默认实现。

现在考虑一个不是 `Writable` 的类型：

```mojo
@fieldwise_init
struct NotWritable(BaseTraits):
    var data: Int
```

当用 `Int` 或 `String`（两者都是 `Writable`）实例化时，`Wrapper` 获得 `Writable` 遵循。对于 `NotWritable`，你可以构建结构体，但无法打印它：

```mojo
var w_int = Wrapper[Int](42)  # Int is Writable
print(w_int)  # Wrapper[Int](value=42)

var w_str = Wrapper[String]("Hello")  # String is Writable
print(w_str)  # Wrapper[String](value=Hello)

# OK: only `Writable` conformance is unavailable
var w_not_writable = Wrapper[NotWritable](NotWritable(10))
# print(w_not_writable)  # Compile-time error:
# Wrapper[NotWritable] doesn't conform to Writable
```

这种模式对于像 `Optional[T]`、`Box[T]`、`Lazy[T]` 和 `List[T]` 这样的单类型容器是标准的。它表示："如果其内部类型可以做 X，这个类型就可以做 X。"

### 示例：部分遵循

对于具有多个不同组件的类型，这种模式可以自然扩展。`Result[T, E]`、`Pair[L, R]`、`Dict[K, V]` 等类型表示："如果其每个部分都可以做 X，这个类型就可以做 X"：

```mojo
comptime BaseTraits = Copyable & Deinitable

@fieldwise_init
struct Pair[L: BaseTraits, R: BaseTraits](
    Hashable where conforms_to(L, Hashable) and conforms_to(R, Hashable)
):
    var left: Self.L
    var right: Self.R


@fieldwise_init
struct NotHashable(BaseTraits):
    var data: Int
```

当 `L` 和 `R` 都是 `Hashable` 时，具体的 `Pair` 类型就变为 `Hashable`，从 trait 获得 `hash()` 方法：

```mojo
var pair = Pair[Int, String](left=1, right="one")
var hash = hash(pair)
print(hash)  # Prints the hash of the pair

# OK: only hashing is unavailable
var pair2 = Pair[Int, NotHashable](left=1, right=NotHashable(10))
# var hash2 = hash(pair2) # Compile-time error
```

### 示例：条件方法访问

当类型采用某个 trait 时，它必须满足该 trait 的必需方法。你用 `where` 子句对这些方法实现进行门控，这些子句与控制遵循是否适用的条件相同。

你可以通过让 `Wrapper` 遵循 `Boolable` 来使其在 `if` 语句中可测试，这要求实现 `__bool__()`：

```mojo
@fieldwise_init
struct Wrapper[T: BaseTraits](
    Writable where conforms_to(T, Writable),
    Boolable where conforms_to(T, Boolable),
    ):
    var value: Self.T

    def __bool__(self) -> Bool where conforms_to(Self.T, Boolable):
        return self.value.__bool__()
```

`__bool__()` 上的条件与用于 `Boolable` 条件遵循的条件相同。由于方法和遵循使用相同的条件，它们保持对齐。你不会出现有遵循但没方法、或有方法但没有相应遵循的情况。

```mojo
var w_str = Wrapper[String]("Hello")
if w_str:  # Chooses the non-empty branch
    print(t"Non-empty string \"{w_str.value}\" is truthy")
else:
    print(t"Empty string \"{w_str.value}\" is falsy")

var w_empty_str = Wrapper[String]("")
if w_empty_str:  # Chooses the empty branch
    print(t"Non-empty string \"{w_empty_str.value}\" is truthy")
else:
    print(t"Empty string \"{w_empty_str.value}\" is falsy")
```

由于 `NotWritable` 不是 `Boolable`，`__bool__()` 上的条件失败，该方法不可用：

```mojo
@fieldwise_init
struct NotWritable(BaseTraits):
    var data: Int

var w_not_writable = Wrapper[NotWritable](NotWritable(10))

# Compile-time error: the method condition is false
if w_not_writable:
    print(t"NotWritable with data {w_not_writable.value.data} is truthy")
else:
    print(t"NotWritable with data {w_not_writable.value.data} is falsy")
```

方法上的 `where` 子句在 trait 遵循之外也很有用。你可以对一个方法进行门控，使其只适用于非空列表、实数，或落在集合索引边界内的值。

### 条件 trait 组合

Mojo 支持灵活的条件组合：

- **无条件** —— 没有特殊子句：

  ```mojo
  struct Foo(Copyable, Deinitable):
  ```

- **简单条件** —— 如 `Wrapper` 所示：

  ```mojo
  struct Wrapper[T: BaseTraits](
      Writable where conforms_to(T, Writable)
  ):
  ```

- **混合** —— 混合无条件 trait 和条件 trait：

  ```mojo
  struct Foo[T: AnyType](
      Copyable, Writable where conforms_to(T, Writable)
  )
  ```

- **多个对齐条件** —— 如 `Pair` 所示：

  ```mojo
  struct Pair[L: BaseTraits, R: BaseTraits](
      Hashable where conforms_to(L, Hashable) and conforms_to(R, Hashable)
  ):
  ```

- **多个独立条件**：

  ```mojo
  struct Foo[T: AnyType](
    Writable where conforms_to(T, Writable),
    Hashable where conforms_to(T, Hashable),
  )
  ```

### 带值参数的条件遵循

条件遵循也适用于值参数。你可以在编译时值条件上门控遵循和方法。

当类型的能力依赖于数值参数时，这很有用。例如，固定容量的包装器可能只有在有容量且其元素可写时才是 `Writable`。`Sized` 遵循是无条件的：

```mojo
comptime ElementTraits = Writable & Copyable & Deinitable
struct SizedListWrapper[capacity: Int, T: ElementTraits](
    Sized, Writable where conforms_to(T, Writable) and capacity > 0
):
    var data: List[Self.T]

    def __init__(out self, value: Self.T):
        self.data = List[Self.T](capacity=Self.capacity)
        for _ in range(Self.capacity):
            self.data.append(value.copy())

    def __len__(self) -> Int:
        return len(self.data)

    def write_to(self, mut writer: Some[Writer]):
        writer.write(repr(self.data))
```

你可以在值条件上门控方法：

```mojo
def first(self) -> Self.T where Self.capacity > 0:
    return self.data[0].copy()
```

当容量为 1 或更大时，类型遵循 `Writable` 且 `first()` 可用。当它为 0 或更小时，两者都不可用：

```mojo
var s = SizedListWrapper[5, Int](42)
print(s)          # List of 42s
print(s.first())  # 42

# var s = SizedListWrapper[0, Int](42)
# print(s)          # Error: Writable not satisfied
# print(s.first())  # Error: constraint is false
```

值条件遵循与类型条件相同的规则。你可以用 `and` 组合它们，并在同一个 `where` 子句中与 `conforms_to` 检查混合使用。
