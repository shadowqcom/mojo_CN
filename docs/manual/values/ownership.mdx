使用某些编程语言时，你可能会面临的一个挑战是必须手动分配和释放内存。当程序的多个部分需要访问同一内存时，很难跟踪谁"拥有"一个值并确定何时释放它是正确的。如果你犯错，可能会导致"释放后使用"错误、"双重释放"错误或"内存泄漏"错误，其中任何一个都可能是灾难性的。

Mojo 通过确保每个值在同一时间只有一个变量拥有，同时仍然允许你与其他函数共享引用来帮助避免这些错误。当所有者的生命周期结束时，Mojo[销毁值](/docs/manual/lifecycle/death)。程序员仍然负责确保任何分配资源的类型（包括内存）也在其析构函数中释放这些资源。Mojo 的所有权系统确保析构函数被及时调用。

在本页中，我们将解释管理此所有权模型的规则，以及如何指定定义值如何传递到函数的不同参数约定。

## 所有权总结

使 Mojo 所有权模型工作的基本规则如下：

- 每个值在同一时间只有一个所有者。
- 当所有者的生命周期结束时，Mojo 销毁该值。
- 如果有对值的现有引用，Mojo 会延长所有者的生命周期。

### 变量和引用

变量*拥有*其值。结构体拥有其字段。

引用允许你访问由另一个变量拥有的值。引用对该值具有可变访问或不可变访问权限。

当你调用函数时，Mojo 会创建引用：函数参数作为可变或不可变引用传递。函数可以返回引用而不是返回值。要捕获返回的引用，你可以使用引用绑定：

```mojo
ref value_ref = list[0]
```

## 参数约定

在所有编程语言中，代码质量和性能在很大程度上取决于函数如何处理参数值。也就是说，函数接收的值是唯一值还是引用，以及它是可变还是不可变，有一系列定义语言的可读性、性能和安全的后果。

在 Mojo 中，我们希望通过默认提供完整的[值语义](/docs/manual/values/value-semantics)，这提供了一致和可预测的行为。但作为一个系统编程语言，我们也需要提供对内存优化的完全控制，这通常需要引用语义。诀窍是以确保所有代码都是内存安全的方式引入引用语义，方法是跟踪每个值的生命周期并在正确的时间（且仅一次）销毁每个值。所有这些都通过使用参数约定在 Mojo 中实现，这些约定确保每个值同时只有一个所有者。

参数约定指定参数是可变还是不可变，以及函数是否拥有该值。每个约定由参数声明开头的关键字定义：

- `read`：函数接收一个**不可变引用**。这意味着函数可以读取原始值（它不是副本），但它不能修改（改变）它。

- `mut`：函数接收一个**可变引用**。这意味着函数可以读取和修改原始值（它不是副本）。

- `var`：函数获取一个值的**所有权**。这意味着函数拥有参数的独占所有权。调用者可能选择将现有值的所有权转移到此函数，但这并不总是发生的情况。被调用者可能接收一个新创建的值，或现有值的副本。

- `ref`：函数获得一个具有参数化可变性的引用：即，引用可以是可变的或不可变的。你可以将 `ref` 参数看作是 `read` 和 `mut` 约定的泛化。`ref` 参数是一个高级主题，在[Lifetimes, origins, and references](/docs/manual/values/lifetimes/)中有更详细的描述。

- `out`：用于[构造函数](/docs/manual/lifecycle/life/#constructor)中 `self` 参数和[命名结果](/docs/manual/functions/#named-results)的特殊约定。`out` 参数在函数开始时未初始化，必须在函数返回之前初始化。虽然 `out` 参数出现在参数列表中，但调用者永远不会传递它们。

- `deinit`：在析构函数和消耗移动生命周期方法中使用的特殊约定。`deinit` 参数在函数开始时初始化，在函数返回时未初始化。

例如，此函数有一个可变引用参数和一个不可变参数：

```mojo
def add(mut x: Int, read y: Int):
    x += y

def main():
    var a = 1
    var b = 2
    add(a, b)
    print(a)
```

```output
3
```

你可能已经看到一些没有声明约定的函数参数。默认情况下，所有参数都是 `read`。在接下来的章节中，我们将更详细地解释每个这些参数约定。

## 不可变参数（`read`）

`read` 约定是所有参数的默认值。被调用函数接收参数值的不可变引用。

例如：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def main():
    var values = [1, 2, 3, 4]
    print_list(values)
```

```output
[1, 2, 3, 4]
```

这里，`print_list()` 函数可以从 `list` 参数读取，但不能修改它。`list` 是 `main()` 函数中 `values` 的引用，而不是副本。

一般来说，传递不可变引用在处理大型或复制成本高的值时要高效得多，因为对于 `read` 参数不会调用复制构造函数和析构函数。

### 与 C++ 和 Rust 的比较

Mojo 的 read 参数约定在某些方面类似于在 C++ 中通过 `const&` 传递参数，这也避免了值的副本并禁用了被调用方中的可变性。然而，read 约定与 C++ 中的 `const&` 有两个重要区别：

- Mojo 编译器实现了生命周期检查器，确保当有对值的未完成引用时，值不会被销毁。

- 像 `Int`、`Float` 和 `SIMD` 这样的小值始终在机器寄存器中传递。这提供了与 C++ 和 Rust 等语言相比的显著性能增强。

Rust 和 Mojo 之间的主要区别在于，Mojo 不需要在调用方传递不可变引用时使用信号。此外，Mojo 在传递小值时更高效，而 Rust 默认移动值而不是通过借用传递它们。这些策略和语法决策使 Mojo 能够提供更易于使用的编程模型。

## 可变参数（`mut`）

如果你希望函数接收一个**可变引用**，请在参数名称前添加 `mut` 关键字。你可以这样理解 `mut`：它意味着函数*内部*对值的任何更改在*外部*函数中都是可见的。

例如，此 `mutate()` 函数更新原始 `list` 值：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def mutate(mut l: List[Int]):
    l.append(5)

def main():
    var values = [1, 2, 3, 4]

    mutate(values)
    print_list(values)
```

```output
[1, 2, 3, 4, 5]
```

其行为就像以下内容的优化替代方案：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def mutate_copy(l: List[Int]) -> List[Int]:
    # def 创建列表的隐式副本，因为它被修改了
    l.append(5)
    return l

def main():
    var values = [1, 2, 3, 4]

    values = mutate_copy(values)
    print_list(values)
```

```output
[1, 2, 3, 4, 5]
```

虽然使用 `mut` 的代码并没有短多少，但因为它不创建值的副本，所以更节省内存。

但是，请记住，作为 `mut` 传递的值必须已经是可变的。例如，如果你尝试获取一个 `read` 值并将其作为 `mut` 传递给另一个函数，你会得到编译错误，因为 Mojo 无法从不可变引用形成可变引用。

:::note

你不能为 `mut` 参数定义[默认值](/docs/manual/functions#optional-arguments)。

:::

### 参数独占性

Mojo 强制执行可变引用的*参数独占性*。这意味着如果一个函数接收一个值的可变引用（如 `mut` 参数），它不能接收任何其他对该值的引用——可变或不可变。也就是说，可变引用不能有任何其他*别名*它的引用。

例如，考虑以下代码示例：

```mojo
def append_twice(mut s: String, other: String):
   # Mojo 知道 's' 和 'other' 不能是同一个字符串。
   s += other
   s += other

def invalid_access():
  var my_string = "o"  # 创建运行时 String 值

  # 错误：传递 `my_string` mut 是无效的，因为它也作为 read 传递。
  append_twice(my_string, my_string)
  print(my_string)
```

这段代码令人困惑，因为用户可能期望输出是 `ooo`，但由于第一个添加同时修改了 `s` 和 `other`，实际输出将是 `oooo`。强制执行可变引用的独占性不仅防止编码错误，还允许 Mojo 编译器在某些情况下优化代码。

当你确实需要可变和不可变引用（或需要将相同值传递给两个参数）时，避免此问题的一种方法是制作一个副本：

```mojo
def valid_access():
  var my_string = "o"           # 创建运行时 String 值
  var other_string = my_string  # 创建 String 值的副本
  append_twice(my_string, other_string)
  print(my_string)
```

请注意，对于可传递到寄存器的简单类型（如 `Int` 和 `Bool`），不强制执行参数独占性，因为它们总是通过复制传递。当将相同值传递给两个 `Int` 参数时，被调用者接收该值的两个副本。

## 转移参数（`var` 和 `^`）

最后，如果你希望函数接收值**所有权**，请在参数名称前添加 `var` 关键字。

此约定通常与传递给函数的变量上的后缀 `^`"转移"信号结合使用，这结束该变量的生命周期。

技术上讲，`var` 关键字并不保证接收的值是*原始值*——它只保证函数获得值的唯一所有权。这通过以下三种方式之一发生：

- 调用者使用 `^` 转移信号传递参数，这结束该变量的生命周期（该变量变为未初始化）并将所有权转移到函数中。

- 调用者**不**使用 `^` 转移信号，在这种情况下，Mojo 复制该值。如果类型不可复制，这是一个编译时错误。

- 调用者传递新创建的"拥有"值，例如从函数返回的值。在这种情况下，没有变量拥有该值，它直接转移到被调用者。例如：

  ```mojo
  def take(var s: String):
      pass

  def main():
      take("A brand-new String!")
  ```

以下代码通过复制字符串来工作，因为 `take_text()` 使用 `var` 约定，并且调用者不包含转移信号：

```mojo
def take_text(var text: String):
    text += "!"
    print(text)

def main():
    var message = "Hello"  # 创建运行时 String 值
    take_text(message)
    print(message)
```

```output
Hello!
Hello
```

然而，如果你在调用 `take_text()` 时添加 `^` 转移信号，编译器会抱怨 `print(message)`，因为此时 `message` 变量不再初始化。也就是说，此版本不会编译：

```mojo
def main():
    var message = "Hello"  # 创建运行时 String 值
    take_text(message^)
    print(message)  # 错误：使用未初始化的值 'message'
```

这是 Mojo 生命周期检查器的一个关键功能，因为它确保没有两个变量拥有同一个值。要修复此错误，你必须在使用 `^` 转移信号结束 `message` 变量的生命周期后不再使用 `message` 变量。所以这是修正后的代码：

```mojo
def take_text(var text: String):
    text += "!"
    print(text)

def main():
    var message = "Hello"  # 创建运行时 String 值
    take_text(message^)
```

```output
Hello!
```

无论它如何接收值，当函数将参数声明为 `var` 时，可以肯定它对该值有唯一可变访问权限。由于值被拥有，当函数退出时该值会被销毁——除非函数将值转移到其他地方。

例如，在以下示例中，`add_to_list()` 接收一个字符串并将其附加到列表中。字符串的所有权转移到列表，因此当函数退出时它不会被销毁。另一方面，`consume_string()` 不将其 `var` 值转移出去，因此该值在函数结束时被销毁。

```mojo
def add_to_list(var name: String, mut list: List[String]):
    list.append(name^)
    # name 未初始化，无需销毁

def consume_string(var s: String):
    print(s)
    # s 在这里被销毁
```

### 转移实现细节

在 Mojo 中，你不应该将"所有权转移"与"移动操作"混淆——它们并不严格相同。

Mojo 有多种方式转移值的所有权：

- 如果一个类型实现了[移动构造函数](/docs/manual/lifecycle/life#move-constructor)、`__init__(take=)`，Mojo 可能会在将值作为 `var` 参数传递给函数时调用此方法*如果*该类型的值被转移，并且*并且*原始变量的生命周期在同一时间结束（使用或不使用 `^` 转移信号）。

- 在某些情况下，Mojo 完全优化掉移动操作，将值保留在相同的内存位置但更新其所有权。在这些情况下，值在不调用复制或移动构造函数的情况下转移。

为了使 `var` 约定在没有转移信号的情况下工作，值类型必须是可复制的（通过 `__init__(out self, *, copy: Self)`）。
