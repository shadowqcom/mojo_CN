在使用某些编程语言时，你可能会遇到这样的挑战：必须手动分配和释放内存。当程序的多个部分需要访问同一块内存时，就很难跟踪到底是谁"拥有"某个值，也很难确定何时才是释放它的合适时机。如果出现失误，就可能导致"释放后使用（use-after-free）"错误、"双重释放（double free）"错误或"内存泄漏（leaked memory）"错误，其中任何一种都可能带来灾难性后果。

Mojo 通过确保任一时刻每个值都只有一个变量拥有它，同时仍允许你与其他函数共享引用，从而帮助避免这些错误。当所有者的生命周期结束时，Mojo 会[销毁该值](/docs/manual/lifecycle/death)。程序员仍然需要负责确保任何分配了资源（包括内存）的类型也在其去初始化器中释放这些资源。Mojo 的所有权系统保证去初始化器会被及时调用。

在本页中，我们将介绍支配这一所有权模型的规则，以及如何指定不同的参数约定来定义值传入函数的方式。

## 所有权摘要

使 Mojo 所有权模型得以运作的基本规则如下：

- 每个值在任一时刻只有一个所有者。
- 当所有者的生命周期结束时，Mojo 销毁该值。
- 如果对该值已存在引用，Mojo 会延长所有者的生命周期。

### 变量与引用

变量*拥有*其值。一个 struct 拥有它的字段。

*引用*让你可以访问由另一个变量所拥有的值。引用对该值要么具有可变访问权，要么具有不可变访问权。

当你调用函数时会创建 Mojo 引用：函数参数以可变或不可变引用的形式传入。函数也可以返回引用而不是返回值。要捕获一个返回的引用，可以使用引用绑定：

```mojo
ref value_ref = list[0]
```

## 参数约定

在所有编程语言中，代码质量与性能都严重依赖于函数如何处理参数值。也就是说，函数接收到的值是独占值还是引用、是可变的还是不可变的，会产生一系列后果，决定了语言的可读性、性能和安全性。

在 Mojo 中，我们希望默认提供完整的[值语义](/docs/manual/values/value-semantics)，这能提供一致且可预测的行为。但作为一种系统编程语言，我们也需要提供对内存优化的完全控制，这通常需要引用语义。关键在于以某种方式引入引用语义，使所有代码都能保证内存安全——通过跟踪每个值的生命周期，并在合适的时机（仅一次）销毁每个值。这一切在 Mojo 中通过使用参数约定得以实现，这些约定确保任一时刻每个值都只有一个所有者。

参数约定指定参数是可变还是不可变，以及函数是否拥有该值。每个约定由参数声明开头的关键字定义：

- default：函数接收一个**不可变引用**。这意味着函数可以读取原始值（它*不是*副本），但不能修改（mutate）它。

- `mut`：函数接收一个**可变引用**。这意味着函数可以读取并修改原始值（它*不是*副本）。

- `var`：函数取得一个值的**所有权**。这意味着函数对该参数具有独占所有权。调用者可以选择将一个已有值的所有权转移给该函数，但情况并非总是如此。被调用者可能收到一个新建的值，或一个已有值的副本。

- `ref`：函数获得一个具有参数化可变性的引用：也就是说，它跟随被引用值的可变性。
  `ref` 参数属于高级主题，在
  [生命周期、来源与引用](/docs/manual/values/lifetimes/)中有更详细的描述。

- `out`：一种特殊约定，用于
  [初始化器](/docs/manual/lifecycle/life/#constructor)中的 `self` 参数以及
  [命名结果](/docs/manual/functions/#named-results)。`out`
  参数在函数开始时处于未初始化状态，必须在函数返回前被初始化。虽然 `out` 参数出现在参数列表中，但它们从来不会由调用者传入。

- `deinit`：一种特殊约定，用于去初始化器以及消费式移动生命周期方法。`deinit` 参数在函数开始时处于已初始化状态，在函数返回时变为未初始化。

例如，以下函数有一个可变引用参数和一个不可变参数：

```mojo
def add(mut x: Int, y: Int):
    x += y

def main():
    var a = 1
    var b = 2
    add(a, b)
    print(a)  # 3
```

你可能已经见过一些没有声明约定的函数参数。默认情况下，所有参数都使用 default 这一不可变只读引用约定。在接下来的章节中，我们将更详细地介绍每种约定。

## 不可变参数（default）

default 约定是一种不可变的只读引用。被调用者收到对该参数值的一个不可变引用。

例如：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def main():
    var values = [1, 2, 3, 4]
    print_list(values)
```

```output
[1, 2, 3, 4]
```

这里 `print_list()` 函数可以从 `list` 参数中读取，但不能修改它。`list` 是对 `main()` 函数中 `values` 的引用，而不是副本。

一般来说，在处理体积较大或复制代价较高的值时，传递不可变引用的效率要高得多，因为对于 default（不可变引用）参数，不会调用复制初始化器和去初始化器。

### 与 C++ 和 Rust 的比较

Mojo 的 default 参数约定在某些方面类似于 C++ 中以 `const&` 传参，两者都避免了值的复制并禁止被调用者修改。然而，default 约定与 C++ 中的 `const&` 有两点重要区别：

- Mojo 编译器实现了一个生命周期检查器，确保当存在对某个值的未完成引用时，该值不会被销毁。

- 像 `Int`、`Float` 和 `SIMD` 这样的较小值总是在机器寄存器中传递。与 C++ 和 Rust 等语言相比，这带来了显著的性能提升。

Rust 与 Mojo 之间的主要区别在于，Mojo 在调用者一方传入不可变引用时不需要使用 sigil。此外，Mojo 在传递较小值时也更高效，而 Rust 默认采用移动值的方式，而不是以只读引用传递。这些策略和语法决策使 Mojo 能够提供一个更易于使用的编程模型。

## 可变参数（`mut`）

如果你希望函数接收一个**可变引用**，请在参数名前加上 `mut` 关键字。你可以这样理解 `mut`：它表示函数*内部*对该值的任何修改在函数*外部*都是可见的。

例如，这个 `mutate()` 函数会更新原始的 `list` 值：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def mutate(mut l: List[Int]):
    l.append(5)

def main():
    var values = [1, 2, 3, 4]

    mutate(values)
    print_list(values)
```

```output
[1, 2, 3, 4, 5]
```

它的行为相当于以下代码的优化替代版本：

```mojo
def print_list(list: List[Int]):
    print(list.__str__())

def mutate_copy(l: List[Int]) -> List[Int]:
    # def creates an implicit copy of the list because it's mutated
    l.append(5)
    return l

def main():
    var values = [1, 2, 3, 4]

    values = mutate_copy(values)
    print_list(values)
```

```output
[1, 2, 3, 4, 5]
```

虽然使用 `mut` 的代码并没有短多少，但它的内存效率更高，因为它不会复制值。

但要记住，作为 `mut` 传入的值必须本身就是可变的。例如，如果你尝试取出一个不可变引用并以 `mut` 形式传给另一个函数，将得到一个编译错误，因为 Mojo 无法从一个不可变引用构造出可变引用。

:::note

你不能为 `mut` 参数定义[默认值](/docs/manual/functions#optional-arguments)。

:::

### 参数互斥性

Mojo 对可变引用强制实施*参数互斥性（argument exclusivity）*。这意味着如果一个函数接收到一个对某个值的可变引用（例如一个 `mut` 参数），它就不能再接收到对该值的任何其他引用——无论可变还是不可变。也就是说，一个可变引用不能有任何其他*别名（alias）*引用它。

例如，考虑以下代码示例：

```mojo
def append_twice(mut s: String, other: String):
   # Mojo knows 's' and 'other' can't be the same string.
   s += other
   s += other

def invalid_access():
  var my_string = "o"  # Create a run-time String value

  # error: passing `my_string` mut is invalid since it's also passed
  # as an immutable reference
  append_twice(my_string, my_string)
  print(my_string)
```

这段代码令人困惑，因为用户可能期望输出是 `ooo`，但由于第一次追加同时修改了 `s` 和 `other`，实际输出将是 `oooo`。强制实施可变引用的互斥性不仅能避免编码错误，还能让 Mojo 编译器在某些情况下对代码进行优化。

当你确实需要同时拥有可变和不可变引用（或需要把同一个值传给两个参数）时，避免此问题的一种方法是制作一个副本：

```mojo
def valid_access():
  var my_string = "o"           # Create a run-time String value
  var other_string = my_string  # Create a copy of the String value
  append_twice(my_string, other_string)
  print(my_string)
```

注意，对于可按寄存器传递的平凡类型（如 `Int` 和 `Bool`），并不会强制实施参数互斥性，因为它们总是按副本传递。当把同一个值传给两个 `Int` 参数时，被调用者会得到该值的两个副本。

## 转移参数（`var` 和 `^`）

如果你希望函数*取得*一个值的所有权，请在参数名前加上 `var` 关键字。

这一约定通常与在调用点对参数使用后缀 `^` 转移 sigil 结合使用。

当使用一个变量时，转移某个值会使原始变量处于未初始化状态。在转移之后、在你给它赋一个原类型的新值之前，不能使用该变量。

### 使用 `var` 进行转移

`var` 的行为取决于调用者是否使用 `^` 转移 sigil，以及该值是否遵循 `Copyable`。

`var` 关键字并不保证函数收到的就是*原始值*。它只保证函数取得*一个值的所有权*。这通过以下三种方式之一发生：

- **值转移**：调用者使用 `^` 转移 sigil。这会转移该值，使原始变量处于未初始化状态。函数参数取得所有权。

- **复制**：在不使用转移 sigil 的情况下，Mojo 会复制该值。如果该类型不是 `Copyable`，则会产生一个编译时错误。

- **新建值**：调用者传入一个新建的值，例如某次函数调用的结果。在这种情况下，没有任何变量拥有该值，因此所有权直接转移给被调用者。例如：

  ```mojo
  def take(var s: String):
      pass

  def main():
      take("A brand-new String!")
  ```

以下代码通过复制字符串来工作，因为 `take_text()` 使用了 `var` 约定，而调用者没有使用转移 sigil：

```mojo
def take_text(var text: String):
    text += "!"
    print(text)

def main():
    var message = "Hello"  # Create a run-time String value
    take_text(message)
    print(message)
```

```output
Hello!
Hello
```

但是，如果在调用 `take_text()` 时加上 `^` 转移 sigil，编译器会针对 `print(message)` 报错，因为此时 `message` 变量已不再处于已初始化状态。也就是说，以下版本无法编译：

```mojo
def main():
    var message = "Hello"  # Create a run-time String value
    take_text(message^)
    print(message)  # error: use of uninitialized value 'message'
```

这是 Mojo 生命周期检查器的一个关键特性，因为它保证不会有两个变量同时拥有同一个值。要修复此错误，你在用 `^` 转移 sigil 结束 `message` 变量的生命周期之后，就不能再使用 `message` 变量。修正后的代码如下：

```mojo
def take_text(var text: String):
    text += "!"
    print(text)

def main():
    var message = "Hello"  # Create a run-time String value
    take_text(message^)
```

```output
Hello!
```

无论函数以何种方式收到该值，只要函数将参数声明为 `var`，就可以确定它对该值具有独占的可变访问权。由于该值是被拥有的，所以当函数退出时该值会被销毁——除非函数将该值转移到了别处。

例如，在以下示例中，`add_to_list()` 接收一个字符串并将其追加到列表中。该字符串的所有权被转移给列表，因此函数退出时它不会被销毁。而 `consume_string()` 没有将其 `var` 值转移出去，因此该值会在函数结束时被销毁。

```mojo
def add_to_list(var name: String, mut list: List[String]):
    list.append(name^)
    # name is uninitialized, nothing to destroy

def consume_string(var s: String):
    print(s)
    # s is destroyed here
```

### 转移的实现细节

在 Mojo 中，你不应将"所有权转移"与"移动操作"混为一谈——它们并不严格是同一回事。

Mojo 有多种转移值所有权的方式：

- 如果一个类型实现了[移动初始化器](/docs/manual/lifecycle/life#move-constructor)
  `__init__(take=)`，那么*当*该类型的一个值作为 `var` 参数被转移进函数时，*并且*原始变量的生命周期在同一时刻结束（无论是否使用 `^` 转移 sigil），Mojo 可能会调用此方法。

- 在某些情况下，Mojo 会将移动操作完全优化掉，让值留在同一块内存位置上，只更新其所有权。在这些情况下，值的转移不会调用复制或移动初始化器中的任何一个。

要让 `var` 约定在*不*使用转移 sigil 的情况下也能工作，该值类型必须是可复制的（通过 `__init__(out self, *, copy: Self)`）。
