程序离不开数据，所有现代编程语言都将数据存储在两个地方之一：调用栈和堆（有时也在 CPU 寄存器中，但我们这里不涉及）。然而，每种语言读取和写入数据的方式略有不同——有时差异很大。因此，在接下来的章节中，我们将解释 Mojo 如何在程序中管理内存，以及这如何影响你编写 Mojo 代码的方式。

## 栈和堆概述

一般来说，所有现代编程语言都将运行中程序的内存分为四个段：

- 文本段。编译后的程序。
- 数据段。全局数据，已初始化或未初始化。
- 栈段。局部数据，在程序运行期间自动管理。
- 堆段。动态分配的数据，由程序员管理。

文本段和数据段的大小是静态的，但栈和堆的大小会随着程序的运行而变化。

栈存储当前函数的局部数据。当调用一个函数时，程序会分配一块内存——一个栈帧——其大小正好足以存储该函数的数据，包括任何固定大小的局部变量。当调用另一个函数时，会在栈顶推入一个新的栈帧。当函数完成时，其栈帧会从栈中弹出。

注意我们只说"固定大小"的局部值存储在栈中。在运行时可以改变大小动态大小的值则存储在堆中，这是一个允许动态内存分配的更大内存区域。从技术上讲，这样一个值的局部变量仍然存储在调用栈中，但其值是一个指向堆上实际值的固定大小指针。考虑一个 Mojo 字符串：它可以有任何长度，其长度可以在运行时改变。因此，Mojo `String` 结构体包含一些固定大小的字段，以及一个指向动态分配的缓冲区的指针，该缓冲区保存实际的字符串数据。

堆和栈之间的另一个重要区别是栈是自动管理的——推入和弹出栈帧的代码由编译器添加。另一方面，堆内存由程序员显式分配和释放内存来管理。你可以通过使用标准库类型如 `List` 和 `String` 间接地这样做，或者使用 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) API 直接这样做。

需要比函数生命周期更长的值（例如，在函数之间传递且不应被复制的数组）存储在堆中，因为堆内存可以从调用栈的任何地方访问，即使创建它的函数从栈中移除也是如此。这种情况下——堆分配的值被多个函数使用——大多数内存错误发生在这里，这也是不同编程语言之间内存管理策略差异最大的地方。

## 内存管理策略

由于内存是有限的，因此程序应尽可能快地从堆中移除未使用的数据（"释放"内存）。确定何时释放该内存相当复杂。

一些编程语言通过使用"垃圾收集器"进程来隐藏内存管理的复杂性，该进程跟踪所有内存使用情况并定期释放未使用的堆内存（也称为自动内存管理）。这种方法的一个显著好处是它减轻了手动内存管理的负担，通常避免更多错误，并使开发人员更高效。然而，它会产生性能成本，因为垃圾收集器会中断程序的执行，并且可能不会很快回收内存。

其他语言要求你手动释放在堆上分配的数据。当正确完成时，这会使程序执行得更快，因为没有垃圾收集器消耗的处理时间。然而，这种方法的问题是程序员会犯错，特别是当程序的多个部分需要访问同一内存时——很难知道程序的哪一部分"拥有"数据并必须释放它。程序员可能会在程序完成之前意外释放数据（导致"释放后使用"错误），或者可能两次释放它（"双重释放"错误），或者可能永远不会释放它（"内存泄漏"错误）。这样的错误和其他错误可能对程序产生灾难性的后果，这些错误通常很难追踪，因此它们不首先发生尤为重要。

Mojo 使用第三种方法，称为"所有权"，它依赖于程序员在传递值时必须遵循的规则集合。这些规则确保在给定时间只有一个"所有者"拥有某个值。当一个值的生命周期结束时，Mojo 调用其析构函数，该析构函数负责释放任何需要释放的堆内存。

通过这种方式，Mojo 有助于确保内存被释放，但它是确定性的，并且从释放后使用、双重释放和内存泄漏等错误中是安全的。此外，它以非常低的性能开销实现这一点。

Mojo 的值所有权模型提供了编程生产力和强内存安全的优秀平衡。它只要求你学习一些新的语法和关于如何在程序中共享内存访问的几条规则。

但在我们解释 Mojo 值所有权模型的规则和语法之前，你首先需要理解[值语义](/docs/manual/values/value-semantics)。
