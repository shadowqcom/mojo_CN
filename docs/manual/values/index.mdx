程序离不开数据，所有现代编程语言都将数据存储在两个地方之一：调用栈和堆（有时也会存储在 CPU 寄存器中，但此处不展开讨论）。然而，每种语言读取和写入数据的方式略有不同——有时差异很大。因此在以下章节中，我们将解释 Mojo 如何在你的程序中管理内存，以及这如何影响你编写 Mojo 代码的方式。

## 栈和堆概述

一般来说，所有现代编程语言都会将运行中程序的内存划分为四个段：

- 文本段（Text）。编译后的程序。
- 数据段（Data）。全局数据，可以是已初始化或未初始化的。
- 栈段（Stack）。局部数据，在程序运行时自动管理。
- 堆段（Heap）。动态分配的数据，由程序员管理。

文本段和数据段的大小是静态的，但栈和堆的大小会随程序运行而变化。

*栈*存储当前函数局部的数据。当一个函数被调用时，程序会分配一块内存——一个*栈帧（stack frame）*——其大小恰好等于存储该函数数据所需的大小，包括所有*固定大小*的局部变量。当另一个函数被调用时，一个新的栈帧会被推入栈顶。当函数执行完毕时，它的栈帧会从栈中弹出。

注意，我们只说"*固定大小*的局部值"存储在栈中。在运行时大小可变的动态大小值则存储在堆中，堆是一块大得多的内存区域，允许进行动态内存分配。从技术上讲，此类值的局部变量仍然存储在调用栈中，但其值是一个指向堆上实际值的固定大小指针。考虑一个 Mojo 字符串：它可以是任意长度，并且其长度可以在运行时改变。因此 Mojo 的 `String` 结构体包含一些静态大小的字段，以及一个指向动态分配缓冲区的指针，该缓冲区保存实际的字符串数据。

堆和栈之间的另一个重要区别是栈是自动管理的——推入和弹出栈帧的代码由编译器添加。而堆内存则由程序员通过显式分配和释放内存来管理。你可以间接地进行此操作——通过使用 `List` 和 `String` 等标准库类型——也可以直接使用 [`alloc()`](/docs/std/memory/alloc/alloc/) 和 [`Pointer`](/docs/std/memory/pointer/Pointer/) API。

需要比函数生命周期更长的值（例如在函数之间传递且不应被复制的数组）会存储在堆中，因为堆内存可以从调用栈的任何位置访问，即使创建它的函数已从栈中移除也是如此。这种情形——堆分配的值被多个函数使用——是大多数内存错误发生的地方，也是各编程语言之间内存管理策略差异最大的地方。

## 内存管理策略

由于内存是有限的，因此程序应尽快从堆中移除未使用的数据（"释放"内存）。而确定何时释放该内存相当复杂。

一些编程语言试图通过使用"垃圾回收器（garbage collector）"进程来向你隐藏内存管理的复杂性，该进程会跟踪所有内存使用情况并定期释放未使用的堆内存（也称为自动内存管理）。这种方法的一个显著优点是它将开发者从手动内存管理的负担中解放出来，通常能避免更多错误并提高开发者的生产力。然而，它会带来性能开销，因为垃圾回收器会中断程序执行，并且可能不会很快回收内存。

其他语言则要求你手动释放在堆上分配的数据。如果处理得当，这能让程序执行得很快，因为没有垃圾回收器消耗处理时间。然而，这种方法的挑战在于程序员会犯错，尤其是当程序的多个部分需要访问同一块内存时——很难判断程序的哪一部分"拥有"该数据并必须释放它。程序员可能在程序尚未使用完数据时就意外释放了它（导致"释放后使用（use-after-free）"错误），或者可能释放两次（"双重释放（double free）"错误），又或者永远不释放（"内存泄漏（leaked memory）"错误）。诸如此类的错误可能给程序带来灾难性后果，并且这些缺陷通常难以排查，因此从一开始就避免它们出现尤为重要。

Mojo 采用第三种称为"所有权（ownership）"的方法，它依赖于程序员在传递值时必须遵循的一组规则。这些规则确保在任一时刻某个值都只有一个"所有者"。当一个值的生命周期结束时，Mojo 会调用其去初始化器（deinitializer），它负责释放所有需要释放的堆内存。

通过这种方式，Mojo 有助于确保内存被释放，并且是确定性且无错的，能避免诸如释放后使用、双重释放和内存泄漏之类的错误。此外，它实现这一切所需的性能开销非常低。

Mojo 的值所有权模型在编程生产力与强内存安全之间提供了出色的平衡。它只要求你学习一些新语法以及关于如何在程序中共享内存访问的若干规则。

但在我们介绍 Mojo 值所有权模型的规则和语法之前，你首先需要了解[值语义](/docs/manual/values/value-semantics)。
