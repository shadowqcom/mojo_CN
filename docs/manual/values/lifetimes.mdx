Mojo 编译器包含一个生命周期检查器，这是一个分析程序数据流的编译器传递。它确定变量何时有效，并在变量生命周期结束时插入析构函数调用。

Mojo 编译器使用一个称为*来源*的特殊值来跟踪变量和引用的有效性。

具体来说，来源回答两个问题：

- 哪个变量"拥有"这个值？
- 可以使用此引用修改该值吗？

例如，考虑以下代码：

```mojo
def print_str(s: String):
    print(s)

def main():
    name: String = "Joan"
    print_str(name)
```

```output
Joan
```

`name = "Joan"` 这一行声明了一个具有标识符（`name`）和 `String` 值的逻辑存储空间的变量。当你将 `name` 传递给 `print_str()` 函数时，函数获得该值的不可变引用。因此，`name` 和 `s` 都指向同一个逻辑存储空间，并且具有关联的来源值，这使得 Mojo 编译器能够对它们进行推理。

来源跟踪和生命周期检查在编译时完成，因此来源不会跟踪为 `name` 变量分配的实际存储空间。相反，来源符号地跟踪变量，因此编译器跟踪 `print_str()` 是在调用者的作用域中用由 `name` 拥有的值调用的。通过跟踪所有权的数据如何在程序中流动，编译器可以识别值的生命周期。

大多数情况下，来源由编译器自动处理。然而，在某些情况下，你需要直接与来源交互：

- 当处理引用时——特别是 `ref` 参数和 `ref` 返回值。

- 当处理像 [`Pointer`](/docs/std/memory/pointer/Pointer/) 或 [`Span`](/docs/std/memory/span/Span/) 这样的类型时，它们的数据引用的来源是参数化的。

本节还涵盖 [`ref` 参数](#ref-arguments)和[`ref` 返回值](#ref-return-values)，它们允许函数作为具有参数化来源的引用接收参数并提供返回值。

## 使用来源

Mojo 的来源值主要由编译器创建，因此你不能直接创建自己的来源值——你通常需要从现有值派生一个来源。

此外，Mojo 使用来源来延长被引用值的生命周期，以便值不会过早被销毁。

### 来源类型

Mojo 提供了一个结构体和一组类型别名（`comptime` 值），你可以用来指定来源类型。顾名思义，`ImmutOrigin` 和 `MutOrigin` `comptime` 值分别表示不可变和可变来源：

```mojo
struct ImmutRef[origin: ImmutOrigin]:
    pass
```

或者你可以使用 [`Origin`](/docs/std/builtin/type_aliases/Origin/) 结构体来指定具有参数化可变性的来源：

```mojo
struct ParametricRef[
    is_mutable: Bool,
    //,
    origin: Origin[mut=is_mutable]
]:
    pass
```

来源类型将引用的可变性作为布尔参数值携带，指示来源是可变的、不可变的，还是根据封装 API 指定的参数具有可变性。

这里的 `is_mutable` 参数是一个[仅推断参数](/docs/manual/parameters/#infer-only-parameters)。`origin` 值通常也被推断。例如，以下代码创建一个到现有值的 [`Pointer`](/docs/std/memory/pointer/Pointer/)，但不需要指定来源——`origin` 从现有值中推断。

```mojo
from std.memory import Pointer

def use_pointer():
    a = 10
    ptr = Pointer(to=a)
```

### 来源集

`OriginSet` 不是一种来源类型，它代表一组来源。来源集用于跟踪在闭包中捕获的值的生命周期。

### 来源值

大多数来源值由编译器创建。作为开发人员，有几种指定来源值的方法：

- 静态来源。`StaticConstantOrigin` `comptime` 值表示持续整个程序持续时间的不可变值。字符串字面量值具有 `StaticConstantOrigin`。

- 派生来源。`origin_of()` 魔法函数返回与传递的值（或值）关联的来源。

- 推断来源。你可以使用推断参数来捕获传递给函数的值的来源。

- 外部来源。外部来源 `MutExternalOrigin` 和 `ImmutExternalOrigin` 表示不被生命周期检查器跟踪的值，例如动态分配的内存。

- 通配符来源。`ImmutAnyOrigin` 和 `MutAnyOrigin` `comptime` 值是特殊情况，表示可能访问任何活动值的引用。

#### 静态来源

当你有一个在整个程序持续时间内存在的值时，可以使用静态来源 `StaticConstantOrigin`。

例如，`StringLiteral` 方法 [`as_string_slice()`](/docs/std/builtin/string_literal/StringLiteral/#as_string_slice) 返回一个指向原始字符串字面量的 [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)。字符串字面量是静态的——它们在编译时分配并且从不被销毁——因此切片是用不可变的静态来源创建的。

#### 派生来源

使用 `origin_of(value)` 运算符获取值的来源。`origin_of()` 的参数可以采用生成以下之一的任意表达式：

- 一个来源值。

- 一个具有内存位置的值。

例如：

```mojo
origin_of(self)
origin_of(x.y)
origin_of(foo())
```

`origin_of()` 运算符在编译时静态分析；传递给 `origin_of()` 的表达式永远不会被求值。（例如，当编译器分析 `origin_of(foo())` 时，它不会运行 `foo()` 函数。）

以下结构体使用 [`OwnedPointer`](/docs/std/memory/owned_pointer/OwnedPointer/) 存储字符串值——一个持有拥有值的智能指针。`as_ptr()` 方法返回一个 `Pointer` 到存储的字符串，使用与原始 `OwnedPointer` 相同的来源。

```mojo
from std.memory import OwnedPointer, Pointer

struct BoxedString:
    var o_ptr: OwnedPointer[String]

    def __init__(out self, value: String):
        self.o_ptr = OwnedPointer(value)

    def as_ptr(mut self) -> Pointer[String, origin_of(self.o_ptr)]:
        return Pointer(to=self.o_ptr[])
```

请注意，`as_ptr()` 方法将 `self` 参数作为 `mut self`。如果它使用默认的 `read` 参数约定，它将是不可变的，并且派生来源（`origin_of(self.o_ptr)`）也将是不可变的。

你也可以将多个表达式传递给 `origin_of()` 以表达两个或更多来源的并集：

`origin_of(a, b)`

#### 来源并集

两个或更多来源的并集创建一个新的来源，为了生命周期扩展的目的，它引用所有原始来源（因此 `a` 和 `b` 的来源的并集扩展两个生命周期）。

来源并集是可变的，当且仅当其所有组成部分来源都是可变的。有关示例，请参阅[具有并集来源的返回值](#return-values-with-union-origins)。

#### 推断来源

由于来源是参数，编译器可以从传递给函数或方法的参数中*推断*一个来源值，如[参数推断](/docs/manual/parameters/#parameter-inference)中所述。这允许函数返回一个与传递给它的参数具有相同来源的值。

有关使用推断来源的示例，请参阅[`ref` 参数](#ref-arguments)部分。

#### 外部来源

外部来源 `MutExternalOrigin` 和 `ImmutExternalOrigin` 表示不与任何现有值别名的值。也就是说，它们指向不由任何其他变量拥有的内存，因此不被生命周期检查器跟踪。例如，[`alloc()`](/docs/std/memory/unsafe_pointer/alloc/) 函数返回一个到新动态分配内存块的 `UnsafePointer`，来源为 `MutExternalOrigin`。该来源指示该内存不由 Mojo 所有权系统管理。当你使用像这样的不安全 API 时，你有责任自己管理生命周期：例如，分配内存的结构体通常应该在析构函数中释放该内存。

#### 通配符来源

通配符来源 `ImmutAnyOrigin` 和 `MutAnyOrigin` 是特殊情况，表示可能访问任何活动值的引用。这些以前广泛用于不安全指针。使用具有通配符来源的指针有效地禁用了该作用域内任何值的 Mojo 即时销毁，只要指针是活动的。因此，不鼓励使用通配符来源，应作为最后手段使用。

## 使用引用

你可以使用 `ref` 关键字与参数和返回值一起使用，以指定具有参数化可变性的引用。也就是说，它们可以是可变的或不可变的。

在被调用函数内部，`ref` 参数看起来像 `read` 或 `mut` 参数。

`ref` 返回值看起来像调用函数的任何其他返回值，但它是对现有值的*引用*，而不是副本。

### `ref` 参数

`ref` 参数约定允许你指定具有参数化可变性的参数：也就是说，你不需要预先知道传递的参数将是可变的还是不可变的。你可能想使用 `ref` 参数有几个原因：

- 你想接受具有参数化可变性的参数。

- 你想将一个参数的生命周期绑定到另一个参数的生命周期。

- 当你需要一个保证在内存中传递的参数时：这对于需要身份的泛型参数可能很重要，无论具体类型是否可传递到寄存器。

`ref` 参数的语法是：

<code><strong>ref</strong> <var>arg_name</var>: <var>arg_type</var></code>

或者：

<code><strong>ref[</strong><var>origin_specifier(s)</var><strong>] </strong>
<var>arg_name</var>: <var>arg_type</var></code>

在第一种形式中，`ref` 参数的来源和可变性从传递的值中推断。第二种形式包含一个来源子句，由方括号内的一个或多个来源说明符组成。来源说明符可以是：

- 一个来源值。

- 一个任意表达式，它被视为 `origin_of(expression)` 的简写。换句话说，以下声明是等效的：

  ```mojo
  ref[origin_of(self)]
  ref[self]
  ```

- 一个 [`AddressSpace`](/docs/std/memory/pointer/AddressSpace/) 值。

- 下划线字符（`_`）表示来源是*未绑定的*。这等同于省略来源说明符。

  ```mojo
  def add_ref(ref a: Int, b: Int) -> Int:
    return a+b
  ```

你也可以显式命名来源。如果你想将参数限制为 `ImmutOrigin` 或 `MutOrigin`，或者如果你想将函数的返回值绑定到参数的来源，这很有用。

例如，`Span` 类型是连续数据（如字符串的子字符串或列表的子集）的非拥有视图。因为它指向它不拥有的数据，所以它在其指向的数据的来源值上进行参数化，该来源值代表数据的生命周期和所有权。

在以下示例中，`to_byte_span()` 函数接收一个 `List[Byte]` 并返回一个与列表具有相同来源的 `Span[Byte]`：

```mojo
from std.collections import List
from std.memory import Span

def to_byte_span[
    is_mutable: Bool,
    //,
    origin: Origin[mut=is_mutable],
](ref[origin] list: List[Byte]) -> Span[Byte, origin]:
    return Span(list)

def main():
    list: List[Byte] = [77, 111, 106, 111]
    _ = to_byte_span(list)
```

在这个例子中，`origin` 参数从 `list` 参数推断，然后用作返回的 `Span` 的来源。

由于 `Span` 采用 `list` 参数的来源，Mojo 编译器可以将 span 的数据识别为由列表拥有。span 将具有与列表相同的生命周期，并且如果列表是可变的，则 span 将是可变的。

### `ref` 返回值

与 `ref` 参数一样，`ref` 返回值允许函数返回一个可变或不可变引用。`ref` 返回值的语法是：

<code><strong>-> ref[</strong><var>origin_specifier(s)</var><strong>] </strong>
 <var>arg_type</var></code>

请注意，你必须为 `ref` 返回值提供来源说明符。来源说明符允许的值与[`ref` 参数](#ref-arguments)列出的值相同。

`ref` 返回值可以是处理更新集合中项的高效方法。执行此操作的标准方法是实现 `__getitem__()` 和 `__setitem__()` dunder 方法。这些方法被调用以从集合中的下标项读取和写入：

```mojo
value = list[a]
list[b] += 10
```

使用 `ref` 参数，`__getitem__()` 可以返回一个可被直接修改的可变引用。这与使用 `__setitem__()` 方法相比有优点和缺点：

- 可变引用更高效——单个更新不会在两个方法之间拆分。然而，被引用的值必须在内存中。

- `__getitem__()`/`__setitem__()` 对允许在检索和设置值时运行任意代码。例如，`__setitem__()` 可以验证或约束输入值。

例如，在以下示例中，`NameList` 有一个返回引用的 `__getitem__()` 方法：

```mojo
struct NameList:
    var names: List[String]

    def __init__(out self, *names: String):
        self.names = []
        for name in names:
            self.names.append(name)

    def __getitem__(ref self, index: Int) raises -> ref[self.names] String:
        if (index >=0 and index < len(self.names)):
            return self.names[index]
        else:
            raise Error("index out of bounds")

def main() raises:
    list = NameList("Thor", "Athena", "Dana", "Vrinda")
    ref name = list[2]
    print(name)
    name += "?"
    print(list[2])
```

```output
Dana
Dana?
```

请注意使用 `ref name` 语法来创建引用绑定。

如果你将 `ref` 返回值赋给一个变量，该变量接收被引用项的*副本*。如果你需要捕获引用以备将来使用，请使用[引用绑定](/docs/manual/variables/#reference-bindings)：

```mojo
var name_copy = list[2]  # list[2] 的拥有副本
ref name_ref = list[2]  # list[2] 的引用
```

#### 返回值的参数化可变性

`ref` 返回参数的另一个优点是支持参数化可变性的能力。例如，回想上面 `__getitem__()` 方法的签名：

```mojo
def __getitem__(ref self, index: Int) raises -> ref[self] String:
```

由于返回值的 `origin` 与 `self` 的 `origin` 绑定，如果使用可变引用调用该方法，返回的引用将是可变的。如果你有 `NameList` 的不可变引用，该方法仍然有效，但它返回一个不可变引用：

```mojo
def pass_immutable_list(list: NameList) raises:
    print(list[2])
    # list[2] += "?" # 错误，此列表是不可变的

def main() raises:
    list = NameList("Sophie", "Jack", "Diana")
    pass_immutable_list(list)
```

```output
Diana
```

没有参数化可变性，你需要编写两个版本的 `__getitem__()`，一个接受不可变的 `self`，另一个接受可变的 `self`。

#### 具有并集来源的返回值

`ref` 返回值可以在其来源说明符中包含多个值，这产生来源的并集。例如，以下 `pick_one()` 函数返回两个输入字符串之一的引用，其来源是两个来源的并集。

```mojo
def pick_one(cond: Bool, ref a: String, ref b: String) -> ref[a, b] String:
    return a if cond else b
```

由于编译器无法静态确定将选择哪个分支，此函数必须使用并集来源 `[a, b]`。这确保编译器在返回引用活动时扩展*两个*值的生命周期。

如果**两个** `a` 和 `b` 都是可变的，则返回的引用是可变的。
