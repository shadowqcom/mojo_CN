GPU 对于高性能计算至关重要，但长期以来，GPU 编程一直是一项高度专业化的技能。Mojo 提供了一个重新思考 GPU 编程并使其更易上手的机会。但如果你从未编写过 GPU 程序，首先需要了解 GPU 硬件和执行模型与 CPU 有何不同。这正是本页面的主题——这里没有代码，所以如果你已经了解 GPU 硬件，可以直接跳到[入门教程](/docs/manual/gpu/intro-tutorial/)或 [GPU 编程基础](/docs/manual/gpu/fundamentals)。

## GPU 架构概述

图形处理器（GPU）和中央处理器（CPU）代表了两种根本不同的计算方式。CPU 拥有少量强大的核心，针对顺序处理和复杂决策进行了优化；而 GPU 则包含数千个更小、更简单的核心，专为并行处理而设计。这些简单的核心缺乏分支预测或深度指令流水线等复杂特性，但擅长同时对大型数据集执行相同的操作。

现代系统充分利用 CPU 和 GPU 处理器各自的优势：CPU 负责处理主程序流程和复杂逻辑，同时通过专用 API 将并行计算卸载到 GPU。图 1 展示了两者之间的一些架构差异，我们将在下面进一步讨论。

GPU 的基本构建块在 NVIDIA GPU 上称为*流式多处理器*（SM），在 AMD GPU 上称为*计算单元*（CU）（它们本质上是相同的概念，我们将统称为 SM）。SM 位于高层 GPU 控制逻辑和各个执行单元之间，充当可以独立且并行运行的自包含处理工厂。

:::note

AMD 和 NVIDIA 使用不同的术语来描述其 GPU 硬件和编程模型。为简单起见，我们在 Mojo 手册中通常使用 NVIDIA 术语，因为它在业界使用更为广泛。

:::

多个 SM 排列在单个 GPU 芯片上，每个 SM 能够同时处理多个工作负载。GPU 的全局调度器将工作分配给各个 SM，而内存控制器则管理 SM 与各种内存层次（全局内存、L2 缓存等）之间的数据流。

GPU 中 SM 的数量因型号和预期用途而有很大差异，从入门级 GPU 中的少量 SM 到高端专业卡中的数十甚至数百个 SM。这种可扩展架构使 GPU 能够在不同大小和类型的工作负载中保持出色的性能。

每个 SM 包含几个关键组件：

- **CUDA 核心（NVIDIA）/流处理器（AMD）：** 这些是执行整数和浮点计算的基本算术逻辑单元（ALU）。单个 SM 可以包含数十或数百个这样的核心。
- **Tensor 核心（NVIDIA）/矩阵核心（AMD）：** 专为矩阵乘法和卷积运算优化的专用单元。
- **特殊函数单元（SFU）：** 处理三角函数、平方根和指数函数等复杂数学运算。
- **寄存器文件：** 保存中间结果和线程特定数据的超高速存储。现代 SM 可以拥有数百 KB 的寄存器空间，在活跃线程之间共享。
- **共享内存/L1 缓存：** 一种可编程的低延迟内存空间，支持线程之间的数据共享。此内存通常可在共享内存和 L1 缓存功能之间进行配置。
- **加载/存储单元：** 管理不同内存空间之间的数据移动，处理来自线程的内存访问请求。

## GPU 执行模型

GPU *内核*（kernel）只是一个在 GPU 上运行的函数，在数千或数百万个*线程*（在 AMD GPU 上也称为*工作项*）上并行执行对大型数据集的特定计算。你可能已经在 CPU 编程中熟悉了线程的概念，但 GPU 线程是不同的。在 CPU 上，线程由操作系统管理，可以执行完全独立的任务，例如管理用户界面、从数据库获取数据等。但在 GPU 上，线程由 GPU 自身管理。对于给定的内核函数，GPU 上的所有线程都执行相同的函数，但每个线程处理数据的不同部分。

*网格*（grid）是在 GPU 上执行内核函数的线程的顶层组织结构。网格由多个*线程块*（在 AMD GPU 上称为*工作组*）组成，线程块进一步划分为并发执行内核函数的各个线程。

将网格划分为线程块有多种目的：

- 它将由网格管理的整体工作负载分解为更小、更易于管理的部分，这些部分可以独立处理。这种划分实现了更好的资源利用率和跨 GPU 中多个 SM 的调度灵活性。
- 线程块为线程通过共享内存和同步原语进行协作提供了作用域，从而实现高效的并行算法和数据共享模式。
- 线程块有助于可扩展性，允许同一程序在不同 GPU 架构上高效运行，因为硬件可以根据可用资源自动分配线程块。

你必须指定网格中线程块的数量以及它们在一维、二维或三维上的排列方式。通常，你需要根据要处理的数据维度来确定网格的维度。例如，处理大型向量时可能选择一维网格，处理矩阵时选择二维网格，处理视频帧时选择三维网格。GPU 为网格中的每个线程块分配一个唯一的*块索引*，用于确定其在网格中的位置。

同样，你还必须指定每个线程块中的线程数量以及它们在一维、二维或三维上的排列方式。GPU 也为块中的每个线程分配一个唯一的*线程索引*，用于确定其在块中的位置。块索引和线程索引的组合唯一标识了线程在整个网格中的位置。

当 GPU 将线程块分配给某个 SM 执行时，SM 将线程块划分为称为*线程束*（warp，在 AMD GPU 上称为*波前* wavefront）的线程子集。线程束的大小取决于 GPU 架构，但目前大多数现代 GPU 使用的线程束大小为 32 或 64 个线程。

如果线程块包含的线程数不能被线程束大小整除，SM 会创建一个部分填充的最后一个线程束，该线程束仍然消耗完整线程束的资源。例如，如果一个线程块有 100 个线程，线程束大小为 32，则 SM 创建：

- 3 个完整的线程束，每个 32 个线程（共 96 个线程）。
- 1 个部分线程束，只有 4 个活跃线程，但仍然占用完整线程束的资源（32 个线程槽位）。

SM 会有效地禁用部分线程束中未使用的线程槽位，但这些槽位仍然消耗硬件资源。因此，你通常应该将线程块大小设置为线程束大小的倍数，以优化资源使用。

线程束中的每个线程同时在不同数据上执行相同的指令，遵循*单指令多线程*（SIMT）执行模型。如果线程束内的线程采取不同的执行路径（称为*线程束分化*），线程束将串行执行所采取的每个分支路径，同时禁用不在该路径上的线程。这意味着当线程束中的所有线程遵循相同的执行路径时，可以实现最佳性能。

一个 SM 可以同时主动管理来自不同线程块的多个线程束，有助于保持执行单元忙碌。例如，如果当前线程束的线程必须等待内存访问，线程束调度器可以快速切换到另一个就绪的线程束。

线程束带来了几个关键的性能优势：

- 硬件只需要管理线程束而不是单个线程，减少了调度开销。
- 线程束中的线程可以通过内存合并高效访问连续的内存位置。
- 硬件自动同步线程束内的线程，无需显式同步。
- 线程束调度器可以通过在线程束之间切换来隐藏内存延迟，最大化计算资源利用率。
