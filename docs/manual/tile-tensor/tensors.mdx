[`TileTensor`](/docs/layout/tile_tensor/TileTensor/) 提供了对存储在线性数组中的多维数据的视图。`TileTensor` 将多维数据的逻辑组织与它在内存中的实际排列方式抽象开来。你可以生成相同数据的新张量"视图"，而无需复制底层数据。这为编写高性能计算算法提供了关键模式，例如：

- 从现有张量中提取瓦片（子张量）。这在 GPU 上尤其有价值，允许线程块将一个瓦片加载到共享内存中，以实现更快的访问和更高效的缓存。
- 对张量进行向量化——将它们重组为多元素向量，以实现更高效的内存加载和存储。
- 将张量划分为线程本地片段，以便在线程块中分配工作。

`TileTensor` 对于编写 GPU 内核特别有价值，其许多 API 是 GPU 专用的。不过，`TileTensor` 也可用于基于 CPU 的算法。

`TileTensor` 由三个主要属性组成：

- 一个[布局](/docs/manual/tile-tensor/layouts/)，定义元素在内存中的排列方式。
- 一个 [`DType`](/docs/std/builtin/dtype/DType/)，定义张量中存储的数据类型。
- 一个指向数据存储内存的指针。

图 1 展示了一个二维列主序布局及对应的线性存储数组。布局内显示的值是存储中的偏移量：因此坐标 (0, 1) 对应存储中的偏移量 2。

由于 `TileTensor` 是一个视图，基于现有张量创建新张量不需要复制底层数据。因此你可以轻松创建一个新视图，表示一个瓦片（子张量），或以不同的顺序访问元素。这些视图都访问相同的数据，因此在某个视图中更改存储的数据会改变所有视图看到的数据。

张量中的每个元素可以是单个（标量）值或 SIMD 向量值。这由张量上的 `element_size` 参数决定。有关更多信息，请参阅[张量向量化](#vectorizing-tensors)。

:::note[TileTensor 和 LayoutTensor]

`TileTensor` 本质上是 [`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/) 的新版本。`TileTensor` 内存效率更高，并且更容易混合使用编译时和运行时维度。然而，`LayoutTensor` 上支持的一些操作尚未在 `TileTensor` 上支持。对于这些操作，你可以使用 [`to_layout_tensor()`](/docs/layout/tile_tensor/TileTensor/#to_layout_tensor) 轻松地从 `TileTensor` 创建 `LayoutTensor`。此方法目前仅支持扁平（非嵌套）布局。

:::

## 访问张量元素

你可以像访问多维数组一样寻址瓦片张量来访问元素：

```mojo
element = tensor2d[x, y]
tensor2d[x, y] = z
```

传递给下标运算符的索引数量必须与张量所需的坐标数量匹配，这也称为张量的*扁平秩*（flat rank）。对于简单布局，这与布局的*秩*相同：二维张量为 2，三维张量为 3，以此类推。对于简单坐标，你可以传递一组单独的坐标，如上所示。对于嵌套坐标，你可以将坐标作为单个 [`Coord`](/docs/layout/coord/Coord/) 值传递。使用嵌套坐标的示例，请参阅[张量索引与嵌套布局](#tensor-indexing-and-nested-layouts)部分。

当你访问张量元素时，解析器需要能够确定你使用了正确数量的坐标。你可以使用编译时断言或约束来保证使用了正确数量的坐标。

```mojo
# 索引二维张量需要两个索引
def takes_2d(tensor2d: TileTensor[...]):
    comptime assert tensor2d.flat_rank == 2
    el0 = tensor2d[0, 0]  # 正常工作
    # el0 = tensor2d[x]  # 编译时错误

# 或者
def takes_2d_constrained(tensor2d: TileTensor[...] where tensor2d.flat_rank == 2):
    el0 = tensor2d[0, 0]
```

有关使用 `where` 子句和 `comptime` 断言的信息，请参阅[编译时约束](/docs/manual/metaprogramming/constraints/)部分。

对于更复杂的"嵌套"布局（如瓦片布局），扁平秩与张量的秩**不**匹配。有关详细信息，请参阅[张量索引与嵌套布局](#tensor-indexing-and-nested-layouts)。

### 标量元素与向量元素

默认情况下，`TileTensor` 的每个元素是单个（标量）值。但张量也可以被*向量化*，使得张量的每个逻辑元素存储一组值。向量化张量可以实现更高效的数据加载和存储代码路径。

`__getitem__()` 方法返回一个 SIMD 向量，向量大小等于张量的 `element_size`（默认为 1）。只要 `element_size` 在调用处已知为 1，你就可以将返回值视为标量值。例如，以下函数接受一个 `element_size=1` 的 `TileTensor`，因此你可以将元素值直接转换为 `Int`。

```mojo
def takes_scalar_tensor(tensor: TileTensor[DType.int32, element_size=1, ...]) -> Int:
    comptime assert tensor.flat_rank == 2
    return Int(tensor[1, 1])
```

你还可以使用 [`load()`](/docs/layout/tile_tensor/TileTensor/#load) 和 [`store()`](/docs/layout/tile_tensor/TileTensor/#store) 方法访问元素，这些方法允许你显式指定向量大小：

```mojo
var elements = tensor.load[4]((Idx(row), Idx(col)))
elements = elements * 2
tensor.store((Idx(row), Idx(col)), elements)
```

`load()` 和 `store()` 方法将索引作为 `Coord` 对象接收。

### 张量索引与嵌套布局

张量的布局可能具有嵌套模式（或子布局），如 [TileTensor 布局](/docs/manual/tile-tensor/layouts/#modes)中所述。这些布局将一个或多个维度划分为子布局。例如，图 2 展示了一个具有嵌套布局的张量：

<figure>

![](../images/layout/tensors/layout-tensor-indexing-nested.png#light)
![](../images/layout/tensors/layout-tensor-indexing-nested-dark.png#dark)

<figcaption><b>图 2.</b> 具有嵌套布局的张量</figcaption>

</figure>

图 2 中的张量具有二维布局，但它不是在每个轴上使用单个坐标进行寻址，而是在每个轴上使用一对坐标。例如，坐标 `((1, 0), (0, 1))` 映射到偏移量 6。

要访问嵌套张量中的值，你可以将嵌套坐标作为 `Coord` 结构体传递：

```mojo
var el1 = tensor[Coord(Coord(Idx(1), Idx(0)), Coord(Idx(0), Idx(1)))]
```

你还可以传递坐标的扁平版本，可以是单个 `Coord` 值，也可以通过传递单独的索引：

```mojo
var el2 = tensor[1, 0, 0, 1]
```

传递给下标运算符的索引数量必须与张量的*扁平秩*匹配。图 2 中的张量扁平秩为 4，因此需要四个坐标。

你可以将嵌套或扁平的 `Coord` 值与 `load()` 和 `store()` 方法一起使用。

## 创建 TileTensor

根据张量数据所在的位置，有几种创建 `TileTensor` 的方式：

- 在 CPU 上。
- 在 GPU 全局内存中。
- 在 GPU 共享内存或本地内存中。

除了从头创建张量的方法外，`TileTensor` 还提供了许多方法来生成现有张量的新视图。

:::note[无边界检查]

`TileTensor` 构造函数不进行任何边界检查来验证分配的内存是否足以容纳布局中指定的所有元素。用户需要确保分配了足够的空间。

:::

### 在 CPU 上创建 `TileTensor`

虽然 `TileTensor` 经常在 GPU 上使用，但你也可以使用它在 CPU 上创建张量。

要在 CPU 上创建 `TileTensor`，你需要一个 [`Layout`](/docs/layout/tile_layout/Layout/) 和一块用于存储张量数据的内存。为 `TileTensor` 分配内存的常见方式是使用 [`InlineArray`](/docs/std/collections/inline_array/InlineArray/) 或 `List`：

```mojo
comptime rows = 8
comptime columns = 16
comptime layout = row_major[rows, columns]()
var storage = InlineArray[Float32, rows * columns](fill=0.0)
var tensor = TileTensor(storage, layout)
```

`InlineArray` 是静态大小的栈分配数组，因此它是为小型张量分配存储的快速高效方式。不过，以这种方式分配的内存大小存在依赖于目标平台的限制。此示例和以下示例将张量内存初始化为零。

你还可以使用 [`List`](/docs/std/collections/list/List/) 创建 `TileTensor`。列表是动态大小的堆分配数组，因此更适合大型张量。

```mojo
comptime rows = 1024
comptime columns = 1024
comptime buf_size = rows * columns
comptime layout = row_major[rows, columns]()
var storage = List[Float32](length=buf_size, fill=0.0)
var tensor = TileTensor(storage, layout)
```

:::note

这两个示例都使用了一个接受 [`Span`](/docs/std/memory/span/Span/) 的 `TileTensor` 构造函数，`Span` 是一种表示由其他地方拥有的连续内存块的类型。Mojo 可以将 `List` 或 `InlineArray` 隐式转换为表示底层内存的 `Span`。Span 跟踪内存块的大小、数据类型和所有权，提供了一种安全引用内存的方式。

:::

### 在 GPU 上创建 `TileTensor`

在 GPU 上创建 `TileTensor` 时，你需要考虑张量数据将存储在哪个内存空间中：

- 全局内存。GPU 最大（也是最慢的）内存空间，全局内存是在 GPU 之间传入和传出数据的主要方式。
- 共享内存或本地内存。共享内存是由一组线程共享的快速片上内存。本地内存特定于单个线程。

#### 在全局内存中创建 `TileTensor`

你必须从主机端分配全局内存，通过分配一个 [`DeviceBuffer`](/docs/std/gpu/host/device_context/DeviceBuffer/)。

在 CPU 上，你可以使用 `DeviceBuffer` 作为存储来构造 `TileTensor`。虽然你可以在 CPU 上创建此张量并将其传入内核函数，但你不能在 CPU 上直接修改其值，因为内存位于 GPU 上。

在这两种情况下，如果你想从 CPU 初始化张量数据，可以在调用内核之前对缓冲区调用 [`enqueue_copy()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_copy) 或 [`enqueue_memset()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_memset)。以下示例展示了从 CPU 初始化 `TileTensor` 并将其传递给 GPU 内核。

```mojo
from std.gpu import global_idx
from std.gpu.host import DeviceContext
from layout import TileTensor, stack_allocation
from layout.tile_layout import row_major

def initialize_tensor_from_cpu_example() raises:
    comptime dtype = DType.float32
    comptime rows = 32
    comptime cols = 8
    comptime block_size = 8
    comptime row_blocks = rows // block_size
    comptime col_blocks = cols // block_size
    comptime input_layout = row_major[rows, cols]()
    comptime size: Int = rows * cols

    def kernel(tensor: TileTensor[dtype, type_of(input_layout), MutAnyOrigin]):
        if global_idx.y < Int(tensor.dim[0]()) and global_idx.x < Int (
            tensor.dim[1]()
        ):
            tensor[global_idx.y, global_idx.x] = (
                tensor[global_idx.y, global_idx.x] + 1
            )

    var ctx = DeviceContext()
    var host_buf = ctx.enqueue_create_host_buffer[dtype](size)
    var dev_buf = ctx.enqueue_create_buffer[dtype](size)
    ctx.synchronize()

    var expected_values = List[Scalar[dtype]](length=size, fill=0)

    for i in range(size):
        host_buf[i] = Scalar[dtype](i)
        expected_values[i] = Scalar[dtype](i + 1)
    ctx.enqueue_copy(dev_buf, host_buf)
    var tensor = TileTensor(dev_buf, input_layout)

    ctx.enqueue_function[kernel](
        tensor,
        grid_dim=(col_blocks, row_blocks),
        block_dim=(block_size, block_size),
    )
    ctx.enqueue_copy(host_buf, dev_buf)
    ctx.synchronize()

    for i in range(rows * cols):
        if host_buf[i] != expected_values[i]:
            raise Error(
                String("位置 {} 处出错，预期 {} 得到 {}").format(
                    i, expected_values[i], host_buf[i]
                )
            )
```

#### 在共享内存或本地内存中创建 `TileTensor`

要在 GPU 的共享内存或本地内存中创建张量，请使用 `tile_tensor` 模块中的 [`stack_allocation()`](/docs/layout/tile_tensor/stack_allocation/) 函数在相应的内存空间中分配存储。

共享内存和本地内存都是非常有限的资源，因此一种常见的模式是将较大张量的一个小瓦片复制到共享内存或本地内存中，以减少内存访问时间。

```mojo
comptime tile_layout = row_major[block_size, block_size]()
var shared_tile = stack_allocation[
    dtype, address_space=AddressSpace.SHARED
](tile_layout)
```

对于共享内存，线程块中的所有线程看到相同的分配。对于本地内存或寄存器内存，每个线程获得一个单独的分配。

在本地内存中分配张量通常是将值存储在寄存器中的一种间接方式。没有办法显式分配寄存器。然而，编译器可以将一些本地内存分配提升为寄存器。要启用此优化，请保持张量的大小较小，并保持对张量的所有索引为静态的——例如，使用 `comptime for` 循环。

:::note

`stack_allocation()` 这个名称有些误导。它是一个*静态*分配，意味着分配在编译时处理。这种分配类似于 C/C++ 的栈分配，其生命周期在分配它的函数返回时结束。此 API 可能会在不久的将来发生变化。

:::

## 张量分块

使用瓦片张量的一个基本模式是将张量划分为更小的瓦片，以实现更简单的寻址、更好的数据局部性和缓存效率。在 GPU 内核中，你可能希望选择与线程块大小对应的瓦片。例如，给定一个 16x16 线程的二维线程块，你可以使用 16x16 的瓦片（每个线程处理瓦片中的一个元素）或 64x16 的瓦片（每个线程处理张量中的 4 个元素）。

瓦片最常见的是一维或二维的。对于逐元素计算（给定张量元素的输出值仅取决于一个输入值），一维瓦片容易理解。对于涉及相邻元素的计算，二维瓦片可以帮助保持数据局部性。例如，矩阵乘法或二维卷积操作通常使用二维瓦片。

`TileTensor` 提供了一个 `tile()` 方法，用于从父张量中提取瓦片。此瓦片是一个新的 `TileTensor`，是原始张量的视图：它不复制任何数据，而是共享原始张量的后备内存。

分块对于在全局内存和共享内存之间复制张量子集等操作非常有用。从全局张量中提取与共享内存张量具有相同维度的瓦片，允许你对两个张量使用相同的寻址方式，而不必使用线程和块索引进行大量数学计算。

:::note[分块与瓦片布局]

[TileTensor 布局](/docs/manual/tile-tensor/layouts/)页面描述了*瓦片布局*，它按瓦片组织张量元素，使得给定瓦片中的所有元素在内存中要么是连续的（[`blocked_product()`](/docs/layout/tile_layout/blocked_product/)），要么可以通过逻辑坐标轻松寻址（[`zipped_divide()`](/docs/layout/tile_layout/zipped_divide/)）。

这些函数与 `TileTensor.tile()` 方法不同，后者从父张量中提取子张量。`tile()` 方法在父张量上施加自己的网格。目前 `tile()` 方法只能用于扁平张量——不能用于分块或瓦片张量。

:::

### 提取瓦片

[`TileTensor.tile()`](/docs/layout/tile_tensor/TileTensor/#tile) 方法在给定坐标处提取给定大小的瓦片。`tile()` 方法仅适用于扁平（非嵌套）布局的张量。

```mojo
comptime tile_size = 32
comptime rows = 64
comptime cols = 128
comptime layout = row_major[rows, cols]()
var storage = List[Float32](capacity=rows * cols)
for i in range(rows * cols):
    storage.append(Float32(i))
var tensor = TileTensor(storage, layout)
var tile = tensor.tile[tile_size, tile_size](0, 1)

```

此代码创建了一个 64x128 的张量。`tile()` 方法将张量视为 32x32 瓦片的矩阵，并提取第 0 行第 1 列的瓦片，如图 3 所示。

<figure>

提取瓦片的布局取决于父张量的布局。例如，如果父张量具有行主序布局（如上所示），则提取的瓦片也具有行主序布局（列间步幅为 1）。但行间步幅与父张量的行步幅相同。

## 张量向量化

在处理张量时，一次访问多个值通常是高效的。例如，让单个 GPU 线程计算多个输出值（"线程粗化"）通常可以提高性能。同样，在将数据从一个内存空间复制到另一个内存空间时，每个线程复制一个 SIMD 向量大小的值（而不是单个值）通常更有帮助。许多 GPU 具有向量化复制指令，可以使复制更高效。

要选择最佳向量大小，你需要了解硬件对你正在使用的数据类型支持哪些向量操作。（例如，如果你在支持 16 字节复制操作的 GPU 上处理 4 字节的值，则可以使用 4 的向量宽度。）

[`vectorize()`](/docs/layout/tile_tensor/TileTensor/#vectorize) 方法创建张量的新视图，其中张量的每个元素是一个值的向量。

```mojo
var vectorized_tensor = tensor.vectorize[1, 4]()
```

向量化后的张量是原始张量的视图，指向相同的数据。底层标量值的数量保持不变，但张量布局和元素布局发生了变化，如图 4 所示。

<figure>

![](../images/layout/tensors/vectorized-tensor.png#light)
![](../images/layout/tensors/vectorized-tensor-dark.png#dark)

<figcaption><b>图 4.</b> 张量向量化</figcaption>

:::note

`TileTensor` 目前仅支持沿单个维度进行向量化，且向量中的值必须在内存中连续。例如，在二维行主序张量中，你可以使用 `[1, 2]` 或 `[1, 4]` 这样的形状对相邻列进行向量化。对于列主序张量，你可以使用 `[4, 1]` 这样的形状对相邻行进行向量化。`LayoutTensor` 支持使用二维向量形状进行向量化。

:::

## 在线程间分配张量

在 GPU 上处理张量时，有时需要将张量的元素分配给线程块中的各个线程。[`distribute()`](/docs/layout/tile_tensor/TileTensor/#distribute) 方法接收一个线程布局和一个线程 ID，返回张量的一个特定于线程的*片段*。许多张量复制 API 要求你传入线程布局，并在内部调用 `distribute()`。

线程布局在张量上进行瓦片化。第 *N* 个线程接收由每个瓦片中的第 *N* 个值组成的片段。例如，图 5 展示了给定一个 4x4 行主序张量和一个 2x2 列主序线程布局时，`distribute()` 如何形成片段：

<figure>

![](../images/layout/tensors/distribute-layout.png#light)
![](../images/layout/tensors/distribute-layout-dark.png#dark)

<figcaption><b>图 5.</b> 将张量划分为片段</figcaption>

</figure>

在图 5 中，数据布局中的数字表示存储中的偏移量（如常）。线程布局中的数字表示线程 ID。

图 5 中的示例使用了较小的线程布局以便说明。在实践中，通常最佳做法是使用 GPU 线程束大小倍数的线程布局大小，以便工作分配到所有可用线程。在多个线程束之间分配工作时，根据线程在块中的位置计算线程 ID：

```mojo
var thread_id = thread_idx.z * block_dim.y * block_dim.x
            + thread_idx.y * block_dim.x + thread_idx.x
```

在单个线程束内分配工作时，你可以使用 [`lane_id()`](/docs/std/gpu/primitives/id/lane_id/) 作为线程 ID。Lane ID 表示线程在线程束内的 ID（从 0 到 `WARP_SIZE - 1`）。

以下代码对一个张量进行向量化和分配，分配给一个完整线程束的线程：

```mojo
comptime simd_size = 4
comptime thread_layout = row_major[WARP_SIZE // simd_size, simd_size]()
var fragment = tile.vectorize[1, simd_size]().distribute[thread_layout](lane_id())
```

给定 16x16 的瓦片大小、32 的线程束大小和 4 的 `simd_size`，此代码生成一个 16x4 的 1x4 向量张量。线程布局是一个 8x4 的行主序布局。

## 复制张量

`TileTensor` 提供了一个基本的 `copy()` 方法用于复制张量数据。此外，`tile_io` 模块提供了一组专门用于在各种 GPU 内存空间之间复制的工具。所有张量复制方法都遵循布局——因此你可以通过将张量复制到具有不同布局的张量来变换张量（前提是两个布局的大小相同）。

`TileTensor.copy()` 方法将数据从源张量复制到当前张量，它们可能位于不同的内存空间中。

此方法逐元素复制数据。此方法不会在多个线程之间分配工作。如果在 GPU 上使用此方法，请使用 `distribute()` 创建特定于线程的张量片段进行复制。或者使用下一节中讨论的线程感知复制方法。

根据张量布局，`copy()` 可能会对张量进行向量化以使复制更高效。你也可以在调用 `copy()` 之前先调用 `vectorize()`。

### 瓦片复制器

[`tile_io` 包](/docs/layout/tile_io/)包含一个 `TileCopier` 特征和一组专门的瓦片复制器结构体，用于在 GPU 内存空间之间移动张量，例如从共享内存复制到本地内存。这些复制器都是*线程布局感知*的：你不需要传入张量片段，而是使用线程布局配置复制器，由它来分配工作。

与 `copy()` 方法一样，你可以在复制之前使用 `vectorize()` 方法来利用向量化复制操作。

许多瓦片复制器对复制的张量形状和线程布局有非常具体的要求，这些要求基于特定的 GPU 和数据类型。

`TileCopier` 特征定义了所有同步瓦片复制器的基本接口，包括一个接受源张量和目标张量作为实参的 `copy()` 方法。通过在函数上参数化 `TileCopier` 特征，你可以传入预置的瓦片复制器，或者针对不同硬件优化的自定义实现（例如使用 NVIDIA 张量内存加速器的瓦片复制器）。

各个瓦片复制器是参数化结构体，提供了在不同内存空间之间复制的方法。每个复制器覆盖一个特定路径，例如从全局内存复制到共享内存：

- [`GenericToSharedTileCopier`](/docs/layout/tile_io/GenericToSharedTileCopier/)
- [`SharedToGenericTileCopier`](/docs/layout/tile_io/SharedToGenericTileCopier/)
- [`GenericToLocalTileCopier`](/docs/layout/tile_io/GenericToLocalTileCopier/)
- [`LocalToGenericTileCopier`](/docs/layout/tile_io/LocalToGenericTileCopier/)
- [`SharedToLocalTileCopier`](/docs/layout/tile_io/SharedToLocalTileCopier/)
- [`LocalToSharedTileCopier`](/docs/layout/tile_io/LocalToSharedTileCopier/)

除了同步瓦片复制器外，`tile_io` 模块目前还包含一个*异步*瓦片复制器：

- [`GenericToSharedAsyncTileCopier`](/docs/layout/tile_io/GenericToSharedAsyncTileCopier/)

此复制器遵循单独的 `AsyncTileCopier` 特征。这些特征是分开的，因为异步瓦片复制器与同步瓦片复制器具有不同的语义。

以下示例演示了 `GenericToSharedAsyncTileCopier` 和 `SharedToGenericTileCopier` 类型的使用。

```mojo
from std.gpu import (
    thread_idx,
    block_idx,
    global_idx,
    barrier,
    WARP_SIZE,
)
from std.gpu.host import DeviceContext
from std.gpu.memory import async_copy_commit_group, async_copy_wait_all
from layout import TileTensor, stack_allocation
from layout.tile_io import GenericToSharedAsyncTileCopier, SharedToGenericTileCopier
from layout.tile_layout import row_major
from std.sys import has_accelerator


def tile_copier_example() raises:
    comptime dtype = DType.float32
    comptime rows = 128
    comptime cols = 128
    comptime block_size = 16
    comptime num_row_blocks = rows // block_size
    comptime num_col_blocks = cols // block_size
    comptime input_layout = row_major[rows, cols]()
    comptime simd_width = 4

    def kernel(
        tensor: TileTensor[dtype, type_of(input_layout), MutAnyOrigin]
    ):
        var global_tile = tensor.tile[block_size, block_size](
            Int(block_idx.y), Int(block_idx.x)
        )
        comptime tile_layout = row_major[block_size, block_size]()
        var shared_tile = stack_allocation[
            dtype, address_space=AddressSpace.SHARED
        ](tile_layout)

        comptime thread_layout = row_major[WARP_SIZE // simd_width, simd_width]()

        GenericToSharedAsyncTileCopier[thread_layout]().copy(
            shared_tile.vectorize[1, simd_width](),
            global_tile.vectorize[1, simd_width](),
        )
        async_copy_commit_group()
        async_copy_wait_all()
        barrier()

        if global_idx.y < rows and global_idx.x < cols:
            shared_tile[thread_idx.y, thread_idx.x] = (
                shared_tile[thread_idx.y, thread_idx.x] + 1
            )
        barrier()

        SharedToGenericTileCopier[thread_layout]().copy(
            global_tile.vectorize[1, simd_width](),
            shared_tile.vectorize[1, simd_width](),
        )

    var ctx = DeviceContext()
    var host_buf = ctx.enqueue_create_host_buffer[dtype](rows * cols)
    var dev_buf = ctx.enqueue_create_buffer[dtype](rows * cols)
    for i in range(rows * cols):
        host_buf[i] = Float32(i)
    var tensor = TileTensor(dev_buf, input_layout)
    ctx.enqueue_copy(dev_buf, host_buf)
    ctx.enqueue_function[kernel](
        tensor,
        grid_dim=(num_row_blocks, num_col_blocks),
        block_dim=(block_size, block_size),
    )
    ctx.enqueue_copy(host_buf, dev_buf)
    ctx.synchronize()
    for i in range(rows * cols):
        if host_buf[i] != Float32(i + 1):
            raise Error(
                String(
                    "意外值 ", host_buf[i], " 在位置 ", i
                )
            )
```

## 总结

在本文档中，我们探讨了 `TileTensor` 的基本概念和实际用法。`TileTensor` 的核心是提供了一个用于处理多维数据的强大抽象。通过组合布局（定义内存组织）、数据类型和内存指针，`TileTensor` 实现了灵活高效的数据操作，而无需不必要地复制底层数据。

我们介绍了几种构成使用 `TileTensor` 基础的基本张量操作，包括创建张量、访问张量元素以及在张量之间复制数据。

我们还介绍了优化数据访问的关键模式：

- 对张量进行分块以提高数据局部性。一次访问一个瓦片的张量可以提高缓存效率。在 GPU 上，分块可以让线程块的线程共享对张量子集的高速访问。
- 对张量进行向量化以实现更高效的数据加载和存储。
- 将张量划分或分配为线程本地片段进行处理。

这些模式为在 Mojo 中编写高效内核同时保持代码简洁可读提供了构建基础。

要查看 `TileTensor` 实际使用的示例，请参阅[使用 Mojo 优化自定义 GPU 操作](/max/tutorials/custom-ops-matmul/)。
