某些数据结构与值语义不太兼容。列表、树和图都需要相互指向的节点。你无法通过在一个值中嵌套另一个值来构建它们，因为类型将永远增长。

在 Mojo 中，你使用指针、堆分配和手动清理来构建这些形状。这个想法最初可能感觉很新，但一旦你分步看到它，模式就会保持简单。

## 避免直接自引用

Mojo 不会让你构建存储其自身另一个实例的类型，即使嵌套在 `Optional` 中：

```mojo
struct Node:
    var value: String
    var next: Optional[Node]  # 错误：递归引用

    # ...
```

每个 `struct` 都有固定的布局。如果 `Node` 直接持有另一个 `Node`，编译器将不知道要保留多少空间。可选字段也无济于事，因为外部值仍然需要为内部值留出空间。

指针解决了这个问题。指针有固定的大小，它们允许值相互指向而不会导致类型爆炸。

## 添加自引用指针

以下代码显示如何设置可以指向其自身类型的节点。此示例为你提供了一个具有值槽和到下一个节点的单个链接的节点类型：

```mojo
struct Node[ElementType: ImplicitlyCopyable & Writable](Movable):
    comptime NodePointer = UnsafePointer[Self, MutExternalOrigin]


    var value: Optional[Self.ElementType] # 节点的 `value`
    var next: Optional[Self.NodePointer] # 指向下一个 `Node` 的指针


    # 使用 `Optional` 值允许'空'节点构造
    # 可以移动到新分配的内存中
    def __init__(out self, value: Optional[Self.ElementType] = None):
        self.value = value
        self.next = {}
```

代码定义了基于
[`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)
的类型特定 `NodePointer` 类型别名。

[`MutExternalOrigin`](/docs/manual/values/lifetimes/)
允许指针表示不会被生命周期检查器跟踪的动态分配内存。你需要根据需要分配和释放内存。

`next` 字段是 `Optional[Self.NodePointer]`，因为节点可能或可能不会链接到另一个节点。`UnsafePointer` 不可为空，因此 `Optional` 提供空状态。`Optional[UnsafePointer]` 与原始指针具有相同的内存布局，因此没有开销。有关此模式的更多信息，请参阅
[处理可空性](/docs/manual/pointers/unsafe-pointers/#working-with-nullability)。

可选的 `value` 让你可以创建"空"节点，使你能够将新的 `Node` 内存分配移动到位。

## 构建节点

这是你将在许多引用结构中使用的关键模式：

1. 分配空间。
2. 构造一个值持有节点。
3. 将其移动到已分配的内存中。
4. 返回指针。

这是该模式的示例：

```mojo
@staticmethod
def make_node(value: Self.ElementType) -> Self.NodePointer:
    var node_ptr = alloc[Self](1)
    node_ptr.init_pointee_move(Self(value))
    return node_ptr
```

这种"分配空间、初始化和移动"的方法在 Mojo 中创建安全的基于指针的结构。

## 链接节点

要链接节点，创建一个新节点并将你的 `next` 指针设置为指向它。此示例显示如何使用提供的值 `append` 新节点。如果已存在 `next` 节点，代码会在附加新节点之前释放它。

```mojo
def append(mut self, value: Self.ElementType):
    # 如果替换 `next`，则释放链
    if self.next:
        var next_ptr = self.next.value()
        next_ptr[].free_chain()
        next_ptr.destroy_pointee()
        next_ptr.free()

    self.next = Self.make_node(value)
```

## 遍历列表

要遍历列表，请跟随链直到到达终点。递归代码使这易于阅读。此示例打印存储在每个节点中的值：

```mojo
@staticmethod
def print_list(node: Optional[Self.NodePointer]):
    if not node:
        print("Empty list")
        return

    var node_ptr = node.value()

    current_value: Optional[Self.ElementType] = node_ptr[].value
    if current_value:
        print(current_value.value(), end=" ")

    if node_ptr[].next:
        Self.print_list(node_ptr[].next)
    else:
        print()
```

模式很简单：检查值，如果存在则打印它，然后移动到下一个链接。

:::note
此示例使用静态方法，但你也可以将其实现为实例方法。
:::

## 清理

因为你为自己分配每个节点，所以你也负责释放它。此清理遍历链并在销毁其 pointee 后释放每个节点：

```mojo
def free_chain(self):
    var current = self.next
    while current:
        var current_ptr = current.value()
        next_node = current_ptr[].next
        current_ptr.destroy_pointee()
        current_ptr.free()
        current = next_node
```

"头"节点保持已分配状态，除非你显式为自己释放它：

```mojo
list_head[].free_chain()
list_head.destroy_pointee()
list_head.free()
```

## 析构函数

当你构建真实的 Mojo 数据结构时，你通常想要一个安全的 API，将原始指针隐藏给用户。在完整的链表类型（而不是可链接节点的小型演示）中，父列表处理节点分配和释放。因为它拥有节点，它还在其
[析构函数](/docs/manual/lifecycle/death/)
中执行清理。

这是一个小示例，显示如何初始化 `self`：

```mojo
struct LinkedList[T]:
    var _head: Optional[Self._NodePointer]

    def __del__(deinit self):
        """通过释放所有节点来清理列表。

        注：
            时间复杂度：O(n) in len(self)。

        另请参阅：
            "选择析构函数的形式！"
            -- Gozer，《鬼娃回魂》（1984）。
        """
        var curr = self._head
        while curr:
            var next = curr.value()[].next
            curr.value().destroy_pointee()
            curr.value().free()
            curr = next
```
