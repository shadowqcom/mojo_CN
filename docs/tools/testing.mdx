`mojo test` 命令已于 2025 年 10 月 31 日被移除。更多信息请参见[弃用提案](https://github.com/modular/modular/blob/main/mojo/proposals/mojo-test-deprecation.md)和[论坛公告](https://forum.modular.com/t/proposal-deprecating-mojo-test/2371)。

现在推荐的测试方法是使用标准库中的 [`TestSuite`](/docs/std/testing/suite/TestSuite/) 结构体，它提供自动测试发现和执行。请继续阅读有关使用 `TestSuite` 的当前测试说明。

:::

Mojo 包含一个用于开发和执行单元测试的框架。Mojo 测试框架由 [Mojo 标准库](/docs/std)中定义的一组断言和用于自动测试发现和执行的 [`TestSuite`](/docs/std/testing/suite/TestSuite/) 结构体组成。

## 入门

让我们从一个编写和运行 Mojo 测试的简单示例开始。

### 1. 编写测试

作为使用 Mojo 测试框架的第一个示例，创建一个名为 `test_quickstart.mojo` 的文件，包含以下代码：

```mojo
# test_quickstart.mojo 的内容
from std.testing import assert_equal, TestSuite

def inc(n: Int) -> Int:
    return n + 1

def test_inc_zero() raises:
    # 此测试包含一个故意的逻辑错误，以展示运行时测试失败的样子
    assert_equal(inc(0), 0)

def test_inc_one() raises:
    assert_equal(inc(1), 2)

def main() raises:
    TestSuite.discover_tests[__functions_in_module()]().run()
```

在此文件中，`inc()` 函数是测试*目标*。名称以 `test_` 开头的函数是测试。通常你应该将目标定义在与测试分开的源文件中，但对于这个简单示例，你可以在同一文件中定义它们。

测试函数在执行时如果抛出错误则*失败*，否则*通过*。此示例中的两个测试使用 `assert_equal()` 函数，如果提供的两个值不相等，它会抛出错误。

:::note

`test_inc_zero()` 的实现包含一个故意的逻辑错误，以便你在下一步执行时可以看到失败测试的示例。

:::

### 2. 执行测试

然后在包含该文件的目录中，在 shell 中执行以下命令：

```bash
mojo run test_quickstart.mojo
```

你应该看到类似以下的输出（注意此示例省略了输出中显示的完整文件系统路径）：

```output
Unhandled exception caught during execution:
Running 2 tests for ROOT_DIR/test_quickstart.mojo
    FAIL [ 0.009 ] test_inc_zero
      At ROOT_DIR/test_quickstart.mojo:40:5: AssertionError: `left == right` comparison failed:
         left: 1
        right: 0
    PASS [ 0.001 ] test_inc_one
--------
Summary [ 0.009 ] 2 tests run: 1 passed , 1 failed , 0 skipped
Test suite 'ROOT_DIR/test_quickstart.mojo' failed!

mojo: error: execution exited with a non-zero result: 1
```

输出显示每个测试运行时的通过或失败状态以及执行时间，随后是运行、通过、失败和跳过的测试摘要。失败的测试会内联显示其错误消息。

## 使用 Mojo 断言函数

Mojo 标准库包含一个 [`testing`](/docs/std/testing/testing/) 模块，其中定义了多个用于实现测试的断言函数。每个断言在其条件满足时返回 `None`，不满足时抛出错误。

- [`assert_true()`](/docs/std/testing/testing/assert_true/)：断言输入值为 `True`。
- [`assert_false()`](/docs/std/testing/testing/assert_false/)：断言输入值为 `False`。
- [`assert_equal()`](/docs/std/testing/testing/assert_equal/)：断言输入值相等。
- [`assert_not_equal()`](/docs/std/testing/testing/assert_not_equal/)：断言输入值不相等。
- [`assert_almost_equal()`](/docs/std/testing/testing/assert_almost_equal/)：断言输入值在容差范围内相等。

布尔断言在失败时报告基本的错误消息。

```mojo
from std.testing import *
assert_true(False)
```

```output
Unhandled exception caught during execution

Error: At Expression [1] wrapper:14:16: AssertionError: condition was unexpectedly False
```

每个函数还接受一个可选的 `msg` 关键字参数，用于在断言失败时提供自定义消息。

```mojo
assert_true(False, msg="paradoxes are not allowed")
```

```output
Unhandled exception caught during execution

Error: At Expression [2] wrapper:14:16: AssertionError: paradoxes are not allowed
```

对于比较浮点值，你应该使用 `assert_almost_equal()`，它允许你指定绝对或相对容差。

```mojo
result = 10 / 3
assert_almost_equal(result, 3.33, atol=0.001, msg="close but no cigar")
```

```output
Unhandled exception caught during execution

Error: At Expression [3] wrapper:15:24: AssertionError: 3.3333333333333335 is not close to 3.3300000000000001 with a diff of 0.0033333333333334103 (close but no cigar)
```

testing 模块还定义了一个[上下文管理器](/docs/manual/errors#use-a-context-manager)，[`assert_raises()`](/docs/std/testing/testing/assert_raises/)，用于断言给定代码块正确抛出了预期的错误。

```mojo
def inc(n: Int) raises -> Int:
    if n == Int.MAX:
         raise Error("inc overflow")
    return n + 1

print("Test passes because the error is raised")
with assert_raises():
    _ = inc(Int.MAX)

print("Test fails because the error isn't raised")
with assert_raises():
    _ = inc(Int.MIN)
```

```output
Unhandled exception caught during execution

Test passes because the error is raised
Test fails because the error isn't raised
Error: AssertionError: Didn't raise at Expression [4] wrapper:18:23
```

:::note

上面的示例将 `inc()` 的返回值赋给了一个[*丢弃模式*](/docs/manual/lifecycle/death/#explicit-lifetime-extension)。没有它，Mojo 编译器会报告返回值未使用的警告。

:::

你还可以为 `assert_raises()` 提供一个可选的 `contains` 参数，指示只有当错误消息包含指定子字符串时测试才通过。其他错误会被传播，导致测试失败。

```mojo
print("Test passes because the error contains the substring")
with assert_raises(contains="required"):
    raise Error("missing required argument")

print("Test fails because the error doesn't contain the substring")
with assert_raises(contains="required"):
    raise Error("invalid value")
```

```output
Unhandled exception caught during execution

Test passes because the error contains the substring
Test fails because the error doesn't contain the substring
Error: invalid value
```

## 编写单元测试

Mojo 单元测试就是一个满足以下所有要求的函数：

- 名称以 `test_` 开头，以便自动发现。
- 不接受任何参数。
- 返回 `None`。
- 抛出错误以指示测试失败。
- 在模块作用域定义，而不是作为 Mojo 结构体的方法。

通常，你应该使用 Mojo 标准库 [`testing`](/docs/std/testing/testing/) 模块中的断言工具来实现测试。你可以在同一个测试函数中包含多个相关断言。但是，如果断言在执行期间抛出错误，则测试函数立即返回，跳过后续的所有断言。

## 使用 TestSuite 运行测试

要运行你的测试，每个测试文件必须包含一个 `main()` 函数，使用 [`TestSuite.discover_tests()`](/docs/std/testing/suite/TestSuite/#discover_tests) 自动发现并执行模块中的所有测试函数。`__functions_in_module()` 编译器内建函数提供当前模块中定义的所有函数列表，`discover_tests()` 会过滤出带有 `test_` 前缀的函数。

以下是一个测试文件示例，包含对名为 `my_target_module` 的源模块中定义的函数的三个测试（该模块未在此展示）。

```mojo
# 文件：test_my_target_module.mojo

from my_target_module import convert_input, validate_input
from std.testing import assert_equal, assert_false, assert_raises, assert_true, TestSuite

def test_validate_input() raises:
    assert_true(validate_input("good"), msg="'good' should be valid input")
    assert_false(validate_input("bad"), msg="'bad' should be invalid input")

def test_convert_input() raises:
    assert_equal(convert_input("input1"), "output1")
    assert_equal(convert_input("input2"), "output2")

def test_convert_input_error() raises:
    with assert_raises():
        _ = convert_input("garbage")

def main() raises:
    TestSuite.discover_tests[__functions_in_module()]().run()
```

然后你可以使用 `mojo run test_my_target_module.mojo` 来运行测试并报告结果。
