本页介绍如何使用 rattler-build 将你的 Mojo 项目转换为可分发的 conda 包。

你可以在任何兼容 conda 的包索引上分发你的 conda 包，例如 [prefix.dev](https://prefix.dev)、[anaconda.org](https://anaconda.org) 或 S3 存储桶。为了获得最大的可见性，我们建议在 prefix.dev 上的 [modular-community 频道](https://prefix.dev/channels/modular-community)分享你的包，如下所述。

## 工作原理

*rattler-build* 是一个将你的源代码转换为 conda 包的工具。你给它一个*配方（recipe）*——一个名为 `recipe.yaml` 的 YAML 文件——它会完成其余工作：获取你的源代码，在隔离环境中编译它，运行你的测试，并写出准备好上传到包索引的 `.conda` 文件。

配方是你的包的声明式描述，指定了：

- 源代码位置（git 提交或 tarball URL）
- 构建过程（一个 `mojo package` 命令）
- 包依赖项
- 用于验证构建的测试命令

完整的打包过程是：

1. 创建一个 `recipe.yaml` 来指定你的包详情。
2. 运行 `rattler-build` 来创建 `.conda` 包。
3. 在公共包索引中分享该包。

:::note

如果你想在 modular-community 频道中分发你的包，你只需要将 `recipe.yaml` 文件合并到 [modular-community 仓库](https://github.com/modular/modular-community)中（该仓库处理步骤 2 和 3）。

:::

然后你和其他用户可以通过将适当的 conda 频道添加到项目清单文件（`pixi.toml`）来使用 `pixi` 或其他 conda 包管理器安装你的包。

## 安装 rattler-build

我们推荐使用 [Pixi](https://pixi.sh/latest/) 来安装 `rattler-build`：

1. 如果你还没有安装 `pixi`，使用以下命令安装：

    ```bash
    curl -fsSL https://pixi.sh/install.sh | sh
    ```

    然后重启终端以使更改生效。

2. 现在全局安装 `rattler-build`：

    ```bash
    pixi global install rattler-build
    ```

3. 验证安装：

    ```bash
    rattler-build --version
    ```

## 编写配方文件

配方是打包过程的核心，定义在一个名为 `recipe.yaml` 的 YAML 文件中。

按照惯例，将你的配方存储在项目根目录的 `conda.recipe/recipe.yaml` 中。`rattler-build` 默认在该位置查找，这也是 GitHub Action（[rattler-build-action](https://github.com/prefix-dev/rattler-build-action)）期望的位置。例如：

```output
my-mojo-lib/
├── src/
│   └── my_mojo_lib/
│       ├── __init__.mojo
│       └── utils.mojo
├── test.mojo
├── conda.recipe/
│   └── recipe.yaml
├── LICENSE
└── README.md
```

### 最小配方文件

本节介绍 Mojo 包最重要的配方字段。有关所有可用配方字段的详情，请参见 [rattler-build 配方参考](https://rattler-build.prefix.dev/latest/reference/recipe_file/)。

你可以复制此模板来开始构建你的 `recipe.yaml` 文件：

```yaml title="recipe.yaml"
context:
  version: "0.1.0"

package:
  name: my-mojo-lib
  version: ${{ version }}

source:
  - git: https://github.com/yourname/my-mojo-lib.git
    rev: a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2

build:
  number: 0
  script:
    - mojo package src/my_mojo_lib -o ${{ PREFIX }}/lib/mojo/my_mojo_lib.mojopkg

requirements:
  build:
    - mojo-compiler =25.5.0
  host:
    - mojo-compiler =25.5.0
  run:
    - ${{ pin_compatible('mojo-compiler') }}

tests:
  - script:
      - if: unix
        then:
          - mojo run test.mojo
    files:
      recipe:
        - test.mojo

about:
  homepage: https://github.com/yourname/my-mojo-lib
  repository: https://github.com/yourname/my-mojo-lib
  license: MIT
  license_file: LICENSE
  summary: A short one-line description of what your library does.

extra:
  maintainers:
    - yourname
```

### 配方技巧

以下是对 Mojo 包特别重要的几点。

#### 使用完整的提交 SHA 作为源版本

`source.rev` 字段应该是完整的 40 字符 git 提交 SHA，而不是分支名或标签。这使得构建可重现——任何从相同配方构建的人都能获得完全相同的源代码。

#### 设置构建号

将 `build.number` 从 `0` 开始。如果你需要重新构建同一版本的库（例如为了适配新的 Mojo 编译器版本），请递增 `build.number` 而不是更改版本。当你更新版本时，将其重置为 `0`。

#### 指定安装位置

在上面的配方中，查看 `build.script` 部分中的 `mojo package` 命令。此命令将 `.mojopkg` 文件输出到 `$PREFIX/lib/mojo/` 非常重要，因为此路径使得包可被 Mojo 编译器自动发现。

当 `rattler-build` 运行你的构建脚本时，它会设置一个 `$PREFIX` 环境变量，指向隔离安装目录的根目录。你的脚本放置在 `$PREFIX` 下的任何文件都会成为 conda 包的一部分——构建期间写入 `$PREFIX/lib/mojo/foo.mojopkg` 的文件在你运行 `pixi add foo` 时会被解压到你的实际环境中。可以将 `$PREFIX` 视为你环境中文件在你机器上所在位置的占位符。

#### 固定 Mojo 编译器版本

Mojo 包针对特定的编译器版本编译，可能与其他版本不兼容。必需的 `mojo-compiler` 版本必须在配方的 `requirements.build` 部分指定，并且必须符合 [conda 包匹配语法](https://docs.conda.io/projects/conda/en/latest/user-guide/concepts/pkg-specs.html#package-match-specifications)。

`requirements.run` 中的 `pin_compatible('mojo-compiler')` 函数根据构建时解析的版本生成版本约束，防止你的包在不兼容的运行时上静默运行。

## 构建包

有了配方文件，你可以从项目根目录使用 `rattler-build` 构建包：

```bash
rattler-build build \
  --recipe conda.recipe/recipe.yaml \
  -c conda-forge \
  -c https://conda.modular.com/max \
  -c https://repo.prefix.dev/modular-community
```

`-c` 标志指定搜索依赖项的 conda 频道（按优先级顺序）。你需要：

- `conda-forge` 用于通用工具
- `https://conda.modular.com/max` 用于 `mojo-compiler` 和 `max`
- `https://repo.prefix.dev/modular-community` 如果你依赖其他社区 Mojo 包

当你运行 `rattler-build build` 时，它会：

1. 创建隔离的构建环境
2. 获取你的源代码
3. 运行你的构建脚本以编译 `.mojopkg` 文件
4. 将结果打包成 `.conda` 归档文件
5. 运行你的测试命令以验证包是否正常工作

输出文件出现在 `output/` 目录中，例如：

```text
output/
└── linux-64/
    └── my-mojo-lib-0.3.0-h1a2b3c4_0.conda
```

文件名中的哈希值（`h1a2b3c4`）是从构建配置派生的，由 rattler-build 自动管理。

## 调试失败的构建

如果构建失败，打开调试 shell 进行交互式调查：

```bash
rattler-build debug shell
```

这会为你提供一个设置了所有环境变量（`$PREFIX`、`$SRC_DIR` 等）且构建环境已激活的 shell，你可以运行构建命令来查找问题。

更多详情请参见 [rattler-build 调试指南](https://rattler-build.prefix.dev/latest/debugging_builds/)。

## 发布到包索引

一旦你有了构建好的 `.conda` 文件，你可以将其上传到任何兼容的主机，例如 [prefix.dev](https://prefix.dev)、[anaconda.org](https://anaconda.org) 或 AWS S3 存储桶。为了获得最大的可见性，请将你的包添加到 [modular-community 频道](https://prefix.dev/channels/modular-community)（托管在 prefix.dev 上），如下所述。

### 发布到 modular-community 频道

要在 [modular-community 频道](https://prefix.dev/channels/modular-community)上发布你的包，请向 [modular-community GitHub 仓库](https://github.com/modular/modular-community)提交拉取请求以添加你的包的 `recipe.yaml` 文件。该仓库会根据仓库中的配方自动构建和托管所有包。

你的 `recipe.yaml` 与上面描述的文件相同。只需将其添加到与你的包名匹配的新目录中：

```text
modular-community/
└── recipes/
    └── my-mojo-lib/
        └── recipe.yaml
```

一旦发布到频道，你可以通过将 `https://repo.prefix.dev/modular-community` 频道添加到项目清单来使用 `pixi` 安装你的包：

```toml title="pixi.toml"
[workspace]
channels = [
  "https://conda.modular.com/max-nightly",
  "https://repo.prefix.dev/modular-community",
  "conda-forge",
]
```

:::note

如果你的包包含 Python 或 Mojo 以外的任何语言，你必须在源代码仓库上启用 [CodeQL 扫描](https://docs.github.com/en/code-security/code-scanning/enabling-code-scanning/configuring-default-setup-for-code-scanning)，并将徽章添加到你的 README。

:::

更多详情请参见 [modular-community README](https://github.com/modular/modular-community?tab=readme-ov-file#modular-community-channel)。

### 更新你的包

当你发布库的新版本时：

1. 更新配方中的 `context.version`。
2. 将 `source.rev` 更新为新的提交 SHA（或更新 tarball URL 和 SHA256）。
3. 将 `build.number` 重置为 `0`。
4. 向 modular-community 提交新的 PR（如果你已经在那里发布过）。

如果你要重新发布同一版本（例如为了支持新的 Mojo 编译器版本），请递增 `build.number` 而不是更改版本。
