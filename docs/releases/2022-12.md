## 2022-12-26 那一周

- 📢 现在可以在参数上下文中调用函数了！在参数上下文中调用
  函数会在编译时对该函数求值。其结果
  随后可用作参数值。例如：

  ```mojo
  fn fma(x: Int, y: Int, z: Int) -> Int:
      return a + b * c

  fn parameter_call():
      alias nelts = fma(32, 2, 16)
      var x: SIMD[f32, nelts]
  ```

- 现在可以通过一元 `+` 表达式禁用 `__mlir_attr` 替换中的
  类型打印。

- 📢 函数中已支持 `let` 声明。`let` 声明是
  局部运行时常量值，始终为右值。它们补充了 `var` 声明
  （后者是可变的左值），且是大多数情况下
  应使用的常规形式。它们生成的 IR 更少，且在初始化后
  始终处于 SSA 形式。

  我们希望在未来扩展以支持结构体中的 `let` 声明，
  以及支持惰性初始化的 `let` 声明（借助数据流分析），
  但目前尚不支持。

- 📚 新增 `NDBuffer` 结构体。

- 新年快乐。

## 2022-12-19 那一周

- 📚 标准库开始搭建：
  1. 添加了 Integer 和 SIMD 结构体以引导标准库。
  2. 添加了非常基础的缓冲区数据结构。

- 我们已有对函数调用中参数结果解析的基础支持！结果
  参数是 Mojo 元编程的一项重要特性。它们允许函数
  返回编译时常量。

  ```mojo
  fn get_preferred_simdwidthof[() -> nelts: Int]():
      return[2]

  fn vectorized_function():
      get_preferred_simdwidthof[() -> nelts]()
      var x: SIMD[f32, nelts]
  ```

- 现在可以在更多情形下将类型用作 `!kgen.mlirtype` 的参数。

- 零结果的 MLIR 操作不再需要指定 `_type: []`。

- 我们支持解析三引号字符串，用于为函数和结构体
  编写文档字符串！

- 提供了一种新的 `__mlir_type[a,b,c]` 语法，用于替换进 MLIR
  类型和属性，旧的占位符方法已被移除。相较占位符，此方法有若干优势：

  1. 更简单。
  2. 它不会形成带占位符的中间结果，后者
     会被 MLIR 的语义分析拒绝，例如之前无法表达的复杂情况。
  3. 提供了一种简单方式将长的属性/类型
     拆分到多行。

- 我们现在支持函数上的 `@evaluator` 装饰器，用于 KGEN 求值器。
  这使得在编译期进行搜索时可以指定用户自定义接口求值器。

- 📢 `import` 语法现已支持！

  它将导入的模块打包为文件操作，实现了与其他声明的有效
  隔离。"import" 到目标上下文只是声明别名，
  在 IR 生成阶段会自动处理正确的符号引用。作为起点，
  这不处理任何包的概念（因为尚未充分构思）。

- 📢 反向二元运算符（如 `__radd__`）现在会在正向版本
  （如 `__add__`）由于某种原因不可用时被查找并使用。

- 📢 隐式转换现已普遍可用，例如在赋值语句、
  变量初始化等场合。可能还有少数几个场合应当支持，
  但我们现在可以开始消除所有字面量上多余的显式
  类型转换。

- 节日快乐

## 2022-12-12 那一周

- 📢 函数重载现已可用。调用解析会根据调用点
  指定的实际参数与值参数筛选候选列表，
  若无候选可用或多个候选可用且存在歧义则报错。
  我们在重载查找中也考虑隐式转换：

  ```mojo
  fn foo(x: Int): pass
  fn foo(x: F64): pass

  foo(Int(1)) # resolves to the first overload
  foo(1.0)    # resolves to the second overload
  foo(1)      # error: both candidates viable with 1 implicit conversion!
  ```

- 短路二元 `and` 和 `or` 表达式现已支持。

- 一元运算符处理更稳健，现已处理 `not`
  表达式以及 Bool 上的 `~x`。

- 📢 编译器现在生成供 GDB/LLDB 使用的调试信息，
  描述变量和函数。

- Mojo Visual Studio Code 扩展的首个版本已发布！
  它支持 Mojo 文件的语法高亮。

- 首版 `Bool` 类型已落地于新的 Mojo 标准
  库！

- 📢 return 语句现已支持隐式转换。

## 2022-12-05 那一周

- "Discard" 模式现已支持，例如 `_ = foo()`

- 我们现在支持函数调用参数中的隐式转换，例如
  自动将 `index` 值转换为 `Int`。这消除了大量
  类型转换，例如无需到处写 F32(1.0)。

   这目前因若干原因受限，后续会改进：
   1. 我们不支持重载，因此许多类型无法从
      所有应当转换的来源转换，例如无法将 "1" 传给
      期望 F32 的参数，因为 F32 无法从 index 创建。
   2. 这不是"检查是否可以调用 `__new__`"，而是
      在不匹配时强制应用，这导致较差的 QoI。
   3. 这不修复需要 radd 的场合。
