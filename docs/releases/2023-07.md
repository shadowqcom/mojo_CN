## 2023-07-26

### ⭐️ 新增

- 同时定义 `__getitem__` 和 `__setitem__` 的类型（即下标访问实例创建计算 LValue 的类型）现在
  可以在参数表达式中被索引。

- 用于带常量边界和步长的循环的 unroll 装饰器：
  - `@unroll`：完全展开循环。
  - `@unroll(n)`：按因子 n 展开循环，其中 `n` 是正整数。
  - unroll 装饰器要求循环边界和迭代步长为
    编译时常量值，否则展开会失败并出现
    编译错误。这也不会让循环归纳变量成为参数。

  ```mojo
  # Fully unroll the loop.
  @unroll
  for i in range(5):
      print(i)

  # Unroll the loop by a factor of 4 (with remainder iterations of 2).
  @unroll(4)
  for i in range(10):
      print(i)
  ```

- Mojo REPL 现在会打印 REPL 中定义的变量值。对
  标量和结构体有完整支持。非标量 SIMD 向量目前
  尚不支持。

### 🛠️ 修复

- [Issue #437](https://github.com/modular/modular/issues/437) - Range 现在可用
  PythonObject 实例化。

- [Issue #288](https://github.com/modular/modular/issues/288) - Python 字符串
  现在可以安全拷贝。

## 2023-07-20

### ⭐️ 新增

- Mojo 现在包含 `Limits` 模块，其中含有获取某类型可表示的
  最大和最小值的函数，按 [Issue
  #51](https://github.com/modular/modular/issues/51) 的要求。以下函数
  从 `Math` 移到 `Limits`：`inf()`、`neginf()`、`isinf()`、`isfinite()`。

- Mojo 装饰器现在区分"signature"和"body"
  装饰器，并按顺序应用。Signature 装饰器（如 `@register_passable`
  和 `@parameter`）在解析体之前修改声明的类型。Body 装饰器（如
  `@value`）在声明完全解析后修改其体。由于顺序原因，signature 装饰器不能在
  body 装饰器之后应用。这意味着以下写法现已无效：

  ```mojo
  @register_passable # error: cannot apply signature decorator after a body one!
  @value
  struct Foo:
      pass
  ```

- 全局变量现在可以在 Mojo 编译归档中导出，使用
  `@export` 装饰器。导出的全局变量是编译归档中的公共符号，默认
  使用变量名作为其链接名。可通过 `@export("new_name")` 指定自定义
  链结名。这不影响 Mojo 代码中的变量名。

- Mojo 现在支持包！Mojo 包通过在目录中放置
  `__init__.mojo` 或 `__init__.🔥` 来定义。同一目录下的其他文件构成包内的模块（这与
  [Python 中的做法](https://docs.python.org/3/tutorial/modules.html#packages) 完全相同）。
  示例：

  ```bash
  main.🔥
  my_package/
    __init__.🔥
    module.🔥
    my_other_package/
      __init__.🔥
      stuff.🔥
  ```

  ```mojo
  # main.🔥
  from my_package.module import some_function
  from my_package.my_other_package.stuff import SomeType

  fn main():
      var x: SomeType = some_function()
  ```

- Mojo 现在支持直接的模块和包导入！模块和包可以被
  导入并绑定到名字。模块和包的元素，如函数、
  类型、全局变量和其他模块，可通过属性
  引用访问，如 `my_module.foo`。注意，模块缺少运行时
  表示，即模块引用不能被实例化。

  ```mojo
  import builtin.io as io
  import SIMD

  io.print("hello world")
  var x: SIMD.Float32 = 1.2
  ```

### 🦋 变更

- 回退了 2023-02-13 的允许非限定结构体成员的特性。
  请改用 `Self` 关键字以方便地访问带绑定
  参数的结构体成员。这是修复
  [Issue #260](https://github.com/modular/modular/issues/260) 所必需的。

- 更新了 RayTracing notebook：添加步骤 5 以创建镜面光照，使
  图像更逼真，以及步骤 6 以添加背景图。

### 🛠️ 修复

- [Issue #260](https://github.com/modular/modular/issues/260) - 结构体内部
  的定义不再遮蔽结构体定义外的定义。

## 2023-07-12

### ⭐️ 新增

- Mojo 现在支持全局变量！这启用了 Mojo 文件中顶层作用域的 `var` 和 `let`
  声明。全局变量初始化器在代码模块由平台加载时按
  全局变量之间的依赖顺序运行，其析构函数按相反顺序
  调用。

- Mojo 编程手册现已用 Jupyter notebook 编写，并完整地
  提供 Mojo Playground（`programming-manual.ipynb`）。（此前 `HelloMojo.ipynb` 包含了大部分
  相同内容，但已过时。）

- 因此，我们也重写了 `HelloMojo.ipynb`，使其更短并提供更
  友好的首次用户体验。

- 现已提供 [`Coroutine` 模块文档](/docs/std/builtin/coroutine/)。
  协程构成 Mojo 异步执行支持的基础。对 `async fn` 的调用可存储在 `Coroutine` 中，从中可以
  恢复、等待并在
  完成后获取其结果。

### 🦋 变更

- `TargetInfo` 模块中的 `simd_bit_width` 已重命名为 `simdbitwidth`，以更好地与 `simdwidthof`、`bitwidthof` 等对齐。

### 🛠️ 修复

- 海象运算符现在可在不带括号的 if/while 语句中工作，
  例如 `if x := function():`。

- [Issue #428](https://github.com/modular/modular/issues/428) - `FloatLiteral` 和 `SIMD` 类型现在支持通过
  `to_int` 或 `__int__` 方法调用转换为 `Int`。其行为与 Python 一致，
  向零取整。

## 2023-07-05

### ⭐️ 新增

- 元组表达式现在无需括号即可工作。例如，`a, b = b, a`
  如你所期望的那样工作。
- 链式赋值（例如 `a = b = 42`）和海象运算符（例如
  `some_function(b := 17)`）现已支持。

### 🦋 变更

- [`TargetInfo`](/docs/std/sys/info/) 模块中的 `simd_width` 和 `dtype_simd_width` 函数
  已重命名为 `simdwidthof`。

- 已从 `alignof`、`sizeof` 和
  `bitwidthof` 中去除 `dtype_` 前缀。现在可以将这些函数（例如 `alignof`）与任何
  参数类型一起使用，包括 `DType`。

- `inf`、`neginf`、`nan`、`isinf`、`isfinite` 和 `isnan` 函数
  从 `Numerics` 模块移至 [`Math`](/docs/std/math/math/)
  模块，以更好地与 Python 的库结构对齐。

### 🛠️ 修复

- [Issue #253](https://github.com/modular/modular/issues/253) - 在未提供参数时访问结构体成员别名的问题。

- [Issue #404](https://github.com/modular/modular/issues/404) - 文档现在对变量名使用 `snake_case`，更符合 Python 风格。

- [Issue #379](https://github.com/modular/modular/issues/379) - 已解决 Tuple
  限制，现在支持多个返回值，即使不带括号。

- [Issue #347](https://github.com/modular/modular/issues/347) - Tuple 不再需要
  括号。

- [Issue #320](https://github.com/modular/modular/issues/320) - Python 对象
  现在可通过 `for` 循环遍历。
