在 Mojo SDK 的第二个发布版本中，有更多值得喜爱的 Mojo 内容！
本版本包含新功能、一项 API 变更以及若干 bug 修复。

此外还更新了
[VS Code 的 Mojo 扩展](https://marketplace.visualstudio.com/items?itemName=modular-mojotools.vscode-mojo)。

## ⭐️ 新增

- Mojo 现在部分支持向函数和方法传递关键字参数（keyword arguments）。
  例如以下代码可以正常工作：

  ```mojo
  fn foo(a: Int, b: Int = 3) -> Int:
      return a * b

  fn main():
      print(foo(6, b=7))  # prints '42'
      print(foo(a=6, b=7))  # prints '42'
      print(foo(b=7, a=6))  # prints '42'
  ```

  参数也可以从关键字参数中推断，例如：

  ```mojo
  fn bar[A: AnyType, B: AnyType](a: A, b: B):
      print("Hello 🔥")

  fn bar[B: AnyType](a: StringLiteral, b: B):
      print(a)

  fn main():
      bar(1, 2)  # prints `Hello 🔥`
      bar(b=2, a="Yay!")  # prints `Yay!`
  ```

  目前存在以下值得注意的限制：

  - 不支持仅关键字参数（keyword-only arguments）：

    ```mojo
    fn baz(*args: Int, b: Int): pass  # fails
    fn baz(a: Int, *, b: Int): pass  # fails
    ```

    （仅关键字参数在
    [PEP 3102](https://peps.python.org/pep-3102/) 中描述。）

  - 不支持可变关键字参数：

    ```mojo
    fn baz(a: Int, **kwargs: Int): pass  # fails
    ```

- Mojo 现在支持 `@nonmaterializable` 装饰器。其目的是标记
  只应存在于参数域（parameter domain）中的数据类型。使用时，
  用 `@nonmaterializable(TargetType)` 装饰一个 struct。
  每当不可实例化类型从参数域转换出来时，它会自动转换为
  `TargetType`。一个不可实例化的 struct 应当将其所有方法
  标注为 `@always_inline`，并且必须可在参数域中计算。
  在以下示例中，`NmStruct` 类型可以在参数域中相加，
  但在实例化时会转换为 `HasBool`。

  ```mojo
  @value
  @register_passable("trivial")
  struct HasBool:
      var x: Bool
      fn __init__(x: Bool) -> Self:
          return Self {x: x}
      @always_inline("nodebug")
      fn __init__(nms: NmStruct) -> Self:
          return Self {x: True if (nms.x == 77) else False}

  @value
  @nonmaterializable(HasBool)
  @register_passable("trivial")
  struct NmStruct:
      var x: Int
      @always_inline("nodebug")
      fn __add__(self: Self, rhs: Self) -> Self:
          return NmStruct(self.x + rhs.x)

  alias stillNmStruct = NmStruct(1) + NmStruct(2)
  # When materializing to a run-time variable, it is automatically converted,
  # even without a type annotation.
  let convertedToHasBool = stillNmStruct
  ```

- 当 Mojo 整数字面量在参数域中使用时，现在会生成
  `IntLiteral` 无限精度整数类型。`IntLiteral` 在运行时计算时会
  实例化为 `Int` 类型，但在编译时使用支持的运算符进行的中间计算，
  现在可以超过 `Int` 类型的位宽。

- Mojo 语言服务器现在支持顶层代码补全，使得在键入对变量、类型等的
  引用时能够进行补全。此修复对应
  [#679](https://github.com/modular/modular/issues/679)。

- Mojo REPL 现在会对结果变量进行着色，以帮助区分输入
  表达式和输出变量。

## 🦋 变更

- Mojo 允许类型实现两种形式的移动构造函数：一种在某个值的
  生命周期结束时被调用，另一种在编译器无法证明这一点时被调用。
  以前两者都命名为 `__moveinit__`，具有以下两种签名：

  ```mojo
  fn __moveinit__(inout self, owned existing: Self): ...
  fn __moveinit__(inout self, inout existing: Self): ...
  ```

  我们为第二种形式赋予了独立的名字，以更清楚地表明
  这是两种独立的操作：第二种已重命名为
  `__takeinit__`：

  ```mojo
  fn __moveinit__(inout self, owned existing: Self): ...
  fn __takeinit__(inout self, inout existing: Self): ...
  ```

  该命名意在表达此操作从源对象“取出”概念上的值
  （而不销毁它），这与前者将值从一个位置“移动”到另一个位置不同。

  更多信息，请参阅 Mojo 手册中关于
  [移动构造函数](/docs/manual/lifecycle/life/#move-constructor)的章节。

- Mojo 中的 Error 类型发生了变化。以前使用 `error.value` 提取错误信息，
  现在你需要使用 `error.message()` 提取错误信息。

## 🛠️ 修复

- [#503](https://github.com/modular/modular/issues/503) - 改进了 lowering
  `kgen.param.constant` 失败时的错误信息。
- [#554](https://github.com/modular/modular/issues/554) - 静态 tuple 的 alias
  无法展开。
- [#500](https://github.com/modular/modular/issues/500) - 由于验证器错误导致
  调用展开失败。
- [#422](https://github.com/modular/modular/issues/422) - 多行字符串中注释
  检测错误。
- [#729](https://github.com/modular/modular/issues/740) - 改进了关于
  如何退出 REPL 的提示信息。
- [#756](https://github.com/modular/modular/issues/756) - 修复了 VS Code 扩展的
  初始化错误。
- [#575](https://github.com/modular/modular/issues/575) - 使用 libedit 构建
  LLDB/REPL，以在终端中获得更好的编辑体验。
