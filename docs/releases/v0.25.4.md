## 要点 {#25-4-highlights}

- Mojo 现在支持 AMD GPU，将硬件兼容性从 NVIDIA 扩展到包括
  AMD 的 GPU 生态系统。这使 Mojo 应用程序能够利用
  AMD 的 RDNA 和 CDNA 架构进行高性能计算工作负载，
  为开发者在为 AI 和计算密集型应用程序选择硬件平台时
  提供更大的灵活性。

- 已添加用于 NVIDIA Blackwell GPU 的原语，
  提供对最新 GPU 架构特性的低级访问。这些
  原语使开发者能够利用 Blackwell 增强的计算
  能力、改进的内存带宽和高级 AI 加速
  特性，包括对较新张量操作和优化内存
  管理模式的支持。

- Python-Mojo 绑定已作为预览版发布！这是
  从现有 Python 代码库调用 Mojo 函数的能力。用例是
  通过用 Mojo 重写代码的某些部分以实现性能来加速
  热点/慢速 Python 代码。

- Mojo 集合类型收到了许多增强。

  - [`List`](/docs/std/collections/list/List/)、
    [`Set`](/docs/std/collections/set/Set/) 和
    [`Dict`](/docs/std/collections/dict/Dict/) 字面量已
    重新实现，以提供与 Python 等效的功能和语法，包括
    像 `[1, 2, 3]` 和 `{k1: v1, k2: v2}` 这样的简单字面量。

  - 像
    `[a*b for a in range(10) if isprime(a) for b in range(20)]`
    这样的列表推导式以及字典和集合推导式现在已支持。

  - 使用 `for` 循环遍历集合不再需要使用
    `[]` 解引用操作符。

  更多详情请参阅 [语言增强](#25-4-language-enhancements) 和
  [标准库变更](#25-4-standard-library-changes)。

- 整个 MAX Kernel 库现已完全开源！更多信息
  请参阅 [MAX AI 内核库参考](/docs/lib/#max-ai-kernels-library)
  和
  [MAX AI 内核源码](https://github.com/modular/modular/tree/main/max/kernels)。

- Mojo 现已在 [Godbolt.org](https://godbolt.org) 上可用，该网站
  又称 "Compiler Explorer"。

## 语言增强 {#25-4-language-enhancements}

- 函数中的 `var` 声明现在支持更灵活的 "模式"，允许
  一次声明多个值，例如 `var a, b = 4, 5` 和
  `var a, b : Int, Float64`。

- Mojo 现在支持在首次赋值时声明变量而不使用 `var` 关键字时
  使用 Python 风格的类型模式。例如，`x = 4;
  y: UInt8 = 5` 同时声明了 `x` 和 `y`，其中 `x` 被推断为默认
  类型 `Int`，而 `y` 获得显式类型 `UInt8`。在不使用
  `var` 的情况下声明变量为你提供函数作用域名称，而 `var` 使
  变量作用域限于其所在的语句（词法作用域），例如 `if` 语句的
  主体。

- Mojo 现在支持 `ref` 模式，将存储的 LValue 绑定到命名
  声明中，将参数约定扩展到局部函数作用域。

  当你想对引用执行某些操作，但不
  想要 [`Pointer`](/docs/std/memory/pointer/Pointer/) 的概念开销时，这
  很有用。这两者等价：

  ```mojo
  fn use_pointer(your_list: List[Int]):
      var p = Pointer(to=your_list[i])  # Form a safe pointer
      ...
      use(p[])     # dereference it

  fn use_ref(your_list: List[Int]):
      ref r = your_list[i]  # Bind element reference to 'r'
      ...
      use(r)     # use it
  ```

  引用在其初始化方法中绑定，之后无法修改：
  引用的使用和变更被解释为对
  引用所指向的值的使用和变更。

- 对于符合
  [`Movable`](/docs/std/builtin/value/Movable/)、
  [`Copyable`](/docs/std/builtin/value/Copyable/) 和 `ExplicitlyCopyable`
  （分别）但未显式实现这些方法的结构体，Mojo 编译器现在将合成
  `__moveinit__()`、`__copyinit__()` 和
  `copy()` 方法。

- 新的 [`@fieldwise_init`](/docs/reference/decorators/fieldwise-init/)
  装饰器可附加到结构体上以合成字段初始化方法 — 一个
  `__init__()` 方法，它接受与结构体中的字段相同的参数。
  这使你无需选择加入 `@value` 合成的其余方法即可获得此
  有用能力。此装饰器允许
  使用可选的 `@fieldwise_init("implicit")` 形式用于单元素结构体，这
  会将初始化方法标记为 [`@implicit`](/docs/reference/decorators/implicit/)。

- `try` 和 `raise` 现在可在编译时工作。

- 现在支持使用 "初始化列表" 创建具有基于上下文推断类型的结构体实例，例如：

  ```mojo
  fn foo(x: SomeComplicatedType): ...

  # Example with normal initializer.
  foo(SomeComplicatedType(1, kwarg=42))
  # Example with initializer list.
  foo({1, kwarg=42})
  ```

- 列表字面量已重新设计以更好地工作。它们通过调用由上下文推断的类型 `T` 的
  `T(<elements>, __list_literal__: ())` 构造函数来生成同构
  序列，否则默认为
  标准库 [`List`](/docs/std/collections/list/List/) 类型。
  `ListLiteral` 类型已从标准库中移除。

- 字典和集合字面量现在可以工作，并默认创建
  集合库中的 [`Dict`](/docs/std/collections/dict/Dict/) 和
  [`Set`](/docs/std/collections/set/Set/) 类型的实例。

## 语言变更 {#25-4-language-changes}

- 隐式 trait 一致性已弃用。每个隐式
  一致性实例都会产生警告，但编译仍会通过。很快它将升级为
  错误。当前依赖隐式
  一致性的任何代码都应显式声明一致性，或者在合适的情况下，
  将空的、不承载功能的 trait 替换为 trait 组合。

- Mojo 不再允许将 `out` 或 `mut` 用作参数名。
  此前你可以使用 `fn x(out: Int)`，但这会导致与
  函数类型的歧义。请改为使用像 `output` 这样的名称。

- `def` 参数不再隐式可变。如果你想要
  局部可变的参数，请显式声明为 `owned`。

- 全局（文件作用域）变量已弃用。Mojo 中的全局变量
  仅部分实现，已知会导致隐晦的错误。现在 Mojo
  编译器会在使用全局变量时发出警告。

## 标准库变更 {#25-4-standard-library-changes}

- GPU 编程增强和变更：

  - Mojo 现在支持 AMD GPU，将硬件兼容性从 NVIDIA 扩展到包括
    AMD 的 GPU 生态系统。这使 Mojo 应用程序能够利用
    AMD 的 RDNA 和 CDNA 架构进行高性能计算工作负载，
    为开发者在为 AI 和计算密集型应用程序选择硬件平台时
    提供更大的灵活性。

  - 已添加用于 NVIDIA Blackwell GPU 的原语，提供
    对最新 GPU 架构特性的低级访问。这些原语
    使开发者能够利用 Blackwell 增强的计算
    能力、改进的内存带宽和高级 AI 加速
    特性，包括对较新张量操作和优化内存
    管理模式的支持。请参阅
    [`gpu.tcgen05`](/docs/std/gpu/compute/arch/tcgen05/) 模块 API 参考
    文档以获取更多信息。

  - 添加了对更广泛消费级硬件的支持，包括：
    - NVIDIA RTX 2060 GPU
    - NVIDIA RTX 4090 GPU

  - 修复了
    [`gpu.block`](/docs/std/gpu/primitives/block/) 和
    [`gpu.warp`](/docs/std/gpu/primitives/warp/) 模块中的
    `sum()` 和 `prefix_sum()` 实现。此前，
    这些实现是不正确的，要么返回错误结果，要么
    挂起内核（由于死锁）。[PR
    4508](https://github.com/modular/modular/pull/4508) 和 [PR
    4553](https://github.com/modular/modular/pull/4553) 由 [Kirill
    Bobyrev](https://github.com/kirillbobyrev) 提交，缓解了发现的问题并添加了
    测试以确保未来的正确性。

- 集合类型增强和变更：

  - [`Dict`](/docs/std/collections/dict/Dict/) 类型现在已成为
    prelude 的一部分，因此无需再导入它。

  - [`List`](/docs/std/collections/list/List/)、
    [`Span`](/docs/std/memory/span/Span/)、
    [`Dict`](/docs/std/collections/dict/Dict/)、
    [`Set`](/docs/std/collections/set/Set/)、
    [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 和
    [`Deque`](/docs/std/collections/deque/Deque/) 迭代器现在直接
    返回对元素的引用，而不是返回
    [`Pointer`](/docs/std/memory/pointer/Pointer/)。这意味着你
    不应再在循环索引变量上使用 `[]` 解引用操作符：

    ```mojo
    var states: List[String] = ["California", "Hawaii", "Oregon"]

    # Old:
    for state in states:
      print(state[])

    # New:
    for state in states:
      # state is an immutable reference
      print(state)
    ```

    默认情况下引用是不可变的。你可以使用 `ref` 关键字
    将索引变量绑定为可变引用：

    ```mojo
    for ref state in states:
      # state is a mutable reference
      state += "!"  # Update the existing list element
    ```

  - [`List`](/docs/std/collections/list/List/)、
    [`InlineArray`](/docs/std/collections/inline_array/InlineArray/)、
    [`Deque`](/docs/std/collections/deque/Deque/)、
    [`LinkedList`](/docs/std/collections/linked_list/LinkedList/) 和
    [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型都支持通过
    列表字面量语法进行构造：

    ```mojo
    var list: List[Int] = [1, 2, 3]
    var vec: SIMD[DType.uint8, 8] = [1, 2, 3, 4, 5, 6, 7, 8]
    var deque: Deque[Float64] = [1, 2.5]
    var llist: LinkedList[Int] = [1, 2, 3]
    var arr: InlineArray[String, 3] = ["hi", "hello", "hey"]
    ```

  - [`Dict`](/docs/std/collections/dict/Dict/) 和
    [`Set`](/docs/std/collections/set/Set/) 分别支持通过 dict
    字面量和 set 字面量语法进行构造：

    ```mojo
    var dict1 = {String("foo"): 1, String("bar"): 2}  # Dict[String, Int]
    var dict2 = {1: 4, 2: 7, 3: 18}                   # Dict[Int, Int]
    var set = {1, 2, 3}                               # Set[Int]
    ```

  - 现在支持 Python 风格的列表、字典和集合推导式。例如：

    ```mojo
    # Basic list comprehension using a List[String]
    var upper_strs = [str.upper() for str in strs]  # List[String]

    # Nested list comprehension with conditional expression
    var nums = [a * b for a in range(1, 5) if a % 2 == 0 for b in [-1, 1]]  # List[Int]

    # Dictionary comprehension
    var squares_dict = {num: num * num for num in range(10)}  # Dict[Int, Int]

    # Set comprehension
    var unique_remainders = {num % 4 for num in range(10)}  # Set[Int]
    ```

  - [`BitSet`](/docs/std/collections/bitset/BitSet/) 数据结构已
    添加到 [`collections`](/docs/std/collections/) 包中。这是一个
    固定的 `BitSet`，简化了与一组位一起工作和执行位
    操作。

  - [`VariadicList`](/docs/std/builtin/variadics/VariadicList/)、
    `VariadicListMem` 和
    [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 已移至
    新的 [`variadics`](/docs/std/builtin/variadics/) 模块。

  - `CollectionElement` trait 已被移除。你可以用
    [`Copyable`](/docs/std/builtin/value/Copyable/) 和
    [`Movable`](/docs/std/builtin/value/Movable/) trait，或
    `Copyable & Movable`
    [trait 组合](/docs/manual/traits/#trait-compositions) 替换其任何使用。

Python-Mojo 互操作性增强和变更：

- Python 对象现在可以使用列表、集合和字典字面量语法构造，
  例如：`var list: PythonObject = [1, "foo", 2.0]` 将生成一个 Python
  list，其中包含其他 Python 对象，而 `var d: PythonObject = {}` 将
  构造一个空字典。

- `Python.unsafe_get_python_exception()` 和
  `Python.throw_python_exception_if_error_state()` 已被移除，由
  `Python().cpython().unsafe_get_error()` 和 `Python().cpython().get_error()` 取代。

- 由于对
  [`PythonObject`](/docs/std/python/python_object/PythonObject/) 的几乎任何操作都可能引发异常，
  `PythonObject` 结构体不再实现
  [`Indexer`](/docs/std/builtin/int/Indexer/) 和
  [`Intable`](/docs/std/builtin/int/Intable/) trait。相反，它现在
  符合 [`IntableRaising`](/docs/std/builtin/int/IntableRaising/)，并且
  用户应显式转换为内置类型并按需处理异常。特别是，
  [`PythonObject.__int__()`](/docs/std/python/python_object/PythonObject/#__int__)
  方法现在返回 Python `int` 而不是 mojo `Int`，因此用户必须
  显式转换为 mojo `Int`（如果需要）（并且必须处理
  转换失败时的异常，例如由于溢出）。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 不再
  实现以下 trait：

  - `Stringable`。相反，
    [`PythonObject.__str__()`](/docs/std/python/python_object/PythonObject/#__str__)
    方法现在返回 Python `str` 对象并可引发异常。新的
    [`Python.str()`](/docs/std/python/python/Python/#str) 静态方法也可
    用于将任意 `PythonObject` 转换为 Python `str`
    对象。

  - [`KeyElement`](/docs/std/collections/dict/#keyelement)。由于 Python
    对象可能不可哈希——即使可哈希，它们也可能在
    [`__hash__()`](/docs/std/python/python_object/PythonObject/#__hash__)
    方法中理论上引发异常——`PythonObject` 无法符合
    [`Hashable`](/docs/std/hashlib/hash/Hashable/)。这对
    使用 `PythonObject` 键访问 Python `dict` 对象没有影响，因为
    [`__getitem__()`](/docs/std/python/python_object/PythonObject/#__getitem__)
    和
    [`__setitem__()`](/docs/std/python/python_object/PythonObject/#__setitem__)
    应正确行为并按需引发异常。已添加
    [`Python.dict()`](/docs/std/python/python/Python/#dict) 工厂函数的
    两个重载，以允许从键值元组列表和关键字参数构造字典。

  - `EqualityComparable`。
    [`PythonObject.__eq__()`](/docs/std/python/python_object/PythonObject/#__eq__)
    和
    [`PythonObject.__ne__()`](/docs/std/python/python_object/PythonObject/#__ne__)
    方法需要返回其他 `PythonObject` 值以支持 rich
    比较。之前比较 `PythonObject` 值的代码应包装在
    [`Bool()`](/docs/std/builtin/bool/Bool/#__init__) 中以显式执行
    可失败的转换：`if Bool(obj1 == obj2): ...`。

  - [`Floatable`](/docs/std/builtin/floatable/Floatable/)。向
    [`SIMD`](/docs/std/builtin/simd/SIMD/#__init__) 添加了显式的、
    可引发异常的构造函数，以允许从实现 `__float__()` 的
    `PythonObject` 值构造 `Float64` 值。

- 新的
  [`def_function()`](/docs/std/python/bindings/PythonModuleBuilder/#def_function)
  API 已添加到
  [`PythonModuleBuilder`](/docs/std/python/bindings/PythonModuleBuilder/)，以
  允许为接受和返回
  `PythonObject` 的任意函数声明 Python 绑定。类似地，新的
  [`def_method()`](/docs/std/python/bindings/PythonTypeBuilder/#def_method)
  API 已添加到
  [`PythonTypeBuilder`](/docs/std/python/bindings/PythonTypeBuilder/)，以允许
  为接受和返回 `PythonObject` 的方法声明 Python 绑定。

- [`ConvertibleFromPython`](/docs/std/python/conversions/ConvertibleFromPython/)
  trait 现已公开。此 trait 由可通过从 `PythonObject` 转换而构造的
  Mojo 类型实现。这是
  `PythonConvertible`
  trait 的反向操作。

- [`Bool`](/docs/std/builtin/bool/Bool/)、
  [`Int`](/docs/std/builtin/int/Int/) 和
  [`String`](/docs/std/collections/string/string/String/) 现在实现
  `ConvertibleFromPython`。

- [`PythonObject(alloc=<value>)`](/docs/std/python/python_object/PythonObject/#__init__)
  是一个新的构造函数，可用于直接将 Mojo 值存储在 Python
  对象中。

  如果提供的 Mojo 值类型之前未使用
  [`PythonModuleBuilder.add_type()`](/docs/std/python/bindings/PythonModuleBuilder/#add_type)
  全局注册相应的 Python `type` 对象，此初始化方法将失败。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 具有
  向下转换为所含 Mojo 值指针的新方法，用于
  Python/Mojo 互操作。

  ```mojo
  struct Person:
      var name: String

  fn greet(obj: PythonObject) raises:
    var person = obj.downcast_value_ptr[Person]()

    print("Hello ", person[].name, "from Mojo🔥!")
  ```

  - [`PythonObject.downcast_value_ptr[T]()`](/docs/std/python/python_object/PythonObject/#downcast_value_ptr)
    检查对象是否是 Mojo 类型 `T` 的包装实例，如果是，
    返回一个 `UnsafePointer[T]`。否则，引发异常。

  - [`PythonObject.unchecked_downcast_value_ptr[T]()`](/docs/std/python/python_object/PythonObject/#unchecked_downcast_value_ptr)
    无条件返回 `UnsafePointer[T]`，无任何运行时类型
    检查。当使用 Python/Mojo 互操作优化内部
    循环并最小化开销时，这很有用。

    还添加了用于从 `PythonObject` 向下转换的等效
    [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/#__init__)
    初始化方法。

  - `TypedPythonObject` 类型已被移除。请改为使用 `PythonObject`。

  - `Python.is_type(x, y)` 静态方法已被移除。请改为使用
    表达式 `x is y`。

- [`os.abort(messages)`](/docs/std/os/os/abort/) 不再支持
  可变数量的 [`Writable`](/docs/std/format/Writable/) 消息。
  虽然此 API 是高级且方便的，但它为
  简单和常见的情况生成了大量 IR，例如当我们有单个 `StringLiteral`
  消息时。我们现在不再需要生成大量臃肿的 IR，相反，
  调用方必须在调用
  `os.abort(message)` 之前在他们那边创建 `String`。

- [`atof()`](/docs/std/collections/string/string/atof/) 函数已
  完全重写，因为对于非常低和非常高的
  指数，它产生了不正确的结果。它现在对于 `e` 左侧少于 19 位的
  字符串正确工作。例如 `1.1385616158185648648648648648616186186e-3` 不
  工作，将引发错误。任何不产生错误的内容现在都保证
  是正确的。虽然当前实现不是最快的，
  但它基于 Daniel Lemire 的论文 [Number Parsing at a Gigabyte per
  Second](https://arxiv.org/abs/2101.11408)。因此，稍加努力确定
  慢速部分，我们可以在未来轻松拥有最先进的
  性能。

- [`math.isclose()`](/docs/std/math/math/isclose/) 函数现在通过新的
  `symmetrical` 参数支持对称（Python 风格）和非对称（NumPy 风格）比较模式。
  该参数默认为新添加的
  对称支持。该函数现在仅支持浮点类型，
  移除了之前对整数和布尔类型的伪支持。支持由
  [PR 4608](https://github.com/modular/modular/pull/4608) 中的
  [@soraros](https://github.com/soraros) 添加。

- [`compile`](/docs/std/compile/) 模块现在提供
  [`get_type_name()`](/docs/std/reflection/type_info/get_type_name/) 函数
  以获取类型的完全限定名。例如，
  `compile.get_type_name[Int]()` 返回 `"std.builtin.int.Int"`。

## 工具链变更 {#25-4-tooling-changes}

- 添加了使用
  `--emit=llvm` 发出 LLVM 中间表示 (.ll) 的支持。
  - 示例用法：`mojo build --emit=llvm YourModule.mojo`

- 移除了对命令行选项 `--emit-llvm` 的支持，由
  `--emit=llvm` 取代。

- 添加了使用 `--emit=asm` 发出汇编代码 (.s) 的支持。
  - 示例用法：`mojo build --emit=asm YourModule.mojo`

- 为通过 [`mojo
  doc`](/docs/cli/doc) 生成的文档添加了关联别名支持。

- 为 [`mojo
  format`](/docs/cli/format) 添加了 struct 和 trait 一致性列表排序支持。

## 已移除 {#25-4-removed}

- `VariadicPack.each()` 和 `VariadicPack.each_idx()` 方法已被移除。
  请使用 [`@parameter
  for`](/docs/reference/decorators/parameter#parametric-for-statement)
  语言构造现在来实现此功能。`write_buffered()` 和
  `write_args()` 函数也已移除，以提高编译速度并
  减少 GPU 上的寄存器压力，你现在应在
  每个调用点展开可变参数包：

  Unbuffered：

  ```mojo
  fn write[*Ts: Writable](mut self, *args: *Ts):
      var string = String()

      @parameter
      for i in range(args.__len__()):
          args[i].write_to(string)
  ```

  Buffered：

  ```mojo
  from utils.write import _WriteBufferStack

  fn write[*Ts: Writable](mut self, *args: *Ts):
      var string = String()
      var buffer = _WriteBufferStack(string)

      @parameter
      for i in range(args.__len__()):
          args[i].write_to(buffer)

      buffer.flush()
  ```
