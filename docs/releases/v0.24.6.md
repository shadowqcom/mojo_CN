## Highlights

以下是本版本一些主要变更的简明摘要,更多详情见后续章节:

- `inout` 和 `borrowed` 参数约定已分别重命名为 `mut` 和 `read`。新增 `out` 约定用于构造器中的 `self` 参数和命名结果。详情请参阅[语言变更](#24-6-language-changes)。

- 标准库中的 `Lifetime` 及相关类型已重命名为 [`Origin`](/docs/std/builtin/type_aliases/Origin/),以更清晰地表明该类型的参数指示引用派生自何处,而不是更复杂的"变量在何处初始化和销毁"的概念。因此,`__lifetime_of()` 操作符现在命名为 `__origin_of()`。

  本版本中还有许多其他与 origin 相关的改进,包括通过在 `__origin_of()` 操作符中或 `ref` origin 说明符(`ref [a, b]`)内列出多个值来指定 origin 的并集。详情请参阅[语言变更](#24-6-language-changes)。

  有关名称变更的背景信息和理由,请参阅[该提案](https://github.com/modular/modular/issues/3623)。有关 origin 的更多信息,请参阅 Mojo 手册中的[Lifetime、origin 和引用](/docs/manual/values/lifetimes/)。

- 隐式转换现在通过 [`@implicit`](/docs/reference/decorators/implicit/) 装饰器可选启用。详情请参阅[语言变更](#24-6-language-changes)。

- 标准库添加了若干新类型,包括 [`Deque`](/docs/std/collections/deque/Deque/)(双端队列)和 [`OwnedPointer`](/docs/std/memory/owned_pointer/OwnedPointer/)(安全、单所有者、不可空智能指针)。详情请参阅[标准库变更](#24-6-standard-library-changes)。

- VS Code 扩展现在支持设置数据断点和函数断点,Mojo LLDB 调试器支持符号断点,例如 `b main` 或 `b my_module::main`。

- 我们对错误信息、LSP 和生成的 API 文档中信息的显示方式做了若干改进。详情请参阅[工具变更](#24-6-tooling-changes)。

- 我们还添加了许多新文档,包括全新的 [Mojo 教程](/docs/manual/get-started/)、关于[操作符和表达式](/docs/manual/operators/)、[错误处理](/docs/manual/errors/)和[指针](/docs/manual/pointers/)的新页面,以及许多较小的添加和改进。

## Language changes {#24-6-language-changes}

- 参数约定变更:

  - `inout` 和 `borrowed` 参数约定已分别重命名为 `mut`(表示"mutate")和 `read`。这些动词反映了被调用方可以对调用方传入的参数值做什么,而无需程序员了解引用等高级特性。

    有关 Mojo 的参数约定,请参阅 Mojo 手册中的[参数约定](/docs/manual/values/ownership/#argument-conventions)。

  - `__init__()`、`__copyinit__()` 和 `__moveinit__()` 方法中 `self` 参数的参数约定已从 `inout` 改为 `out`,反映构造器方法在不读取 `self` 值的情况下初始化它。这也使得正确拼写初始化器的类型成为可能,这在以前是不支持的:

    ```mojo
    struct Foo:
        fn __init__(out self): pass

    fn test():
        # This works now
        var fnPtr : fn(out x: Foo)->None = Foo.__init__

        var someFoo : Foo
        fnPtr(someFoo)  # initializes someFoo.
    ```

    以前的 `fn __init__(inout self)` 语法在本版本 Mojo 中仍受支持,但未来将被移除。请迁移到新语法。

  - 类似地,命名结果的拼写已切换为使用 `out` 语法,而不是 `-> T as name`。函数最多可以有一个命名结果或使用通常 `->` 语法指定的返回类型。`out` 参数可出现在参数列表的任何位置,但通常是最后一个(除了 `__init__` 方法,它们通常是第一个)。

    ```mojo
    # This function has type "fn() -> String"
    fn example(out result: String):
      result = "foo"
    ```

    解析器仍接受旧语法作为同义词,但最终将被弃用并移除。

    这在[公开提案中进行了广泛讨论](https://github.com/modular/modular/issues/3623)。更多信息,请参阅 Mojo 手册中的[命名结果](/docs/manual/functions/#named-results)。

- 单参数构造器现在需要 [`@implicit`](/docs/reference/decorators/implicit/) 装饰器才允许隐式转换。以前你可以定义一个接受单个参数的 `__init__`:

  ```mojo
  struct Foo:
      var value: Int

      fn __init__(out self, value: Int):
          self.value = value
  ```

  这将允许你在 `Foo` 的位置传递一个 `Int`:

  ```mojo
  fn func(foo: Foo):
      print("implicitly converted Int to Foo:", foo.value)

  fn main():
      func(Int(42))
  ```

  这可能导致难以调试的复杂错误。默认情况下,此隐式行为现在被关闭,因此你必须显式构造 `Foo`:

  ```mojo
  fn main():
      func(Foo(42))
  ```

  你仍可以通过添加 `@implicit` 装饰器选择启用隐式转换。例如,要启用从 `Int` 到 `Foo` 的隐式转换:

  ```mojo
  struct Foo:
      var value: Int

      @implicit
      fn __init__(out self, value: Int):
          self.value = value
  ```

  更多信息请参阅 Mojo 手册中的[构造器和隐式转换](/docs/manual/lifecycle/life#constructors-and-implicit-conversion)。

- 与 origin 相关的变更:

  - `AnyLifetime` 类型(用于将 origin 类型声明为参数)已重命名为 [`Origin`](/docs/std/builtin/type_aliases/Origin/),`__lifetime_of()` 操作符重命名为 `__origin_of()`。

  - `Origin` 现在是 MLIR origin 类型的完整包装。

    - `Origin.type` 别名已重命名为 `_mlir_origin`。在参数列表中,你现在可以直接写 `Origin[..]`,而不是 `Origin[..].type`。

    - `ImmutableOrigin` 和 `MutableOrigin` 现在分别只是 `Origin[False]` 和 `Origin[True]` 的别名。

    - 现在支持在 `ref [..]` 参数的 origin 说明符中使用 `Origin` struct 值。

    - 添加了 `Origin.cast_from` 用于转换 origin 值的可变性。

  - `ref` 参数和结果现在允许直接在 origin 说明符中提供内存值,而不需要使用 `__origin_of()`。不过,显式使用 `__origin_of()` 仍然可以,并且在为参数(例如 `Pointer` 类型的参数)指定 origin 时需要这样做。例如,以下写法现在无需 `__origin_of()` 也有效:

    ```mojo
    fn return_ref(a: String) -> ref [a] String:
        return a
    ```

  - 已合并若干 origin 处理和语法的改进,包括支持三元操作符以及允许在 `ref` 说明符中使用多个参数(它们隐式地是并集)。这能够清晰地表达简单算法:

    ```mojo
    fn my_min[T: Comparable](ref a: T, ref b: T) -> ref [a, b] T:
      return a if a < b else b
    ```

    `my_min` 自动且隐式地传播其参数的可变性也很好,所以诸如 `my_min(str1, str2) += "foo"` 之类的写法是有效的。

  - 不带 origin 子句的 `ref` 函数参数现在被视为 `ref [_]`,这在语法上更便利和一致:

    ```mojo
    fn takes_and_return_ref(ref a: String) -> ref [a] String:
        return a
    ```

  - `__type_of(x)` 和 `__origin_of(x)` 操作符现在更通用:它们允许内部有任意表达式,允许在参数上下文中引用动态值,甚至允许在非 raising 上下文中引用 raising 函数。这些操作从不求值其表达式,因此表达式中发生的任何副作用都不会在运行时被求值,消除了对 `__type_of(expensive())` 可能成为问题的担忧。

  - Mojo 中的析构器插入逻辑现在知道,在签名中接受 `MutableAnyOrigin` 或 `ImmutableAnyOrigin` 的类型可能访问析构器插入正在跟踪的任何活跃值,消除了诸如 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 等不安全 API 的重大可用性问题。考虑在此变更之前使用字符串的典型示例:

    ```mojo
    var str = String(...)
    var ptr = str.unsafe_ptr()
    some_low_level_api(ptr)
    _ = str^  # OLD HACK: Explicitly keep string alive until here!
    ```

    以前需要 `_ = str^` 模式,因为 Mojo 编译器不知道"ptr"可能引用什么。因此,它不知道 `some_low_level_api()` 可能访问 `str`,因此认为在调用之前销毁 `String` 是可以的——这就是为什么需要显式延长 lifetime 的原因。

    Mojo 现在知道 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 可能访问 `MutableAnyOrigin` origin,并假设使用该 origin 的任何 API 都可能使用活跃值。在这种情况下,它假设 `some_low_level_api()` 可能访问 `str`,由于它可能正在使用它,因此不能在调用之前销毁 `str`。这样做的结果是,对于这些情况,旧的 hack 不再需要了!

  - 函数类型现在接受一个 origin 集合参数。此参数表示参数闭包捕获的值的 origin。编译器自动用正确的 origin 集合标记参数闭包。这使得 lifetime 和参数闭包能够正确组合。

    ```mojo
    fn call_it[f: fn() capturing [_] -> None]():
        f()

    fn test():
        var msg = String("hello world")

        @parameter
        fn say_hi():
            print(msg)

        call_it[say_hi]()
        # no longer need to write `_ = msg^`!!
    ```

    请注意,这仅适用于已显式添加 `[_]` 作为捕获 origin 的高阶函数。默认情况下,编译器仍假设 `capturing` 闭包不引用任何 origin。这很快会改变。

- 仅推断参数现在可以通过关键字显式绑定,启用了标准库中的一些重要模式:

  ```mojo
  struct StringSlice[is_mutable: Bool, //, origin: Origin[is_mutable]]: ...
  alias ImmStringSlice = StringSlice[is_mutable=False]
  # This auto-parameterizes on the origin, but constrains it to being an
  # immutable slice instead of a potentially mutable one.
  fn take_imm_slice(a: ImmStringSlice): ...
  ```

- 用于开启断言的标志已更改,例如要启用所有检查:

  ```bash
  mojo -D ASSERT=all main.mojo
  ```

  级别为:

  - `none`:所有断言关闭
  - `warn`:打印断言错误,例如用于多线程测试(以前为 `-D
    ASSERT_WARNING`)
  - `safe`:标准 CPU 安全断言的默认模式
  - `all`:开启所有断言(以前为 `-D MOJO_ENABLE_ASSERTIONS`)

  你现在还可以传递 `Stringable` 参数来格式化消息,在断言关闭时不会有运行时开销或 IR 膨胀成本。以前你必须:

  ```mojo
  x = -1
  debug_assert(
    x > 0, String.format_sequence(“expected x to be more than 0 but got: ”, x)
  )
  ```

  这在发布构建中无法被编译器优化掉,你现在可以传递多个参数以无运行时成本格式化消息:

  ```mojo
  debug_assert(x > 0, “expected x to be more than 0 but got: ”, x)
  ```

- 现在支持参数的自动参数化。指定具有未绑定参数的参数化类型会导致它们作为仅推断参数被隐式添加到函数签名中。

  ```mojo
  fn foo[value: SIMD[DType.int32, _]]():
    pass

  # Equivalent to
  fn foo[size: Int, //, value: SIMD[DType.int32, size]]():
    pass
  ```

- Mojo 现在可以在参数表达式中解释简单的 LLVM 内联函数,使诸如 `count_leading_zeros` 等能在编译时工作:
  [Issue #933](https://github.com/modular/modular/issues/933)。

- 引入了 `@explicit_destroy` 注解、`__disable_del` 关键字、`UnknownDestructibility` trait 和 `ImplicitlyDestructible` 关键字,用于实验性的显式销毁类型特性。

- 添加了关联类型;我们现在可以在 trait中拥有诸如 `alias T: AnyType`、`alias N: Int` 等别名,然后在遵循该 trait 的 struct 中指定它们。更多信息,请参阅[泛型的关联别名](/docs/manual/traits#associated-aliases-for-generics)。

## Standard library changes {#24-6-standard-library-changes}

- 引入了新的 [`Deque`](/docs/std/collections/deque/Deque/)(双端队列)集合类型,基于动态调整大小的循环缓冲区,在两端进行高效的 O(1) 添加和移除,以及对所有元素的 O(1) 直接访问。

  `Deque` 支持完整的 Python `collections.deque` API,确保所有预期的 deque 操作行为与 Python 一致。

  对标准 Python API 的增强包括用于非破坏性访问最后一个和第一个元素的 `peek()` 和 `peekleft()` 方法,以及用于自定义内存分配和性能的高级构造器选项(`capacity`、`min_capacity` 和 `shrink`)。这些选项允许优化的内存使用和减少的缓冲区重新分配,根据应用需求提供灵活性。

- `Formatter` struct 已被 [`Writer`](/docs/std/format/Writer/) trait 取代,以启用缓冲 IO,将打印和文件写入性能提升至与 C 相同的速度。它现在更通用,可以写入任何 `Span[Byte]`。为与此对齐,`Formattable` trait 现命名为 [`Writable`](/docs/std/format/Writable/),用于初始化新 `String` 的 `String.format_sequence()` 静态方法已重命名为 [`String.write()`](/docs/std/collections/string/string/String/#write)。以下是使用所有变更的示例:

  ```mojo
  from memory import Span

  @value
  struct NewString(Writer, Writable):
      var s: String

      # Writer requirement to write a Span of Bytes
      fn write_bytes(inout self, bytes: Span[Byte, _]):
          self.s._iadd[False](bytes)

      # Writer requirement to take multiple args
      fn write[*Ts: Writable](inout self, *args: *Ts):
          @parameter
          fn write_arg[T: Writable](arg: T):
              arg.write_to(self)

          args.each[write_arg]()

      # Also make it Writable to allow `print` to write the inner String
      fn write_to[W: Writer](self, inout writer: W):
          writer.write(self.s)


  @value
  struct Point(Writable):
      var x: Int
      var y: Int

      # Pass multiple args to the Writer. The Int and StringLiteral types call
      # `writer.write_bytes` in their own `write_to` implementations.
      fn write_to[W: Writer](self, inout writer: W):
          writer.write("Point(", self.x, ", ", self.y, ")")

      # Enable conversion to a String using `str(point)`
      fn __str__(self) -> String:
          return String.write(self)


  fn main():
      var point = Point(1, 2)
      var new_string = NewString(str(point))
      new_string.write("\n", Point(3, 4))
      print(new_string)
  ```

  ```output
  Point(1, 2)
  Point(3, 4)
  ```

- `TypeIdentifiable` trait 已被移除,改为 `compile.reflection` 模块中新的 `get_type_name` 工具。

- Python 互操作变更:

  - 引入了 `TypedPythonObject`,作为用静态类型信息注释 [`PythonObject`](/docs/std/python/python_object/PythonObject/) 值的轻量方式。此设计可能会显著演进和变化。

    - 添加了 `TypedPythonObject[Tuple].__getitem__()`,用于访问 Python tuple 的元素。

  - 添加了 [`Python.add_object()`](/docs/std/python/python/Python/#add_object),用于将命名的 `PythonObject` 值添加到 Python "module" 对象实例。

  - 添加了 [`Python.unsafe_get_python_exception()`](/docs/std/python/python/Python/#unsafe_get_python_exception),作为获取当前 CPython 错误状态对应的 Mojo `Error` 的高效低层实用工具。

  - 添加 [`PythonObject.from_borrowed_ptr()`](/docs/std/python/python_object/PythonObject/#from_borrowed_ptr),以简化从 CPython"借用引用"指针构造 `PythonObject` 值的过程。

    对于从"强引用"指针构造 `PythonObject` 的更常见情况,应继续使用现有的 `PythonObject.__init__(PyObjectPtr)`。

  - 支持 `PythonObject` 的多维索引和切片
    (PR [#3549](https://github.com/modular/modular/pull/3549),
    PR [#3583](https://github.com/modular/modular/pull/3583))。

    ```mojo
    var np = Python.import_module("numpy")
    var a = np.array(PythonObject([1,2,3,4,5,6])).reshape(2,3)
    print((a[0, 1])) # 2
    print((a[1][::-1])) # [6 5 4]
    ```

    请注意,语法 `a[1, ::-1]` 当前不受支持。

  - 添加了 [`PythonObject.__contains__()`](/docs/std/python/python_object/PythonObject/#__contains__)。([PR #3101](https://github.com/modular/modular/pull/3101))

    示例用法:

    ```mojo
    x = PythonObject([1,2,3])
    if 1 in x:
        print("1 in x")
    ```

- 指针相关变更:

  - [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 类型现在拥有一个 `origin` 参数,可在 `UnsafePointer` 指向具有已知 origin 的值时使用。此 origin 通过 `ptr[]` 间接操作传播。此参数和其他 `UnsafePointer` 参数(类型除外)现在仅关键字。

  - 你现在可以使用 `SIMD` 标量整数类型对 `UnsafePointer` 进行索引:

    ```mojo
    p = UnsafePointer[Int].alloc(1)
    i = UInt8(1)
    p[i] = 42
    print(p[i])
    ```

  - 新增 [`OwnedPointer`](/docs/std/memory/owned_pointer/OwnedPointer/) 类型,作为安全、单所有者、不可空智能指针,具有与 Rust 的 [`Box<>`](https://doc.rust-lang.org/std/boxed/struct.Box.html) 和 C++ 的 [`std::unique_ptr`](https://en.cppreference.com/w/cpp/memory/unique_ptr) 类似的语义。
    ([PR #3524](https://github.com/modular/modular/pull/3524))

  - `Arc` 已重命名为 [`ArcPointer`](/docs/std/memory/arc_pointer/ArcPointer/),以与 `OwnedPointer` 保持一致。

  - [`ArcPointer`](/docs/std/memory/arc_pointer/ArcPointer/) 现在实现了 [`Identifiable`](/docs/std/builtin/identifiable/Identifiable/),可使用 `a is b` 进行指针等价比较。

  - `Reference` 类型已重命名为 [`Pointer`](/docs/std/memory/pointer/Pointer/):`UnsafePointer` 的内存安全补充。此变更的动机是 `Pointer` 是可赋值的,且需要用 `ptr[]` 显式解引用。重命名为 `Pointer` 澄清了"引用"指的是 `ref` 参数和结果,并为我们提供了一个更接近 C++ 社区所期望的模型。

    有关 Mojo 指针类型的概述,请参阅 Mojo 手册中新的[指针简介](/docs/manual/pointers/)页面。

  - 为 `UnsafePointer` 添加了新的 [`as_noalias_ptr()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#as_noalias_ptr) 方法。此方法向编译器指定结果指针是一个独特的可识别对象,不别名本地作用域中的任何其他内存。

- 添加了 [`Floatable`](/docs/std/builtin/floatable/Floatable/) 和 [`FloatableRaising`](/docs/std/builtin/floatable/FloatableRaising/) trait,用于表示可使用内置 `float` 函数转换为 `Float64` 值的类型。使 `SIMD` 和 `FloatLiteral` 遵循 `Floatable` trait。([PR #3163](https://github.com/modular/modular/pull/3163))

  ```mojo
  fn foo[F: Floatable](v: F):
    ...

  var f = float(Int32(45))
  ```

- [`rebind()`](/docs/std/builtin/rebind/rebind/) 标准库函数现在除 `@register_passable("trivial")` 类型外,还可用于仅内存类型,无需拷贝。更多信息,请参阅 Mojo 手册中的[`rebind()` 内置](/docs/manual/parameters/#the-rebind-builtin)。

- 引入了 [`random.shuffle()`](/docs/std/random/random/shuffle/) 函数,用于随机化 `List` 的元素。
  ([PR #3327](https://github.com/modular/modular/pull/3327))

  示例:

  ```mojo
  from random import shuffle

  var l = List[Int](1, 2, 3, 4, 5)
  shuffle(l)
  ```

- [`Dict.__getitem__()`](/docs/std/collections/dict/Dict/#__getitem__) 方法现在返回引用,而不是值的副本(或抛出错误)。这通过允许从 `Dict` 元素借用,改善了使用 `Dict` 的常见代码的性能。

- [`Slice.step`](/docs/std/builtin/builtin_slice/Slice/#fields) 现在是 `Optional[Int]`,与 Python 中 `slice.step` 的可选性匹配。
  ([PR #3160](https://github.com/modular/modular/pull/3160))

- 现在有一个 [`Byte`](/docs/std/builtin/simd/#aliases) 别名,以便在处理位包时更好地表达意图。
  ([PR #3670](https://github.com/modular/modular/pull/3670))。

- 用新函数扩展了 [`os.path`](/docs/std/os/path/path/):
  - `os.path.expandvars()`:展开路径中的环境变量
    ([PR #3735](https://github.com/modular/modular/pull/3735))。
  - `os.path.splitroot()`:将路径拆分为驱动器、根和尾部。
  ([PR #3780](https://github.com/modular/modular/pull/3780))。

- 为 `String` struct 添加了 [`reserve()`](/docs/std/collections/string/string/String/#reserve) 方法和新的构造器,以分配额外容量。([PR #3755](https://github.com/modular/modular/pull/3755))。

- 新的 [`StringLiteral.get[some_stringable]()`](/docs/std/builtin/string_literal/StringLiteral/#get) 方法可用。它允许从编译时动态的 `Stringable` 值形成运行时常量的 `StringLiteral`。

- [`Span`](/docs/std/memory/span/Span/) 已从 `utils` 模块移至 `memory` 模块。

- [`Span`](/docs/std/memory/span/Span/) 现在实现了 `__reversed__()`。这意味着可以使用 `reversed(my_span)` 获取 `Span` 的反向迭代器。用户当前应优先使用此方法,而不是 `my_span[::-1]`。

- 新增 `AsBytes` trait,用于从任何实现 `as_bytes()` 的类型获取 `Span[Byte]`。`String.as_bytes()` 和 `String.as_bytes_slice()` 已合并到 `String.as_bytes()` 下,以返回 `Span[Byte]`。如果你需要副本,可以使用 `List(my_string.as_bytes())` 将 `Span` 转换为 `List`。

- [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 现在实现了 `strip()`、`rstrip()` 和 `lstrip()`。

- [`StringRef`](/docs/std/collections/string/string_slice/StringSlice/) 现在实现了 `split()`,可用于按分隔符将 `StringRef` 拆分为 `List[StringRef]`。([PR
  #2705](https://github.com/modular/modular/pull/2705))

- [`StringRef`](/docs/std/collections/string/string_slice/StringSlice/) 现在可表示,因此 `repr(StringRef("hello"))` 将返回 `StringRef('hello')`。

- 从 Mojo 标准库 `prelude` 模块自动导出的实体集合中移除了更多内容:
  - `UnsafePointer` 已被移除。请通过 `from memory import UnsafePointer` 显式导入。
  - `StringRef` 已被移除。请通过 `from utils import StringRef` 显式导入。

- 恢复了 [`Tuple`](/docs/std/builtin/tuple/Tuple/) 和 `ListLiteral` 的隐式可拷贝性。

- [C 外部函数接口 (FFI) 的别名](/docs/std/ffi/#aliases)已重命名:`C_int` -> `c_int`、`C_long` -> `c_long` 等。

- `Float32` 和 `Float64` 现在以可往返保证和最短表示进行打印和转换为字符串:

  ```plaintext
  Value                       Old                       New
  Float64(0.3)                0.29999999999999999       0.3
  Float32(0.3)                0.30000001192092896       0.3
  Float64(0.0001)             0.0001                    0.0001
  Float32(0.0001)             9.9999997473787516e-05    0.0001
  Float64(-0.00001)           -1.0000000000000001e-05   -1e-05
  Float32(-0.00001)           -9.9999997473787516e-06   -1e-05
  Float32(0.00001234)         1.2339999557298142e-05    1.234e-05
  Float32(-0.00000123456)     -1.2345600453045336e-06   -1.23456e-06
  Float64(1.1234567e-320)     1.1235052786429946e-320   1.1235e-320
  Float64(1.234 * 10**16)     12340000000000000.0       1.234e+16
  ```

- `utils` 包中的 `StaticIntTuple` 数据结构已重命名为 [`IndexList`](/docs/std/utils/index/IndexList/)。该数据结构现在允许指定元素的索引位宽以及底层索引是有符号还是无符号。

- 添加了 [`DLHandle.get_symbol()`](/docs/std/ffi/OwnedDLHandle/#get_symbol),用于获取动态库中符号的指针。这比现有的获取函数指针的方法更通用。

## Tooling changes {#24-6-tooling-changes}

- VS Code Mojo 调试器现在拥有 `buildArgs` JSON 调试配置设置,可与 `mojoFile` 一起使用,以定义编译 Mojo 文件时的构建参数。

- VS Code 扩展现在支持 `Configure Build and Run Args` 命令,帮助设置 `Run Mojo File` 和 `Debug Mojo File` 操作文件的构建和运行参数。在 Mojo 文件右上角的 `Run and Debug` 选择器中会出现相应按钮。

- VS Code 扩展现在拥有 `mojo.run.focusOnTerminalAfterLaunch` 设置,用于控制启动后是聚焦于 `Mojo: Run Mojo File` 命令使用的终端还是编辑器。
  [Issue #3532](https://github.com/modular/modular/issues/3532)。

- VS Code 扩展现在拥有 `mojo.SDK.additionalSDKs` 设置,允许用户提供扩展在确定要使用的默认 SDK 时可使用的 MAX SDK 列表。用户可以使用 `Mojo: Select the default MAX SDK` 命令选择要使用的默认 SDK。

- VS Code 扩展现在支持设置[数据断点](https://code.visualstudio.com/docs/editor/debugging#_data-breakpoints)和[函数断点](https://code.visualstudio.com/docs/editor/debugging#_function-breakpoints)。

- Mojo LLDB 调试器现在支持符号断点,例如 `b main` 或 `b my_module::main`。

- 包含类型名的错误信息不再包含推断或默认参数(除非需要)。例如,以前 Mojo 抱怨如下内容:

  ```plaintext
  ... cannot be converted from 'UnsafePointer[UInt, 0, _default_alignment::AnyType](), MutableAnyOrigin]' to 'UnsafePointer[Int, 0, _default_alignment[::AnyType](), MutableAnyOrigin]'
  ```

  现在它更有帮助地抱怨:

  ```plaintext
  ... cannot be converted from 'UnsafePointer[UInt]' to 'UnsafePointer[Int]'
  ```

- 工具现在正确打印 `ref` 参数和结果的 origin,并在方法中打印 `self` 而不是 `self: Self`。

- Mojo Language Server 和生成的文档现在正确打印参数化结果类型,例如显示 `SIMD[type, simd_width]` 而不是 `SIMD[$0, $1]`。

- 生成的 API 文档现在显示 struct 的签名,并标识 `@register_passable` 和 `@register_passable("trivial")` 类型。

- VS Code 扩展现在允许取消其私有 MAX SDK 的安装。

- VS Code 扩展现在在调试会话开始时自动打开 Run and Debug 标签页。

- `mojo debug --vscode` 命令现在支持 `--init-command` 和 `--stop-on-entry` 标志。执行 `mojo debug --help` 获取更多信息。

- VS Code 上的 Mojo LLDB 调试器现在支持检查作为合成类型处理的变量的原始属性,例如 Mojo 的 `List` 或 C++ 的 `std::vector`。

- VS Code 扩展现在允许在有多个可用 SDK 时选择默认 SDK。

## Removed

- 已移除 `DType` 的 `UnsafePointer.bitcast()` 重载。请将你的 `DType` 包装在 `Scalar[my_dtype]` 中,以调用现在唯一的 `bitcast()` 重载。
