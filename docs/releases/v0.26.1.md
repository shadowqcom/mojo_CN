## 亮点 {#26-1-highlights}

- **扩展的 reflection 模块。** `reflection` 模块现在提供丰富的编译期内省能力：结构体字段枚举、类型与字节偏移；源位置追踪；以及对动态获取类型的 trait 一致性检查。这些 API 支持高级元编程模式，例如自动序列化和调试格式化。参见 [Reflection 与内省](#26-1-reflection)。

- **显式销毁类型。** Mojo 现在一等支持显式销毁类型（有时被称为“线性类型”linear types）。`AnyType`、`Movable` 和 `Copyable` trait 不再要求 `__del__()` 方法；当需要隐式销毁时请使用 `ImplicitlyDestructible`。显式销毁类型可让你编码出要求显式资源处理的强大不变量。参见 [语言变更](#26-1-language-changes) 和 [显式销毁类型](#26-1-explicitly-destroyed-types)。

- **带类型的错误。** 函数现在可以指定它们抛出的类型，而不必默认使用 `Error`（例如 `fn foo() raises CustomError -> Int`）。带类型的错误非常高效——它们编译为一种替代返回值，不进行栈展开——使其适用于 GPU 和嵌入式目标。参见 [语言增强](#26-1-language-enhancements)。

- **带默认实现的 trait。** `Hashable`、`Writable` 和 `Equatable` trait 现在提供默认实现，可利用 reflection 自动从结构体字段派生行为。简单结构体无需编写任何样板代码即可符合这些 trait——只需确保所有字段都符合相同 trait。参见 [带默认实现的 trait](#26-1-trait-defaults)。

- **`UInt` 类型重新设计。** `UInt` 结构体已被替换为 `Scalar[DType.uint]` 的类型别名，从而支持更强大的、面向机器字长无符号 SIMD 数据类型的泛型编程。参见 [其他库变更](#26-1-other-library)。

- **String 的 UTF-8 安全性。** `String` 现在提供三个显式构造器用于原始字节：`from_utf8=`（校验并在出错时抛出）、`from_utf8_lossy=`（将无效序列替换为 �）和 `unsafe_from_utf8=`（不做校验）。这使得 UTF-8 处理保证在构造时就明确表达。参见 [String 与文本](#26-1-string-and-text)。

## 语言增强 {#26-1-language-enhancements}

- Mojo 现在支持抛出“带类型的错误”，函数可以指定它抛出什么类型，而不必默认使用
  [`Error`](/docs/std/builtin/error/Error/) 类型。这是通过在 `raises` 关键字之后指定类型来完成的，例如 `fn foo() raises CustomError -> Int`。

  Mojo 中抛出的错误非常高效——它们作为一种替代返回值工作：例如，一个形如 `fn () raises Int -> Float32:` 的函数会编译成要么返回 `Int`、要么返回 `Float32` 的代码，并使用一个隐式布尔结果来判断哪个是有效的——其中不涉及昂贵的栈展开或缓慢的动态逻辑。这意味着抛出的错误在 GPU 和其他嵌入式目标上也能良好工作。

  `try` 块中“被捕获”的类型会被自动推断为 `try` 体内抛出的第一个类型，例如：

  ```mojo
  try:
      print(foo())
  except err:       # "err" is typed as CustomError
      print(err)
  ```

  带类型的抛出与泛型“开箱即用”地配合，允许定义如下高阶函数：

  ```mojo
  fn parametric_raise_example[ErrorType: AnyType](fp: fn () raises ErrorType) raises ErrorType:
      # ... presumably some iteration or other exciting stuff happening here.
      fp()
  ```

  这与其他支持配合，可允许上下文相关的泛型抛出类型，例如：

  ```mojo
  fn call_parametric_raise_example[GenTy: AnyType](func_ptr: fn () raises GenTy):
    fn raise_int() raises Int: pass
    try:
        parametric_raise_example(raise_int)
    except err_int:   # Typed as Int
        ref x: Int = err_int

    fn raise_string() raises String: pass
    try:
      parametric_raise_example(raise_string)
    except err_string: # Typed as String
        ref s: String = err_string

    try:
      parametric_raise_example(func_ptr)
    except err_gen: # Typed as GenTy
        ref s: GenTy = err_gen

    # Non-raising functions infer an error type of `Never`, allowing these
    # functions to propagate non-raisability across generic higher-order
    # functions conveniently.
    fn doesnt_raise(): pass
    # Note this isn't in a try block. Mojo knows 'parametric_raise_example'
    # doesn't raise because the 'doesnt_raise' function doesn't.
    parametric_raise_example(doesnt_raise)
  ```

  作为其中的一部分，上下文管理器已扩展以支持带类型的抛出，并能在需要处理时推断错误类型，例如：

  ```mojo
  struct MyGenericExitCtxtMgr:
    # Called on entry to the with block.
    fn __enter__(self): ...
    # Called on exit from the with block when no error is thrown.
    fn __exit__(self): ...
    # Called on exit from the with block if an error is thrown.
    fn __exit__[ErrType: AnyType](self, err: ErrType) -> Bool: ...
  ```

- Mojo 现在支持 [`Never`](/docs/std/builtin/type_aliases/#never) 类型，
  它永远无法被实例化。该类型可用于没有正常返回值的函数（如
  [`abort()`](/docs/std/os/os/abort/)），以及保证会抛出而不返回正常值的函数。
  被声明为抛出 `Never` 的函数（以及以 `Never` 作为其错误类型实例化的泛型函数）会编译为与不 `raise` 的函数相同的 ABI。

- Mojo 现在允许使用 `comptime(x)` 表达式，强制某个子表达式在编译期求值。当无法（或不想）将某些类型物化为运行时值时，这能让与这些类型协作更优雅。例如，如果你只想从编译期布局中获取大小：

  ```mojo
  fn takes_layout[a: Layout]():
    # materializes entire layout value just to get the size out of it
    print(a.size())
    # Could already work around this with a comptime declaration, verbosely.
    comptime a_size = a.size()
    print(a_size)
    # Can now tell Mojo to evaluate the expression at comptime.
    print(comptime(a.size()))
  ```

- Mojo 现在在 trait 方法中区分 `...` 和 `pass`。`...` 继续表示没有默认实现——`pass` 现在指定一个什么都不做的默认实现。例如：

  ```mojo
  trait T:
      # No default implementation
      fn foo(self): ...

      # Default implementation that does nothing
      fn bar(self) : pass
  ```

  当对一个有返回结果的 trait 方法使用 `pass` 来定义默认实现时，编译器会报错：

  ```mojo
  trait T:
      foo.mojo:2:26: error: trait method has results but default implementation returns no value; did you mean '...'?
      fn foo(self) -> Int: pass
                           ^
      trait.mojo:2:8: note: in 'foo', declared here
      fn foo(self) -> Int: pass
         ^
  ```

- Mojo 现在允许函数类型之间从非抛出函数到抛出函数的隐式转换。它还允许结果类型可隐式转换的函数类型之间的隐式转换。

  ```mojo
  fn takes_raising_float(a: fn () raises -> Float32): ...
  fn returns_int() -> Int: ...
  fn example():
      # This is now ok.
      takes_raising_float(returns_int)
  ```

- 当类型可隐式拷贝或可隐式转换为目标类型时，Mojo 现在允许返回引用的函数转换为返回值的函数：

  ```mojo
  fn fn_returns_ref(x: SomeType) -> ref [x.field] Int: ...
  fn examples():
      # OK, Int result from fn_returns_ref can be implicitly copied.
      var f1 : fn (x: SomeType) -> Int = fn_returns_ref
      # OK, Int result from fn_returns_ref implicitly converts to Float64.
      var f2 : fn (x: SomeType) -> Float64 = fn_returns_ref
  ```

- 上下文管理器（用于 `with` 语句中）现在可以定义消费式退出方法——即 `fn __exit__(var self)`——这对显式销毁的上下文管理器很有用。这同样适用于 `deinit`。

- `deinit` 参数约定现在可应用于结构体方法的任何参数，但参数类型仍必须是所属结构体类型。

- Mojo 现在支持 `...` 表达式。它是
  [`EllipsisType`](/docs/std/builtin/type_aliases/#ellipsistype) 的逻辑空值。它可用于重载函数，例如 `getitem()` 调用：

  ```mojo
  struct YourType:
    fn __getitem__(self, idx: Int) -> Int:
      # ... behavior when passed x[i]
    fn __getitem__(self, idx: EllipsisType) -> Int:
      # ... behavior when passed x[...]
  ```

## 语言变更 {#26-1-language-changes}

- Mojo 语言的基础 trait 层级已变更，以扩展对显式销毁类型（有时被称为“线性类型”linear types）的一等支持。

  [`AnyType`](/docs/std/builtin/anytype/AnyType/)、
  [`Movable`](/docs/std/builtin/value/Movable/) 和
  [`Copyable`](/docs/std/builtin/value/Copyable/) trait 不再要求类型提供 `__del__()` 方法——该方法原本可由编译器在某个 owned 值未被使用时隐式调用。取而代之的是，在泛型代码中应使用
  [`ImplicitlyDestructible`](/docs/std/builtin/anytype/ImplicitlyDestructible/) trait 来要求类型可隐式销毁。

  显式销毁类型让 Mojo 程序能够在类型系统中编码强大的不变量，通过将类型建模为要求用户“在未来”采取某种行动，而不是简单地将实例“随手丢弃”到地上。

  使用 `T: AnyType` 的代码可以改为使用 `T: ImplicitlyDestructible` 以在此变更后保留原有行为。

  相关地，`UnknownDestructibility` trait 不再需要，因为它等价于新的 `AnyType` 行为。

- Mojo 不再支持仅凭参数重载函数：例如它不会尝试在 `fn foo[a: Int8]():` 和 `fn foo[a: Int32]():` 之间消歧。Mojo 此前从未以可靠方式完整实现该支持，移除它简化了语言。当然，它仍支持基于函数参数重载。

- for-each 循环中的 `__next_ref__()` 方法已被移除。现在你可以实现迭代器的 `__next__()` 方法，使其返回值或引用。直接使用集合时，Mojo 会使用返回引用的变体，但会允许其符合
  [`Iterator`](/docs/std/iter/Iterator/) 以便与使用拷贝值的泛型算法配合使用。

- `origin_of(x)` 运算符现在返回 `Origin` 类型的值，而不是内部的 MLIR 类型，且别名如 `ImmutOrigin` 现在也是 `Origin` 类型。

- `Origin.cast_from[x]` 语法已被替换为从任意 origin 到不可变 origin 的安全隐式转换（`ImmutOrigin(x)`）以及显式的不安全转换（`unsafe_origin_mutcast[origin, mut=m]`）。

- 用于显式解包参数的 `*_` 和 `**_` 语法已被简化的 `...` 语法替换。原本的 `T[4, 5, *_, **_]` 现在可以使用 `T[4, 5, ...]`。`...` 会同时延迟关键字参数和非关键字参数的绑定。

- 编译器现在会在使用 `alias` 关键字时发出警告，并建议改用 `comptime`。

- 编译器现在会对未限定的结构体参数访问发出警告，例如

  ```mojo
  @fieldwise_init
  struct MyStuff[my_param: Int]:
      fn give_me_stuff(self) -> Int:
          # Warning: unqualified access to struct parameter 'my_param'; use 'Self.my_param' instead
          return my_param
  ```

- Mojo 编译器在诊断无效调用时生成更清晰的错误信息：它会提及参数名，而不是“argument #4”。

## 库变更 {#26-1-library-changes}

### Reflection 与内省 {#26-1-reflection}

- [`reflection`](/docs/std/reflection/) 模块已显著扩展，具备新的编译期内省能力。该模块已从 `compile.reflection` 迁移到顶层 `reflection` 模块（请将导入从
  `from compile.reflection import ...` 更新为 `from reflection import ...`）。
  在内部，该模块现在组织为 `type_info` 和 `struct_fields` 子模块，不过通过 `from reflection import ...` 的公共 API 保持不变。

  **结构体字段内省** - 用于编译期结构体分析的新 API：

  - `struct_field_count[T]()` - 返回结构体中的字段数量
  - `struct_field_names[T]()` - 以
    [`InlineArray`](/docs/std/collections/inline_array/InlineArray/)
    `[StaticString, N]` 形式返回字段名
  - `struct_field_types[T]()` - 返回所有字段类型的变长序列
  - `struct_field_index_by_name[T, name]()` - 按名称返回字段索引
  - `struct_field_type_by_name[T, name]()` - 返回包装在
    `ReflectedType` 中的字段类型

  这些 API 既适用于具体类型，也适用于泛型类型参数：

  ```mojo
  fn print_fields[T: AnyType]():
      comptime names = struct_field_names[T]()
      comptime types = struct_field_types[T]()
      @parameter
      for i in range(struct_field_count[T]()):
          print(names[i], get_type_name[types[i]]())
  ```

  **按索引访问字段** - 两个新的魔法函数支持基于索引的字段访问而无需拷贝：

  - `__struct_field_type_at_index(T, idx)` - 按索引返回字段类型
  - `__struct_field_ref(idx, ref s)` - 返回字段的引用

  与会进行拷贝的 `kgen.struct.extract` 不同，`__struct_field_ref()` 返回引用，使 reflection 工具能够与不可拷贝类型协作：

  ```mojo
  fn print_all_fields[T: AnyType](ref s: T):
      comptime names = struct_field_names[T]()
      @parameter
      for i in range(struct_field_count[T]()):
          print(names[i], "=", __struct_field_ref(i, s))
  ```

  **字段字节偏移** - `offset_of[T, name=field_name]()` 返回结构体中具名字段的字节偏移，支持无拷贝序列化和其他底层内存操作。该偏移在编译期根据目标的数据布局计算，并正确处理对齐填充。
  这类似于 C/C++ 的 `offsetof` 和 Rust 的 `offset_of!` 宏。还提供了一个 `offset_of[T, index=i]()` 重载用于按字段索引查找。

  ```mojo
  from reflection import offset_of

  struct Point:
      var x: Int      # offset 0
      var y: Float64  # offset 8 (aligned)

  fn main():
      comptime x_off = offset_of[Point, name="x"]()  # 0
      comptime y_off = offset_of[Point, name="y"]()  # 8
  ```

  **类型内省工具：**

  - `is_struct_type[T]()` - 如果 `T` 是 Mojo 结构体类型则返回 `True`。用于在使用结构体专属 API 的 reflection 代码前进行保护，以避免在非结构体类型（例如 MLIR 基本类型）上出现编译器错误。请使用
    `@parameter if`，因为这些 API 在编译期求值。
    ([Issue #5734](https://github.com/modular/modular/issues/5734))

  - `get_base_type_name[T]()` - 返回参数化类型基类型的非限定名。例如 `get_base_type_name[List[Int]]()` 返回
    `"List"`。用于无论元素类型如何都能识别集合类型。
    ([Issue #5735](https://github.com/modular/modular/issues/5735))

  **源位置内省：**

  - [`SourceLocation`](/docs/std/reflection/location/SourceLocation/) - 一个保存文件名、行号和列号信息的结构体
  - [`source_location()`](/docs/std/reflection/location/source_location/) -
    返回调用处的位置
  - `call_location()` - 返回调用者被调用的位置
    （要求调用者为 `@always_inline`）

  这些此前是 `builtin._location` 中的内部 API（`_SourceLocation`、`__source_location`、`__call_location`）。旧模块已被移除。

  ```mojo
  from reflection import source_location, call_location, SourceLocation

  fn main():
      var loc = source_location()
      print(loc)  # main.mojo:5:15

  @always_inline
  fn log_here():
      var caller_loc = call_location()
      print("Called from:", caller_loc)
  ```

  注意：这些 API 在参数表达式中不能正确工作（comptime 上下文返回占位值）。

  **trait 一致性检查** - `conforms_to()` 内建函数现在接受来自 reflection API（如 `struct_field_types[T]()`）的类型，从而可对动态获取的字段类型进行一致性检查：

  ```mojo
  @parameter
  for i in range(struct_field_count[MyStruct]()):
      comptime field_type = struct_field_types[MyStruct]()[i]
      @parameter
      if conforms_to(field_type, Copyable):
          print("Field", i, "is Copyable")
  ```

### 带默认实现的 trait {#26-1-trait-defaults}

- 若干 trait 现在拥有使用 reflection 从结构体字段自动派生行为的默认实现。这意味着简单结构体无需实现任何方法即可符合这些 trait——所有字段只需符合相同的 trait：

  **[`Hashable`](/docs/std/hashlib/hash/Hashable/)** - 默认 `__hash__()`
  对所有字段求哈希：

  ```mojo
  @fieldwise_init
  struct Point(Hashable):
      var x: Float64
      var y: Float64

  hash(Point(1.5, 2.7))  # Works automatically
  ```

  **[`Writable`](/docs/std/format/Writable/)** - 默认 `write_to()`
  对所有字段格式化：

  ```mojo
  @fieldwise_init
  struct Point(Writable):
      var x: Float64
      var y: Float64

  print(Point(1.5, 2.7))  # Point(x=1.5, y=2.7)
  ```

  **[`Equatable`](/docs/std/builtin/comparable/Equatable/)** - 默认
  `__eq__()` 比较所有字段：

  ```mojo
  @fieldwise_init
  struct Point(Equatable):
      var x: Int
      var y: Int

  print(Point(1, 2) == Point(1, 2))  # True
  ```

  注意：默认的 `Equatable` 执行逐成员相等比较，这对含有浮点字段（由于 NaN 语义）的类型可能不合适。
  如需自定义行为，请重写这些方法中的任意一个。

### 集合与迭代器 {#26-1-collections}

- 移除了 [`List`](/docs/std/collections/list/List/) 的变长初始化器。

  - 类似下面的语句：

    ```mojo
    var x = List[Int32](1, 2, 3)
    ```

    可更新为：

    ```mojo
    var x: List[Int32] = [1, 2, 3]
    ```

  - 类似下面的表达式：

    ```mojo
    var x = foo(List[Float32](1, 2, 3))
    ```

    可更新为将显式类型“提示”移到第一个元素周围：

    ```mojo
    var x = foo([Float32(1), 2, 3])
    ```

  - 类似下面的表达式：

    ```mojo
    var data = Span(List[Byte](1, 2, 3))
    ```

    可更新为将显式元素类型移到 `Span`：

    ```mojo
    var data = Span[Byte]([1, 2, 3])
    ```

- 不带步长的 `List` 切片现在返回
  [`Span`](/docs/std/memory/span/Span/)，而不是 `List`，且不再分配内存。

- [`InlineArray`](/docs/std/collections/inline_array/InlineArray/) 不再符合
  [`ImplicitlyCopyable`](/docs/std/builtin/value/ImplicitlyCopyable/)。用户必须显式拷贝数组或获取引用。

- [`IndexList`](/docs/std/utils/index/IndexList/) 不再可从 `Int` 隐式构造。此前，填充构造器（将单个 `Int` 广播到所有元素）被标记为 `@implicit`，允许形如 `var x: IndexList[3] = 5` 的代码创建 `(5, 5, 5)`。为提升类型安全性，该隐式转换已被移除。请改用显式构造：`IndexList[3](5)`。

- [`Dict`](/docs/std/collections/dict/Dict/) 现在在失败时抛出自定义的
  [`DictKeyError`](/docs/std/collections/dict/DictKeyError/) 类型，使查找失败的处理更高效。

  ```mojo
  var d = Dict[String, Int]()
  var key = "missing_key"
  try:
      _ = d[key]
  except e:
      print(e)  # Prints: DictKeyError
  ```

- 新增 [`ContiguousSlice`](/docs/std/builtin/builtin_slice/ContiguousSlice/) 和
  [`StridedSlice`](/docs/std/builtin/builtin_slice/StridedSlice/) 类型，加入 `builtin_slice` 模块以支持无步长切片的特化。

- `Span` 现在符合 [`Iterable`](/docs/std/iter/Iterable/)。

- [`any()`](/docs/std/builtin/bool/any/) 和
  [`all()`](/docs/std/builtin/bool/all/) 现在可作用于 `Iterable`，这意味着它们可作用于 [`map()`](/docs/std/iter/map/) 的结果。

- [`Tuple`](/docs/std/builtin/tuple/Tuple/) 已改进：
  - 元组现在可通过 `Tuple.concat()` 拼接。
  - 元组现在可通过 `Tuple.reverse()` 反转。

- [`peekable()`](/docs/std/iter/peekable/) 函数已加入
  [`iter`](/docs/std/iter/)。它允许用户在不前进迭代器的情况下查看下一个元素。

### String 与文本 {#26-1-string-and-text}

- [`String`](/docs/std/collections/string/string/String/) 的 UTF-8 保证已加强。
  - 它现在有三个独立的构造器用于将原始字节（`Span[Byte]`）转换为 `String`：
    - `String(from_utf8=...)`: 如果字节不是有效的 UTF-8 则抛出错误
    - `String(from_utf8_lossy=...)`: 将无效的 UTF-8 字节序列
      转换为 `(U+FFFD, �)` 替换字符，且不抛出错误。
    - `String(unsafe_from_utf8=...)`: 不做任何检查，不安全地假定输入字节是有效 UTF-8。
  - `append_byte()` 已被废弃，由 `append()` 替换。

- `String` 和
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 的 `strip()`、`lstrip()` 和 `rstrip()` 方法现在支持剥离多字节 unicode 码点。此外，如果“chars”字符串包含的字符与待剥离字符串中某个字符共享首字节，`lstrip()` 和 `strip()` 不再产生无效 UTF-8。

- [`StringLiteral.format()`](/docs/std/builtin/string_literal/StringLiteral/#format)
  现在在格式字符串无效时会发出编译期约束错误（而不是运行时错误）。

  ```mojo
  "Hello, {!invalid}".format("world")
  # note: constraint failed: Conversion flag "invalid" not recognized.
  ```

- `StringSlice.char_length()` 已重命名为 `count_codepoints()`。相同的函数也被加到 `String` 和 `StringLiteral`。

- 新增 [`CStringSlice`](/docs/std/ffi/cstring/CStringSlice/) 作为以类型安全方式与以 null 结尾的 C 风格字符串（`const char*`）交互的接口。

- 移除了 `String.join(*Writable)` 这个接受变长参数序列的重载，因为它可能与剩余的 `String.join(Span[Writable])` 重载产生歧义。

- 移除了 `Int.__init__(self, value: StringSlice, base: UInt)` 构造器。用户应直接调用 [`atol()`](/docs/std/collections/string/string/atol/)。

### 指针与内存 {#26-1-pointer-and-memory}

- [`OwnedDLHandle.get_symbol()`](/docs/std/ffi/OwnedDLHandle/#get_symbol)
  现在返回 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)
  `[T, MutAnyOrigin]`，而不是 `UnsafePointer[T, ImmutAnyOrigin]`。
  从共享库加载的绝大多数符号都是为可变使用而设计的，从可变到不可变（通过
  `.as_immutable()`）比从不可变到可变（通过
  `.unsafe_mut_cast[True]()`）更安全。需要不可变指针的用户现在只需对结果调用 `.as_immutable()` 即可。

- “LegacyUnsafePointer” 类型已变更，将其可变性作为首个无默认值的推断参数，而不是作为后续带默认值 true 的显式参数。我们建议尽快弃用此类型，但若要粗略模拟先前行为，可尝试：

  ```mojo
  from memory import LegacyUnsafePointer
  comptime UnsafePointer = LegacyUnsafePointer[mut=True, *_, **_]
  ```

- 外部 origin 现在使用类型层级的
  `{Mut,Immut,}ExternalOrigin` 别名来表达，而不是拼写为
  `Origin[True].external`，从而与其他 origin 类型保持一致。

- `UnsafePointer` 现在可通过 `unsafe_from_address` 初始化器从原始内存地址初始化。

- [`alloc()`](/docs/std/memory/unsafe_pointer/alloc/) 现在带有
  [`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert/) 以确保 count 非负。

### 显式销毁类型 {#26-1-explicitly-destroyed-types}

- 标准库中现已提供对显式销毁类型的基本支持。显式销毁类型——有时被称为“线性类型”——是不定义 `__del__()` 方法的类型，编译器无法自动调用该方法来销毁实例。取而代之的是，显式销毁类型必须提供一个接受 `deinit self` 的具名方法，程序员的职责是在某个 owned 实例不再被使用时显式调用它。

  更新后的 `AnyType` trait 可用于参数，以表示支持不能被隐式销毁的对象实例的泛型代码。

  - `Span`、`UnsafePointer`、[`Pointer`](/docs/std/memory/pointer/Pointer/) 和
    [`OwnedPointer`](/docs/std/memory/owned_pointer/OwnedPointer/) 可指向显式销毁类型。
    - 新增 `UnsafePointer.destroy_pointee_with()`，用于通过指向类型析构器的函数指针就地销毁显式销毁类型。
  - `List`、`InlineArray`、
    [`Optional`](/docs/std/collections/optional/Optional/)、
    [`Variant`](/docs/std/utils/variant/Variant/)、
    `VariadicListMem` 和
    [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 现在可包含显式销毁类型。
    - `Variant.take()` 现在接收 `deinit self` 而非 `mut self`。
    - 新增 `Variant.destroy_with()`，通过传入类型的析构器函数就地销毁显式销毁类型。
    - 参数的 `*args` 语言语法现在支持显式销毁类型。
  - `Iterator.Element` 不再要求 `ImplicitlyDestructible`。
  - `UnsafeMaybeUninitialized` 现在可包含显式销毁类型。

### 类型系统与 trait {#26-1-type-system}

- 通过使用 `conforms_to()` 和
  [`trait_downcast()`](/docs/std/builtin/rebind/trait_downcast/) 执行“延迟”元素类型一致性检查的“无条件一致性”新技术，一些标准库类型现在能够符合此前无法符合的 trait：

  - `List`、`Dict`、[`Set`](/docs/std/collections/set/Set/)、
    [`Deque`](/docs/std/collections/deque/Deque/)、`InlineArray` 和
    [`LinkedList`](/docs/std/collections/linked_list/LinkedList/) 现在符合
    `Writable`、`Stringable` 和
    `Representable`。`List` 还符合
    `Equatable`。
  - `Pointer`、[`ArcPointer`](/docs/std/memory/arc_pointer/ArcPointer/) 和
    `OwnedPointer` 现在符合 `Writable`。
  - `Iterator`、`Tuple`、`Variant` 和 `Optional` 不再要求其元素类型为 `Copyable`。

- `Iterator` trait 和 for-each 循环移除了 `__has_next__()`
  方法，现在使用 `__next__()` 方法并 `raises`
  [`StopIteration`](/docs/std/iter/StopIteration/)。这更贴合 Python 先例，实现更方便，并在某些情况下可带来轻微的性能提升。

- `ImplicitlyBoolable` trait 已被移除。该 trait 允许类型隐式转换为
  [`Bool`](/docs/std/builtin/bool/Bool/)。此行为很少使用，且可能导致微妙 bug，例如错误地将 `Int` 或 `UnsafePointer` 等类型传给期望 `Bool` 的参数会静默编译成功。

- `Error` 类型不再符合
  [`Boolable`](/docs/std/builtin/bool/Boolable/) 或
  [`Defaultable`](/docs/std/builtin/value/Defaultable/)。错误现在必须以有意义的上下文构造，可选项应通过 `Optional[Error]` 表达，而不是把错误当作布尔值对待。

- `Copyable` trait 现在细化 `Movable` trait。这意味着已经要求 `Copyable` 的结构体和泛型算法不必再额外声明要求 `Movable`。

- `EqualityComparable` trait 已废弃，由功能完全相同的 `Equatable` 替代。

- 我们已从类枚举类型（如
  [`DType`](/docs/std/builtin/dtype/DType/) 和
  [`AddressSpace`](/docs/std/memory/pointer/AddressSpace/)）中移除
  [`Identifiable`](/docs/std/builtin/identifiable/Identifiable/)。此变更与 `Identifiable` 用于比较内存地址这一理念相关。

### Python 互操作 {#26-1-python-interop}

- `ConvertibleFromPython` trait 及相关初始化器现在有一个必需的关键字参数。之前：`Int(pyObj)`。之后：`Int(py=pyObj)`。这避免了在多个重载可能适用、或隐式转换为 `PythonObject` 可能掩盖 Python 操作发生的歧义。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 现在支持从 `None` 隐式转换，允许更自然的类 Python 代码：

  ```mojo
  var obj: PythonObject = None  # Now works without explicit PythonObject(None)

  fn returns_none() -> PythonObject:
      return None  # Implicit conversion
  ```

### 文件 I/O 与 OS {#26-1-file-io}

- `io` 模块中的基本文件 I/O 操作现已用 Mojo 原生实现，直接使用 `libc` 系统调用（`open()`、`close()`、`read()`、`write()`、`lseek()`）。[`FileHandle`](/docs/std/io/file/FileHandle/) 类型不再依赖 CompilerRT 函数，提供更好的性能与透明度。错误处理现包含基于 errno 的消息以改善诊断。

- 新增 `os.process` 子模块，提供生成和等待进程的工具。它们使用 `posix_spawn()`，不经过系统 shell。

- 各种 OS 封装函数现将在抛出的错误消息中包含 `errno` 的值。

- `os` 模块现公开 [`link()`](/docs/std/os/os/link/) 函数，封装 unix `link(2)` 系统调用。

- `os` 模块现公开 [`symlink()`](/docs/std/os/os/symlink/) 函数，封装 unix `symlink(2)` 系统调用。

### GPU 编程 {#26-1-gpu}

- [`Layout`](/docs/layout/layout/Layout/) 不再符合
  [`ImplicitlyCopyable`](/docs/std/builtin/value/ImplicitlyCopyable/)。此变更的动机是此前很容易意外在运行时物化
  `Layout`，例如使用 `Layout.size()` 等方法。此变更带来一些下游变更，用户需要适配。下面是一些有助于过渡的常见模式：

  ```mojo
  from layout import Layout


  fn foo(a: Layout) -> Layout:
      return a.copy()  # `a` needs to be explicitly copied.


  fn bar(var a: Layout) -> Layout:
      return a^  # If a is taken by value, one can use the transfer operator.


  fn baz():
      comptime a = Layout.row_major(4, 4)
      # `a` needs to be materialized because `foo` returns a type that
      # is not ImplicitlyCopyable (`Layout`).
      var b = foo(materialize[a]())

      # `bar` moves `b` by value, but `foo` also takes `b` by reference,
      # so we need to explicitly copy.
      _ = bar(b.copy())
      _ = foo(b)
      # Since we are no longer using `b`, it's fine to take it by value here.
      _ = bar(b^)

      # Since `Layout.size()` returns an `Int`, we can use a `comptime`
      # expression to compute the return value without materializing `a`.
      for i in range(comptime (a.size())):
          ...
  ```

- `DeviceContext.enqueue_function_checked()` 和
  `DeviceStream.enqueue_function_checked()` 已被重命名为
  `enqueue_function()`。类似地，`DeviceContext.compile_function_checked()`
  已被重命名为 `compile_function()`。

- `DeviceContext.enqueue_function()` 和
  `DeviceContext.enqueue_function()` 现在在为 NVIDIA GPU 指定了 `shared_mem_bytes` 但未指定 `func_attribute` 且分配 > 48KB 时，自动将
  `func_attribute` 推断为
  `FuncAttribute.MAX_DYNAMIC_SHARED_SIZE_BYTES(shared_mem_bytes)`。这消除了在许多情况下两次指定相同共享内存大小的需要，减少了样板代码并防止值不匹配。在 AMD GPU 上或分配 ≤ 48KB 时，应在需要时提供显式
  `func_attribute` 值。

- `inlined_assembly()` 函数现已从 `sys` 模块公开导出，允许用户将原始汇编指令直接嵌入 Mojo 代码。
  这使用 LLVM 风格的内联汇编语法，提供对硬件操作的细粒度控制。示例：

  ```mojo
  from sys import inlined_assembly

  # Convert bfloat16 to float32 on NVIDIA GPU using PTX assembly.
  var result = inlined_assembly[
      "cvt.f32.bf16 $0, $1;",
      Float32,
      constraints="=f,h",
      has_side_effect=False,
  ](my_bf16_as_int16)
  ```

### 格式化与输出 {#26-1-formatting}

- [`Writer`](/docs/std/format/Writer/) 已重新设计，仅支持 UTF-8 数据，而非任意 `Byte` 序列。`write_bytes()` 方法已被 `write_string()` 替换。

  - 与这些变更一致，`String` 的 `write_bytes()` 方法也已废弃，其初始化器 `__init__(out self, *, bytes: Span[Byte])` 的关键字参数已重命名为 `unsafe_from_utf8`。这使其与现有的 `StringSlice` 构造器更一致，并明确指出从任意字节构造本质上是不安全的。

- `Writer` 和 `Writable` 已移入新的 `format` 模块，从 `io` 中移出。这些 trait 与二进制 I/O 并不直接相关，而是与类型/值的字符串格式化紧密相关。

- `Writable` trait 现在通过可选的
  `write_repr_to()` 方法支持调试格式化，该方法由 [`repr()`](/docs/std/format/repr/repr/)
  和 `{!r}` 格式说明符调用。
  此外，`repr()` 和字符串格式化方法（`String`、`StringSlice` 和 `StringLiteral` 上的 `.format()`）现在接受 `Writable` 类型，支持无中间字符串分配的高效格式化。为保留既有行为，同时实现 `Stringable & Representable` 和 `Writable` 的类型将继续使用 `Stringable & Representable` 方法；仅实现 `Writable` 的类型才会使用新代码路径。

- [`Counter`](/docs/std/collections/counter/Counter/) 现在符合
  `Writable`、`Stringable` 和 `Representable`。

- [`black_box()`](/docs/std/benchmark/compiler/black_box/) 已加入
  `benchmark` 工具，作为防止编译器激进优化掉值的一种方式。与
  [`keep()`](/docs/std/benchmark/compiler/keep/) 类似，但它返回其参数。

### 其他库变更 {#26-1-other-library}

- [`UInt`](/docs/std/builtin/simd/#uint) 结构体已被替换为新的
  `UInt` 类型别名，指向 `Scalar[DType.uint]`。这是一项重大变更，通过抽象机器字长的无符号 SIMD 数据 dtype，支持更强大的泛型编程。

  此变更可能会破坏依赖 `UInt` 与 `Int`/`SIMD` 之间隐式转换的代码。`SIMD` 类型在编译期也稍微不那么易折叠，这可能导致 where 子句、comptime 表达式以及参数化上下文中的其他代码现在失败或崩溃。这些不足将在后续补丁中按需解决。

- `Int` 与 `UInt` 之间的隐式转换已被移除。

- [`random`](/docs/std/random/) 模块现在使用基于 Philox 算法的纯 Mojo 实现（通过内部封装），替换了此前的 `CompilerRT` C++ 依赖。Philox 算法提供出色的统计质量，可在 CPU 和 GPU 上工作，并使随机数生成完全透明且源码可用。注意，这会改变给定种子值的随机数序列，可能影响依赖可复现序列的测试或代码。

- `StringableRaising` 已废弃，其在标准库中的用法已被移除。

- `Variadic` 现在拥有 `zip_types()`、`zip_values()` 和 `slice_types()`。

## 工具链变更 {#26-1-tooling-changes}

- Mojo 编译器现在支持 `-Werror` 标志，它将所有警告视为编译错误。这对于强制执行更严格的代码质量标准很有用，尤其是在 CI/CD 流水线中。该标志可与 Mojo 编译器工具（`mojo run`、`mojo build`、`mojo package`、`mojo doc`）配合使用。
  当与 `--disable-warnings` 一起使用时，警告会先被提升为错误，因此错误不会被抑制。
  - 对应的 `-Wno-error` 标志禁用将警告视为错误。
    当同时指定两个标志时，最后一个生效。
- 使用 `--target-accelerator` 指定 CUDA 架构时，现在期望的是 sm 版本字符串，而不仅仅是计算能力。例如，
  `--target-accelerator=nvidia:80` 应改为
  `--target-accelerator=nvidia:sm_80`。如果版本格式不正确，编译器将默认使用最低支持的 sm 版本。
- Mojo LSP 服务器现在对文档更新去抖动，以减少快速输入期间的 CPU 使用。此前每次按键都会触发完整文档解析；现在更新会以 150ms 延迟合并，在活跃编辑期间将解析频率降低 10-50 倍。
- Mojo 编译器现在在错误信息中“差异对比”非常长的类型，以更易懂的方式解释发生了什么。
- 具有不同详细程度的 elaboration 错误打印，可在函数实例化失败时控制参数值如何作为 elaboration 错误的一部分显示。
  `--elaboration-error-verbose=value` 现在接受一个值，其中：
  - `no-params` 表示不显示任何具体参数值。
    这有助于将与递归相关的错误消息折叠成更短的块。
  - `simple-params` 表示以用户友好的格式显示简单类型（包括数字类型和字符串）的具体参数值
    （默认值）。
  - `all-params` 表示显示所有具体参数值。
    这适用于不介意阅读 MLIR 属性但希望对参数值有更多可见性的高级程序员。
- 新增 `--elaboration-max-depth` 以控制最大 elaborator 实例化深度。此（无符号）值有助于检测编译期递归。默认值为 `std::numeric_limits<unsigned>::max()`。
- 使用 `--validate-doc-strings` 的文档字符串校验现在在 `fn` 函数被声明为抛出错误（`raises`）但缺少
  [`Raises` 文档字符串](https://github.com/modular/modular/blob/main/mojo/stdlib/docs/docstring-style-guide.md#errors)
  时会发出错误（此前仅发出警告）。由于 Mojo 自动将所有 `def` 函数视为[抛出函数](/docs/manual/functions/#raising-and-non-raising-functions)，我们不对 `def` 函数强制 `Raises` 文档（以避免嘈杂的误报）。
- 文档字符串校验现在包含 `comptime` 别名。`--diagnose-missing-doc-strings` 标志现在检查公共别名是否有格式正确的文档字符串（摘要以句号结尾，以大写字母开头）。参数化别名也检查是否有正确的 `Parameters:` 段落。
- `--validate-doc-strings` 标志已对 `mojo doc` 废弃，并从其他工具（`mojo build`、`mojo run`、`mojo package`）中移除。请使用 `-Werror` 将警告视为错误。
- Mojo 编译器现在支持 `-Xlinker` 标志以将选项直接传递给链接器，例如：

  ```console
  mojo build -Xlinker -lfoo main.mojo
  ```

  注意：此选项仅对 `mojo build` 有效。对于 `mojo run`，参数会被忽略并发出警告。
- Mojo 编译器现在为 `mojo build`、`mojo run` 和 `mojo package` 支持 `--experimental-export-fixit` 标志。此标志将修复建议导出为与 `clang-apply-replacements` 兼容的 YAML 文件，而不是直接应用。这对于将 Mojo 的修复建议集成到外部工具工作流中很有用。该标志与 `--experimental-fixit`（直接应用修复建议）互斥。
- Mojo 调试器 `mojo break-on-raise` 功能现在在调试器实例中包含多个目标时也能正确工作。该设置是按目标的。

## 实验性变更 {#26-1-experimental-changes}

本节描述的变更是实验性的，可能在未来版本中被更改、替换或移除。

- Mojo 现在支持编译期 trait 一致性检查（通过 `conforms_to()`）和向下转型（通过 `trait_downcast()`）。这允许用户实现基于 trait 一致性的静态分派等功能。例如：

  ```mojo
  fn maybe_print[T : AnyType](maybe_printable : T):
    @parameter
    if conforms_to(T, Writable):
      print(trait_downcast[Writable](maybe_printable))
    else:
      print("[UNPRINTABLE]")
  ```

- 在 `where` 子句中增加了对 [`DType`](/docs/std/builtin/dtype/DType/) 表达式的支持：

  ```mojo
  fn foo[dt: DType]() -> Int where dt == DType.int32:
      return 42
  ```

  目前支持以下表达式：
  - 相等与不等
  - `is_signed()`、`is_unsigned()`、`is_numeric()`、`is_integral()`、
    `is_floating_point()`、`is_float8()`、`is_half_float()`

- 在 `where` 子句中增加了对 [`SIMD`](/docs/std/builtin/simd/SIMD/) 表达式的支持：

  ```mojo
  fn foo[dt: DType, x: Int]() -> Int where SIMD[dt, 4](x) + 2 > SIMD[dt, 4](0):
      return 42
  ```

  目前支持以下表达式：
  - 默认构造以及从 `Int` 和
    [`IntLiteral`](/docs/std/builtin/int_literal/IntLiteral/) 构造
  - 相等、不等及其他比较运算符
  - 加法、减法和乘法
  - 按位逻辑运算，不包括移位

## 移除 {#26-1-removed}

- 以下已废弃的 GPU 兼容模块已被移除：
  - `gpu.id` - 改用 `from gpu import block_idx, thread_idx, ...`
  - `gpu.block` - 改用 `from gpu.primitives.block import ...`
  - `gpu.warp` - 改用 `from gpu.primitives.warp import ...`
  - `gpu.cluster` - 改用 `from gpu.primitives.cluster import ...`
  - `gpu.grid_controls` - 改用 `from gpu.primitives.grid_controls import ...`
  - `gpu.mma` - 改用 `from gpu.compute.mma import ...`
  - `gpu.mma_operand_descriptor` - 改用
    `from gpu.compute.mma_operand_descriptor import ...`
  - `gpu.mma_util` - 改用 `from gpu.compute.mma_util import ...`
  - `gpu.mma_sm100` - 改用 `from gpu.compute.arch.mma_nvidia_sm100 import ...`
  - `gpu.semaphore` - 改用 `from gpu.sync.semaphore import ...`
  - `gpu.tcgen05` - 改用 `from gpu.compute.arch.tcgen05 import ...`

- DeviceContext 的 `enqueue_function_unchecked()` 和
  `compile_function_unchecked()` 已被移除。请将代码迁移为使用 `enqueue_function()` 和 `compile_function()`。

- `NDBuffer` 已被移除。请改用
  [`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/)。

- `UnsafePointer.offset()` 方法现已废弃。请改用指针算术：

  ```mojo
  # Before
  new_ptr = ptr.offset(n)

  # After
  new_ptr = ptr + n
  ```

## 修复 {#26-1-fixed}

- 修复了若干与 reflection 相关的编译器崩溃：
  - [Issue #5731](https://github.com/modular/modular/issues/5731): reflection
    函数现在可在 `Int`、`NoneType` 和 `Origin` 等内建类型上正确工作。
  - [Issue #5732](https://github.com/modular/modular/issues/5732):
    `get_type_name()` 现在能处理参数中带有构造器调用的类型（如 `A[B(True)]`）（通过 `struct_field_types()` 提取时）。
  - [Issue #5723](https://github.com/modular/modular/issues/5723):
    `get_type_name()` 现在能处理来自
    `struct_field_types()` 的嵌套参数化类型。
  - [Issue #5754](https://github.com/modular/modular/issues/5754):
    `struct_field_type_by_name()` 现在使用
    `ReflectedType.T` 作为类型标注时能正确工作。
  - [Issue #5808](https://github.com/modular/modular/issues/5808):
    `rebind()` 和 `rebind_var()` 现在接受来自
    `struct_field_types()` 的向下转型类型，允许形如
    `rebind_var[types[i]](downcast[types[i], Trait]()^)` 的模式。
- [Issue #5618](https://github.com/modular/modular/issues/5618): 本应是隐式转换错误时却出现的编译器崩溃。
- [Issue #5361](https://github.com/modular/modular/issues/5361): mojo doc 在带有 origin 的参数化函数别名上崩溃。
- [Issue #5137](https://github.com/modular/modular/issues/5137): 带 raises 的尾递归函数不会进行尾调用优化。
- [Issue #5138](https://github.com/modular/modular/issues/5138): 带本地栈临时对象的函数不会进行尾调用优化。
- Mojo 不再在复杂参数化代码中发生无关类型检查错误时抱怨“cannot infer parameter X”。现在在这些情况下会给出更有用、更具可操作性的错误信息。
- [`time.sleep()`](/docs/std/time/time/sleep/) 现在在 NVIDIA GPU 上对于超过 1 毫秒的时长也能正确工作。此前，由于底层 `nanosleep` 内建函数的硬件限制，睡眠时长被静默截断为 1ms。AMD GPU 现在通过 `s_sleep` 指令提供基本睡眠支持，足以用于自旋等待退避操作，但不能提供精确的挂钟时间。此外，`global_perf_counter_ns()` 现已从 `time` 包导出，供需要纳秒级计时的 GPU 代码使用。
- [Issue #5578](https://github.com/modular/modular/issues/5578): 与 `ref` 一起使用时所有权重载不工作。
- [Issue #1850](https://github.com/modular/modular/issues/1850): Mojo 假定函数开头的字符串字面量是文档注释。
- [Issue #4501](https://github.com/modular/modular/issues/4501): 不完整赋值的错误解析。
- [Issue #4765](https://github.com/modular/modular/issues/4765): 解析器接受无意义的 var ref a = n 绑定形式。
- [`Codepoint.unsafe_decode_utf8_codepoint()`](/docs/std/collections/string/codepoint/Codepoint/#unsafe_decode_utf8_codepoint)
  在传入空 span 时不再返回 `Codepoint(0)` (NUL)。取而代之的是，`debug_assert()` 现在强制要求输入 span 非空，与该函数既有的安全契约一致。
- [Issue #5635](https://github.com/modular/modular/issues/5635):
  [`Deque`](/docs/std/collections/deque/Deque/) 在 `capacity > min_capacity` 时收缩重分配错误处理空 deque。
