## 2023-06-29

### ⭐️ 新增

- 你现在可以在 Mojo Playground 中分享 `.ipynb` notebook 文件。只需将
  文件保存在 `shared` 目录下，然后右键单击文件并选择
  **Copy Sharable link**。要打开分享的 notebook，你必须已拥有
  Mojo Playground 的访问权限；
  打开分享的 notebook 时，单击 notebook 顶部的 **Import** 以保存你自己的副本。有关此功能的更多详情，请参见 Mojo Playground 文件浏览器中 `help` 目录内的说明。

### 🦋 变更

- [`Functional`](/docs/std/algorithm/functional/) 模块中的 `unroll2()` 和 `unroll3()` 函数已重命名，作为 `unroll()` 函数的重载。这些函数展开 2D 和 3D 循环，
  `unroll()` 可根据输入参数的数量确定意图。

### 🛠️ 修复

- [Issue #229](https://github.com/modular/modular/issues/229) - 在所有字段初始化前从 `__init__` 抛出异常时的问题。

- [Issue #74](https://github.com/modular/modular/issues/74) - 带递归引用的 Struct
  定义崩溃。

- [Issue #285](https://github.com/modular/modular/issues/285) -
  [`TargetInfo`](/docs/std/sys/info/) 模块现在包含
  `is_little_endian()` 和 `is_big_endian()`，用于检查目标主机是否使用
  小端或大端。

- [Issue #254](https://github.com/modular/modular/issues/254) - 嵌套作用域中的参数名遮蔽
  现在被正确处理。

## 2023-06-21

### ⭐️ 新增

- 添加了基于参数签名的重载支持。例如，现在
  可以编写以下代码：

  ```mojo
  fn foo[a: Int](x: Int):
      pass

  fn foo[a: Int, b: Int](x: Int):
      pass
  ```

  有关重载解析逻辑的详情，请参见 Mojo 手册中关于
  [parameters](/docs/manual/parameters/#overloading-on-parameters) 的章节。

- 在 `Autotune` 中新增了 `cost_of()` 函数。此元函数
  必须在编译期调用，返回函数（在编译的某个阶段）中 MLIR 操作的
  数量，可用于
  在高阶生成器中构建基础启发式。

  ```mojo
  from autotune import cost_of

  fn generator[f: fn(Int) -> Int]() -> Int:
      @parameter
      if cost_of[fn(Int) -> Int, f]() < 10:
          return f()
      else:
          # Do something else for slower functions...
  ```

- 添加了一个新的示例 notebook，包含基本的 Ray Tracing 算法。

### 🦋 变更

- `Assert` 模块中的 `constrained_msg()` 已重命名为
  `constrained()`。

### 🛠️ 修复

- 标记为 `@adaptive` 的重载现在能正确处理仅在声明的参数名上
  不同的签名，例如以下现在能正确工作：

  ```mojo
  @adaptive
  fn foobar[w: Int, T: DType]() -> SIMD[T, w]: ...

  @adaptive
  fn foobar[w: Int, S: DType]() -> SIMD[S, w]: ...
  ```

- [Issue #219](https://github.com/modular/modular/issues/219) - 在同一单元格中重定义函数和
  struct 的问题。

- [Issue #355](https://github.com/modular/modular/issues/355) - Matmul notebook 中 Python 与 naive mojo 的循环顺序
  已为一致性重新排序。循环顺序现在遵循 (M, K, N) 顺序。

- [Issue #309](https://github.com/modular/modular/issues/309) - 在测试包内使用 snake case 命名，并将
  断言移出 TestSuite struct。

## 2023-06-14

### ⭐️ 新增

- 现已支持 Tuple 类型语法，例如以下可用：

  ```mojo
  fn return_tuple() -> (Int, Int):
      return (1, 2)
  ```

### 🦋 变更

- `TupleLiteral` 类型已重命名为 `Tuple`，例如
  `Tuple[Int, Float]`。

### 🛠️ 修复

- [Issue #354](https://github.com/modular/modular/issues/354) - 返回 tuple 即使加括号也不工作。
- [Issue #365](https://github.com/modular/modular/issues/365) - `FloatLiteral` 文档中的拷贝粘贴错误。
- [Issue #357](https://github.com/modular/modular/issues/357) - 当可变参数结构体成员函数缺少
  输入参数时崩溃。

## 2023-06-07

### ⭐️ 新增

- Tuple 语法现在可在赋值的左侧（"lvalue"
  位置）工作，启用诸如 `(a, b) = (b, a)` 的功能。有几点
  注意事项：元素类型必须完全匹配（无隐式转换），
  这只适用于 `TupleLiteral` 类型的值（值得注意的是，它目前尚不能与
  `PythonObject` 一起工作），且元组语法需要括号。

### ❌ 移除

- Mojo Playground 不再包含以下 Python 包（由于大小、
  计算成本与
  [environment complications](https://github.com/modular/modular/issues/300)）：
  `torch`、`tensorflow`、`keras`、`transformers`。

### 🦋 变更

- 数据类型和标量名称现在遵循 numpy 使用的命名约定。因此我们使用 `Int32` 而非 `SI32`，类似地使用 `Float32`
  而非 `F32`。关闭
  [Issue #152](https://github.com/modular/modular/issues/152)。

### 🛠️ 修复

- [Issue #287](https://github.com/modular/modular/issues/287) - computed
  lvalues don't handle raising functions correctly
- [Issue #318](https://github.com/modular/modular/issues/318) - Large integers
  are not being printed correctly
- [Issue #326](https://github.com/modular/modular/issues/326) - Float modulo
  operator is not working as expected
- [Issue #282](https://github.com/modular/modular/issues/282) - Default
  arguments are not working as expected
- [Issue #271](https://github.com/modular/modular/issues/271) - Confusing error
  message when converting between function types with different result semantics
