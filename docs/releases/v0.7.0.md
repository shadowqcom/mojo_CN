## ⭐️ 新增

- 一个新的 Mojo 原生字典类型，
  [`Dict`](/docs/std/collections/dict/)，用于存储键值对。
  `Dict` 存储遵循
  [`CollectionElement`](/docs/std/builtin/value/CollectionElement/)
  trait 的值。键需要遵循新的
  [`KeyElement`](/docs/std/collections/dict/#keyelement) trait，该 trait
  尚未被其他标准库类型实现。短期内，你可以创建自己的包装类型用作键。例如，
  以下示例定义了一个 `StringKey` 类型，并用它创建一个将
  字符串映射到 `Int` 值的字典：

  ```mojo
  from collections.dict import Dict, KeyElement

  @value
  struct StringKey(KeyElement):
      var s: String

      fn __init__(inout self, owned s: String):
          self.s = s ^

      fn __init__(inout self, s: StringLiteral):
          self.s = String(s)

      fn __hash__(self) -> Int:
          return hash(self.s)

      fn __eq__(self, other: Self) -> Bool:
          return self.s == other.s

  def main():
      var d = Dict[StringKey, Int]()
      d["cats"] = 1
      d["dogs"] = 2
      print(len(d))         # prints 2
      print(d["cats"])      # prints 1
      print(d.pop("dogs"))  # prints 2
      print(len(d))         # prints 1
  ```

  我们计划在后续版本中为标准库类型添加 `KeyElement` 遵循。

  用户可以通过在调用 `mojo` 编译源文件时指定
  `-D MOJO_ENABLE_ASSERTIONS` 来选择启用标准库代码中使用的断言。
  当断言触发时，程序退出前会打印断言信息和栈回溯。
  默认情况下，出于性能原因，标准库中*未启用*断言。

- Mojo 语言服务器现在实现了 References 请求。IDE 利用
  此功能来支持**转到引用（Go to References）**和**查找所有引用（Find All References）**。
  当前的限制是不支持当前文档之外的引用，
  这将在未来得到解决。

- [`sys.info`](/docs/std/sys/info/) 模块现在包含
  `num_physical_cores()`、`num_logical_cores()` 和 `num_performance_cores()`
  函数。

- 由内存类型（例如 `String`）组成的同质可变参数变得更强大且更易用。
  这些参数会被投影为
  [`VariadicListMem`](/docs/std/builtin/variadics/VariadicListMem/)。

  （此前的版本使 register passable 类型（例如 `Int`）的可变列表更易用。）

  对 `VariadicListMem` 进行下标操作现在返回元素本身，而不是某个
  难懂的内部类型。此外，我们现在支持 `inout` 和 `owned`
  可变参数：

  ```mojo
  fn make_worldly(inout *strs: String):
      # This "just works" as you'd expect!
      for i in range(len(strs)):
          strs[i] += " world"
  fn main():
      var s1: String = "hello"
      var s2: String = "konnichiwa"
      var s3: String = "bonjour"
      make_worldly(s1, s2, s3)
      print(s1)  # hello world
      print(s2)  # konnichiwa world
      print(s3)  # bonjour world
  ```

  （此前的版本使可变列表更易用，但对 `VariadicListMem` 进行下标操作
  返回的是低级指针，需要用户调用 `__get_address_as_lvalue()` 来
  访问元素。）

  注意，如上所示对可变列表进行下标操作效果良好，但直接用
  `for` 循环遍历可变列表会产生一个 `Reference`
  （见下文描述）而不是所需的值，因此需要额外的下标操作；
  我们打算在未来修复此问题。

  ```mojo
  fn make_worldly(inout *strs: String):
      # Requires extra [] to dereference the reference for now.
      for i in strs:
          i[] += " world"
  ```

  异质可变参数尚未迁移到新模型，但
  会在未来的更新中迁移。

  注意，对于像 `Int` 这样的 register passable 类型的可变参数，可变列表
  包含的是值而非引用，因此不需要解引用运算符
  （`[]`）。以下代码继续像以前一样工作：

  ```mojo
  fn print_ints(*nums: Int):
      for num in nums:
          print(num)
      print(len(nums))
  ```

- Mojo 现在拥有一个安全的
  [`Reference`](/docs/std/memory/pointer/Pointer/) 类型的原型版本。编译器的
  生命周期跟踪阶段可以对引用进行推理，以安全地延长局部变量的生命周期，
  并检查间接访问的安全性。`Reference` 类型是全新的（且目前没有语法糖），
  因此必须用空下标显式解引用：`ref[]` 提供对底层值的访问。

  ```mojo
  fn main():
      var a: String = "hello"
      var b: String = " references"

      var aref = Reference(a)
      aref[] += b
      print(a)  # prints "hello references"

      aref[] += b
      # ^last use of b, it is destroyed here.

      print(aref[]) # prints "hello references references"
      # ^last use of a, it is destroyed here.
  ```

  虽然 `Reference` 类型在内存中的表示与 C 指针或 Mojo 的
  `Pointer` 类型相同，但它还跟踪一个符号化的“生命周期”值，
  以便编译器对可能被访问的值集合进行推理。该
  生命周期是引用静态类型的一部分，因此它会传播通过
  围绕它构建的泛型算法和抽象。

  `Reference` 类型可以形成对可变和不可变内存对象的引用，
  例如栈上或借用/inout/owned 函数参数。它完全以可变性参数化，
  消除了[由于可变性说明符导致的代码重复
  问题](https://duckki.github.io/2024/01/01/inferred-mutability.html)，
  并为统一的用户级类型提供了基础。例如，它可用于实现
  同时处理可变和不可变数组切片的数组切片对象。

  虽然这对 Mojo 的生命周期系统来说是重要的一步，但它
  仍处于*非常*早期且使用起来有些笨拙。值得注意的是，没有用于
  使用引用的语法糖，例如自动解引用。它的若干方面
  还需要进一步打磨。它正通过可变内存参数得到锻炼，这也是
  它们现在开始表现更好的原因。

  注意：安全的 `Reference` 类型和不安全的指针类型定义在
  同一个模块中，当前名为 `memory.unsafe`。我们预计在未来的
  版本中重构此模块。

- Mojo 现在允许类型实现 `__refattr__()` 和 `__refitem__()`，
  以便在返回引用的计算访问器上启用属性和下标语法。在
  这些方法访问内存中值的常见场景下，这提供了一种比
  实现传统 get/set 对更方便且性能显著更高的替代方案。注意：当引用
  支持自动解引用时，这在未来可能会改变——届时我们可能改为
  直接从 `__getattr__()` 返回引用。
- 参数化闭包现在可以通过 `__copy_capture` 装饰器按复制捕获 register passable
  类型的值。例如，以下代码会输出
  `5`，而不是 `2`。

  ```mojo
  fn foo(x: Int):
      var z = x

      @__copy_capture(z)
      @parameter
      fn formatter() -> Int:
          return z
      z = 2
      print(formatter())

  fn main():
      foo(5)
  ```

- String 现在实现了 KeyElement，可作为 Dict 中的键使用。
- 对具有自引用类型字段的结构体提供更健壮的支持。
  例如，以下代码可以正常工作并输出 `0`：

  ```mojo
  struct Foo(CollectionElement):
      var vec: DynamicVector[Self]

      fn __init__(inout self: Self):
          self.vec = DynamicVector[Self]()

      fn __moveinit__(inout self: Self, owned existing: Self):
          self.vec = existing.vec ^

      fn __copyinit__(inout self: Self, existing: Self):
          self.vec = existing.vec

  fn main():
      var foo = Foo()
      print(len(foo.vec))
  ```

## ❌ 移除

- `__takeinit__` 特殊构造函数形式已从语言中移除。
  此“非破坏性移动”操作此前与 `x^` 传递运算符关联，
  但其行为不可预测且不一致。既然 Mojo 已有 trait，
  将其建模为类型上显式的 `.take()` 操作会更好，该操作会转移出
  类型的内容而不结束其生命周期。例如，对于持有指针的类型，`take()`
  可能返回一个指向相同数据的新实例，并将其自身内部指针置空。

  此更改明确了生命周期何时结束，以及何时显式取出一个 LValue 的内容。

- 当前实现的自动调优（autotuning）已弃用，因为 Mojo 的
  自动调优实现正在进行重新设计。围绕当前实现的教程也已
  移除，因为它们正在被重写。

  因此，`autotune()`、`autotune_fork()` 和 `search()` 函数
  已从标准库中移除。

- 仅适用于 register passable 元素类型的 `_OldDynamicVector` 类型
  已被移除。请将使用迁移至
  [`DynamicVector`](/docs/std/collections/list/List/)，它
  同时适用于 register passable 和内存类型。

- `utils.vector` 中的 `UnsafeFixedVector` 已被移除。我们建议改用
  [`DynamicVector`](/docs/std/collections/list/List/)
  或 [`InlinedFixedVector`](/docs/std/collections/inline_array/InlineArray/)。

- `@adaptive` 装饰器已从语言中移除。在非搜索上下文中对该装饰器的
  任何使用都可以用 `@parameter if` 替换。例如：

  ```mojo
  @adaptive
  fn foo[a: Bool]():
      constrained[a]()
      body1()

  @adaptive
  fn foo[a: Bool]():
      constrained[not a]()
      body2()
  ```

  可以重写为：

  ```mojo
  fn foo[a: Bool]():
      @parameter
      if a:
          body1()
      else:
          body2()
  ```

  因此，特殊的 `__adaptive_set` 属性也已移除。

- 结果参数（Result parameters）已从 Mojo 中移除。函数参数列表中的
  结果参数声明不再被允许，前向 alias 声明也不再被允许。这包括
  移除 `param_return` 语句。

- 由于闭包模型的改进和完善，`@noncapturing` 和 `@closure` 装饰器
  已被移除。详见下文！

## 🦋 变更

- Mojo 闭包模型已得到改进，变得更直接且更安全。
  Mojo 有两种闭包类型：参数闭包和运行时闭包。参数闭包
  可用于高阶函数，是 `vectorize` 和 `parallelize` 等函数的支柱。
  它们始终由 `@parameter` 标注，类型为 `fn() capturing -> T`
  （其中 `T` 是返回类型）。

  另一方面，运行时闭包始终是动态值，通过调用其复制构造函数
  捕获值，并保留对其捕获状态的所有权。你可以通过编写一个捕获
  值的嵌套函数来定义运行时闭包：

  ```mojo
  fn outer(b: Bool, x: String) -> fn() escaping -> None:
      fn closure():
          print(x) # 'x' is captured by calling String.__copyinit__

      fn bare_function():
          print("hello") # nothing is captured

      if b:
          # closure can be safely returned because it owns its state
          return closure^

      # function pointers can be converted to runtime closures
      return bare_function
  ```

  运行时闭包的类型形式为 `fn() escaping -> T`。你可以将
  等效的函数指针作为运行时闭包传递。

  敬请期待用于移动捕获和按引用捕获的捕获列表语法，
  以及更统一的闭包模型！

- `@unroll(n)` 装饰器现在可以接受用于展开因子的参数表达式，即
  `n` 可以是整数类型的参数表达式。

- `python` 包中的 `cpython` 模块已被移至内部
  模块，即 `_cpython`。

- `AnyType` 和 `Destructable` 已统一为单个 trait `AnyType`。
  每个名义类型（即所有 struct）现在都会自动遵循 `AnyType`。

- 此前，`mojo package` 命令会输出一个 Mojo 包，其中
  同时包含部分编译的 Mojo 代码，以及针对特定计算机架构的完全编译的机器码——
  该架构是调用 `mojo package` 命令所用机器的架构。

  现在，`mojo package` 只包含部分编译的 Mojo 代码。它仅在包
  首次被 `import` 时，针对所使用的特定计算机架构进行完全编译。
  因此，Mojo 包更小且更具可移植性。

- `polynomial_evaluate` 的 `simd_width` 和 `dtype` 参数已交换。基于
  [#1587](https://github.com/modular/modular/issues/1587) 中的请求，
  `polynomial_evaluate` 函数也已扩展，使得
  `coefficients` 参数可以接受
  [`StaticTuple`](/docs/std/utils/static_tuple/StaticTuple/) 或
  [`VariadicList`](/docs/std/builtin/variadics/VariadicList/)。

- 作为移除 `let` 声明的微小一步，本版本移除了
  警告：`'var' was never mutated, consider switching to a 'let'`。
