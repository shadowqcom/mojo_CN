## 亮点 {#0-26-2-highlights}

- **官方 Modular AI agent skill。** Modular 发布了用于 MAX 与 Mojo 的
  [官方 AI agent skill](https://github.com/modular/skills)。这四个 skill——`new-modular-project`、`mojo-syntax`、`mojo-gpu-fundamentals` 和 `mojo-python-interop`——帮助 AI 编码 agent 创建带正确工具链的新项目、生成正确的现代 Mojo 语法、遵循 GPU 编程最佳实践，并处理 Python-Mojo 互操作。这些 skill 遵循开放的
  [Agent Skills Standard](https://agentskills.io/specification)，可与 Claude Code 及其他兼容 agent 配合使用。通过
  `npx skills add modular/skills` 安装。

- **条件 trait一致性。** 结构体现在可以声明仅在类型参数满足某些条件时才适用的 trait 一致性，使用一致性列表中的 `where` 子句。九个标准库类型——包括 `List`、`Dict`、`Set` 和 `Optional`——现在使用此特性在编译期强制执行 trait 要求。参见
  [语言增强](#0-26-2-language-enhancements) 和
  [条件一致性](#0-26-2-conditional-conformances)。

- **`def`/`fn` 统一。** `def` 现在是 Mojo 的标准函数声明关键字。`def` 函数不再隐式抛出，现在与 `fn` 具有相同语义：默认不抛出，对可抛出的函数使用显式
  `raises`。`fn` 已废弃，将在未来版本中移除。参见
  [语言增强](#0-26-2-language-enhancements)。

- **T-字符串。** Mojo 现在支持带 `t"..."` 前缀的模板字符串。
  T-字符串产生一个 `TString` 值，它同时捕获静态格式字符串和运行时参数，支持无需立即分配的结构化字符串处理。参见
  [语言增强](#0-26-2-language-enhancements)。

- **`comptime if` 和 `comptime for`。** 新的 `comptime if` 和
  `comptime for` 语法替换了用于编译期条件与循环的旧式 `@parameter if` 和
  `@parameter for` 装饰器形式。本版本两种语法都接受；`@parameter` 形式将很快被废弃。参见
  [语言增强](#0-26-2-language-enhancements)。

- **`assert` 语句。** Mojo 现在支持独立的 `assert` 语句，类似于 Python 的 `assert`。它在运行时检查条件，若条件为假则中止，可带可选消息。在底层，`assert` 脱糖为 `debug_assert()` 并遵循 `-D ASSERT` 标志。
  参见 [语言增强](#0-26-2-language-enhancements)。

- **`@align(N)` 装饰器。** 结构体现在可以使用 `@align(N)` 指定最小对齐，类似于 C++ 的 `alignas` 和 Rust 的 `#[repr(align(N))]`。对齐值可以是结构体参数，从而支持通用的缓存对齐与硬件对齐类型。参见
  [语言增强](#0-26-2-language-enhancements)。

- **隐式 `Int` 到 `SIMD` 转换已废弃。** 从 `Int` 到 `Int8` 或 `Float32` 等 `SIMD` 标量类型的隐式转换现已废弃。依赖这些转换的代码应改用显式构造器。`mojo build --experimental-fixit` 命令可协助迁移。参见
  [数学与数值类型](#0-26-2-math)。

- **初始化统一。** `__moveinit__()` 和 `__copyinit__()` 方法现已重命名为 `__init__()`，分别带仅关键字参数 `take` 和 `copy`。旧名称仍被接受，但应迁移到现代形式。参见
  [初始化统一](#0-26-2-init-unification)。

- **`Stringable` 和 `Representable` 已废弃。** 这些 trait 被统一的 `Writable` trait 替换，后者提供默认实现。大多数标准库类型已经移除了 `Stringable` 和
  `Representable` 一致性。参见
  [String 与文本](#0-26-2-string)。

- **UTF-8 安全性改进。** `String` 和 `StringSlice` 的下标操作在索引落在多字节码点中间时现在会 panic，`String.resize()` 在会产生无效 UTF-8 的操作上会 panic。字节位置下标现在返回整个 Unicode 码点而不是单个字节。参见 [String 与文本](#0-26-2-string)。

- **`trait` 不再继承 `ImplicitlyDestructible`。** trait 声明不再自动符合 `ImplicitlyDestructible`；需要它的 trait 现在必须显式选择加入。这延续了 v0.26.1 在显式销毁类型上的工作，并鼓励生态默认支持线性类型。参见
  [其他变更](#0-26-2-other-language-changes)。

## 文档 {#0-26-2-documentation}

- 在 Mojo 手册中新增了 [给 Python 开发者的 Mojo 提示](/docs/manual/python-to-mojo/) 页面，涵盖 Python 开发者学习 Mojo 时遇到的关键差异。主题包括使用 `var` 的变量声明、类型标注、整数与浮点除法、隐式转换以及其他常见陷阱。如果你从 Python 转来，此页面帮你避免意外、更快地写出地道的 Mojo 代码。

- 在 Mojo 手册中新增了
  [实例初始化深入](/docs/manual/lifecycle/initialization/) 页面。此页面解释逻辑初始化与字段初始化的区别、如何编写满足编译器逐字段初始化要求的 `__init__` 构造器，以及拷贝和移动构造器如何融入初始化模型。对任何使用非平凡结构体类型的人都是必读。

- 在 Mojo 手册中新增了 [泛型](/docs/manual/generics/) 页面，附带条件 trait 一致性的实例。该页面展示了如何使用 `where` 子句声明一个泛型类型仅在其类型参数满足某些条件时才符合某 trait，例如仅当容器元素类型为 `Equatable` 时才使容器为 `Equatable`。

- 重构并扩展了 Mojo 手册的 [元编程](/docs/manual/metaprogramming/) 章节。这包括一个新的介绍页面，概述 Mojo 的编译期元编程模型，以及关于编译期求值、reflection、物化的新页面，还有前面提到的泛型页面。这些变更共同覆盖了此前未文档化的若干主题，并提供了从基本参数到高级元编程技术的更平滑学习路径。

- 更新了 [Jupyter Notebooks](/docs/tools/notebooks/) 页面，新增 Apple Silicon GPU 示例和设置说明，使搭载 M 系列芯片的 macOS 用户可在 notebook 中运行 GPU 加速的 Mojo 代码，无需外接 GPU。

## 语言增强 {#0-26-2-language-enhancements}

- `def` 现在是 Mojo 的标准函数声明关键字。`def` 函数不再隐式抛出，现在与 `fn` 具有相同语义：默认不抛出，接受 `raises` 说明符，并支持带类型的错误。
  `fn` 现已废弃，将在未来版本中移除。我们建议将所有 `fn` 声明切换为 `def`。

  ```mojo
  # Previously
  def foo():                        # Implicitly raised Error.
  fn bar():                         # Did not raise.
  fn baz() raises:                  # Explicitly raised Error.
  fn qux() raises EmptyDictError:   # Raised a typed error.

  # Now
  def foo():                        # Does not raise.
  def bar() raises:                 # Explicitly raises Error.
  def baz() raises EmptyDictError:  # Raises a typed error.
  fn qux():                         # Deprecated: use 'def' instead.
  fn qux() raises:                  # Deprecated: use 'def' instead.
  fn qux() raises EmptyDictError:   # Deprecated: use 'def' instead.
  ```

  此变更通过使错误处理显式化来澄清函数契约：不带 `raises` 的 `def` 保证错误在本地被处理或不会发生，编译器会强制执行此不抛出保证。

- Mojo 现在在结构体声明上支持**条件 trait一致性**。
  一个结构体可声明仅当其类型参数满足某些条件时才符合某 trait，使用一致性列表中的 `where` 子句。`where` 子句接受任意
  [`Bool`](/docs/std/builtin/bool/Bool/) 类型的参数
  表达式。例如，
  [`List`](/docs/std/collections/list/List/) 现在用此特性在元素类型符合时才条件性地符合
  [`Equatable`](/docs/std/builtin/comparable/Equatable/) 和
  [`Writable`](/docs/std/format/Writable/)：

  ```mojo
  struct List[T: Movable](
      Copyable,
      Equatable where conforms_to(T, Equatable),
      Movable,
      Writable where conforms_to(T, Writable),
  ):
      ...
  ```

  下面是一个自包含的小示例：

  ```mojo
  @fieldwise_init
  struct Wrapper[T: Copyable & ImplicitlyDestructible](
      Writable where conforms_to(T, Writable),
  ):
      var value: Self.T

  @fieldwise_init
  struct NotWritable(Copyable, ImplicitlyDestructible):
      var data: Int

  def main():
      var w = Wrapper[Int](42)
      print(w)  # OK — Int is Writable. Prints: Wrapper[Int](value=42)

      var w2 = Wrapper[NotWritable](NotWritable(10))  # OK to construct
      print(w2)  # errors at parse time
  ```

  **当前限制**：尚不支持对
  [`RegisterPassable`](/docs/std/builtin/value/RegisterPassable/)、
  [`TrivialRegisterPassable`](/docs/std/builtin/value/TrivialRegisterPassable/) 和
  [`ImplicitlyDestructible`](/docs/std/builtin/anytype/ImplicitlyDestructible/)
  的条件一致性。

- Mojo 现在支持 t-字符串（模板字符串），用于构建带插值表达式的结构化字符串模板。T-字符串使用 `t"..."` 前缀并产生一个
  [`TString`](/docs/std/format/tstring/TString/) 值，它同时捕获静态格式字符串和任意运行时
  参数，而不是立即产生一个
  [`String`](/docs/std/collections/string/string/String/)：

  ```mojo
  def main():
      var x = 10
      var y = 20
      print(t"{x} + {y} = {x + y}")  # prints: 10 + 20 = 30
  ```

  使用 `{{` 和 `}}` 在输出中包含字面花括号：

  ```mojo
  print(t"Use {{braces}} like this")  # prints: Use {braces} like this
  ```

- Mojo 现在支持 `comptime if` 和 `comptime for` 作为编译期条件和循环结构的首选语法，替换旧的 `@parameter if` 和 `@parameter for` 装饰器形式：

  ```mojo
  # Old syntax (still accepted, deprecated in a future release)
  @parameter
  if some_condition:
      ...

  @parameter
  for i in range(10):
      ...

  # New syntax
  comptime if some_condition:
      ...

  comptime for i in range(10):
      ...
  ```

  本版本两种语法都接受。`@parameter` 形式将很快被废弃，解析器会生成一个警告和修复建议以迁移到新语法。

- Mojo 现在支持独立的 `assert` 语句，类似于 Python 的 `assert`。它在运行时检查条件，若条件为假则中止程序：

  ```mojo
  assert x > 0, "x must be positive"
  assert len(items) != 0
  ```

  条件必须是 `Bool` 表达式，可选的消息可以是任意 `Writable` 表达式（`StringLiteral`、
  `String`、[`Int`](/docs/std/builtin/int/Int/) 等）。在底层，`assert` 脱糖为对
  [`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert/) 的调用，
  因此它遵循既有的 `-D ASSERT` 标志：用 `-D ASSERT=all` 编译时断言激活，否则为空操作。

- Mojo 现在支持
  [`@align`](/docs/reference/decorators/align/)`(N)` 装饰器，用于为结构体指定最小对齐，类似于 C++ 的 `alignas` 和 Rust 的 `#[repr(align(N))]`。值 `N` 必须是 2 的正幂，并以字节为单位指定最小对齐。实际对齐为 `max(N, natural_alignment)`——你不能用 `@align` 将对齐降低到结构体自然对齐以下。例如，对一个包含 `Int`（8 字节对齐）的结构体使用 `@align(1)` 会发出警告，结构体仍将保持 8 字节对齐。

  ```mojo
  from sys import align_of

  @align(64)
  struct CacheAligned:
      var data: Int

  def main():
      print(align_of[CacheAligned]())  # Prints 64
  ```

  栈分配和堆分配都尊重 `@align`。

  对齐值也可以是结构体参数，从而支持通用对齐类型：

  ```mojo
  @align(Self.alignment)
  struct AlignedBuffer[alignment: Int]:
      var data: Int

  def main():
      print(align_of[AlignedBuffer[64]]())   # Prints 64
      print(align_of[AlignedBuffer[128]]())  # Prints 128
  ```

- Mojo 现在支持为推断参数指定默认值，使得创建部分绑定的类型更容易：

  ```mojo
  struct Pointer[mut = False, // o: Origin[mut]] : pass

  # Default to immutable pointer
  comptime ImmPointer = Pointer[_]
  # Explicitly set to mutable pointer
  comptime mutPointer = Pointer[mut = True, _]
  # Inferred mutability from `SomeOrigin()`
  comptime InferredPointer = Pointer[SomeOrigin()]
  # Parametric mutability pointer.
  comptime ParametricPointer = Pointer[...]
  ```

- Mojo 现在强制执行更明确的参数绑定规则：
  - `[]` 是强制性的，用于让类型更具体：

    ```mojo
    struct SomeStruct[a : Int = 1]:
      pass

    # SS1 is a parametric type
    comptime SS1 = SomeStruct

    # SS2 a concrete type alias of `SomeStruct[1]
    comptime SS2 = SomeStruct[]

    ```

  - 使用 `[]` 时，它必须产生一个具体类型，除非使用 `_`/`...`
    来解绑某个/多个缺失参数。

    ```mojo
    struct SomeStruct[a : Int, b: Int, c: Int = 2]:
      pass

    # Error: can not infer `b`, since `[]` must produce a concrete type, without `_`/`...``
    comptime SS1 = SomeStruct[1]

    # This is a concrete type alias of `SomeStruct[1, 1, 2]`
    comptime SS2 = SomeStruct[1, 1]

    # Using `...` defers binding of b and c, and produces `SomeStruct[1, ?, ?]` (preserving possible defaults)
    comptime SS3 = SomeStruct[1, ...]

    # Even though SS3 unbinds `c`, Mojo keeps track of the fact that there is a default value for c:
    # This install b (using 1) and c (using default value), and produce `SomeStruct[1, 1, 2]`
    comptime SS4 = SS3[1]

    # This installs the default and is identical to `SomeStruct[1, ?, 2]`
    comptime SS5 = SomeStruct[1, _]

    # This unbind the default explicitly and is identical to `SomeStruct[1, ?, ?]`
    comptime SS6 = SomeStruct[1, _, _]


    # The following two are equivalent:
    comptime SS7 = SomeStruct
    comptime SS8 = SomeStruct[...]

    ```

- Mojo 现在支持更灵活的默认参数和参数，当其类型是参数化时，可在声明类型上不匹配。这允许在它们作为默认值使用时从中推断参数，例如：

  ```mojo
    def take_string_slice[o: ImmOrigin](str: StringSlice[o] = ""): ...
    def use_it():
      take_string_slice() # Ok, defaults to empty string, inferring "o".
      # Explicit calls also work of course.
      take_string_slice(StaticString("hello"))

    # Default value is checked for validity at the call site.
    def defaultArgumentBadType2[T: AnyType](a: T = 1.0): pass
    def callDefaultArgumentBadType2():
        # Ok!
        defaultArgumentBadType2[Float64]()
        # error: value passed to 'a' cannot be converted from 'FloatLiteral[1]' to 'Int'
        defaultArgumentBadType2[Int]()
  ```

- Mojo 现在允许移动构造器以 `deinit` 或 `var` 接收其“take”参数。一般应优先使用 `deinit`，但在某些不寻常情况下 `var` 很有用——你希望有类似 C++ 的行为，即移动构造器处理完值之后析构器仍会在该值上运行。

  ```mojo
  def __init__(out self, *, var take: Self):
    self.data = munge(take.data)
    # take.__del__() runs here.
  ```

## 语言变更 {#0-26-2-language-changes}

### 初始化统一 {#0-26-2-init-unification}

- 作为“初始化统一”的一部分，`__moveinit__()` 和 `__copyinit__()` 方法
  [已重命名](https://github.com/modular/modular/blob/main/mojo/proposals/remove_move_and_copy_init.md) 为
  `fn __init__(out self, *, take: Self)` 和
  `fn __init__(out self, *, copy: Self)`。Mojo 现在接受这些初始化器名称，但也（暂时）支持旧的 `__moveinit__()` 和
  `__copyinit__()` 名称。但是，这些旧方法的参数名现在必须分别命名为 `take` 和 `copy`。请尽可能迁移到更现代的 `__init__` 名称。

- 作为初始化统一的一部分，
  [`Movable`](/docs/std/builtin/value/Movable/) 和
  [`Copyable`](/docs/std/builtin/value/Copyable/) 的 `__moveinit__is_trivial` 和
  `__copyinit__is_trivial` 成员
  已分别重命名为 `__move_ctor_is_trivial` 和 `__copy_ctor_is_trivial`。

### 废弃 {#0-26-2-language-deprecations}

- `@register_passable("trivial")` 现已废弃。请改为符合
  `TrivialRegisterPassable` trait。该装饰器将在下个版本之后移除。

- `@register_passable` 现已废弃。请改为符合 `RegisterPassable` trait。该装饰器将在下个版本之后移除。

- `LegacyUnsafePointer` 现已废弃。请改用
  [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)。
  查看 `unsafe_pointer.mojo` 中的文档字符串以获取迁移指南。
  `LegacyUnsafePointer` 将在下个版本之后移除。

### `comptime assert` {#0-26-2-comptime-assert}

- 不稳定的 `__comptime_assert` 语法现已最终确定为 `comptime assert`。旧语法会发出带修复建议的废弃警告。

- `comptime assert` 不再对永假条件报错。断言只在其父作用域被具体化时才会触发。

- 静态为 False 的 `comptime assert` 现在会结束一个作用域。同一作用域中其后跟随的任何代码现在都是警告，可被移除。

### 其他变更 {#0-26-2-other-language-changes}

- `**_` 和 `*_` 在参数绑定列表中不再受支持。请使用更简洁的 `...` 来显式解绑任何未指定的参数。

- 同质变长参数现在以
  [`VariadicParamList`](/docs/std/builtin/variadics/VariadicParamList/)
  类型（原 `VariadicList`）传递，参数现在统一以
  [`VariadicList`](/docs/std/builtin/variadics/VariadicList/)
  （原 `VariadicListMem`）传递，而不是直接传递平凡类型。

- 下标中的切片字面量已变更，使其更类似于集合字面量。它们现在向 `__slice_literal__` 关键字参数传递一个空元组以消歧切片。如果你定义了自己的 range 类型，请向其构造器添加一个 `__slice_literal__: () = ()` 参数。

- `trait` 声明不再自动继承 `ImplicitlyDestructible`。`struct` 声明未变更，继续继承 `ImplicitlyDestructible`。

  此前，
  [`@explicit_destroy`](/docs/reference/decorators/explicit-destroy/)
  注解是退出
  `ImplicitlyDestructible` 一致性所必需的。现在，如果某 trait 的用法依赖隐式可销毁性，它必须显式选择加入：

  ```mojo
  # Before
  trait Foo:
      ...

  # After:
  trait Foo(ImplicitlyDestructible):
      ...
  ```

  反之，如果某 trait 想支持非隐式可销毁类型，它不再需要用 `@explicit_destroy` 标注：

  ```mojo
  # Before
  @explicit_destroy
  trait Foo:
      ...

  # After
  trait Foo:
      ...
  ```

  让 `struct` 继续继承 `ImplicitlyDestructible` 而 `trait` 不继承，旨在在常见情况下的可用性与熟悉度，与培养 Mojo 生态对显式销毁类型广泛支持的需求之间取得平衡。

  如果大多数 `struct` 类型在实践中是 `ImplicitlyDestructible`，那不是问题。但是，如果许多生态库在编写时带有不必要的 `ImplicitlyDestructible` 约束，那将妨碍任何单独选择成为显式销毁的 `struct` 类型的可用性。

  带有泛型算法和类型的库应以支持线性类型的方式编写。让 trait 对 `ImplicitlyDestructible` 选择加入，鼓励了支持的默认立场，仅在真正需要时才让特定类型和函数选择加入更窄的 `ImplicitlyDestructible` 要求。

  大多数按引用接收输入的泛型算法应不受影响。

- 从包的 `__init__.mojo` 重新导出的符号不再被同名子模块遮蔽。例如，如果 `pkg/foo.mojo` 定义了 `fn foo` 且 `pkg/__init__.mojo` 执行 `from .foo import foo`，那么 `from pkg import foo` 和 `from pkg import *` 现在会正确解析到该函数而不是模块。

- `is_compile_time()` 已重命名为 `__is_run_in_comptime_interpreter`，它现在是一个关键字而不是函数调用。它提供了一种机制，支持在 comptime 解释器与运行时生成代码中使用不同的代码执行路径。此值不能用作任何 comptime 表达式中的常量，因为对 comptime 表达式它总是求值为 `True`。请将此检查用作运行时 `if` 的条件。如果将其用作 `comptime if` 的条件，编译器现在会发出警告。

- Mojo 支持使用标准 Python `__getitem__()` 和 `__getattr__()` 方法进行下标和命名索引。此前它使用启发式方法来确定 `__get*__` 方法是以动态还是参数索引操作。Mojo 现在有一个简单明确的策略：如果某类型实现了 `__getitem_param__()` 或 `__getattr_param__()` 方法且索引是有效的参数表达式，编译器会选择它（但不支持 `__setitem__()` 配对）。如果不实现或索引只是有效的运行时值，Mojo 会照常尝试 `__getitem__()`/`__setitem__()`。这使行为更可预测、更明确，但要求类型在希望进行参数式下标时切换到 `param` 方法名。这仅影响少量特殊类型，如 `Tuple` 和 `VariadicPack`。

- `@doc_private` 装饰器已重命名为 `@doc_hidden`，以更好地反映其目的是将声明从文档生成中隐藏，而非暗示访问控制的任何变更。旧的 `@doc_private` 名称仍被接受但已废弃，将在未来版本中移除。

## 库变更 {#0-26-2-library-changes}

### 条件一致性 {#0-26-2-conditional-conformances}

- [`Dict`](/docs/std/collections/dict/Dict/) 现在使用真正的
  `Writable` 条件一致性。`Dict` 类型仅在其键和值类型都符合 `Writable` 时才符合 `Writable`，由 `where` 子句在编译期强制执行。

- 标准库类型现在使用条件一致性，替换此前的 `_constrained_conforms_to` 检查：
  - [`Deque`](/docs/std/collections/deque/Deque/):
    `Equatable`、
    [`Hashable`](/docs/std/hashlib/hash/Hashable/)、`Writable`
  - `Dict`: `Writable`、`Equatable`、`Hashable`
  - [`InlineArray`](/docs/std/collections/inline_array/InlineArray/):
    `Copyable`、`Equatable`、`Hashable`、`Writable`
  - [`LinkedList`](/docs/std/collections/linked_list/LinkedList/):
    `Equatable`、`Hashable`、`Writable`
  - `List`: `Equatable`、`Hashable`、`Writable`
  - [`Optional`](/docs/std/collections/optional/Optional/):
    `Hashable`、`Writable`、`Copyable`、
    [`ImplicitlyCopyable`](/docs/std/builtin/value/ImplicitlyCopyable/)
  - [`Set`](/docs/std/collections/set/Set/): `Copyable`、
    [`Comparable`](/docs/std/builtin/comparable/Comparable/)、
    `Equatable`、`Hashable`、`Writable`
  - [`Tuple`](/docs/std/builtin/tuple/Tuple/): `Copyable`、
    `Equatable`、`Hashable`、`ImplicitlyCopyable`、`Writable`
  - [`Variant`](/docs/std/utils/variant/Variant/): `Writable`

### 集合与迭代器 {#0-26-2-collections}

- `Dict` 内部已被替换为使用 SIMD 组探测进行查找的 Swiss Table 实现。这改进了查找、插入和删除性能——尤其是在查找不在 dict 中的键时——同时将负载因子从 2/3 提高到 7/8，以获得更好的内存效率。
  `power_of_two_initial_capacity` 关键字参数已重命名为 `capacity`，现在接受任意正整数（内部向上取整到最近的 2 的幂，最小为 16）。

- 当表已满墓碑但活跃元素数低时，`Dict` 现在执行就地墓碑重哈希。这防止了在反复插入/删除循环后不必要的容量翻倍。

- [`StaticTuple`](/docs/std/utils/static_tuple/StaticTuple/) 现在支持比较运算符。当 `element_type: Equatable` 时提供 `__eq__()`/`__ne__()`，当 `element_type: Comparable` 时提供 `__lt__()`/`__le__()`/`__gt__()`/ `__ge__()`。全部使用编译期展开的循环进行字典序比较。

- [`Set.pop()`](/docs/std/collections/set/Set/#pop) 现在直接使用
  [`Dict.popitem()`](/docs/std/collections/dict/Dict/#popitem)，避免冗余的重哈希。
  顺序从 FIFO 变为 LIFO，匹配 Python 无序 `set.pop()`。

- `Set.__gt__()` 和 `Set.__lt__()` 现在使用 O(1) 的 `len()` 检查加单次 `issubset()` 遍历，而不是两次完整遍历。

- `InlineArray` 现在要求构造时显式使用字面量。
  例如：

  ```Mojo
  var a: InlineArray[UInt8, 4] = [1, 2, 3, 4]
  # instead of InlineArray[UInt8, 4](1, 2, 3, 4)
  ```

- 以下类型现在正确实现了 `write_repr_to()`：
  - `List`、`Set`

- [`itertools`](/docs/std/itertools/) 模块现包含
  三个新的迭代器组合子：
  - [`cycle(iterable)`](/docs/std/itertools/itertools/cycle/):
    创建一个无限循环遍历元素的迭代器
  - [`take_while[predicate](iterable)`](/docs/std/itertools/itertools/take_while/):
    在断言返回 True 时产出元素
  - [`drop_while[predicate](iterable)`](/docs/std/itertools/itertools/drop_while/):
    在断言返回 True 时丢弃元素，然后产出剩余元素

### String 与文本 {#0-26-2-string}

- `Stringable` 和 `Representable` trait 现已废弃。请改用 `Writable` 让你的类型可作为字符串格式化。
  `Writable` 提供默认实现，因此在许多情况下只需添加 `Writable` 一致性就足够了，无需手动实现 `write_to()` 或 `write_repr_to()`，不过你可以手动实现它们以获得自定义输出。

- 标准库正开始移除对 `Stringable` 和 `Representable` trait 的支持，转而使用统一的 `Writable` trait。
  大多数标准库类型已移除了对 `Stringable` 和 `Representable` 的一致性，相关的 `__str__()` 和 `__repr__()` 方法已被废弃。

- `String`、
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 和
  `StringLiteral` 上的 `__reversed__()` 方法已废弃，由新的 `codepoints_reversed()` 方法取代。新方法名明确表示迭代是按逆序遍历 Unicode 码点，与既有的 `codepoints()` 和 `codepoint_slices()` 方法保持一致。已废弃的 `__reversed__()` 方法仍可工作，但会发出废弃警告。

- 从 `String` 构造 `StringSlice` 的构造器现在会传播可变性。如果你有一个指向 `String` 的可变引用，`StringSlice(str)` 返回可变的 `StringSlice`。
  [`String.as_string_slice()`](/docs/std/collections/string/string/String/#as_string_slice)
  方法现已废弃，推荐使用 `StringSlice(str)` 构造器，且
  `String.as_string_slice_mut()` 已被移除。

- [`String.ljust()`](/docs/std/collections/string/string/String/#ljust)、
  `String.rjust()` 和 `String.center()` 已重命名为
  `String.ascii_ljust()`、`String.ascii_rjust()` 和 `String.ascii_center()`。
  `StringSlice` 和 `StaticString` 上的等价方法也同样如此。

- [`String.resize()`](/docs/std/collections/string/string/String/#resize)
  现在在新长度会截断码点时会 panic。
  此前它会产生包含无效 UTF-8 的字符串。

- 当 `fill_byte` >=128 时，`String.resize()` 现在会 panic。此前它会创建无效 UTF-8。

- 当索引落在 UTF-8 编码码点中间时，对 `String` 和 `StringSlice` 进行下标操作现在会 panic。此前它们会返回无效 UTF-8。此 panic 是无条件的。如果你确实想要先前行为，请使用 `.as_bytes()[...]`。

- `StringSlice[byte=]` 下标现在返回 `StringSlice` 而不是 `String`。这与基于 range 的下标一致。

- 按字节位置对 `String` 和 `StringSlice` 进行下标现在会返回整个 Unicode 码点。此前它会返回单个字节，并在索引落在多字节码点起始字节时产生无效 UTF-8。

- `String`、`StringSlice` 和 `StringLiteral` 的 `.format()` 方法现在要求其参数为 `Writable`。

- `TString.write_to()` 现在对格式字符串使用紧凑编码。
  格式字符串在编译期被展平为以 NUL 结尾的字面量段，产生比此前基于结构的预编译条目更小的静态数据和更快的运行时。

- 格式化编译期格式字符串（`StringLiteral`）不再分配内存。它使用 `global_constant` 来存储本会被堆分配的已解析格式化数据。

- T-字符串现在支持 raw 前缀（`rt"..."`），它将反斜杠保留为字面字符，同时仍支持插值。

  ```mojo
  var name = "Mojo"
  print(t"C:\{name}\Documents") # prints "C:\Mojo\Documents"
  ```

- 对 `String` 和 `StringSlice` 进行下标现在要求为 range 索引使用具名参数。例如，`s[1:3]` 现在是 `s[byte=1:3]`。

### 类型系统与 trait {#0-26-2-type-system}

- `Bool` 不再符合
  [`Indexer`](/docs/std/builtin/int/Indexer/) trait。此前，
  `Bool` 可用于索引集合（例如 `nums[True]`），这对强类型语言而言不是理想行为。请使用 `Int(my_bool)` 显式将 `Bool` 转换为索引。

- 以下类型现在符合 `Writable`，并具有 `write_to()` 和 `write_repr_to()` 的自定义实现。
  - `Tuple`
  - `Variant`
  - `Optional`

- 所有带 `@register_passable("trivial")` 装饰器的 trait 和结构体现在都继承 `TrivialRegisterPassable` trait。该装饰器已从它们身上移除。

- 新增 `utils/type_functions` 模块，用于存放类型函数。类型函数是从编译期参数输入产生类型的 `comptime` 声明。与接受和返回运行时值的常规 `fn` 函数不同，类型函数完全在编译期运作——它们接受 `comptime` 参数并求值为一个类型，没有运行时成分。
  - `ConditionalType`——一个类型函数，根据编译期布尔条件在两个类型之间进行条件选择。它是三元条件表达式 `Then if If else Else` 的类型层面等价物。

- 新增 `reflection/traits`，提供编译期元函数（`AllWritable`、`AllMovable`、`AllCopyable`、`AllImplicitlyCopyable`、`AllDefaultable`、`AllEquatable`），当变长类型列表中的所有类型都符合对应 trait 时求值为 `True`。

- 向 `std.utils` 添加了 `UnsafeNicheable` 和 `UnsafeSingleNicheable` trait。这些 trait 允许类型暴露已知的无效位模式（“niches”），可供 `Optional` 和 `Variant` 等容器使用以避免存储单独的 tag，从而使 `size_of[Optional[T]]() == size_of[T]()`。
  `UnsafeSingleNicheable` 是用于类型恰好有一个 niche 值的常见情况的简化子 trait。
  - `Variant` 和 `Optional` 现在自动利用此特性：当变体类型符合条件时，判别 tag 会被完全省略，减小变体的大小。例如，对任何实现了 `UnsafeNicheable` 的 `T`，`size_of[Optional[T]]() == size_of[T]()`。
  - 由于一些编译器限制，`Variant` 在过渡期也只与 `Movable` 类型一起工作，而不是 `AnyType`。

### 数学与数值类型 {#0-26-2-math}

- 从 `Int` 到 [`SIMD`](/docs/std/builtin/simd/SIMD/) 的隐式转换现已废弃，将在未来版本的 Mojo 中移除。这包括废弃从 `Int` 到特定 `SIMD` 标量类型（如 `Int8` 或 `Float32`）的转换。

  > 注意：实验性的 `mojo build --experimental-fixit` 命令在协助迁移代码以反映此变更时可能有用。

  当前依赖隐式转换的代码，例如：

  ```mojo
  def foo(arg: Int) -> Float32:
      return arg
  ```

  应改为使用显式转换：

  ```mojo
  def foo(arg: Int) -> Float32:
      return Float32(arg)
  ```

  有时，当发生从标量 `Int` 到更宽 `SIMD` 值的隐式转换时，编译器会建议一个略显冗长的变更，将类型转换和“splat”一次性完成：

  ```diff
  var bits: SIMD[DType.uint8, 16] = ...
  - var y = bits >> (j * 4)
  + var y = bits >> SIMD[DType.uint8, 16](j * 4)
  ```

  一个更简单的变更是使类型转换显式，并让“splat”继续隐式发生（这将保持支持）：

  ```diff
  var bits: SIMD[DType.uint8, 16] = ...
  - var y = bits >> (j * 4)
  + var y = bits >> UInt8(j * 4)
  ```

  关于 `LayoutTensor.element_type` 也可能发出类似的过于冗长的建议，编译器可能建议形如以下的变更：

  ```diff
  - tensor[i] = i * l
  + tensor[i] = LayoutTensor[DType.uint32, Layout(IntTuple(-1)), stack].element_type(i * l)
  ```

  其中一个更简单的变更就足够了：

  ```diff
  - tensor[i] = i * l
  + tensor[i] = UInt32(i * l)

  # Note: If the tensor's `dtype` is not statically known, this works as well:
  + tensor[i] = Scalar[tensor.dtype](i * l)
  ```

- `SIMD` 的安全除法运算符（`__floordiv__`、`__mod__`、`__divmod__`）现在以逐元素方式返回安全结果。此前如果除数中有*任意*一个元素为零，则返回零结果：

  ```Mojo
  comptime Int32x2 = SIMD[DType.int32, 2]

  var a = Int32x2(99, 99)
  var b = Int32x2(4, 0)
  # Now returns [24, 0]
  # Previously returned [0, 0]
  print(a.__floordiv__(b))
  ```

- [`Int.__truediv__()`](/docs/std/builtin/int/Int/#__truediv__)
  现在执行截断整数除法，返回 `Int` 而不是此前已废弃的 `Float64`。请使用显式 `Float64` 转换进行浮点除法。

- [`SIMD.__round__()`](/docs/std/builtin/simd/SIMD/#__round__)
  的文档现澄清了既有行为：平局时舍入到最近的偶数，而不是远离零。

- [`Int.write_padded()`](/docs/std/builtin/int/Int/#write_padded)
  现在在计算宽度时会考虑负号，使宽度无论正负都一致：

  ```Mojo
  Int(1).write_padded(s, 4)  # writes "   1"
  Int(-1).write_padded(s, 4) # writes "  -1"
  ```

- `SIMD` 现在为整型
  [`DType`](/docs/std/builtin/dtype/DType/) 提供 `write_padded()` 方法，匹配 `Int.write_padded()` 的行为。填充按元素添加。与 `SIMD` 常规打印不同，默认不在元素之间添加空格：

  ```Mojo
  Int32(1).write_padded(s, 4)  # writes "   1"
  Int32(-1).write_padded(s, 4) # writes "  -1"

  # "[   1,  -1,   0,1234]"
  SIMD[DType.int32, 4](1,-1,0,1234).write_padded(s, 4)
  # "[255,255]"
  SIMD[DType.uint8, 2](255).write_padded(s, 1)
  ```

- 向 `std.math` 添加了 [`comb(n, k)`](/docs/std/math/math/comb/) 和
  [`perm(n, k)`](/docs/std/math/math/perm/)，匹配 Python 的
  `math.comb()` 和 `math.perm()`。`comb(n, k)` 计算二项式系数 C(n, k) 而不计算完整阶乘，当 `k > n` 时返回 0。`perm(n, k)` 计算排列 P(n, k)；省略 `k`（默认 `-1`）返回 `n!`。

- `builtin.math` 模块已合并到
  [`math`](/docs/std/math/)。trait
  [`Absable`](/docs/std/math/math/Absable/)、
  [`DivModable`](/docs/std/math/math/DivModable/)、
  [`Powable`](/docs/std/math/math/Powable/)、
  [`Roundable`](/docs/std/math/math/Roundable/) 和函数
  [`abs()`](/docs/std/math/math/abs/)、
  [`divmod()`](/docs/std/math/math/divmod/)、`max()`、
  `min()`、[`pow()`](/docs/std/math/math/pow/)、
  [`round()`](/docs/std/math/math/round/) 现在是
  `math` 模块的一部分，并继续在 prelude 中可用。显式从 `builtin.math` 导入的代码应改为从 `math` 导入。

- `std.math` 中的数学函数（`exp()`、`exp2()`、`log2()`、`erf()`、`tanh()`、`sin()`、`cos()`、`tan()`、`acos()`、`asin()`、`atan()`、`atan2()`、`acosh()`、`asinh()`、`atanh()`、`cosh()`、`sinh()`、`expm1()`、`log10()`、`log1p()`、`logb()`、`cbrt()`、`erfc()`、`j0()`、`j1()`、`y0()`、`y1()`）现在在其签名上使用 `where dtype.is_floating_point()` 子句，而不是函数体内的 `__comptime_assert` 检查。
  这在调用点提供了更好的编译期错误信息。使用这些函数并带有泛型 `dtype` 参数的调用者可能需要添加证据证明（通过 `where` 子句或 `__comptime_assert`）其类型是浮点。

### 指针与内存 {#0-26-2-memory}

- 向 [`memory`](/docs/std/memory/) 模块添加了
  [`uninit_move_n()`](/docs/std/memory/memory/uninit_move_n/)、
  [`uninit_copy_n()`](/docs/std/memory/memory/uninit_copy_n/) 和
  [`destroy_n()`](/docs/std/memory/memory/destroy_n/)
  函数，用于高效的批量内存操作。这些函数处理在连续内存中移动、拷贝和销毁多个值，并对平凡类型使用 `memcpy` 自动优化。它们封装了检查 `__move_ctor_is_trivial`、`__copy_ctor_is_trivial` 或 `__del__is_trivial` 并选择适当实现的常见模式。
  `List` 集合现在内部使用这些函数，以提升代码清晰度和可维护性。

- [`Origin`](/docs/std/builtin/type_aliases/Origin/)
  结构体现在将底层 MLIR origin 作为参数接收而不是存储它。这遵循 `IntLiteral` 及相关类型的设计，并修复了一些内存安全问题。

- [`UnsafeMaybeUninit`](/docs/std/memory/unsafe_maybe_uninit/UnsafeMaybeUninit/)
  已按此重命名，其方法名也更新以反映 `init` 名。它现在还公开一个 `zeroed()` 方法以获取清零的未初始化内存。它在被拷贝或移动时也不再调用 `abort()`，允许更实用的用法。

- [`Span`](/docs/std/memory/span/Span/)`[T]` 不再被限制为 `Copyable` 类型。它现在可与 `T: AnyType` 一起工作。
  有一些限制，包括迭代要求 `T: Copyable`。

### GPU 编程 {#0-26-2-gpu}

- `std.gpu.primitives.warp` 中的
  [`lane_group_sum()`](/docs/std/gpu/primitives/warp/lane_group_sum/)、
  [`lane_group_max()`](/docs/std/gpu/primitives/warp/lane_group_max/) 和
  [`lane_group_min()`](/docs/std/gpu/primitives/warp/lane_group_min/)
  现在总是将归约结果广播到所有参与 lane，使用优化的硬件特定路径（AMD DPP、Blackwell redux 或 butterfly shuffle 模式）。此前的
  `lane_group_sum_and_broadcast()`、`lane_group_max_and_broadcast()` 函数已废弃——请使用短名称。

- [`TileTensor`](/docs/layout/tile_tensor/TileTensor/) 现在支持分层索引。例如，形状为 `(4, (3, 2))` 的 `TileTensor` 可按 `(1)`、`(1, 1)` 或 `(1, (1, 1))` 索引。

- `TileTensor` 现在支持展平到深度 4。

- `nn` 中的许多内核已迁移到使用 `TileTensor`。我们将在未来几周内提供更多关于 `TileTensor` 及其用法的文档。

### FFI 与系统 {#0-26-2-ffi}

- [`ffi`](/docs/std/ffi/) 模块现在是标准库中的顶层模块，而不是嵌套在 `sys` 之下。这提升了 FFI 功能的可发现性。请将导入从 `from sys.ffi import ...` 更新为 `from ffi import ...`。

- 新增
  [`UnsafeUnion`](/docs/std/ffi/unsafe_union/UnsafeUnion/)`[*Ts]`，
  一种用于 FFI 互操作的 C 风格无 tag 联合类型。与 `Variant` 不同，`UnsafeUnion` 不跟踪存储的是哪个类型（无判别式），使其适合与 C 联合互操作及底层类型双关。内存布局完全匹配 C 联合（大小为元素的最大值，对齐为元素的最大值）。

  所有元素类型必须具有平凡的拷贝、移动和销毁操作，匹配 C 联合语义——其中类型没有构造器或析构器。

  构造是显式的（无隐式转换）以强调此类型的不安全性质。所有访问器方法都以 `unsafe_` 为前缀，以明确这些操作是不安全的。

  ```mojo
  from ffi import UnsafeUnion

  # Define a union that can hold Int32 or Float32
  comptime IntOrFloat = UnsafeUnion[Int32, Float32]

  var u = IntOrFloat(Int32(42))
  print(u.unsafe_get[Int32]())  # => 42
  print(u)  # => UnsafeUnion[Int32, Float32](size=4, align=4)

  # Type punning (reinterpreting bits)
  var u2 = IntOrFloat(Float32(1.0))
  print(u2.unsafe_get[Int32]())  # => 1065353216 (IEEE 754 bits)
  ```

- `sys.param_env` 模块中的 `env_get_bool()`、`env_get_int()`、`env_get_string()` 和
  `env_get_dtype()` 函数已在新模块 `sys.defines` 中重命名为 `get_defined_bool()`、`get_defined_int()`、`get_defined_string()` 和 `get_defined_dtype()`。新名称更好地反映这些函数读取的是编译期定义（通过 `-D` 设置），而非运行时环境变量。
  [`is_defined()`](/docs/std/sys/defines/is_defined/) 函数也已移至
  `sys.defines` 而未更名。`sys.param_env` 中的旧名称已废弃但仍可用。

### 测试 {#0-26-2-testing}

- [`testing`](/docs/std/testing/) 模块现在为 `Tuple` 提供
  [`assert_equal`](/docs/std/testing/testing/assert_equal/) 和
  [`assert_not_equal`](/docs/std/testing/testing/assert_not_equal/)
  重载，支持在测试中直接进行元组到元组的比较，而不是逐元素断言。元素类型必须符合 `Equatable & Writable`。

- `assert_equal` 和 `assert_not_equal` 现在可与实现了 `Writable` 的类型一起工作。

### 其他库变更 {#0-26-2-other-library}

- 将
  [`CompilationTarget.unsupported_target_error()`](/docs/std/sys/info/CompilationTarget/#unsupported_target_error)
  更改为返回 `Never` 并移除其 `result` 类型参数。

- 移除了 `DType.get_dtype[T]()` 和 `DType.is_scalar[T]()`。这些是用于在泛型代码中提取 `SIMD` 的 `DType` 的底层操作。如今的 Mojo 中有更好的替代方案可使用 reflection 能力。

- [`perf_counter_ns()`](/docs/std/time/time/perf_counter_ns/) 现在在 GPU 上返回正确的纳秒而不是原始周期计数。此前在 NVIDIA GPU 上它使用 `clock64`（一个依赖 GPU 核心时钟频率的周期计数器）；现在它使用 `globaltimer`，后者提供真正的纳秒分辨率。在 AMD GPU 上，它现在使用 `s_memrealtime`（一个恒速实时时钟）而不是 `s_memtime`（一个周期计数器）。

- [`DimList`](/docs/kernels/buffer/dimlist/DimList/) 类型已改为将维度表示为类型的参数，而不是类型内的值，直接反映维度在编译期已知这一事实。请将 `DimList(x, y)` 改为 `DimList[x, y]()`。

## 工具链变更 {#0-26-2-tooling-changes}

- Mojo 编译器现在除了接受既有的非连接形式外，也接受连接形式的 `-D` 选项。现在 `-Dfoo` 和 `-D foo` 都被接受。

- `mojo build` 现在支持若干 `--print-*` 选项，用于发现目标配置和受支持的架构：
  - `--print-effective-target`: 显示处理所有命令行标志后解析出的目标配置。
  - `--print-supported-targets`: 列出所有可用的 LLVM 目标架构。
  - `--print-supported-cpus`: 列出给定目标三元组的合法 CPU 名称（需要 `--target-triple`）。
  - `--print-supported-accelerators`: 列出所有受支持的 GPU 和加速器架构（NVIDIA、AMD、Apple Metal）。

- `mojo format` 现在默认在目录上运行时只格式化 Mojo 文件（`.mojo`、`.🔥`）。此前它也会格式化 Python 文件，这与 pre-commit 钩子中 Python 专用格式化工具冲突。需要格式化 Python 文件的用户可直接使用 `mblack`。

- `mojo format` 现在支持 `--print-cache-dir`（隐藏，使用 `--help-hidden` 查看），用于显示格式化器缓存目录的路径。

- `mojo build --emit=asm` 现在也会输出 GPU 内核汇编文件，与主机 `.s` 输出并存。对于 NVIDIA 目标，PTX 写为 `<out>_<kernelfn>.ptx`；对于 Apple Metal 目标，LLVM IR 写为 `<out>_<kernelfn>.ll`；对于 AMD 目标，写为 `.amdgcn` 文件。从同一函数生成的多个内核通过数字后缀消歧（例如 `<out>_<kernelfn>_1.ptx`）。

- `mojo doc` 在私有成员的处理上现在与 Python 更一致。任何以下划线（`_`）开头的成员名称都被视为私有，除非它是“dunder”成员（以下划线开头并以下划线结尾）。在实践中，这意味着以双下划线开头但不以双下划线结尾的成员（`__example()`）现在被视为私有。以 `__mlir` 开头的 dunder 方法现在被视为公开，除非用 `@doc_private` 装饰器标记。

## 移除 {#0-26-2-removed}

- `.🔥`（火焰）和 `📦`（包）emoji 文件扩展名不再受支持。所有 Mojo 源文件请使用 `.mojo`，包初始化文件请使用 `__init__.mojo`。移除 emoji 扩展名是为了简化工具链并提升跨不同系统和编辑器的兼容性。

- `owned` 关键字已被移除。请根据情况对参数使用 `var`，或对 `__moveinit__`/`__del__` 参数使用 `deinit`。

- `Dict.EMPTY` 和 `Dict.REMOVED` comptime 别名已被移除。这些是旧哈希表设计的内部实现细节。

- `@nonmaterializable` 装饰器已重命名为 `@__nonmaterializable`。此装饰器不应在标准库之外使用，并可能在未来版本中移除。

## 修复 {#0-26-2-fixed}

- 修复了 Mojo 在 `extern` C 函数调用中错误地传递或返回结构体的 bug。编译器现在在外部调用降阶时应用平台 ABI 强制转换（x86-64 上的 System V AMD64、ARM64 上的 AAPCS），将结构体分解为 C ABI 要求的寄存器类型——匹配 Clang 和 Rust 的行为。这解决了调用接收或返回结构体类型的 C 函数时静默给出错误答案的 bug。

- [Issue #5845](https://github.com/modular/modular/issues/5845): 带转换的自定义抛出类型函数在返回 StringSlice 时失败

- [Issue #5722](https://github.com/modular/modular/issues/5722): 当 `__init__` 在所有字段初始化之前抛出时 `__del__` 错误地运行。

- [Issue #5875](https://github.com/modular/modular/issues/5875): 将宽度 > 1 的 `SIMD[DType.bool, N]` 存储到指针并按元素读回现在返回正确的值。

- [`StringSlice.find`](/docs/std/collections/string/string_slice/StringSlice/#find):
  修复了 SIMD 字符串搜索中的整数溢出 bug，该 bug 导致在搜索长于 `simd_width_of[DType.bool]()` 的字符串和大于 UInt16.MAX 的 haystack 时搜索失败。

- [`LinkedList.reverse()`](/docs/std/collections/linked_list/LinkedList/#reverse):
  修复了缺失的 `prev` 指针更新，该问题导致 `__reversed__()` 在反转后产生错误结果。

- Mojo 此前会将具有 `__moveinit__()` 方法的类型视为 `Movable`，即使它们并不符合 `Movable`。可移动性现在与暗示该方法的一致性绑定。
