## 🔥 传奇

- Trait 来了！

  你现在可以定义一个 *trait*，它由一组必需的方法原型组成。一个 struct
  可以通过实现这些方法来*遵循（conform to）*该 trait。这使你能够
  编写适用于任何遵循给定 trait 的 struct 的泛型函数。

  以下章节简要概述了 trait——更多细节请参阅
  [Mojo 手册](/docs/manual/traits/)和这篇
  [trait 博客文章](https://modul.ar/traits-blog)！

  Trait 使用 `trait` 关键字声明。Trait 的主体应当
  包含以 `...` 作为主体的方法签名。尚不支持默认
  方法实现。

  ```mojo
  trait SomeTrait:
      fn required_method(self, x: Int): ...
  ```

  通过从 trait 继承，可以在 struct 上实现该 trait。

  ```mojo
  struct SomeStruct(SomeTrait):
      fn required_method(self, x: Int):
          print("hello traits", x)
  ```

  然后你可以编写接受任何遵循该 trait 的类型的泛型函数。
  通过创建一个带有 trait 类型参数的参数化函数即可实现：

  ```mojo
  fn fun_with_traits[T: SomeTrait](x: T):
      x.required_method(42)
  ```

  可以用遵循该 trait 的类型的实例来调用它：

  ```mojo
  var thing = SomeStruct()
  # Infer the parameter `T`!
  fun_with_traits(thing)
  ```

  Trait 也可以从其他 trait 继承，这简单地要求子 trait 的实现者
  也遵循所有父 trait。

  ```mojo
  trait Parent:
      fn parent_func(self): ...

  trait Child(Parent):
      fn child_func(self): ...
  ```

  随后，父 trait 和子 trait 的方法都可以在 `Child` trait 的实例上
  调用。同时，子 trait 的实例可以转换为父 trait 的实例。

  ```mojo
  fn the_parents[T: Parent](x: T):
      x.parent_func()

  fn the_children[T: Child](x: T):
      x.child_func()
      x.parent_func()
      # Upcast `x` from instance of `Child` to `Parent`.
      the_parents(x)
  ```

  更多信息，请参阅 Mojo 手册中的
  [Trait 页面](/docs/manual/traits/)。

- 语言中添加了一个基础的 `Destructable` trait。这是一个每个 trait
  都会自动遵循的核心 trait。这使得泛型类型和泛型集合的析构成为可能。

  **注意：** 我们知道这个 trait 也许拼写为 `Destructible` 更合适。
  我们计划在未来移除它，并将其功能移至 `AnyType`，
  这样任何不提供自己析构函数的类型都将拥有一个默认的、空操作的析构函数。

- 我们在标准库中添加了一些 trait，你可以在自己的类型上实现它们：

  - [`Destructable`](/docs/std/builtin/anytype/AnyType/)
  - [`Copyable`](/docs/std/builtin/value/Copyable/)
  - [`Movable`](/docs/std/builtin/value/Movable/)
  - [`Stringable`](/docs/std/builtin/str/Stringable/)
  - [`Intable`](/docs/std/builtin/int/Intable/)
  - [`Sized`](/docs/std/builtin/len/Sized/)
  - [`CollectionElement`](/docs/std/builtin/value/CollectionElement/)

- 我们添加了内建的 [`len()`](/docs/std/builtin/len/len/)、`str()` 和
  `int()` 函数，它们分别适用于实现了 `Sized`、
  `Stringable` 和 `Intable` trait 的类型。

- [`DynamicVector`](/docs/std/collections/list/List/) 现在是
  一个正规的泛型集合，可以使用任何实现了 `Movable`
  和 `Copyable` trait 的类型。这意味着你现在可以编写，例如，
  `DynamicVector[String]`。此外，`DynamicVector` 现在在析构时会调用其元素的
  析构函数，因此 `_del_old` 已被删除。

- `print` 现在适用于任何实现 `Stringable` 的类型，通过调用其
  `__str__` 方法：

  ```mojo
  @value
  struct BoxedInt(Stringable):
      var value: Int

      fn __str__(self) -> String:
          return self.value

  print(BoxedInt(11), "hello traits!", BoxedInt(42))
  ```

## ⭐️ 新增

- [Mojo 手册](/docs/manual/)是一个全新的、完整的 Mojo 用户指南。
  它尚未包含关于 Mojo 的*所有*内容，但它包含了很多，
  而且比原先的编程手册（现已弃用）内容更多。

  此外，整个 Mojo 手册和其他 Mojo 文档现在已
  [在 GitHub 上开源](https://github.com/modular/modular/tree/main/mojo/docs)，
  我们非常乐意接受贡献以帮助改进它们！

- Mojo 现在支持部分自动参数化：当函数声明带有一个部分绑定类型的
  参数时，该类型的未绑定参数会隐式添加到函数的输入参数中。例如：

  ```mojo
  @value
  struct Fudge[a: Int, b: Int, c: Int = 7]: ...

  # These function declarations are roughly equivalent:
  fn eat(f: Fudge[5]): ...               # implicitly parameterized
  fn eat[_b: Int](f: Fudge[5, _b]): ...  # explicitly parameterized
  ```

  在 `eat()` 的第一个签名中，`b` 参数未绑定，因此它被*隐式*
  添加为函数的输入参数。

  在 `eat()` 的第二个签名中，作者显式定义了一个
  输入参数（`_b`），它绑定到参数类型的第二个参数（恰好是 `b`）。

  这两个函数都可以这样调用：

  ```mojo
  eat(Fudge[5, 8]())
  ```

  Mojo 从实参中推断 `b` 参数的值（本例中为 8）。

  使用第二个签名，你还可以显式传递 `_b` 参数值：

  ```mojo
  eat[3](Fudge[5, 3]())
  ```

  此外，Mojo 现在允许你使用 `_` 显式标记参数为未绑定，
  其语法含义是“未绑定参数的占位符”。例如：

  ```mojo
  # These function declarations are roughly equivalent:
  fn eat(f: Fudge[5, _, c=_]): ...                    # implicitly parameterized
  fn eat(f: Fudge[c=_, a=5, b=_]): ...                # implicitly parameterized
  fn eat[_b: Int, _c: Int](f: Fudge[5, _b, _c]): ...  # explicitly parameterized
  ```

  前两个签名显式地取消绑定 `b` 和 `c` 参数。

  在最后一个签名中，`_b` 和 `_c` 参数由作者显式声明，
  并绑定到参数类型中的 `b` 和 `c` 参数。

  这些签名中的任何一个都可以这样调用：

  ```mojo
  eat(Fudge[5, 8]())
  eat(Fudge[5, 8, 9]())
  ```

  注意，struct 参数的默认参数值是绑定的，除非用户显式取消绑定。

  更多信息，请参阅
  [Mojo 手册](/docs/manual/parameters/#fully-bound-partially-bound-and-unbound-types)。

- 参数化类型现在可以在某些上下文中部分绑定。例如，
  添加了一个新的 `Scalar` 类型别名，定义为：

  ```mojo
  alias Scalar = SIMD[size=1]
  ```

  这创建了一个参数化类型别名 `Scalar`，带有单个 `DType` 类型的
  参数。类型在其他上下文中也可以部分或完全绑定。例如，
  函数内类型值的 `alias` 声明现在可以正常工作：

  ```mojo
  fn type_aliases():
      alias T = SIMD
      print(T[DType.float32, 1]())
      alias Partial = T[type=DType.int32]
      print(Partial[2]())
  ```

- `__mlir_op` 功能现在支持返回多个结果的操作。
  要使用它们，你需将 `_type` 字段写为类型的 `Tuple`。例如：

  ```mojo
  # The `ret` variable has type `Tuple[Int, Int]`.
  let ret = __mlir_op.`multi_result_op`[_type=(Int, Int)]()
  ```

- Mojo 现在能够使用
  [`read_bytes()`](/docs/std/io/file/FileHandle/#read_bytes) 方法从文件读取
  原始字节。例如：

  ```mojo
  with open("file.binary", "r") as f:
      data = f.read_bytes()
  ```

- 内建 `file.FileHandle` 上的
  [`read()`](/docs/std/io/file/FileHandle/#read) 和
  [`read_bytes()`](/docs/std/io/file/FileHandle/#read_bytes) 方法添加了
  size 参数。size 参数默认为 -1，并在 size 为负数时保持先前的
  “读取到 EOF”行为。

  ```mojo
  with open("file.binary", "r") as f:
      data1 = f.read_bytes(1024)
      data2 = f.read_bytes(256)
  ```

- [`Path`](/docs/std/pathlib/path/Path/) 现在拥有 `read_bytes()` 和
  `read_text()` 方法，用于从路径读取文件内容：

  ```mojo
  let text_path = Path("file.txt")
  let text = text_path.read_text()

  let binary_path = Path("file.binary")
  let data = binary_path.read_bytes()
  ```

- `Tensor` 新增了 `save()` 和 `load()` 方法，用于保存和加载文件。这些
  方法会保留形状和数据类型信息。例如：

  ```mojo
  let tensor = Tensor[DType.float32]()
  tensor.save(path)

  let tensor_from_file = Tensor[DType.float32].load(path)
  ```

- 为
  [`DTypePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 和
  [`Pointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 添加了下标操作：

  ```mojo
  let p = DTypePointer[DType.float16].alloc(4)
  for i in range(4):
      p[i] = i
      print(p[i])
  ```

- `file.FileHandle` 现在拥有一个 `seek()` 方法。

- [`String`](/docs/std/collections/string/string/String/) 现在拥有一个
  [`rfind()`](/docs/std/collections/string/string/String/#rfind) 方法，
  类似于 Python 的 `str.rfind()`。

- `String` 现在拥有一个
  [`split()`](/docs/std/collections/string/string/String/#split) 方法，
  类似于 Python 的 `str.split()`。

- [`Path`](/docs/std/pathlib/path/Path/) 现在拥有一个
  [`suffix()`](/docs/std/pathlib/path/Path/#suffix) 方法，
  类似于 Python 的 `pathlib.Path.suffix`。

- Mojo REPL 现在支持缩进表达式，使得执行从缩进块（例如文档字符串）
  中复制的表达式稍微更容易。

- Mojo 语言服务器现在实现了 Document Symbols 请求。IDE 利用
  此功能来支持**大纲视图（Outline View）**和**转到符号（Go to Symbol）**。
  此修复对应 [Issue #960](https://github.com/modular/modular/issues/960)。

- Mojo 语言服务器现在会在补全 `import` 语句中的模块
  或包时显示文档。

- Mojo 语言服务器现在支持处理文档字符串内部定义为 markdown Mojo 代码块的
  代码示例。这使得在 API 文档中编写示例时能够使用 IDE 功能。

- Mojo 语言服务器现在提供语义 token 信息，为那些语义无法静态分析的
  符号提供更好的高亮。

- Mojo 语言服务器现在将文档字符串分类为折叠区域，
  使它们更容易折叠，从而在编辑时减少垂直空间占用。

- `mojo` 驱动程序中接受参数的命令行选项现在可以
  以两种方式之一编写：`--foo FOO` 和 `--foo=FOO` 均可。此前
  仅前者有效。

## 🦋 变更

- 可变列表类型
  [`VariadicList`](/docs/std/builtin/variadics/VariadicList/) 和
  [`VariadicListMem`](/docs/std/builtin/variadics/VariadicListMem/)
  现在可迭代。可变参数会在函数体内部自动投影为这些
  类型之一，因此可变参数可被迭代：

  ```mojo
  fn print_ints(*nums: Int):
      for num in nums:
          print(num)
      print(len(nums))
  ```

- [`testing`](/docs/std/testing/testing/) 包中的 assert 函数
  现在在断言失败时会抛出 `Error`，而不是返回一个表示断言是否成功的
  `Bool`。

- [`AnyType`](/docs/std/builtin/type_aliases/) 类型的参数不再
  被隐式假定为 register passable。一个新的 `AnyRegType` 类型
  用于表示 register passable 的泛型类型。

- 在 [`benchmark`](/docs/std/benchmark/benchmark/) 报告中更改单位
  现在改为通过参数而非参数传递：

  ```mojo
  let report = benchmark.run[timer]()
  report.print(Unit.ms)
  ```

- `inout` 参数上的默认值不再被允许，即以下代码现在会抛出错误：

  ```mojo
  fn inout_default(inout x: Int = 2): ...
  ```

- `to_string()` 函数已从
  [`PythonObject`](/docs/std/python/python_object/PythonObject/) 中移除，改为
  使用新的 `__str__()` 函数。它与 trait 的组合性更好，因此可以
  与泛型 `str()` 函数一起使用。
