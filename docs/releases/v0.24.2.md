## 🔥 Legendary

- Mojo 标准库现已开源!请查看 [README](https://github.com/modular/modular/blob/main/mojo/stdlib/README.md) 了解入门所需的一切。

- struct 和其他名义类型现在允许隐式遵循 trait。如果一个 struct 实现了某 trait 的所有要求,则它隐式遵循该 trait。例如,任何实现了 `__str__()` 方法的 struct 都隐式遵循 `Stringable`,并可与 `str()` 内置函数一起使用。

  ```mojo
  @value
  struct Foo:
      fn __str__(self) -> String:
          return "foo!"

  fn main():
      print(str(Foo())) # prints 'foo!'
  ```

  我们仍强烈建议在可能时显式列出 struct 所遵循的 trait:

  ```mojo
  @value
  struct Foo(Stringable): ...
  ```

  这不仅对文档和传达意图很有用,而且在未来,显式遵循对于默认方法和扩展等特性也会很有用。

- Mojo 的 Python 互操作性现在支持向 Python 函数传递关键字参数:

  ```mojo
  from python import Python

  def main():
      plt = Python.import_module("matplotlib.pyplot")
      plt.plot((5, 10), (10, 15), color="red")
      plt.show()
  ```

## Language changes

### ⭐️ New

- Mojo 现在支持可变关键字参数,通常称为 `**kwargs`。这意味着你现在可以像这样声明和调用函数:

  ```mojo
  fn print_nicely(**kwargs: Int) raises:
    for key in kwargs.keys():
        print(key[], "=", kwargs[key[]])

   # prints:
   # `a = 7`
   # `y = 8`
  print_nicely(a=7, y=8)
  ```

  有关更多详情(以及当前限制列表),请参阅 Mojo 手册中的[可变关键字参数](/docs/manual/functions#variadic-keyword-arguments)。

### 🦋 Changed or removed

- `let` 声明现在会产生编译时错误而非警告,这是我们[移除 let 声明](https://github.com/modular/modular/blob/main/mojo/proposals/remove-let-decls.md)的下一步。编译器目前仍识别 `let` 关键字以便给出良好的错误信息,但这将在后续版本中移除。

- Mojo 现在会对 `def` 和 `fn` 声明中未使用的值都发出警告,而不是完全在 `def` 中禁用该警告。它从不会对未使用的 `object` 或 `PythonObject` 值发出警告,而是将警告与这些类型关联,而不是与它们所在的函数种类关联。这将有助于捕获 `def` 中的 API 使用错误,并使导入的 Python API 在 `fn` 中更符合人体工程学。

- 暂时地,动态类型值将在语言中被禁用。例如,以下写法现在会因错误而失败:

  ```mojo
  var t = Int  # dynamic type values not allowed

  struct SomeType: ...

  takes_type(SomeType)  # dynamic type values not allowed
  ```

  我们希望退一步(重新)设计类型值变量、存在类型和其他动态特性。这不会影响类型值**参数**,因此以下写法仍如往常一样工作:

  ```mojo
  alias t = Int  # still 🔥

  struct SomeType: ...

  takes_type[SomeType]()  # already 🔥

  >fn uses_trait[T: SomeTrait](value: T): ... # still 🔥
  ```

- 参数表达式中的 `*_` 表达式现在必须出现在位置参数列表的末尾,而不允许出现在中间。

  ```mojo
  # No longer supported
  alias FirstUnbound = SomeStruct[*_, 42]
  alias MidUnbound   = SomeStruct[7, *_, 6]
  # Still supported
  alias LastUnbound  = SomeStruct[42, *_]
  ```

  我们之所以收窄这一范围,是因为我们希望鼓励类型设计者把参数顺序排对,并且未来希望将 `*_` 扩展为支持关键字参数。

## Standard library changes

### ⭐️ New

- `DynamicVector` 已重命名为 [`List`](/docs/std/collections/list/List/),并已从 `collections.vector` 模块移至 `collections.list` 模块。此外:

  - 你现在可以从可变数量的值构造一个 `List`。例如:

    ```mojo
    var numbers = List[Int](1, 2, 3)
    ```

  - `List` 和 [`InlinedFixedVector`](/docs/std/collections/inline_array/InlineArray/) 类型现在支持负数索引。这意味着你可以写 `vec[-1]`,它等价于 `vec[len(vec)-1]`。

  - `List.push_back()` 已被移除。请改用 `append()` 函数。

- [`print()`](/docs/std/io/io/print/) 函数现在接受 `sep` 和 `end` 关键字参数。这意味着你可以这样写:

  ```mojo
  print("Hello", "Mojo", sep=", ", end="!!!\n") # prints Hello, Mojo!!!
  ```

  `sep` 默认为空字符串,`end` 默认为 "\n"。

  另外,`print_no_newline()` 函数已被移除。请改用 `print(end="")`。

- [`FloatLiteral`](/docs/std/builtin/float_literal/FloatLiteral/) 类型现在是一个无限精度的不可物化类型。这意味着你可以使用 `FloatLiteral` 进行无舍入误差的编译时计算。在运行时物化时,`FloatLiteral` 值会被转换为 [`Float64`](/docs/std/builtin/simd/)。

  ```mojo
  # third is an infinite-precision FloatLiteral value
  alias third = 1.0 / 3.0
  # t is a Float64
  var t = third
  ```

- 所有字符串类型现在都遵循 [`IntableRaising`](/docs/std/builtin/int/IntableRaising/) trait。这意味着你现在可以调用 `int("123")` 来获取整数 `123`。如果无法从字符串解析出整数,则会抛出错误。

- `Tensor` 类型现在拥有 `argmax()` 和 `argmin()` 函数,用于计算最大值或最小值的位置。注意:这应当返回 `Tensor[Int]`,但目前输出 tensor 与输入 tensor 类型相同。这将在未来版本中修复。

- 新增 [`collections.OptionalReg`](/docs/std/collections/optional/OptionalReg/) 类型,它是 [`Optional`](/docs/std/collections/optional/Optional/) 的可寄存器传递替代方案。

- `math` 模块中新增 [`ulp()`](/docs/std/math/math/ulp/) 函数。它允许你获取浮点值的最低精度单位(或最后一位单位)。

### 🦋 Changed

- [`DTypePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)、`Buffer` 和 `NDBuffer` 上的 `simd_load()`、`simd_store()`、`aligned_simd_load()` 和 `aligned_simd_store()` 方法已被合并为一组更具表达力的 `load()` 和 `store()` 方法,并带有仅关键字的 `width` 和 `alignment` 参数:

  ```mojo
  # Doesn't work
  my_simd = my_buffer.simd_load[simd_width](index)
  # Works
  my_simd = my_buffer.load[width=simd_width](index)
  # Doesn't work
  my_buffer.aligned_simd_store[width, alignment](my_simd)
  # Works
  my_buffer.store[width=width, alignment=alignment](my_simd)
  ```

- `EqualityComparable` trait 现在除了之前要求的 `__eq__()` 方法外,还要求实现 `__ne__()` 方法以遵循该 trait。

- 许多类型现在声明遵循 `EqualityComparable` trait。

- [`StaticTuple`](/docs/std/utils/static_tuple/StaticTuple/) 的参数顺序已更改为 `StaticTuple[type, size]`,以与 `SIMD` 及类似的集合类型保持一致。

- [`elementwise()`](/docs/std/algorithm/functional/elementwise/) 函数的签名已更改。新顺序为 `function`、`simd_width`,然后是 `rank`。结果是,rank 参数现在可以被推断,你可以不带它调用 `elementwise()`:

  ```mojo
  elementwise[func, simd_width](shape)
  ```

- `PythonObject` 现在是可寄存器传递的。

- `PythonObject.__iter__()` 现在可在更多类型的可迭代 Python 对象上正确工作。尝试对不可迭代的对象进行迭代现在会抛出异常,而不是表现为迭代空序列。`__iter__()` 现在也借用 `self` 而非要求 `inout`,允许如下代码:

  ```mojo
  for value in my_dict.values():
    ...
  ```

### 🚚 Moved

- 我们借开源 Mojo 标准库之机,将一些模块重新归位到其正确的包中。具体而言,以下是一些值得指出的破坏性变更。请相应更新你的导入语句。

  - `Buffer`、`NDBuffer` 及相关类型已从 `memory` 包移至新的 `buffer` 包。

    ```mojo
    from buffer import Buffer, NDBuffer
    ```

  - `utils.list`,包括 [`Dim`](/docs/std/buffer/dimlist/Dim/) 和 [`DimList`](/docs/std/buffer/dimlist/DimList/) 类型,已移至 `buffer` 包。

    ```mojo
    from buffer import Dim, DimList
    ```

  - [`parallel_memcpy()`](/docs/std/algorithm/memory/parallel_memcpy/) 函数已从 `memory` 包移至 `buffer` 包。

    ```mojo
    from buffer import parallel_memcpy
    ```

  - `random` 包中返回 `Tensor` 的 `rand()` 和 `randn()` 函数已移至 `tensor` 包。注意,写入 `DTypePointer` 的重载仍保留在 `random` 包中。

    如果你恰好在同一源文件中使用两个版本,可以使用 `import as` 语法同时导入两者:

    ```mojo
    from tensor import rand
    from random import rand as rand_dt
    ```

  - `trap()` 函数已重命名为 [`abort()`](/docs/std/os/os/abort/)。它也从 `debug` 模块移至 `os` 模块。

    ```mojo
    from os import abort
    ```

  - [`isinf()`](/docs/std/utils/numerics/isinf/) 和 [`isfinite()`](/docs/std/utils/numerics/isfinite/) 方法已从 `math.limits` 移至 `math` 模块。

    ```mojo
    from math import ininf, isfinite
    ```

## Tooling changes

### ⭐️ New

- 文档字符串代码块现在可以使用 `%#` 在文档生成时隐藏代码行。

  例如:

  ```mojo
  var value = 5
  %# print(value)
  ```

  将生成如下文档:

  ```mojo
  var value = 5
  ```

  隐藏的行在测试执行时会像普通代码行一样被处理。这允许在文档字符串示例中编写额外代码,仅用于确保示例可运行/可测试。

- Mojo LSP 服务器现在允许你指定额外的搜索路径,用于在文档中解析导入模块。你可以在命令行上使用 `-I` 选项指定搜索路径,也可以将它们添加到 VS Code 扩展的 `mojo.lsp.includeDirs` 设置中。

## Other changes

### ❌ Removed

- `__get_address_as_lvalue` 魔法函数已被移除。你现在可以通过解引用操作符(`[]`)从 `Pointer` 或 `Reference` 获取 LValue:

  ```mojo
  var ptr: Pointer[MyRecord]
  ...
  # Doesn't work
  __get_address_as_lvalue(ptr.value) = MyRecord(3, 5)
  # Works
  ptr[] = MyRecord(3, 5)
  ```

- `memcpy` 函数的类型参数现在会自动推断。这意味着形如 `memcpy[Dtype.xyz](...)` 的调用将不再有效,用户需要将代码改为 `memcpy(...)`。

- 适用于 `Buffer` 类型的 [`memcpy()`](/docs/std/memory/memory/memcpy/) 重载已被移除,改为仅保留适用于 [`Pointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 和 [`DTypePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 的重载:

  ```mojo
  # Doesn't work
  memcpy(destBuffer, srcBuffer, count)
  # Works
  memcpy(destBuffer.data, srcBuffer.data, count)
  ```

- `math.limit` 中的 `max_or_inf()`、`min_or_neginf()` 函数已被移除。这些函数仅由 SIMD 类型使用。

- 如前所述,`print_no_newline()` 函数已被移除。请改用 `print(end="")`。
