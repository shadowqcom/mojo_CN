## ✨ Highlights

- `AnyPointer` 已重命名为 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/),现在是 Mojo 首选的不安全指针类型。它有若干增强,包括:

  - 元素类型现在可以是任何类型:它不再要求 `Movable`。

  - 因此,`take_value()`、`emplace_value()` 和 `move_into()` 方法已改为顶层函数并被重命名。新函数为:

    - [`initialize_pointee_copy`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_copy)
    - [`initialize_pointee_move`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_move)
    - [`move_from_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#take_pointee)
    - [`move_pointee`](/docs/std/memory/unsafe_pointer/UnsafePointer/#move_pointee_into)

  - 新增 [`destroy_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#destroy_pointee) 函数,在所指对象上运行析构器。

  - `UnsafePointer` 可以直接通过 `UnsafePointer(someRef)` 从 `Reference` 初始化,并可通过 `yourPointer[]` 转换为引用。两者都会推断元素类型和地址空间。请注意,当将指针转换为引用时,Mojo 无法跟踪原始值的生命周期。因此,得到的引用并不比原始指针更安全。

- 所有指针类型都进行了一些清理以使其更一致,例如 `unsafe.bitcast()` 全局函数现在是统一的指针上的 [`bitcast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#bitcast) 方法,它可以转换元素类型和地址空间。

- 对可变参数支持进行了改进。

  - 异构可变参数包参数现在即使在内存类型下也能可靠工作,并拥有更便利的 API,如 [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 类型所定义。例如,`print` 的简化版本可以像这样实现:

    ```mojo
    fn print[T: Stringable, *Ts: Stringable](first: T, *rest: *Ts):
        print_string(str(first))

        @parameter
        fn print_elt[T: Stringable](a: T):
            print_string(" ")
            print_string(a)
        rest.each[print_elt]()
    ```

  - Mojo 现在支持声明同时具有可选参数和可变参数的函数,既可以是位置的也可以是仅关键字的。例如,以下写法现在可行:

    ```mojo
    fn variadic_arg_after_default(
      a: Int, b: Int = 3, *args: Int, c: Int, d: Int = 1, **kwargs: Int
    ): ...
    ```

    位置可变参数在存在可选参数时也能工作。即:

    ```mojo
    fn variadic_param_after_default[e: Int, f: Int = 2, *params: Int]():
      pass
    ```

    请注意,目前尚不支持可变关键字参数。

  有关更多信息,请参阅 Mojo 手册中的[可变参数](/docs/manual/functions/#variadic-arguments)。

- `mojo build` 和 `mojo run` 命令现在支持 `-g` 选项。这个更短的别名等价于写 `--debug-level full`。该选项在 `mojo debug` 命令中也可用,且已是默认。

- 许多新的标准库 API 已填充,包括许多社区贡献。变更列在标准库章节中。

- Mojo 手册新增了一个关于[类型](/docs/manual/types/)的页面。

## Language changes

- 某些接受索引(`__getitem__()`、`__setitem__()` 和 `__refitem__()`)或名称(`__getattr__()` 和 `__setattr__()`)的 dunder 方法现在可以将索引或名称作为参数值而非实参值接受。当你定义这些方法之一且除 `self`(对于 getter)或 `self` 和被设置的值(对于 setter)外没有其他实参时,该功能即被启用。

  这使得只能用参数进行下标操作的类型成为可能,以及如下示例之类的事情,它将属性名作为参数传递,以便在编译时检查属性名。

  ```mojo
  struct RGB:
     fn __getattr__[name: StringLiteral](self) -> Int:
         @parameter
         if name == "r":   return ...
         elif name == "g": return ...
         else:
             constrained[name == "b", "can only access with r, g, or b members"]()
             return ...

  var rgb = RGB()
  print(rgb.b) # Works
  print(rgb.q) # Compile error
  ```

- Mojo 现在允许用户使用 `__source_location()` 和 `__call_location()` 函数动态捕获代码的源位置和函数的调用位置。例如:

  ```mojo
  from builtin._location import __call_location

  @always_inline
  fn my_assert(cond: Bool, msg: String):
      if not cond:
        var call_loc = __call_location()
        print("In", call_loc.file_name, "on line", str(call_loc.line) + ":", msg)

  fn main():
      my_assert(False, "always fails")  # some_file.mojo, line 193
  ```

  这会打印 "`In /path/to/some_file.mojo on line 193: always fails`"。请注意,`__call_location()` 仅在 `@always_inline` 或 `@always_inline("nodebug")` 函数中工作。如果它被放在一个从 `@always_inline("nodebug")` 函数*调用的* `@always_inline` 函数中,会给出错误结果。

  该功能仍在演进中,暂时你需要显式导入这些 API,如上所示。未来,这些可能会成为内置函数,不需要导入语句。

  `__source_location()` 和 `__call_location()` 在参数上下文中调用时都不工作。例如:

  ```mojo
  from builtin._location import __call_location

  @always_inline
  fn mystery_location() -> String:
      var loc = __call_location()
      return str(loc.file_name)

  def main():
      alias doesnt_work = mystery_location() # <unknown location in parameter context>
  ```

## Standard library changes

### ⭐️ New

- [`List`](/docs/std/collections/list/List/) 有几个新方法:

  - `pop(index)` 用于在特定索引处移除元素。默认情况下,`List.pop()` 移除列表中的最后一个元素。
    (@LJ-9801, 修复了
    [#2017](https://github.com/modular/modular/issues/2017))

  - `resize(new_size)` 用于调整列表大小,无需指定额外值。
    ([@mikowals](https://github.com/mikowals), 修复了
    [#2133](https://github.com/modular/modular/issues/2133))

  - `insert(index, value)` 用于在指定索引处向 `List` 插入值。([@whym1here](https://github.com/whym1here), 修复了
    [#2134](https://github.com/modular/modular/issues/2134))

  - 新构造器 `List(ptr, size, capacity)`,以避免在构造新 `List` 时对现有连续内存分配进行深拷贝。([@StandinKP](https://github.com/StandinKP), 修复了
    [#2170](https://github.com/modular/modular/issues/2170))

- [`Dict`](/docs/std/collections/dict/Dict/) 现在拥有 `update()` 方法,用于从另一个 `Dict` 更新键/值。
  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

- [`Set`](/docs/std/collections/set/Set/) 现在拥有集合操作的命名方法:
  - `difference()` 对应 `-`
  - `difference_update()` 对应 `-=`
  - `intersection_update()` 对应 `&=`
  - `update()` 对应 `|=`

  ([@arvindavoudi](https://github.com/arvindavoudi))

- `Dict`、`List` 和 `Set` 都遵循 `Boolable` trait。当这些集合包含任何元素时求值为 `True`,否则为 `False`:

  ```mojo
  def list_names(names: List[String]):
      if names:
          for name in names:
              print(name[])
      else:
          print("No names to list.")
  ```

  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

- 新增 [`reversed()`](/docs/std/builtin/reversed/reversed/) 函数用于创建反向迭代器。几种 range 类型、`List` 和 `Dict` 现在支持反向迭代。

  ```mojo
  var numbers = List(1, 2, 3, 4, 5)
  for number in reversed(numbers):
      print(number)
  ```

  ([@helehex](https://github.com/helehex) 和
  [@jayzhan211](https://github.com/jayzhan211), 贡献于
  [#2325](https://github.com/modular/modular/issues/2325))

- [`Optional`](/docs/std/collections/optional/Optional/) 现在实现了 `__is__` 和 `__isnot__` 方法,因此你可以将 `Optional` 与 `None` 进行比较。例如:

  ```mojo
  var opt = Optional(1)
  if opt is not None:
      print(opt.value()[])
  ```

  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

- [`Tuple`](/docs/std/builtin/tuple/Tuple/) 现在可以与仅内存元素类型(如 `String`)一起工作,并允许你通过参数表达式直接索引。这意味着你现在可以像 Python 一样简单地使用 `x = tup[1]`,而不是 `x = tup.get[1, Int]()`。你现在也可以通过 `tup[1] = x` 赋值给 tuple 元素。

  ```mojo
  var tuple = ("Green", 9.3)
  var name = tuple[0]
  var value = tuple[1]
  ```

  请注意,由于下标必须是参数表达式,因此你无法使用普通的 `for` 循环遍历 `Tuple`。

- `Reference` 类型有几项变更,包括:

  - 它已从 `memory.unsafe` 移至 `memory.reference` 模块。
  - `Reference` 现在拥有 [`unsafe_bitcast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#bitcast) 方法,类似于指针类型。

  - 几个不安全方法已被移除,包括 `offset()`、`destroy_element_unsafe()` 和 `emplace_ref_unsafe()`。这是因为 `Reference` 是一个安全类型——请使用 `UnsafePointer` 进行不安全操作。

- [`Bool`](/docs/std/builtin/bool/Bool/) 现在可以从任何遵循 [`Boolable`](/docs/std/builtin/bool/Boolable/) trait 的类型隐式转换。这意味着你不再需要编写如下代码:

  ```mojo
  @value
  struct MyBoolable:
    fn __bool__(self) -> Bool: ...

  fn takes_boolable[T: Boolable](cond: T): ...

  takes_boolable(MyBoolable())
  ```

  相反,你可以简单地写:

  ```mojo
  fn takes_bool(cond: Bool): ...

  takes_bool(MyBoolable())
  ```

  请注意,对 `takes_bool()` 的调用会执行隐式转换,因此在某些情况下仍然最好显式声明类型参数,例如:

  ```mojo
  fn takes_two_boolables[T: Boolable](a: T, b: T):
    # Short circuit means `b.__bool__()` might not be evaluated.
    if a.__bool__() and b.__bool__():
      ...
  ```

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 现在遵循 [`KeyElement`](/docs/std/collections/dict/#keyelement) trait,意味着它可以用作 [`Dict`](/docs/std/collections/dict/Dict/) 的键类型。这允许你在 Mojo 中轻松构建并与 Python 字典交互:

  ```mojo
  def main():
      d = PythonObject(Dict[PythonObject, PythonObject]())
      d["foo"] = 12
      d[7] = "bar"
      d["foo"] = [1, 2, "something else"]
      print(d)  # prints `{'foo': [1, 2, 'something else'], 7: 'bar'}`
  ```

- [`FileHandle.seek()`](/docs/std/io/file/FileHandle/#seek) 现在拥有一个 `whence` 参数,默认值为 `os.SEEK_SET`,用于从文件开头定位。你现在可以设置为 `os.SEEK_CUR`,以当前 `FileHandle` 定位位置为偏移:

  ```mojo
  var f = open("/tmp/example.txt")
  # Skip 32 bytes
  f.seek(os.SEEK_CUR, 32)
  ```

  或 `os.SEEK_END` 以从文件末尾偏移:

  ```mojo
  # Start from 32 bytes before the end of the file
  f.seek(os.SEEK_END, -32)
  ```

- [`FileHandle.read()`](/docs/std/io/file/FileHandle/#read) 现在可以直接读入 [`DTypePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/):

  ```mojo
  var file = open("/tmp/example.txt", "r")

  # Allocate and load 8 elements
  var ptr = DTypePointer[DType.float32].alloc(8)
  var bytes = file.read(ptr, 8)
  print("bytes read", bytes)
  print(ptr.load[width=8]())
  ```

- `sys` 模块现在包含一个 `exit()` 函数,可以以指定的错误码退出 Mojo 程序。

  ```mojo
  from sys import exit

  exit(0)
  ```

- `Tensor` 的构造器已更改为更一致。结果是,当用指针数据构造 tensor 时,构造器将 shape 作为第一个实参(而非第二个)。

  如果你向 `Tensor` 构造器传递单个标量值,它现在会将该值广播到 tensor 的所有元素。例如,`Tensor[DType.float32](TensorShape(2,2), 0)` 构造一个以全零初始化的 `2x2` tensor。这提供了一种简单的填充 tensor 数据的方式。

- [`String`](/docs/std/collections/string/string/String/) 现在拥有 `removeprefix()` 和 `removesuffix()` 方法。
  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

- [`ord`](/docs/std/collections/string/string/ord/) 和 [`chr`](/docs/std/collections/string/string/chr/) 函数已改进,可接受任何 Unicode 字符。([@mzaks](https://github.com/mzaks),
  贡献于 [#1616](https://github.com/modular/modular/issues/1616))

- [`atol()`](/docs/std/collections/string/string/atol/) 现在可以处理空白字符。`atol()` 函数在内部由 `String.__Int__()` 使用,因此 `int(String( " 10 "))` 现在返回 `10`,而不是抛出错误。
  ([@artemiogr97](https://github.com/artemiogr97))

- [`SIMD`](/docs/std/builtin/simd/SIMD/) 现在实现了 `__rmod__()` 方法。([@bgreni](https://github.com/bgreni), 修复了
  [#1482](https://github.com/modular/modular/issues/1482))

- [`bool(None)`](/docs/std/builtin/bool/bool-function/) 现已实现。
  (@zhoujingya)

- [`DTypePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 类型现在实现了 `gather()`,用于从当前指针的偏移处收集 `SIMD` 向量。类似地,添加了对 `scatter()` 的支持,用于将 `SIMD` 向量散射到当前指针的偏移处。
  ([@leandrolcampos](https://github.com/leandrolcampos))

- [`len()`](/docs/std/builtin/len/len/) 函数现在可以处理以负结束值指定的 [`range()`](/docs/std/builtin/range/range/),从而使 `len(range(-1))` 等能正确工作。
  ([@soraros](https://github.com/soraros))

- [`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert/) 现在会在其错误信息中打印其位置(被调用处的文件名、行号和列号)。类似地,[`testing`](/docs/std/testing/testing/) 模块中的 `assert` 辅助函数现在在其消息中包含位置信息。

- [`testing.assert_equal[SIMD]()`](/docs/std/testing/testing/assert_equal/) 函数现在在比较的两个 `SIMD` 实参中任意元素不匹配时都会抛出错误。
  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

- [`testing.assert_almost_equal()`](/docs/std/testing/testing/assert_almost_equal/) 和 [`math.isclose()`](/docs/std/math/math/isclose/) 函数现在拥有一个 `equal_nan` 标志。当设置为 `True` 时,NaN 被视为相等。

- `object` 类型现在支持除法、取模和左/右移位操作符,包括就地变体和反向变体。
  (@LJ-9801, 修复了
  [#2224](https://github.com/modular/modular/issues/2224))

- 为 `SIMD` 整数添加了检查算术运算。

  `SIMD` 整数类型(包括像 `Int64` 这样的有大小整数标量)现在可以使用以下新方法执行检查加法、减法和乘法:

  - `add_with_overflow()`
  - `sub_with_overflow()`
  - `mul_with_overflow()`

  检查算术允许调用者确定操作是否超出了该类型的数值限制。例如:

  ```mojo
  var simd = SIMD[DType.int8, 4](7, 11, 13, 17)
  var product: SIMD[DType.int8, 4]
  var overflow: SIMD[DType.bool, 4]
  (product, overflow) = simd.mul_with_overflow(simd)
  for i in range(len(product)):
    if overflow[i]:
            print("<overflow>")
        else:
            print(product[i])
  ```

  ([@lsh](https://github.com/lsh))

- 新增 [`os.remove()`](/docs/std/os/os/remove/) 和 [`os.unlink()`](/docs/std/os/os/unlink/) 用于删除文件。
  ([@artemiogr97](https://github.com/artemiogr97), 修复了
  [#2306](https://github.com/modular/modular/issues/2306))

### 🦋 Changed

- [`parallel_memcpy()`](/docs/std/algorithm/memory/parallel_memcpy/) 函数已从 `buffer` 包移至 `algorithm` 包。请相应更新你的导入。

- [`Optional.value()`](/docs/std/collections/optional/Optional/#value) 现在返回所包含值的引用,而不是副本。

  要手动执行拷贝,请对结果进行解引用:

  ```mojo
  var result = Optional(123)

  var value = result.value()[]
  ```

  ([@lsh](https://github.com/lsh), 修复了
  [#2179](https://github.com/modular/modular/issues/2179))

- 根据已接受的社区提案,[将字节序列表示为无符号 8 位整数序列](https://github.com/modular/modular/blob/main/mojo/proposals/byte-as-uint8.md),已开始向使用 `UInt8` 过渡,将 `Error` 的数据指针改为 `DTypePointer[DType.uint8]`。
  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse), 贡献于
  [#2317](https://github.com/modular/modular/issues/2317))

- 在各种标准库 API 和内部实现中,继续从遗留 `Pointer` 类型过渡到 `UnsafePointer`。
  ([@gabrieldemarmiesse](https://github.com/gabrieldemarmiesse))

## Tooling changes

- 未指定输出 `-o` 实参时 `mojo build` 的行为略有变化:`mojo build ./test-dir/program.mojo` 现在将可执行文件输出到 `./program` 路径,而以前它会输出到 `./test-dir/program` 路径。

- `mojo package` 命令不再支持 `-D` 标志。所有编译环境标志应在包使用时(例如 `mojo run` 或 `mojo build`)提供。

- REPL 不再允许类型级变量声明未初始化,例如它会拒绝 `var s: String`。这是因为它(暂时)无法跨单元格正确跟踪生命周期,因此此类代码会导致崩溃。你可以通过初始化为一个虚拟值并在稍后覆盖来绕过此限制。此限制仅适用于顶层变量,函数中的变量工作方式一如既往。

## Other changes

### Low-level language changes

- 新增一个低层 `__get_mvalue_as_litref(x)` 内置,用于在不检查底层值初始化状态的情况下,以 `!lit.ref` 值的形式访问底层内存表示。这在非常底层的逻辑中很有用,但并非为通用可用性而设计,未来可能会发生变化。

- 现在可以在内联 MLIR op 上指定属性:

  ```mojo
  _ = __mlir_op.`kgen.source_loc`[
      _type = (
          __mlir_type.index, __mlir_type.index, __mlir_type.`!kgen.string`
      ),
      _properties = __mlir_attr.`{inlineCount = 1 : i64}`,
  ]()
  ```

  如上例所示,在 op 构造期间可以传入受保护的 `_properties` 属性,其值为 MLIR `DictionaryAttr`。

### ❌ Removed

- 已移除对"仅寄存器"可变参数包的支持。请将如下示例中的 `AnyRegType` 升级为 `AnyType`,而不是:

  ```mojo
  fn your_function[*Types: AnyRegType](*args: *Ts): ...
  ```

  这一改动让你能访问更好的 API,且对非平凡类型具有内存安全性和正确性的好处。如果你需要类型上的特定 API,请使用正确的 trait 而非 `AnyType`。

- `List.pop_back()` 已被移除。请改用 `List.pop()`,它默认弹出列表中的最后一个元素。

- `SIMD.to_int(value)` 已被移除。请改用 `int(value)`。

- `__get_lvalue_as_address(x)` 魔法函数已被移除。要获取值的引用,请使用 `Reference(x)`,如果需要不安全指针,可使用 `UnsafePointer.address_of(x)`。
