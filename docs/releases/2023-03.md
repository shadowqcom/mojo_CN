## 2023-03-27 那一周

- 📢 参数名在函数签名中不再具有关键作用。这
  为定义高阶函数提供了更大灵活性，因为作为
  参数传入的函数不必其参数名匹配。

   ```mojo
   # Define a higher-order function...
   fn generator[
      func: __mlir_type[`!kgen.signature<`, Int, `>() -> !kgen.none`]
   ]():
      pass

   # Int parameter is named "foo".
   fn f0[foo: Int]():
      pass

   # Int parameter is named "bar".
   fn f1[bar: Int]():
      pass

   fn main():
      # Both can be used as `func`!
      generator[f0]()
      generator[f1]()
   ```

   请期待改进的函数类型语法...

- 📢 两个魔法运算符，名为 `__get_lvalue_as_address(x)` 和
  `__get_address_as_lvalue` 将存储 LValue 与 `!kgen.pointer`
  类型之间相互转换（分别）。这在使用 `Pointer[T]`
  库类型时最有用。`Pointer(to=lvalue)` 方法在内部使用第一个。
  第二个目前必须显式使用，可用于
  将指针投影为可以传递并用作 self 值的引用，例如：

  ```mojo
  # "Replacement new" SomeHeavy value into the memory pointed to by a
  # Pointer[SomeHeavy].
  __get_address_as_lvalue(somePointer.value) = SomeHeavy(4, 5)
  ```

  注意，`__get_address_as_lvalue` 假设指定地址已存在值，
  因此上面的赋值会在重新赋值前运行 `SomeHeavy`
  析构函数（如果有）。

- `__mlir_op` 中的 `(((x)))` 语法已被移除，转而使用
  `__get_lvalue_as_address`，它解决相同问题且更通用。

- 📢 当使用可变 `self` 参数调用结构体的 `__init__` 方法时，
  现在必须像其他可变方法一样用 `&` 声明。这通过使 `__init__`
  与其他可变方法一致来澄清
  变更模型。

- 📚 添加可变字符串 join 函数。

- 📚 在可能时以 0 或 null 默认初始化值。

- 📚 添加压缩、对齐和掩码存储内联函数。

## 2023-03-20 那一周

- 初始 `String` 类型已加入标准库，附带一些非常基础
  的方法。

- 添加 `DimList`，以消除在整个
  标准库中使用 MLIR 列表类型的需要。

- 📢 用于拷贝值的 `__clone__` 方法现已更名为 `__copy__`，以
  更好地遵循 Python 的术语。

- 📢 `__copy__` 方法现在将其 self 参数作为 "read" 值接受，
  而不是按引用接受。这使其更易编写，适用于
  `@register_passable` 类型，并向早期优化器和数据流分析 pass
  暴露更多优化机会。

  ```mojo
  # Before:
  fn __clone__(inout self) -> Self: ...

  # After:
  fn __copy__(self) -> Self: ...
  ```

- 📢 新增 `@register_passable("trivial")` 可应用于
  无需自定义 `__copy__` 或 `__del__` 方法、且其状态仅由
  `@register_passable("trivial")` 类型组成的结构体。这消除了
  为 `Int` 等平凡类型定义 `__copy__` 样板的需要，并减少了
  编译器为平凡类型生成的 IR 数量。

- 现在你可以写回到由计算左值表达式产生的结构体属性。例如
  当 `a[i]` 由 `__getitem__`/`__setitem__` 调用产生时，
  `a[i].x = ..` 可工作。这通过执行 `a[i]` 的读取、
  更新临时值再执行写回实现。

- 将非参数化、`@register_passable` 类型用作
  参数值的剩余障碍已清除。诸如 `Int` 之类的类型应能作为
  参数值充分使用。

- 函数调用中已添加参数包推断。调用带参数包的函数时
  现在可以省略包类型：

  ```mojo
  fn foo[*Ts: AnyType](*args: *Ts): pass

  foo(1, 1.2, True, "hello")
  ```

  注意，参数包的语法也已更改。

- 📚 添加运行时字符串类型。

- 📚 引入 DimList 结构体，以消除使用低级 MLIR
  操作的需要。

## 2023-03-13 那一周

- 📢 结构体的初始化器现在使用 `__init__` 而非 `__new__`，
  遵循 Python 的标准做法。你可以用两种
  风格之一编写它们，传统风格中你变更 self：

  ```mojo
  fn __init__(self, x: Int):
      self.x = x
  ```

  或者作为返回实例的函数：

  ```mojo
  fn __init__(x: Int) -> Self:
      return Self {x: x}
  ```

  注意，`@register_passable` 类型必须使用后一种风格。

- 📢 默认参数约定现在改为 `borrowed` 约定。"read"
  参数像 C++ 的 `const&` 一样传递，因此在向函数传递值时
  无需调用拷贝构造函数（即 `__clone__` 方法）。与 C++ 的 `const&`
  有两点不同：

  1. 未来的借用检查器将确保不存在与不可变借用
     并存的可变别名。
  2. `@register_passable` 值直接在 SSA 寄存器中传递（因此
     通常在机器寄存器中），而不是使用额外的引用
     包装。这更高效，是 `@register_passable` 值如
     整数和指针的"正确默认"。

  这也为从 `__clone__` 方法参数中移除引用要求铺平了道路，
  使我们能填充更多对它们的支持。

- Mojo 已添加对可变包参数的支持。现在可以
  编写异质可变包，例如：

  ```mojo
  fn foo[*Ts: AnyType](args*: Ts): pass

  foo[Int, F32, String, Bool](1, 1.5, "hello", True)
  ```

- 添加了 `owned` 参数约定。该参数约定
  表示函数取得参数的所有权，并负责
  管理其生命周期。

- 添加了 `borrowed` 参数约定。该约定表示
  被调用方获得对调用方上下文中值的不可变共享引用。

- 📚 将 `getenv` 函数添加到 `OS` 模块，以启用获取环境
  变量。

- 📚 在 `NDBuffer` 中启用动态步长。

## 2023-03-06 那一周

- 📢 已支持将捕获型 async 函数用作参数。

- 📢 返回结果参数已从 `return` 语句移到一个新的
  `param_return` 语句。这允许从可抛出函数中返回结果
  参数：

  ```mojo
  @raises
  fn foo[() -> out: Int]():
      param_return[42]
      raise Error()
  ```

  以及在 `@parameter if` 分支中返回不同参数：

  ```mojo
  fn bar[in: Bool -> out: Int]():
      @parameter
      if in:
          param_return[1]
      else:
          param_return[2]
  ```

- 📢 Mojo 现在支持在函数末尾省略不可达的返回。例如：

  ```mojo
  fn foo(cond: Bool) -> Int:
      if cond:
          return 0
      else:
          return 1

  fn bar() -> Int:
      while True:
          pass
  ```

- 字符串字面量现在支持拼接，因此 `"hello " "world"`
  会被视为与 `"hello world"` 相同。

- 函数、结构体和控制流语句的空函数体不再
  允许。请在其中使用 `pass` 显式标记为空，
  就像 Python 中一样。

- 📢 Mojo 中的结构体现在默认驻留在内存中，而非在
  寄存器中传递。这对通用性（大型
  结构体、指针身份重要的结构体等）是正确默认，并且是
  借用模型的关键技术。对于 `Int` 和 `SIMD` 等简单类型，
  它们可以标记为 `@register_passable`。

  注意，仅内存类型目前有一些限制：它们不能用于
  接受并返回 `!mlirtype` 参数的泛型算法，也
  不能用于参数表达式。因此，许多
  类型必须标记为 `@register_passable` 才能绕过限制。我们
  预计随时间推移启用这些用例。

- 📢 Mojo 现在支持计算左值，这意味着你终于可以赋值给
  下标表达式，而不必显式调用 `__setitem__`。

  一些细节：Mojo 允许你定义多个 `__setitem__`
  重载，但会挑选与你的 `__getitem__` 类型匹配的那个（若
  存在）。它允许你通过引入相关值的临时拷贝将计算左值传入
  inout 参数。

- Mojo 现在对在参数表达式和作为参数值类型中使用寄存器主结构体类型
  有更好支持。这将允许
  许多标准库类型从使用裸 MLIR 类型如
  `__mlir_type.index` 迁移到使用 `Int`。这推动我们
  消除到处都是 MLIR 类型，使结构体类型在
  参数系统中成为一等公民。

- 📚 添加一个 `sort` 函数。

- 📚 添加 non-temporal store 以启用缓存旁路。
