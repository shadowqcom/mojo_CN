## 要点

- 旧的 `borrowed`/`inout` 关键字和 `-> T as foo` 语法已被弃用，
  现在会生成编译器警告。请改为使用 `read`/`mut`/`out`
  参数语法。更多信息请参阅 Mojo 手册中的
  [参数约定](/docs/manual/values/ownership/#argument-conventions)。

- `bool()`、`float()`、`int()` 和 `str()` 函数已被弃用，
  会生成编译器警告。请改为使用 `Bool()`、`Float64()`、`Int()` 和
  `String()` 构造函数。更多详情请参阅
  [标准库变更](#25-1-standard-library-changes)。

- 标准库中有许多与字符串相关的变更。新的
  [`Char`](/docs/std/collections/string/codepoint/Codepoint/) 结构体
  表示单个 Unicode 字符，并包含若干用于分类字符类型的方法。
  当使用 `for` 循环遍历 `String` 的字符时，现在应使用
  [`String.chars()`](/docs/std/collections/string/string/String/#chars) 方法
  来提供一个 `Char` 值的迭代器，或使用
  [`String.char_slices()`](/docs/std/collections/string/string/String/#char_slices)
  方法来为每个字符提供一个
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)
  实例的迭代器。`StringRef` 已被移除，由
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 取代。
  此外，各种功能已从 `String` 和 `StringLiteral` 迁移到更通用的
  `StringSlice` 类型。更多详情请参阅
  [标准库变更](#25-1-standard-library-changes)。

- 你现在可以使用 [`SIMD`](/docs/std/builtin/simd/SIMD/) 构造函数将
  现有的 `SIMD` 值（包括 `Scalar` 值）转换为不同的类型，不过
  你仍可使用 [`SIMD.cast()`](/docs/std/builtin/simd/SIMD/#cast)
  方法来推断新向量的大小。更多详情请参阅
  [标准库变更](#25-1-standard-library-changes)。

## 语言变更 {#25-1-language-changes}

- 旧的 `borrowed`/`inout` 关键字和 `-> T as foo` 语法现在会生成
  警告。请改为使用 `read`/`mut`/`out` 参数语法。更多信息请
  参阅 Mojo 手册中的
  [参数约定](/docs/manual/values/ownership/#argument-conventions)。

- 初始化方法现在被视为返回 `Self` 实例的静态方法。这意味着
  初始化方法的 `out` 参数现在与其他任何函数结果或 `out` 参数
  被同等对待。这通常是不可见的，只是像 `instance.__init__()`
  和 `x.__copyinit__(y)` 这样的模式不再有效。只需将其分别替换为
  `instance = T()` 和 `x = y`。

- [`@value`](/docs/reference/decorators/value/) 装饰器现在还会
  派生 `ExplicitlyCopyable` trait 的实现。
  这将有助于 Mojo 集合类型默认过渡到显式可复制要求。

- 对同构元组进行索引现在会得到一致的元素类型，
  无需 rebind：

  ```mojo
    var x = (1, 2, 3, 3, 4)
    var y : Int = x[idx]     # Just works!
  ```

- 你现在可以用一个仅关键字参数来重载位置参数，并使用不同名称
  的仅关键字参数：

  ```mojo
    struct OverloadedKwArgs:
        var val: Int

        fn __init__(out self, single: Int):
            self.val = single

        fn __init__(out self, *, double: Int):
            self.val = double * 2

        fn __init__(out self, *, triple: Int):
            self.val = triple * 3

        fn main():
            OverloadedKwArgs(1)        # val=1
            OverloadedKwArgs(double=1) # val=2
            OverloadedKwArgs(triple=2) # val=6
  ```

  这同样适用于索引操作：

  ```mojo
  struct OverloadedKwArgs:
    var vals: List[Int]

    fn __init__(out self):
        self.vals = List[Int](0, 1, 2)

    fn __getitem__(self, idx: Int) -> Int:
        return self.vals[idx]

    fn __getitem__(self, *, idx2: Int) -> Int:
        return self.vals[idx2 * 2]

    fn __setitem__(mut self, idx: Int, val: Int):
        self.vals[idx] = val

    fn __setitem__(mut self, val: Int, *, idx2: Int):
          self.vals[idx2 * 2] = val


  fn main():
      var x = OverloadedKwArgs()
      print(x[1])       # 1
      print(x[idx2=1])  # 2

      x[1] = 42
      x[idx2=1] = 84

      print(x[1])       # 42
      print(x[idx2=1])  # 84
  ```

- `__disable_del x` 操作已被收紧，将 `x` 的所有字段视为在删除点
  已被消耗，因此它应在对所有子字段进行转移或其他方式消耗之后
  （例如在函数末尾）使用，而不是在使用这些字段之前使用。

## GPU 编程 {#25-1-gpu-programming}

- 新的 [`gpu` 包](/docs/std/gpu/) 提供了用于 GPU 编程的底层
  编程构造。Mojo `gpu` API 允许你手动管理 CPU 主机与 GPU 设备
  之间的交互、管理设备之间的内存、同步线程等。目前使用这些
  API 的最佳方式是在
  [MAX 自定义操作](https://docs.modular.com/max/develop/custom-ops/)
  内部。

  以下代码示例展示了一个用 Mojo 编写的 GPU 内核：

  ```mojo
  from max.tensor import ManagedTensorSlice
  from gpu import thread_idx, block_dim, block_idx

  fn gpu_add_kernel(out: ManagedTensorSlice, x: ManagedTensorSlice[out.type, out.rank]):
      tid_x = thread_idx.x + block_dim.x * block_idx.x
      tid_y = thread_idx.y + block_dim.y * block_dim.y
      if tid_x < x.dim_size(0) and tid_y < x.dim_size(1):
          out[tid_x, tid_y] = x[tid_x, tid_y] + 1
  ```

  上面的示例仅包含在 GPU 上运行的实际内核代码，
  不包括定义自定义操作或启动内核的代码。有关更完整的示例，
  请参阅
  [`vector_addition.mojo`](https://github.com/modular/modular/blob/main/max/examples/custom_ops/kernels/vector_addition.mojo)
  和
  [`top_k.mojo`](https://github.com/modular/modular/blob/main/max/examples/custom_ops/kernels/top_k.mojo)。

- [`layout` 包](/docs/layout/) 包含用于处理
  *layouts*（布局）的 API，布局描述了张量的组织方式（例如行主序
  或列主序布局），以及
  [`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/) 类型，
  该类型表示具有指定布局的张量。`layout` 包可用于
  构建在 GPU 上运行的高效张量操作。

  我们将在未来的版本中继续为 `gpu` 和
  `layout` 包添加代码示例和文档。

## 标准库变更 {#25-1-standard-library-changes}

- 用于将值转换为不同类型的内置函数已被实际构造函数取代：

  | **Before** | **After**   |
  |------------|-------------|
  | `bool()`   | `Bool()`    |
  | `float()`  | `Float64()` |
  | `int()`    | `Int()`     |
  | `str()`    | `String()`  |

  这些函数是 Mojo 还无法区分隐式构造和显式构造时的临时方案。
  在本版本中你会收到弃用警告，在下一个版本中它们将变为编译错误。
  你可以通过 `Match Case` 和 `Match Whole Word`
  搜索并替换 `int(` 为 `Int(` 等方式快速更新代码。

- [`String`](/docs/std/collections/string/string/) 及相关类型：

  - 添加了 [`Char`](/docs/std/collections/string/codepoint/Codepoint/)，用于
    表示和存储单个 Unicode 字符。

    - `Char` 实现了
      `CollectionElement`、
      [`EqualityComparable`](/docs/std/builtin/comparable/#equalitycomparable)、
      [`Intable`](/docs/std/builtin/int/Intable/) 和
      `Stringable`。

    - `Char` 提供了用于分类字符类型的方法，包括：
      [`Char.is_ascii()`](/docs/std/collections/string/codepoint/Codepoint/#is_ascii)、
      [`Char.is_ascii_digit()`](/docs/std/collections/string/codepoint/Codepoint/#is_ascii_digit)、
      [`Char.is_ascii_upper()`](/docs/std/collections/string/codepoint/Codepoint/#is_ascii_upper)、
      [`Char.is_ascii_lower()`](/docs/std/collections/string/codepoint/Codepoint/#is_ascii_lower)、
      [`Char.is_ascii_printable()`](/docs/std/collections/string/codepoint/Codepoint/#is_ascii_printable)、
      [`Char.is_posix_space()`](/docs/std/collections/string/codepoint/Codepoint/#is_posix_space)、
      [`Char.is_python_space()`](/docs/std/collections/string/codepoint/Codepoint/#is_python_space)。

    - 添加了从 `Char` 构造的 `String()` 构造函数。

    - `Char` 可通过
      [`Char.to_u32()`](/docs/std/collections/string/codepoint/Codepoint/#to_u32)
      转换为 `UInt32`。

    - [`chr()`](/docs/std/collections/string/string/chr/) 在收到
      不是有效 `Char` 的码点值时现在会中止。

  - `StringRef` 已被移除，由
    [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 取代。
    这两种类型是 ABI 兼容的，若要获得完全相同的行为，可以使用
    `StaticString`，它是
    `StringSlice[StaticConstantOrigin]` 的别名。

  - 各种功能已从 `String` 和 `StringLiteral` 迁移到更通用的
    `StringSlice` 类型。

  - 添加了
    [`StringSlice.from_utf8()`](/docs/std/collections/string/string_slice/StringSlice/#from_utf8)
    工厂方法，用于从包含 UTF-8 编码数据的缓冲区构造经过验证的 `StringSlice`。
    如果缓冲区内容不是有效的 UTF-8，此方法将引发异常。

  - 添加了
    [`StringSlice.chars()`](/docs/std/collections/string/string_slice/StringSlice/#chars)，
    它返回一个 `Char` 迭代器。这是一个兼容的 UTF-8 解码器，
    返回字符串中编码的每个 Unicode 码点。

  - 添加了
    [`StringSlice.__getitem__(Slice)`](/docs/std/collections/string/string_slice/StringSlice/#__getitem__)，
    它返回一个子字符串。仅支持步长为 1。

  - 若干标准库函数已改为接受 `StringSlice`
    而不是 `String`。这使它们可通用于内存中任何经过适当编码的
    字符串，而无需字符串是堆分配的。这包括：
    [`ascii()`](/docs/std/collections/string/string/ascii/)、
    [`atol()`](/docs/std/collections/string/string/atol/)、
    [`atof()`](/docs/std/collections/string/string/atof/)、
    [`b16decode()`](/docs/std/base64/base64/b16decode/)、
    [`b16encode()`](/docs/std/base64/base64/b16encode/)、
    [`b64decode()`](/docs/std/base64/base64/b64decode/)、
    [`b64encode()`](/docs/std/base64/base64/b64encode/) 和
    [`ord()`](/docs/std/collections/string/string/ord/)。

  - 添加了新的
    [`String.chars()`](/docs/std/collections/string/string/String/#chars) 和
    [`String.char_slices()`](/docs/std/collections/string/string/String/#char_slices)
    迭代器方法，并弃用了现有的 `String.__iter__()` 方法。

    不同的使用场景可能更倾向于遍历字符串中编码的 `Char`，
    或遍历包含单个字符的子切片。这两种遍历语义都不是显然的默认
    行为，因此现有的 `__iter__()`
    方法已被弃用，暂时改为编写显式的遍历方法。

    以下形式的代码：

    ```mojo
    var s: String  = ...
    for c in s:
        # ...
    ```

    可以迁移到使用 `.char_slices()` 方法：

    ```mojo
    var s: String = ...
    for c in s.char_slices():
        # ...
    ```

  - 添加了
    [`StringSlice.char_length()`](/docs/std/collections/string/string_slice/StringSlice/#char_length)
    方法，与现有的
    [`StringSlice.byte_length()`](/docs/std/collections/string/string_slice/StringSlice/#byte_length)
    方法相配套。

  - [`String.__len__()`](/docs/std/collections/string/string/String/#__len__)
    和
    [`StringSlice.__len__()`](/docs/std/collections/string/string_slice/StringSlice/#__len__)
    方法现在返回字符串的字节长度。

    此前，这些方法的文档说明它们最终会返回 Unicode 码点长度。
    现已改为保证返回字节长度，因为字节长度是它们当今最常用的使用方式
    （例如作为底层内存操作逻辑的边界）。此外，码点长度是字符串长度的一种更
    专门化的概念，很少是正确的度量。

    知道需要码点长度的用户可以使用 `str.char_length()` 方法，
    或 `len(str.chars())`。

  - `StringSlice` 现在实现了
    `Representable`，并且该
    实现现在被 `String.__repr__()` 和
    `StringLiteral.__repr__()` 使用。

  - `StringSlice` 现在实现了
    [`EqualityComparable`](/docs/std/builtin/comparable/#equalitycomparable)。

    此前，`StringSlice` 已实现更通用的 `__eq__()` 和
    `__ne__()` 与具有任意其他 origin 的 `StringSlice` 类型进行比较。
    但是，为了满足 `EqualityComparable`，`StringSlice` 现在还具有
    更窄的比较方法，仅支持与具有完全相同 origin 的另一个
    `StringSlice` 进行比较。

  - `String.write()` 静态方法已迁移到 `String()` 构造函数，
    并现已进行缓冲。不要这样做：

    ```mojo
    var msg = "my message " + String(x) + " " + String(y) + " " + String(z)
    ```

    它会重新分配 `String`，你应改为：

    ```mojo
    var msg = String("my message", x, y, z, sep=" ")
    ```

    这样更整洁，并缓冲到栈上，使 `String` 仅分配一次。

  - 你现在可以将任何 [`Writer`](/docs/std/format/Writer/) 传递给
    `write_buffered()`：

    ```mojo
    from utils.write import write_buffered

    var string = String("existing string")
    write_buffered(string, 42, 42.4, True, sep=" ")
    ```

    这会先写入栈上的缓冲区，再重新分配 `String`。

- 集合：

  - 新的 [`LinkedList`](/docs/std/collections/linked_list/LinkedList/) 类型
    已添加到标准库中。

  - 添加了
    [`Optional.copied()`](/docs/std/collections/optional/Optional/#copied)，用于
    通过复制指针所指对象，从 `Optional[Pointer[T]]` 构造一个
    owned `Optional[T]`。

  - 添加了 [`Dict.get_ptr()`](/docs/std/collections/dict/Dict/#get_ptr)，它
    返回一个 `Optional[Pointer[V]]`。如果字典中存在给定的键，
    optional 将持有指向该值的指针。否则，返回一个空的 optional。

  - 添加了新的 [`List.extend()`](/docs/std/collections/list/List/#extend)
    重载，接受 [`SIMD`](/docs/std/builtin/simd/SIMD/) 和
    [`Span`](/docs/std/memory/span/Span/)。这些方法通过复制 `SIMD` 向量
    或 `Span[Scalar[..]]` 的元素来扩展 `List[Scalar[..]]`，
    简化了某些感知 SIMD 的优化功能的编写。

- [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 变更：

  - `UnsafePointer` 的 `bitcast()` 方法现已拆分为
    [`bitcast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#bitcast) 用于
    更改类型、
    [`origin_cast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#origin_cast)
    用于更改可变性、
    [`static_alignment_cast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#static_alignment_cast)
    用于更改对齐方式，以及
    [`address_space_cast()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#address_space_cast)
    用于更改地址空间。

  - `UnsafePointer` 现在按可变性进行参数化。此前，
    `UnsafePointer` 只能表示可变指针。

    新的 `mut` 参数可用于将 `UnsafePointer` 限制为特定的
    可变性：`UnsafePointer[T, mut=False]` 表示指向不可变 `T` 值的指针。
    这类似于 C++ 中的 `const *` 指针。

  - [`UnsafePointer.address_of()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#address_of)
    现在会从参数推断所得指针的 origin 和可变性。例如：

    ```mojo
    var local = 10
    # Constructs a mutable pointer, because `local` is a mutable memory location
    var ptr = UnsafePointer.address_of(local)
    ```

    要强制构造一个指向原本可变内存位置的不可变指针，请使用
    cast：

    ```mojo
    var local = 10
    # Cast the mutable pointer to be immutable.
    var ptr = UnsafePointer.address_of(local).origin_cast[mut=False]()
    ```

  - 若干标准库集合类型上的 `unsafe_ptr()` 方法已更新为使用
    参数化可变性：它们将返回一个 `UnsafePointer`，其可变性
    继承自调用点接收方的 `ref self` 可变性。例如，`ptr1` 将是
    不可变的，而 `ptr2` 将是可变的：

    ```mojo
    fn take_lists(read list1: List[Int], mut list2: List[Int]):
        # Immutable pointer, since receiver is immutable `read` reference
        var ptr1 = list1.unsafe_ptr()

        # Mutable pointer, since receiver is mutable `mut` reference
        var ptr2 = list2.unsafe_ptr()
    ```

- 新增和更新的 trait：

  - `ExplicitlyCopyable`
    trait 已更改为要求一个 `fn copy(self) -> Self` 方法。此前，
    `ExplicitlyCopyable` 要求签名
    为 `fn __init__(out self, *, other: Self)` 的初始化方法。

    这改善了当程序员在代码中查找可能执行复制的地方时的
    "可 grep 性"和一目了然的可读性。

  - `IntLike` trait 已被移除，其功能合并到了
    [`Indexer`](/docs/std/builtin/int/Indexer/) trait 中。这使得
    `SIMD` 标量整数类型和 `UInt` 可用于索引所有
    集合类型，并优化掉了 `UInt` 索引的归一化检查。

  - 已添加 `ImplicitlyIntable` trait，允许类型通过
    实现 `__as_int__()` 方法被隐式转换为 `Int`：

    ```mojo
    @value
    struct Foo(ImplicitlyIntable):
        var i: Int

        fn __as_int__(self) -> Int:
            return self.i
    ```

- 你现在可以使用构造函数来 cast `SIMD` 类型：

  ```mojo
  var val = Int8(42)
  var cast = Int32(val)
  ```

  当将标量类型传递给更大的向量大小时，它也适用：

  ```mojo
  var vector = SIMD[DType.int64, 4](cast) # [42, 42, 42, 42]
  ```

  对于标量以外的值，`SIMD` 向量的大小需要相等：

  ```mojo
  var float_vector = SIMD[DType.float64, 4](vector)
  ```

  [`SIMD.cast()`](/docs/std/builtin/simd/SIMD/#cast) 仍然存在，
  用于推断新向量的大小：

  ```mojo
  var inferred_size = float_vector.cast[DType.uint64]() # [42, 42, 42, 42]
  ```

- 添加了 [`SIMD.from_bytes()`](/docs/std/builtin/simd/SIMD/#from_bytes) 和
  [`SIMD.as_bytes()`](/docs/std/builtin/simd/SIMD/#as_bytes)，用于将
  字节列表转换为标量列表，反之亦然，接受字节序作为参数。类似于
  Python 的 `int.from_bytes()` 和 `int.to_bytes()` 函数。

- 你现在可以将 [`max()`](/docs/std/math/math/max/) 和
  [`min()`](/docs/std/math/math/min/) 与可变数量的参数一起使用。

- `bit_ceil()` 已被重命名为
  [`next_power_of_two()`](/docs/std/bit/bit/next_power_of_two/)，
  `bit_floor()` 被重命名为
  [`prev_power_of_two()`](/docs/std/bit/bit/prev_power_of_two/)。这是为了
  改善其使用时的可读性和清晰度。

- 为 [`b64decode()`](/docs/std/base64/base64/b64decode/) 添加了一个新的
  布尔 `validate` 参数。

- 之前接受 `List` 的 [`b64encode()`](/docs/std/base64/base64/b64encode/) 重载
  已改为接受 [`Span`](/docs/std/memory/span/Span/)。

- 已从某些标准库初始化方法中移除了 `@implicit` 装饰器，
  这些方法执行分配。这减少了 Mojo 代码可能在用户未意识到的情况下
  隐式分配的位置。

  从以下方法中移除了 `@implicit`：

  - `String.__init__(out self, StringSlice)`
  - `List.__init__(out self, owned *values: T)`
  - `List.__init__(out self, span: Span[T])`

- 在 [`sys.ffi`](/docs/std/ffi/) 中添加了更多别名，以满足
  FFI 绑定的常见需求。

## 工具链变更 {#25-1-tooling-changes}

- `mblack`（又称 [`mojo format`](/docs/cli/format/)）不再格式化非 Mojo
  文件。这防止了对 Python 文件的意外格式化。

- 完整的结构体签名信息现在通过文档生成器公开，
  并通过 Mojo 语言服务器在符号大纲和悬停 markdown 中公开。

- [`env_get_dtype()`](/docs/std/sys/param_env/env_get_dtype/) 函数已
  添加到 [`sys.param_env`](/docs/std/sys/param_env/) 模块。这使你能够
  从参数环境中获取 `DType` 的值。

## 已移除

- `StringRef` 已被移除。请改为使用
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)。

  - 更改了 [`sys.argv()`](/docs/std/sys/arg/argv/) 以返回
    `StringSlice` 列表。

  - 添加了从 `StringSlice` 构造的显式
    [`Path()`](/docs/std/pathlib/path/Path/#__init__) 构造函数。

- `Tuple.get[i, T]()` 方法已被移除。请按需使用 `tup[i]` 或
  `rebind[T](tup[i])` 代替。

- `StringableCollectionElement` 已被弃用。请改为使用
  `WritableCollectionElement`，它仍允许你构造 `String`，但可以避免
  中间分配。

- `IntLike` trait 已被移除，其功能合并到了
  [`Indexer`](/docs/std/builtin/int/Indexer/) trait 中。

- 用于直接初始化 register passable 类型的
  `Type{field1: 42, field2: 17}` 语法已被移除。这是旧语法 — 要升级
  你的代码，请将 [`@value`](/docs/reference/decorators/value/) 装饰器添加到
  你的 struct 以获得字段初始化方法，并改为使用
  `Type(field1=42, field2 = 17)`。
