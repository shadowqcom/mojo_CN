## Highlights

以下是本版本一些主要变更的简明摘要,更多详情见后续章节:

- Mojo 现在支持 Python 3.12 互操作性。

- 自动导入到用户 Mojo 程序中的实体(类型、别名、函数)集合已大幅减少。这可能会破坏现有用户代码,因为用户需要为以前自动包含的情况显式导入他们正在使用的内容。

- [`print()`](/docs/std/io/io/print/) 现在要求其参数遵循 [`Formattable`](/docs/std/format/Writable/) trait。这默认启用了高效的基于流的写入,避免了不必要的中间 String 堆分配。

- 新的内置 [`input()`](/docs/std/io/io/input/) 函数会打印可选提示并从标准输入读取一行,与 Python 方式相同。

- Mojo 现在允许在 `fn` 中以与 `def` 中相同的方式隐式定义变量。`var` 关键字仍允许使用,但现在可选。

- Mojo 现在会诊断由别名引用引起的"参数排他性"违规。Mojo 要求引用(包括由于 `borrowed`/`inout` 参数引起的隐式引用)在可变时被唯一引用(非别名)。这在 24.5 版本中是警告,但将在后续版本中升级为错误。

- Mojo 现在支持"条件遵循",即 struct 上的某些方法具有 struct 本身所没有的额外 trait要求。

- `DTypePointer`、`LegacyPointer` 和 `Pointer` 已被移除。请改用 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)。以前接受 `DTypePointer` 的函数现在接受等价的 `UnsafePointer`。有关使用指针的更多信息,请参阅 Mojo 手册中的[不安全指针](/docs/manual/pointers/unsafe-pointers)。

- 标准库有许多新 API,包括字符串、集合以及与文件系统和环境交互的新特性。变更列在标准库章节中。

- VS Code 扩展现在支持为 VS Code 提供的内置 MAX SDK,该 SDK 由扩展自动下载,用于所有 Mojo 功能,包括 Mojo Language Server、Mojo 调试器、Mojo 格式化器等。

- [`mojo test`](/docs/tools/testing/) 现在使用 Mojo 编译器运行单元测试。这将解决有时出现的编译问题,也将改善整体测试执行时间。

## Language changes

- Mojo 现在允许在 `fn` 中以与 `def` 中相同的方式隐式定义变量。`var` 关键字仍允许使用,且仍表示声明一个带有作用域的新变量(在 `def` 和 `fn` 中均是)。放宽此限制使 `fn` 和 `def` 更相似,但它们在其他重要方面仍有差异。

- Mojo 现在会诊断由别名引用引起的"参数排他性"违规。Mojo 要求引用(包括由于 `borrowed`/`inout` 参数引起的隐式引用)在可变时被唯一引用(非别名)。这对代码安全很重要,因为它允许编译器(和代码阅读者)理解值在何处、何时被修改。它对性能优化也很有用,因为它允许编译器知道通过不可变引用的访问不会在背后改变。以下是一个无效示例:

  ```mojo
  fn take_two_strings(a: String, inout b: String):
     # Mojo knows 'a' and 'b' cannot be the same string.
     b += a

  fn invalid_access():
    var my_string = String()

    # warning: passing `my_string` inout is invalid since it is also passed
    # borrowed.
    take_two_strings(my_string, my_string)
  ```

  这类似于 [Swift 排他性检查](https://swift.org/blog/swift-5-exclusivity/),以及 [Rust 语言](https://doc.rust-lang.org/beta/book/ch04-02-references-and-borrowing.html)有时被称为"别名与可变性互斥"。话虽如此,Mojo 的实现细节略有不同,因为 lifetime 嵌入在类型中。

  这在 24.5 版本中是警告,但将在后续版本中升级为错误。

  :::note
  参数排他性不适用于可寄存器传递类型。它们按拷贝传递,因此不形成别名。
  :::

- Mojo 现在支持"条件遵循",即 struct 上的某些方法具有 struct 本身所没有的额外 trait要求。这通过显式声明的 `self` 类型来表达:

  ```mojo
  struct GenericThing[Type: AnyType]:  # Works with anything
    # Sugar for 'fn normal_method[Type: AnyType](self: GenericThing[Type]):'
    fn normal_method(self): ...

    # Just redeclare the requirements with more specific types:
    fn needs_move[Type: Movable](self: GenericThing[Type], owned val: Type):
      var tmp = val^  # Ok to move 'val' since it is Movable
      ...
  fn usage_example():
    var a = GenericThing[Int]()
    a.normal_method() # Ok, Int conforms to AnyType
    a.needs_move(42)  # Ok, Int is movable

    var b = GenericThing[NonMovable]()
    b.normal_method() # Ok, NonMovable conforms to AnyType

      # error: argument type 'NonMovable' does not conform to trait 'Movable'
    b.needs_move(NonMovable())
  ```

  条件遵循也适用于 dunder 方法和其他内容。

- 作为"条件遵循"的一种具体形式,struct 中的初始化器可以指示要在其 `self` 参数类型中使用的特定参数绑定。例如:

  ```mojo
  @value
  struct MyStruct[size: Int]:
      fn __init__(inout self: MyStruct[0]): pass
      fn __init__(inout self: MyStruct[1], a: Int): pass
      fn __init__(inout self: MyStruct[2], a: Int, b: Int): pass

  def test(x: Int):
      a = MyStruct()      # Infers size=0 from 'self' type.
      b = MyStruct(x)     # Infers size=1 from 'self' type.
      c = MyStruct(x, x)  # Infers size=2 from 'self' type.
  ```

- Mojo 现在支持命名结果绑定。命名结果绑定可用于直接将函数结果放置到函数的输出槽中。与"保证"命名返回值优化(NRVO)相比,该特性在放置函数结果方面提供了更多灵活性和保证。如果一个 `@register_passable` 结果绑定到一个名称,结果值将作为可变引用被访问。

  ```mojo
  fn efficiently_return_string(b: Bool) -> String as output:
      if b:
          output = "emplaced!"
          mutate(output)
          return
      return "regular return"
  ```

  如果我们为 `output` 使用临时变量,就需要移动到结果槽中,如果结果类型不可移动,这将无法工作。

  在具有命名结果的函数中,`return` 可在不带操作数的情况下使用以表示从函数退出,或正常使用以指定函数的返回值。如果结果在函数的所有正常退出路径上未被初始化,编译器将报错。

- `__setitem__()` 现在可以与可变参数列表一起工作,例如:

  ```mojo
  struct YourType:
      fn __setitem__(inout self, *indices: Int, val: Int): ...
  ```

  Mojo 编译器现在总是使用 `__setitem__()` 的最后一个关键字参数传递被设置的"新值",例如将 `yourType[1, 2] = 3` 转换为 `yourType.__setitem__(1, 2, val=3)`。这修复了 [Issue
  #248](https://github.com/modular/modular/issues/248)。

- 在可能抛出错误的代码区域中使用的 Mojo 上下文管理器不再需要定义形式为 `fn __exit__(self, e: Error) -> Bool` 的"条件"退出函数。该函数允许上下文管理器有条件地拦截并处理错误,允许函数继续执行。这对某些应用很有用,但在许多情况下,条件退出会委托给无条件退出函数 `fn __exit__(self)`。

  具体而言,这启用定义无条件传播内部错误的 `with` 区域,允许如下代码:

  ```mojo
  def might_raise() -> Int:
      ...

  def foo() -> Int:
      with ContextMgr():
          return might_raise()
      # no longer complains about missing return

  def bar():
      var x: Int
      with ContextMgr():
          x = might_raise()
      print(x) # no longer complains about 'x' being uninitialized
  ```

- `async` 函数现在支持仅内存结果(如 `String`、`List` 等)和 `raises`。相应地,[`Coroutine`](/docs/std/builtin/coroutine/Coroutine/) 和 [`RaisingCoroutine`](/docs/std/builtin/coroutine/RaisingCoroutine/) 都已更改为接受 `AnyType` 而非 `__TypeOfAllTypes`。这意味着 `async` 函数的结果类型不需要是 `Movable`。

  ```mojo
  async fn raise_or_string(c: Bool) raises -> String:
      if c:
          raise "whoops!"
      return "hello world!"
  ```

  请注意,`async` 函数尚不支持间接调用、`ref` 结果和构造器。

- [`Reference`](/docs/std/memory/pointer/Pointer/) 类型(以及许多迭代器)现在使用[仅推断参数](/docs/manual/parameters/#infer-only-parameters)来表示其 lifetime 的可变性,简化了接口。

- 环境变量 `MOJO_PYTHON` 可指向一个可执行文件,以将 Mojo 固定到特定版本:

  ```sh
  export MOJO_PYTHON="/usr/bin/python3.11"
  ```

  或指向一个虚拟环境,以便始终访问这些 Python 模块:

  ```sh
  export MOJO_PYTHON="~/venv/bin/python"
  ```

  对于具有动态 `libpython` 但没有 Python 可执行文件的环境,`MOJO_PYTHON_LIBRARY` 仍然存在。

- Mojo 的指针别名语义已更改。最初,Mojo 采用了一组类似 C 的指针别名和派生语义。然而,C 语义带来了许多在 Mojo 中不需要的历史和包袱,并使编译器优化复杂化。整体而言,该语言在指针别名与 lifetime 和独占可变引用等方面提供了一组更强的不变量。

  现在禁止将派生自 Mojo 分配指针的非指针类型值(如整数地址)转换为指针类型值。"派生"是指非指针类型值的位与原始指针值有重叠。相应地,接受 `address` 关键字参数的 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 构造器已被移除。

  在绝对必要的情况下,仍可进行此转换,例如与 Python 等其他语言互操作时。在这种情况下,编译器做两个假设:从非指针类型值派生的任何指针不会别名任何 Mojo 派生的指针,并且任何外部函数调用具有任意的内存效应。

- 对协程的 `await` 现在会消耗它。这加强了协程只能被 await 一次的不变量。

## Standard library changes

- [`builtin`](/docs/std/builtin/) 包:

  - 自动导入到用户 Mojo 程序中的实体(类型、别名、函数)集合已大幅减少。以前,由于 `builtin` 模块的处理方式,以下模块中的所有实体会被自动包含:

    `memory`、`sys`、`os`、`utils`、`python`、`bit`、`random`、`math`、`builtin`、`collections`

    现在,只有 `prelude/__init__.mojo` 中显式枚举的实体会被自动导入到用户 Mojo 程序中。这将破坏大量用户代码,因为用户需要为以前通常包含的情况显式导入他们正在使用的内容(如
    [`Optional`](/docs/std/collections/optional/Optional/)、
    [`Variant`](/docs/std/utils/variant/Variant/),以及诸如
    [`abort()`](/docs/std/os/os/abort/)、
    [`alignof()`](/docs/std/sys/info/align_of/)、
    [`bitcast()`](/docs/std/memory/unsafe/bitcast/)、
    [`bitwidthof()`](/docs/std/sys/info/bit_width_of/)、
    [`external_call()`](/docs/std/ffi/external_call/)、
    [`simdwidthof()`](/docs/std/sys/info/simd_width_of/) 和
    [`sizeof()`](/docs/std/sys/info/size_of/) 等函数)。

  - `builtin` 模块中的一些类型已移至不同模块以增加清晰度,这之所以成为可能,是因为我们现在拥有一个可以从 `builtin` 以外的模块重新导出符号的 `prelude` 模块。

    特别是,`builtin.string` 模块已移至 [`collections.string`](/docs/std/collections/string/)。

- 输入和输出:

  - 新增内置 [`input()`](/docs/std/io/io/input/) 函数,行为与 Python 相同。
    ([PR #3392](https://github.com/modular/modular/pull/3392))

    ```mojo
    name = input("Enter your name: ")
    print("Hello, " + name + "!")
    ```

    如果用户输入 "Mojo",它返回 "Hello, Mojo!"

    在使用 JIT 编译运行 `input()` 函数时存在一个已知问题(参见 issue
    [#3479](https://github.com/modular/modular/issues/3479))。

  - [`print()`](/docs/std/io/io/print/) 现在要求其参数遵循 [`Formattable`](/docs/std/format/Writable/) trait。这默认启用了高效的基于流的写入,避免了不必要的中间 String 堆分配。

    以前,`print()` 要求类型遵循 `Stringable`。这意味着要执行如 `print(a, b, c)` 的调用,会进行至少三次单独的 String 堆分配,分别保存 `a`、`b` 和 `c` 的格式化值。如果 `a.__str__()` 实现为将 `a` 的字段连接在一起,总分配数可能会高得多,如下例所示:

    ```mojo
    struct Point(Stringable):
        var x: Float64
        var y: Float64

        fn __str__(self) -> String:
            # Performs 3 allocations: 1 each for str(..) of each of the fields,
            # and then the final returned `String` allocation.
            return "(" + str(self.x) + ", " + str(self.y) + ")"
    ```

    上述类型可以通过以下变更过渡到额外实现 `Formattable`:

    ```mojo
    struct Point(Stringable, Formattable):
        var x: Float64
        var y: Float64

        fn __str__(self) -> String:
            return String.format_sequence(self)

        fn format_to(self, inout writer: Formatter):
            writer.write("(", self.x, ", ", self.y, ")")
    ```

    在上例中,[`String.format_sequence()`](/docs/std/collections/string/string/String/#format_sequence) 用于从实现 `Formattable` 的类型构造 `String`。这种以类型的 `Formattable` 实现来实现其 `Stringable` 实现的模式,最小化了样板代码和重复代码,同时保持与常用的 `str()` 函数要求的向后兼容性。

    <!-- TODO(MOCO-891): Remove this warning when error is improved. -->

    :::note
    当将不实现 `Formattable` 的类型传递给 `print()` 时显示的错误当前不能完全描述根本原因:

    ```shell
    error: invalid call to 'print': callee with non-empty variadic pack argument expects 0 positional operands, but 1 was specified
       print(point)
       ~~~~~^~~~~~~
    ```

    如果你看到上述错误,请确保所有参数类型都实现了 `Formattable`。
    :::

  - [`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert) 现在也要求其 `message` 参数遵循 `Formattable`。

  - 在 `tempfile` 模块中新增 [`TemporaryDirectory`](/docs/std/tempfile/tempfile/TemporaryDirectory)。
    ([PR 2743](https://github.com/modular/modular/pull/2743))

  - 在 `tempfile` 模块中新增 [`NamedTemporaryFile`](/docs/std/tempfile/tempfile/NamedTemporaryFile)。
    ([PR 2762](https://github.com/modular/modular/pull/2762))

- [`String`](/docs/std/collections/string/string) 及相关类型:

  - `builtin.string` 模块已移至 [`collections.string`](/docs/std/collections/string/)。

  - 新增 [`String.format()`](/docs/std/collections/string/string/String#format) 方法。([PR #2771](https://github.com/modular/modular/pull/2771))

    支持 `*args` 的自动和手动索引。

    示例:

    ```mojo
    print(
      String("{1} Welcome to {0} {1}").format("mojo", "🔥")
    )
    # 🔥 Wecome to mojo 🔥
    ```

    ```mojo
    print(String("{} {} {}").format(True, 1.125, 2))
    #True 1.125 2
    ```

  - [`String.format()`](/docs/std/collections/string/string/String#format) 现在支持转换标志 `!s` 和 `!r`,允许在格式字符串中进行 `str()` 和 `repr()` 转换。([PR
    #3279](https://github.com/modular/modular/pull/3279))

    示例:

    ```mojo
    String("{} {!r}").format("Mojo", "Mojo")
    # "Mojo 'Mojo'"

    String("{0!s} {0!r}").format("Mojo")
    # "Mojo 'Mojo'"
    ```

  - `String` 类现在拥有 [`rjust()`](/docs/std/collections/string/string/String#rjust)、[`ljust()`](/docs/std/collections/string/string/String#ljust) 和 [`center()`](/docs/std/collections/string/string/String#center) 方法,用于根据宽度和填充字符返回对齐后的字符串。([PR
    #3278](https://github.com/modular/modular/pull/3278))

  - [`atol()`](/docs/std/collections/string/string/atol) 函数现在正确支持前导下划线(例如 `atol("0x_ff", 0)`),当指定或推断(基数 0)了适当的基数时。符合 Python [整数字面量](<https://docs.python.org/3/reference/lexical_analysis.html#integers>)中的非 10 进制整数字面量。([PR #3180](https://github.com/modular/modular/pull/3180))

  - 为 `String` 和 `StringLiteral` 新增 [`unsafe_cstr_ptr()`](/docs/std/collections/string/string/String#unsafe_cstr_ptr) 方法,返回一个 `UnsafePointer[c_char]`,便于与 C API 互操作。

  - 为 [`String`](/docs/std/collections/string/string/String#byte_length)、[`StringSlice`](/docs/std/collections/string/string_slice/StringSlice#byte_length) 和 [`StringLiteral`](/docs/std/builtin/string_literal/StringLiteral#byte_length) 添加了 `byte_length()` 方法,并弃用了它们的私有 `_byte_length()` 方法。向 [`String.__len__()`](/docs/std/collections/string/string/String#__len__) 方法添加了警告,即未来它将返回以 Unicode 码点为单位的长度,而 [`StringSlice.__len__()`](/docs/std/collections/string/string_slice/StringSlice#__len__) 现在确实返回 Unicode 码点长度。
    ([PR #2960](https://github.com/modular/modular/pull/2960))

  - 新增 [`StaticString`](/docs/std/collections/string/string_slice/#aliases) 类型别名。它可在需要运行时字符串参数时代替 [`StringLiteral`](/docs/std/builtin/string_literal/StringLiteral) 使用。

  - 新增接受 `StringLiteral` 的 [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice#__init__) 初始化器。

  - 从 `DTypePointer.int8` 构造 `StringRef` 的构造器已更改为接受 `UnsafePointer[c_char]`,反映了它们用于与 C API 兼容性的用途。

  - 继续向 `UnsafePointer` 和无符号字节类型过渡字符串:

    - [`String.unsafe_ptr()`](/docs/std/collections/string/string/String#unsafe_ptr) 现在返回 `UnsafePointer[UInt8]`(原为 `UnsafePointer[Int8]`)

    - [`StringLiteral.unsafe_ptr()`](/docs/std/builtin/string_literal/StringLiteral#unsafe_ptr) 现在返回 `UnsafePointer[UInt8]`(原为 `UnsafePointer[Int8]`)

- [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer) 及其他引用类型变更:

  - `DTypePointer`、`LegacyPointer` 和 `Pointer` 已被移除。请改用 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer)。有关使用指针的更多信息,请参阅 Mojo 手册中的[不安全指针](/docs/manual/pointers/unsafe-pointers)。

    以前接受 `DTypePointer` 的函数现在接受等价的 `UnsafePointer`。从 `DTypePointer` 转换到 `UnsafePointer` 的快速规则是:

    ```mojo
    DTypePointer[type] -> UnsafePointer[Scalar[type]]
    ```

    可能有你拥有如下形式代码的地方:

    ```mojo
    fn f(ptr: DTypePointer):
    ```

    这等价于 `DTypePointer[*_]`。在这种情况下,你必须向函数添加一个仅推断的 `type` 参数:

    ```mojo
    fn f[type: DType, //](ptr: UnsafePointer[Scalar[type]]):
    ```

    因为我们不能在 struct 内部有未绑定的参数。

    也可能有你使用 `DTypePointer[Scalar[DType.invalid/index]]` 的地方,自然地将其更改为 `UnsafePointer[NoneType/Int]`。但由于这些不是存储 `Scalar` 的 `UnsafePointer`,你可能必须 `rebind/bitcast` 到适当的类型。

  - `DTypePointer` 的 [`load()`](/docs/std/memory/unsafe_pointer/UnsafePointer#load) 和 [`store()`](/docs/std/memory/unsafe_pointer/UnsafePointer#store) 方法已移至 `UnsafePointer`。

  - `UnsafePointer` 现在在底层类型为 `Scalar[DType]` 时支持 [`strided_load()`](/docs/std/memory/unsafe_pointer/UnsafePointer#strided_load)、[`strided_store()`](/docs/std/memory/unsafe_pointer/UnsafePointer#strided_store)、[`gather()`](/docs/std/memory/unsafe_pointer/UnsafePointer#gather) 和 [`scatter()`](/docs/std/memory/unsafe_pointer/UnsafePointer#scatter)。

  - 用于处理 `UnsafePointer` 的全局函数已通过使用条件遵循过渡为方法:

    - `destroy_pointee(p)` =>
      [`p.destroy_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer#destroy_pointee)
    - `move_from_pointee(p)` =>
      [`p.take_pointee()`](/docs/std/memory/unsafe_pointer/UnsafePointer#take_pointee)
    - `initialize_pointee_move(p, value)` =>
      [`p.init_pointee_move(value)`](/docs/std/memory/unsafe_pointer/UnsafePointer#init_pointee_move)
    - `initialize_pointee_copy(p, value)` =>
      [`p.init_pointee_copy(value)`](/docs/std/memory/unsafe_pointer/UnsafePointer#init_pointee_copy)
    - `move_pointee(src=p1, dst=p2)` =>
      [`p.move_pointee_into(p2)`](/docs/std/memory/unsafe_pointer/UnsafePointer#move_pointee_into)

  - `UnsafePointer.offset()` 方法已弃用,将在未来版本中移除。请改用[指针算术](/docs/manual/pointers#storing-multiple-values)。

    ```mojo
    new_ptr = ptr.offset(1)
    ```

    变为:

    ```mojo
    new_ptr = ptr + 1
    ```

  - `UnsafePointer` 现在拥有 [`alignment`](/docs/std/memory/unsafe_pointer/UnsafePointer#parameters) 参数,用于指定指针的静态对齐。因此,[`UnsafePointer.alloc()`](/docs/std/memory/unsafe_pointer/UnsafePointer#alloc) 不再接受对齐参数,对齐应在类型中指定。

    ```mojo
    UnsafePointer[type].alloc[alignment](x) # now becomes
    UnsafePointer[type, alignment].alloc(x)
    ```

  - `UnsafePointer` 拥有新的 [`exclusive: Bool =
    False`](/docs/std/memory/unsafe_pointer/UnsafePointer#parameters) 参数。将此参数设置为 true 会告诉编译器用户知道此指针和从中派生的所有指针对底层内存分配具有独占访问权。编译器不保证会对此信息做任何事情。

  - 不再可能(隐式或显式)从 `Reference` 转换到 `UnsafePointer`。请使用 [`UnsafePointer.address_of(someRef[])`](/docs/std/memory/unsafe_pointer/UnsafePointer#address_of) 而不是 `UnsafePointer(someRef)`,这使代码显式表达 `UnsafePointer` 获取引用所指向内容的地址。

- Python 互操作性变更:

  - Mojo 现在支持 Python 3.12 互操作性。

  - 现在可以从 Python 对象的列表或 tuple 创建嵌套的 [`PythonObject`](/docs/std/python/python_object/PythonObject):

    ```mojo
    var np = Python.import_module("numpy")
    var a = np.array([1, 2, 3])
    var b = np.array([4, 5, 6])
    var arrays = PythonObject([a, b])
    assert_equal(len(arrays), 2)
    ```

    也允许更便利的调用语法:

    ```mojo
    var stacked = np.hstack((a, b))
    assert_equal(str(stacked), "[1 2 3 4 5 6]")
    ```

    ([PR #3264](https://github.com/modular/modular/pull/3264))

  - 不再需要使用 [`Python.add_to_path(".")`](/docs/std/python/python/Python#add_to_path) 访问本地 Python 模块。它现在的行为与 Python 相同。你可以访问与目标文件在同一文件夹中的模块:

    - `mojo run /tmp/main.mojo` 可以访问 `/tmp/mymodule.py`

    - `mojo build main.mojo -o ~/myexe && ~/myexe` 可以访问 `~/mymodule.py`

- 集合:

  - [`List`](/docs/std/collections/list/List) 值现在在元素类型可比较相等时,可以用 `==` 和 `!=` 进行相等比较。([PR #3195](https://github.com/modular/modular/pull/3195))

  - [`Optional`](/docs/std/collections/optional/Optional) 值现在在元素类型可比较相等时,可以用 `==` 和 `!=` 进行相等比较。

  - 新增 [`Counter`](/docs/std/collections/counter/Counter) 类字典类型,匹配 Python 版本的大部分特性。
    ([PR #2910](https://github.com/modular/modular/pull/2910))

  - [`Dict`](/docs/std/collections/dict/Dict) 现在实现了 [`setdefault()`](/docs/std/collections/dict/Dict#setdefault),按键从字典获取值,如果不存在则设置为默认值。
    ([PR #2803](https://github.com/modular/modular/pull/2803))

  - `Dict` 现在支持 [`popitem()`](/docs/std/collections/dict/Dict#popitem),移除并返回 `Dict` 中的最后一项。
    ([PR #2701](https://github.com/modular/modular/pull/2701))

  - 新增 [`Dict.__init__()`](/docs/std/collections/dict/Dict#__init__) 重载,以指定初始容量。
    ([PR #3171](https://github.com/modular/modular/pull/3171))

    容量必须是 2 的幂且大于等于 8。

    它通过跳过增量增长步骤来加快初始化。

    示例:

    ```mojo
    var dictionary = Dict[Int,Int](power_of_two_initial_capacity = 1024)
    # Insert (2/3 of 1024) entries
    ```

  - `ListLiteral` 现在支持 `__contains__()`。
    ([PR #3251](https://github.com/modular/modular/pull/3251))

- 文件系统和环境实用工具:

  - 新增 [`Path.home()`](/docs/std/pathlib/path/Path#home),返回用户主目录的路径。

  - 新增 [`os.path.expanduser()`](/docs/std/os/path/path/expanduser) 和 [`pathlib.Path.exapanduser()`](/docs/std/pathlib/path/Path#expanduser),允许将 `String` 或 `Path` 中的前缀 `~` 展开为用户主路径:

    ```mojo
    import os
    print(os.path.expanduser("~/.modular"))
    # /Users/username/.modular
    print(os.path.expanduser("~root/folder"))
    # /var/root/folder (on macos)
    # /root/folder     (on linux)
    ```

  - 新增 [`os.path.split()`](/docs/std/os/path/path/split),将路径拆分为 `head, tail`:

    ```mojo
    import os
    head, tail = os.path.split("/this/is/head/tail")
    print("head:", head)
    print("tail:", tail)
    # head: /this/is/head
    # tail: tail
    ```

  - 新增 [`os.makedirs()`](/docs/std/os/os/makedirs) 和 [`os.removedirs()`](/docs/std/os/os/removedirs),用于创建和删除嵌套目录:

    ```mojo
    import os
    path = os.path.join("dir1", "dir2", "dir3")
    os.path.makedirs(path, exist_ok=True)
    os.removedirs(path)
    ```

  - 新增 [`pwd`](/docs/std/pwd/pwd/) 模块,用于在 POSIX 系统上访问 `/etc/passwd` 中的用户信息。这遵循与 Python 相同的逻辑:

    ```mojo
    import pwd
    import os
    current_user = pwd.getpwuid(os.getuid())
    print(current_user)

    # pwd.struct_passwd(pw_name='jack', pw_passwd='********', pw_uid=501,
    # pw_gid=20, pw_gecos='Jack Clayton', pw_dir='/Users/jack',
    # pw_shell='/bin/zsh')

    print(current_user.pw_uid)

    # 501

    root = pwd.getpwnam("root")
    print(root)

    # pwd.struct_passwd(pw_name='root', pw_passwd='*', pw_uid=0, pw_gid=0,
    # pw_gecos='System Administrator', pw_dir='/var/root', pw_shell='/bin/zsh')
    ```

- 其他新 trait 和相关特性:

  - 新增 `ExplicitlyCopyable` trait,用于标记可被显式拷贝但可能不可隐式拷贝的类型。

    这支持将标准库集合类型从隐式可拷贝性过渡的工作,因为隐式可拷贝性可能导致意外的高开销拷贝。

  - 新增 [`Identifiable`](/docs/std/builtin/identifiable/Identifiable) trait,用于描述实现了 `__is__()` 和 `__isnot__()` trait 方法的类型。
    ([PR #2807](https://github.com/modular/modular/pull/2807))

  - 遵循 [`Boolable`](/docs/std/builtin/bool/Boolable)(即实现 `__bool__()`)的类型不再隐式转换为 `Bool`。引入了新的 `ImplicitlyBoolable` trait,用于需要此行为的类型。

- 杂项:

  - [`NoneType`](/docs/std/builtin/none/NoneType) 现在是一个普通的标准库类型,而不是原始 MLIR 类型的别名。

    写成 `fn() -> NoneType` 的函数签名应过渡到写成 `fn() -> None`。

  - Mojo 现在拥有 [`UInt`](/docs/std/builtin/simd/#uint) 类型,用于建模具有平台相关宽度的无符号(标量)整数。`UInt` 实现了对整数有意义的大多数算术运算,但 `__neg__()` 是显著的例外。诸如 `min()`/`max()` 等内置函数,以及诸如 `ceildiv()`、`align_down()` 和 `align_up()` 等 `math` 函数也针对 `UInt` 实现。

  - 既然我们有了 `UInt` 类型,使用它来表示哈希的返回类型。一般而言,哈希应是无符号整数,在某些情况下也可带来性能提升。

  - 在 `sys.ffi` 中新增 [`c_char`](/docs/std/ffi/#aliases) 类型别名。

  - [`sort()`](/docs/std/builtin/sort/sort) 现在支持 `stable` 参数。可通过以下方式调用

    ```mojo
    sort[cmp_fn, stable=True](list)
    ```

    该算法需要 $$O(N)$$ 辅助内存。如果额外内存分配失败,程序会崩溃。

  - `sort()` 不再接受 `LegacyPointer`,因为该类型已被移除。

  - 新增 [`oct()`](/docs/std/builtin/format_int/oct) 内置函数,用于将整数格式化为八进制。
    ([PR #2914](https://github.com/modular/modular/pull/2914))

  - 向 `testing` 模块新增 [`assert_is()`](/docs/std/testing/testing/assert_is) 和 [`assert_is_not()`](/docs/std/testing/testing/assert_is_not) 测试函数。

  - [`math`](/docs/std/math/constants/) 包现在包括 `pi`、`e` 和 `tau` 常量(关闭 Issue
    [#2135](https://github.com/modular/modular/issues/2135))。

  - `numerics` 中的 [`ulp`](/docs/std/math/math/ulp) 函数已移至 `math` 模块。

  - `bit` 模块现在为 `Int` 类型支持 [`bit_reverse()`](/docs/std/bit/bit/bit_reverse)、[`byte_swap()`](/docs/std/bit/bit/byte_swap) 和 [`pop_count()`](/docs/std/bit/bit/pop_count)。
    ([PR #3150](https://github.com/modular/modular/pull/3150))

  - 一些 `bit` 函数为清晰起见已重命名:

    - `countl_zero()` ->
      [`count_leading_zeros()`](/docs/std/bit/bit/count_leading_zeros)

    - `countr_zero()` ->
      [`count_trailing_zeros()`](/docs/std/bit/bit/count_trailing_zeros)

  - [`Slice`](/docs/std/builtin/builtin_slice/Slice) 现在对 `start` 和 `end` 使用 `OptionalReg[Int]`,并实现了接受可选值的构造器。`Slice._has_end()` 也已被移除,因为没有结束的 Slice 现在由空的 `Slice.end` 选项表示。
    ([PR #2495](https://github.com/modular/modular/pull/2495))

    ```mojo
      var s = Slice(1, None, 2)
      print(s.start.value()) # must retrieve the value from the optional
    ```

  - [`algorithm.elementwise()`](/docs/std/algorithm/functional/elementwise) 的 `rank` 参数不再需要,只进行推断。

  - `time.now()` 函数已弃用。请改用 [`time.perf_counter()`](/docs/std/time/time/perf_counter) 或 [`time.perf_counter_ns`](/docs/std/time/time/perf_counter_ns)。

  - 从 `Bool` 构造 [`SIMD`](/docs/std/builtin/simd/SIMD) 已限制为 `DType.bool` 数据类型。

## Tooling changes

- [`mojo test`](/docs/tools/testing) 新特性和变更:

  - `mojo test` 现在使用 Mojo 编译器运行单元测试。这将解决有时出现的编译问题,也将改善整体测试时间,因为我们只会在执行所有测试之前编译一次单元测试。

    这些变更不适用于 doctest,因为它们的语义不同。

  - `mojo test` 命令现在接受 `--filter` 选项,可缩小收集和执行的测试集。过滤字符串是 POSIX 扩展正则表达式。

  - `mojo test` 命令现在支持使用与 `mojo build` 相同的编译选项。

  - 你现在可以通过传递 `--debug` 标志使用 `mojo test` 调试单元测试。支持大多数调试标志;运行 `mojo test --help` 获取完整列表。

    目前不支持调试 doctest。

- Mojo 调试器新特性和变更:

  - `mojo debug --rpc` 命令已重命名为 [`mojo debug
    --vscode`](/docs/cli/debug#debug-server-options),现在能够管理多个 VS Code 窗口。

  - Mojo 调试器现在支持 `break-on-raise` 命令,指示调试器在任何 `raise` 语句处停止。VS Code 上的调试器中也添加了类似功能。

  - Mojo 调试器现在隐藏由编译器为 Mojo 代码创建的人工函数参数 `__result__` 和 `__error__`。

- VS Code 支持变更:

  - VS Code 扩展现在支持为 VS Code 提供的内置 MAX SDK,该 SDK 由扩展自动下载,用于所有 Mojo 功能,包括 Mojo Language Server、Mojo 调试器、Mojo 格式化器等。

  - 在 VS Code 上的 Mojo Language Server 中添加了代理,可更优雅地处理崩溃。

- Mojo Language Server 不再将 `.` 设置为自动补全的提交字符。

## Removed

- 已从编译器中移除对遗留 `fn __init__(...) -> Self:` 形式的支持,请切换到使用 `fn __init__(inout self, ...):`。

- 内置 `tensor` 模块已被移除。相同功能可在 `max.tensor` 中找到,但通常建议尽可能使用 `buffer` 模块中的 struct。

- 移除了 `String.unsafe_uint8_ptr()`。`String.unsafe_ptr()` 现在返回相同内容。

- 移除了 `StringLiteral.unsafe_uint8_ptr()` 和 `StringLiteral.as_uint8_ptr()`。

- 移除了 `SIMD.splat(value: Scalar[type])`。请改用 `SIMD` 的构造器。

- 移除了 `SIMD.{add,mul,sub}_with_overflow()` 方法。

- 移除了 `SIMD.min()` 和 `SIMD.max()` 方法。相同功能可使用内置 [`min()`](/docs/std/math/math/min/) 和 [`max()`](/docs/std/math/math/max/) 函数。

- 移除了 Mojo Language Server 对未使用的函数参数的警告。

- `Run Mojo File in Dedicated Terminal` 操作已被移除,`Run Mojo File` 操作将始终为每个 mojo 文件打开专用终端,以保证正确的环境。
