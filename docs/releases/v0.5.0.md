## ⭐️ 新增

- [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型现在默认使用
  该类型的架构 SIMD 宽度。这意味着你可以编写
  `SIMD[DType.float32]`，它等价于
  `SIMD[DType.float32, simdwidthof[DType.float32]()]`。

- [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型现在包含一个 `join()`
  函数，允许你将两个 `SIMD` 值拼接起来并
  生成一个新的 `SIMD` 值。

- Mojo 现在支持编译期*关键字参数（keyword parameters）*，这是在已有
  [关键字参数](/docs/manual/parameters/#optional-parameters-and-keyword-parameters)
  支持基础上的新增功能。
  例如：

  ```mojo
  fn foo[a: Int, b: Int = 42]():
      print(a, "+", b)

  foo[a=5]()        # prints '5 + 42'
  foo[a=7, b=13]()  # prints '7 + 13'
  foo[b=20, a=6]()  # prints '6 + 20'
  ```

  关键字参数在 struct 中也受支持：

  ```mojo
  struct KwParamStruct[a: Int, msg: String = "🔥mojo🔥"]:
      fn __init__(inout self):
          print(msg, a)

  fn use_kw_params():
      KwParamStruct[a=42]()               # prints '🔥mojo🔥 42'
      KwParamStruct[5, msg="hello"]()     # prints 'hello 5'
      KwParamStruct[msg="hello", a=42]()  # prints 'hello 42'
  ```

  更多细节，请参阅
  [Mojo 手册](/docs/manual/parameters/#optional-parameters-and-keyword-parameters)。

  目前存在以下值得注意的限制：

  - 尚**不支持**仅关键字参数：

    ```mojo
    fn baz[*args: Int, b: Int](): pass  # fails
    fn baz[a: Int, *, b: Int](): pass  # fails
    ```

    （Python 中类似的仅关键字参数在
    [PEP 3102](https://peps.python.org/pep-3102/) 中描述。）

  - 尚**不支持**可变关键字参数：

    ```mojo
    fn baz[a: Int, **kwargs: Int](): pass  # fails
    ```

- Mojo 现在支持函数的“自动”参数化。这意味着
  如果函数实参类型是参数化的但没有绑定参数，
  它们会自动作为输入参数添加到函数上。这与现有功能配合，
  让你能够以更少的样板代码编写参数化函数。

  ```mojo
  @value
  struct Thing[x: Int, y: Int]:
      pass

  fn foo(v: Thing):
      print(v.x)
      print(v.y)

  fn main():
      let v = Thing[2, 3]()
      foo(v)
  ```

  但是，尚**不支持**部分自动参数化：

  ```mojo
  fn foo(v: Thing[y=7]):  # Partially bound type not allowed yet.
      ...
  ```

- 使用方括号语法调用 `__getitem__` 时支持关键字参数传递：

  ```mojo
  @value
  struct MyStruct:
      fn __getitem__(self, x: Int, y: Int, z: Int) -> Int:
          return x * y + z

  MyStruct()[z=7, x=3, y=5]  # returns 22
  ```

  但是，使用方括号语法向 `__setitem__` 传递关键字参数尚
  **不被支持**：

  ```mojo
  @value
  struct OtherStruct:
      fn __setitem__(self, x: Int, y: Int): pass

  OtherStruct()[x=1] = 4  # fails
  ```

- 函数实参的输入参数现在可以在函数签名内被引用：

  ```mojo
  fn foo(x: SIMD, y: SIMD[x.type, x.size]):
      pass
  ```

- [`benchmark`](/docs/std/benchmark/benchmark/) 模块已被
  简化和改进，你现在可以运行：

  ```mojo
  import benchmark
  from time import sleep

  fn sleeper():
      sleep(.01)

  fn main():
      let report = benchmark.run[sleeper]()
      print(report.mean())
  ```

  它不再需要捕获型 `fn`，因此可以对同一作用域之外的函数进行基准测试。

  你可以用以下方式打印报告：

  ```mojo
  report.print()
  ```

  ```plaintext
  ---------------------
  Benchmark Report (s)
  ---------------------
  Mean: 0.012314264957264957
  Total: 1.440769
  Iters: 117
  Warmup Mean: 0.0119335
  Warmup Total: 0.023866999999999999
  Warmup Iters: 2
  Fastest Mean: 0.012227958333333334
  Slowest Mean: 0.012442699999999999
  ```

  所有函数的单位默认为秒，但可以通过以下方式更改：

  ```mojo
  from benchmark import Unit

  report.print[Unit.ms]()
  ```

- Mojo 现在支持 struct 参数推导（又称类模板参数推导，或 CTAD），
  适用于部分绑定的类型。Struct 参数推导也可以从静态方法进行。例如：

  ```mojo
  @value
  struct Thing[v: Int]: pass

  struct CtadStructWithDefault[a: Int, b: Int, c: Int = 8]:
      fn __init__(inout self, x: Thing[a]):
          print("hello", a, b, c)

      @staticmethod
      fn foo(x: Thing[a]):
          print("🔥", a, b, c)

  fn main():
      _ = CtadStructWithDefault[b=7](Thing[6]())  # prints 'hello 6 7 8'
      CtadStructWithDefault[b=7].foo(Thing[6]())  # prints '🔥 6 7 8'
  ```

- `Tensor` 新增了 `fromfile()` 和 `tofile()` 方法，用于以字节形式
  保存和加载文件。

- 内建的 `print()` 函数现在可在 `Tensor` 类型上使用。

- `TensorShape` 和 `TensorSpec` 现在拥有接受
  [`DynamicVector[Int]`](/docs/std/collections/list/List/) 和
  [`IndexList`](/docs/std/utils/index_/IndexList/) 来初始化形状的
  构造函数。

- [`String`](/docs/std/collections/string/string/String/) 类型现在拥有
  `count()` 和 `find()` 方法，用于统计子串出现次数或
  查找子串在字符串中的偏移索引。

- `String` 类型现在拥有 `replace()` 方法，允许你用另一个字符串
  替换子串。

## 🦋 变更

- [`VariadicList`](/docs/std/builtin/variadics/VariadicList/) 和
  [`VariadicListMem`](/docs/std/builtin/variadics/VariadicListMem/)
  已移至 builtins 下，不再需要导入。

- 可变参数现在会在函数体内部自动投影为 `VariadicList` 或
  `VariadicListMem`。这使得使用可变参数更加灵活。例如：

  ```mojo
    fn print_ints(*nums: Int):
        let len = len(nums)
        for i in range(len):
            print(nums[i])
        print(len)
  ```

- [`InlinedFixedVector`](/docs/std/collections/inline_array/InlineArray/)
  的参数顺序已交换。参数现在是 `[type, size]` 而不是
  `[size, type]`。`InlinedFixedVector` 现在拥有默认 size，这意味着
  可以直接将 `InlinedFixedVector` 用作 `InlinedFixedVector[Float32]`，
  并使用默认 size。

- `Buffer` 和 `NDBuffer` 中的 `write_file()` 方法已重命名为
  `tofile()`，以与 Python 命名保持一致。

- Mojo 现在默认会利用主机上所有 NUMA socket 上的所有可用核心。
  此前的默认行为是仅使用第一个 socket 上的所有核心。

## ❌ 移除

- `math.numerics` 模块现在已私有，因为其类型（`FPUtils` 和
  `FlushDenormals`）不应被外部使用。

## 🛠️ 修复

- [#532](https://github.com/modular/modular/issues/532) - 编译器将
  while True 循环优化掉
- [#760](https://github.com/modular/modular/issues/760) - 编译错误：
  'hlcf.for.yield' op specifies 0 branch inputs but target expected 1 along
  control-flow edge from here
- [#849](https://github.com/modular/modular/issues/849) - `Tensor` 类型
  现在在构造时以零初始化。
- [#912](https://github.com/modular/modular/issues/912) - `__get_address_as_lvalue`
  的无效加载。
- [#916](https://github.com/modular/modular/issues/916) - 为 `inout` 参数
  指定默认值时解析器崩溃。
- [#943](https://github.com/modular/modular/issues/943) - 在嵌套循环中
  使用 continue 时 Mojo 卡住
- [#957](https://github.com/modular/modular/issues/957) - 当在编译期求值
  包含内存类型可变参数的函数调用时解析器崩溃。
- [#990](https://github.com/modular/modular/issues/990) - 修复了负分子
  地板除法的舍入问题。
- [#1018](https://github.com/modular/modular/issues/1018) - 在某些情况下
  sort 函数返回无效结果。本版本修复了其中一些
  边界情况。
- [#1010](https://github.com/modular/modular/issues/1010) - 在 alias 声明中
  初始化 tensor 导致崩溃。
- [#1110](https://github.com/modular/modular/issues/1110) - `time.now()`
  函数现在在所有操作系统上都返回纳秒。
- [#1115](https://github.com/modular/modular/issues/1115) - 无法将
  非 register passable 类型加载到 SSA 寄存器中。
