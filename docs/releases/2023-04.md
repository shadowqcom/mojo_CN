## 2023-04-24 那一周

- 📢 嵌套函数的默认行为已更改。捕获变量的 Mojo 嵌套
  函数默认是非参数化的运行时闭包，这意味着：

  ```mojo
  def foo(x):
      # This:
      def bar(y): return x * y
      # Is the same as:
      let bar = lambda y: x * y
  ```

  这些闭包不能有输入或结果参数，因为它们始终
  物化为运行时值。闭包中捕获的值（上例中的 `x`）
  按拷贝捕获：有拷贝构造函数的值不能被
  拷贝，且捕获在闭包中是不可变的。

  不捕获任何内容的嵌套函数默认是"参数化"
  闭包：它们可以有参数并可作为参数值使用。
  要恢复捕获型闭包先前的行为——"参数化，
  按不安全引用捕获的闭包"——请用
  `@parameter` 装饰器标记嵌套函数。

- 📢 Mojo 现在完全支持 "运行时" 闭包：捕获状态物化为
  运行时值的嵌套函数。这包括取函数地址、间接调用、
  通过函数参数传递闭包。注意，按引用捕获仍然
  不安全！

  你也可以使用该类的实例对成员函数取引用，
  方法是 `foo.member_function`，这会创建一个将 `foo` 绑定到
  `self` 参数的闭包。

- 📢 Mojo 现在支持 Python 风格的 `with` 语句和上下文管理器。

  这些东西对实现诸如我们的
  trace region 支持以及 Runtime 支持等非常有用。

  Mojo 中的上下文管理器实现三个方法：

  ```mojo
  fn __enter__(self) -> T:
  fn __exit__(self):
  fn __exit__(self, err: Error) -> Bool:
  ```

  第一个在进入上下文时调用，并返回一个
  值，可选择地绑定到目标以供 with 体内使用。如果 with 块
  正常退出，调用第二个方法进行清理。如果
  抛出错误，调用第三个方法并传入 Error 值。如果
  该方法返回 true，错误被视为已处理；若返回 false，错误会被
  重新抛出，使传播继续出 'with' 块。

- 📢 Mojo 函数现在支持变量作用域！函数内部的显式 `var` 和 `let`
  声明可以遮蔽更高"作用域"中的声明，
  其中作用域定义为任何新的缩进块。此外，
  `for` 循环的迭代变量现在作用域限定于循环体，因此
  终于可以写

  ```mojo
  for i in range(1): pass
  for i in range(2): pass
  ```

- 📢 Mojo 现在支持结构体上的 `@value` 装饰器以减少样板代码并
  鼓励值语义的最佳实践。`@value` 装饰器会查看
  结构体是否有逐字段初始化器（参数对应结构体的每个
  字段）、一个 `__copyinit__` 方法和一个 `__moveinit__` 方法，
  并在可能时合成缺失的成员。例如，如果你写：

  ```mojo
  @value
  struct MyPet:
    var name: String
    var age: Int
  ```

  `@value` 装饰器将为你合成以下成员：

  ```mojo
  fn __init__(inout self, owned name: String, age: Int):
      self.name = name^
      self.age = age
  fn __copyinit__(inout self, existing: Self):
      self.name = existing.name
      self.age = existing.age
  fn __moveinit__(inout self, owned existing: Self):
      self.name = existing.name^
      self.age = existing.age
  ```

  该装饰器可大幅减少定义常见聚合体所需的样板代码，
  并自动赋予你所有权管理
  的最佳实践。`@value` 装饰器可与需要自定义
  拷贝构造函数的类型一起使用（你的定义优先）。未来我们可以
  探索让装饰器接受参数以进一步定制其行为。

- 📚 Memcpy 和 memcmp 现在一致地使用 count 作为字节数。

- 📚 添加字符串的可变字符串 join。

- 📚 引入 `reduce_bit_count` 方法以统计 SIMD 向量中所有
  元素中 1 的个数。

- 📚 在指数为整数时优化 `pow` 函数。

- 📚 添加 `len` 函数，跨不同
  支持它的结构体分派到 `__len__`。

## 2023-04-17 那一周

- 📢 错误信息已大幅改善，得益于诊断中 Mojo 类型的
  美化打印。

- 📢 可变值现在可以直接索引，无需包装在
  `VariadicList` 中！

- 📢 函数中的 `let` 声明现在可以惰性初始化，且从未
  被修改的 `var` 声明会收到建议将其转换为 `let` 声明的
  警告。惰性初始化允许比要求初始化器内联更灵活的初始化
  模式，例如：

  ```mojo
  let x: Int
  if cond:
      x = foo()
  else:
      x = bar()
  use(x)
  ```

- 📢 用 `def` 定义的函数现在默认返回 `object`，而非
  `None`。这意味着你可以在 `def` 函数内返回值（可转换为
  `object`）而无需指定返回类型。

- 📢 `@raises` 装饰器已被移除。可抛出的 `fn` 应通过
  在函数参数列表后指定 `raises` 来声明。理由是
  `raises` 是类型系统的一部分，而非函数修饰符。

- 📢 `BoolLiteral` 类型已被移除。Mojo 现在直接将
  `True` 和 `False` 发出为 `Bool`。

- 📢 已添加函数类型语法。现在你可以用
  `fn(Int) -> String` 或 `async def(&String, *Int) -> None` 编写函数类型。无需再
  手写 `!kgen.signature` 类型！

- 📢 浮点字面量不再作为 `FloatLiteral` 发出，而非 MLIR `f64`
  类型！

- 📢 Mojo 类型现已支持自动析构函数，目前写作
  `fn __del___(owned self):`（多出的下划线稍后会被去掉）。
  这些析构函数类似 Python 对象析构函数和 C++ 析构函数，
  主要区别在于它们在值的最后一次使用后"尽快"
  运行。这意味着它们不适合
  C++ 风格的 RAII 模式（对此请使用 `with` 语句，目前未支持）。

  这些对仅内存和可寄存器传递的类型
  通常可靠，但需注意闭包已知 *无法* 正确捕获
  值。在闭包附近对有趣类型要格外小心！

- 新增一个（极其危险！）的内建函数，用于低级
  所有权操作。`__get_address_as_owned_value(x)` 内建函数取一个
  低级地址值（`!kgen.pointer` 类型）并返回
  指向内存的 `owned` 值。该值在调用内建函数时假定
  为活，但它是"拥有的"，因此需要被调用者消费，否则
  将被自动销毁。这是对指针进行"placement delete"的有效方式。

  ```mojo
  # "Placement delete": destroy the initialized object begin pointed to.
  _ = __get_address_as_owned_value(somePointer.value)

  # Result value can be consumed by anything that takes it as an 'owned'
  # argument as well.
  consume(__get_address_as_owned_value(somePointer.value))
  ```

- 另一个魔法运算符 `__get_address_as_uninit_lvalue(x)` 加入了
  魔法 LValue 运算符家族。该运算符将指针投影为
  像 `__get_address_as_lvalue(x)` 那样的 LValue。区别在于
  `__get_address_as_uninit_lvalue(x)` 告诉编译器 pointee
  进入时未初始化、退出时已初始化，这意味着你可以
  将其用作 C++ 意义上的"placement new"。`__get_address_as_lvalue(x)` 告诉
  编译器 pointee 已初始化，因此对其重新赋值会
  运行析构函数。

  ```mojo
  # "*Re*placement new": destroy the existing SomeHeavy value in the memory,
  # then initialize a new value into the slot.
  __get_address_as_lvalue(somePointer.value) = SomeHeavy(4, 5)

  # Ok to use an lvalue, convert to borrow etc.
  use(__get_address_as_lvalue(somePointer.value))

  # "Placement new": Initialize a new value into uninitialied memory.
  __get_address_as_uninit_lvalue(somePointer.value) = SomeHeavy(4, 5)

  # Error, cannot read from uninitialized memory.
  use(__get_address_as_uninit_lvalue(somePointer.value))
  ```

  注意，`__get_address_as_lvalue` 假设指定地址已存在值，
  因此上面的赋值会在重新赋值前运行 `SomeHeavy`
  析构函数（如果有）。

- 📢 实现对 `__moveinit__` 的完整支持（即移动构造函数）

  这实现了仅内存类型按需定义两种不同
  类型的移动构造函数：

  1. `fn __moveinit__(inout self, owned existing: Self)`：传统的 Rust
     风格移动构造函数，在取得
     源绑定的所有权时移动数据。
  2. `fn __moveinit__(inout self, inout existing: Self):`：C++ 风格的"窃取"
     移动构造函数，可用于从任意 LValue 取值。

  这赋予我们出色的表达能力（优于 Rust/C++/Swift），
  并自然融入我们的生命周期跟踪与值
  分类系统。

- 可调用类型的 `__call__` 方法已放宽为按
  借用接受 `self`，允许调用不可拷贝的被调用者。

- 隐式转换现在在 `raise` 语句中被正确调用，允许
  将字符串转换为 `Error` 类型。

- 自动析构函数改用 `__del__` 而非 `__del___` 启用。

- 📚 添加内建 FloatLiteral 类型。

- 📚 为 SIMD 类型添加处理负值的整数
  `floordiv` 和 `mod`。

- 📚 添加 F64 到 String 的转换器。

- 📚 让 `print` 函数接受可变输入。

## 2023-04-10 那一周

- 📢 引入消费运算符 `x^`

  这引入了后置消费运算符，它产生一个给定
  生命周期跟踪对象（以及将来可移动 LValue）的 RValue。

- Mojo 现在在需要时为某些类型自动合成空的析构方法。

- `object` 类型已被构建为完全动态类型，具有动态
  函数分派，并具备完整的错误处理支持。

  ```mojo
  def foo(a) -> object:
      return (a + 3.45) < [1, 2, 3] # raises a TypeError
  ```

- 📢 `@always_inline` 装饰器不再需要用于将捕获
  闭包作为参数传递，无论对于这些函数本身还是参数中
  含捕获闭包的函数。这些函数仍被内联，
  但这是捕获型参数闭包的实现细节。Mojo 现在
  区分捕获型和非捕获型闭包。嵌套函数默认
  是捕获型的，可通过 `@noncapturing` 装饰器变为非捕获型。
  顶层函数可通过标记 `@closure` 装饰器作为
  捕获型闭包传递。

- 📢 已添加对列表字面量的支持。列表字面量 `[1, 2, 3]`
  生成可变异质列表类型。

- 可变参数已扩展以与内存主类型一起工作。

- 切片语法现在通过添加到编译器内建的新 `slice` 对象得到
  完整支持。使用 `a[1:2:3]` 的切片索引现在会发出
  对带切片对象的 `__setitem__` 和 `__getitem__` 的调用。

- 调用语法已连接到 `__call__`。现在你可以在自定义
  类型上 `f()`！

- 闭包现在被显式类型化为捕获型或非捕获型。如果
  函数打算接受捕获型闭包，则必须指定
  `capturing` 函数效果。

- 📚 添加 `Tile2D` 函数以启用通用 `2D` 分块优化。

- 📚 添加 `slice` 结构体，以通过
  `getitem`/`setitem` 获取/设置元素范围。

- 📚 为 autotuning 添加语法糖，既可指定 autotuned 值，
  也可搜索和声明求值函数。

## 2023-04-03 那一周

- `AnyType` 和 `NoneType` 别名已添加，并在所有
  文件中自动导入。

- 📢 Mojo VS Code 扩展已通过文档字符串校验改进。现在
  它会在函数文档字符串的参数名错误时发出警告，
  例如。

- 📢 在 `_CompilerBuiltin` 中新增内建字面量类型 `TupleLiteral`。
  它表示字面元组值，例如 `(1, 2.0)` 或 `()`。

- 📢 `Int` 类型已被移至新的 `Builtin` 模块，并在所有
  代码中自动导入。整数字面量的类型已从
  MLIR `index` 类型改为 `Int` 类型。

- Mojo 现在具有强大的流敏感的未初始化变量检查器。这
  意味着你在使用值之前需要初始化它们，即使你
  覆盖所有子组件。这使编译器能够推理
  值的真实生命周期，这是建立
  自动值销毁的重要垫脚石。

- 📢 已添加调用语法支持。现在你可以直接调用实现
  `__call__` 方法的对象，如 `foo(5)`。

- 📢 拷贝构造函数的名字已从 `__copy__` 改名为
  `__copyinit__`。此外，非 `@register_passable` 类型现在像
  实现初始化方法那样实现它，你填充按引用的 self，例如：

  ```mojo
  fn __copyinit__(inout self, existing: Self):
      self.first = existing.first
      self.second = existing.second
  ```

  这使拷贝构造的工作更类似于初始化，并且
  仍让拷贝 `x = y` 与初始化 `x = T(y)` 区分。

- 📢 内存主类型的初始化器现在必须采用
  `__init__(inout self, ...):` 形式且结果类型为 None，而对于寄存器主
  类型，它仍采用 `__init__(...) -> Self:` 形式。`T{}`
  初始化语法已对内存主类型移除。

- Mojo 字符串字面量现在发出内建 `StringLiteral` 类型！少了一个
  需要担心的 MLIR 类型。

- 新增 `__getattr__` 和 `__setattr__` dunder 方法。Mojo 在尝试
  非静态成员查找时会调用类型上的这些方法。
  这允许编写动态对象，例如 `x.foo()`，其中 `foo` 不是
  `x` 的成员。

- 已添加早期析构函数支持。类型现在可以定义特殊的
  析构方法 `__del___`（注意三个下划线）。这是一个早期
  特性，仍在构建中。有许多注意事项、bug
  和缺失部分。请期待！

- 📚 负数情况下的整数除法和 mod 的舍入已修正。

- 📚 添加标量类型（UI8、SI32、F32、F64 等），它们是
  `SIMD[1, type]` 的别名。
