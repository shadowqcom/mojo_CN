## ⭐️ 新增

- Mojo 现在支持默认参数值。例如：

  ```mojo
  fn foo[a: Int = 3, msg: StringLiteral = "woof"]():
      print(msg, a)

  fn main():
      foo()  # prints 'woof 3'
      foo[5]()  # prints 'woof 5'
      foo[7, "meow"]()  # prints 'meow 7'
  ```

  推断的参数值优先于默认值：

  ```mojo
  @value
  struct Bar[v: Int]:
      pass

  fn foo[a: Int = 42, msg: StringLiteral = "quack"](bar: Bar[a]):
      print(msg, a)

  fn main():
      foo(Bar[9]())  # prints 'quack 9'
  ```

  Struct 也支持默认参数：

  ```mojo
  @value
  struct DefaultParams[msg: StringLiteral = "woof"]:
      alias message = msg

  fn main():
      print(DefaultParams[]().message)  # prints 'woof'
      print(DefaultParams["meow"]().message)  # prints 'meow'
  ```

- 新的 [`file`](/docs/std/io/file/) 模块添加了基本的文件 I/O
  支持。你现在可以编写：

  ```mojo
  var f = open("my_file.txt", "r")
  print(f.read())
  f.close()
  ```

  或

  ```mojo
  with open("my_file.txt", "r") as f:
      print(f.read())
  ```

- Mojo 现在允许上下文管理器支持 `__enter__` 方法而无需
  实现对应的 `__exit__` 方法，从而支持如下惯用法：

  ```mojo
  # This context manager consumes itself and returns it as the value.
  fn __enter__(owned self) -> Self:
      return self^
  ```

  在此 Mojo *无法* 调用一个空操作的 `__exit__` 方法，因为上下文
  管理器已被 `__enter__` 方法消耗。这可用于那些传统上配合 `with`
  语句使用的类型（例如文件描述符），尽管 Mojo 的保证式提前析构
  并不要求这么做。

- Mojo 中实现了一个非常基础版本的 `pathlib`。该模块将在
  接下来的几个版本中持续改进，以达到与 Python 的功能对等。

- `memory.unsafe` 模块现在包含一个 `bitcast` 函数。这是一个
  低级操作，允许在指针和标量之间进行位转换（bitcasting）。

- 参数化类型的输入参数现在可以作为该类型或该类型变量的
  属性引用被直接访问。例如：

  ```mojo
  @value
  struct Thing[param: Int]:
      pass

  fn main():
      print(Thing[2].param) # prints '2'
      let x = Thing[9]()
      print(x.param) # prints '9'
  ```

  值上的输入参数甚至可以在参数上下文中访问。例如：

  ```mojo
  fn foo[value: Int]():
      print(value)

  let y = Thing[12]()
  alias constant = y.param + 4
  foo[constant]() # prints '16'
  ```

- Mojo REPL 现在支持代码补全。在键入时按 <kbd>Tab</kbd>
  即可查询可能的补全结果。

- 来自 Python 的错误信息现在会在 Mojo 中暴露出来。例如以下代码
  应当输出 `No module named 'my_uninstalled_module'`：

  ```mojo
  fn main():
      try:
          let my_module = Python.import_module("my_uninstalled_module")
      except e:
          print(e)
  ```

- 错误信息现在可以存储动态信息。例如以下代码应当输出
  "Failed on: Hello"

  ```mojo
  fn foo(x: String) raises:
      raise Error("Failed on: " + x)

  fn main():
      try:
          foo("Hello")
      except e:
          print(e)
  ```

## 🦋 变更

- 我们改进并简化了 `parallelize` 函数。该函数现在通过
  缓存 Mojo 并行运行时来省去部分开销。

- Mojo REPL 和 Jupyter 环境不再隐式暴露 `Python`、
  `PythonObject` 或 `Pointer`。这些符号现在必须显式导入，
  例如：

  ```mojo
  from python import Python
  from python.object import PythonObject
  from memory.unsafe import Pointer
  ```

- 使用 `__mlir_op` 前缀指定属性的语法已更改，
  以模仿 Python 的关键字参数传递语法。也就是说，应当使用 `=`
  而不是 `:`，例如：

  ```mojo
  # Old syntax, now fails.
  __mlir_op.`index.bool.constant`[value : __mlir_attr.false]()
  # New syntax.
  __mlir_op.`index.bool.constant`[value=__mlir_attr.false]()
  ```

- 你现在可以直接打印 `Error` 对象。`message()` 方法
  已被移除。

## 🛠️ 修复

- [#794](https://github.com/modular/modular/issues/794) - 使用 `in`
  运算符时解析器崩溃。
- [#936](https://github.com/modular/modular/issues/936) - `Int` 构造函数
  现在接受其他 `Int` 实例。
- [#921](https://github.com/modular/modular/issues/921) - 在没有 `main`
  函数的模块上运行 `mojo` 时提供更好的错误信息。
- [#556](https://github.com/modular/modular/issues/556) - UInt64 现在
  可以正确打印。
- [#804](https://github.com/modular/modular/issues/804) - 当传递
  不支持类型的可变参数时，改为输出错误而不是崩溃。
- [#833](https://github.com/modular/modular/issues/833) - 赋值模块值时
  解析器崩溃。
- [#752](https://github.com/modular/modular/issues/752) - 调用 async def 时
  解析器崩溃。
- [#711](https://github.com/modular/modular/issues/711) - 重载
  解析逻辑现在会正确地优先选择实例方法而非静态方法（在其他条件
  匹配程度相同的情况下），并且当静态方法的第一个参数为 `Self` 类型时
  不再崩溃。
- [#859](https://github.com/modular/modular/issues/859) - 修复了 `rebind`
  内建函数令人困惑的错误信息和文档。
- [#753](https://github.com/modular/modular/issues/753) - 直接使用 LLVM
  方言会在编译器中产生奇怪的错误。
- [#926](https://github.com/modular/modular/issues/926) - 修复了当返回类型为
  `StringRef` 的函数抛出错误时出现的问题。
  当函数抛出错误时，它会错误地返回该错误的字符串值。
- [#536](https://github.com/modular/modular/issues/536) - 在 python 异常上
  报告更多信息。
