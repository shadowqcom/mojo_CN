## 要点

- Mojo 标准库的部分内容继续逐步开源！现已开源的包
  包括：

  - [`algorithm`](/docs/std/algorithm/)
  - [`benchmark`](/docs/std/benchmark/)
  - `buffer`
  - [`compile`](/docs/std/compile/)
  - [`complex`](/docs/std/complex/)
  - [`gpu`](/docs/std/gpu/)
  - [`logger`](/docs/std/logger/)
  - [`runtime`](/docs/std/runtime/)
  - [`subprocess`](/docs/std/subprocess/)

  更多信息请参阅
  [标准库参考](/docs/lib/#standard-library) 和
  [标准库
  源码](https://github.com/modular/modular/tree/main/mojo/stdlib)。

- MAX AI 内核库的部分内容继续逐步开源！现已开源的包
  包括：

  - [`layout`](/docs/layout/)
  - [`linalg`](/docs/kernels/linalg/)

  更多信息请参阅
  [MAX AI 内核库参考](/docs/lib/#max-ai-kernels-library) 和
  [MAX AI 内核
  源码](https://github.com/modular/modular/tree/main/max/kernels)。

- 现已通过 `&` 语法支持 trait 组合。trait 组合将两个 trait 合并为一个
  逻辑 trait，其约束集是两个原始 trait 约束集的并集。更多信息请参阅
  Mojo 手册中的
  [Trait 组合](/docs/manual/traits/#trait-compositions)。

- Mojo 中的字符串类型得到了若干重大改进。详情请参阅
  [标准库变更](#25-3-standard-library-changes)。

## 语言变更 {#25-3-language-changes}

- Mojo 现在可以使用
  [用户声明的 `__merge_with__()` dunder 方法](https://github.com/modular/modular/blob/main/mojo/proposals/custom-type-merging.md)
  来在三元操作中使用不同类型时合并值。这已被采用以允许指针
  自然地与三元操作符配合工作，例如
  `var x = one_pointer if cond else other_pointer`。

- 自动参数化现在扩展到了 struct 元类型。例如，声明
  `fn foo[M: type_of(StringLiteral[_])]` 将自动对
  `StringLiteral` 的未绑定参数进行参数化。

- 当存储从未被使用的值时，Mojo 编译器现在会发出警告，例如：
  `x = foo(); x = bar()` 会对 `x` 的第一次赋值发出警告，因为它被
  覆盖了。通常你可以通过删除死代码来解决此问题，或
  改为赋值给 `_`：`_ = foo(); x = bar()`。你还可能在变量声明中
  遇到此问题，例如 `var x = 0; ...; x = foo()`。在这种
  情况下，请将变量声明为未初始化，例如
  `var x: Int`。你也可以通过将变量名改为以下划线开头
  来完全消除此警告，例如 `_x`。

- Mojo 编译器现在会对初始化方法中过时的 `mut self` 用法发出警告，
  请改为切换到 `fn __init__(out self)`。

- `def` 函数现在要求参数具有类型标注，并将缺失的返回类型视为返回
  `None`。此前这些默认为 `object` 类型，导致了各种问题。
  在我们有时间研究合适的替代方案之前，对 `object` 的支持已被
  移除。

## 标准库变更 {#25-3-standard-library-changes}

Mojo 中的字符串类型得到了若干重大改进：

- [`String`](/docs/std/collections/string/string/String/) 类型不再从
  [`StringLiteral`](/docs/std/builtin/string_literal/StringLiteral/) 和
  [`StaticString`](/docs/std/collections/string/string_slice/#aliases) 复制数据，
  因为它们是已知的静态常量值。这使我们能够将
  从这些值构造变为隐式的，从而同时改善易用性和性能。
  它还实现了 "小字符串优化"，避免了常见短字符串的堆
  分配。在 64 位系统上，`String` 可以
  内联存储多达 23 个字节。其拷贝构造函数现在是 O(1)，在
  变更时才延迟执行字符串数据复制。

- [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 和
  [`StaticString`](/docs/std/collections/string/string_slice/#aliases)
  类型现在已成为 prelude 的一部分，无需再导入它们。这些
  对于只需要字符串数据 "视图" 而非拥有和
  修改它的代码很有用。

- [`StringLiteral`](/docs/std/builtin/string_literal/StringLiteral/) 类型
  已迁移到更可靠的 "依赖类型" 设计，其中字符串的值由参数而不是
  存储成员承载。这消除了在与
  `StringLiteral` 工作时涉及在运行时尝试操作 `StringLiteral` 的一类
  编译器崩溃。作为此变更的结果，许多 API 应切换为
  使用 [`StaticString`](/docs/std/collections/string/string_slice/#aliases)
  而不是 `StringLiteral`。有关字面量的此 "依赖类型" 设计的
  更多信息，请参阅提案
  [Fixing Simple Literals in Mojo](https://github.com/modular/modular/blob/main/mojo/proposals/fixing-simple-literals.md)。

- `String` 支持新的 `String(unsafe_uninit_length=x)` 构造函数和
  `str.resize(unsafe_uninit_length=x)`，用于希望分配空间以
  使用自定义不安全初始化模式填充的客户端。
  `String(ptr=x, length=y)` 构造函数已被移除。

- `String` 支持与假设 null 终止的旧版 C API 配合工作，
  但细节已变更：`String` 现在不再隐式
  null 终止，这意味着假设 `str.unsafe_ptr()` 会返回 null 终止
  字符串是不正确的。为此，请使用
  `str.unsafe_cstr_ptr()` 方法。它现在要求字符串是可变的，以便
  按需延迟 null 终止。这改善了不传递给旧版 API 的
  字符串的性能。

- [`List`](/docs/std/collections/list/List/) 类型已得到改进，
  类似于 `String`，以减少不一致并启用 power-user 功能，
  包括添加 `List(unsafe_uninit_length=x)` 和
  `list.resize(unsafe_uninit_size=n)` 方法，以避免调用方
  计划覆盖的已初始化内存。

- [`Set`](/docs/std/collections/set/Set/) 现在符合
  [`Copyable`](/docs/std/builtin/value/Copyable/) trait，因此你可以将集合
  存储在其他类型的集合中（例如，作为 `Dict` 中的值）。

- 以下 trait 已被移除，由 trait 组合取代：
  `EqualityComparableCollectionElement`、`RepresentableCollectionElement`、
  `TestableCollectionElement`、`Testable`、`StringableIdentifiable`、
  `StringableCollectionElement`、`IntervalPayload`、`WritableCollectionElement`、
  `ComparableCollectionElement`、`BoolableCollectionElement`、
  `EqualityComparableWritableCollectionElement`、
  `EqualityComparableWritableCollectionElementNew`、`CollectionElementNew`、
  `WritableCollectionElementNew`。

  例如，你可以用
  `EqualityComparable & CollectionElement` 替换 `EqualityComparableCollectionElement`。
  `StringableCollectionElement`
  此前已被弃用并计划移除；它可以用
  `Writable & CollectionElement` 替换。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 类型
  正在重构，以为 Mojo-Python 互操作性的若干改进做准备：

  - 由于对 `PythonObject` 的几乎任何操作都可能引发异常，
    `PythonObject` 结构体不再实现以下 trait：
    `ImplicitlyBoolable`、`ImplicitlyIntable`。

  - `PythonObject` 不再可从 tuple 或 list
    字面量隐式构造。例如，`var x: PythonObject = [1, 2, "foo"]` 不再被
    接受。请改为使用新的 `Python.list()` 和 `Python.tuple()`
    工厂方法。例如：

    ```mojo
    var x = Python.list(1, 2, "foo")
    ```

    （`list()` 和 `tuple()` 工厂方法最初添加在
    `PythonObject` 上，但已移至 `Python` 结构体。）

    我们希望在未来随着标准库的成熟重新启用字面量语法。

  - `PythonObject.from_borrowed_ptr()` 已被移除，由
    具有 `from_borrowed_ptr` 仅关键字参数的构造函数取代。

  - 已弃用的 `PythonObject.to_float64()` 方法已被移除。请改为使用
    `Float64()` 构造函数。

- [`Span`](/docs/std/memory/span/Span/) 现在具有 `swap_elements()` 方法，
  它接受两个索引并在 span 内交换它们。

- [`Pointer`](/docs/std/memory/pointer/Pointer/) 现在具有 `get_immutable()`
  方法，用于返回一个具有相同底层数据但具有
  `ImmutableOrigin` 的新 `Pointer`。

- 你现在可以使用 `WritableVariadicPack` 将全部值都为
  `Writable` 的
  [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 转发给 writer：

  ```mojo
  from utils.write import WritableVariadicPack

  fn print_message[*Ts: Writable](*messages: *Ts):
      print("message:", WritableVariadicPack(messages), "[end]")

  x = 42
  print_message("'x = ", x, "'")
  ```

  ```text
  message: 'x = 42' [end]
  ```

  在此示例中，可变参数包在 `print` 调用中与
  额外参数一起被缓冲到栈上，然后再进行一次系统调用写入到
  stdout。

- AMD GPU 内核中的 [`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert/)
  现在行为与 NVIDIA 上相同，会打印线程信息和
  条件之后传递的可变参数：

  ```mojo
  from gpu.host import DeviceContext

  fn kernel():
      var x = 1
      debug_assert(x == 2, "x should be 2 but is: ", x)

  def main():
      with DeviceContext() as ctx:
          ctx.enqueue_function[kernel](grid_dim=2, block_dim=2)
  ```

  运行 `mojo run -D ASSERT=all [filename]` 将输出：

  ```text
  At /tmp/test.mojo:5:17: block: [0,0,0] thread: [0,0,0] Assert Error: x should be 2 but is: 1
  At /tmp/test.mojo:5:17: block: [0,0,0] thread: [1,0,0] Assert Error: x should be 2 but is: 1
  At /tmp/test.mojo:5:17: block: [1,0,0] thread: [0,0,0] Assert Error: x should be 2 but is: 1
  At /tmp/test.mojo:5:17: block: [1,0,0] thread: [1,0,0] Assert Error: x should be 2 but is: 1
  ```

- [`constrained[cond, string]()`](/docs/std/builtin/constrained/constrained/)
  函数现在接受多个在失败时打印连接的字符串，
  因此你可以使用：

  ```mojo
  constrained[cond, "hello: ", String(n), ": world"]()
  ```

  这比使用字符串连接在编译时更高效，也更具人机工程性。

- [`pathlib.Path.write_text()`](/docs/std/pathlib/path/Path/#write_text) 现在
  接受 `Writable` 参数而不是 `Stringable` 参数。这使
  函数通过移除一次 String 分配更高效。

- 添加了
  [`pathlib.Path.write_bytes()`](/docs/std/pathlib/path/Path/#write_bytes)
  ，用于将原始字节写入文件。

- 添加了
  [`os.path.split_extension()`](/docs/std/os/path/path/split_extension/)，
  用于将路径拆分为其根和扩展名。

- 添加了 [`os.path.is_absolute()`](/docs/std/os/path/path/is_absolute/)，用于
  检查给定路径是否为绝对路径。

- 现在可以指定原子操作中使用的一致性模型，默认为
  顺序一致性。一致性模型在
  `Consistency` 结构体中定义。

- 添加了
  [`Variant.is_type_supported()`](/docs/std/utils/variant/Variant/#is_type_supported)
  方法。（[PR #4057](https://github.com/modular/modular/pull/4057)）示例：

  ```mojo
    def takes_variant(mut arg: Variant):
        if arg.is_type_supported[Float64]():
            arg = Float64(1.5)
    def main():
        var x = Variant[Int, Float64](1)
        takes_variant(x)
        if x.isa[Float64]():
            print(x[Float64]) # 1.5
  ```

- `SIMD` 的 `type` 参数已重命名为 `dtype`。

- `bit` 包中的 `is_power_of_two(x)` 函数现在是
  `Int`、`UInt` 和 `SIMD` 的方法。

- `Pointer.address_of(...)` 和 `UnsafePointer.address_of(...)` 函数
  已被弃用。请改为使用
  [`Pointer(to=...)`](/docs/std/memory/pointer/Pointer/#__init__) 和
  [`UnsafePointer(to=...)`](/docs/std/memory/unsafe_pointer/UnsafePointer/#__init__)
  构造函数。从概念上讲，这是在说 "请初始化一个
  `Pointer`（如果愿意，可视为引用）指向 *内存中的某个其他地址*"。在
  未来，这些 `address_of()` 函数将被移除。

## 工具链变更 {#25-3-tooling-changes}

- 修复了调试器中 SIMD 布尔值显示：SIMD 布尔值现在可以
  正确显示，并正确提取位。

- 改进了语言服务器性能：语言服务器现在避免
  解析超过其需要的内容，全面改善了性能。

- Mojo 编译器现在能够解释 `Int` 和 `UInt` 类型的方法中
  使用 `index` 方言的所有算术运算。
  这使用户最终能够在编译时计算常量：

  ```mojo
  alias a: Int = 1000000000
  alias b: Int = (5 * a) // 2
  ```

  此前，编译器会抛出错误 "cannot fold operation"。

- 为 `mojo build` 命令添加了新的 `--emit-llvm` 选项，允许
  用户发出 LLVM IR。当指定 `--emit-llvm` 时，构建过程
  将：将 mojo 代码编译为 LLVM IR，将 IR 保存到 .ll 文件（使用与
  输入文件相同的名称），并将 IR 打印到 stdout 以便立即检查。

## 其他变更

- 向 `__mlir_op` 添加属性的语法现在仅限于固有
  属性（由操作定义的那些）。大多数用户不需要
  附加其他类型的属性，这有助于防止拼写错误和当
  方言变更时 mojo 代码过时。

## 已移除 {#25-3-removed}

- `SIMD.roundeven()` 方法已从标准库中移除。
  此功能现在由
  [`round()`](/docs/std/math/math/round/) 函数处理。

- 关于过时的 `borrowed` 和 `inout` 关键字以及过时的
  `-> Int as name` 语法的错误消息已被移除。

- `object` 类型已被移除。

- `utils.numerics.ulp` 已被移除。请改为使用
  `math` 包中的 [`ulp()`](/docs/std/math/math/ulp/) 函数。

- 在 25.2 版本中弃用的若干自由函数现已
  移除。这包括：

  - `str` 自由函数。请改为使用 `String` 构造函数。
  - `int` 自由函数。请改为使用 `Int` 构造函数。
  - `bool` 自由函数。请改为使用 `Bool` 构造函数。
  - `float` 自由函数。请改为使用 `Float64` 构造函数。

- 移除了已弃用的
  [`DeviceContext`](/docs/std/gpu/host/device_context/DeviceContext/) 方法
  `copy_sync()` 和 `memset_sync()`。

- `unroll()` 工具已被移除。请改为使用
  [`@parameter for` 构造](/docs/reference/decorators/parameter/#parametric-for-statement)。

  ```mojo
  from utils.loop import unroll

  # Before
  @always_inline
  @parameter
  fn foo[i: Int]():
      body_logic[i]()
  unroll[foo, iteration_range]()

  # After
  @parameter
  for i in range(iteration_range):
      body_logic[i]()
  ```

- `InlinedString` 类型已被移除。请改为使用 `String`，它现在
  支持小字符串优化 (SSO)。

- `AsBytes` trait 已被移除。
