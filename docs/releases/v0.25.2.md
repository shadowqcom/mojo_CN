## 要点

- 查看 [Mojo 手册](/docs/manual/) 中新的 [GPU 基础](/docs/manual/gpu/fundamentals/) 章节以及
  [使用 Mojo 和 MAX Driver 开始 GPU 编程](/docs/manual/gpu/intro-tutorial/)
  教程，作为在 Mojo 中开始 GPU 编程的指南！

- [`gpu`](/docs/std/gpu/) 包中的某些 API 已得到增强，简化了
  GPU 的使用。

  - 如果你只执行 GPU 内核一次，现在可以先跳过编译，直接将其
    传递给
    [`DeviceContext.enqueue_function()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_function)，
    而无需先 enqueue 之前先编译它。

  - `DeviceContext` 上用于在主机和 GPU 内存之间异步复制缓冲区的
    三个独立方法已合并为一个重载的
    [`enqueue_copy()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_copy)
    方法，而用于同步复制的三个独立方法已合并为一个重载的
    [`copy_sync()`](/docs/std/gpu/host/device_context/DeviceContext/#copy_sync)
    方法。

  - `gpu.shuffle` 模块已重命名为
    [`gpu.warp`](/docs/std/gpu/primitives/warp/)，以更好地反映其用途。

  - [`gpu`](/docs/std/gpu/) 包的 API 文档已扩展，并且
    [`layout`](/docs/layout/) 包的 API 文档正在编写中，从核心类型、
    函数和 trait 开始。

  更多信息请参阅更新日志的
  [标准库变更](#25-2-standard-library-changes) 章节。

- 旧的 `borrowed`/`inout` 关键字和 `-> T as foo` 语法已不再
  支持，现在会生成编译错误。请改为使用 `read`/`mut`/`out`
  参数语法。更多信息请参阅 Mojo 手册中的
  [参数约定](/docs/manual/values/ownership#argument-conventions)。

- 标准库中有许多与字符串相关的变更。值得注意的是，`Char`
  类型已重命名为
  [`Codepoint`](/docs/std/collections/string/codepoint/Codepoint/)，以更好地
  体现其存储单个 Unicode 码点的预期用途。
  此外，相关的方法和类型名称也已更新。更多详情请参阅
  [标准库变更](#25-2-standard-library-changes)。

- 已添加对 128 位和 256 位有符号和无符号整数的支持。这包括
  [`DType`](/docs/std/builtin/dtype/DType/) 别名
  `DType.int128`、`DType.uint128`、`DType.int256` 和 `DType.uint256`，以及
  [`SIMD`](/docs/std/builtin/simd/SIMD/) 对 128 位和 256 位
  有符号和无符号元素类型的支持。请注意，这暴露了 LLVM 的能力
  （和限制），LLVM 可能并不总是为这些类型提供高性能，
  并可能缺少除法、求余等操作。更多详情请参阅
  [标准库变更](#25-2-standard-library-changes)。

## 语言变更 {#25-2-language-changes}

- 现在允许引用具有未绑定（或部分绑定）参数集的结构体类型中的别名，
  只要被引用的别名不依赖任何未绑定的参数：

  ```mojo
  struct StructWithParam[a: Int, b: Int]:
    alias a1 = 42
    alias a2 = a+1

  fn test():
    _ = StructWithParams.a1 # ok
    _ = StructWithParams[1].a2 # ok
    _ = StructWithParams.a2 # error, 'a' is unbound.
  ```

- 当 `@parameter for` 的循环展开因子较大时（默认 >1024），
  Mojo 编译器现在会发出警告，这可能导致编译时间过长和
  生成的代码体积过大。设置 `--loop-unrolling-warn-threshold` 可将默认值
  更改为不同的阈值，或设置为 `0` 以禁用警告。

- Mojo 编译时解释器现在可以处理更多 LLVM 内联函数，
  包括返回浮点值的内联函数。这允许诸如
  [`round()`](/docs/std/math/math/round/) 等函数在编译时
  上下文中使用时进行常量折叠。

- Mojo 编译器现在只有一个编译时解释器。此前它有两个：
  一个用于处理解析器中依赖类型的几个重要情况（但也有许多限制），
  另一个是在 "instantiation" 时运行的主要解释器，功能完全通用。
  这让人困惑并导致了大量 bug。我们现已移除了特殊情况下的解析时
  解释器，用更通用的依赖类型解决方案替代它。
  此变更对大多数用户应该是不可见的，但应能解决一些长期存在的 bug，
  并显著简化编译器实现，使我们能更快地推进。

## 标准库变更 {#25-2-standard-library-changes}

- [`Optional`](/docs/std/collections/optional/Optional/)、
  [`Span`](/docs/std/memory/span/Span/) 和
  [`InlineArray`](/docs/std/collections/inline_array/InlineArray/) 已添加到
  prelude 中。你现在不再需要显式导入这些类型即可在程序中使用它们。

- GPU 编程变更：

  - 你现在可以先跳过编译 GPU 内核，直接将其传递给
    [`DeviceContext.enqueue_function()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_function)：

    ```mojo
    from gpu.host import DeviceContext

    fn func():
        print("Hello from GPU")

    with DeviceContext() as ctx:
        ctx.enqueue_function[func](grid_dim=1, block_dim=1)
    ```

    但是，如果你多次重用相同的函数和参数，每次 enqueue 会产生
    大约 50-500 纳秒的开销。因此你仍可先使用
    [`DeviceContext.compile_function()`](/docs/std/gpu/host/device_context/DeviceContext/#compile_function)
    编译函数，然后将其传递给 `DeviceContext.enqueue_function()`，如下所示：

    ```mojo
    with DeviceContext() as ctx:
      var compiled_func = ctx.compile_function[func]()
      # Multiple kernel launches with the same function/parameters
      ctx.enqueue_function(compiled_func, grid_dim=1, block_dim=1)
      ctx.enqueue_function(compiled_func, grid_dim=1, block_dim=1)
    ```

  - [`DeviceContext`](/docs/std/gpu/host/device_context/DeviceContext/) 上
    的以下方法：

    - `enqueue_copy_to_device()`
    - `enqueue_copy_from_device()`
    - `enqueue_copy_device_to_device()`

    已合并为单个重载的
    <!-- rumdl-disable-next-line MD013 -->
    [`enqueue_copy()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_copy)
    方法。此外，以下方法：

    - `copy_to_device_sync()`
    - `copy_from_device_sync()`
    - `copy_device_to_device_sync()`

    已合并为重载的
    [`copy_sync()`](/docs/std/gpu/host/device_context/DeviceContext/#copy_sync)
    方法。

  - `gpu.shuffle` 模块已重命名为
    [`gpu.warp`](/docs/std/gpu/primitives/warp/)，以更好地反映其用途。
    例如：

    ```mojo
    import gpu.warp as warp

    var val0 = warp.shuffle_down(x, offset)
    var val1 = warp.broadcast(x)
    ```

- 已添加对 128 位和 256 位有符号和无符号整数的支持。

  - 以下别名已添加到
    [`DType`](/docs/std/builtin/dtype/DType/) 结构体：`DType.int128`、
    `DType.uint128`、`DType.int256` 和 `DType.uint256`。

  - [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型现在支持 128 位和
    256 位有符号和无符号元素类型。请注意，这暴露了 LLVM 的能力
    （和限制），LLVM 可能并不总是为这些类型提供高性能，
    并可能缺少除法、求余等操作。

  - 已为单元素 `SIMD` 值添加了以下
    [`Scalar`](/docs/std/builtin/simd/#aliases) 别名：
    `Int128`、`UInt128`、`Int256` 和
    `UInt256`。

- [`String`](/docs/std/collections/string/) 及相关类型：

  - `Char` 类型已重命名为
    [`Codepoint`](/docs/std/collections/string/codepoint/Codepoint/)，以
    更好地体现其存储单个 Unicode 码点的预期用途。
    此外，相关的方法和类型名称也已更新，包括：

    - `StringSlice.chars()` 和 `String.chars()` 分别改为
      [`StringSlice.codepoints()`](/docs/std/collections/string/string_slice/StringSlice/#codepoints)
      和
      [`String.codepoints()`](/docs/std/collections/string/string/String/#codepoints)

    - `StringSlice.char_slices()` 和 `String.char_slices()` 分别改为
      [`StringSlice.codepoint_slices()`](/docs/std/collections/string/string_slice/StringSlice/#codepoint_slices)
      和
      [`String.codepoint_slices()`](/docs/std/collections/string/string/String/#codepoint_slices)

    - `CharsIter` 改为
      [`CodepointsIter`](/docs/std/collections/string/string_slice/CodepointsIter/)

    - `Char.unsafe_decode_utf8_char()` 改为
      [`Codepoint.unsafe_decode_utf8_codepoint()`](/docs/std/collections/string/codepoint/Codepoint/#unsafe_decode_utf8_codepoint)

    - 将字符串 `codepoint_slices()` 方法返回的迭代器类型公开为
      [`CodepointSliceIter`](/docs/std/collections/string/string_slice/CodepointSliceIter/)。

  - [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)
    现在支持从
    [`String`](/docs/std/collections/string/string/String/) 迁移过来的若干
    新方法。现有的 `String` 方法已更新为改为调用相应的新
    `StringSlice` 方法：

    - [`center()`](/docs/std/collections/string/string_slice/StringSlice/#center)
    - [`is_ascii_digit()`](/docs/std/collections/string/string_slice/StringSlice/#is_ascii_digit)
    - [`is_ascii_printable()`](/docs/std/collections/string/string_slice/StringSlice/#is_ascii_printable)
    - [`islower()`](/docs/std/collections/string/string_slice/StringSlice/#islower)
    - [`isupper()`](/docs/std/collections/string/string_slice/StringSlice/#isupper)
    - [`ljust()`](/docs/std/collections/string/string_slice/StringSlice/#ljust)
    - [`lower()`](/docs/std/collections/string/string_slice/StringSlice/#lower)
    - [`rjust()`](/docs/std/collections/string/string_slice/StringSlice/#rjust)
    - [`split()`](/docs/std/collections/string/string_slice/StringSlice/#split)
    - [`upper()`](/docs/std/collections/string/string_slice/StringSlice/#upper)

  - 添加了
    [`StringSlice.is_codepoint_boundary()`](/docs/std/collections/string/string_slice/StringSlice/#is_codepoint_boundary)
    方法，用于查询给定的字节索引是否是已编码 UTF-8 码点之间的边界。

  - [`StringSlice.__getitem__(Slice)`](/docs/std/collections/string/string_slice/StringSlice/#__getitem__)

    字符串，如：

  - `StringLiteral.get[value]()` 方法（用于转换 `Stringable` 类型的
    编译时值）已更改为名为
    `get_string_literal[value]()` 的函数。

- 集合：

  - 新的 [`IntervalTree`](/docs/std/collections/interval/IntervalTree/) 数据
    结构已添加到标准库中。这是一种树数据结构，允许进行高效的
    范围查询。

  - 为
    [`LinkedList`](/docs/std/collections/linked_list/LinkedList/) 添加了
    迭代器（[PR
    #4005](https://github.com/modular/modular/pull/4005)）

    - [`LinkedList.__iter__()`](/docs/std/collections/linked_list/LinkedList/#__iter__)
      用于创建前向迭代器。

    - [`LinkedList.__reversed__()`](/docs/std/collections/linked_list/LinkedList/#__reversed__)
      用于创建后向迭代器。

    ```mojo
    var ll = LinkedList[Int](1, 2, 3)
    for element in ll:
      print(element[])
    ```

  - `List.bytecount()` 已重命名为
    [`List.byte_length()`](/docs/std/collections/list/List/#byte_length)，以便
    与字符串类 API 保持一致。

  - [`InlineArray(unsafe_uninitialized=True)`](/docs/std/collections/inline_array/InlineArray/#__init__)
    构造函数现在改写为 `InlineArray(uninitialized=True)`。

- [`IntLiteral`](/docs/std/builtin/int_literal/IntLiteral/)
  和 [`FloatLiteral`](/docs/std/builtin/float_literal/FloatLiteral/) 类型
  的设计已更改，将它们的编译时专用值作为 parameter 而不是存储字段
  来维护。这正确地建模了无限精度字面量在运行时无法表示的事实，
  并消除了在边角情况下遇到的若干 bug。这是通过编译器中增强的依赖类型
  支持实现的。

- `Buffer` 结构体已被移除，由
  [`Span`](/docs/std/memory/span/Span/) 和 `NDBuffer` 取代。

- [`round()`](/docs/std/math/math/round/) 函数现已修复，执行
  "round half to even"（又称 "银行家舍入"），而不是
  "round half away from zero"。

- [`UnsafePointer.alloc()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#alloc)
  方法已更改为生成具有空 `Origin` 参数的指针，
  而不是具有 `MutableAnyOrigin`。这缓解了 any
  origin 参数延长此常见方法中无关局部变量生命周期的问题。

- 现已为更多包提供了文档：

  - [`compile`](/docs/std/compile/) 包
  - [`gpu`](/docs/std/gpu/) 包
  - [`layout`](/docs/layout/) 包正在编写中，从核心
    类型、函数和 trait 开始

- 添加了新的 `sys.is_compile_time()` 函数。这使你能够查询代码
  是否在编译时执行。例如：

  ```mojo
  from sys import is_compile_time

  fn check_compile_time() -> String:
    if is_compile_time():
        return "compile time"
    else:
        return "runtime"

  def main():
      alias var0 = check_compile_time()
      var var1 = check_compile_time()
      print("var0 is evaluated at ", var0, " , while var1 is evaluated at ", var1)
  ```

  将打印
  `var0 is evaluated at compile time, while var1 is evaluated at runtime`。

## 工具链变更 {#25-2-tooling-changes}

- Mojo API 文档生成现在能够在嵌套参数化类型中使用名称而不是
  索引来显示函数和结构体参数引用。例如，代替

  ```mojo

  sort[type: CollectionElement, //, cmp_fn: fn($1|0, $1|0) capturing -> Bool](span: Span[type, origin])

  ```

  现在显示

  ```mojo

  sort[type: CollectionElement, //, cmp_fn: fn(type, type) capturing -> Bool](span: Span[type, origin])

  ```

## 已移除

- 使用旧参数约定（如 `inout`）以及在命名结果中使用 `as` 现在会
  产生错误消息而不是警告。

- 对 `List.size` 的直接访问已被移除。请改为使用公共 API。

  示例：

  扩展 List：

  ```mojo
  base_data = List[Byte](1, 2, 3)

  data_list = List[Byte](4, 5, 6)
  ext_data_list = base_data.copy()
  ext_data_list.extend(data_list) # [1, 2, 3, 4, 5, 6]

  data_span = Span(List[Byte](4, 5, 6))
  ext_data_span = base_data.copy()
  ext_data_span.extend(data_span) # [1, 2, 3, 4, 5, 6]

  data_vec = SIMD[DType.uint8, 4](4, 5, 6, 7)
  ext_data_vec_full = base_data.copy()
  ext_data_vec_full.extend(data_vec) # [1, 2, 3, 4, 5, 6, 7]

  ext_data_vec_partial = base_data.copy()
  ext_data_vec_partial.extend(data_vec, count=3) # [1, 2, 3, 4, 5, 6]
  ```

  高效地切片并扩展列表：

  ```mojo
  base_data = List[Byte](1, 2, 3, 4, 5, 6)
  n4_n5 = Span(base_data)[3:5]
  extra_data = Span(List[Byte](8, 10))
  end_result = List[Byte](capacity=len(n4_n5) + len(extra_data))
  end_result.extend(n4_n5)
  end_result.extend(extra_data) # [4, 5, 8, 10]
  ```

- `InlinedFixedVector` 和 `InlineList` 已被移除。当上界在
  编译时已知时，请改为使用
  [`InlineArray`](/docs/std/collections/inline_array/InlineArray/)。
  如果上界直到运行时才可知，请使用 [`List`](/docs/std/collections/list/List/)
  并配合 `capacity` 构造函数以最小化分配。

## 已修复

- [#3976](https://github.com/modular/modular/issues/3976) [`random.randn_float64()`](/docs/std/random/random/randn_float64/)
  和 [`random.randn()`](/docs/std/random/random/randn/) 中的 `variance`
  参数已重命名为 `standard_deviation`，以便值从正确的分布中抽取。
