## Highlights

本版本的主要主题:

- 改进 `def` 函数的性能和易用性。

- 继续围绕 `UnsafePointer` 类型统一标准库 API。

- 标准库集合类型的许多易用性改进。

- 向 `Dict` 插入元素时的显著性能改进。该指标上的性能仍未达到我们期望的水平,但已大幅改善。

- 新增 `@parameter for` 机制,用于表达编译时循环,取代了早期(且不那么可靠)的 `@unroll` 装饰器。

- Mojo 手册新增关于[控制流](/docs/manual/control-flow/)、[测试](/docs/tools/testing/)以及使用[不安全指针](/docs/manual/pointers/unsafe-pointers/)的页面。

## Language changes

- Mojo 改变了 `def` 函数参数的处理方式。以前,默认情况下,`def` 的参数按 `owned` 约定处理,这会拷贝值,使该值在被调用方中可变。

  这可能由于不必要的拷贝大量出现而引发重大性能问题。它还要求你将不可拷贝类型显式声明为 `borrowed`。现在 Mojo 采用了不同方式:`def` 函数默认以 `borrowed` 接收参数(与 `fn` 函数一致),但**仅在参数被修改时**才在函数体内对值进行本地拷贝。

  这改善了易用性、性能和一致性。

- `def` 函数中的隐式变量定义更灵活:你现在可以通过 `a,b,c = foo()` 将变量隐式声明为元组返回的结果。例如:

  ```mojo
  def return_two(i: Int) -> (Int, Int):
    return i, i+1

  a, b = return_two(5)
  ```

  隐式变量声明现在也可以遮蔽全局不可变符号(如模块名和内置项),而不会产生编译器错误。例如:

  ```mojo
  slice = foo()
  ```

- Mojo 函数可以在结果类型说明符中使用新的 `ref` 关键字返回对存储的自动解引用。例如:

  ```mojo
  @value
  struct Pair:
      var first: Int
      var second: Int

      fn get_first_ref(inout self) -> ref [self] Int:
          return self.first

  fn show_mutation():
      var somePair = Pair(5, 6)
      somePair.get_first_ref() = 1
    ```

  此方法提供了一种通用方式来返回给定类型的"自动解引用"引用。值得注意的是,这消除了 `__refitem__()` 存在的必要。因此 `__refitem__()` 已被移除,并由返回引用的 `__getitem__()` 取代。

- Mojo 增加了对*仅推断参数*的支持。仅推断参数必须出现在参数列表的开头,且不能由用户显式指定。它们声明在 `//` 标记的左侧,很像仅位置参数。这允许程序员定义带依赖参数的函数,而无需调用者指定所有必要的参数。例如:

  ```mojo
  fn parameter_simd[dt: DType, //, value: Scalar[dt]]():
      print(value)

  fn call_it():
      parameter_simd[Int32(42)]()
  ```

  在上例中,`Int32(42)` 直接传入 `value`,即第一个非仅推断参数。`dt` 从参数本身推断为 `DType.int32`。

  这同样适用于 struct。例如:

  ```mojo
  struct ScalarContainer[dt: DType, //, value: Scalar[dt]]:
      pass

  fn foo(x: ScalarContainer[Int32(0)]): # 'dt' is inferred as `DType.int32`
      pass
  ```

  这应当让使用依赖参数更符合人体工程学。请参阅 Mojo 手册中的[仅推断参数](/docs/manual/parameters/#infer-only-parameters)。

- Mojo 现在允许在形成对重载参数函数的引用(但不调用)时解析该函数。例如,以下写法现在可行:

  ```mojo
  fn overloaded_parameters[value: Int32]():
      pass

  fn overloaded_parameters[value: Float32]():
      pass

  fn form_reference():
      alias ref = overloaded_parameters[Int32()] # works!
  ```

- Mojo 现在支持在 struct、函数、trait、别名和全局变量上添加 `@deprecated` 装饰器。该装饰器将附加声明标记为已弃用,并在用户代码中引用已弃用声明时发出警告。该装饰器需要一个弃用消息,以字符串字面量形式指定。

  ```mojo
  @deprecated("Foo is deprecated, use Bar instead")
  struct Foo:
      pass

  fn outdated_api(x: Foo): # warning: Foo is deprecated, use Bar instead
      pass

  @deprecated("use another function!")
  fn bar():
      pass

  fn techdebt():
      bar() # warning: use another function!
  ```

- Mojo 引入了 [`@parameter for`](/docs/reference/decorators/parameter/#parametric-for-statement),一个用于编译时编程的新特性。`@parameter for` 定义一个 for 循环,其中序列和序列中的归纳值都必须是参数值。例如:

  ```mojo
  fn parameter_for[max: Int]():
      @parameter
      for i in range(max)
          @parameter
          if i == 10:
              print("found 10!")
  ```

  目前,`@parameter for` 要求序列的 `__iter__()` 方法返回一个 `_StridedRangeIterator`,这意味着归纳变量必须是 `Int`。未来计划放宽这些限制。

- `Reference` 和 `AnyLifetime` 的 `is_mutable` 参数现在是 `Bool`,而非低层 `__mlir_type.i1` 值。

  这改善了显式书写 `Reference` 类型的易用性。

- Mojo 现在会根据你的搜索路径顶部的 Python 链接到 Python 动态库:`PATH`。这允许你激活如 `conda` 的虚拟环境,并访问该环境中安装的 Python 模块,而无需设置 `MOJO_PYTHON_LIBRARY`。以前 Mojo 会在安装时找到一个 `libpython` 动态库并将路径放入 `.modular/modular.cfg`,如果你激活了不同 Python 版本的虚拟环境,可能导致版本冲突。

- `AnyRegType` 已重命名为 `__TypeOfAllTypes`,Mojo 现在禁止将非平凡的可寄存器传递类型绑定到 `__TypeOfAllTypes`。这关闭了语言中一个重大的安全漏洞。今后,请使用 `AnyType` 进行泛型编程。

- `let` 关键字已从语言中完全移除。我们之前移除了 `let` 声明但仍向用户提供错误信息。现在,它已从语法中完全消失。

## Standard library changes

- 新 trait 和相关特性:

  - 添加了内置 [`repr()`](/docs/std/format/repr/repr/) 函数和 `Representable` trait。
  ([PR #2361](https://github.com/modular/modular/pull/2361))

  - 添加了 [`Indexer`](/docs/std/builtin/int/Indexer/) trait,用于表示实现了 `__index__()` 方法的类型,这允许这些类型在常见的 `__getitem__()` 和 `__setitem__()` 实现中被接受,并允许对其调用新的内置
    [`index()`](/docs/std/builtin/int/index/)
    函数。现在大多数标准库容器可以被任何实现 `Indexer` 的类型索引。例如:

    ```mojo
    @value
    struct AlwaysZero(Indexer):
        fn __index__(self) -> Int:
            return 0

    struct MyList:
        var data: List[Int]

        fn __init__(inout self):
            self.data = List[Int](1, 2, 3, 4)

        fn __getitem__[T: Indexer](self, idx: T) -> Int:
            return self.data[index(idx)]

    print(MyList()[AlwaysZero()])  # prints `1`
    ```

    遵循 `Indexer` trait 的类型会隐式转换为 Int。这意味着你可以编写接受 `Int` 的泛型 API,而不必让它们接受遵循 `Indexer` 的泛型类型。例如:

    ```mojo
    @value
    struct AlwaysZero(Indexer):
        fn __index__(self) -> Int:
            return 0

    @value
    struct Incrementer:
        fn __getitem__(self, idx: Int) -> Int:
            return idx + 1

    var a = Incrementer()
    print(a[AlwaysZero()])  # works and prints 1
    ```

    ([PR #2685](https://github.com/modular/modular/pull/2685))

  - 添加了若干 trait,允许用户定义类型被各种内置和数学函数支持。

    <!-- rumdl-disable MD013 -->

    | 函数                                          | Trait                                             | 所需方法       |
    |------------------------------------------------|----------------------------------------------------|-----------------|
    | [`abs()`](/docs/std/math/math/abs/)            | [`Absable`](/docs/std/math/math/Absable/)          | `__abs__()`     |
    | [`pow()`](/docs/std/math/math/pow/)            | [`Powable`](/docs/std/math/math/Powable/)          | `__pow__()`     |
    | [`round()`](/docs/std/math/math/round/)        | [`Roundable`](/docs/std/math/math/Roundable/)      | `__round__()`   |
    | [`math.ceil`](/docs/std/math/math/ceil/)       | `math.Ceilable`                                    | `__ceil__()`    |
    | [`math.ceildiv`](/docs/std/math/math/ceildiv/) | `math.CeilDivable` <br/> `math.CeilDivableRaising` | `__ceildiv__()` |
    | [`math.floor`](/docs/std/math/math/floor/)     | `math.Floorable`                                   | `__floor__()`   |
    | [`math.trunc`](/docs/std/math/math/trunc/)     | `Truncable`                                        | `__trunc__()`   |

    {/* rumdl-enable MD013 */}

    注意:

    - 遵循 `Powable` trait 也意味着该类型可与幂操作符(`**`)一起使用。

    - 对于 `ceildiv()`,struct 可以遵循 `CeilDivable` trait 或 `CeilDivableRaising` trait。

    - 由于正在进行的重构,trait `Ceilable`、`CeilDivable`、`Floorable` 和 `Truncable` 不会出现在 API 参考中。它们应从 `math` 模块导入,但 `Truncable` 例外,它(暂时)作为内置 trait 可用,无需导入。

    示例:

    ```mojo
    from math import sqrt

    @value
    struct Complex2(Absable, Roundable):
        var re: Float64
        var im: Float64

        fn __abs__(self) -> Self:
            return Self(sqrt(self.re * self.re + self.im * self.im), 0.0)

        fn __round__(self) -> Self:
            return Self(round(self.re, 0), round(self.im, 0))

        fn __round__(self, ndigits: Int) -> Self:
            return Self(round(self.re, ndigits), round(self.im, ndigits))

    ```

- 基准测试:

  - 作为 `benchmark` 包一部分的 [`bencher`](/docs/std/benchmark/bencher/) 模块现已公开并有文档。该模块提供了诸如 `Bencher` 等类型,可以执行一个 `Benchmark`,并允许通过 `BenchmarkConfig` struct 进行基准测试配置。

- [`String`](/docs/std/collections/string/string/) 及相关类型:

  - **破坏性变更。** 内置类/类型对 `String` 的隐式转换现已移除。请显式使用 `str()` 转换为 `String`。

  - 新增 [`String.isspace()`](/docs/std/collections/string/string/String/#isspace) 方法,与 Python 的通用分隔符一致。这取代了 `string` 模块中的 `isspace()` 自由函数。(如果你需要旧函数,它暂时以 `_isspace()` 形式可用。它现在接受一个 `UInt8`,但其他方面不变。)

  - [`String.split()`](/docs/std/collections/string/string/String/#split) 现在默认按空白字符分割,并具有 Python 风格的行为,默认会移除所有相邻的空白字符。

  - [`String.strip()`](/docs/std/collections/string/string/String/#strip)、[`lstrip()`](/docs/std/collections/string/string/String/#lstrip) 和 [`rstrip()`](/docs/std/collections/string/string/String/#rstrip) 现在可以移除空白字符之外的自定义字符。此外,现在有若干关于空白字符、ASCII 小写/大写等的实用别名。
    ([PR #2555](https://github.com/modular/modular/pull/2555))

  - `String` 现在拥有 [`splitlines()`](/docs/std/collections/string/string/String/#splitlines) 方法,允许在行边界处分割字符串。此方法支持[通用换行符](https://docs.python.org/3/glossary.html#term-universal-newlines),并提供保留或移除换行字符的选项。([PR
    #2810](https://github.com/modular/modular/pull/2810))

  - `InlinedString` 已重命名为 `InlineString`,以与其他类型保持一致。

  - [`StringRef`](/docs/std/collections/string/string_slice/StringSlice/) 现在实现了 [`strip()`](/docs/std/collections/string/string_slice/StringSlice/#strip),可用于移除首尾空白字符。([PR
    #2683](https://github.com/modular/modular/pull/2683))

  - `StringRef` 现在实现了 [`startswith()`](/docs/std/collections/string/string_slice/StringSlice/#startswith) 和 [`endswith()`](/docs/std/collections/string/string_slice/StringSlice/#endswith)。([PR #2710](https://github.com/modular/modular/pull/2710))

  - 新增 [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 类型,以取代标准库代码中对不安全 `StringRef` 类型的使用。

    `StringSlice` 是对编码字符串数据的非拥有引用。与 `StringRef` 不同,`StringSlice` 安全地绑定到它所指向的数据的生命周期。

    - 为 `String` 和 `StringLiteral` 添加了新的 [`as_string_slice()`](/docs/std/collections/string/string/String/#as_string_slice) 方法。
    - 添加了从 `UnsafePointer` 和以字节为单位的长度构造 `StringSlice` 的初始化器。

  - 为 `String` 和 `StringLiteral` 添加了新的 [`as_bytes_slice()`](/docs/std/collections/string/string/String/#as_bytes_slice) 方法,返回由该字符串拥有的字节的 `Span`。

  - 继续向 [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 和无符号字节类型过渡字符串:
    - `String._as_ptr()` 已重命名为 [`String.unsafe_ptr()`](/docs/std/collections/string/string/String/#unsafe_ptr),返回类型更改为 `UnsafePointer`(原为 `DTypePointer`)。
    - `StringLiteral.data()` 已重命名为 [`StringLiteral.unsafe_ptr()`](/docs/std/builtin/string_literal/StringLiteral/#unsafe_ptr),返回类型更改为 `UnsafePointer`(原为 `DTypePointer`)。
    - `InlineString.as_ptr()` 已重命名为 `unsafe_ptr()`,现在返回 `UnsafePointer[UInt8]`(原为 `DTypePointer[DType.int8]`)。
    - `StringRef.data` 现在是 `UnsafePointer`(原为 `DTypePointer`),[`StringRef.unsafe_ptr()`](/docs/std/collections/string/string_slice/StringSlice/#unsafe_ptr) 现在返回 `UnsafePointer[UInt8]`(原为 `DTypePointer[DType.int8]`)。

- 其他内置项:

  - `Slice.__len__()` 函数已被移除,且 [`Slice`](/docs/std/builtin/builtin_slice/Slice/) 不再遵循 `Sized` trait。这澄清了语义上的歧义:slice 的长度总是取决于被切片对象的长度。需要现有功能的用户可以使用 [`Slice.unsafe_indices()`](/docs/std/builtin/builtin_slice/Slice/#indices) 方法。这使得该实现不检查 slice 边界是否具体或在任何给定对象长度之内这一事实变得显式。

  - 新增内置 [`sort()`](/docs/std/builtin/sort/sort/) 函数,用于遵循 `ComparableCollectionElement` trait 的元素列表。([PR #2609](https://github.com/modular/modular/pull/2609))

  - `int()` 现在可以接受一个字符串和指定的基数来从字符串解析整数:`int("ff", 16)` 返回 `255`。此外,如果指定基数为零,字符串将被解析为整数字面量,基数由字符串是否包含前缀 `"0x"`、`"0o"` 或 `"0b"` 决定。
    ([PR #2273](https://github.com/modular/modular/pull/2273),
    修复了 [#2274](https://github.com/modular/modular/issues/2274))

  - 新增 [`bin()`](/docs/std/builtin/format_int/bin/) 内置函数,将整数类型转换为其二进制字符串表示。
    ([PR #2603](https://github.com/modular/modular/pull/2603))

  - 新增 `atof()` 内置函数,可将 `String` 转换为 `float64`。([PR
    #2649](https://github.com/modular/modular/pull/2649))

  - 你现在可以使用内置 [`any()`](/docs/std/builtin/bool/any/) 和 [`all()`](/docs/std/builtin/bool/all/) 函数检查集合中的真值元素。由于 `SIMD.__bool__()` 现在被约束为 `size=1`,你必须显式使用这些函数来获取多于一个元素的 SIMD 向量的真值。这避免了围绕 `SIMD` 到 `Bool` 隐式转换的常见错误。
    ([PR #2600](https://github.com/modular/modular/pull/2600))

    例如:

    ```mojo
      fn truthy_simd():
          var vec = SIMD[DType.int32, 4](0, 1, 2, 3)
          if any(vec):
              print("any elements are truthy")
          if all(vec):
              print("all elements are truthy")
    ```

  - `object` 现在实现了所有位操作符。
    ([PR #2324](https://github.com/modular/modular/pull/2324))

  - [`Tuple`](/docs/std/builtin/tuple/Tuple/) 现在支持 `__contains__()`。
    ([PR #2709](https://github.com/modular/modular/pull/2709)) 例如:

    ```mojo
    var x = Tuple(1, 2, True)
    if 1 in x:
        print("x contains 1")
    ```

  - `ListLiteral` 和 `Tuple` 现在只要求元素类型为 `Movable`。因此,`ListLiteral` 和 `Tuple` 本身不再 `Copyable`。

  - 新增 `ImmutableStaticLifetime` 和 `MutableStaticLifetime` 辅助类型。

- [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 及其他:

  - 为 `UnsafePointer[Scalar[_]]` 指针新增 [`memcpy()`](/docs/std/memory/memory/memcpy/) 重载。

  - 从 `UnsafePointer` 和其他指针类型中移除了 `get_null()` 方法。请改用默认构造器:`UnsafePointer[T]()`。

  - 许多返回指针类型的函数已统一为拥有 `unsafe_ptr()` 的公共 API 函数。

  - `Tensor.data()` 方法已重命名为 `unsafe_ptr()`。返回类型仍为 `DTypePointer[T]`。

- 集合:

  - [`List`](/docs/std/collections/list/List/) 现在拥有 [`index()`](/docs/std/collections/list/List/#index) 方法,允许你查找 `EqualityComparable` 类型的 `List` 中元素的(第一个)位置。例如:

    ```mojo
    var my_list = List[Int](2, 3, 5, 7, 3)
    print(my_list.index(3))  # prints 1
    ```

  - `List` 现在可以使用简化语法转换为 `String`:

    ```mojo
    var my_list = List[Int](2, 3)
    print(my_list.__str__())  # prints [2, 3]
    ```

    请注意,`List` 尚未遵循 `Stringable` trait,因此你尚不能使用 `str(my_list)`。
      ([PR #2673](https://github.com/modular/modular/pull/2673))

  - `List` 拥有调用 [`count()`](/docs/std/collections/list/List/#count) 方法的简化语法:`my_list.count(x)`。
    ([PR #2675](https://github.com/modular/modular/pull/2675))

  - `List()` 现在支持 `__contains__()`,因此你现在可以将列表与 `in` 操作符一起使用:

    ```mojo
    if x in my_list:
    ```

    ([PR #2667](https://github.com/modular/modular/pull/2667))

  - `List` 现在拥有 [`unsafe_get()`](/docs/std/collections/list/List/#unsafe_get),用于获取元素的引用,不带边界检查或负索引回绕。请注意此方法不安全。请谨慎使用。
    [PR #2800](https://github.com/modular/modular/pull/2800)

  - 为 `Dict` 新增 [`fromkeys()`](/docs/std/collections/dict/Dict/#fromkeys) 方法,返回具有指定键和值的 `Dict`。

  - `Dict` 现在拥有通过 `my_dict.__str__()` 到 `String` 的简化转换。请注意,`Dict` 不遵循 `Stringable` trait,因此 `str(my_dict)` 尚不可行。

- [`SIMD`](/docs/std/builtin/simd/SIMD/) 类型:

  - 新增带 `IndexList` 掩码的 [`SIMD.shuffle()`](/docs/std/builtin/simd/SIMD/#shuffle)。
    ([PR #2315](https://github.com/modular/modular/pull/2315))

  - [`SIMD.__bool__()`](/docs/std/builtin/simd/SIMD/#__bool__) 受约束,仅在 `size` 为 `1` 时工作。对于多于一个元素的 SIMD 向量,请使用 [`any()`](/docs/std/builtin/bool/any/) 或 [`all()`](/docs/std/builtin/bool/all/)。
    ([PR #2502](https://github.com/modular/modular/pull/2502))

  - [`SIMD.reduce_or()`](/docs/std/builtin/simd/SIMD/#reduce_or) 和 [`SIMD.reduce_and()`](/docs/std/builtin/simd/SIMD/#reduce_and) 方法现在是位运算,并支持整数类型。
    ([PR #2671](https://github.com/modular/modular/pull/2671))

  - 新增 [`SIMD.__repr__()`](/docs/std/builtin/simd/SIMD/#__repr__) 以获取 `SIMD` 类型的详细字符串表示。
    ([PR #2728](https://github.com/modular/modular/pull/2728))

- [`math`](/docs/std/math/math/) 包:

  - `math.bit` 模块已移至新的顶层 [`bit`](/docs/std/bit/bit/) 模块。该模块中的以下函数已重命名:
    - `ctlz` -> `countl_zero`
    - `cttz` -> `countr_zero`
    - `bit_length` -> `bit_width`
    - `ctpop` -> `pop_count`
    - `bswap` -> `byte_swap`
    - `bitreverse` -> `bit_reverse`

  - `math.rotate_bits_left()` 和 `math.rotate_bits_right()` 函数已移至 `bit` 模块。

  - `math` 模块中的 `is_power_of_2()` 函数现在称为 `is_power_of_two()` 并位于 `bit` 模块中。

  - `abs()`、`round()`、`min()`、`max()`、`pow()` 和 `divmod()` 函数已从 `math` 移至 `builtin`,因此你不再需要导入这些函数。

  - `math.tgamma()` 函数已重命名为 [`math.gamma()`](/docs/std/math/math/gamma/),以符合 Python 的命名。

  - 以下函数的实现已从 `math` 模块移至新的 [`utils.numerics`](/docs/std/utils/numerics/) 模块:`isfinite()`、`isinf()`、`isnan()`、`nan()`、`nextafter()` 和 `ulp()`。这些函数仍会在 `math` 模块中暴露。

  - [`math.gcd()`](/docs/std/math/math/gcd/) 现在可处理负数输入,并且与 Python 的实现一样,接受可变整数列表。还添加了针对整数 `List` 或 `Span` 的新重载。
    ([PR #2777](https://github.com/modular/modular/pull/2777))

- 异步和协程:

  - [`Coroutine`](/docs/std/builtin/coroutine/Coroutine/) 现在需要一个 lifetime 参数。该参数在调用 async 函数时由解析器自动设置。它包含所有实参的 lifetime 以及实参的任何 lifetime 访问。这确保了 async 函数对实参的捕获在协程存活期间保持实参存活。

  - 不再允许 async 函数调用借用非平凡的可寄存器传递类型。由于 async 函数捕获其实参,但可寄存器传递类型(暂时)没有 lifetime,Mojo 无法正确跟踪引用,使这不安全。为弥补这一安全漏洞,Mojo 暂时禁止在 async 函数中将非平凡的可寄存器传递类型绑定到 borrowed 参数。

- 杂项:

  - 新增 [`InlineArray`](/docs/std/collections/inline_array/InlineArray/) 类型,可处理仅内存类型。与现有的 [`StaticTuple`](/docs/std/utils/static_tuple/StaticTuple/) 类型对比,后者在概念上是一种数组类型,但仅适用于 `__TypeOfAllTypes`。([PR
    #2294](https://github.com/modular/modular/pull/2294))

  - [`base64`](/docs/std/base64/) 包现在包括对 Base64 和 Base16 编码方案的编码和解码支持。
    ([PR #2364](https://github.com/modular/modular/pull/2364))
    ([PR #2584](https://github.com/modular/modular/pull/2584))

  - [`Variant`](/docs/std/utils/variant/Variant/) 和 [`Optional`](/docs/std/collections/optional/Optional/) 中的 `take()` 函数已重命名为 `unsafe_take()`。

  - `Variant` 中的 `get()` 函数已被 `__getitem__()` 取代。即 `v.get[T]()` 应被替换为 `v[T]`。

  - `algorithm` 模块中的若干函数现在是内置函数。这包括 `sort()`、`swap()` 和 `partition()`。当我们重新设计内置 `sort()` 函数并对其进行优化时,`swap()` 和 `partition()` 可能会进行调整。

- `infinity` 和 `NaN` 现在在 [`testing.assert_almost_equal()`](/docs/std/testing/testing/assert_almost_equal/) 中得到正确处理,并且 `utils/numerics.mojo` 中添加了一个 `inf` 函数。
  ([PR #2375](https://github.com/modular/modular/pull/2375))

## Tooling changes

- 在命令行上调用 `mojo package my-package -o my-dir`,其中 `my-package` 是 Mojo 包源目录,`my-dir` 是现有目录,现在将 Mojo 包输出到 `my-dir/my-package.mojopkg`。以前,这必须完整写出,如 `-o my-dir/my-package.mojopkg`。

- Mojo Language Server 现在会在局部变量未使用时报告警告。

- 几个 `mojo` 子命令现在支持 `--diagnostic-format` 选项,用于更改错误、警告和其他诊断信息的打印格式。通过在命令行上指定 `--diagnostic-format json`,错误和其他诊断信息将以结构化的 [JSON Lines](https://jsonlines.org) 格式输出,便于机器解析。

  支持 `--diagnostic-format` 的子命令完整列表如下:`mojo build`、`mojo doc`、`mojo run`、`mojo package` 和 `mojo test`。此外,`mojo test --json` 选项已被纳入此新选项;要获得相同行为,请运行 `mojo test --diagnostic-format json`。

  请注意,JSON 输出的格式可能会变化;我们目前不保证它在 Mojo 各版本间稳定。

- 新增 `--validate-doc-strings` 选项到 `mojo`,以对无效文档字符串发出错误而非警告。

- `mojo` 的 `--warn-missing-doc-strings` 标志已重命名为 `--diagnose-missing-doc-strings`。

- 新增装饰器 `@doc_private`,可用于将声明从 `mojo doc` 的输出中隐藏。它还移除了声明必须具有文档的要求(例如,与 `--diagnose-missing-doc-strings` 一起使用时)。

- 调试器用户现在即使在编译器内联了调用的情况下,也可以在 O0 构建中对函数调用设置断点。

- Mojo Language Server 现在支持重命名局部变量。

## Other changes

### Removed

- `@unroll` 装饰器已被弃用并移除。该装饰器本应保证被装饰的循环会被展开,否则编译器会报错。在实践中,随着时间推移,这一保证被削弱,因为基于编译器的方法无法像 Mojo 参数系统那样稳健。此外,`@unroll` 装饰器不会使循环归纳变量成为参数值,限制了其实用性。请使用 `@parameter for` 作为替代!

- `object.print()` 方法已被移除。由于 `object` 现在遵循 `Stringable` trait,你可以使用 `print(my_object)` 代替。

- 以下函数已从 math 模块中移除:
  - `clamp()`;请使用新的 `SIMD.clamp()` 方法。
  - `round_half_down()` 和 `round_half_up()`;这些可以使用 `ceil()` 和 `floor()` 函数轻松实现。
  - `add()`、`sub()`、`mul()`、`div()`、`mod()`、`greater()`、`greater_equal()`、`less()`、`less_equal()`、`equal()`、`not_equal()`、`logical_and()`、`logical_xor()` 和 `logical_not()`;相反,用户应直接依赖相应的操作符(`+`、`-`、`*`、`/`、`%`、`>`、`>=`、`<`、`<=`、`==`、`!=`、`&`、`^` 和 `~`)。
  - `identity()` 和 `reciprocal()`;用户可以轻松实现这些。
  - `select()`;已移除,改为直接使用 `SIMD.select()`。
  - `is_even()` 和 `is_odd()`;这些可以通过与 `1` 的位运算 `&` 轻松实现。
  - `roundeven()`;新的 `SIMD.roundeven()` 方法现在提供相同功能。
  - `div_ceil()`;请使用新的 `ceildiv()` 函数。
  - `rotate_left()` 和 `rotate_right()`;相同功能在 `SIMD` 类型的内置 `SIMD.rotate_{left,right}()` 方法中可用,在 `Int` 类型中则位于 `bit.rotate_bits_{left,right})()` 方法中。
  - 接受整数参数指数的 `math.pow()` 重载。
  - `align_down_residual()`;它可以使用 `align_down()` 轻松实现。
  - `all_true()`、`any_true()` 和 `none_true()`;请直接使用 `SIMD.reduce_and()` 和 `SIMD.reduce_or()`。
  - `reduce_bit_count()`;请直接使用新的 `SIMD.reduce_bit_count()`。
  - `rint()` 和 `nearbyint()`;视情况使用 `round()` 或 `SIMD.roundeven()`。

- `EvaluationMethod` 已从 `math.polynomial` 中移除,Estrin 方法不再可用。该方法被限制在 10 次或以下,使用不足,且性能不明确。未来,如果需要,当有更好的性能基准测试基础设施时,可能会以改进的实现重新引入。`math.polynomial.polynomial_evaluate()` 的默认行为不变(Horner 方法)。

- `math.bit.select()` 和 `math.bit.bit_and()` 函数已被移除。相同功能分别在内置 `SIMD.select` 和 `SIMD.__and__()` 方法中可用。

- `math.limit` 模块已被移除。相同功能可用如下:
  - `math.limit.inf()`:使用 `utils.numerics.max_or_inf()`
  - `math.limit.neginf()`:使用 `utils.numerics.min_or_neg_inf()`
  - `math.limit.max_finite()`:使用 `utils.numerics.max_finite()`
  - `math.limit.min_finite()`:使用 `utils.numerics.min_finite()`

- `tensor.random` 模块已被移除。相同功能现在可通过 `Tensor.rand()` 和 `Tensor.randn()` 静态方法访问。

- 内置 `SIMD` struct 不再遵循 `Indexer`;用户必须使用 `int` 显式转换 `Scalar` 值。

- [#1837](https://github.com/modular/modular/issues/1837) 修复了自引用 variant 使编译器崩溃的问题。
- [#2363](https://github.com/modular/modular/issues/2363) 修复了 LSP 在简单 trait 定义上崩溃的问题。
- [#1787](https://github.com/modular/modular/issues/1787) 修复了在别名表达式中对 `FloatLiteral` 使用 `//` 时的错误。
