title: Mojo v25.5
date: 2025-08-05

## 要点 {#25-5-highlights}

- Mojo 现在以 `mojo` Conda 包的形式独立可用。它包括
  Mojo 编译器、标准库和 `layout` 包（在 GPU 编程中
  被广泛使用）。它还包括 Mojo 开发者工具：
  LSP、调试器、格式化工具等。

  要在 v25.5 中使用 Python 到 Mojo 的互操作性，你必须安装
  `modular` 包。这将在未来的版本中移至 `mojo` 包。

  更多详情请参阅[安装指南](/install/)。

- 现已支持参数化别名：别名可以用
  可选参数列表指定（就像函数一样）。参数化别名
  也被视为第一类参数值。更多详情请参阅
  Mojo 手册中的
  [参数化别名](/docs/manual/parameters/#parametric-aliases)。

- Mojo API 文档现在会为参数、参数和
  返回值类型生成交叉引用。

## 语言增强 {#25-5-language-enhancements}

- `@parameter for` 现在适用于更广泛的集合类型，使
  诸如 `@parameter for i in [1, 2, 3]: ...` 之类的事情成为可能。

- `StringLiteral` 现在会在运行时使用时自动实体化为 `String`：

  ```mojo
  alias param = "foo"        # type = StringLiteral
  var runtime_value = "bar"  # type = String
  var runtime_value2 = param # type = String
  ```

  这使用户无需转换
  或标注类型即可获得所有他们期望的行为，例如：

  ```mojo
  var string = "hello"
  string += " world"

  var if_result = "foo" if True else "bar"
  ```

  从 `StringLiteral` 初始化的 `String` 最初指向静态
  常量内存，并且在首次变更之前不执行任何分配。

- 编译器现在会检测将编译时
  解释器栈内存的引用实体化到运行时代码的尝试。这包括相关的引用
  内存的类型，如切片、span 和指针。

  编译器目前无法在实体化到运行时时跟踪内部栈对象的
  生命周期，这可能导致内存泄漏。考虑此
  示例：

  ```mojo
  fn test_comptime_materialize():
    # This is ok! Forms a comptime pointer to a comptime "stack" value of
    # String type.
    alias comptime_ptr = String("foo" + "bar").unsafe_ptr()
    # This is ok too, dereferences the pointer at comptime, loading the byte.
    alias byte = comptime_ptr[]
    # This materializes a Byte from comptime to runtime.
    var rt_byte = byte
    # Error: cannot materialize to runtime value, the type contains an origin
    # referring to a compile-time value
    var bad_usage = comptime_ptr
  ```

  此前编译器会实体化 `String` 值的内存表示，但
  不知道它需要被销毁。现在它能检测到此
  问题。如果你遇到此问题，请重构代码以将完整对象
  （例如 String）显式实体化到运行时：

  ```mojo
  alias comptime_string = String("foo" + "bar")
  var runtime_string = comptime_string
  ```

## 语言变更 {#25-5-language-changes}

- `@value` 装饰器已正式弃用并发出警告，它将
  在下一个 Mojo 版本中被移除。请迁移到
  [`@fieldwise_init`](/docs/reference/decorators/fieldwise-init/)
  和合成的 `Copyable` 和 `Movable` trait 一致性。

- 隐式 trait 一致性已被移除。所有一致性必须显式
  声明。

- `owned` 参数约定正被重命名为 `var`。这反映了
  `var` 已经被一致地用于 "命名、有作用域、拥有的值"，
  这正是 `owned` 约定所做的。在此版本中，
  `var` 和 `owned` 都允许在参数列表中使用，但 `owned` 将在
  后续版本中被移除，因此请迁移你的代码。

- 现在完全支持函数重载，只要在具有相同参数类型列表的两个函数
  签名中，至少一个签名在某个位置是
  仅关键字参数，并且该位置的参数名不同。此前当
  返回类型不同时，一个边角情况阻止了此支持。例如，这两个函数现在可以共存：

  ```mojo
  fn get(self, idx: Int) -> Int
  fn get(self, *, idx2: Int) -> Float32
  ```

## 标准库变更 {#25-5-standard-library-changes}

- 对 [`String`](/docs/std/collections/string/string/String/) 进行索引现在
  返回
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)，
  避免了一次分配。`String.split()` 现在返回 `List[StringSlice]`。

- 添加了对更广泛消费级 AMD 硬件的支持，包括：

  - AMD Radeon RX 7xxx GPU
  - AMD Radeon RX 9xxx GPU

- 现已通过以下函数提供对 AMD RDNA3+ GPU 的编译时检查
  （可从 `sys.info` 导入）：

  - `_is_amd_rdna3()`
  - `_is_amd_rdna4()`
  - `_is_amd_rdna()`

- 为 RDNA3+ GPU 添加了 WMMA 矩阵乘法指令，以帮助支持
  在这些 GPU 上运行 AI 模型。

- 添加了对 NVIDIA GeForce RTX 3090 的支持。

- [`memory.UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 现已
  隐式包含在所有 mojo 文件中。此外，
  [`OpaquePointer`](/docs/std/memory/unsafe_pointer/#opaquepointer)（相当于
  C 中的 `void*`）已移至 `memory` 模块，并也已
  隐式包含。

- Python 互操作变更：

  - Mojo 方法现在可以接受 `py_self: UnsafePointer[Self]` 而不是原始的
    `py_self: PythonObject`，消除了常见情况下所需的
    向下转换样板代码。

  - Mojo 函数现在可以原生接受
    来自 Python 的关键字参数，使用 `OwnedKwargsDict[PythonObject]` 作为
    最后一个参数。这使直接从 Python 使用关键字
    参数调用成为可能，无需包装函数。

    ```mojo
    from collections import OwnedKwargsDict

    # Callable from Python as `foo(10, y=20)`
    fn foo(x: PythonObject, kwargs: OwnedKwargsDict[PythonObject]):
        y = kwargs["y"]
    ```

  - [`PythonTypeBuilder`](/docs/std/python/bindings/PythonTypeBuilder/)
    工具现在允许：
    - 为 Python 静态方法注册绑定，即不需要
      类实例的方法。
    - 注册接受参数的初始化方法。类型不再需要是
      `Defaultable` 才能从 Python 公开和创建。

  - `PythonConvertible` trait 已重命名为
    [`ConvertibleToPython`](/docs/std/python/conversions/ConvertibleToPython/)。
    这现在与
    [`ConvertibleFromPython`](/docs/std/python/conversions/ConvertibleFromPython/)
    trait 一致，建模可以转换为或从
    `PythonObject` 转换的 Mojo 类型。

  更多信息请参阅 Mojo 手册中的
  [从 Python 调用 Mojo](/docs/manual/python/mojo-from-python/)。

- 添加了 [`Iterator`](/docs/std/iter/Iterator/) trait，用于建模
  生成值序列的类型。

  类型可以通过提供 `__next__()` 和 `__has_next__()`
  方法来实现 `Iterator`。此命名和行为基于
  Python
  [`Iterator`](https://docs.python.org/3/library/collections.abc.html#collections.abc.Iterator)
  类型标注，由于 Mojo 当前的约束而略有不同。

  任何实现 `Iterator` 的类型都可在 `for` 和
  `@parameter for` 循环语法中使用。

  `Iterator` 目前没有用于支持遍历
  借用 `ref` 值的变体。

- [`Dict`](/docs/std/collections/dict/Dict/) 类型现在具有 `H`
  参数，允许用户提供自定义 `Hasher` 类型。

  - `default_hasher` (AHasher) 和 `default_comp_time_hasher` (Fnv1a)
    现已提供
  - `Dict` 的 `H` 参数默认为 `default_hasher`

- [`Hashable`](/docs/std/hashlib/hash/Hashable/) trait 已更新为
  使用新的数据流策略。

  - 现在要求用户实现方法
    `fn __hash__[H: Hasher](self, mut hasher: H):`
    （有关更多详情，请参阅 `Hashable` API 文档）。

- `InlineArray` 现在可以用大小 0 构造。这使得在
  元素数量是泛型的并且可能也是 0 的情况下更容易
  使用 `InlineArray`。

- `List.append(Span)` 已重命名为 `List.extend(Span)`。这
  对于可读性和一致性很重要，`append()` 总是使
  列表长度恰好增加 1。在 Python 和 Rust 中，`extend()` 都是
  接受任意长度数量的额外元素（可能为 0）以添加到列表的
  操作变体。

- 库中提供了新的 [`io`](/docs/std/io/) 模块。先前在 `builtin` 模块中的某些核心
  输入/输出 API 已移至 `io`。
  目前 `io` 模块中的所有 API 都是自动导入的。
  以下 API 已移至 `io`：

  - 与文件相关的 API，如 `open()`、`FileHandle` 和 `FileDescriptor`。
  - `Writer` 和 `Writable` trait。
  - `input()` 和 `print()` 函数。

- `StringLiteral.strip()` 系列函数现在返回 `StaticString`。

## 工具链变更 {#25-5-tooling-changes}

- 添加了对 GCC 风格调试标志 `-g0`、`-g1` 和 `-g2` 的支持，以匹配
  常见的编译器约定：

  - `-g0`：无调试信息（`--debug-level=none` 的别名）。
  - `-g1`：行表调试信息（`--debug-level=line-tables` 的别名）。
  - `-g2`：完整调试信息（`--debug-level=full` 的别名）。

- 为 Mojo 语言服务器添加了进度报告支持。当服务器正在解析
  文档时，它将在你的编辑器中发出
  进度通知。

## 已移除 {#25-5-removed}

- `sys.info` 包中的各种函数已移至
  [`sys.info.CompilationTarget`](/docs/std/sys/info/CompilationTarget/)
  结构体：

  - `is_x86()`
  - `has_sse4()`
  - `has_avx()`
  - `has_avx2()`
  - `has_avx512f()`
  - `has_fma()`
  - `has_vnni()`
  - `has_neon()`
  - `has_neon_int8_dotprod()`
  - `has_neon_int8_matmul()`

- `UnsafePointer.address_of()` 已被移除。请改为使用 `UnsafePointer(to=...)`
  构造函数。类似地，`Pointer.address_of()` 已被移除。

- `DType.tensor_float32` 已被移除，因为库和编译器中缺少对它的支持。
