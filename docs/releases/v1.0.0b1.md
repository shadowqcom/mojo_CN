## 亮点 {#1-0-0-b1-highlights}

- **`fn` 已弃用；请使用 `def`。** Mojo 现在对 `fn` 的使用发出编译器警告；这将在下一个版本中变成编译错误。这完成了始于 v0.26.2 的 def/fn 统一工作：`def` 现在是 Mojo 的标准函数声明关键字，具有与 `fn` 相同的非抛异常语义。参见[语言变更](#1-0-0-b1-language-changes)。

- **统一的闭包。** 本版本继续此前版本开始的闭包统一工作：无状态闭包会自动提升为顶层函数（并可作为 FFI 回调传递），支持 `ref` 捕获约定，默认捕获约定可与显式捕获列表组合，并新增 `thin` 函数效果，声明一个不携带捕获状态的纯函数指针类型。参见[语言增强](#1-0-0-b1-language-enhancements)。

- **`UnsafePointer` 设计上非空。** 默认的空构造器和 `__bool__()` 方法已被弃用，`UnsafePointer` 不再遵循 `Defaultable` 或 `Boolable`。请用 `Optional[UnsafePointer[...]]` 表达可空性，它共享 `UnsafePointer` 的布局（空地址是 `None` 的 niche），因此可空指针保持零开销且对 FFI 安全。参见[指针与内存](#1-0-0-b1-pointer-memory)。

- **默认边界检查的集合。** 已从所有标准库集合中移除负索引——`x[-1]` 现在是编译期错误；请改用 `x[len(x) - 1]`——并且 CPU 上所有集合默认开启边界检查。越界访问会报告用户的调用点。GPU 上为性能考虑默认仍关闭边界检查；使用 `mojo build -D ASSERT=all` 可启用。参见[集合与迭代器](#1-0-0-b1-collections)。

- **`NDBuffer` 已移除。** `NDBuffer` 已从标准库中完全移除。请迁移到 `TileTensor`。参见[集合与迭代器](#1-0-0-b1-collections)。

- **扩展的 GPU 硬件支持。** Apple Metal 成为更强大的 Mojo 目标——`print()` 可用，支持动态线程组内存（`external_memory[]()`），Apple M5 MMA 内在函数启用硬件矩阵乘累加，Apple GPU 目标默认优先选用 `metal4` 特性。新增对 AMD MI250X 和 NVIDIA B300（sm_103a）加速器的支持。参见 [GPU 编程](#1-0-0-b1-gpu)。

- **GPU 原语 id 访问器从 `UInt` 迁移到 `Int`。** `thread_idx`、`block_idx`、`block_dim`、`grid_dim`、`global_idx`、`lane_id`、`warp_id` 以及 cluster 访问器现在返回 `Int`，这是将大小和偏移统一标准化为 `Int` 的更广泛迁移的一部分。临时的 `*_uint` 别名提供迁移路径；它们最终将被弃用并移除。参见 [GPU 编程](#1-0-0-b1-gpu)。

- **CPU `DeviceContext` 扩展。** `DeviceContext(api="cpu")` 现在是 CPU 工作的流序执行上下文，为 NUMA 感知的 CPU 调度铺路。新增 `enqueue_cpu_function()` 和 `enqueue_cpu_range()` 可将主机函数和并行范围入队，与周围工作保持流序关系。参见 [GPU 编程](#1-0-0-b1-gpu)。

- **`String` 和 `StringSlice` 的字形簇支持。** 新增 UAX #29 字形簇分割，提供 `graphemes()`、`count_graphemes()`、`[grapheme=...]` 切片语法和反向迭代。正确处理组合标记、emoji ZWJ 序列、旗帜 emoji、Hangul 音节以及其他多码点簇。参见[字符串与文本](#1-0-0-b1-string)。

- **类型精化。** 编译器现在会根据 `where` 子句、`comptime if` 语句和 `comptime assert` 语句精化类型，由 `conforms_to()` 表达式驱动。这使 `trait_downcast` 在常见情况下不再必要——Mojo 能识别某类型在精化作用域内是否满足某 trait，并允许直接调用其 trait 方法。参见[语言增强](#1-0-0-b1-language-enhancements)。

- **统一的反射 API。** `std.reflection` 中新增 `reflect[T]()` 入口，返回一个 `Reflected[T]` 句柄，取代一组 `struct_field_*` 自由函数和 `get_type_name` / `get_base_type_name`。`reflect` 通过 prelude 自动 import。旧式自由函数和 `ReflectedType[T]` 包装器现在被标记为 `@deprecated`。参见[其他库变更](#1-0-0-b1-other-library)。

## 语言增强 {#1-0-0-b1-language-enhancements}

- 新增了基于编译期假设的类型精化，使 Mojo 能根据 `where` 子句、`comptime if` 语句和 `comptime assert` 语句精化类型。作用域内的精化由 `conforms_to()` 表达式驱动。

  之前：

  ```mojo
  def __contains__(self, value: Self.T) -> Bool where conforms_to(Self.T, Equatable):
      for item in self:
          if trait_downcast[Equatable](item) == trait_downcast[Equatable](value):
              return True
      return False
  ```

  之后：

  ```mojo
  def __contains__(self, value: Self.T) -> Bool where conforms_to(Self.T, Equatable):
      for item in self:
          if item == value:
              return True
      return False
  ```

- **统一闭包改进**。本版本继续此前版本开始的闭包统一工作：无状态闭包会自动提升，支持 `ref` 捕获约定，默认捕获约定可与显式捕获列表组合，并新增 `thin` 函数效果声明一个不携带捕获状态的纯函数指针类型。

  ```mojo
  def main() raises:
      var a, b, c, d = 1, 2, 3, 4
      var x = "hello"

      # Legacy closure: no capture list. Cannot capture variables.
      def hello():
          print("hi")

      # Unified closure with no captures (stateless). Stateless closures
      # lift to top-level functions and can be passed as FFI callbacks.
      def add_one(n: Int) {} -> Int:
          return n + 1

      # Unified closure with explicit captures and a default capturing
      # convention:
      def my_fn() {mut a, b, c^, read}:
          # capture:
          # `a` by mut reference
          # `b` by immut reference
          # `c` by moving
          # `d` by immut reference (the default `read` convention)
          use(a, b, c, d)

      # Unified closure that captures `x` by ref (carries an
      # origin-mutability parameter):
      def show_x() {ref x}:
          print(x)

      # Function effects come before the capture list. The calling context
      # must handle errors raised from a `raises` closure.
      def fallible() raises {}:
          raise Error("nope")

      # Closures are invoked like ordinary functions:
      hello()
      print(add_one(41))
      my_fn()
      show_x()
      try:
          fallible()
      except e:
          print(e)

      # The `thin` function effect declares a plain function pointer
      # type that doesn't carry captured state. Stateless closures and
      # top-level functions are compatible with `thin` function pointers:
      var fn_ptr: def(Int) thin -> Int = add_one
      print(fn_ptr(99))
  ```

- 新增 `abi("C")` 作为函数效果，用于在函数定义和函数指针类型上声明 C 调用约定。标记为 `abi("C")` 的函数对结构体参数和返回值使用平台 C ABI（System V x86-64 / ARM64 AAPCS），实现与 C 库的安全互操作。`DLHandle.get_function()` 现在强制要求类型参数携带 `abi("C")`，防止加载 C 符号时出现静默的 ABI 不匹配。

  ```mojo
  # C-ABI function definition (safe as a callback into C code)
  def add(a: Int32, b: Int32) abi("C") -> Int32:
      return a + b

  # C-ABI function pointer type (safe for use with DLHandle.get_function)
  var f = handle.get_function[def(Float64) abi("C") -> Float64]("sqrt")
  ```

- 新增了对条件 [`RegisterPassable`](/docs/std/builtin/value/RegisterPassable/) 遵循的支持。

- 三元 `if/else` 表达式现在在显而易见时将每个元素强制转换为其上下文类型。例如，下面这段可以正常工作，而不再产生不兼容元类型错误：

  ```mojo
  comptime some_type: Movable = Int if cond else String
  ```

- 当被调用方接受兼容的可变列表或 pack 时，可变列表和 pack 可通过 `*pack` 在运行时调用中转发。

  ```mojo
  def callee[*Ts: Writable](*args: *Ts):
      comptime for i in range(args.__len__()):
          print(args[i])

  def forwarder[*Ts: Writable](*args: *Ts):
      callee(*args)

  forwarder(1, "hello", 3.14)  # prints each value on a separate line
  ```

- 异构可变 pack 现在可通过 [`SomeTypeList`](/docs/std/builtin/anytype/SomeTypeList/) 辅助类型指定。以下两者等价：

  ```mojo
  def foo[*arg_types: Copyable](*args: *arg_types) -> Int: ...
  def foo(*args: *SomeTypeList[Copyable]) -> Int: ...
  ```

- 字符串字面量现在支持 `\uXXXX` 和 `\UXXXXXXXX` Unicode 转义序列，与 Python 一致。生成的码点以 UTF-8 存储。无效码点和代理项在解析时被拒绝。

- [T-string](/docs/std/format/tstring/TString/) 现在可用于 `comptime assert` 消息：

  ```mojo
  def foo[i: Int]():
      comptime assert i > 5, t"expected i > 5, got {i}"
  ```

## 语言变更 {#1-0-0-b1-language-changes}

- 函数声明的 `fn` 关键字已被弃用。Mojo 现在对 `fn` 的使用发出编译器警告；这将在下一个版本中变成编译错误。请改用 `def`。

- `unified` 关键字已被移除；请在函数签名后用显式捕获列表 `{...}` 指定统一闭包语义。空的捕获列表 `{}` 表示统一且无捕获；不带任何捕获列表的闭包是旧式闭包。Mojo 现在还会在函数指针类型省略 `thin` 效果时发出警告；显式指定 `thin` 可消除该警告。

- 形如 `from pkg import ...` 的 import 语句不再使 `pkg` 对模块可用。

- 移除了对长度或类型不同的元组进行比较的支持。此类比较（例如 `(1, 2) != (4, 5, 6)`）现在被类型系统静态拒绝，而不是静默返回不相等。

- 可变参数列表现在是 [`ParameterList`](/docs/std/builtin/variadics/ParameterList/) 和 [`TypeList`](/docs/std/builtin/variadics/TypeList/) 而非 `!kgen.param_list`，因此可以像普通类型一样使用：

  ```mojo
  def callee[*values: Int]():
      var v = 0
      for i in range(len(values)):
          v += values[i]
      for elt in values:
          v += elt
  ```

- 每个 Mojo 函数现在都有自己唯一的函数字面量类型。两个单独定义的函数，即使签名完全相同，也不能通过其字面量类型互换使用；请使用函数指针类型（例如 `def(Int) thin -> Int`）对它们进行抽象。

- `A if comptime(C) else B` 现在会跳过死分支的展开，将三元表达式视为类似 `comptime if C: A else: B` 的编译期求值约定。

- `@explicit_destroy` 与无条件的 `ImplicitlyDestructible` 遵循一起使用时现在在解析时被拒绝；它仅在带条件的（where 子句约束的）遵循中仍然有效。

## 库变更

### 类型系统与 trait {#1-0-0-b1-type-system}

- [`Boolable`](/docs/std/builtin/bool/Boolable/)、[`Defaultable`](/docs/std/builtin/value/Defaultable/) 和 [`Writable`](/docs/std/format/Writable/) trait 不再继承自 [`ImplicitlyDestructible`](/docs/std/builtin/anytype/ImplicitlyDestructible/)。需要析构器约束的泛型代码现在必须显式请求：`T: Writable & ImplicitlyDestructible`。

- 标准库类型现在使用条件遵循：
  - [`Span`](/docs/std/memory/span/Span/)：`Writable`、[`Hashable`](/docs/std/hashlib/hash/Hashable/)
  - [`Tuple`](/docs/std/builtin/tuple/Tuple/)、[`Optional`](/docs/std/collections/optional/Optional/)、[`Variant`](/docs/std/utils/variant/Variant/) 和 [`UnsafeMaybeUninit`](/docs/std/memory/unsafe_maybe_uninit/UnsafeMaybeUninit/)：`RegisterPassable`
  - `Tuple`：`Defaultable`（当所有元素类型都是 `Defaultable` 时）
  - `Variant`：[`Copyable`](/docs/std/builtin/value/Copyable/)、[`ImplicitlyCopyable`](/docs/std/builtin/value/ImplicitlyCopyable/)
  - `Optional`：[`DevicePassable`](/docs/std/builtin/device_passable/DevicePassable/)（以元素类型为条件）

- [`ArcPointer`](/docs/std/memory/arc_pointer/ArcPointer/) 现在在其内部类型遵循时才有条件地遵循 `Hashable` 和 [`Equatable`](/docs/std/builtin/comparable/Equatable/)，其中 `__eq__()` 和 `__hash__()` 委托给被管理值（与 C++ `shared_ptr` 和 Rust `Arc` 语义一致）。这使 `ArcPointer` 可用作 [`Dict`](/docs/std/collections/dict/Dict/) 键或 [`Set`](/docs/std/collections/set/Set/) 元素，采用基于值的相等性；指针身份仍可通过 `is` 运算符获得。

- [`Path`](/docs/std/pathlib/path/Path/) 现在遵循 [`Comparable`](/docs/std/builtin/comparable/Comparable/)，支持字典序排序以及与 `sort()` 一起使用。

### 原子操作 {#1-0-0-b1-atomic}

- 原子操作已移至专门的 [`std.atomic`](/docs/std/atomic/) 模块。`Consistency` 类型已重命名为 [`Ordering`](/docs/std/atomic/atomic/Ordering/)，其 `MONOTONIC` 成员重命名为 `RELAXED`，以与其他语言使用的约定对齐。按如下方式更新现有代码：

  ```mojo
  # Before
  from std.os import Atomic
  from std.os.atomic import Atomic, Consistency, fence

  _ = atom.load[ordering=Consistency.MONOTONIC]()

  # After
  from std.atomic import Atomic, Ordering, fence

  _ = atom.load[ordering=Ordering.RELAXED]()
  ```

- 调换了 [`Atomic.compare_exchange()`](/docs/std/atomic/atomic/Atomic/#compare_exchange) 的排序参数顺序，使 `success_ordering` 列在 `failure_ordering` 之前，与 C++、Rust 等语言使用的约定一致。

- `Ordering` 现在有一个默认构造器，在 Apple GPU 上选择 `RELEASE`，在所有其他目标上选择 `SEQUENTIAL`。所有 [`Atomic`](/docs/std/atomic/atomic/Atomic/) 方法和 [`fence()`](/docs/std/atomic/atomic/fence/) 都使用这个感知平台的默认值，而不是硬编码 `SEQUENTIAL`。

### 指针与内存 {#1-0-0-b1-pointer-memory}

- [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 现在设计上非空。默认的空构造器 `__init__(out self)` 和 `__bool__(self)` 方法已被弃用，`UnsafePointer` 不再遵循 `Defaultable` 或 `Boolable`。完整设计请参见 [non-null pointer proposal](https://github.com/modular/modular/blob/main/mojo/proposals/non-null-pointer.md)。

  要迁移，请用 `Optional[UnsafePointer[...]]` 表达可空性，它共享 `UnsafePointer` 的布局（空地址是 `None` 的 niche），因此可空指针保持零开销且对 FFI 安全。

  ```mojo
  # Before: null default construction
  var ptr = UnsafePointer[Int, origin]()

  # After: express absence with Optional
  var ptr: Optional[UnsafePointer[Int, origin]] = None

  # Before: Bool-based null check
  if ptr:
      use(ptr[])

  # After: check the Optional, then unwrap
  if ptr:
      use(ptr.value()[])
  ```

  对于稍后会被填充的字段的非空占位符（例如按需分配的缓冲区），请使用 `UnsafePointer.unsafe_dangling()`——一个对齐良好但悬垂的指针。它不是空哨兵；惰性初始化类型必须单独跟踪初始化状态。

- [`CStringSlice`](/docs/std/ffi/cstring/CStringSlice/) 不再能表示空指针。要表示可空性，请使用 `Optional[CStringSlice]`，它保证具有与 `const char*` 相同的大小和布局（`NULL` 对应空的 `Optional`）。

- [`OwnedDLHandle.get_symbol()`](/docs/std/ffi/OwnedDLHandle/#get_symbol) 现在返回 `Optional[UnsafePointer[...]]` 而不是在找不到符号时中止，使调用方能优雅地处理缺失的符号。

- [`alloc[T](count, alignment)`](/docs/std/memory/unsafe_pointer/alloc/) 现在在底层分配失败时中止。

- 新增 [`std.memory.forget_deinit()`](/docs/std/memory/memory/forget_deinit/)，使低层代码能跳过为某个值运行析构器。请谨慎使用，仅在构建低层抽象时使用。

### 集合与迭代器 {#1-0-0-b1-collections}

- `NDBuffer` 已完全移除。请迁移到 [`TileTensor`](/docs/layout/tile_tensor/TileTensor/)。

- 已从所有标准库集合（[`List`](/docs/std/collections/list/List/)、`Span`、[`InlineArray`](/docs/std/collections/inline_array/InlineArray/)、[`String`](/docs/std/collections/string/string/String/)、[`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)、[`LinkedList`](/docs/std/collections/linked_list/LinkedList/)、[`Deque`](/docs/std/collections/deque/Deque/)、[`IntTuple`](/docs/layout/int_tuple/IntTuple/)）中移除负索引，以便在 CPU 上默认进行低开销的边界检查。使用负的 [`IntLiteral`](/docs/std/builtin/int_literal/IntLiteral/) 进行索引现在会触发编译期错误：

  ```text
  constraint failed: negative indexing is not supported, use e.g. `x[len(x) - 1]` instead
  ```

  请将所有 `x[-1]` 更新为 `x[len(x) - 1]`。

- 边界检查现在在 CPU 上对所有集合默认开启。越界访问会报告用户的调用点：

  ```mojo
  def main():
      var x = [1, 2, 3]
      print(x[3])
  ```

  ```text
  At: /tmp/main.mojo:3:12: Assert Error: index 3 is out of bounds, valid range is 0 to 2
  ```

  GPU 上为性能考虑边界检查默认仍关闭。使用 `mojo build -D ASSERT=all` 可在 GPU 上启用边界检查；使用 `-D ASSERT=none` 可禁用包括 CPU 边界检查在内的所有断言。

- 接受不同类型参数或接受 [`Intable`](/docs/std/builtin/int/Intable/)/[`IntableRaising`](/docs/std/builtin/int/IntableRaising/) 但不是 [`Indexer`](/docs/std/builtin/int/Indexer/) 参数的 [`range()`](/docs/std/builtin/range/range/) 重载已被移除。调用方应传递一致的整型参数类型。

- 在迭代模块中新增 [`IterableOwned`](/docs/std/iter/IterableOwned/) trait。遵循 `IterableOwned` 的类型实现 `__iter__(var self)`，它消费集合并返回一个拥有底层元素所有权的迭代器。`List`、`Optional`、`Deque`、`LinkedList`、`Dict`、`Set`、[`Counter`](/docs/std/collections/counter/Counter/) 和 `InlineArray` 现已遵循；`Span` 在 `T: Copyable` 时有条件地遵循，owned 迭代器按值 yield 拷贝。

  迭代器适配器（[`enumerate()`](/docs/std/iter/enumerate/)、[`zip()`](/docs/std/iter/zip/)、[`map()`](/docs/std/iter/map/)、[`peekable()`](/docs/std/iter/peekable/)、[`take_while()`](/docs/std/itertools/itertools/take_while/)、[`drop_while()`](/docs/std/itertools/itertools/drop_while/)、[`product()`](/docs/std/itertools/itertools/product/)、[`cycle()`](/docs/std/itertools/itertools/cycle/)、[`count()`](/docs/std/itertools/itertools/count/)、[`repeat()`](/docs/std/itertools/itertools/repeat/)）现在都遵循 `IterableOwned`。新增了消费输入可迭代对象的 `enumerate()`、`zip()`、`map()`、`peekable()`、`take_while()`、`drop_while()`、`product()` 和 `cycle()` 的 owned 重载。

- 为 `Optional` 新增 `map()` 和 `and_then()` 方法。[`map()`](/docs/std/collections/optional/Optional/#map) 对包含的值应用一个函数（返回 `Optional[To]`）；[`and_then()`](/docs/std/collections/optional/Optional/#and_then) 对本身返回 `Optional` 的操作进行 flat-map。

  ```mojo
  var o = Optional[Int](42)

  def closure(n: Int) {} -> String:
      return String(n + 1)

  var mapped: Optional[String] = o.map[To=String](closure)
  print(mapped) # Optional("43")
  ```

- 新增 [`Optional.destroy_with(destroy_func)`](/docs/std/collections/optional/Optional/#destroy_with)，使用调用方提供的析构器就地销毁 `Optional[T]`。这使 `Optional` 能持有非 `ImplicitlyDestructible` 的元素类型（例如标记为 [`@explicit_destroy`](/docs/reference/decorators/explicit-destroy/) 的类型），与 [`Variant.destroy_with()`](/docs/std/utils/variant/Variant/#destroy_with) 对应。两个 `destroy_with()` 方法现在除接受纯函数引用外，还接受捕获局部状态的闭包。`Variant.destroy_with()` 的调用方现在必须显式传入被销毁的类型（例如 `v^.destroy_with[Int](destroy_func)`），因为 `T` 无法再从闭包类型推断。

- 为 `Span` 新增了通用的 `__contains__()` 方法，适用于任何遵循 `Equatable` 的元素类型，而不仅仅是 [`Scalar`](/docs/std/builtin/simd/Scalar/) 类型。

- [`assert_raises()`](/docs/std/testing/testing/assert_raises/) 现在可捕获自定义 `Writable` 错误类型，而不仅仅是 [`Error`](/docs/std/builtin/error/Error/)。

### 字符串与文本 {#1-0-0-b1-string}

- `String.__len__()` 已弃用。请改用 [`String.byte_length()`](/docs/std/collections/string/string/String/#byte_length) 或 [`String.count_codepoints()`](/docs/std/collections/string/string/String/#count_codepoints)。

- **`String` 和 `StringSlice` 的字形簇支持**。新增 UAX #29 字形簇分割，正确处理组合标记、emoji ZWJ 序列、旗帜 emoji、Hangul 音节以及其他多码点簇。

  - `graphemes()` 返回一个 [`GraphemeSliceIter`](/docs/std/collections/string/iterators/GraphemeSliceIter/)，将每个用户感知的 "字符" 作为 `StringSlice` yield；`count_graphemes()` 返回字形簇计数。
  - `StringSlice` 通过 `grapheme=` 关键字参数支持按字形簇切片，与现有的 `byte=` 索引器对应（例如 `s[grapheme=0:3]`）。由于字形边界是通过正向扫描发现的，这在字节长度上是 O(n)——当已知字节偏移时请优先使用 `byte=`。
  - 字形感知算法 `grapheme_indices()`、`nth_grapheme(n)` 和 `split_at_grapheme(n)` 与 Rust 的 `str::grapheme_indices` 等对应，对编辑器和 UI 将光标字节位置映射到字形边界很有用。
  - `GraphemeSliceIter` 通过 `next_back()`、`peek_back()` 以及 `String` / `StringSlice` 上的 `graphemes_reversed()` 构造器支持反向迭代。由于 UAX #29 状态机是正向扫描的，反向迭代每个簇的成本比正向迭代更高。
  - `GraphemeSliceIter.remaining_byte_length()` 以 O(1) 报告迭代器的剩余字节范围。
  - `count_graphemes()` 在可打印 ASCII 序列上采用快速路径：纯 ASCII 文本约快 10 倍，以 ASCII 为主的混合文本约快 5-6 倍。纯非 ASCII 文本（阿拉伯语、俄语、中文）不变。

### 诊断与调试 {#1-0-0-b1-diagnostics}

- [`abort(message)`](/docs/std/os/os/abort/) 现在在其输出中包含调用点位置。你也可以传入显式的 [`SourceLocation`](/docs/std/reflection/location/SourceLocation/) 来覆盖它：

  ```mojo
  abort("something went wrong")
  # prints: ABORT: path/to/file.mojo:42:5: something went wrong

  var loc = current_location()
  abort("something went wrong", location=loc)
  ```

- `abort(message)` 现在会在 NVIDIA 和 AMD GPU 上打印其消息，包括块和线程 ID。此前，消息在这些 GPU 上被静默抑制。在 Apple GPU 上，目前消息仍被静默抑制。

- 新的诊断会报告用户的调用点而非标准库源码：[`check_bounds()`](/docs/std/collections/check_bounds/check_bounds/) 用于集合在越界索引时断言，[`debug_assert()`](/docs/std/builtin/debug_assert/debug_assert/) 现在接受一个 `call_location` 参数，供调用方覆盖所报告的 `SourceLocation`。

- `SourceLocation` 字段现在为私有；请改用 `line()`、`column()` 和 `file_name()` 访问器方法。

- 新增了对浮点加载的未初始化内存读取检测。当用 `-D MOJO_STDLIB_SIMD_UNINIT_CHECK=true` 编译时，每次浮点加载都会与调试分配器的毒化模式（浮点类型的最大有限值，例如 `Float32` 的 `FLT_MAX`）进行比对；匹配则触发 `abort()`。该毒化值非 NaN，因此可以与 `nan-check` 共存于仅写活跃位置的内核中。禁用时（默认）零运行时开销。

- `InlineArray` 的存储构造器现在使用 `debug_assert[assert_mode="safe"]` 进行元素计数检查，因此大小不匹配默认即可捕获，而不仅是在 `-D ASSERT=all` 下。

### GPU 编程 {#1-0-0-b1-gpu}

- 新增对 AMD MI250X 加速器的支持。

- **扩展的 Apple 硅 GPU 支持**。Apple Metal GPU 现在是更强大的 Mojo 目标。

  - [`print()`](/docs/std/io/io/print/) 和 `_printf()` 现在可在 Apple Metal GPU 上工作。输出通过 Metal 的 `os_log` 路径分块传输，仅支持 Float32 的格式化器以符合 Metal 的硬件限制。`_printf()` 目前仅输出格式字符串（不含插值参数）；`|x| < 1e-7` 被截断为 `0.0`。
  - [`external_memory[]()`](/docs/std/gpu/memory/memory/external_memory/)（动态线程组内存）现在在 Apple 硅上受支持，因此使用 `external_memory[]()` 的现有 GPU 内核无需更改即可工作。
  - [`std.gpu.compute.arch.mma_apple`](/docs/std/gpu/compute/arch/mma_apple/) 中的 Apple M5 MMA 内在函数（`apple_mma_load()`、`apple_mma_store()`、`_mma_apple()`）在 Apple GPU 上启用硬件矩阵乘累加。
  - 在 [`std.sys`](/docs/std/sys/) 中新增 [`CompilationTarget.is_apple_m5()`](/docs/std/sys/info/CompilationTarget/#is_apple_m5)，用于在编译期检测 Apple M5 目标；[`is_apple_silicon()`](/docs/std/sys/info/CompilationTarget/#is_apple_silicon) 现在在其检查中包含 M5。
  - 当工具链支持时，Apple GPU 目标现在默认优先选用 `metal4` 特性，自动将 `-metal4` 附加到 arch，而不再需要显式选择 `m5-metal4`。
  - **原子排序**：Metal 不支持 `release` 排序。Apple GPU 目标现在默认使用 `monotonic`（relaxed）原子排序。
  - **浮点宽度**：编译器现在对 Apple GPU 目标拒绝宽于 32 位的浮点类型（`Float64`/`Float80`/`Float128`），因为 Metal 仅支持 `Float16` 和 `Float32`。

- **GPU 设备 API**：

  - 新增对 NVIDIA B300（sm_103a）加速器的支持。[`std.sys.info`](/docs/std/sys/info/) 和 [`std.gpu.host.info`](/docs/std/gpu/host/info/) 中的新辅助函数识别 B300 目标，以便在 Blackwell B300 上正确进行内核调度。
  - 新增 [`DeviceStream.enqueue_host_func(func, user_data)`](/docs/std/gpu/host/device_context/DeviceStream/#enqueue_host_func)，为 Mojo 内核和自定义算子暴露 `cuLaunchHostFunc` 原语。接受一个 `thin def(OpaquePointer[MutAnyOrigin]) -> None` 回调和一个不透明的 `user_data` 指针。目前仅支持 CUDA；非 CUDA 后端会抛异常。
  - [`DeviceContext`](/docs/std/gpu/host/device_context/DeviceContext/) 初始化现在会运行自动 GPU 健康检查，检测硬件降频、不可纠正的 ECC 错误和僵尸 VRAM，并在 GPU 不健康时以可操作的错误消息使设备创建失败。新增 [`DeviceContext.run_healthcheck()`](/docs/std/gpu/host/device_context/DeviceContext/#run_healthcheck) 以显式重新调用该检查。设置 `MODULAR_DEVICE_CONTEXT_DISABLE_HEALTHCHECK=true` 可禁用。
  - 优化了 GPU [`elementwise()`](/docs/std/algorithm/functional/elementwise/) 索引计算和分发，采用 `use_32bit` 快速路径、4 倍展开的 grid-stride 处理、warp 对齐的块大小，以及 SM100+ 单 tile 路由。

- GPU 原语 id 访问器（[`thread_idx`](/docs/std/gpu/primitives/id/thread_idx/)、[`block_idx`](/docs/std/gpu/primitives/id/block_idx/)、[`block_dim`](/docs/std/gpu/primitives/id/block_dim/)、[`grid_dim`](/docs/std/gpu/primitives/id/grid_dim/)、[`global_idx`](/docs/std/gpu/primitives/id/global_idx/)、[`lane_id`](/docs/std/gpu/primitives/id/lane_id/)、[`warp_id`](/docs/std/gpu/primitives/id/warp_id/)、[`cluster_dim`](/docs/std/gpu/primitives/id/cluster_dim/)、[`cluster_idx`](/docs/std/gpu/primitives/id/cluster_idx/) 和 [`block_id_in_cluster`](/docs/std/gpu/primitives/id/block_id_in_cluster/)）已从 `UInt` 迁移到 `Int`。

  这是将 Mojo 中所有大小和偏移统一标准化为 `Int` 类型的更广泛迁移的一部分。作为同一迁移的相关步骤，[`TensorCore.load_a()`](/docs/layout/tensor_core/TensorCore/#load_a) 和 [`TensorCore.load_b()`](/docs/layout/tensor_core/TensorCore/#load_b) 现在也接受 `Int` 参数而非 `UInt`。

  为提供渐进的迁移路径，七个非 cluster 访问器临时提供了 `*_uint` 别名：

  | 访问器         | 旧式 `UInt` 别名    |
  |----------------|----------------------|
  | `thread_idx`   | `thread_idx_uint`    |
  | `block_idx`    | `block_idx_uint`     |
  | `block_dim`    | `block_dim_uint`     |
  | `grid_dim`     | `grid_dim_uint`      |
  | `global_idx`   | `global_idx_uint`    |
  | `lane_id`      | `lane_id_uint`       |
  | `warp_id`      | `warp_id_uint`       |

  三个 cluster 访问器（`cluster_dim`、`cluster_idx`、`block_id_in_cluster`）直接迁移，没有 `*_uint` 别名，因为其使用范围有限。

  代码可通过使用 `*_uint` 别名的重命名 import 来保留其先前的 `UInt` 行为：

  ```diff
  - from std.gpu import thread_idx
  + from std.gpu import thread_idx_uint as thread_idx
  ```

  分阶段迁移期间短暂存在的临时 `*_int` 访问器（作为前向兼容辅助）已被移除；请使用未加前缀的访问器（现在默认返回 `Int`）。`*_uint` 别名最终将被弃用并移除。

  - [`parallelize()`](/docs/std/algorithm/backend/cpu/parallelize/parallelize/)、[`parallelize_over_rows()`](/docs/std/algorithm/backend/cpu/parallelize/parallelize_over_rows/)（在 [`std.algorithm.backend.cpu.parallelize`](/docs/std/algorithm/backend/cpu/parallelize/) 中）以及 [`std.algorithm.functional`](/docs/std/algorithm/functional/) 中的 `elementwise()` 重载现在接受一个可选的尾随 `ctx: Optional[DeviceContext] = None`。当提供时，上下文会转发给 `sync_parallelize()`；否则行为不变。

  - `GenericToSharedAsyncTileCopier` 上的 `masked: Bool = False` 参数。启用时，越界向量接收零字节拷贝并进行零填充，与 [`LayoutTensor.copy_from_async[is_masked=True, fill=Fill.ZERO]`](/docs/layout/layout_tensor/LayoutTensor/#copy_from_async) 一致。
  - [`AsyncTileCopier`](/docs/layout/tile_io/AsyncTileCopier/) trait，抽象拷贝器遵循。

- **用于稀疏 2D 张量加载的 TMA `gather4`**。在 SM100（Blackwell）上新增 TMA `gather4` 操作，可在单条 TMA 指令中从 2D 张量加载 4 个非连续行，作为 [`cp_async_bulk_tensor_2d_gather4()`](/docs/std/gpu/memory/memory/cp_async_bulk_tensor_2d_gather4/) 内在函数暴露在 [`std.gpu.memory`](/docs/std/gpu/memory/) 中，并与 [`TMATensorTile`](/docs/layout/tma_async/TMATensorTile/) 集成。该 API 支持：

- 为 `DeviceContext`、[`DeviceBuffer`](/docs/std/gpu/host/device_context/DeviceBuffer/) 和 [`HostBuffer`](/docs/std/gpu/host/device_context/HostBuffer/) 上的 [`enqueue_copy()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_copy)、[`enqueue_copy_from()`](/docs/std/gpu/host/device_context/DeviceBuffer/#enqueue_copy_from) 和 [`enqueue_copy_to()`](/docs/std/gpu/host/device_context/DeviceBuffer/#enqueue_copy_to) 新增基于 `Span` 的重载，为主机-设备内存传输提供比裸 `UnsafePointer` 更安全的替代方案。

### 其他库变更 {#1-0-0-b1-other-library}

- 从整个标准库中移除了 `trait_downcast()` 和 `trait_downcast_var()`，由类型精化取代（参见[语言增强](#1-0-0-b1-language-enhancements)）。公共 API 不变。

- [`external_call()`](/docs/std/ffi/external_call/) 的 `return_type` 要求已从 [`TrivialRegisterPassable`](/docs/std/builtin/value/TrivialRegisterPassable/) 放宽为 `RegisterPassable`。

- 多个标准库 API 新增了统一闭包重载：`parallelize()` 和 `parallelize_over_rows()`（在 `std.algorithm.backend.cpu.parallelize` 中）、[`bench.bencher()`](/docs/std/benchmark/bencher/Bencher/)、[`DeviceContext.execution_time()`](/docs/std/gpu/host/device_context/DeviceContext/#execution_time) 和 [`DeviceContext.enqueue_function()`](/docs/std/gpu/host/device_context/DeviceContext/#enqueue_function)（GPU 入队路径，从先前的 `enqueue_closure()` 重命名而来）。

- 在 [`std.reflection`](/docs/std/reflection/) 中将反射 API 整合到一个统一入口 [`reflect[T]()`](/docs/std/reflection/reflect/reflect/) 之后，返回一个 [`Reflected[T]`](/docs/std/reflection/reflect/Reflected/) 句柄。`reflect()` 通过 prelude 自动 import。句柄上的方法取代了 `struct_field_*` 自由函数家族（去掉 `struct_` 前缀——只有结构体才有字段）和 `get_type_name()` / `get_base_type_name()` 自由函数：

  ```mojo
  struct Point:
      var x: Int
      var y: Float64

  def main():
      comptime r = reflect[Point]()
      print(r.name())                          # "Point"
      print(r.field_count())                   # 2
      print(r.field_names()[0])                # x
      comptime y_type = r.field_type["y"]()    # Reflected[Float64]
      print(y_type.name())                     # "SIMD[DType.float64, 1]"
      print(reflect[List[Int]]().base_name())  # "List"
      var v: y_type.T = 3.14
  ```

  旧式自由函数和 [`ReflectedType[T]`](/docs/std/reflection/struct_fields/ReflectedType/) 包装器现在被标记为 [`@deprecated`](/docs/reference/decorators/deprecated/)；它们将在未来版本中移除。

- [`align_down()`](/docs/std/math/math/align_down/) 和 [`align_up()`](/docs/std/math/math/align_up/) 现在接受通用的 `SIMD[dtype, width]` 整数值，取代先前仅 `UInt` 的重载。

- 扩展 [`FastDiv`](/docs/std/utils/fast_div/FastDiv/) 和 [`mulhi()`](/docs/std/gpu/intrinsics/mulhi/) 以支持 64 位整数类型。

- 新增 `Variadic.contains_value` comptime 别名，用于在编译期检查可变序列是否包含某个特定值。

## 工具链变更 {#1-0-0-b1-tooling-changes}

- 移除了旧式 `MOJO_ENABLE_STACK_TRACE_ON_ERROR` 和 `MOJO_ENABLE_STACK_TRACE_ON_CRASH` 环境变量。改为将 `MODULAR_DEBUG` 环境变量设置为 `stack_trace_on_error`，以在 Mojo 程序抛出错误时启用栈跟踪生成。

- **调试器 UX**：

  - Mojo 调试器现在在 LLDB 中显示 `Variant` 变量的活跃类型名称和值（例如 `Int(42)` 或 `String("hello")`），而不是暴露原始的 `_DefaultVariantStorage` 内部结构。
  - Mojo 调试器现在在 LLDB 中将 `Optional[T]` 变量显示为 `None` 或 `Some(value)`，而不是暴露原始的 `_DefaultVariantStorage` 内部结构。
  - Mojo 调试器现在将标量类型（例如 `UInt8`、`Float32`）显示为纯值而非 `([0] = value)`，并从结构体显示中省略内部的 `_mlir_value` 包装字段。
  - Mojo 调试器现在在 LLDB 中对所有指向类型正确显示 `UnsafePointer[T]` 值，包括有符号整数（不再渲染为巨大的无符号值）、`Bool`（`True`/`False`）和浮点数。
  - Mojo 调试器现在在 LLDB 中将 `StringSlice`、`StaticString` 及其底层 `Span[Byte]` 值显示为带引号的字符串。
  - 在 `-O0` 下，可平凡析构的类型（`Int`、`Float`、`Bool`、`SIMD` 等）现在在调试器中保持可见直到其词法作用域结束，而不是在 ASAP 析构点消失。

- **LSP 与 REPL 响应性**：

  - REPL/笔记本上下文中的代码补全和签名帮助现在通过跨请求缓存已解析的先前单元格，达到每个请求摊销 O(1)，消除了长会话中二次 O(N²) 的变慢。
  - LSP 解析时间通过延迟导入字节码声明的函数体解析、惰性解析具名 import 而减少，避免了对大型传递依赖的急切拉取。带 docstring 代码块的文件解析速度约快 2 倍。
  - 为 `mojo-lsp-server` 新增 `--mojo-version` 标志，用于验证 LSP 正在使用的 Mojo 版本。

- **`mojo` CLI 与工具链**：

  - `mojo --version` 现在打印语义化的 Mojo 版本（例如 `1.0.0...`）而非内部构建标识符，且编译器进行版本检查时也使用相同的版本。
  - `mojo build --print-supported-targets` 现在按字母顺序排列已注册目标，并带有优雅的空列表消息。
  - 当使用 `--target-triple` 不带 `--target-cpu` 交叉编译且主机和目标架构不同时，编译器现在选择目标的基线 CPU。
  - macOS 上经 ASAN 插桩的 Mojo 二进制文件现在使用 `llvm-symbolizer` 而非 `atos`，因此栈跟踪会报告通过用户函数的完整内联调用链。
  - Mojo 包文件（`.mojopkg`）现在使用格式版本 2 和 zstd 压缩的 MLIR 字节码，显著减小了包、wheel 和 Docker 镜像的大小。

- **`mojo doc` 与 docstring 校验**：

  - `mojo doc` 现在在 API 文档 JSON 的 `"type"` 字段中保留参数化类型名（例如 `List[K]`、`Optional[V]`、`UnsafePointer[Scalar[dtype]]`），而不是仅输出裸基名。
  - 当公共 Mojo 模块没有模块级 docstring 且 `-mojo-diagnose-missing-doc-strings` 处于激活状态时，`mojo doc` 现在会发出诊断。私有模块和嵌套在私有包中的模块不受此限制。
  - docstring 校验不再要求推断参数（参数列表中 `//` 之前的那些）必须被文档化；对它们进行文档化仍然有效。
  - docstring 校验现在通篇接受 `!` 和 `?` 作为有效的句子结尾标点。
  - `def ... raises` 函数现在像其他任何会抛异常的函数一样需要 `Raises:` docstring 段落。已从 `mojo doc` JSON 输出中移除 `isDef` 字段。

- **`mojo format`（`mblack`）**：

  - 不再支持已弃用的 `fn` 关键字或已移除的 `owned` 参数约定。
  - 现在能正确解析新的统一闭包语法，包括 `raises {captures}` 效果顺序，且不再在 `var^` 捕获中的 `^` 和操作数之间插入多余空格。

- comptime 函数调用现在在错误消息和生成的文档中打印更美观，省略 `VariadicList`/`VariadicPack` 并在需要时包含关键字参数标签。

## 已移除 {#1-0-0-b1-removed}

- `escaping` 函数效果不再受支持。请将 `def(...) escaping -> T` 闭包迁移为使用显式捕获列表 `{...}`（参见[语言增强](#1-0-0-b1-language-enhancements)）。

- 在 26.2 中弃用的若干构造不再被接受：

  - `@register_passable` 和 `@register_passable("trivial")` 装饰器不再受支持。请改为遵循 `RegisterPassable` 和 `TrivialRegisterPassable` trait。使用其中任何一个装饰器现在都会产生一个指向等价 trait 的硬错误。
  - 旧式 `__moveinit__()` 和 `__copyinit__()` 方法名不再被自动重写为统一的 `__init__()` 形式。请将这些方法重命名为 `__init__()`，分别使用仅关键字参数 `take: Self` 和 `copy: Self`，正如 26.2 中 [init 统一](/docs/releases/v0.26.2#0-26-2-init-unification)所引入的那样。现有旧式写法现在会编译失败并报诸如 `no matching function in initialization` 的错误，而不会被静默重写。

- 已弃用的 `@doc_private` 装饰器已被移除。请改用 [`@doc_hidden`](/docs/reference/decorators/doc-hidden/)。

- 从 `std.gpu.intrinsics` 中移除了 `store_release()`、`store_relaxed()`、`load_acquire()` 和 `load_relaxed()` 辅助函数。请改用带有所需 [`Ordering`](/docs/std/atomic/atomic/Ordering/) 的 [`Atomic[dtype, scope=...].store()`](/docs/std/atomic/atomic/Atomic/#store) 和 [`Atomic[dtype, scope=...].load()`](/docs/std/atomic/atomic/Atomic/#load)：

  ```mojo
  # Before
  from std.gpu.intrinsics import store_release, load_acquire
  store_release[scope=Scope.GPU](ptr, value)
  var v = load_acquire[scope=Scope.GPU](ptr)

  # After
  from std.atomic import Atomic, Ordering
  Atomic[dtype, scope="device"].store[ordering=Ordering.RELEASE](ptr, value)
  var v = Atomic[dtype, scope="device"].load[ordering=Ordering.ACQUIRE](ptr)
  ```

- API 移除：

  - 移除了 `param_env.mojo` 模块。请改用 [`defines.mojo`](/docs/std/sys/defines/)。
  - 移除了 `LinkedList.__getitem__()`。对 `LinkedList` 索引是 O(n) 的，暴露 `__getitem__()` 会鼓励意外的二次复杂度代码；请改为迭代列表。
  - 移除了未使用的 `UIntSized` trait 及其在 prelude 中的重导出。
  - 从 `elementwise()`、`reduction()` 和 `reducescatter()` 内核 API 中移除了 `pdl_level` 参数。PDL 用法现在是内部的编译期默认值。

## 已修复 {#1-0-0-b1-fixed}

- 修复了 NVIDIA GPU 上 `Float64` 的 [`math.sqrt()`](/docs/std/math/math/sqrt/) 在 LLVM IR 转换时产生神秘的 `could not find LLVM intrinsic: "llvm.nvvm.sqrt.approx.d"` 失败。`math.sqrt()` 现在在编译期拒绝 NVIDIA GPU 上的 `Float64`，并给出消息 `DType.float64 isn't supported for approx sqrt on NVIDIA GPU`。[`math.sin()`](/docs/std/math/math/sin/) 和 [`math.cos()`](/docs/std/math/math/cos/) 的约束消息也类似地进行了细化以指明该运算。
  ([Issue #6434](https://github.com/modular/modular/issues/6434))

- 修复了将列表、字典、集合或切片字面量传递给 `*Ts` 约束的可变 pack 参数（例如 `def foo[*Ts: Iterable](*args: *Ts)`）时 pack 推断失败的问题，错误为 `could not infer type of parameter pack ... given value with unresolved type`。pack 推断现在应用单参数 trait 约束参数已使用的相同默认类型回退，因此 `foo([1, 2, 3], [4, 5, 6])` 会在绑定 pack 之前将每个字面量解析为其默认类型（例如 `List[Int]`）。

- 修复了当 `$HOME` 不可被运行 UID 遍历时（常见于镜像构建时 UID 与运行时 UID 不同的容器化 CI 中），`mojo` 在启动时以 `std::filesystem::filesystem_error` 中止的问题。配置搜索现在将权限错误视为 "未找到" 并继续尝试下一个候选。
  ([Issue #6412](https://github.com/modular/modular/issues/6412))

- `mojo run` 和 `mojo debug` 现在通过将引用的共享库加载到进程内 JIT 来遵循 `-Xlinker` 标志。此前这些标志被丢弃（带有 `-Xlinker argument unused` 警告），使通过 `external_call()` 调用外部共享库的程序在运行时无法解析这些符号。支持的 `-Xlinker` 形式与系统链接器接受的镜像；对 JIT 无意义的标志会被报告为警告并被忽略。
  ([Issue #6155](https://github.com/modular/modular/issues/6155))

- 修复了 Python 3.14 free-threaded 构建的 `libpython` 自动发现失败。发现脚本构造库文件名时未带 ABI 标志后缀（例如查找 `libpython3.14.dylib` 而非 `libpython3.14t.dylib`）。
  ([Issue #6366](https://github.com/modular/modular/issues/6366))

- 修复了 Linux 上 `RTLD.LOCAL` 值错误的问题。它被设置为 `4`（`RTLD_NOLOAD`）而非 `0`，导致带 `RTLD.NOW | RTLD.LOCAL` 的 `dlopen()` 失败。
  ([Issue #6410](https://github.com/modular/modular/issues/6410))

- 修复了因过期的语法缓存导致 Mojo 版本升级后 `mojo format` 崩溃的问题。
  ([Issue #6144](https://github.com/modular/modular/issues/6144))

- 修复了 [`atof()`](/docs/std/collections/string/string/atof/) 对接近正常/次正规边界的浮点数产生不正确结果的问题（例如 `Float64("4.4501363245856945e-308")` 返回了正确值的一半）。
  ([Issue #6196](https://github.com/modular/modular/issues/6196))

- 修复了在带 MLIR 类型字段的结构体（例如 `__mlir_type.index`）上使用默认 `Writable`、`Equatable` 或 `Hashable` 实现时的编译器崩溃（"'get_type_name' requires a concrete type"）。编译器现在会正确报告该字段未实现所需 trait。
  ([Issue #5872](https://github.com/modular/modular/issues/5872))

- 修复了 [`Atomic.store()`](/docs/std/atomic/atomic/Atomic/#store) 静默丢弃请求的 `scope` 的问题。先前的实现 lowering 为 `atomicrmw xchg` 而未转发 `syncscope`，因此 `Atomic[..., scope="device"].store(...)` 在 NVPTX 上发出的是系统作用域存储（额外的 L2/NVLink 栅栏），在 AMDGPU 上是过度同步的存储。`Atomic.store()` 现在通过 `pop.store atomic syncscope(...)` lowering，在 NVPTX 上发出 `st.release.<scope>`，在 AMDGPU 上发出正确作用域的 LLVM 原子存储。Mojo API 表面不变。

- 修复了 [`Process.run()`](/docs/std/os/process/Process/#run) 不继承父进程环境变量的问题。通过 `Process.run()` 生成的子进程现在能正确接收父进程的环境。

- 修复了字符串字面量中 `\xhh` 和 `\ooo` 转义序列被解释为原始字节而非 Unicode 码点的问题，这导致 `>= 0x80` 的值产生格式错误的 UTF-8。这些转义现在与 Python `str` 语义（以及现有的 `\u`/`\U` 处理）一致：`"\x85"` 将 U+0085（NEL）编码为两个 UTF-8 字节，`ord("\x85")` 返回 `133` 而非 `5`。依赖 `\xhh` 为非 ASCII 值发出单个原始字节的代码必须显式构造字节（例如通过 `List[Byte]` 字面量）。
  ([Issue #2842](https://github.com/modular/modular/issues/2842))

- 修复了 `MI250X` AMDGPU 架构的数据布局错误问题。
  ([Issue #6451](https://github.com/modular/modular/issues/6451))

- 修复了若干 Apple 目标问题：当安装的 Xcode 无法编译 Metal 4.0 时，macOS 26 目标检测不再产生诸如 `metal:2-metal4` 的未识别 arch 字符串（`-metal4` 后缀现在仅在工具链支持时才附加）；`UnsafePointer.gather()`、`UnsafePointer.scatter()` 和 `strided_load()` 不再在 Apple GPU 上静默读取零（每 lane 回退现在使用类型化指针算术；NVIDIA、AMD 和 CPU 路径不变）；`rotate_left()` 和 `rotate_right()` 内在函数现在能正确 lowering 到 Apple AIR 后端。

- 修复了若干 `TileTensor` 问题：`write_to()` 现在通过通用 elementwise 回退正确处理 1D、3D+、嵌套布局和动态形状张量（在所有秩下使用方括号分隔、逗号分隔的格式化）；`__getitem__()` 中的对齐错误已修复；`load()` 和 `store()` 中的默认对齐现在使用调用方指定的 `width` 参数而非 `Self.element_size`；CPU 上的 SIMD 加载/存储现在使用 `alignment=1` 以防止在自然不对齐数据上发生段错误（GPU 仍在布局保证对齐的地方使用对齐访问）。

- 修复了若干 [`tile_layout`](/docs/layout/tile_layout/) 问题：[`blocked_product()`](/docs/layout/tile_layout/blocked_product/) 现在按模式对块和 tiler 维度进行 zip（与旧式 `blocked_product()` 行为一致）；[`complement()`](/docs/layout/layout/complement/) 现在传播 `UNKNOWN_VALUE` 而非返回形状为 `0` 的静态形状，因此下游布局代数会回退到运行时维度，且 `LayoutTensor.flatten().vectorize[N]()` 的边界检查是正确的；[`idx2crd()`](/docs/layout/coord/idx2crd/) 现在对嵌套布局返回正确的坐标。

- 修复了 `mojo --version` 打印 MAX 版本而非 Mojo 编译器版本的问题。

- 修复了 `comptime` 的 `and`/`or` 表达式以接受任何 `Boolable` 操作数，与运行时行为一致。这也使像 `comptime if some_Bool and some_Optional` 这样的混合类型表达式可用。

- 修复了若干影响有效 Mojo 程序的代码生成正确性问题：一个 SRoA 误编译，错误地通过常量 GEP 将以动态偏移访问的数组提升；一个 use-after-free，即活跃 owned 值的析构器被插入到对带 `#lit.any.origin` 的 ref 的 `lit.ref.store` 之前而非之后；调用通过 `sret` 返回结构体的 `abi("C")` 函数时的静默内存损坏；以及用 `sret`/`byval` ABI 多次调用同一外部函数时出现的虚假 `existing function with conflicting attributes` 错误。

- 修复了若干影响 REPL/笔记本上下文、与参数包相关的诊断、从 `.mojopkg` 导入的文件以及使用无状态闭包的文件的 `mojo-lsp-server` 崩溃。LSP 也不再误将 REPL 缓冲区标识符（包含 `.mojo` 扩展名）当作相对模块 import。

- 修复了若干调试器显示问题：在 `-O0` 下 ASAP 析构点之后的变量现在正确显示 "not available" 而非陈旧值；无符号整数（`UInt`、`UInt8` 等）以正确的无符号语义显示；`ref` 循环变量显示 `index` 而非 `pointer<index>`；类型为 `Scalar[T]` 的 `String` 字段和 `Tuple` 值正确显示。

- 修复了两个 `mojo format`（`mblack`）问题：跨行拆分长 t-string 字面量时不再丢失 `t` 前缀；在可变 pack 解包注解中不再在 `*` 和复杂操作数之间插入多余空格。

- 修复了 [`BitSet.set_all()`](/docs/std/collections/bitset/BitSet/#set_all) 和 [`BitSet.toggle_all()`](/docs/std/collections/bitset/BitSet/#toggle_all) 向每个底层 64 位字写入 `~0` 的问题，包括当 `size` 不是 64 的倍数时超出逻辑 `size` 的位。那些多余的高位被 `__len__()` 计入，产生不正确的填充计数；这些方法现在会屏蔽掉未使用的高位。

- 修复了 AMD GPU 上的 [`syncwarp()`](/docs/std/gpu/sync/sync/syncwarp/)，此前它被实现为 no-op。它现在 lowering 为 `llvm.amdgcn.wave.barrier`，提供正确排序跨 lane 的共享内存写后读所需的控制流同步。

- 修复了 [`isnan()`](/docs/std/utils/numerics/isnan/)、[`isinf()`](/docs/std/utils/numerics/isinf/) 和 [`isfinite()`](/docs/std/utils/numerics/isfinite/) 在 LLVM lowering 期间对 `float8_e3m4` 和 `float4_e2m1fn` 失败的问题。`float4_e2m1fn`（无 NaN/Inf 编码）折叠为常量分支；`float8_e3m4` 通过 `bfloat16` 转换以复用现有 `llvm.is.fpclass` 路径。
