## 🔥 Legendary

- Mojo 现在已与 [MAX 平台](/max)捆绑发布！

  因此,Mojo 包的版本号现在与 MAX 版本号保持一致,后者遵循 `YY.MAJOR.MINOR` 版本方案。由于这是我们在 2024 年的首次发布,因此该版本号为 `24.1`。

- Mojo 调试支持现已上线!Mojo VS Code 扩展包含调试器支持。详情请参阅 Mojo 手册中的[调试](/docs/tools/debugging/)。

## ⭐️ New

- 我们现在在集合中拥有一个 [`Set`](/docs/std/collections/set/Set/) 类型!`Set` 由 `Dict` 支撑,因此它具有快速的添加、删除和 `in` 检查,并要求成员元素遵循 `KeyElement` trait。

  ```mojo
  from collections import Set

  var set = Set[Int](1, 2, 3)
  print(len(set))  # 3
  set.add(4)

  for element in set:
      print(element[])

  set -= Set[Int](3, 4, 5)
  print(set == Set[Int](1, 2))  # True
  print(set | Set[Int](0, 1) == Set[Int](0, 1, 2))  # True
  let element = set.pop()
  print(len(set))  # 1
  ```

- Mojo 现在支持将 `x in y` 表达式作为 `y.__contains__(x)` 的语法糖,同时也支持 `x not in y`。

- Mojo 现在支持仅关键字参数和参数(parameters)。例如:

  ```mojo
  fn my_product(a: Int, b: Int = 1, *, c: Int, d: Int = 2):
      print(a * b * c * d)

  my_product(3, c=5)     # prints '30'
  my_product(3, 5, d=7)  # error: missing 1 required keyword-only argument: 'c'
  ```

  这包括支持声明同时使用可变参数和仅关键字参数/参数的签名。例如,以下写法现在可行:

  ```mojo
  fn prod_with_offset(*args: Int, offset: Int = 0) -> Int:
      var res = 1
      for i in range(len(args)):
          res *= args[i]
      return res + offset

  print(prod_with_offset(2, 3, 4, 10))         # prints 240
  print(prod_with_offset(2, 3, 4, offset=10))  # prints 34
  ```

  请注意,目前尚不支持可变仅关键字参数/参数(例如 `**kwargs`)。也就是说,以下写法是不允许的:

  ```mojo
  fn variadic_kw_only(a: Int, **kwargs): ...
  ```

  更多信息,请参阅 Mojo 手册中的[仅位置参数和仅关键字参数](/docs/manual/functions/#positional-only-and-keyword-only-arguments)。

- `print()` 函数现在接受一个用于 `end` 的仅关键字参数,可用于控制打印元素后是否输出换行符。默认情况下,`end` 仍为 "\n"。

- Mojo SDK 现在可以安装在 AWS Graviton 实例上。

- 新版本的 Mojo Playground 已上线。新的 playground 是一个简单的 Mojo 代码交互式编辑器,类似于 Rust Playground 或 Go Playground。旧的基于 JupyterLab 的 playground 将保留在线直至 3 月 20 日。

- Mojo LSP 服务器现在会为填充空文档字符串生成 fixit:

  ```mojo
  fn foo(arg: Int):
      """""" # Unexpected empty documentation string
  ```

  应用上述 fixit 后会生成:

  ```mojo
  fn foo(arg: Int):
      """[summary].

      Args:
          arg: [description].
      """
  ```

- 新增 `*_` 语法,允许用户显式地解绑任意数量的位置参数。例如:

  ```mojo
  struct StructWithDefault[a: Int, b: Int, c: Int = 8, d: Int = 9]: pass

  alias all_unbound = StructWithDefault[*_]
  # equivalent to
  alias all_unbound = StructWithDefault[_, _, _, _]

  alias first_bound = StructWithDefault[5, *_]
  # equivalent to
  alias first_bound = StructWithDefault[5, _, _, _]

  alias last_bound = StructWithDefault[*_, 6]
  # equivalent to
  alias last_bound = StructWithDefault[_, _, _, 6]

  alias mid_unbound = StructWithDefault[3, *_, 4]
  # equivalent to
  alias mid_unbound = StructWithDefault[3, _, _, 4]
  ```

  如上所示,该语法可用于在操作数列表的开头、末尾或中间显式解绑任意数量的参数。由于这些未绑定参数最终必须被显式指定,因此这些参数的默认值不会被应用。例如:

  ```mojo
  alias last_bound = StructWithDefault[*_, 6]
  # When using last_bound, you must specify a, b, and c. last_bound
  # doesn't have a default value for `c`.
  var s = last_bound[1, 2, 3]()
  ```

  更多信息,请参阅 Mojo 手册中关于[部分绑定类型](/docs/manual/parameters/#fully-bound-partially-bound-and-unbound-types)和[函数的自动参数化](/docs/manual/parameters/#automatic-parameterization)的章节。

- [`DynamicVector`](/docs/std/collections/list/List/) 现在支持迭代。迭代值是 `Reference` 实例,需要解引用:

  ```mojo
  var v: DynamicVector[String]()
  v.append("Alice")
  v.append("Bob")
  v.append("Charlie")
  for x in v:
      x[] = str("Hello, ") + x[]
  for x in v:
      print(x[])
  ```

- `DynamicVector` 现在拥有 [`reverse()`](/docs/std/collections/list/List/#reverse) 和 [`extend()`](/docs/std/collections/list/List/#extend) 方法。

- `mojo package` 命令现在生成与编译选项无关的包。诸如 O0 或 --debug-level 之类的编译选项不再需要或被接受。因此,包现在更小且极具可移植性。

- `@register_passable` 值的初始化器现在可以(且应该!)像内存类型一样使用 `inout self` 参数来指定:

  ```mojo
  @register_passable
  struct YourPair:
      var a: Int
      var b: Int
      fn __init__(inout self):
          self.a = 42
          self.b = 17
      fn __copyinit__(inout self, existing: Self):
          self.a = existing.a
          self.b = existing.b
  ```

  这种形式使语言更加一致,更接近 Python,并且更容易实现高级特性。使用这种新形式也不会带来性能影响:编译器会自动安排将值通过寄存器返回,而无需你为此操心。

  旧版的 `-> Self` 语法在本版本中仍受支持,但将在后续版本中移除,因此请迁移你的代码。需要注意的一点是:某个 struct 应使用其中一种风格,混合使用两种风格效果不佳。

- 对于可能抛出错误的 `@register_passable` 类型,其初始化器**必须**使用 `inout self` 形式:

  ```mojo
  @register_passable
  struct RaisingCtor:
      fn __init__(inout self) raises:
          raise
  ```

- 可能抛出错误的 `async` 函数在此构建中已被暂时禁用。Mojo async 的实现正在进行重构 🚧。

- 标准库的 `slice` 类型已重命名为 [`Slice`](/docs/std/builtin/builtin_slice/Slice/),并引入了一个 `slice` 函数。这使 Mojo 更接近 Python,并使 `Slice` 类型遵循 `Int` 等其他类型的命名约定。

- 下标中的 "Slice" 语法不再硬编码为内置 `slice` 类型:它现在适用于容器 `__getitem__()` 方法接受的任何类型。例如:

  ```mojo
  @value
  struct UnusualSlice:
      var a: Int
      var b: Float64
      var c: String

  struct YourContainer:
      fn __getitem__(self, slice: UnusualSlice) -> T: ...
  ```

  基于该实现,你可以对 `YourContainer` 的实例进行下标操作,如 `yc[42:3.14:"🔥"]`,三个值会被传递给 `UnusualSlice` 构造器。

- `__refitem__()` 访问器方法现在可以返回 `Reference`,而不必返回 MLIR 内部引用类型。

- 新增 [`AnyPointer.move_into()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_move) 方法,用于将值从一个指针内存位置移动到另一个。

- 新增内置 [`hex()`](/docs/std/builtin/format_int/hex/) 函数,可用于将任何其类型实现了 [`Intable`](/docs/std/builtin/int/Intable/) trait 的值格式化为十六进制字符串。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 现在实现了 `__is__` 和 `__isnot__`,因此你可以在 `PythonObject` 上使用 `x is y` 和 `x is not y` 形式的表达式。

- [`PythonObject`](/docs/std/python/python_object/PythonObject/) 现在遵循 `SizedRaising` trait。这意味着内置 [`len()`](/docs/std/builtin/len/len/) 函数现在可在 `PythonObject` 上使用。

- `os` 包现在包含 [`stat()`](/docs/std/os/fstat/stat/) 和 [`lstat()`](/docs/std/os/fstat/lstat/) 函数。

- 一个新的 [`os.path`](/docs/std/os/path/path/) 包现在允许你查询路径上的属性。

- `os` 包现在拥有一个 [`PathLike`](/docs/std/os/pathlike/PathLike/) trait。一个 struct 通过实现 `__fspath__()` 函数来遵循 `PathLike` trait。

- [`pathlib.Path`](/docs/std/pathlib/path/Path/) 现在具有查询路径属性的函数。

- [`listdir()`](/docs/std/pathlib/path/Path/#listdir) 方法现在存在于 [`pathlib.Path`](/docs/std/pathlib/path/) 上,同时也存在于 `os` 模块中以处理 `PathLike` struct。例如,以下示例列出 `/tmp` 目录中的所有目录:

  ```mojo
  from pathlib import Path

  fn walktree(top: Path, inout files: DynamicVector[Path]):
      try:
          var ls = top.listdir()
          for i in range(len(ls)):
              var child = top / ls[i]
              if child.is_dir():
                  walktree(child, files)
              elif child.is_file():
                  files.append(child)
              else:
                  print("Skipping '" + str(child) + "'")
      except:
          return

  fn main():
      var files = DynamicVector[Path]()

      walktree(Path("/tmp"), files)

      for i in range(len(files)):
          print(files[i])
  ```

- [`find()`](/docs/std/builtin/string_literal/StringLiteral/#find)、[`rfind()`](/docs/std/builtin/string_literal/StringLiteral/#rfind)、[`count()`](/docs/std/collections/string/string_slice/StringSlice/#count) 和 `__contains__()` 方法现在可在字符串字面量上使用。这意味着你可以这样写:

  ```mojo
  if "Mojo" in "Hello Mojo":
      ...
  ```

- 现在可以使用内置 [`breakpoint()`](/docs/std/builtin/breakpoint/breakpoint/) 函数在代码中以编程方式插入断点。

  注意:在 Graviton 实例上,调试器在命中此类断点后可能无法恢复执行。

- 新增一个内置 [`Boolable`](/docs/std/builtin/bool/Boolable/) trait,描述可以表示为布尔值的类型。要遵循该 trait,类型必须实现 `__bool__()` 方法。

- 包中的模块现在可以使用纯相对的 `from` 导入:

  ```mojo
  from . import another_module
  ```

- 简单类型(如 MLIR 类型和函数类型)现在可以隐式绑定到需要拷贝构造器或移动构造器的 trait,例如 [`Movable`](/docs/std/builtin/value/Movable/)、[`Copyable`](/docs/std/builtin/value/Copyable/) 和 `CollectionElement`。

- 一个新的魔法 `__origin_of(expr)` 调用将产生一个内存值的生命周期。我们希望并期望随着参数系统的演进,它最终会被 `Reference(expr).lifetime` 取代,但在此期间它对函数签名中的使用非常重要。

- 一个新的魔法 `__type_of(expr)` 调用将产生一个值的类型。这允许引用其他变量的类型。例如:

  ```mojo
  fn my_function(x: Int, y: __type_of(x)) -> Int:
      let z: __type_of(x) = y
      return z
  ```

## 🦋 Changed

- 作为迈向[移除 let 声明](https://github.com/modular/modular/blob/main/mojo/proposals/remove-let-decls.md)的又一步,我们已在编译器中移除了对 let 声明的支持。为便于迁移,我们将 `let` 声明解析为 `var` 声明,因此你的代码不会破坏。我们会对此发出警告,但请将代码切换为显式使用 `var`,因为此迁移支持将在后续更新中移除。

  ```mojo
  fn test():
      # treated as a var, but please update your code!
      let x = 42  # warning: 'let' is being removed, please use 'var' instead
      x = 9
  ```

- 现在不再能在[自动参数化函数](/docs/manual/parameters/#automatic-parameterization)中显式指定隐式参数。这一能力属于疏忽,现在会报错:

  ```mojo
  fn autoparameterized(x: SIMD):
      pass

  autoparameterized[DType.int32, 1](3) # error: too many parameters
  ```

- `vectorize_unroll` 已被移除,[`vectorize`](/docs/std/algorithm/functional/vectorize/) 现在拥有一个名为 `unroll_factor` 的参数,默认值为 1。增大 `unroll_factor` 可能以二进制大小为代价提升性能。详情请参阅[此处的循环展开博客](https://www.modular.com/blog/what-is-loop-unrolling-how-you-can-speed-up-mojo)。

- `vectorize` 的签名已更改,闭包 `func` 移至第一个参数:

  ```mojo
  vectorize[func, width, unroll_factor = 1](size)
  vectorize[func, width, size, unroll_factor = 1]()
  ```

  文档字符串已更新,提供了展示两种签名差异的示例。

- `unroll` 的签名已更改,闭包 `func` 移至第一个参数:

  ```mojo
  unroll[func, unroll_count]()
  ```

- `NDBuffer` 和 `Buffer` 类型的签名已更改。现在两者都将类型作为第一个参数,且不再需要 shape 参数。这允许你使用这些类型并获得合理的默认值。例如:

  ```mojo
  NDBuffer[DType.float32, 3]
  ```

  等价于

  ```mojo
  NDBuffer[DType.float32, 3, DimList.create_unknown[3]()]
  ```

  用户仍可将静态 shape(若已知)指定给该类型:

  ```mojo
  NDBuffer[DType.float32, 3, DimList(128, 128, 3)]
  ```

- 缺失函数参数的错误信息已改进:不再描述参数数量(例如 `callee expects at least 3 arguments, but 1 was specified`),而是按名称描述缺失的参数(例如 `missing 2 required positional arguments: 'b', 'c'`)。

- `CollectionElement` trait 现在是一个内置 trait,并已从 `collections.vector` 中移除。

- `DynamicVector(capacity: Int)` 构造器已更改为将 `capacity` 作为仅关键字参数,以防止从 `Int` 的隐式转换。

- `Variant.get[T]()` 现在返回指向该值的 `Reference`,而不是返回副本。

- [`String`](/docs/std/collections/string/string/String/) 的方法 `tolower()` 和 `toupper()` 已分别重命名为 `str.lower()` 和 `str.upper()`。

- `ref` 和 `mutref` 标识符不再作为 Mojo 关键字保留。我们最初考虑将它们用作引用的语言糖,但我们认为通用的语言特性结合 [`Reference`](/docs/std/memory/pointer/Pointer/) 类型将能提供良好的体验,无需专门的语法糖。
