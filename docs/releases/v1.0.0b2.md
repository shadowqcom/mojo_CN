## 亮点 {#1-0-0-b2-highlights}

- **集合不再要求 `Copyable` 元素。** 核心集合类型——`List`、`Deque`、`LinkedList`、`InlineArray`、`Dict` 和 `Set`——现在接受 move-only 元素，以 `Movable & ImplicitlyDestructible` 作为新的最低约束取代 `Copyable`。这消除了一个长期存在的摩擦来源：将值存入集合会强制它及其内容变为可拷贝。要求拷贝的方法仍以 `Copyable` 为门槛。参见[集合与迭代器](#1-0-0-b2-collections)。

- **更多位置支持尾随 `where` 子句。** 尾随 `where` 子句现在在结构体声明、`comptime` alias 声明，以及用于解除签名中任意位置使用的受约束类型的约束时受支持。单个尾随 `where` 可以同时约束声明并满足其使用类型的要求，编译器在需要时会建议缺失的子句。参见[语言增强](#1-0-0-b2-language-enhancements)。

- **`enqueue_function()` 和 `compile_function()` 接受单个 kernel 参数。** `DeviceContext.enqueue_function[func]()` 和 `compile_function[func]()` 现在接受一次 kernel 参数，而不再要求传两次，简化了所有 GPU 函数调用点。旧的双参数形式和过渡性的 `*_experimental` 别名已被弃用。参见[设备上下文与执行](#1-0-0-b2-gpu-device-context)。

- **Unicode 感知的字符串下标。** `String` 和 `StringSlice` 现在支持按 Unicode 码点（`[codepoint=...]`）或字形簇（`[grapheme=...]`）进行索引或切片的关键字下标，因此 `String("🔄🔥🔄")[codepoint=1:2]` 返回 `"🔥"`。这使正确的、编码感知的文本索引变得直接，无需手动进行字节算术。参见[字符串与文本](#1-0-0-b2-string)。

- **更快的 Python → Mojo 互操作。** 从 Python 调用 Mojo 现在每次调用的开销显著降低：非 kwargs 可调用对象使用 CPython 的 `METH_FASTCALL` 约定，`PythonObject.__del__()` 在调用线程已持有 GIL 时跳过 GIL 往返，整型转换对精确的 Python `int` 值走快速路径。无需修改代码即可受益。参见 [Python 互操作](#1-0-0-b2-python)。

- **新增和扩展的文档。** 本版本新增了 Closures 页面、新的 `TileTensor` 指南、扩展了部分绑定与未绑定类型以及 `rebind()` 的覆盖，以及若干新的参考页——内置类型、函数重载、闭包声明、CLI 特性开关和 docstring——外加可下载的 Mojo 基础速查表。参见[文档](#1-0-0-b2-documentation)。

- **`mojo package` 现在是 `mojo precompile`。** 打包命令已被重命名，`.mojopkg` 扩展名被弃用，改用 `.mojoc`——这影响所有预编译 Mojo 包的人，尤其是自定义算子作者。新的 `.mojoc` 包也显著更小，编译和加载时间更快。参见[工具链变更](#1-0-0-b2-tooling-changes)。

- **检查并清除 Mojo 编译缓存。** 新增 `mojo --print-cache-location` 和 `mojo --clear-cache` 标志报告和清除磁盘上的编译缓存（`.mojo_cache`），遵循标准缓存路径优先级。`--clear-cache` 默认会提示；传入 `-f` 可在脚本中跳过提示。参见[工具链变更](#1-0-0-b2-tooling-changes)。

- **`fn` 现在是错误。** 使用旧式 `fn` 关键字现在会产生编译错误而非警告，完成 def/fn 统一：`def` 是 Mojo 唯一的函数声明关键字。请将剩余的 `fn` 声明移到 `def`。参见[已移除](#1-0-0-b2-removed)。

- **隐式 `std` import 现在是错误。** 标准库 import 必须完全限定；编译器不再隐式解析裸 `std` 模块名。除使 import 显式外，这还阻止编译器占用 `algorithm` 和 `memory` 等名字，将它们释放给用户模块。参见[语言变更](#1-0-0-b2-language-changes)。

- **反射 API 重构。** `reflect[T]` 现在是 `Reflected[T]` 句柄类型的 `comptime` alias 而非函数，因此调用点去掉了括号（`reflect[T].name()`），弃用的自由函数反射 API（`get_type_name()`、`struct_field_*` 家族和 `ReflectedType[T]`）已被移除，改用 `reflect[T]` 上的方法。新增 `reflect_fn[func]` alias 增加并行的函数侧反射。参见[反射](#1-0-0-b2-reflection)。

- 为 `TileTensor` 新增了 Mojo 手册文档，包括更新的 [tile `Layout` 指南](/docs/manual/tile-tensor/layouts/)、带示例的 [`TileTensor` 指南](/docs/manual/tile-tensor/tensors/)，以及描述 `TileTensor` 与 `LayoutTensor` 之间关系的[介绍](/docs/manual/tile-tensor/)。

- 扩展了 Mojo 手册对[部分绑定与未绑定类型](/docs/manual/parameters/#partially-bound-and-unbound-types)和[自动参数化](/docs/manual/parameters/#automatic-parameterization)的覆盖，提供了关于 `rebind()` 更清晰、更易发现的指导。

- 新增了若干 Mojo 参考页：[无需 import 即可使用的内置（prelude）类型](/docs/reference/types/)、[函数重载与编译器的重载解析规则](/docs/reference/function-declarations/#function-overloads)、[闭包声明](/docs/reference/closure-declarations/)、[CLI 特性开关](/docs/tools/feature-toggles/) 和 [Mojo docstring](/docs/reference/docstrings/)。还新增了 [Mojo 基础速查表](/docs/reference/cheat-sheets/)，一张可下载的 Mojo 核心语法快速参考卡。

## 语言增强 {#1-0-0-b2-language-enhancements}

- 尾随 `where` 子句现在在更多声明上下文中受支持：

  - 在结构体声明上。约束是类型的一部分，在每个绑定处都会检查：

    ```mojo
    struct SIMD[dtype: DType, size: Int]
        where dtype != DType.invalid
        where size.is_power_of_two():
      ...
    ```

  - 在 `comptime` alias 声明上：

    ```mojo
    comptime PositiveOnly[N: Int]: AnyType where N > 0 = ...
    ```

  - 用于_解除_签名中任意位置出现的受约束类型的约束。单个尾随 `where` 会同时约束声明并满足同一签名内使用类型的要求：

    ```mojo
    struct Matrix[m: Int, n: Int] where m > 0 where n > 0: ...

    def solve_linear_system[n: Int, a: Matrix[n, n], b: Vector[n]]() -> Vector[n]
        where n > 0:
      ...
    ```

    如果没有尾随 `where` 解除约束，编译器会报告错误并建议缺失的子句。

- 新增了 `@unavailable` 装饰器，将函数或方法标记为故意不可用。与 `@deprecated`（发出警告）不同，引用 `@unavailable` 声明是错误。与 `@deprecated` 一样，它接受原因消息（位置参数或 `reason=`）或 `use=symbol` 替换。当给定 `use=symbol` 时，错误包含将调用重命名为 `symbol` 的 fix-it。

  ```mojo
  struct Foo:
      @unavailable("message here...")
      def foo(self) -> Int:
          ...

  @unavailable(use=new_api)
  def old_api():
      ...

  def new_api():
      pass
  ```

- 类型现在可以用 where 子句有条件地 "ImplicitlyDestructible"：

  ```mojo
  @explicit_destroy("Message when implicitly destroyed")
  struct ConditionallyLinearType[T: AnyType](
      ImplicitlyDestructible where conforms_to(T, ImplicitlyDestructible)
  ):
      var data: Self.T
  ```

- Mojo 现在支持构建为扩宽源而支持隐式转换的类型，使这样的代码无需 rebind 即可 "直接工作"：

  ```mojo
  def origin_superset_conversion(
    a: String, b: String, c: Bool
  ) -> Pointer[String, origin_of(a, b)]:
    if c:  # These pointers implicitly convert.
        return Pointer(to=a)
    else:
        return Pointer(to=b)
  ```

- 类型可以在希望绑定到备用地址空间时参数化 `out` 参数修饰符，例如：

  ```mojo
  struct MemType(Movable):
    # Can be constructed into any address space.
    def __init__[addr_space: AddressSpace](out[addr_space] self):
        ...

    # Only constructable into GLOBAL address space.
    def __init__(arg: Int, out[AddressSpace.GLOBAL] self):
        ...
  ```

- `ref` 参数现在可以使用通用地址空间，例如 `ref[origin, _]`。通用地址空间会自动参数化到函数签名中。

## 语言变更 {#1-0-0-b2-language-changes}

- 已移除对 "仅 set" 访问器的支持。你需要定义一个 `__getitem__` 或 `__getattr__` 才能使用定义了相应 setter 的类型。这消除了确定有效元素类型的一类 bug。

- `register_passable` 效果关键字已被移除。寄存器可传递性现在根据类型的内容隐式计算，因此显式关键字不再需要，也不再被接受。

- 经过一段弃用期后，隐式 `std` import 现在是错误。从标准库的 import 现在必须完全限定。因此，编译器不再占用这些模块名，为名为 `algorithm`、`memory` 等的用户模块铺路。

- 对 `@export` 函数上 `abi` 效果的处理收紧了：

  - 在 `@export` 装饰器中指定 `ABI="C"` 现已被弃用；应改用 `abi("C")`。

    ```mojo
    @export("old", ABI="C")
    def old(): pass

    @export("new")
    def new() abi("C"): pass
    ```

  - 标记为 `@export` 的函数现在必须给定显式 `abi` 效果，而不是隐式依赖默认值（相当于 `abi("Mojo")`）。编译器会在缺失 `abi` 效果时发出警告，这将在未来版本中变为错误。

    注意 `main` 函数是例外。它总是被隐式 `@export`，在 `main` 被显式 `@export` 的情况下，它会隐式获得正确的 ABI。但是，如果用户既显式 `@export` `main` _又_ 提供了不兼容的 ABI（例如 `raises` 和 `abi("C")`），仍会发出错误。

  - 标记为 `raises` 的函数不能再被给定 `abi("C")` 效果，也不能用已弃用的 `ABI="C"` 选项如此 `@export`。

- 参数列表中的 `where` 子句（param-`where`）现已被弃用。请将 `where` 子句从参数列表移到声明的尾随 `where`。注意 `struct` 和 `comptime` 声明在声明级 `where` 落地之前会暂时失去 `where` 支持。

## 库变更 {#1-0-0-b2-library-changes}

### 类型系统与 trait {#1-0-0-b2-type-system}

- [`ImplicitlyCopyable`](/docs/std/builtin/value/ImplicitlyCopyable/)、[`Intable`](/docs/std/builtin/int/Intable/)、[`Equatable`](/docs/std/builtin/comparable/Equatable/)、[`Indexer`](/docs/std/builtin/int/Indexer/) 和 [`Writer`](/docs/std/format/Writer/) trait 不再继承自 [`ImplicitlyDestructible`](/docs/std/builtin/anytype/#implicitlydestructible)。依赖通过这些 trait（或通过继承自 `Equatable` 的 [`Comparable`](/docs/std/builtin/comparable/Comparable/)）传递接收析构器约束的泛型代码现在必须显式写出，例如 `T: ImplicitlyCopyable & ImplicitlyDestructible` 或 `T: Indexer & ImplicitlyDestructible`。实践中，根据 `ImplicitlyCopyable` docstring 的指导，大多数泛型代码应优先使用 `T: Copyable`。

- [`Movable`](/docs/std/builtin/value/Movable/) trait要求的 `__init__` 方法，其命名参数已从 `take` 改为 `move`。显式调用移动初始化器现在是 `SomeObject(move=)` 而非 `SomeObject(take=)`。

- 在 `std.memory` 中新增了 `is_trivially_movable()`、`is_trivially_copyable()` 和 `is_trivially_destructible()`。这些辅助函数返回某类型的移动构造器、拷贝构造器或析构器是否是平凡的（即位拷贝或 no-op）。

### 反射 {#1-0-0-b2-reflection}

- `reflect[T]` 现在是 `Reflected[T]` 句柄类型的 `comptime` alias，而非返回零大小句柄实例的函数。`Reflected[T]` 上的所有方法都是 `@staticmethod`，且该类型不再可构造。调用点请去掉括号：

  ```mojo
  # Before
  comptime r = reflect[Point]()
  print(r.field_count())
  print(reflect[Point]().name())
  comptime y_handle = reflect[Point]().field_type["y"]()
  var v: y_handle.T = 3.14

  # After
  comptime r = reflect[Point]
  print(r.field_count())
  print(reflect[Point].name())
  comptime y_handle = reflect[Point].field_type["y"]
  var v: y_handle.T = 3.14
  ```

  `field_type[name]` 现在是一个参数化 `comptime` 成员 alias，直接产出 `Reflected[FieldT]`——无需尾随 `()`，且结果完全可组合（例如 `reflect[T].field_type["x"].name()`）。先前弃用的自由函数 `get_type_name()`、`get_base_type_name()` 和 `struct_field_*` 家族（连同 `ReflectedType[T]` 包装器）已被移除；请使用 `reflect[T]` 上对应的方法：

  | 已移除                                   | 替代                                    |
  |-----------------------------------------|------------------------------------------|
  | `get_type_name[T]()`                    | `reflect[T].name()`                      |
  | `get_base_type_name[T]()`               | `reflect[T].base_name()`                 |
  | `is_struct_type[T]()`                   | `reflect[T].is_struct()`                 |
  | `struct_field_count[T]()`               | `reflect[T].field_count()`               |
  | `struct_field_names[T]()`               | `reflect[T].field_names()`               |
  | `struct_field_types[T]()`               | `reflect[T].field_types()`               |
  | `struct_field_index_by_name[T, name]()` | `reflect[T].field_index[name]()`         |
  | `struct_field_type_by_name[T, name]()`  | `reflect[T].field_type[name]`            |
  | `struct_field_ref[idx, T](s)`           | `reflect[T].field_ref[idx](s)`           |
  | `offset_of[T, name=name]()`             | `reflect[T].field_offset[name=name]()`   |
  | `offset_of[T, index=index]()`           | `reflect[T].field_offset[index=index]()` |
  | `ReflectedType[T]`                      | `Reflected[T]`                           |

- 新增 `ReflectedFn[func]`，通过 `reflect_fn[func]` `comptime` alias 访问的函数侧反射句柄。通过静态方法暴露函数自省，与类型侧 `Reflected[T]` API 平行：

  ```mojo
  from std.reflection import reflect_fn

  def my_func(x: Int) -> Int:
      return x + 1

  def main():
      print(reflect_fn[my_func].display_name())  # "my_func"
      print(reflect_fn[my_func].linkage_name())  # mangled symbol name
  ```

### 指针与内存 {#1-0-0-b2-pointer-memory}

- 新增 [`UntrackedOrigin`](/docs/std/builtin/type_aliases/#untrackedorigin) 和 [`UnsafeAnyOrigin`](/docs/std/builtin/type_aliases/#unsafeanyorigin) 源 alias（及其 `Mut`/`Immut` 变体），作为 `ExternalOrigin` 和 [`AnyOrigin`](/docs/std/builtin/type_aliases/#anyorigin) 的新名称。`UntrackedOrigin` 是空源：它不别名任何东西，因此生命周期检查器无从跟踪，它仍然是与 Mojo 程序外部内存交互的受支持工具。`UnsafeAnyOrigin` 是通用源：它可能别名任何东西，击败生命周期扩展和排他性检查，因此其 `Unsafe` 前缀标记它为计划弃用并移除的逃生舱。

  [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/)、[`TileTensor`](/docs/layout/tile_tensor/TileTensor/) 和 [`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/) 上的源丢弃转换方法相应地从 `as_any_origin()` 重命名为 `as_unsafe_any_origin()`。

  旧的 `ExternalOrigin`、`ImmutExternalOrigin` 和 `MutExternalOrigin` alias 现已被弃用，引用时发出弃用警告；请分别改用 `UntrackedOrigin`、`ImmutUntrackedOrigin` 和 `MutUntrackedOrigin`。弃用别名仍会转发到新名称，因此现有代码会继续编译，直到它们在未来版本中被移除。

- 在 `memory.alloc` 中新增了感知 layout 的 `alloc()`/`dealloc()` 分配 API。`alloc()` 返回一个 [`Allocation[T]`](/docs/std/memory/alloc/Allocation/)，一个拥有所有权的句柄，将已分配指针与其分配时使用的 [`Layout`](/docs/std/memory/alloc/Layout/) 打包在一起，`dealloc()` 消费该句柄以释放存储。`Layout[T]` 将元素计数和对齐打包为单个值，使大小和对齐要求在每个调用点都显式且并置。

  `Allocation` 及其不带 layout 的裸对应物 [`ThinAllocation`](/docs/std/memory/alloc/ThinAllocation/) 是 `@explicit_destroy` 类型：编译器强制每个分配在所有路径上被释放——通过传给 `dealloc()`，或通过用 `unsafe_leak()` 取走裸指针的所有权——防范静默泄漏、双重释放和 use-after-free。这些 API 旨在最终取代裸指针分配 API，以促进内存安全。

  ```mojo
  from std.memory import alloc, dealloc, Layout

  var layout = Layout[Int32](count=4)
  var allocation = alloc(layout)
  var ptr = allocation.unsafe_ptr()
  for i in range(layout.count()):
      (ptr + i).init_pointee_move(i)
  dealloc(allocation^)
  ```

- 在 `std.memory.arc_pointer` 中新增 [`WeakPointer[T]`](/docs/std/memory/arc_pointer/WeakPointer/) 类型，提供对 [`ArcPointer[T]`](/docs/std/memory/arc_pointer/ArcPointer/) 的弱引用，用于构建仍可被销毁的自引用和循环引用数据结构。

- `UnsafePointer.unsafe_from_address()` 现在有一个重载构造器，接受 `IntLiteral`，并在地址无效（`0` 或负）时发出编译期断言。

- [`UnsafeUnion`](/docs/std/ffi/unsafe_union/UnsafeUnion/) 现在传播其源的地址空间，而不是默认为 `GENERIC` 地址空间，使其能与地址空间特定的内存（如 GPU 共享内存）一起使用。

### 集合与迭代器 {#1-0-0-b2-collections}

- 核心集合类型不再要求其元素类型为 [`Copyable`](/docs/std/builtin/value/Copyable/)——`Movable & ImplicitlyDestructible` 现在是最低约束。这适用于 [`List[T]`](/docs/std/collections/list/List/)、[`Deque[T]`](/docs/std/collections/deque/Deque/)、[`LinkedList[T]`](/docs/std/collections/linked_list/LinkedList/)、[`InlineArray[T, size]`](/docs/std/collections/inline_array/InlineArray/)、[`Dict[K, V, H]`](/docs/std/collections/dict/Dict/) 的两个类型参数（连同 `SwissTable`/`SwissTableEntry`/`OwnedKwargsDict` 和放宽的 [`KeyElement`](/docs/std/collections/dict/#keyelement) trait）以及 [`Set[T]`](/docs/std/collections/set/Set/)。要求拷贝的方法仍以 `Copyable` 为门槛。[`Counter[V]`](/docs/std/collections/counter/Counter/) 不变。`Dict.setdefault()` 和 `Set.add()` 现在按 `var T` 接受其参数；对于 move-only 类型，请调用为 `d.setdefault(key^, default)` 或 `set.add(value^)`。

- `List[T]` 现在有条件地遵循 `ImplicitlyDestructible`：仅当其元素类型 `T` 遵循时，`List` 才隐式可析构。这使 `List` 能持有必须被显式销毁的元素（否则丢弃这样的 `List` 会泄漏它们），代价是泛型代码中检查更严格。

  以仅 `Movable` 元素约束按值接受 `List` 的泛型代码现在对每个 `T` 都会编译失败。此前错误被推迟，仅当 `T` 用非 `ImplicitlyDestructible` 类型实例化时才触发。请在元素约束中加入 `& ImplicitlyDestructible`：

  ```mojo
  # Now errors for every `T` (previously only when `T` lacked a destructor):
  def foo[T: Movable, //](var list: List[T]):
      pass

  # Fix: require the destructor bound explicitly.
  def foo[T: Movable & ImplicitlyDestructible, //](var list: List[T]):
      pass
  ```

  存储 `List` 的结构体同样受影响。要么约束元素类型，要么更好地传播条件遵循，使你的类型也支持显式销毁元素，通过 `destroy_with()` 转发清理：

  ```mojo
  # Option 1: require the element type to be implicitly destructible.
  struct Foo[T: Movable & ImplicitlyDestructible]:
      var list: List[Self.T]

  # Option 2: conditionally conform, and forward explicit destruction.
  @explicit_destroy("...")
  struct Foo[T: Movable](
      ImplicitlyDestructible where conforms_to(T, ImplicitlyDestructible),
  ):
      var list: List[Self.T]

      def destroy_with(deinit self, f: Some[def(var Self.T)]):
          self.list^.destroy_with(f)
  ```

- 在 `std.collections` 模块中新增 [`BinaryHeap`](/docs/std/collections/binary_heap/BinaryHeap/) 集合。这是一个基于列表的二叉最大堆。

- 为 [`Iterator`](/docs/std/iter/Iterator/) trait 新增 [`nth()`](/docs/std/iter/Iterator/#nth) 作为默认方法。它将迭代器前进 `n` 个元素（销毁它们）并返回下一个元素，如果迭代器在到达索引 `n` 之前耗尽则返回 `None`。

  ```mojo
  var l = [10, 20, 30, 40]
  print(iter(l).nth(0).value())   # 10
  print(iter(l).nth(3).value())   # 40
  var missing = iter(l).nth(10)   # None (Optional)
  ```

- 在 `std.itertools` 中新增 [`take()`](/docs/std/itertools/itertools/take/) 和 [`drop()`](/docs/std/itertools/itertools/drop/) 迭代器适配器。`take(iter, n)` yield 前 `n` 个元素，`drop(iter, n)` 丢弃前 `n` 个元素。它们自然组合以选择任何可迭代对象的子范围：

  ```mojo
  from std.itertools import take, drop

  var nums = [1, 2, 3, 4, 5]
  for x in take(drop(nums, 1), 3):
      print(x)  # 2, 3, 4
  ```

- 为 `LinkedList` 新增 [`index()`](/docs/std/collections/linked_list/LinkedList/#index) 方法，用于查找值的首次出现。与 Python 的 `list.index()` 不同，它省略了 `start`/`stop` 参数。

- `Dict` 现在将后备缓冲区分配推迟到首次插入。默认构造和 `capacity=0` 的字典不再执行任何堆分配。

### 字符串与文本 {#1-0-0-b2-string}

- `String.as_bytes_mut()` 已被重命名为 `String.unsafe_as_bytes_mut()`，以反映向结果 [`Span[Byte]`](/docs/std/memory/span/Span/) 写入无效 UTF-8 可能导致后续诸如越界访问等问题。

- 若干 [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/) 构造器现已被弃用。

  - `StringSlice(ptr=..., length=...)` 已弃用；请改用 `StringSlice(unsafe_from_utf8=Span(...))`。
  - `StringSlice(unsafe_from_utf8_ptr=...)`（接受裸的空终止 `UnsafePointer[Byte]` 或 `UnsafePointer[c_char]`）已弃用；请从指针构造一个 `CStringSlice` 并使用新的 `StringSlice(unsafe_from_utf8=CStringSlice(...))` 构造器。

- [`String`](/docs/std/collections/string/string/String/) 和 `StringSlice` 现在暴露 `bytes()` 方法，返回一个新的 `BytesIter`，即字符串原始 UTF-8 字节的迭代器。这通过在字节级别操作而不解释多字节 UTF-8 序列，补充了现有的 `codepoints()` 和 `graphemes()` 迭代器。

  ```mojo
  var s = StringSlice("é")  # Encoded in UTF-8 as 0xC3 0xA9.
  for b in s.bytes():
      print(b)  # 195, 169
  ```

- `String` 和 `StringSlice` 现在支持 Unicode 感知的下标：

  - 仅关键字 `[codepoint=...]` 下标按 Unicode 码点偏移索引或切片，例如 `String("🔄🔥🔄")[codepoint=1:2]` 返回 `"🔥"`。
  - `[grapheme=...]` 下标按字形索引，例如 `String("👨‍🚀🧑‍🌾क्षि")[grapheme=1]` 返回 `"🧑‍🌾"`。

### Python 互操作 {#1-0-0-b2-python}

- CPython FFI 绑定现在携带 `abi("C")` 效果。传递给 `def_py_c_function()`、`def_py_c_method()` 或 `PyCapsule_New()` 的用户编写的 Python 扩展回调必须在其签名中加入 `abi("C")`，例如 `def my_func(self: PyObjectPtr, args: PyObjectPtr) abi("C") -> PyObjectPtr:`。通过更高级的 `def_function()`、`def_method()` 和 `def_staticmethod()` 路径注册的函数不受影响。

- PythonObject 可转换性得到了简化和清理。当使用需要自定义转换到 [`PythonObject`](/docs/std/python/python_object/PythonObject/) 的类型时，我们过去常写这样的代码：

  ```mojo
  struct MyCustomType(ConvertibleToPython, ImplicitlyCopyable):
     def to_python_object(var self) raises -> PythonObject:
        return PythonObject( ... custom logic ...)

  def hi_python(a: Some[ImplicitlyCopyable & ConvertibleToPython]) raises:
      print(t"Hi, {a.to_python_object()}!")

  def example():
      hi_python(MyCustomType())
  ```

  这种方法允许自定义类型实现 [`ConvertibleToPython`](/docs/std/python/conversions/ConvertibleToPython/) 以获得作为 Python 对象的特定领域编码。Mojo 通过使所有 `ConvertibleToPython` 类型隐式转换为 `PythonObject` 简化了这一点，因此这可以/应该简化为：

  ```mojo
  def hi_python(a: PythonObject) raises:
      print(t"Hi, {a}!")
  ```

- 通过 [`PythonModuleBuilder`](/docs/std/python/bindings/PythonModuleBuilder/) 和 [`PythonTypeBuilder`](/docs/std/python/bindings/PythonTypeBuilder/) 注册的 Python → Mojo FFI 调用每次调用开销显著降低：

  - 用 `def_function()` / `def_method()` / `def_staticmethod()` 注册的非 kwargs 可调用对象现在使用 CPython 的 `METH_FASTCALL` 调用约定而非 `METH_VARARGS`。接受 kwargs 的函数仍使用 `METH_VARARGS | METH_KEYWORDS`。

  - 当当前线程已持有 GIL（通过 `PyGILState_Check` 检查）时，`PythonObject.__del__()` 跳过 `PyGILState_Ensure` / `PyGILState_Release` 往返。在常见的 Python → Mojo FFI 路径上（CPython 将已持有的 GIL 交给被调用方），析构器只付出检查和直接 `Py_DecRef` 的代价。公共契约不变——从未持有 GIL 的线程丢弃 `PythonObject` 仍然安全。

  - `Int(py=obj)` 和 `Scalar[IntDType](py=obj)` 通过 `PyLong_AsSsize_t` 对精确 Python `int` 走快速路径。

- 扩展 `PyObjectFunction` 以支持 7 和 8 参数签名，添加相应的类型 alias 和 `@implicit` 构造器重载。

### 其他库变更 {#1-0-0-b2-other-library}

- `std.algorithm` 归约（`sum`、`product`、`mean`、`max`、`min` 以及底层 `_reduce_generator` 加上 CPU 和 GPU 后端）的归约轴现在是名为 `reduce_dim` 的仅关键字编译期参数，而非运行时参数。在参数列表中传递它，例如 `sum[..., reduce_dim=axis](shape, ctx)`。

- 在 `std.algorithm.functional` 中新增 `dual_elementwise()`，在单次 GPU 内核启动中执行两个元素函数在其各自形状上的运算，将两个独立的 elementwise 过程融合为一个。

- `random.Random`、`random.NormalRandom` 和内部 `_PhiloxWrapper` 的默认 `seed` 从 `0` 改为 `0x3D30F19CD101`（67280421310721），以匹配 PyTorch 的 `at::Philox4_32_10` 默认值。省略 `seed` 参数的调用现在会产生不同的输出流；显式传入 `seed=0` 以保留先前行为。

- 为 Philox RNG 新增 `Random.step_uniform_unbiased()` 和 `NormalRandom.step_normal_4()` 原语。`step_uniform_unbiased()` 使用所有 32 个原始位返回四个 (0, 1) 范围内的 `Float32` 值；`step_normal_4()` 通过同步骤 Box-Muller 配对从单个 Philox 步骤返回四个正态值。

## GPU 编程 {#1-0-0-b2-gpu-programming}

### 设备上下文与执行 {#1-0-0-b2-gpu-device-context}

- `DeviceContext.enqueue_function[func]()` 和 `DeviceContext.compile_function[func]()` 现在接受单个 kernel 参数，而不再要求传递两次。先前的双参数形式 `enqueue_function[func, func]()` 和 `compile_function[func, func]()` 已被弃用。过渡性的 `enqueue_function_experimental()` 和 `compile_function_experimental()` alias 也已被弃用；请切换到 `enqueue_function()` / `compile_function()`。

  ```mojo
  # Before
  ctx.enqueue_function[my_kernel, my_kernel](grid_dim=1, block_dim=1)
  ctx.enqueue_function_experimental[my_kernel](grid_dim=1, block_dim=1)

  # After
  ctx.enqueue_function[my_kernel](grid_dim=1, block_dim=1)
  ```

- 在 `std.gpu.host` 中新增 [`DeviceContextList[size]`](/docs/std/gpu/host/device_context/DeviceContextList/)：固定大小的、`Copyable`/`ImplicitlyCopyable`/[`Sized`](/docs/std/builtin/len/Sized/) 的 [`DeviceContext`](/docs/std/gpu/host/device_context/DeviceContext/) 值集合。多设备自定义算子 `execute` 方法现在接收一个 `DeviceContextList[N]`——图编译器通过可变参数构造器从附加到算子的每设备上下文合成一个。内核可以用 `dev_ctxs[i]`（运行时）或 `dev_ctxs.__getitem_param__[i]()`（comptime）索引它，并用 `len()` 迭代。这取代了先前的 `DeviceContextPtrList` 模式。

  ```mojo
  from gpu.host import DeviceContext, DeviceContextList

  @compiler.register("mo.distributed.allreduce.sum")
  struct DistributedAllReduceSum:
      @staticmethod
      def execute[
          dtype: DType, rank: Int, target: StaticString, _trace_name: StaticString,
      ](
          outputs: FusedOutputVariadicTensors[dtype=dtype, rank=rank, ...],
          inputs: InputVariadicTensors[dtype=dtype, rank=rank, ...],
          signal_buffers: MutableInputVariadicTensors[dtype=DType.uint8, rank=1, ...],
          dev_ctxs: DeviceContextList,
      ) capturing raises:
          comptime num_devices = inputs.size
          # ... use dev_ctxs[i] per device ...
  ```

- 新增 [`std.gpu.host.CompletionFlag`](/docs/std/gpu/host/device_context/CompletionFlag/)，一个对 MLRT `M::Driver::CompletionFlag`（固定主机内存中映射到设备地址空间的 8 字节槽）的非拥有句柄。与新的 `DeviceStream.wait_for_host_value(flag, value)` 方法配对，该方法暂停流直到标志的 64 位槽等于给定值。对应于 CUDA 的 `cuStreamWaitValue64` 并能干净地作为等待值节点捕获到 CUDA 图中，让 CPU 线程（或由 `enqueue_host_func()` 分派的 AsyncRT worker）无需第二个流或阻塞主机函数回调即可基于主机产生的数据门控 GPU 流。目前仅支持 CUDA；其他后端会抛异常。

- 新增 [`DevicePointer`](/docs/std/gpu/host/device_context/DevicePointer/) 结构体，一个指向设备内存的指针的主机侧表示，持有对所属 `DeviceBuffer` 的引用并执行边界检查。

- 为 `DeviceContext` 新增 `max_single_allocation_size` 查询，报告驱动当前会处理的最大单次分配；在 Metal 上它反映实时的 Metal 框架限制，而 CUDA/HIP 报告可用内存。

- 新增 `PDLLevel.ON` 命名常量作为 `PDLLevel(1)` 的 alias，用于代替数字形式的 `PDLLevel(0)`/`PDLLevel(1)`。

### Layout 与坐标 {#1-0-0-b2-gpu-layout}

- 将 [`Idx`](/docs/std/utils/coord/#idx) 改为 [`ComptimeInt`](/docs/std/utils/coord/ComptimeInt/) 的 `comptime` alias。请使用 `Idx[value]` 而非 `Idx[value]()` 来表示编译期坐标。

- [`Coord`](/docs/std/utils/coord/Coord/)、[`coord()`](/docs/std/utils/coord/coord-function/)、`Idx`、`ComptimeInt` 及相关坐标辅助工具现在位于标准库模块 [`std.utils.coord`](/docs/std/utils/coord/) 中。[`layout.coord`](/docs/layout/coord/) 模块为 layout 和 kernel 代码重新导出相同符号；`layout` 还为方便将常用名字提升到包作用域。

- 内核坐标 API 现在使用 `Coord` 以保留编译期静态形状信息：

  - `elementwise()` 现在向其回调传递 `Coord` 而非 `IndexList[rank]`，并接受 `Coord` 形状参数，使你能传递静态维度。将回调从 `def func[width, rank, align](idx: IndexList[rank])` 重写为 `def func[width, align](coord: Coord)`，将调用从 `elementwise(func, IndexList[2](...), ctx)` 重写为 `elementwise(func, Coord(...), ctx)`。

  - `Int` 现在遵循 `CoordLike`，因此 `Int` 值可直接传给 `Coord` 构造器而无需包装在 `Idx(...)` 中。

- 为 [`Layout`](/docs/layout/layout/Layout/) 和 `TileTensor` 新增嵌套布局支持（CuTe layout 代数）。单个 `.tile[]` API 现在同时处理扁平父布局和嵌套父布局，新增的 `row_major_nested()`/`col_major_nested()` 构造器（加上 `RowMajorNestedLayout`/`ColMajorNestedLayout` alias）为 MFMA 寄存器 tile 和 `blocked_product` 输出构建重新嵌套的布局。

- 新增 `TileTensor.copy_from()` 和 `TileTensor.split()`，用于在兼容的 tile 视图之间拷贝以及将 tile 拆分为静态或运行时大小的分区。

### 设备目标与硬件支持 {#1-0-0-b2-gpu-targeting}

- 在 `std.sys.info` 中新增 `has_nvidia_gpu_accelerator[subarch]` 和 `has_nvidia_gpu_accelerator[subarchs]` 重载，结合编译期和运行时检查主机是否有给定子架构或更新的 NVIDIA GPU。

- 新增 `std.sys.machine` 模块，提供 `MachineDefinition`，以及扩展的 `DeviceSpec` 和 `DeviceRef` 类型，用于在编译期间聚合并提供更丰富的静态设备信息。

- 在 Metal（Apple GPU）后端上新增对 `fp8e4m3`、`fp8e4m3fn` 和 `fp8e5m2` 浮点类型的支持，并在 Apple M2（Apple8）Metal GPU 上启用原生 `Int` <-> `bfloat16` 转换。

- NVIDIA GPU 上 `Float32` 的 `math.log()` 现在使用 `lg2.approx.ftz.f32` PTX 内在函数，它将次正规输入和输出刷新为零（与 CUDA 的 `__logf` 一致），避免了更慢的次正规处理路径。

## 工具链变更 {#1-0-0-b2-tooling-changes}

- `mojo package` 命令已重命名为 `mojo precompile`。类似地，`.mojopkg` 文件扩展名已被弃用；请改用 `.mojoc` 文件扩展名。

  ```text
  # Before
  mojo package my_package -o my_package.mojopkg

  # After
  mojo precompile my_package -o my_package.mojoc
  ```

- `mojo precompile` 现在通过丢弃每个模块解析器输出的冗余序列化副本，生成显著更小的 `.mojoc` 包，这也减少了包编译和加载时间。

- 新增 `mojo --print-cache-location` 和 `mojo --clear-cache` 用于检查和清除磁盘上的 Mojo 编译缓存（`.mojo_cache`）。解析的路径遵循现有优先级（`MODULAR_CACHE_DIR`、`MODULAR_HOME`、`MODULAR_DERIVED_PATH`、`XDG_CACHE_HOME` 等）。`--clear-cache` 默认会提示确认；传入 `-f`（或 `--force`）可在脚本使用中跳过提示。

  ```text
  $ mojo --print-cache-location
  /home/you/.cache/modular/.mojo_cache

  $ mojo --clear-cache
  This will remove the Mojo compile cache at:
    /home/you/.cache/modular/.mojo_cache
  Proceed? [y/N] y
  Removed /home/you/.cache/modular/.mojo_cache

  $ mojo --clear-cache -f   # no prompt
  ```

- 当模块位于只读目录时（例如安装在只读 `site-packages` 中的 Mojo 扩展），从 Python import Mojo 模块不再失败。此前 importer 总是尝试将其编译产物写入源旁边的 `__mojocache__` 目录，这在只读文件系统上会引发 `OSError`。importer 现在在源目录可写时保留这种树内行为，否则将缓存重定向到 Modular 缓存文件夹。该位置遵循标准 Modular 配置：`modular.cfg` 中的 `cache_dir` 键、`MODULAR_CACHE_DIR` 和 `MODULAR_HOME` 环境变量，以及 XDG 基础目录规范。

- `mojo` 编译器现在会在指向不可访问源位置（例如来自预编译库）的诊断中打印文件名和行号，而不是主文件顶部的位置：

  ```text
  # Before
  $> mojo example.mojo
  /path/to/example.mojo:33:16: error: invalid call to '__setitem__': violated constraint
     vec[base + i] = values[i].cast[dtype]()
     ~~~^~~~~~~~~~

  /path/to/example.mojo:1:1: note: constraint declared here evaluated to False, expected 'mut'
  from std.algorithm.functional import elementwise
  ^
  /path/to/example.mojo:1:1: note: function declared here
  from std.algorithm.functional import elementwise
  ^

  # After
  $> mojo example.mojo
  /path/to/example.mojo:33:16: error: invalid call to '__setitem__': violated constraint
      vec[base + i] = values[i].cast[dtype]()
      ~~~^~~~~~~~~~

  max/kernels/src/layout/layout_tensor.mojo:2092: note: constraint declared here evaluated to False, expected 'mut'
  max/kernels/src/layout/layout_tensor.mojo:2090: note: function declared here
  ```

- 当源信息不可用时，`mojo` 编译器现在通过合成声明并美化打印它，提供更有用的诊断。

  例如，不再是下面这样在 "here" 之后没有上下文信息：

  ```text
  /path/to/file.mojo:2092: note: function declared here:
  ```

  用户现在会看到：

  ```text
  /path/to/file.mojo:2092: note: function declared here:
  def __setitem__[*Tys: Indexer](self, *args: *Tys.values, *, val: SIMD[dtype, Self.element_size]) where mut
  ```

  此类情况下的诊断覆盖率和质量将在后续版本中持续改进。

- Mojo 编译器现在在导致失败的某个操作数值上报告与调用相关的错误，而不是在调用整体上。这使理解跨越多行的多参数调用中的失败更容易。

- 改进了范围广泛的编译器诊断的清晰度和可操作性——声明解析、`main()`、解析器、词法分析器、签名和调用发射错误——解释了什么错了以及如何修复。

- 改进了将 `VariadicPack` 展开到固定元数被调用方的诊断：编译器现在附加指向受支持分派器模式的提示，且 `callee(*pack)` pack 解包不匹配现在会报告实际和期望的元素类型，而不仅是 pack trait。

- `MODULAR_DEBUG=uninitialized-read-check` 失败现在会打印每个陷阱 lane 的内核源位置、dtype、lane 索引、观察到的位模式以及块/线程索引，而不是被 thread-(0,0,0) 打印门静默。

- `mojo format` 现在接受闭包捕获列表中的裸移动捕获形式 `{name^}`。此前只有等价的 `{var name^}` 形式能通过格式化器往返。

- Mojo 语言服务器现在对在重新解析期间到达的补全请求返回 `ContentModified` 而非 `InvalidRequest`，修复了 Neovim 内置 LSP 客户端等客户端中补全缺失的问题。

- LLDB 调试器现在为 Mojo 的 `PythonObject`（显示底层 Python 类型名并解码 `None`、`bool`、`int`、`float` 等常见内置类型，以及 `list`/`tuple`/`dict` 的项计数）和 `Dict[K, V]`（显示 `(size N)` 并按插入顺序暴露活跃条目及其键和值）提供类型摘要。

## 已移除 {#1-0-0-b2-removed}

- 旧式 `fn` 关键字现在产生错误而非警告。请迁移到 `def`。

- `DeviceContextPtr` 和 `DeviceContextPtrList` 类型已从 `std.runtime.asyncrt` 中移除。自定义算子 `execute` 方法现在直接接受 `DeviceContext`（或上下文真正可选时接受 `Optional[DeviceContext]`），多设备算子接受 `DeviceContextList[N]`（参见 _库变更_ 下的新条目）。辅助函数 `get_device_context()` 和 `get_optional_device_context()` 不再需要——直接传递 `DeviceContext` 即可。`CpuDeviceContext` 运行时总是为 CPU 路径提供真实上下文，因此不再需要可空包装器。

  ```mojo
  # Before
  from runtime.asyncrt import DeviceContextPtr, DeviceContextPtrList

  @compiler.register("my_op")
  struct MyOp:
      @staticmethod
      def execute[target: StaticString](
          output: OutputTensor,
          input: InputTensor,
          ctx: DeviceContextPtr,
      ) raises:
          var gpu_ctx = ctx.get_device_context()
          ...

  # After
  from gpu.host import DeviceContext

  @compiler.register("my_op")
  struct MyOp:
      @staticmethod
      def execute[target: StaticString](
          output: OutputTensor,
          input: InputTensor,
          ctx: DeviceContext,
      ) raises:
          ...
  ```

- 移除了 `DeviceContext.compile_function_unchecked()` 和 `DeviceContext.enqueue_function_unchecked()`。请改用带检查的 `compile_function()` 和 `enqueue_function()`。

- 从 `elementwise` 和归约 API 中移除了若干参数和重载：

  - 从 `elementwise`（在 `std.algorithm.functional` 中）移除了 `use_blocking_impl` 参数，从归约 API（`std.algorithm.reduction` 中的 `reduce`、`max`、`min`、`sum`、`product`、`mean`）移除了类似的 `single_thread_blocking_override` 参数。这些操作现在总是以相同方式分派工作，当问题规模小时自动使用单个 worker，因此不再需要阻塞变体。

  - 从 `elementwise`、`dual_elementwise` 和 GPU elementwise 实现中移除了 `pdl_level` 参数。现在总是使用 PDL 级别 1。

  - 移除了 `elementwise`（在 `std.algorithm.functional` 中）的两个 `Optional[DeviceContext]` 重载；调用方现在直接穿透非可选的 `DeviceContext`。`CpuDeviceContext` 运行时总是为 CPU 路径提供真实上下文，因此不再需要可空包装器。

- `std.reflection` 中已弃用的自由函数反射 API 已被移除。请改用统一的 `reflect[T]` API；完整迁移表参见 _库变更_ 下的[反射](#1-0-0-b2-reflection)。

- 若干先前已弃用的 API 已被移除：

  - `constrained[cond, msg]()` 函数。请改用 `comptime assert cond, msg`。

  - `normalize_index()` 的 `Int` 返回重载。请使用 `UInt` 返回重载（或内联编写索引算术，例如 `x[len(x) - 1]`）。

  - 默认的 `UnsafePointer()` 空构造器。要建模可空指针，请使用 `Optional[UnsafePointer[...]]`。对于延迟初始化的非空占位符，请使用 `UnsafePointer.unsafe_dangling()`。

- 已从 `mojo precompile` 中移除 `-kgenModule` 标志。它发出序列化的 KGEN 模块（`.mlirbc`）而非 `.mojoc` 包，仅内部使用。

## 已修复 {#1-0-0-b2-fixed}

- 修复了一个 GPU 归约正确性 bug，当行数达到 `256 * sm_count`（在 148-SM GPU 上为 37888 行）时，连续最后一轴归约（例如沿最后一轴的 `mean`）会产生错误结果。N-D 归约被规范化为 rank-3 `(outer, reduce, inner)` 形状，因此最后一轴归约有尾随的 `inner == 1` 维度；内核启动器将其视为非连续归约，一旦设备线程饱和，就分派了一个其跨行 SIMD 打包仅在真实 inner 维度提供相邻行时才有效的内核。连续性现在从布局推导（当 reduce 维度之后每个维度都是单位大小时，reduce 维度是最内层）。

- 将每次 `mojo` 调用保留的虚拟地址空间减少约 1 GiB。JIT 内存映射器的保留粒度是 1 GiB，因此每次新保留都会向上取整到该大小并 mmap `PROT_READ|PROT_WRITE`，膨胀了 `VmPeak` 并计入 Linux `RLIMIT_AS`。这导致两个 `mojo` 进程在内存受限的 CI runner（例如 GitHub Actions 免费层，7 GiB）上并发运行时，`libKGENCompilerRTShared.so` 中出现非确定性 OOM 崩溃。粒度现在是 64 MiB；大型编译仍可工作，因为映射器按需保留额外 slab。
  ([Issue #6433](https://github.com/modular/modular/issues/6433))

- 尝试从损坏的符号链接 import 源 Mojo 包不再导致编译器崩溃。
  ([Issue #6424](https://github.com/modular/modular/issues/6424))

- 修复了一个阻止 `from . import module` 并产生虚假递归引用错误的 bug。

- `MODULAR_NVPTX_COMPILER_PATH` 现在是 Mojo 缓存位置的一部分，因此切换到不同的 `ptxas` 不再重用切换前生成的 CUBIN 缓存条目。
  ([Issue #6549](https://github.com/modular/modular/issues/6549))

- 修复了一个生命周期检查器 bug，即销毁一个捕获源的类型（其析构器可访问这些源）未能将引用值的生命周期扩展到 `__del__` 调用之后。

- 修复了 linear/no-return 函数交互，使 `read` 参数和其他值不再需要在 no-return 调用（例如 `abort()`）之后保持存活，减少了代码大小并消除了虚假的线性类型错误。

- 修复了参数推断和 trait 转换中的若干编译器崩溃和误编译，包括跨向上转换错误地拒绝类型值可转换性，以及 trait 之间的 `Downcast` 丢弃原始类型的 trait 遵循。

- 修复了若干 trait 继承和遵循 bug：精化了继承带默认关联 alias（其默认引用 `Self`，或被精化的 trait 声明为抽象）的 trait 被拒绝或崩溃；`where conforms_to(T, Trait)` 子句未传播到后续参数匹配；从字节码加载 trait 函数可能崩溃；预编译包存根闭包 trait 在其完整定义之前缓存产生 "closure trait missing call" 崩溃；将带兼容 `__call__` 方法的结构体传给函数 trait 参数现在会自动遵循或产生正确错误，而非崩溃。
  ([Issue #6354](https://github.com/modular/modular/issues/6354))

- 修复了一个 bug，即将函数字面量传给以语法糖闭包 trait（例如 `comptime CallbackType = def(Int) -> Int`）类型化的参数时，未能将字面量膨胀为所需的 trait遵循者。

- 修复了一个 bug，即在 x86-64 等目标上，将大于 16 字节的结构体传给用 `abi("C")` 装饰的 Mojo 回调会失败，因为回调缺少必需的 `byval` 标志。
  ([Issue #6511](https://github.com/modular/modular/issues/6511))

- 修复了一个代码生成 bug，即对通过 `sret` 返回结构体的 `abi("C")` 函数进行间接尾调用可能读取未初始化内存；此类间接调用的 `tail` 属性现在被正确移除。

- 当同名 `.mojoc` 模块和过时的 `.mojopkg` 在目录中并存时，编译器现在优先选择 `.mojoc` 模块，避免因选用旧构建而导致的错误。

- 修复了当编译器因字段不是 `ImplicitlyCopyable` 而无法合成隐式拷贝构造器时的误诊，并纠正了条件遵循备份路径以检查 `ImplicitlyCopyable` 而非 `Copyable`。

- 重新启用了先前被禁用的 elaborator 中的错误报告。

- 将非 `VariadicPack` 值（例如 `print(*l)`，其中 `l` 是 `List[Int]`）展开现在会发出清晰错误而非使解析器崩溃。
  ([Issue #6350](https://github.com/modular/modular/issues/6350))

- 直接放在结构体、trait 或扩展体中，或模块作用域内的控制流语句（`if`、`for`、`while`、`try`、`with` 及其 `comptime` 形式）现在会发出解析错误而非使编译器崩溃。

- 修复了 `mojo doc` 在为没有有效源位置的声明（例如来自字节码包）发出诊断时崩溃的问题。

- 修复了 `TileTensor.raw_store()` 未将其 `width` 参数转发到底层 `UnsafePointer.store()` 调用的问题。

- 修复了一个 POP 到 LLVM 的 lowering 失败（"existing function with conflicting signature"），该失败发生在图同时组合了通过 `enqueue_function()` 的外部 cubin/PTX 启动和 matmul 时；启动路径现在将 grid/block 维度、共享内存大小和属性计数转换为 `UInt32` 以匹配 C ABI。

- `MODULAR_DEBUG=uninitialized-read-check` 不再对 fp8 dtype 产生误报，其合法的饱和到最大值与毒化哨兵位完全相同；填充和加载点检查现在对所有 fp8 格式跳过（fp16、bf16、fp32 和 fp64 不受影响）。

- 修复了仅有限浮点 float8 dtype（`float8_e4m3fn`、`float8_e8m0fnu`）的 `isinf()`，此前它落到一个没有 `i8` 重载的 `llvm.is.fpclass` 内在函数并在 LLVM lowering 期间失败；`isinf()` 现在对这些格式在编译期正确返回 `False`。

- 修复了若干 Apple GPU（Metal）后端代码生成 bug：解包含指针字段的 `OptionalReg[T]` 时的非法通用地址空间访问、在缺乏原生支持的 M1（Apple7）和 M2（Apple8）GPU 上的 `bfloat16` 算术，以及 `SIMD` 浮点向量上不可 lowering 的 `max()` 内在函数。

- 通过从 AMD RDNA GPU 架构模式中移除 `amdgpu:` 前缀，修复了编译期的 AMD RDNA GPU 架构检测，此前这导致在 AMD RDNA GPU 上编译失败。

- 修复了 `UnsafePointer` 的隐式构造器。当函数接受 `UnsafePointer[mut=False, ...]` 并被传入可变指针时，重载解析选择了错误的构造器，导致新源为 `ImmutableAnyOrigin`。这是个问题，因为它偶尔会隐藏指针之间的可变性别名，并隐藏一些未使用的变量。该构造器现在正确转换为 `ImmutOrigin(Self.origin)`。
