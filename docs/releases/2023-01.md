## 2023-01-30 那一周

- VS Code 扩展中新增了一个基础的 Mojo 语言服务器，它会在你
  编写代码时解析代码，并提供警告、错误和修复建议！

- 💯 Mojo 标准库现在默认隐式导入。

- 重构了协程降级支持，并实现了新的 `Coroutine[T]` 类型。现在，
  调用 async 函数的结果必须包装在 `Coroutine[T]` 中，否则会
  内存泄漏。未来，当 Mojo 支持析构函数以及将库类型作为字面量
  类型时，async 函数调用的结果会自动包装在 `Coroutine[T]` 中。
  但目前仍需手动完成。该类型实现了所有预期的钩子，例如
  `__await__`，以及用于获取结果的 `get()`。典型用法：

  ```mojo
  async fn add_three(a: Int, b: Int, c: Int) -> Int:
      return a + b + c

  async fn call_it():
      let task: Coroutine[Int] = add_three(1, 2, 3)
      print(await task)
  ```

- ⭐️ 我们现在会在 `fn` 声明（而非 `def`）的语句上下文诊断
  未使用的表达式值。这可以捕获与未使用值相关的 bug，例如
  忘记加括号来调用函数时。

- 📢 `@always_inline("nodebug")` 函数装饰器可用于需要被强制内联、
  但结果中不应包含调试信息的函数。这应当用于像 `Int.__add__` 这类
  应被视为内建的方法。

- 📢 `@export` 装饰器现在支持显式符号名导出，例如：

  ```mojo
  @export("baz") # exported as 'baz'
  fn some_mojo_fn_name():
  ```

- 📢 🚧 下标语法现已连接到 `__getitem__` dunder 方法。

  这使类型作者可以实现 `__getitem__` 方法以启用对值的
  下标访问。这是 Python 语义的扩展版（因为我们支持重载），
  允许你定义 N 个索引，而非接受一个元组的单版本（这也很方便，
  因为我们尚无元组）。

  注意，这有一个非常非常重要的限制：下标尚未
  连接到 `__setitem__`。这意味着你可以用
  `.. = v[i]` 读取值，但无法用 `v[i] = ..` 存储。对此，请
  继续直接调用 `__setitem__`。

- 📢 函数调用支持参数推断。

  对于调用点指定参数数量不足的函数调用，
  我们现在可以从参数列表推断参数。为此我们
  匹配平行类型结构来推断参数必须是什么。

  注意，此过程在参数列表中从左到右进行，先应用显式
  指定的参数，再尝试推断新参数。这类似于 C++ 的做法，
  意味着你可以据此重新排列参数列表。例如，
  类似 `dyn_cast` 的函数按如下实现会更优雅：

  `fn dyn_cast[DstType: type, SrcType: type](src: SrcType) -> DstType:`

  而非将 `SrcType`/`DstType` 参数顺序颠倒。

- 📚 添加可增长的 Dynamic vec 结构体。

## 2023-01-23 那一周

- 原地运算（如 `+=`/`__iadd__`）现在可以按需让 `self` 按值传递，
  而不必要求按引用传递。
- ⭐️ 原地运算不再允许返回非 None 值。对应
  语法是语句，而非表达式。

- 标准库新增 `TaskGroup` 类型。该类型可用于
  在多线程工作队列上调度多个任务并行执行。async 函数可以
  通过 taskgroup 一次性 `await` 所有任务。

- 📢 我们现在支持 for 循环！定义了 `__iter__` 方法、且其返回类型
  定义了 `__next__` 和 `__len__` 方法的类型，
  有资格在 `for el in X()` 语句中使用。当长度为零时
  控制流退出循环。

  这意味着现在可以这样写：

  ```mojo
  for item in range(start, end, step):
      print(item)
  ```

- 结果参数现在有名字了。这在引用函数返回类型中的结果
  参数时很有用：

  ```mojo
  fn return_simd[() -> nelts: Int]() -> SIMD[f32, nelts]:
  ```

- 📢 我们现在支持值参数列表中的同质可变参数，使用
  标准 Python `fn thing(*args: Int):` 语法！可变参数在
  参数列表中也受支持：

  ```mojo
  fn variadic_params_and_arguments[*a: Int](*b: Int):
      print(a[0])
      print(b[1])
  ```

- 📚 添加 range 结构体以启用 `for ... range(...)` 循环。

- 📚 引入 unroll 生成器，允许通过库函数展开循环。

## 2023-01-16 那一周

- 📢 参数上下文现已支持结构体字段引用，因此
  可以使用 `someInt.value` 取出底层的 MLIR 对象。这应当
  允许更广泛地在参数中使用第一类类型。
- 📢 我们现在支持结构体的"pretty"初始化语法，例如：

  ```mojo
  struct Int:
      var value: __mlir_type.index
      fn __new__(value: __mlir_type.index) -> Int:
          return Int {value: value}
  ```

  这消除了在结构体初始化器中直接使用 MLIR `lit.struct.create` op
  的需要。此语法将来可能变更，因为引入所有权后，
  我们那时将能支持标准 `__init__` 模型。
- 📢 现在可以为 `__mlir_op` 操作附加 region。这是
  通过一个 hack 实现的，允许一个可选的 `_region` 属性
  列出对 region 体的引用（由于缺少列表 `[]` 字面量，目前最多 1 个 region）。
- 嵌套函数现在可以解析，例如：

  ```mojo
  fn foo():
      fn bar():
          pass
      bar()
  ```

- Python 风格的 `async` 函数现在应当可用，并且 `await` 表达式
  前缀已支持。这在与异步函数协作时提供了 async/await 语法糖的
  愉悦。由于我们尚无合适的内存所有权支持，
  这目前使用起来仍有几分危险。

- 字符串字面量已支持。

- 返回处理现在由编译器内部的数据流 pass 处理，因此
  可以从 if 语句中提前返回。

- 解析器现在支持在诊断中生成 'fixit' 提示，并在字典字面量
  使用冒号而非等号时使用，例如：

  ```log
  x.mojo:8:48: error: expected ':' in subscript slice, not '='
      return __mlir_op.`lit.struct.create`[value = 42]()
                                                 ^
                                                 :
  ```

- 📚 添加对缓冲区进行操作的归约方法。

- 📚 添加更多数学函数，如 sigmoid、sqrt、rsqrt 等。

- 📚 添加 partial load / store，启用基于条件的加载与存储。

## 2023-01-09 那一周

- 函数签名中的 `/` 和 `*` 标记现已解析，并检查其
  不变量。但我们尚不支持关键字参数，
  因此它们并不太有用。
- 函数现在支持新的 `@nodebug_inline` 装饰器。
  （历史说明：它后来被 `@alwaysinline("nodebug")` 取代。）

  Mojo 栈底层的许多东西都是围绕 MLIR 对象的、
  零抽象的简单包装，例如 Int 上的 `+`
  运算符或 Bool 自身的 `__bool__` 方法。这些运算符
  需要即便在 -O0 也被强制内联，但它们有一些
  我们需要处理的问题：

  1. 用户绝不会想步入 Bool 的 `__bool__` 方法或
     Int 上的 + 方法。除非你在调试 Int 本身，否则这对调试器 QoI 会
     极其糟糕。我们需要类似
     `__always_inline__, __nodebug__` 属性，就像 clang 在
     xmmintrin.h 等头文件中使用的那样。

  2. 类似地，这些"运算符"应被用户视为原语：
     他们不想了解 MLIR 或 Int 的内部实现细节。

  3. 这些零抽象的简单东西应在编译管线早期被消除，
     以免拖慢编译器，避免用琐碎叶子节点撑爆调用图。
     这类东西会拖慢 elaborator，干扰
     fold() 等 MLIR 基础设施，撑爆 IR，或
     撑爆生成的调试信息。

  4. 在参数上下文中，我们希望其中一些被内联，
     以便被属性逻辑简化，并与规范类型更好协作。
     这对那些必须盯着生成 IR 的人而言只是锦上添花。

  解决方案是新的 `@nodebug_inline` 装饰器。该装饰器
  使解析器强制内联被调用者，而不是生成对它的调用。在此过程中，
  它将操作的位置设为调用本身（即"nodebug"部分），并剥离
  作为内部实现细节的 let 声明。

  这是面向构建标准库本身的高级超级用户功能，因此
  在能力和范围上有意受限：只能用于
  小函数，不支持 region、按引用、抛出、
  async 等。

- 另外，我们现在支持函数上的 `@alwaysInline` 装饰器。这是
  适用于任意函数的通用装饰器，表示
  该函数必须被内联。与 `@nodebug_inline` 不同，这种内联
  在编译管线后期执行。

- 现在我们已有合适的 import 支持，`__include` hack 已被移除。

- `__mlir_op` 现在可以取左值地址：

  你可以在 __mlir_op 中使用神奇的 `(((x)))` 语法，强制 `x`
  表达式为左值，并产生其地址。这提供了一种逃生舱
  （隔离在 `__mlir_op` 领域）以允许对左值地址的
  不安全访问。

- 我们现在支持 `__rlshift__` 和 `__rtruediv__`。

- 📢 解析器现在解析作用域别名引用。这允许我们支持
  诸如 `SomeType.someAlias` 之类的内容，对其值进行前向替换。这
  解除 DType 等类型中别名的使用障碍。我们最终希望在 AST 中保留
  引用，但这已解除库开发的障碍。

- 📚 添加 `now` 函数和 `Benchmark` 结构体以启用计时与
  基准测试。

- 📚 在可能时将 `NDBuffer` 中更多计算从运行时移至
  编译时（例如维度在编译时已知时）。

## 2023-01-02 那一周

- 📚 添加了 `print` 函数，可用于 Integer 和 SIMD 值。

- 前端现在有一个新的诊断子系统，被 `kgen` 工具使用（但
  测试用的 `kgen-translate` 不使用），它支持诊断中的源范围。
  之前我们输出如下错误：

  ```log
  x.mojo:13:3: error: invalid call to 'callee': in argument #0, value of type '$F32::F32' cannot be converted to expected type '$int::Int'
    callee(1.0+F32(2.0))
    ^
  x.lit:4:1: note: function declared here
  fn callee(a: Int):
  ^
  ```

  现在我们输出：

  ```log
  x.mojo:13:3: error: invalid call to 'callee': in argument #0, value of type '$F32::F32' cannot be converted to expected type '$int::Int'
    callee(1.0+F32(2.0))
    ^      ~~~~~~~~~~~~
  x.lit:4:1: note: function declared here
  fn callee(a: Int):
  ^
  ```

- 📢 结果参数现已正确支持。它们现在通过 alias 声明
  前向声明，然后在调用中用箭头绑定，例如：

  ```mojo
  alias a: __mlir_type.index
  alias b: __mlir_type.index
  idx_result_params[xyz * 2 -> a, b]()
  ```

- 修掉了隐式转换的若干小问题。例如，
  现在在参数绑定上下文以及带显式类型的
  `alias` 声明中支持隐式转换。
- 函数和结构体上允许文档字符串，但目前
  被解析器丢弃。

- 📚 添加一个 `print` 方法！！！

- 📚 在 Mojo 中演示一个朴素 matmul。

- 📚 初步开展依赖类型的工作（例如 FPUtils、nan、inf
  等）

- 📚 允许在编译时通过
  TargetInfo 查询 simd_width、os 等硬件属性。
