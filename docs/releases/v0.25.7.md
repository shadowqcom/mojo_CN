## 要点

- 已添加新的、改进的
  [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 类型，旧版本已重命名为
  `LegacyUnsafePointer`。
  新版本修复了旧 `LegacyUnsafePointer` 的若干问题。

  - `LegacyUnsafePointer` 具有允许不安全隐式
    可变性和 origin 转换的构造函数，容易意外进行不安全的更改。新的 `UnsafePointer` 消除了这些。
  - 新的 `UnsafePointer` 现在具有推断的可变性参数，
    简化了 API。
  - `UnsafePointer` 的 origin 参数没有默认值，因此
    必须显式指定或未绑定。`LegacyUnsafePointer` 默认
    为 `MutAnyOrigin`，这导致许多值的生命周期被
    不必要地延长。

  更多信息请参阅
  [指针和内存变更](#25-7-pointer-and-memory-changes)。

- 编译时错误的许多增强，包括抑制无关
  消息并为许多别名和
  参数保留更具可读性的显示。详情请参阅 [工具链变更](#25-7-tooling-changes)。

- 添加了关于
  [GPU 块和 warp 操作及同步](/docs/manual/gpu/block-and-warp/) 的新文档。

## 语言增强 {#25-7-language-enhancements}

- Mojo 现在支持 `comptime` 关键字作为 `alias` 的同义词。
  `comptime` 关键字可与 `alias` 互换用于编译时
  声明。两个关键字都完全受支持并产生相同的行为。例如：

  ```mojo
  comptime x = 5      # New preferred syntax
  alias y = 10        # Still fully supported
  comptime MyType[T: AnyType] = T  # Works with parametric declarations
  ```

  注意：未来的更新将把错误消息和内部术语迁移为
  使用 "comptime"。`alias` 关键字目前仍受支持以保持向后
  兼容。

- Mojo 现在支持在不在 struct 或 trait 中时用单个语句解包
  alias/comptime 元组。例如：

  ```mojo
  comptime i, f = (1, 3.0)
  comptime q, v = divmod(4, 5)
  ```

- [Issue #3925](https://github.com/modular/modular/issues/3925)：Mojo 现在允许
  方法根据 "owned" 与 "by-ref" 参数约定进行重载，
  当给定 owned 值时选择 owned 重载，否则
  选择 by-ref 版本。这允许略微更高效的算法，
  例如消耗 vs 借用迭代器：

  ```mojo
  struct MyCollection:
    fn __iter__(var self) -> Self.ConsumingIterator: ...
    fn __iter__(self) -> Self.BorrowingIterator: ...
  ```

- 集合字面量现在具有默认类型。例如，你现在可以
  在对定义为
  `fn zip[T: Iterable](impl:T)` 的函数调用中将
  `[1,2,3]` 绑定到 `T`，因为它将默认为标准
  库的 `List` 类型。

- Mojo 现在具有 `__functions_in_module()` 实验性内联函数，允许对
  调用它的模块中声明的函数进行
  反射。例如：

  ```mojo
  fn foo(): pass

  def bar(x: Int): pass

  def main():
    alias funcs = __functions_in_module()
    # equivalent to:
    alias same_funcs = Tuple(foo, bar)
  ```

  该内联函数目前仅限于从 `main()` 函数内使用。
  有关在测试套件中使用 `__functions_in_module()` 的示例，请参阅
  [使用 TestSuite 运行测试](/docs/tools/testing/#running-tests-with-testsuite)

- `@implicit` 装饰器现在接受可选的 `deprecated` 关键字
  参数。这可用于逐步淘汰隐式转换，而不是仅
  移除装饰器（这可能导致另一条意外的隐式
  转换路径）。例如，编译器现在会警告以下内容：

  ```mojo
  struct MyStuff:
    @implicit(deprecated=True)
    fn __init__(out self, value: Int):
      pass

  fn deprecated_implicit_conversion():
    # warning: deprecated implicit conversion from 'IntLiteral[1]' to 'MyStuff'
    _: MyStuff = 1

    _ = MyStuff(1)  # this is okay, because the conversion is already explicit.
  ```

- `@deprecated` 装饰器现在可以使用 `use`
  关键字参数接受目标符号。这与现有的位置
  字符串参数互斥。将自动生成弃用警告。

  ```mojo
  @deprecated(use=new)
  fn old():
    pass

  fn new():
    pass

  fn main():
    old() # 'old' is deprecated, use 'new' instead
  ```

- 在声明参数化 `__call__()` 方法但没有
  下标方法（`__getitem__()`、`__setitem__()` 或
  `__getattr__()`）之一的 struct 实例中，现在可以
  使用参数调用 `__call__()` 方法：

  ```mojo
  struct Callable:
    fn __init__(out self):
      pass

    fn __call__[x: Int](self, y: Int) -> Int:
      return x + y

    fn main():
      var c = Callable()
      print(c[1](2)) # 3
  ```

  此前你必须显式查找 `__call__()`：

  ```mojo
  print(c.__call__[1](2))
  ```

- 添加了 `DType.float4_e2m1fn` 作为 4 位浮点 `e2m1` 格式。此
  `Float4_e2m1` 类型由
  [Open Compute MX 规范](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf) 定义。

- `deinit` 方法现在可以将整个 `self` 转移到另一个 `deinit` 方法。

- Mojo 现在在使用
  `mojo build --sanitize address` 构建的程序中使用系统分配器。这意味着 ASan 可以看到 Mojo 堆分配
  并应能够检测到更多堆内存错误。

## 语言变更 {#25-7-language-changes}

- `__type_of()` 魔术函数已重命名为 `type_of()`。使用旧
  拼写将产生错误。类似地，`__origin_of()` 已重命名
  为 `origin_of()`。

- 像 `(Int, Float64)` 这样的表达式不再像
  `Tuple[Int, Float64]` 这样的元组类型的语法糖。

## 库变更 {#25-7-library-changes}

### 指针和内存变更 {#25-7-pointer-and-memory-changes}

- `UnsafePointer` 已重命名为 `LegacyUnsafePointer`，新的
  [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 已
  [取代它](https://forum.modular.com/t/proposal-unsafepointer-v2/2411?u=nate)。
  类似地，`OpaquePointer` 已重命名为 `LegacyOpaquePointer`，新的
  [`OpaquePointer`](/docs/std/memory/unsafe_pointer/#opaquepointer) 已
  取代它。主要区别在于参数的顺序，现在
  如下所示：

  ```mojo
  struct UnsafePointer[
    mut: Bool, //, # Inferred mutability
    type: AnyType,
    origin: Origin[mut], # Non-defaulted origin
    *,
    address_space: AddressSpace = AddressSpace.GENERIC,
  ]

  alias OpaquePointer[
    mut: Bool, //, # Inferred mutability
    origin: Origin[mut], # Non-defaulted origin
    *,
    address_space: AddressSpace = AddressSpace.GENERIC,
  ] = UnsafePointer[NoneType, origin, address_space=address_space]
  ```

  其隐式构造函数不再允许具有不同
  可变性和 origin 值的指针之间的不安全转换。代码需要
  更新到新的 `UnsafePointer`，但是，在过渡期间，用户可以
  查找并替换其当前使用 `UnsafePointer` 的地方并将它们重命名为
  `LegacyUnsafePointer`。另一个选项是用户可以在
  依赖旧指针类型的任何文件开头添加以下导入
  语句：

  ```mojo
  from memory import LegacyUnsafePointer as UnsafePointer, **_]
  # and/or if you use OpaquePointer
  from memory import LegacyOpaquePointer as OpaquePointer
  ```

  用户还可以使用 `as_legacy_pointer()` 和 `as_unsafe_pointer()`
  转换方法在此
  迁移期间在两种指针类型之间转换。

  *注意*：`LegacyUnsafePointer` 和 `LegacyOpaquePointer` 最终将
  在未来的 Mojo 版本中被弃用和移除。

  为 `UnsafePointer` 提供了一些有用的新类型别名：
  - `MutUnsafePointer`
  - `ImmutUnsafePointer`
  - `MutOpaquePointer`
  - `ImmutOpaquePointer`

  最后，[`alloc()`](/docs/std/memory/unsafe_pointer/alloc/) 已
  从 `UnsafePointer` 上的静态方法移至独立的 `alloc()` 函数。
  因此，写为：

  ```mojo
  var ptr = UnsafePointer[Int].alloc(3)
  ```

  的代码必须更改为：

  ```mojo
  var ptr = alloc[Int](3)
  ```

  有关迁移到新 `UnsafePointer` 的更多详情，请参阅
  以下内容提供的迁移指南：
  <!-- rumdl-disable-next-line MD013 -->
  [UnsafePointer v2 提案](https://github.com/modular/modular/blob/main/mojo/proposals/unsafe-pointer-v2.md#migration-guide-from-legacyunsafepointer-to-the-new-unsafepointer)。

- 为 `UnsafePointer` 添加了 `swap_pointees()` 函数，作为当指针可能
  互相别名时 `swap()` 的替代方案。

- 针对
  [`LayoutTensor`](/docs/layout/layout_tensor/LayoutTensor/)、
  `NDBuffer` 和 `UnsafePointer` 的 `origin_cast()` 已
  被弃用并移除。`LayoutTensor` 和 `NDBuffer` 现在支持更安全的
  `as_any_origin()` origin 转换方法。`UnsafePointer` 具有相同的安全
  替代方案，此外，它具有安全的 `as_immutable()`
  转换函数和显式不安全的 `unsafe_mut_cast()` 和
  `unsafe_origin_cast()` 转换方法。

- `empty` origin 已重命名为 `external`。此 origin 表示
  Mojo 生命周期检查器不跟踪的值。从
  `alloc()` 新分配的内存以 origin `MutOrigin.external` 返回。

- 将 `MutableOrigin` 重命名为 `MutOrigin`，将 `ImmutableOrigin` 重命名为 `ImmutOrigin`。

- 将 `MutableAnyOrigin` 重命名为 `MutAnyOrigin`，将 `ImmutableAnyOrigin` 重命名为
  `ImmutAnyOrigin`。

- 不带
  关键字参数的 [`memcpy()`](/docs/std/memory/memory/memcpy/) 和
  [`parallel_memcpy()`](/docs/std/algorithm/memory/parallel_memcpy/) 已弃用。

### 集合和迭代器

- [`Span`](/docs/std/memory/span/Span/) 和
  [`StringSlice`](/docs/std/collections/string/string_slice/StringSlice/)
  构造函数现在接受 `Int` 作为长度参数而不是 `UInt`。此
  变更使这些类型更易于与整数字面量和其他
  基于 `Int` 的 API 一起使用。

- 添加了 `Span.binary_search_by()`，允许使用自定义
  比较器函数进行二分搜索。

- 向
  `Span` 结构体添加了 `unsafe_get()`、`unsafe_swap_elements()` 和 `unsafe_subspan()`。

- [`Optional`](/docs/std/collections/optional/Optional/) 现在符合
  `Iterable` 和 `Iterator`，作为大小为 1 或 0 的集合。

- 新的 [`ContiguousSlice`](/docs/std/builtin/builtin_slice/ContiguousSlice/)
  和
  [`StridedSlice`](/docs/std/builtin/builtin_slice/StridedSlice/)
  类型已添加到 `builtin_slice` 模块，以支持
  无步长切片的特化。

- 不带步长的 [`List`](/docs/std/collections/list/List/) 切片现在
  返回 `Span`，而不是 `List`，并且不再分配内存。

- 若干标准库 API 已更新为使用 `Int` 而不是 `UInt`
  以改善人机工程性，消除了使用
  `Int` 值（整数字面量和循环索引的默认类型）时显式转换的需要：
  - `BitSet[size: Int]` - 将参数从 `UInt` 更改为 `Int`
  - `BitSet.set(idx: Int)`、`BitSet.clear(idx: Int)`、`BitSet.toggle(idx: Int)`、
    `BitSet.test(idx: Int)` - 从 `UInt` 更改为 `Int`
  - `String(unsafe_uninit_length: Int)` - 从 `UInt` 更改为 `Int`
  - `String.capacity() -> Int` - 将返回类型从 `UInt` 更改为 `Int`
  - `String.reserve(new_capacity: Int)` - 从 `UInt` 更改为 `Int`
  - `List(length: Int, fill: T)` - 从 `UInt` 更改为 `Int`
  - `Codepoint.unsafe_write_utf8() -> Int` - 将返回类型从 `UInt` 更改为
    `Int`
  - `Codepoint.utf8_byte_length() -> Int` - 将返回类型从 `UInt` 更改为
    `Int`

- 向
  `itertools` 模块添加了 [`repeat()`](/docs/std/itertools/itertools/repeat/) 函数，该函数创建一个迭代器，将元素重复指定
  次数。与 Python 的 `itertools.repeat()` 不同，无限
  迭代目前不支持 - 需要 `times` 参数。
  示例用法：

  ```mojo
  from itertools import repeat

  for val in repeat(42, times=3):
      print(val)  # Prints: 42, 42, 42
  ```

- 如果元素类型也可
  比较，则元组现在支持比较操作。例如，现在可以编写 `(1, "a") == (1, "a")` 或
  `(1, "a") < (1, "b")`。

### 字符串和文本

- [`Codepoint`](/docs/std/collections/string/codepoint/Codepoint/) 现在
  符合 [`Writable`](/docs/std/format/Writable/)。

- `Codepoint` 现在符合
  [`Comparable`](/docs/std/builtin/comparable/Comparable/)，添加了 `__le__()`、
  `__lt__()`、`__ge__()` 和 `__gt__()` 实现。

### 数学及数值类型

- 已弃用的 `DType.index` 现已被移除，由
  [`DType.int`](/docs/std/builtin/dtype/DType/#int) 取代。

- 添加了 `DType.float4_e2m1fn` 作为 4 位浮点 `e2m1` 格式。此
  `Float4_e2m1` 类型由
  [Open Compute MX 规范](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf) 定义。

- `math.isqrt()` 已重命名为 [`rsqrt()`](/docs/std/math/math/rsqrt/)，
  因为它执行倒数平方根功能。

- [`math`](/docs/std/math/math/) 包现在具有 `acos()`、`asin()`、`cbrt()` 和 `erfc()` 的 Mojo 原生
  实现。

- [`SIMD`](/docs/std/builtin/simd/SIMD/) 现在实现
  [`DivModable`](/docs/std/math/math/DivModable/) trait。

- `Int` 和 `UInt` 之间的隐式转换现已弃用。

  在未来版本的 Mojo 中，将移除 `Int.__init__(UInt)` 和 `UInt.__init__(Int)` 上的
  `@implicit` 装饰器。当前执行
  `Int` 和 `UInt` 之间隐式转换的代码将发出弃用
  警告，并应更新为显式读取 `Int(uint_val)` 或
  `UInt(int_val)`。

- `ImplicitlyIntable` trait 已被移除。实现此 trait 的类型
  可被隐式转换为 `Int`。

  `Bool` 是唯一实现
  `ImplicitlyIntable` 的 Mojo 标准库类型。从 `Bool` 到 `Int` 的转换现在可以
  显式执行，使用 `Int(bool-val)`（通过剩余的 `Intable` trait，该 trait 仅
  支持*显式*转换）。

### GPU 支持

- 添加了对 NVIDIA GeForce GTX 970 的支持。

- [`gpu.sync.syncwarp()`](/docs/std/gpu/sync/sync/syncwarp/) 现在
  通过 `SIMDGROUP` 屏障实现支持
  Apple GPU。在 Apple GPU 上，这
  使用 `SIMDGROUP`
  屏障为所有活动通道提供执行同步，无内存围栏。对于线程组内存排序，请
  改为使用
  [`barrier()`](/docs/std/gpu/sync/sync/barrier/)。请注意，Apple GPU 上不支持通道
  掩码，因此忽略掩码参数。

- [`gpu.primitives.warp`](/docs/std/gpu/primitives/warp/) 现在
  支持具有原生 SIMD-group shuffle 操作的 Apple
  GPU。这在 Apple 硬件上启用 `shuffle_idx()`、
  `shuffle_up()`、`shuffle_down()` 和 `shuffle_xor()`，方法
  是将 Metal `simd_shuffle*` 内联函数映射到 AIR
  （`llvm.air.simd_shuffle[_up/_down/_xor]`）指令，实现与 NVIDIA 和 AMD 后端的特性
  一致。

- [`gpu.intrinsics.store_release()`](/docs/std/gpu/intrinsics/store_release/)
  和
  [`gpu.intrinsics.load_acquire()`](/docs/std/gpu/intrinsics/load_acquire/)
  现在支持 Apple silicon GPU，扩展了这些设备上正确内存
  同步的支持。

- [`gpu`](/docs/std/gpu/) 包已重新组织为逻辑
  子目录，以更好地组织代码：
  - `gpu/primitives/` - 低级 GPU 执行原语（warp、block、
    cluster、id、grid_controls）
  - `gpu/memory/` - 内存操作（async_copy、TMA、地址空间）
  - `gpu/sync/` - 同步原语（屏障、信号量）
  - `gpu/compute/` - 计算操作（mma、tensor cores、tcgen05）

  **向后兼容性**：所有现有导入继续不变地工作。
  已弃用的导入路径（`gpu.id`、`gpu.mma`、`gpu.cluster`、
  `gpu.grid_controls`、`gpu.warp`、`gpu.semaphore`、`gpu.mma_sm100`、
  `gpu.tcgen05`、`gpu.mma_util`、`gpu.mma_operand_descriptor` 和
  `gpu.tensor_ops`）保留为带有弃用
  通知的重新导出包装器。用户可以按自己的
  节奏迁移到新的推荐导入模式：

  ```mojo
  # Old (deprecated but still works):
  from gpu.id import block_idx, thread_idx
  from gpu.mma import mma
  from gpu.mma_sm100 import UMMAKind
  from gpu.tcgen05 import tcgen05_alloc
  from gpu.semaphore import Semaphore
  from gpu.cluster import cluster_sync

  # New (recommended):
  from gpu import block_idx, thread_idx, cluster_sync
  from gpu.compute.mma import mma
  from gpu.compute.mma_sm100 import UMMAKind
  from gpu.compute.tcgen05 import tcgen05_alloc
  from gpu.sync.semaphore import Semaphore
  ```

- `_GPUAddressSpace` 类型已被移除并合并到
  [`AddressSpace`](/docs/std/memory/pointer/AddressSpace/) 中。GPU 特定
  地址空间常量（`GLOBAL`、`SHARED`、`CONSTANT`、`LOCAL`、
  `SHARED_CLUSTER`）现在作为统一 `AddressSpace`
  类型上的别名可用。`GPUAddressSpace` 别名也已移除，改为
  直接使用 `AddressSpace`。由于 `AddressSpace` 是 prelude 的一部分，在大多数代码中不再需要显式导入
  它。

- TMA（Tensor Memory Accelerator）类型已移至专用模块。
  类型 `TMADescriptor`、`TensorMapSwizzle`、`TensorMapDataType`、
  `TensorMapInterleave`、`TensorMapL2Promotion`、`TensorMapFloatOOBFill` 和
  函数 `create_tma_descriptor()` 和 `prefetch_tma_descriptor()` 现在可从
  [`gpu.host.nvidia.tma`](/docs/std/gpu/host/nvidia/tma/) 获取，
  而不是 `gpu.host._nvidia_cuda`。

### 测试 {#25-7-testing}

- [`assert_equal()`](/docs/std/testing/testing/assert_equal/) 现在
  在字符串比较失败时显示
  彩色逐字符差异，使
  发现差异更容易。差异字符在
  左字符串中以红色突出显示，在右字符串中以绿色突出显示。

- `mojo test` 命令已被移除。推荐的测试策略是
  定义测试函数，从 `main()` 显式调用它们（或使用新的
  `TestSuite` 框架），并使用 `mojo run` 运行。

- [`TestSuite`](/docs/std/testing/suite/TestSuite/) 现在可以使用 `.generate_report()` 生成测试
  报告。此外，添加了 `TestReport` 和 `TestSuiteReport`
  结构体。

- `TestSuite` 现在允许使用
  `TestSuite.skip()` 方法显式跳过已注册的测试。

- `TestSuite` 现在允许从 CLI 参数进行基本控制。可以通过在
  `--skip` 标志后传递测试函数名称从 CLI 跳过测试，例如

  ```console
  mojo run test_my_stuff.mojo --skip test_currently_failing test_also_failing
  ```

  类似地，`--only` 标志启用允许列表的规范，例如
  以下将跳过任何其他已注册的测试用例：

  ```console
  mojo run test_my_stuff.mojo --only test_only_this test_this_as_well
  ```

  `--skip-all` 标志将跳过套件中所有已注册的测试用例。请注意
  `--only` 尊重跳过的测试，即它不运行使用
  `TestSuite.skip()` 跳过的测试。

### 系统和 OS

- 添加了 [`os.isatty()`](/docs/std/os/os/isatty/) 函数以检查
  文件描述符是否指向终端。此函数接受 `Int` 文件
  描述符。如果你有
  [`FileDescriptor`](/docs/std/io/file_descriptor/FileDescriptor/) 对象，
  请改用其 `isatty()` 方法。

- 添加了
  [`sys.compile.SanitizeAddress`](/docs/std/sys/compile/#sanitizeaddress)，
  为 Mojo 代码提供在编译时检测 `--sanitize address` 的方式。

- `DLHandle` 不再是公共 API 的一部分。要从 Mojo 访问动态链接
  库，请改为使用 [`OwnedDLHandle`](/docs/std/ffi/OwnedDLHandle/)。
  新类型为动态链接库提供基于 RAII 的自动资源管理。`DLHandle` 已重命名为 `_DLHandle` 并
  保持内部可用以供标准库使用。

### 性能优化

- 通过消除不必要的
  栈分配来优化浮点到字符串格式化性能。用于浮点格式化的内部查找表
  （`cache_f32` 和 `cache_f64`）现在存储为全局常量，而不是
  为每次转换在栈上实体化。这将 `Float64` 的栈
  开销减少约 10KB，将 `Float32` 的栈开销减少约 600 字节，
  改善所有浮点格式化操作的性能，包括 `print()`、
  字符串插值和 `str()` 转换。

- 通过消除大型查找表的栈分配来优化数字解析性能。用于数字解析的内部查找表
  （`powers_of_5_table` 和 `POWERS_OF_10`）现在使用
  [`global_constant`](/docs/std/builtin/globals/global_constant/)
  函数存储为全局常量，而不是
  为每次解析操作在栈上实体化。这将数字解析
  操作的栈开销减少约 10.6KB，改善字符串到数字转换的性能，包括
  `atof()` 和相关浮点解析操作。

### 其他库变更

- [`Hasher`](/docs/std/hashlib/hasher/Hasher/) trait 的
  `_update_with_bytes()` 方法现在接受 `Span[Byte]` 而不是
  `UnsafePointer[UInt8]` 和单独的长度参数。此变更适用于
  所有哈希器实现，包括 `AHasher` 和 `Fnv1a`。

- Philox 随机数生成器（`Random` 和 `NormalRandom`）已
  从 `gpu.random` 移至 [`random.philox`](/docs/std/random/philox/)。
  这些类型现在在 CPU 和 GPU 上都工作。使用
  `from random import Random, NormalRandom` 或
  `from random.philox import Random, NormalRandom` 导入它们。

## 工具链变更 {#25-7-tooling-changes}

- 错误和警告消息现在在许多情况下保留 `comptime`/alias 名称，
  以防止复杂类型的极长类型名称。编译器将
  根据简单的
  启发式在需要时展开这些以理解类型，例如：

  ```mojo
  struct Dep[T: AnyType, v: T]: pass
  alias MyDep[T: AnyType, v: T] = Dep[T, v]
  alias MyDepGetAlias0 = MyDep.hello
  ```

  产生：

  ```console
  $ mojo t.mojo
  t.mojo:10:29: error: 'MyDep' needs more parameters bound before accessing attributes
  alias MyDepGetAlias0 = MyDep.hello
                            ^
  t.mojo:10:29: note: 'MyDep' is aka 'alias[T: AnyType, v: T] Dep[T, v]'
  ```

  请在需要公开更多信息的情况下提交 issue。

- 错误消息现在保留对 `always_inline("builtin")`
  函数的符号调用，而不是将它们内联到错误消息中。

- 此版本包含对 elaboration 错误的若干改进。
  *elaborator* 是确定最终参数值并将代码从
  参数化转换为具体的编译器阶段。来自
  elaboration 的常见错误包括 "function instantiation failed" 和 "call expansion
  failed" 消息，当确定实际参数值不
  匹配任何可行函数重载时。

  elaborator 还检查约束（使用
  [`constrained()`](/docs/std/builtin/constrained/constrained/) 函数定义），因此
  在此阶段生成约束失败。

  - Elaboration 错误现在报告完整的调用实例化失败路径。
    对于此 Mojo 文件：

    ```mojo
    fn fn1[T: ImplicitlyCopyable, //] (a: T):
        constrained[False]()
    fn fn2[T: ImplicitlyCopyable, //] (a: T):
        return fn1(a)
    fn main():
        fn2(1)
    ```

    现在错误打印 `main -> fn2 -> fn1 -> constrained[False]` 的路径
    而不仅仅是 `constrained[False]`。

  - Elaboration 错误现在打印出调用
    展开失败的平凡参数值。对于此简单 Mojo 程序：

    ```mojo
    fn fn1[a: Int, b: Int]():
        constrained[a < b]()

    fn fn2[a: Int, b: Int]():
        fn1[a, b]()

    fn main():
        fn2[4, 2]()
    ```

    现在错误消息显示 `parameter value(s): ("a": 4, "b": 2)`：

    ```mojo
    test.mojo:6:14: note: call expansion failed with parameter value(s): ("a": 4, "b": 2)
        fn1[a, b]()
    ```

    默认情况下现在仅打印字符串和数值，其他
    值显示为 `...`。使用 `--elaboration-error-verbose` 显示所有
    参数值。

  - 默认情况下省略与 prelude 相关的 elaboration 错误消息。
    prelude 是从 `std/builtin/_startup.mojo` 导出的 API 集。
    这些 API 持续存在于所有调用展开路径中，但很少是报告
    错误的来源。现在默认省略这些 API 以清理
    elaboration 错误。

    使用 `--elaboration-error-include-prelude` 包含 prelude。

    - 默认（无 prelude）：

      ```mojo
      test.mojo:43:4: error: function instantiation failed
        fn main():
          ^
      test.mojo:45:12: note: call expansion failed
            my_func()
      ...
      ```

    - 带 prelude：

      ```mojo
      oss/modular/mojo/stdlib/std/builtin/_startup.mojo:119:4: error: function instantiation failed
      fn __mojo_main_prototype(
        ^
      oss/modular/mojo/stdlib/std/builtin/_startup.mojo:119:4: note: call expansion failed with parameter value(s): (...)
      oss/modular/mojo/stdlib/std/builtin/_startup.mojo:42:4: note: function instantiation failed
      fn __wrap_and_execute_main[
        ^
      oss/modular/mojo/stdlib/std/builtin/_startup.mojo:68:14: note: call expansion failed
          main_func()
                  ^
      test.mojo:43:4: note: function instantiation failed
      fn main():
        ^
      test:45:12: note: call expansion failed
          my_func()
      ...
      ```

  - 已向 `mojo run` 和
    `mojo build` 命令添加 `--elaboration-error-limit` 选项。此选项设置打印的 elaboration
    错误数量限制。默认值为 20。要更改限制，请使用
    <code>--elaboration-error-limit=</code><var>limit</var>，其中 *limit* 为
    `0` 表示无限制。

- 已向所有 Mojo CLI 命令添加 `--help-hidden` 选项以显示隐藏
  选项。

- `mojo debug` 现在拒绝 `debug` 与目标之间的未知选项。

- Mojo 语言服务器现在将报告更连贯的代码操作。

- `mojo` CLI 现在具有 `--experimental-fixit` 标志，可自动
  应用解析器发出的 FixIt 提示。此功能高度
  实验，用户应确保他们备份文件（或将其签入
  源代码控制）后再使用它。

## 已移除 {#25-7-removed}

- `mojo test` 已弃用并按
  [弃用提案](https://forum.modular.com/t/proposal-deprecating-mojo-test/2371) 中所述移除。
  有关更多信息，请参阅 [测试](#25-7-testing) 章节。

- `LayoutTensorBuild` 类型已被移除。请改为直接使用带参数的 `LayoutTensor`。

- 以下 trait 已被移除：`LessThanComparable`、
  `GreaterThanComparable`、`LessThanOrEqualComparable`、
  `GreaterThanOrEqualComparable`。类型只实现其中一个的情况极其罕见，因此可以直接使用 `Comparable` 代替。

- 所有与遥测相关的代码已从 Mojo 编译器中移除。这
  应消除在不良互联网连接上某些挂起和不当行为的
  来源。

## 已修复 {#25-7-fixed}

- [Issue #5111](https://github.com/modular/modular/issues/5111)：
  `math.cos()` 和 `math.sin()` 函数现在可以在编译时求值。

- 修复了当元素以嵌套单元素元组存储时 `IntTuple.value(i)` 方法返回不正确值的问题。此前，调用
  `Layout.row_major(M, N).stride.value(i)` 会返回负偏移值
  （例如 -65536、-65537）而不是实际步长值。这影响任何
  使用 `value()` 方法访问布局步长或形状值的代码。

- 修复了 `LayoutTensor.shape[idx]()` 方法对嵌套
  布局返回不正确值的问题。当访问具有
  像 `((32, 2), (32, 4))` 这样的嵌套布局的张量的形状维度时，bug 会出现，该方法会返回
  无用值而不是正确的乘积（例如 64）。

- 修复了具有不同内存布局的张量之间
  `LayoutTensor` 元素算术操作（`+`、`-`、`*`、`/`）。此前，当操作数具有
  不同布局时，像 `a.transpose() - b` 这样的操作会产生不正确的结果，因为两个操作数都错误地使用了相同的布局索引。
  现在根据每个张量的布局正确计算每个张量的单独索引。

- 修复了 `LayoutTensor.shape[idx]()` 方法对嵌套
  布局返回不正确值的问题。当访问具有
  像 `((32, 2), (32, 4))` 这样的嵌套布局的张量的形状维度时，bug 会出现，该方法会返回
  无用值而不是正确的乘积（例如 64）。

- 修复了 `layout._fillers` 中的 `arange()` 函数以正确处理嵌套
  布局结构。此前，当使用
  像
  `Layout(IntTuple(IntTuple(16, 8), IntTuple(32, 2)), ...)` 这样的嵌套布局填充张量时，函数会失败，因为它
  尝试错误地从嵌套元组中提取形状值。

- [Issue #5479](https://github.com/modular/modular/issues/5479)：当编译没有 struct 上下文的独立 `__del__` 函数时，Mojo 崩溃。

- [Issue #5500](https://github.com/modular/modular/issues/5500)：添加了
  `gpu/host/info.mojo` 的全面文档，解释 GPU 目标
  配置和 LLVM 数据布局字符串。文档现在包括
  所有 MLIR 目标组件的详细说明、NVIDIA/AMD/Apple GPU 的特定供应商模式、添加新 GPU
  架构的分步指南，以及获取数据布局字符串的实用方法。

- [Issue #5492](https://github.com/modular/modular/issues/5492)：修复了
  `FileHandle` "rw" 模式意外截断文件内容的问题。使用
  `open(path, "rw")` 打开文件现在正确保留现有文件内容并
  允许读取和写入，类似于 Python 的 "r+" 模式。此前，
  "rw" 模式会立即截断文件，使读取
  现有内容并可能导致数据丢失成为不可能。

- [Issue #3849](https://github.com/modular/modular/issues/3849)：添加了打开文件时对追加模式（"a"）的支持。`open()` 函数现在接受
  "a" 作为有效模式，该模式打开文件以追加。写入以追加模式打开的文件的内容被添加到文件末尾，不截断
  现有内容。如果文件不存在，将创建它。

- [Issue #3208](https://github.com/modular/modular/issues/3208)：修复了
  以写入模式打开
  FIFO（命名管道）时 `FileHandle` 引发 "unable to remove existing file" 错误的问题。使用 `open(path, "w")` 打开特殊文件（如 FIFO、设备和
  套接字）现在工作正常。此前，
  写入模式会尝试在打开文件之前删除现有文件，这对于
  不应删除的特殊文件会失败。

- [Issue #5142](https://github.com/modular/modular/issues/5142)：
  `sys.intrinsics.compressed_store` 函数现在包含 `debug_assert` 以
  捕获 null 指针使用，提供清晰的错误消息而不是以段错误
  崩溃。

- `sys.intrinsics.strided_load()`、`sys.intrinsics.strided_store()`、
  `sys.intrinsics.masked_load()` 和 `sys.intrinsics.masked_store()` 函数
  现在包含 `debug_assert()` 以捕获 null 指针使用，提供清晰的错误消息而不是以段错误
  崩溃。

- `logger` 包现在以彩色打印其级别。

- 引发 `deinit` 方法现在理解 `self` 在错误
  路径中已去初始化，避免对隐式析构函数的冗余调用并改善线性
  类型支持。
