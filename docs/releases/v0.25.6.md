:::caution 版本方案变更！

此版本在技术上是一个版本 *降级*，因为我们在
开头添加了 `0.`：`0.25.6`。这是必要的，因为我们开始
在 pypi.org 上发布 `mojo`
包，重要的是我们尚未发布大于 1.0 的包。

在 0.25.6 版本发布后不久，我们 "yank"（撤回）了所有
大于 1.0 的 Conda 包，这样除非你显式指定
版本，否则它们不会被安装。因此你仍会得到最新版本，如下所示：

```sh
pixi add mojo
```

如果你想要旧版本，只需指定版本，如下所示：

```sh
pixi add "mojo==25.5"
```

但是，如果你使用 `pip` 或
`uv` 将 `mojo` 安装为 Python 包，可用的最旧版本是 `0.25.6`。

:::

## 要点 {#25-6-highlights}

- 你现在可以 **`pip install mojo`**！

  虽然我们仍然喜欢 [Pixi](/pixi) 的环境可靠性，
  但使用 `pip` 或 `uv` 安装 Mojo 进一步增强了我们与
  Python 生态系统的互操作性，使你更容易[用 Mojo 扩展你的 Python
  代码](/docs/manual/python/mojo-from-python)。更多信息请参阅
  [Mojo 安装指南](/install/)。

- 我们发布了新版本的 Mojo Visual Studio Code 扩展，现在可以
  与稳定版和 nightly Mojo 版本**同时**工作。你可以从
  [Visual Studio Code Marketplace](https://marketplace.visualstudio.com/items?itemName=modular-mojotools.vscode-mojo)
  或
  [Open VSX Registry](https://open-vsx.org/extension/modular-mojotools/vscode-mojo)
  安装 Mojo 扩展。

  新扩展替换了旧的稳定版本，因此如果你安装了
  稳定版本，只需更新即可获得新版本。如果你安装了
  nightly 版本的扩展，应卸载它并
  安装常规（非 nightly）版本。

- 新的 [Mojo 愿景](/docs/vision/) 文档解释了我们对 Mojo 语言的动机和设计
  决策。

- 新的 [Mojo 路线图](/docs/roadmap/) 提供了跨多个阶段的
  语言高级路线图。

- Mojo 现在支持默认 trait 方法，允许 trait 提供可重用的
  行为，而无需每个符合要求的 struct 重新实现
  它。默认方法会被符合要求的 struct 自动继承，除非
  显式覆盖。更多信息请参阅 Mojo 手册中的
  [默认方法实现](/docs/manual/traits/#default-method-implementations)。

- 添加了对许多消费级 GPU 的支持，包括对 Apple
  silicon GPU 的初始支持。详情请参阅 [GPU 支持](#25-6-gpu-support)。

- Mojo 中建模复制的方式已全面重构。`Copyable` trait
  已更新为表示可以 *显式* 复制的类型（使用
  `copy()` 方法），并且新的 `ImplicitlyCopyable` "标记" trait 可用于
  *选择加入* 使类型也可隐式复制。**这会将
  默认行为从隐式可复制切换为仅显式
  可复制。** 若干标准库 trait、类型和函数现在
  要求显式 `Copyable` 而不是 `ImplicitlyCopyable`。更多
  信息请参阅
  [标准库变更](#25-6-standard-library-changes)。

- Mojo 程序中未捕获的异常或段错误现在可以
  生成堆栈跟踪。这目前仅适用于基于 CPU 的代码。要生成
  完全符号化的堆栈跟踪，请设置 `MOJO_ENABLE_STACK_TRACE_ON_ERROR`
  环境变量，使用 `mojo build` 启用调试信息（例如
  `-debug-level=line-tables`），然后运行生成的二进制文件。

- 重大标准库改进包括：

  - 使 `SIMD` 类型符合 `Comparable` 和 `EqualityComparable`，
    这意味着你可以将 `SIMD` 值用作 `Dict` 键等。详情
    请参阅
    [SIMD 及相关类型](#25-6-simd-and-related-types)。

  - 新的 `Some[Trait]` 工具，使
    声明符合 trait 的参数更容易。详情请参阅
    [其他标准库变更](#25-6-other-standard-library-changes)。

  - 对 Mojo 中迭代器工作方式的若干增强，包括新的
    `Iterable` trait。更多信息请参阅
    [集合和迭代器变更](#25-6-collections-and-iterators-changes)。

## 语言增强 {#25-6-language-enhancements}

- Mojo 现在允许在函数名中（在 `def` 和 `fn` 之后）以及在
  `.` 之后的属性引用中使用关键字。这特别允许在
  正则表达式库中使用 `match()` 方法，即使 Mojo 将其作为硬
  关键字。在其他位置的使用仍可使用反引号：

  ```mojo
  struct MatchExample:
      fn match(self): # This is ok now.
          pass

  fn test_match(a: MatchExample):
      a.match() # This is ok now.
      a.`match`() # This is still valid.
  ```

- 当为涉及参数调用的复杂类型生成错误消息时，
  Mojo 编译器现在会正确打印函数参数值，消除了
  GPU 布局中发生的一大类 `T != T` 错误。

## 语言变更 {#25-6-language-changes}

- struct 上的方法现在可以使用 `deinit`
  参数约定声明其 `self` 参数。此参数约定用于
  `__del__()` 和 `__moveinit__()` 等方法，以指示它们
  拆除相应的值而无需再次运行其析构函数。除
  这两种方法外，此约定还可用于声明 "命名" 析构函数，
  这是不运行值析构函数自身而消耗并销毁值的方法。例如，标准的
  [`VariadicPack`](/docs/std/builtin/variadics/VariadicPack/) 类型具有这些
  方法：

  ```mojo
  struct VariadicPack[...]:
      # implicit destructor
      fn __del__(deinit self): ...
      # move constructor
      fn __moveinit__(out self, deinit existing: Self): ...
      # custom explicit destructor that destroys "self" by transferring all of
      # the stored elements.
      fn consume_elements[
        elt_handler: fn (idx: Int, var elt: element_type) capturing
    ](deinit self): ...
  ```

  此参数约定是一个相当窄的 power-user 功能，用于
  澄清销毁模型并使线性类型更好地适应
  模型。（线性类型只是一种没有 `__del__()` 方法的
  类型，但提供了用户必须显式调用的析构函数。线性类型是
  尚未完全实现的提议特性。）

  - `__del__()` 和 `__moveinit__()` 方法现在应将其 `self`
    和 `existing` 参数作为 `deinit` 而不是 `owned` 或 `var`。

  - `__disable_del` 关键字和语句已被移除，请使用 `deinit`
    方法。

- Mojo 编译器现在会警告使用已弃用的 `owned` 关键字，
  请按警告所示迁移到 `var` 或 `deinit`。

- 之前已弃用的 `@value` 装饰器已被移除。

- 在 trait 中访问关联别名和方法现在需要
  限定引用（前缀 `Self.`），使其与
  struct 中访问成员别名和方法需要 `self.` 的方式一致。

- 当隐式实体化非 `ImplicitlyCopyable` 对象时，Mojo 编译器现在会引发错误，请将类型标记为
  `ImplicitlyCopyable` 或使用 `materialize[value: T]()` 显式
  将参数实体化为动态值。

  这通常发生在你使用 `alias`
  关键字生成编译时值，然后将其赋值给运行时变量时：

  ```mojo
  alias lst = [1, 2, 3, 4]  # Create a compile-time list value
  var dyn_list = lst  # Implicitly materializes the compile-time value to a
                      #  dynamically-allocated runtime value
  ```

  别名是编译时临时值；要将其赋值给运行时
  变量，Mojo 必须分配内存并复制值。由于这可能在实体化像
  列表这样的内存值时导致意外的内存分配，Mojo 仅在类型
  为 `ImplicitlyCopyable` 时才允许内存值的隐式实体化，这是该类型应
  廉价复制
  的信号。

  你可以使用 `materialize()` 函数显式实体化值：

  ```mojo
   var dyn_list = materialize[lst]()
  ```

## 标准库变更 {#25-6-standard-library-changes}

### 可复制性变更

- Mojo 中建模复制的方式已全面重构。

  此前，Mojo 有两个用于建模可复制性的 trait：

  - `Copyable` 表示可以隐式复制的类型
  - `ExplicitlyCopyable` 表示只能通过
    显式调用 `.copy()` 方法复制的类型。

  绝大多数类型默认实现 `Copyable`（因此
  是隐式可复制的），`ExplicitlyCopyable` 部分引入但
  有重大使用限制。

  现在，新的 `Copyable` trait 表示可以
  *显式* 复制的类型（使用 `.copy()`），并且新的 `ImplicitlyCopyable` "标记"
  trait 可用于 *选择加入* 使类型也可隐式复制。
  这将默认行为从隐式可复制切换为仅显式
  可复制。

  新的 `ImplicitlyCopyable` trait 继承自 `Copyable`，并且
  不需要额外的方法。`ImplicitlyCopyable` 被编译器
  特殊识别。（`ImplicitlyCopyable` 类型也可
  使用 `.copy()` 显式复制。）

  这使非隐式可复制类型可用于所有
  标准库功能，解决了 Mojo 实际上
  强制所有类型隐式可复制的长期问题。
  这将使 Mojo 程序更高效、更易读，减少
  因意外的隐式复制导致的性能和正确性问题。

  通过此变更，符合 `Copyable` 的类型不再隐式
  可复制：

  ```mojo
  @fieldwise_init
  struct Person(Copyable):
      var name: String

  fn main():
      var p = Person("Connor")
      var p2 = p           # ERROR: not implicitly copyable
      var p3 = p.copy()    # OK: may be copied explicitly
  ```

  要使类型可隐式复制，请声明对
  `ImplicitlyCopyable` 标记 trait 的一致性：

  ```mojo
  @fieldwise_init
  struct Point(ImplicitlyCopyable):
      var x: Float32
      var y: Float32

  fn main():
      var p = Point(5, 10)
      var p2 = p           # OK: may be implicitly copied
      var p3 = p.copy()    # OK: may be explicitly copied
  ```

  另一个细微之处是，仅可为
  字段本身都是 `ImplicitlyCopyable`（而不仅仅是
  `Copyable`）的类型合成 `ImplicitlyCopyable`。如果你需要使具有任何非 `ImplicitlyCopyable`
  字段的类型支持隐式复制，你可以声明对
  `ImplicitlyCopyable` 的一致性，但手动编写 `__copyinit__()` 定义：

  ```mojo
  struct Container(ImplicitlyCopyable):
      var x: SomeCopyableType
      var y: SomeImplicitlyCopyableType

      fn __copyinit__(out self, existing: Self):
          self.x = existing.x.copy()   # Copy field explicitly
          self.y = existing.y
  ```

  有关可复制性的更多信息，请参阅 Mojo
  手册中关于
  [拷贝构造函数](/docs/manual/lifecycle/life/#copy-constructor) 的章节。

- 以下标准库类型和函数现在仅要求显式
  `Copyable` 用于其元素和参数类型，使其可与
  非隐式可复制的类型一起使用：
  [`List`](/docs/std/collections/list/List/)、
  [`Span`](/docs/std/memory/span/Span/)、
  [`InlineArray`](/docs/std/collections/inline_array/InlineArray/)
  [`Optional`](/docs/std/collections/optional/Optional/)、
  [`Variant`](/docs/std/utils/variant/Variant/)、
  [`Tuple`](/docs/std/builtin/tuple/Tuple/)、
  [`Dict`](/docs/std/collections/dict/Dict/)、
  [`Set`](/docs/std/collections/set/Set/)、
  [`Counter`](/docs/std/collections/counter/Counter/)、
  [`LinkedList`](/docs/std/collections/linked_list/LinkedList/)、
  [`Deque`](/docs/std/collections/deque/Deque/) 和
  [`reversed()`](/docs/std/builtin/reversed/reversed/)。

  此外，以下 trait 现在要求显式 `Copyable` 而不是
  `ImplicitlyCopyable`：
  `KeyElement`、`IntervalElement`、`ConvertibleFromPython`

- 以下 Mojo 标准库类型不再隐式可复制：
  [`List`](/docs/std/collections/list/List/)、
  [`Dict`](/docs/std/collections/dict/Dict/)、
  [`DictEntry`](/docs/std/collections/dict/DictEntry/)、
  [`OwnedKwargsDict`](/docs/std/collections/dict/OwnedKwargsDict/)、
  [`Set`](/docs/std/collections/set/Set/)、
  [`LinkedList`](/docs/std/collections/linked_list/LinkedList/)、
  [`Node`](/docs/std/collections/linked_list/Node/)
  [`Counter`](/docs/std/collections/counter/Counter/)、
  [`CountTuple`](/docs/std/collections/counter/CountTuple/)、
  [`BitSet`](/docs/std/collections/bitset/BitSet/)、`UnsafeMaybeUninitialized`、
  `DLHandle`、[`BenchConfig`](/docs/std/benchmark/bencher/BenchConfig/)、
  [`BenchmarkInfo`](/docs/std/benchmark/bencher/BenchmarkInfo/)、
  [`Report`](/docs/std/benchmark/benchmark/Report/)、
  [`PythonTypeBuilder`](/docs/std/python/bindings/PythonTypeBuilder/)。

  要创建这些类型之一的副本，请显式调用 `.copy()` 方法：

  ```mojo
  var l = List[Int](1, 2, 3)

  # ERROR: Implicit copying of `List` is no longer supported:
  # var l2 = l

  # Instead, perform an explicit copy:
  var l2 = l.copy()
  ```

  或者，要转移所有权，
  [使用 `^` 转移符号](/docs/manual/values/ownership/#transfer-arguments-var-and-)：

  ```mojo
  var l = List[Int](1, 2, 3)
  var l2 = l^
  # `l` is no longer accessible.
  ```

- 由于 `List` 和 `Dict` 被广泛使用，此版本通过将
  这些类型的隐式副本变为警告而不是错误来分阶段引入。这
  将在下一个 Mojo 版本中变为硬错误。

- 定义自定义 `.copy()` 方法的用户类型必须更新以将该
  逻辑移至 `__copyinit__()`。`.copy()` 方法现在由 `Copyable` 上的
  默认 trait 实现提供，不应被覆盖：

  ```mojo
  trait Copyable:
      fn __copyinit__(out self, existing: Self, /):
          ...

      fn copy(self) -> Self:
          return Self.__copyinit__(self)
  ```

### SIMD 及相关类型 {#25-6-simd-and-related-types}

- `SIMD` 类型的比较操作符（例如 `__eq__()` 和 `__le__()`）现在
  返回单个 `Bool` 而不是布尔 `SIMD` 掩码。此外，`SIMD`
  现在具有返回布尔掩码的显式元素
  比较（例如 `eq()` 和 `le()`）。
  - 这使 `SIMD` 符合 `EqualityComparable` trait，使
    在集合中使用 `SIMD` 向量、作为字典键、通用搜索
    算法等成为可能。此外，`Scalar` 现在符合 `Comparable` trait，
    即当大小为 1 时 `SIMD` 符合 `Comparable`。
  - 因此，`SIMD.__bool__()` 不再需要
    限制为标量，而是对向量元素执行 `any` 归约。

- 非标量 `SIMD` 构造函数不再允许 `Bool`
  值的隐式 splat。这可能导致编译时无法捕获的细微 bug，
  例如：

  ```mojo
  fn foo[w: Int](v: SIMD[_, w]) -> SIMD[DType.bool, w]:
    return v == 42  # this silently reduced to a single bool, and then splat
  ```

  与 `InlineArray` 类似，具有 `fill`
  仅关键字参数的显式构造函数可用于更安全地表达相同的逻辑：

  ```mojo
  fn foo[w: Int](v: SIMD[_, w]) -> SIMD[DType.bool, w]:
    return SIMD[DType.bool, w](fill=(v == 42))  # highlights the splat logic

  fn bar(Scalar[_]) -> Scalar[DType.bool]:
    # still works, since implicit splatting to a scalar is never ambiguous
    return v == 42
  ```

- 若干包装 MLIR 类型的类型已更改以进一步
  封装其行为，向非高级
  用户隐藏此低级行为。

  - 可从原始 MLIR 值构造的类型现在需要
    使用 `mlir_value` 仅关键字参数初始化方法。
    受影响的类型包括 `SIMD` 和 `UInt`。

  - 具有原始 MLIR 类型字段的类型已将其 `value` 字段重命名为
    `_mlir_value`。
    受影响的类型包括：`Bool` 和 `DType`。

- `SIMD.from_bits()` 工厂方法现在是一个构造函数，请使用
  `SIMD(from_bits=...)` 代替。

- `DType.index` 已弃用，由新的 `DType.int` 取代。此外，添加了新的
  `DType.uint`，建模宽度与
  机器字长匹配的无符号整数。

- `index()` 自由函数现在返回 `Int`，而不是原始 MLIR
  `__mlir_type.index` 值。

### 路径和文件系统变更

- 为 `Path` 类型添加了 [`parts()`](/docs/std/pathlib/path/Path/#parts) 方法，例如代替编写：

  ```mojo
  var path = Path("path/to/file")
  var parts = path.path.split(DIR_SEPARATOR)
  ```

  你现在可以编写：

  ```mojo
  var path = Path("path/to/file")
  var parts = path.parts()
  ```

- 为 `Path` 类型添加了 [`name()`](/docs/std/pathlib/path/Path/#name) 方法，它返回
  文件或目录的名称。

- 添加了 `os.path.realpath()` 以将符号链接解析为绝对路径并
  移除相对路径组件（`.`、`..` 等）。行为与
  Python 等效函数相同。

### 集合和迭代器变更 {#25-6-collections-and-iterators-changes}

- 添加了 [`iter`](/docs/std/iter/) 模块，其中包括新的 `Iterable`
  trait（和现有的 `Iterator` trait）。该模块还提供
  [`enumerate()`](/docs/std/iter/enumerate/)、
  [`iter()`](/docs/std/iter/iter/)、[`map()`](/docs/std/iter/map/)、
  [`next()`](/docs/std/iter/next/) 和 [`zip()`](/docs/std/iter/zip/)
  函数。新的通用 `zip()` 函数替换了之前版本中提供的
  `IntTuple` 专用
  `zip()` 函数。

  - `Iterable` 的 `origin` 参数现在命名为 `iterable_origin`
    ，其 `mut` 参数现在命名为 `iterator_mut` 以避免命名冲突。

- [`Iterator`](/docs/std/iter/Iterator/) 现在具有默认的 `bounds()` trait
  方法。它返回迭代器剩余长度的下限和上限。这可用于在从迭代器构建或扩展
  集合时进行预分配。

- 为 `Dict` 添加了
  [`take_items()`](/docs/std/collections/dict/Dict/#take_items)
  排空迭代器。

- 如果 [`Span`](/docs/std/memory/span/Span/) 的
  元素实现 `Representable` trait，它现在是 `Representable` 的。

- 为 [`List`](/docs/std/collections/list/List/)、
  [`Deque`](/docs/std/collections/deque/Deque/)、
  [`Dict`](/docs/std/collections/dict/Dict/)、
  [`LinkedList`](/docs/std/collections/linked_list/LinkedList/)、
  [`Optional`](/docs/std/collections/optional/Optional/) 和
  [`Set`](/docs/std/collections/set/Set/) 添加 `repr()` 支持。

- [`InlineArray`](/docs/std/collections/inline_array/InlineArray/) 现在
  自动检测其元素类型是否为平凡可析构，以
  不在其 `__del__()` 函数中调用析构函数。这改善了
  平凡可析构类型（如 `Int` 及相关类型）的性能。

- 类似于上述，`List` 现在会自动基于
  元素类型是否为平凡（可复制、可析构等）进行优化。这里
  不再有 `hint_trivial_type` 参数，因为现在这是自动
  完成的。

- `String.splitlines()` 现在返回 `List[StringSlice]` 而不是
  `List[String]`。这避免了不必要的中间分配。

- `StringSlice.from_utf8()` 工厂方法现在是一个构造函数，请使用
  `StringSlice(from_utf8=...)` 代替。

- `Span` 现在实现了通用的 `.count()` 方法，可传入
  返回布尔 `SIMD` 向量的函数。该函数以向量化的方式计算它返回 `True` 的次数。这适用于
  任何 `Span[Scalar[D]]`，例如 `Span[Byte]`。

- [`Optional`](/docs/std/collections/optional/Optional/) 和
  [`OptionalReg`](/docs/std/collections/optional/OptionalReg/) 现在可以
  在表达式中与 `Bool` 组合，无论是在编译时还是运行时：

  ```mojo
  alias value = Optional[Int](42)

  @parameter
  if CompilationTarget.is_macos() and value:
      print("is macos and value is:", value.value())
  ```

- [`sort()`](/docs/std/builtin/sort/sort/)、
  [`LinkedList.pop()`](/docs/std/collections/linked_list/LinkedList/#pop)、
  [`LinkedList.maybe_pop()`](/docs/std/collections/linked_list/LinkedList/#maybe_pop)
  和 [`Dict.popitem()`](/docs/std/collections/dict/Dict/#popitem) 不再
  复制元素，改善了性能。

- `IndexList` 和 `DimList` 类型不再可从元组值隐式构造。大多数现有调用点已使用显式初始化方法
  调用（`IndexList(...)`），因此已移除隐式转换以确保
  统一性和一致性。

### 指针变更

- 从
  [`UnsafePointer`](/docs/std/memory/unsafe_pointer/UnsafePointer/) 中移除了 `alignment` 参数和 `static_alignment_cast()` 方法。此
  `alignment` 参数仅由 `alloc()` 静态方法使用。

- 为 `UnsafePointer.alloc()` 添加了 `alignment` 关键字参数。在
  struct 上的 `alignment` 参数位置使用此参数。

- 从 `Span` 中移除了 `alignment` 参数，类似于上述的
  `UnsafePointer`。

- `UnsafePointer.init_pointee_explicit_copy()` 方法已被移除。
  请改为使用
  [`UnsafePointer.init_pointee_copy()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_copy)。

- `UnsafePointer.move_pointee_into()` 已被弃用。请改为使用
  [`UnsafePointer.init_pointee_move_from()`](/docs/std/memory/unsafe_pointer/UnsafePointer/#init_pointee_move_from)。

  `src.move_pointee_into(dst)` 使用了与直观的
  `LHS = RHS` 赋值语义相反的参数顺序，实际上是 `RHS -> LHS`。新
  函数修复了此可读性问题（`dst.init_pointee_move_from(src)`），并且
  额外遵循其他现有方法用于初始化指针内存位置的
  `init_pointee_*()` 命名约定。

### 原子操作

- 添加了 [`os.atomic.fence()`](/docs/std/atomic/atomic/fence/) 用于创建
  原子内存围栏。

  ```mojo
    from os.atomic import Atomic, Consistency, fence

    fn decrease_ref_count(ref_count: Atomic[DType.uint64]):
      if atomic.fetch_sub[ordering = Consistency.MONOTONIC](1) == 1:
        fence[Consistency.ACQUIRE]()
        # ...
  ```

- 为
  [`Atomic.load()`](/docs/std/atomic/atomic/Atomic/) 添加内存排序参数。

### 系统变更

- 添加了 `sys.info.platform_map()` 用于指定可以根据
  平台具有不同值的类型：

  ```mojo
  from sys.info import platform_map

  alias EDEADLK = platform_map["EDEADLK", linux = 35, macos = 11]()
  ```

- 将 `sys.info` 中的以下函数从
  `flatcase` 重命名为 `snake_case` 名称：

  | Old name          | New name            |
  |-------------------|---------------------|
  | `alignof()`       | `align_of()`        |
  | `bitwidthof()`    | `bit_width_of()`    |
  | `simdbitwidth()`  | `simd_bit_width()`  |
  | `simdbytewidth()` | `simd_byte_width()` |
  | `simdwidthof()`   | `simd_width_of()`   |
  | `sizeof()`        | `size_of()`         |

  旧名称已弃用，将在下一个版本中移除。

### GPU 支持 {#25-6-gpu-support}

- 添加了对在 Mojo 中为 Apple Silicon GPU 编程的初始支持。但是，
  MAX 图尚未在 Apple Silicon GPU 上启用，并且许多硬件
  特性仍有待启用。

- 添加了对 AMD RX 6900 XT 消费级 GPU 的支持。

- 在 `gfx1150`、`gfx1151` 和 `gfx1152` 架构中添加了对 AMD RDNA3.5 消费级 GPU 的支持。已为
  AMD Radeon 860M、880M 和 8060S GPU 添加了代表性配置。

- 添加了对 NVIDIA GTX 1080 Ti 消费级 GPU 的支持。

- 添加了对 NVIDIA Tesla P100 数据中心 GPU 的支持。

- 更新了 `layout_tensor()` 复制相关函数以支持 2D 和 3D
  线程块维度。

### 其他标准库变更 {#25-6-other-standard-library-changes}

- 引入了新的 `Some` 工具，以减少声明
  实现给定 trait 或 trait
  组合的类型参数的语法负担。例如，代替编写

  ```mojo
  fn foo[T: Intable, //](x: T) -> Int:
      return x.__int__()
  ```

  现在可以编写：

  ```mojo
  fn foo(x: Some[Intable]) -> Int:
      return x.__int__()
  ```

- [`compile.reflection.get_type_name()`](/docs/std/reflection/type_info/get_type_name/)
  工具现在具有有限的打印参数化类型的能力，例如
  打印 `SIMD[DType.float32, 4]` 而不仅仅是 `SIMD`。如果参数不可
  打印，则改为打印 `<unprintable>` 占位符。新的
  `qualified_builtins` 标志还允许用户控制最常见的
  （但不是全部）内置类型的详细程度。

## Kernels 变更 {#25-6-kernels-changes}

- Mojo 中提供了用于 SM100 的快速 matmul。请在
  [`matmul_sm100.mojo`](https://github.com/modular/modular/commits/main/max/kernels/src/linalg/matmul_sm100.mojo) 中查看它。

- 将
  [`comm`](https://github.com/modular/modular/tree/main/max/kernels/src/comm)
  模块从标准库（`gpu.comm`）移至 MAX AI 内核库。
  任何使用 `gpu.comm` 的导入都应更新为 `comm`。

## 工具链变更 {#25-6-tooling-changes}

- `mojo test` 现在会忽略名称以 `.` 开头的文件夹。这
  将排除 Unix 系统上的隐藏文件夹。

- 当声明 `fn` 函数引发错误（`raises`）且没有
  [`Raises` 文档字符串](https://github.com/modular/modular/blob/main/mojo/stdlib/docs/docstring-style-guide.md#errors) 时，`mojo doc --validate-doc-strings` 现在会发出警告。
  但是，由于 Mojo 自动将所有 `def` 函数视为
  [引发函数](/docs/manual/functions/#raising-and-non-raising-functions)，
  我们不对 `def` 函数强制要求 `Raises` 文档（以避免嘈杂的误
  报）。

- 现已提供 nightly `mojo` Python wheels。要在 Python 虚拟环境中安装
  Mojo 开发所需的一切，你可以使用：

  ```sh
  pip install --pre mojo \
   --index-url https://dl.modular.com/public/nightly/python/simple/
  ```

  更多信息请参阅 [Mojo 安装指南](/install/)。

- 为准备未来的 Mojo 1.0，`mojo` 和 `mojo-compiler` 包
  的版本前缀添加了 `0.`。

## 已移除 {#25-6-removed}

- Mojo MLIR C 绑定已被移除。这是一个用于
  早期实验的私有包。

  文档。
